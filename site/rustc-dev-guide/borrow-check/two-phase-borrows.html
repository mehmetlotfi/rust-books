    قرض‌های دوفازی

    قرض‌های دوفازی (two-phase borrows) نسخه‌ای آزادتر از قرض‌های تغییرپذیر هستند که اجازه می‌دهند فراخوانی‌های متد تودرتو مانند vec.push(vec.len()) نوشته شوند. چنین قرض‌هایی ابتدا در یک فاز «رزرو» مانند قرض‌های اشتراکی عمل می‌کنند و بعداً می‌توانند به یک قرض تغییرپذیر کامل «فعال» شوند.

    تنها برخی قرض‌های تغییرپذیر ضمنی می‌توانند دوفازی باشند؛ هر &mut یا ref mut که در کد منبع نوشته شود هرگز قرض دوفازی نیست. مواردی که قرض دوفازی تولید می‌کنیم عبارت‌اند از:

    1. قرض خودکار (autoref) هنگام فراخوانی متدی که گیرنده‌اش ارجاع تغییرپذیر است.
    2. یک قرض مجدد (reborrow) تغییرپذیر در آرگومان‌های تابع.
    3. قرض تغییرپذیر ضمنی در عملگر انتساب مرکب سربارگذاری‌شده.

    برای ارائه‌ی چند مثال:

    // In the source code

// Case 1:
let mut v = Vec::new();
v.push(v.len());
let r = &mut Vec::new();
r.push(r.len());

// Case 2:
std::mem::replace(r, vec![1, r.len()]);

// Case 3:
let mut x = std::num::Wrapping(2);
x += x;

    با بازکردن این‌ها به‌قدری که قرض‌های دوفازی نمایان شوند:

    // Case 1:
let mut v = Vec::new();
let temp1 = &two_phase v;
let temp2 = v.len();
Vec::push(temp1, temp2);
let r = &mut Vec::new();
let temp3 = &two_phase *r;
let temp4 = r.len();
Vec::push(temp3, temp4);

// Case 2:
let temp5 = &two_phase *r;
let temp6 = vec![1, r.len()];
std::mem::replace(temp5, temp6);

// Case 3:
let mut x = std::num::Wrapping(2);
let temp7 = &two_phase x;
let temp8 = x;
std::ops::AddAssign::add_assign(temp7, temp8);

    اینکه یک قرض می‌تواند دوفازی باشد یا نه، پس از بررسی نوع با یک پرچم روی AutoBorrow ردیابی می‌شود و سپس هنگام ساخت MIR به یک BorrowKind می‌شود.

    هر قرض دوفازی به یک مقدار موقت اختصاص می‌یابد که فقط یک‌بار استفاده می‌شود. بنابراین می‌توانیم تعریف کنیم:

    • نقطه‌ای که مقدار موقت در آن مقداردهی می‌شود، نقطه‌ی رزرو قرض دوفازی نامیده می‌شود.
    • نقطه‌ای که مقدار موقت در آن استفاده می‌شود، که عملاً همیشه یک فراخوانی تابع است، نقطه‌ی فعال‌سازی نامیده می‌شود.

    نقطه‌های فعال‌سازی با بازدیدکننده‌ی (visitor) GatherBorrows پیدا می‌شوند. سپس BorrowData هم نقطه‌ی رزرو و هم نقطه‌ی فعال‌سازی قرض را نگه می‌دارد.

    بررسی قرض‌های دوفازی

    قرض‌های دوفازی طوری در نظر گرفته می‌شوند که انگار قرض تغییرپذیر هستند، با این استثناها:

    1. در هر مکان از MIR بررسی می‌کنیم آیا قرض دوفازی‌ای در این مکان فعال می‌شود. اگر یک قرض دوفازی زنده در یک مکان فعال شود، بررسی می‌کنیم که هیچ قرضی با آن قرض دوفازی تداخل نداشته باشد.
    2. در نقطه‌ی رزرو، اگر قرض‌های تغییرپذیر زنده‌ی متداخل وجود داشته باشند خطا می‌دهیم، و اگر قرض‌های اشتراکی متداخل وجود داشته باشند lint صادر می‌کنیم.
    3. میان نقطه‌ی رزرو و نقطه‌ی فعال‌سازی، قرض دوفازی مانند یک قرض اشتراکی عمل می‌کند. اینکه آیا در چنین نقطه‌ای هستیم (در is_active) را با استفاده از Dominators برای گراف MIR تعیین می‌کنیم.
    4. پس از نقطه‌ی فعال‌سازی، قرض دوفازی مانند یک قرض تغییرپذیر عمل می‌کند.
