    درخت‌های اثبات

    حل‌گر صفت (trait solver) خودش فقط برمی‌گرداند که آیا یک goal برقرار است یا نه و قیدهای لازم را اعلام می‌کند، اما گاهی می‌خواهیم بدانیم هنگام تلاش برای اثبات آن چه اتفاقی افتاده است. هرچند بقیهٔ کامپایلر باید به‌طور کلی حل‌گر صفت را مانند یک جعبهٔ سیاه ببیند، نمی‌توانیم درون آن را کاملاً نادیده بگیریم و «درخت‌های اثبات» (proof trees) را به‌عنوان رابطی برای این کار فراهم می‌کنیم. برای استفاده از آن‌ها صفت ProofTreeVisitor را پیاده‌سازی می‌کنید؛ برای نمونه به پیاده‌سازی‌های موجود آن نگاه کنید. مهم‌ترین کاربردها محاسبهٔ علت‌های ابهام intercrate برای خطاهای coherence، بهبود خطاهای حل‌گر صفت و استنتاج زودهنگام امضای closureها است.

    محاسبهٔ درخت‌های اثبات

    حل‌گر صفت از Canonicalization استفاده می‌کند و برای هر goal تودرتو از یک InferCtxt کاملاً جداگانه بهره می‌برد. هم تشخیص‌ها (diagnostics) و هم auto-traitها در rustdoc باید «نگاه کردن به goalهای تودرتو» را درست مدیریت کنند. با داشتن goalی مانند Vec<Vec<?x>>: Debug، آن را به exists<T0> Vec<Vec<T0>>: Debug canonicalize می‌کنیم، آن goal را به Vec<Vec<?0>>: Debug نمونه‌سازی می‌کنیم، goal تودرتوی Vec<?0>: Debug را به دست می‌آوریم، این را canonicalize می‌کنیم تا exists<T0> Vec<T0>: Debug به دست آید، آن را به‌صورت Vec<?0>: Debug نمونه‌سازی می‌کنیم که در نتیجه goal تودرتوی ?0: Debug پدید می‌آید که مبهم است.

    درخت‌های اثبات را با دادن یک ProofTreeBuilder به گراف جست‌وجو (search graph) محاسبه می‌کنیم که گام‌های ارزیابی حل‌گر صفت را به یک درخت تبدیل می‌کند. هنگام ذخیرهٔ هر داده‌ای که از متغیرهای استنتاج یا placeholderها استفاده می‌کند، آن داده همراه با فهرست همهٔ متغیرهای استنتاج بدون قیدی که طی این محاسبه ساخته شده‌اند canonicalize می‌شود. سپس این CanonicalState هنگام پیمایش درخت اثبات در بافت استنتاج والد نمونه‌سازی می‌شود و از فهرست متغیرهای استنتاج برای اتصال همهٔ مقادیر canonicalize‌شده‌ای که طی این ارزیابی ساخته شده‌اند استفاده می‌شود.

    اشکال‌زدایی حل‌گر

    پیش‌تر سعی کردیم از درخت‌های اثبات برای اشکال‌زدایی پیاده‌سازی حل‌گر هم استفاده کنیم. این کار نیازمندی‌های طراحی متفاوتی نسبت به تحلیل برنامه‌نویسی‌شدهٔ آن دارد. روش پیشنهادی برای اشکال‌زدایی حل‌گر صفت استفاده از tracing است. حل‌گر صفت فقط از سطح tracing با نام debug برای «شکل» کلی خود و از trace برای جزئیات بیشتر استفاده می‌کند. بنابراین RUSTC_LOG=rustc_next_trait_solver=debug طرح کلی را به شما می‌دهد و اگر اطلاعات دقیق‌تری لازم باشد می‌توان از RUSTC_LOG=rustc_next_trait_solver=trace استفاده کرد.
