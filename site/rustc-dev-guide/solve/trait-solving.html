    حل صفت (جدید)

    این فصل توضیح می‌دهد حل صفت (trait solving) با حل‌گر جدیدِ در حال توسعه (WIP) که در rustc_trait_selection/solve قرار دارد چگونه کار می‌کند. می‌توانید به مستندات حل‌گر فعلی و حل‌گر chalk نیز نگاهی بیندازید.

    مفاهیم اصلی

    هدف سامانهٔ صفت بررسی این است که آیا یک قید صفت (trait bound) مفروض برقرار است یا نه. این کار به‌ویژه هنگام بررسی نوع بدنهٔ توابعِ - احتمالاً جنریک - انجام می‌شود. برای مثال:

    fn uses_vec_clone<T: Clone>(x: Vec<T>) -> (Vec<T>, Vec<T>) {
    (x.clone(), x)
}

    در اینجا فراخوانی x.clone() ایجاب می‌کند ثابت کنیم Vec<T> صفت Clone را پیاده‌سازی می‌کند، با این فرض که T: Clone برقرار است. می‌توانیم T: Clone را فرض کنیم، چون فراخوانندگان این تابع آن را اثبات خواهند کرد.

    مفهوم «اثبات Vec<T>: Clone با فرض T: Clone» یک Goal نامیده می‌شود. هر دوی Vec<T>: Clone و T: Clone با Predicate نمایش داده می‌شوند. predicateهای دیگری هم هستند، به‌ویژه قیدهای برابری روی آیتم‌های وابسته: <Vec<T> as IntoIterator>::Item == T. برای فهرست کامل، به enum با نام PredicateKind نگاه کنید. یک Goal به‌صورت predicateای که باید ثابت کنیم و param_envای که این predicate باید در آن برقرار باشد نمایش داده می‌شود.

    goalها را با بررسی اینکه آیا هر Candidate ممکن برای goal مفروض اعمال می‌شود، با اثبات بازگشتی goalهای تودرتوی آن اثبات می‌کنیم. برای فهرستی از candidateهای ممکن همراه با مثال، به CandidateSource نگاه کنید. مهم‌ترین candidateها، candidateهای Impl هستند، یعنی پیاده‌سازی‌های صفتی که کاربر نوشته است، و candidateهای ParamEnv، یعنی مفروضات در محیط فعلی ما.

    با نگاه به مثال بالا، برای اثبات Vec<T>: Clone ابتدا از impl<T: Clone> Clone for Vec<T> استفاده می‌کنیم. برای استفاده از این impl باید goal تودرتوی T: Clone را ثابت کنیم. این goal می‌تواند از فرض T: Clone در ParamEnv استفاده کند که هیچ goal تودرتویی ندارد. بنابراین Vec<T>: Clone برقرار است.

    حل‌گر صفت می‌تواند موفقیت، ابهام (ambiguity) یا خطا را به‌صورت یک CanonicalResponse برگرداند. برای موفقیت و ابهام، قیدهای استنتاج و قیدهای ناحیه (region) را نیز برمی‌گرداند.
