    TypeTreeها برای Autodiff

    TypeTreeها چه هستند؟

    توصیف‌گرهای چیدمان حافظه برای Enzyme. این‌ها به Enzyme دقیقاً می‌گویند نوع‌ها در حافظه چگونه ساختار یافته‌اند تا بتواند مشتق‌ها را به‌طور کارا محاسبه کند.

    ساختار

    TypeTree(Vec<Type>)

Type {
    offset: isize,  // byte offset (-1 = everywhere)
    size: usize,    // size in bytes
    kind: Kind,     // Float, Integer, Pointer, etc.
    child: TypeTree // nested structure
}

    مثال: fn compute(x: &f32, data: &[f32]) -> f32

    ورودی ۰: x: &f32

    TypeTree(vec![Type {
    offset: -1, size: 8, kind: Pointer,
    child: TypeTree(vec![Type {
        offset: 0, size: 4, kind: Float,  // Single value: use offset 0
        child: TypeTree::new()
    }])
}])

    ورودی ۱: data: &[f32]

    TypeTree(vec![Type {
    offset: -1, size: 8, kind: Pointer,
    child: TypeTree(vec![Type {
        offset: -1, size: 4, kind: Float,  // -1 = all elements
        child: TypeTree::new()
    }])
}])

    خروجی: f32

    TypeTree(vec![Type {
    offset: 0, size: 4, kind: Float,  // Single scalar: use offset 0
    child: TypeTree::new()
}])

    چرا لازم است؟

    • Enzyme نمی‌تواند چیدمان نوع‌های پیچیده را از LLVM IR استنتاج کند
    • از تحلیل کند الگوی حافظه جلوگیری می‌کند
    • محاسبهٔ درست مشتق را برای ساختارهای تودرتو ممکن می‌کند
    • به Enzyme می‌گوید کدام بایت‌ها مشتق‌پذیرند و کدام‌ها فراداده (metadata) هستند

    Enzyme با این اطلاعات چه می‌کند:

    بدون TypeTreeها:

    ; Enzyme sees generic LLVM IR:
define float @distance(ptr %p1, ptr %p2) {
; Has to guess what these pointers point to
; Slow analysis of all memory operations
; May miss optimization opportunities
}

    با TypeTreeها:

    define "enzyme_type"="{[-1]:Float@float}" float @distance(
    ptr "enzyme_type"="{[-1]:Pointer, [-1,0]:Float@float}" %p1, 
    ptr "enzyme_type"="{[-1]:Pointer, [-1,0]:Float@float}" %p2
) {
; Enzyme knows exact type layout
; Can generate efficient derivative code directly
}

    TypeTreeها - توضیح offset و ‎-1

    ساختار Type

    Type {
    offset: isize, // WHERE this type starts
    size: usize,   // HOW BIG this type is
    kind: Kind,    // WHAT KIND of data (Float, Int, Pointer)
    child: TypeTree // WHAT'S INSIDE (for pointers/containers)
}

    مقدارهای offset

    offset معمولی (۰، ۴، ۸ و غیره)

    موقعیت بایت مشخص درون یک ساختار

    struct Point {
    x: f32, // offset 0, size 4
    y: f32, // offset 4, size 4
    id: i32, // offset 8, size 4
}

    TypeTree برای &Point (نمایش داخلی):

    TypeTree(vec![
    Type { offset: 0, size: 4, kind: Float },   // x at byte 0
    Type { offset: 4, size: 4, kind: Float },   // y at byte 4
    Type { offset: 8, size: 4, kind: Integer }  // id at byte 8
])

    این LLVM را تولید می‌کند:

    "enzyme_type"="{[-1]:Pointer, [-1,0]:Float@float, [-1,4]:Float@float, [-1,8]:Integer, [-1,9]:Integer, [-1,10]:Integer, [-1,11]:Integer}"

    offset برابر ‎-1 (ویژه: «همه‌جا»)

    یعنی «این الگو برای همهٔ عنصرها تکرار می‌شود»

    مثال ۱: آرایهٔ مستقیم [f32; 100] (بدون غیرمستقیم‌سازی اشاره‌گر)

    TypeTree(vec![Type {
    offset: -1, // ALL positions
    size: 4,    // each f32 is 4 bytes
    kind: Float, // every element is float
}])

    LLVM تولیدشده: "enzyme_type"="{[-1]:Float@float}"

    مثال ۱ب: ارجاع به آرایه &[f32; 100] (با غیرمستقیم‌سازی اشاره‌گر)

    TypeTree(vec![Type {
    offset: -1, size: 8, kind: Pointer,
    child: TypeTree(vec![Type {
        offset: -1, // ALL array elements
        size: 4,    // each f32 is 4 bytes
        kind: Float, // every element is float
    }])
}])

    LLVM تولیدشده: "enzyme_type"="{[-1]:Pointer, [-1,-1]:Float@float}"

    به‌جای فهرست‌کردن ۱۰۰ Type جداگانه با offsetهای 0,4,8,12...396

    مثال ۲: برش (slice) &[i32]

    // Pointer to slice data
TypeTree(vec![Type {
    offset: -1, size: 8, kind: Pointer,
    child: TypeTree(vec![Type {
        offset: -1, // ALL slice elements
        size: 4,    // each i32 is 4 bytes
        kind: Integer
    }])
}])

    LLVM تولیدشده: "enzyme_type"="{[-1]:Pointer, [-1,-1]:Integer}"

    مثال ۳: ساختار ترکیبی

    struct Container {
    header: i64,        // offset 0
    data: [f32; 1000],  // offset 8, but elements use -1
}
    TypeTree(vec![
    Type { offset: 0, size: 8, kind: Integer }, // header
    Type { offset: 8, size: 4000, kind: Pointer,
        child: TypeTree(vec![Type {
            offset: -1, size: 4, kind: Float // ALL array elements
        }])
    }
])

    تمایز کلیدی: مقدارهای تکی در برابر آرایه‌ها

    مقدارهای تکی برای دقت از offset برابر 0 استفاده می‌کنند:

    • &f32 دقیقاً یک مقدار f32 در offset ۰ دارد
    • دقیق‌تر از استفاده از ‎-1 («همه‌جا») است
    • تولید می‌کند: {[-1]:Pointer, [-1,0]:Float@float}

    آرایه‌ها برای کارایی از offset برابر -1 استفاده می‌کنند:

    • &[f32; 100] همان الگو ۱۰۰ بار تکرار شده است
    • استفاده از ‎-1 از فهرست‌کردن ۱۰۰ offset جداگانه جلوگیری می‌کند
    • تولید می‌کند: {[-1]:Pointer, [-1,-1]:Float@float}
