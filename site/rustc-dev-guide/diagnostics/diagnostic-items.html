    آیتم‌های تشخیصی

    هنگام نوشتن lintها، بررسی نوع‌ها، صفت‌ها و تابع‌های مشخص کار رایجی است. این موضوع این پرسش را پیش می‌آورد که این بررسی چگونه باید انجام شود. نوع‌ها را می‌توان با مسیر کامل نوعشان بررسی کرد. اما این کار مستلزم کدنویسی سخت (hard coding) مسیرهاست و در برخی موارد مرزی می‌تواند به طبقه‌بندی نادرست بینجامد. برای جلوگیری از این مشکل، rustc آیتم‌های تشخیصی (diagnostic items) را معرفی کرده است که نوع‌ها را از طریق Symbolها شناسایی می‌کنند.

    یافتن آیتم‌های تشخیصی

    آیتم‌های تشخیصی با attribute به نام rustc_diagnostic_item به آیتم‌های درون rustc/std/core/alloc افزوده می‌شوند. آیتم مربوط به یک نوع مشخص را می‌توان با باز کردن کد منبع در مستندات و جست‌وجوی این attribute پیدا کرد. توجه کنید که این attribute اغلب با attribute به نام cfg_attr اضافه می‌شود تا از خطاهای کامپایل در هنگام آزمون‌ها جلوگیری شود. یک تعریف معمولاً چنین به نظر می‌رسد:

    // This is the diagnostic item for this type   vvvvvvv
#[cfg_attr(not(test), rustc_diagnostic_item = "Penguin")]
struct Penguin;

    آیتم‌های تشخیصی معمولاً فقط به صفت‌ها، نوع‌ها و تابع‌های مستقل افزوده می‌شوند. اگر هدف بررسی یک نوع وابسته یا یک متد است، لطفاً از آیتم تشخیصی همان آیتم استفاده کنید و به استفاده از آیتم‌های تشخیصی مراجعه کنید.

    افزودن آیتم‌های تشخیصی

    یک آیتم تشخیصی جدید را می‌توان با این دو گام اضافه کرد:

    1. آیتم هدف را در مخزن Rust پیدا کنید. سپس آیتم تشخیصی را به صورت یک رشته از طریق attribute به نام rustc_diagnostic_item اضافه کنید. این کار گاهی ممکن است هنگام اجرای آزمون‌ها خطای کامپایل ایجاد کند. با استفاده از attribute به نام cfg_attr همراه با شرط not(test) می‌توان از این خطاها جلوگیری کرد (افزودن آن به همه‌ی attributeهای rustc_diagnostic_item به عنوان اقدام پیشگیرانه اشکالی ندارد). در نهایت باید چنین به نظر برسد:

      // This will be the new diagnostic item        vvv
#[cfg_attr(not(test), rustc_diagnostic_item = "Cat")]
struct Cat;

      برای قراردادهای نام‌گذاری آیتم‌های تشخیصی، لطفاً به قراردادهای نام‌گذاری مراجعه کنید.

    2. به آیتم‌های تشخیصی در کد از طریق symbolها در \[`rustc_span::symbol::sym`\] دسترسی پیدا می‌شود. برای افزودن آیتم تشخیصی که تازه ساخته‌اید، کافی است فایل ماژول را باز کنید و نام آن، در اینجا `Cat`، را در جای درست فهرست اضافه کنید.

    اکنون می‌توانید یک pull request با تغییراتتان ایجاد کنید.

    نکته: هنگام استفاده از آیتم‌های تشخیصی در پروژه‌های دیگر مانند Clippy، ممکن است مدتی طول بکشد تا مخزن‌ها همگام‌سازی شوند.

    قراردادهای نام‌گذاری

    آیتم‌های تشخیصی هنوز قرارداد نام‌گذاری مشخصی ندارند. موارد زیر رهنمودهایی هستند که در آینده باید استفاده شوند، اما ممکن است با نام‌های موجود تفاوت داشته باشند:

    • نوع‌ها، صفت‌ها و شمارش‌ها با UpperCamelCase نام‌گذاری می‌شوند (مثال‌ها: Iterator و HashMap)
    • برای نام نوع‌هایی که چندین بار استفاده می‌شوند، مانند Writer، بهتر است نام دقیق‌تری انتخاب شود، مثلاً با افزودن ماژول به آن (مثال: IoWriter)
    • آیتم‌های وابسته نباید آیتم تشخیصی مستقل خود را داشته باشند، بلکه باید به صورت غیرمستقیم از طریق آیتم تشخیصی نوعی که از آن می‌آیند در دسترس قرار گیرند.
    • تابع‌های مستقل مانند std::mem::swap() باید با snake_case و با یک ماژول مهم (صادرشده) به عنوان پیشوند نام‌گذاری شوند (مثال‌ها: mem_swap و cmp_max)
    • ماژول‌ها معمولاً نباید آیتم تشخیصی داشته باشند. آیتم‌های تشخیصی برای پرهیز از استفاده‌ی مسیرها اضافه شدند، و بنابراین به کار بردن آن‌ها برای ماژول‌ها به احتمال زیاد نتیجه‌ی معکوس می‌دهد.

    استفاده از آیتم‌های تشخیصی

    در rustc، آیتم‌های تشخیصی از طریق Symbolها از درون ماژول rustc_span::symbol::sym جست‌وجو می‌شوند. سپس می‌توان آن‌ها را با TyCtxt::get_diagnostic_item() به DefIdها نگاشت کرد یا با TyCtxt::is_diagnostic_item() بررسی کرد که آیا با یک DefId مطابقت دارند. هنگام نگاشت از یک آیتم تشخیصی به DefId، این متد یک Option<DefId> برمی‌گرداند. این مقدار می‌تواند None باشد، اگر symbol یک آیتم تشخیصی نباشد یا نوع ثبت نشده باشد، مثلاً هنگام کامپایل با #[no_std]. همه‌ی مثال‌های زیر بر پایه‌ی DefIdها و کاربرد آن‌ها هستند.

    مثال: بررسی یک نوع

    use rustc_span::symbol::sym;

/// This example checks if the given type (`ty`) has the type `HashMap` using
/// `TyCtxt::is_diagnostic_item()`
fn example_1(cx: &LateContext<'_>, ty: Ty<'_>) -> bool {
    match ty.kind() {
        ty::Adt(adt, _) => cx.tcx.is_diagnostic_item(sym::HashMap, adt.did()),
        _ => false,
    }
}

    مثال: بررسی پیاده‌سازی یک صفت

    /// This example checks if a given [`DefId`] from a method is part of a trait
/// implementation defined by a diagnostic item.
fn is_diag_trait_item(
    cx: &LateContext<'_>,
    def_id: DefId,
    diag_item: Symbol
) -> bool {
    if let Some(trait_did) = cx.tcx.trait_of_item(def_id) {
        return cx.tcx.is_diagnostic_item(diag_item, trait_did);
    }
    false
}

    نوع‌های وابسته

    به نوع‌های وابسته‌ی آیتم‌های تشخیصی می‌توان به صورت غیرمستقیم دسترسی پیدا کرد؛ ابتدا DefId صفت را می‌گیرید و سپس TyCtxt::associated_items() را فراخوانی می‌کنید. این فراخوانی یک شیء AssocItems برمی‌گرداند که می‌توان از آن برای بررسی‌های بعدی استفاده کرد. برای نمونه‌ای از این کاربرد، clippy_utils::ty::get_iterator_item_ty() را ببینید.

    استفاده در Clippy

    Clippy تا جای ممکن از آیتم‌های تشخیصی استفاده می‌کند و چند تابع پوششی و کمکی توسعه داده است. لطفاً هنگام استفاده از آیتم‌های تشخیصی در Clippy به مستندات آن نیز مراجعه کنید. (به ابزارهای رایج برای نوشتن lintها مراجعه کنید.)
