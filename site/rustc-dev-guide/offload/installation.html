راهنمای توسعهٔ rustcrustc Development Guide

    Installation

    std::offload تا حدی در ساخت‌های nightly برای کاربران در دسترس است. با این حال فعلاً همه هنوز باید rustc را از منبع بسازند تا از همهٔ قابلیت‌های آن استفاده کنند.

    Rustup installation.

    اگر روی لینوکس x86_64 هستید، می‌توانید toolchain از نوع nightly را این‌طور نصب کنید:

    rustup +nightly component add offload

    Build instructions

    در غیر این صورت باید مخزن Rust را clone و پیکربندی کنید:

    git clone git@github.com:rust-lang/rust
cd rust
./configure --enable-llvm-link-shared --release-channel=nightly --enable-llvm-assertions --enable-llvm-offload --enable-llvm-enzyme --enable-clang --enable-lld --enable-option-checking --enable-ninja --disable-docs

    اگر ترجیح می‌دهید clang موجود را دوباره استفاده کنید نه اینکه آن را بسازید، --enable-clang را حذف کنید و به‌جای آن --enable-llvm-offload-clang-dir=<absolute path to the directory holding ClangConfig.cmake> را بدهید. باید با (نسخهٔ major) LLVM در src/llvm-project مطابقت داشته باشد.

    پس از آن می‌توانید rustc را با این بسازید:

    ./x build --stage 1 library

    پس از آن rustc toolchain link به شما اجازه می‌دهد از طریق cargo از آن استفاده کنید:

    rustup toolchain link offload build/host/stage1
rustup toolchain install nightly # enables -Z unstable-options

    دستورالعمل ساخت خود LLVM

    git clone git@github.com:llvm/llvm-project
cd llvm-project
mkdir build
cd build
cmake -G Ninja ../llvm -DLLVM_TARGETS_TO_BUILD="host;AMDGPU;NVPTX" -DLLVM_ENABLE_ASSERTIONS=ON -DLLVM_ENABLE_PROJECTS="clang;lld" -DLLVM_ENABLE_RUNTIMES="offload;openmp" -DLLVM_ENABLE_PLUGINS=ON -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=.
ninja
ninja install

    این یک ساخت کارای LLVM به شما می‌دهد.

    Testing

    این اسکریپت تست را برای تست‌های مخصوص offload اجرا کنید:

    ./x test --stage 1 tests/codegen-llvm/gpu_offload

    برای تست CI به‌صورت محلی، می‌توانید از دستورهای شرح‌داده‌شده در تست با Docker استفاده کنید:

    cargo run --manifest-path src/ci/citool/Cargo.toml run-local dist-x86_64-linux

    این همهٔ آرتیفکت‌های کامپایلر را در پوشهٔ obj ذخیره می‌کند، اما اگر کد مخصوص rustc را تغییر دهید، ممکن است لازم باشد این پوشه را حذف کنید چون در غیر این صورت ایمیج Docker حالتش را cache می‌کند.

    زیرماژول‌ها هم باید در این مرحله checkout شده باشند.
