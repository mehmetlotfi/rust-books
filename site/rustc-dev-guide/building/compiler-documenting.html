راهنمای توسعهٔ rustcrustc Development Guide

    Building documentation

    این فصل توضیح می‌دهد چگونه مستندات اجزای toolchain، مثل کتابخانهٔ استاندارد (std) یا کامپایلر (rustc) را بسازید.

    • Document everything

      این از rustdoc مربوط به toolchain بتا استفاده می‌کند، پس خروجی آن (اندکی) با rustdoc در stage 1 فرق دارد، چون rustdoc در حال توسعهٔ فعال است:

      ./x doc

      اگر می‌خواهید مطمئن شوید مستندات همان‌طور که در CI دیده می‌شود به نظر می‌رسند:

      ./x doc --stage 1

      این تضمین می‌کند rustdoc (فعلی) ساخته می‌شود، و سپس از آن برای مستندسازی اجزا استفاده می‌شود.

    • درست مثل اجرای تست‌های جداگانه یا ساخت اجزای مشخص، می‌توانید فقط مستنداتی را که می‌خواهید بسازید:

      ./x doc src/doc/book
./x doc src/doc/nomicon
./x doc compiler library

      برای فهرست کامل کتاب‌ها صفحهٔ فهرست مستندات nightly را ببینید.

    • مستندسازی آیتم‌های داخلی rustc

      مستندات کامپایلر به‌طور پیش‌فرض ساخته نمی‌شوند. برای اینکه با x doc به‌طور پیش‌فرض ساخته شوند، bootstrap.toml را تغییر دهید:

      build.compiler-docs = true

      توجه کنید که وقتی فعال باشد، مستندات آیتم‌های داخلی کامپایلر هم ساخته می‌شود.

      نکته: مستندات کامپایلر در این پیوند قرار دارد.

    Contributing documentation

    بهبود مستندات بسیار مورد استقبال است. منبع doc.rust-lang.org در src/doc در درخت قرار دارد، و مستندات API استاندارد از خود کد منبع تولید می‌شوند (مثلاً library/std/src/lib.rs). pull requestهای مستندات مثل pull requestهای دیگر کار می‌کنند.

    برای پیدا‌کردن issueهای مرتبط با مستندات از برچسب A-docs استفاده کنید.

    رهنمودهای سبک مستندات را می‌توانید در RFC 1574 بیابید.

    برای ساخت مستندات کتابخانهٔ استاندارد از x doc --stage 1 library --open استفاده کنید. برای ساخت مستندات یک کتاب (مثلاً کتاب unstable) از x doc src/doc/unstable-book استفاده کنید. نتایج باید در build/host/doc ظاهر شوند و به‌طور خودکار در مرورگر پیش‌فرض شما باز شوند. برای اطلاعات بیشتر ساخت مستندات را ببینید.

    همچنین می‌توانید برای بررسی اصلاحات کوچک مستقیماً از rustdoc استفاده کنید. برای مثال، rustdoc src/doc/reference.md مرجع را در doc/reference.html رندر می‌کند. ممکن است CSS به‌هم‌ریخته باشد، اما می‌توانید درستی HTML را بررسی کنید.

    لطفاً توجه کنید که ما اصلاحات تایپوگرافی/غلط‌یابی مستندات داخلی را نمی‌پذیریم، چون معمولاً ارزش اتلاف وقت و زمان بازبینی را ندارد. نمونه‌های مستندات داخلی کامنت‌های کد و مستندات API در rustc هستند. با این حال، اگر همراه با بهبودهای دیگر در همان PR باشند، آزادید آن‌ها را اصلاح کنید.
