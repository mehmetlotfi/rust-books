    Bootstrap چگونه این کار را انجام می‌دهد

    مفهوم اصلی در Bootstrap یک Step ساخت است؛ این stepها با Builder::ensure به هم زنجیر می‌شوند. Builder::ensure یک Step را به عنوان ورودی می‌گیرد و آن را تنها در صورتی اجرا می‌کند که پیش‌تر اجرا نشده باشد. بیایید نگاه دقیق‌تری به Step بیندازیم.

    خلاصه‌ای از Step

    یک Step مجموعه‌ای دقیق و جزئی از اقدامات را نشان می‌دهد که در فرایند تولید یک artifact دخیل‌اند. می‌توان آن را مانند یک قاعده (rule) در Makefileها دانست. صفت (trait) با نام Step به این شکل تعریف شده است:

    pub trait Step: 'static + Clone + Debug + PartialEq + Eq + Hash {
    type Output: Clone;

    const DEFAULT: bool = false;
    const ONLY_HOSTS: bool = false;

    // Required methods
    fn run(self, builder: &Builder<'_>) -> Self::Output;
    fn should_run(run: ShouldRun<'_>) -> ShouldRun<'_>;

    // Provided method
    fn make_run(_run: RunConfig<'_>) { ... }
}
    • run تابعی است که مسئول انجام کار است. Builder::ensure تابع run را فراخوانی می‌کند.
    • should_run رابط خط فرمان است که تعیین می‌کند آیا فراخوانی‌ای مانند x build foo باید یک Step مشخص را اجرا کند یا نه. در یک زمینه «پیش‌فرض» که هیچ مسیری داده نشده است، make_run مستقیماً فراخوانی می‌شود.
    • make_run فقط برای مواردی فراخوانی می‌شود که مستقیماً از طریق CLI درخواست شده‌اند، و نه برای stepهایی که وابستگی stepهای دیگر هستند.

    نقاط ورود

    پیش از رسیدن به کد اصلی Bootstrap چند گام مقدماتی وجود دارد:

    1. اسکریپت shell یا make: ./x یا ./x.ps1 یا make
    2. اسکریپت پوششی برای راحتی کار: x.py
    3. src/bootstrap/bootstrap.py
    4. src/bootstrap/src/bin/main.rs

    برای توضیح دقیق‌تر جزئیات پیاده‌سازی، src/bootstrap/README.md را ببینید.
