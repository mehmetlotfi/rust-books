    cfg(bootstrap) در وابستگی‌های کامپایلر

    کامپایلر Rust از چند crate خارجی استفاده می‌کند که ممکن است با خود کامپایلر به وابستگی چرخه‌ای برسند: کامپایلر برای ساخت شدن به نسخه به‌روز یک crate نیاز دارد، اما آن crate به نسخه به‌روز کامپایلر نیاز دارد. این صفحه توضیح می‌دهد که چگونه می‌توان با #[cfg(bootstrap)] این چرخه را شکست.

    فعال‌سازی #[cfg(bootstrap)]

    معمولاً استفاده از #[cfg(bootstrap)] در یک crate خارجی یک هشدار ایجاد می‌کند:

    warning: unexpected `cfg` condition name: `bootstrap`
 --> src/main.rs:1:7
  |
1 | #[cfg(bootstrap)]
  |       ^^^^^^^^^
  |
  = help: expected names are: `docsrs`, `feature`, and `test` and 31 more
  = help: consider using a Cargo feature instead
  = help: or consider adding in `Cargo.toml` the `check-cfg` lint config for the lint:
           [lints.rust]
           unexpected_cfgs = { level = "warn", check-cfg = ['cfg(bootstrap)'] }
  = help: or consider adding `println!("cargo::rustc-check-cfg=cfg(bootstrap)");` to the top of the `build.rs`
  = note: see <https://doc.rust-lang.org/nightly/rustc/check-cfg/cargo-specifics.html> for more information about checking conditional configuration
  = note: `#[warn(unexpected_cfgs)]` on by default

    می‌توان با افزودن این خط‌ها به فایل Cargo.toml پروژه این هشدار را خاموش کرد:

    [lints.rust]
unexpected_cfgs = { level = "warn", check-cfg = ['cfg(bootstrap)'] }

    اکنون می‌توان #[cfg(bootstrap)] را در crate درست مانند خود کامپایلر به کار برد: وقتی از کامپایلر bootstrap استفاده می‌شود، کدی که با #[cfg(bootstrap)] علامت‌گذاری شده کامپایل می‌شود، و در غیر این صورت کدی که با #[cfg(not(bootstrap))] علامت‌گذاری شده کامپایل می‌شود.

    رقص به‌روزرسانی

    به عنوان یک مثال مشخص، تغییری را در نظر می‌گیریم که در آن attribute با نام #[naked] به یک attribute ناایمن (unsafe) تبدیل شد و همین موضوع یک وابستگی چرخه‌ای با crate با نام compiler-builtins ایجاد کرد.

    گام ۱: پذیرفتن رفتار جدید در کامپایلر (#139797)

    در این مثال می‌توان با غیرفعال کردن یک خطا، هم رفتار قدیمی و هم رفتار جدید را همزمان پذیرفت.

    گام ۲: به‌روزرسانی crate (#821)

    حالا در crate از #[cfg(bootstrap)] برای استفاده از رفتار قدیمی و از #[cfg(not(bootstrap))] برای استفاده از رفتار جدید بهره بگیرید.

    گام ۳: به‌روزرسانی نسخه crate مورد استفاده کامپایلر (#139934)

    برای compiler-builtins این کار به معنای افزایش شماره نسخه بود؛ در موارد دیگر ممکن است به‌روزرسانی یک git submodule باشد.

    گام ۴: حذف رفتار قدیمی از کامپایلر (#139753)

    اکنون می‌توان از crate به‌روزشده استفاده کرد. در این مثال، این یعنی رفتار قدیمی را می‌توان حذف کرد.
