    افزودن یک هدف جدید

    این‌ها مجموعه‌ای از مراحل برای افزودن پشتیبانی از یک هدف جدید هستند. حالت‌های نهایی و مسیرهای رسیدن به آنها بسیار متنوع‌اند، بنابراین ممکن است همهٔ بخش‌ها به مقصود شما مربوط نباشند.

    همچنین مستندات مربوطه را در سیاست ردهٔ هدف‌ها ببینید.

    تعیین یک LLVM جدید

    برای هدف‌های بسیار جدید، ممکن است لازم باشد از فورک متفاوتی از LLVM نسبت به آنچه در حال حاضر همراه Rust ارائه می‌شود استفاده کنید. در این صورت، به زیرماژول git به نام src/llvm-project بروید (ممکن است لازم باشد دست‌کم یک بار ./x check را اجرا کنید تا زیرماژول به‌روز شود)، کامیت مناسب فورک خود را checkout کنید، سپس آن ارجاع جدید زیرماژول را در مخزن اصلی Rust کامیت کنید.

    یک مثال این است:

    cd src/llvm-project
git remote add my-target-llvm some-llvm-repository
git checkout my-target-llvm/my-branch
cd ..
git add llvm-project
git commit -m 'Use my custom LLVM'

    استفاده از LLVM از پیش ساخته‌شده

    اگر یک checkout محلی از LLVM دارید که از قبل ساخته شده است، ممکن است بتوانید Rust را طوری پیکربندی کنید که ساخت شما را به‌عنوان LLVM سیستم در نظر بگیرد تا از ساخت‌های تکراری جلوگیری شود.

    می‌توانید با استفاده از بخش target در bootstrap.toml به Rust بگویید از نسخهٔ از پیش ساخته‌شدهٔ LLVM استفاده کند:

    [target.x86_64-unknown-linux-gnu]
llvm-config = "/path/to/llvm/llvm-7.0.1/bin/llvm-config"

    اگر قصد دارید از LLVM سیستم استفاده کنید، پیش‌تر مسیرهای زیر را مشاهده کرده‌ایم، اگرچه ممکن است در سیستم شما متفاوت باشند:

    • /usr/bin/llvm-config-8
    • /usr/lib/llvm-8/bin/llvm-config

    توجه کنید که باید ابزار FileCheck از LLVM نصب شده باشد، که برای آزمون‌های codegen استفاده می‌شود. این ابزار معمولاً همراه LLVM ساخته می‌شود، اما اگر از LLVM از پیش نصب‌شدهٔ خودتان استفاده می‌کنید، باید FileCheck را به روش دیگری فراهم کنید. در سیستم‌های مبتنی بر Debian می‌توانید بستهٔ llvm-N-tools را نصب کنید (که N شمارهٔ نسخهٔ LLVM است، مثلاً llvm-8-tools). به‌طور جایگزین، می‌توانید مسیر FileCheck را با گزینهٔ پیکربندی llvm-filecheck در bootstrap.toml مشخص کنید یا می‌توانید آزمون codegen را با گزینهٔ rust.codegen-tests در bootstrap.toml غیرفعال کنید.

    ساخت یک مشخصات هدف

    باید با یک فایل JSON هدف شروع کنید. می‌توانید مشخصات یک هدف موجود را با --print target-spec-json ببینید:

    rustc -Z unstable-options --target=wasm32-unknown-unknown --print target-spec-json

    آن JSON را در یک فایل ذخیره کنید و آن را متناسب با هدف خود تغییر دهید.

    افزودن مشخصات هدف

    پس از اینکه یک مشخصات JSON را تکمیل کردید و توانستید تا حدی با موفقیت کامپایل کنید، می‌توانید مشخصات را در خود کامپایلر کپی کنید.

    باید یک خط به جدول بزرگ درون ماکروی supported_targets در ماژول rustc_target::spec اضافه کنید. سپس یک فایل متناظر برای هدف جدید خود اضافه می‌کنید که شامل یک تابع target است.

    به هدف‌های موجود به‌عنوان نمونه نگاه کنید.

    برای استفاده از این هدف در bootstrap، باید سه‌گانهٔ هدف (target triple) را به‌طور صریح به فهرست STAGE0_MISSING_TARGETS در src/bootstrap/src/core/sanity.rs اضافه کنیم. این کار لازم است زیرا کامپایلر پیش‌فرض bootstrap (که معمولاً یک کامپایلر beta است) هدف جدیدی را که اضافه کرده‌ایم نمی‌شناسد. بنابراین باید به STAGE0_MISSING_TARGETS اضافه شود تا bootstrap بداند که این هدف هنوز توسط کامپایلر stage0 پشتیبانی نمی‌شود.

    const STAGE0_MISSING_TARGETS: &[&str] = &[
+   "NEW_TARGET_TRIPLE"
];

    وصله کردن crateها

    ممکن است لازم باشد در crateهایی که کامپایلر به آنها وابسته است تغییراتی ایجاد کنید، مانند libc یا cc. در این صورت می‌توانید از قابلیت [patch] در Cargo استفاده کنید. برای مثال، اگر می‌خواهید از نسخهٔ منتشرنشدهٔ libc استفاده کنید، می‌توانید آن را به فایل Cargo.toml سطح بالا اضافه کنید:

    diff --git a/Cargo.toml b/Cargo.toml
index 1e83f05e0ca..4d0172071c1 100644
--- a/Cargo.toml
+++ b/Cargo.toml
@@ -113,6 +113,8 @@ cargo-util = { path = "src/tools/cargo/crates/cargo-util" }
 [patch.crates-io]
+libc = { git = "https://github.com/rust-lang/libc", rev = "0bf7ce340699dcbacabdf5f16a242d2219a49ee0" }

 # See comments in `src/tools/rustc-workspace-hack/README.md` for what's going on
 # here
 rustc-workspace-hack = { path = 'src/tools/rustc-workspace-hack' }

    پس از این، cargo update -p libc را اجرا کنید تا lockfileها به‌روز شوند.

    مراقب باشید که اگر به یک وابستگی محلی از نوع path وصله کنید، این کار هشدارهای آن وابستگی را فعال می‌کند. برخی وابستگی‌ها عاری از هشدار نیستند، و به دلیل تنظیم rust.deny-warnings در bootstrap.toml، ممکن است ساخت ناگهان شروع به شکست کند. برای دور زدن هشدارها، ممکن است بخواهید:

    • وابستگی را برای رفع هشدارها تغییر دهید
    • یا برای اهداف توسعهٔ محلی، هشدارها را با تنظیم rust.deny-warnings = false در bootstrap.toml سرکوب کنید.

    کامپایل متقابل

    وقتی مشخصات هدف را هم به‌صورت JSON و هم در کد داشته باشید، می‌توانید rustc را کامپایل متقابل کنید:

    DESTDIR=/path/to/install/in \
./x install -i --stage 1 --host aarch64-apple-darwin.json --target aarch64-apple-darwin \
compiler/rustc library/std

    اگر مشخصات هدف شما از قبل در کامپایلر bootstrap موجود باشد، می‌توانید به‌جای فایل JSON برای هر دو آرگومان از آن استفاده کنید.

    ارتقای یک هدف از ردهٔ 2 (هدف) به ردهٔ 2 (میزبان)

    دو سطح از هدف‌های ردهٔ 2 وجود دارد:

    • هدف‌هایی که فقط کامپایل متقابل می‌شوند (rustup target add)
    • هدف‌هایی که toolchain بومی دارند (rustup toolchain install)

    برای نمونه‌ای از ارتقای یک هدف از کامپایل متقابل به بومی، #75914 را ببینید.
