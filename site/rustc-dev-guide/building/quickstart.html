راهنمای توسعهٔ rustcrustc Development Guide

    شروع سریع

    این یک راهنمای شروع سریع برای راه‌اندازی کامپایلر است. برای اطلاعات بیشتر دربارهٔ مراحل جداگانه، صفحه‌های دیگر این فصل را ببینید.

    ابتدا مخزن را کلون کنید:

    git clone https://github.com/rust-lang/rust.git
cd rust

    هنگام ساخت کامپایلر، مستقیماً از cargo استفاده نمی‌کنیم؛ در عوض از یک پوشش به نام «x» استفاده می‌کنیم که با ./x فراخوانی می‌شود.

    باید یک پیکربندی برای ساخت ایجاد کنیم. از ./x setup برای ساخت یک پیکربندی پیش‌فرض مناسب استفاده کنید.

    ./x setup

    سپس می‌توانیم کامپایلر را بسازیم. از ./x build برای ساخت کامپایلر، کتابخانهٔ استاندارد و چند ابزار استفاده کنید. همچنین می‌توانید ./x check را برای فقط بررسی آن اجرا کنید. همهٔ این دستورها می‌توانند مؤلفه‌ها/مسیرهای مشخصی را به‌عنوان آرگومان بگیرند، برای مثال ./x check compiler برای بررسی فقط کامپایلر.

    ./x build

    هنگام ایجاد تغییری در کامپایلر که روی نحوهٔ کامپایل کتابخانهٔ استاندارد تأثیر نمی‌گذارد (مثلاً تغییر در یک پیام خطا)، از --keep-stage-std 1 استفاده کنید تا از کامپایل مجدد آن جلوگیری شود.

    پس از ساخت کامپایلر و کتابخانهٔ استاندارد، اکنون یک toolchain کامپایلر کارکن دارید. می‌توانید با لینک کردن آن، با rustup از آن استفاده کنید.

    rustup toolchain link stage1 build/host/stage1

    توجه: اگر از ./x setup tools استفاده کنید، مرحلهٔ پیش‌فرض به‌جای 1 روی 2 تنظیم می‌شود. دستور خود را بر این اساس تنظیم کنید:

    rustup toolchain link stage2 build/host/stage2

    اکنون یک toolchain به نام stage1 دارید که به ساخت شما لینک شده است. می‌توانید از آن برای آزمودن کامپایلر استفاده کنید.

    rustc +stage1 testfile.rs

    پس از ایجاد یک تغییر، می‌توانید مجموعه آزمون کامپایلر را با ./x test اجرا کنید.

    ./x test مجموعه آزمون کامل را اجرا می‌کند، که کند است و به‌ندرت چیزی است که می‌خواهید. معمولاً پس از تغییر در کامپایلر، ./x test tests/ui چیزی است که می‌خواهید، که همهٔ آزمون‌های UI را که کامپایلر را روی یک فایل آزمون مشخص فراخوانی می‌کنند و خروجی را بررسی می‌کنند، آزمایش می‌کند.

    ./x test tests/ui

    اگر تغییری داده‌اید و می‌خواهید فایل‌های .stderr را با خروجی جدید به‌روز کنید، از --bless استفاده کنید.

    تبریک، اکنون آمادهٔ ایجاد تغییر در کامپایلر هستید! اگر سؤال‌های بیشتری دارید، فصل کامل ممکن است پاسخ‌ها را داشته باشد، و اگر نداشت، با خیال راحت در Zulip درخواست کمک کنید.

    اگر از VSCode، Vim، Emacs، Helix یا Zed استفاده می‌کنید، ./x setup از شما می‌پرسد که آیا می‌خواهید پیکربندی ویرایشگر را راه‌اندازی کنید. برای اطلاعات بیشتر، روندهای کاری پیشنهادی را ببینید.
