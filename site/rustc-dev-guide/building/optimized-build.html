راهنمای توسعهٔ rustcrustc Development Guide

    ساخت بهینه‌شدهٔ کامپایلر

    گزینه‌ها و تکنیک‌های پیکربندی ساخت متعددی وجود دارد که می‌توان برای کامپایل یک نسخهٔ rustc که تا حد ممکن بهینه باشد (مثلاً هنگام ساخت rustc برای یک توزیع لینوکس) از آنها استفاده کرد. وضعیت این گزینه‌های پیکربندی برای هدف‌های مختلف Rust اینجا پیگیری می‌شود. این صفحه توضیح می‌دهد که هنگام ساخت rustc توسط خودتان چگونه می‌توانید از این رویکردها استفاده کنید.

    بهینه‌سازی زمان لینک

    بهینه‌سازی زمان لینک (link-time optimization) تکنیک قدرتمندی در کامپایلر است که می‌تواند کارایی برنامه را افزایش دهد. برای فعال کردن (Thin-)LTO هنگام ساخت rustc، گزینهٔ پیکربندی rust.lto را روی "thin" در bootstrap.toml تنظیم کنید:

    rust.lto = "thin"

    توجه کنید که LTO برای rustc در حال حاضر فقط برای هدف x86_64-unknown-linux-gnu پشتیبانی و آزمایش می‌شود. هدف‌های دیگر ممکن است کار کنند، اما هیچ تضمینی ارائه نمی‌شود. به‌ویژه، rustc بهینه‌شده با LTO در حال حاضر در ویندوز کامپایل نادرست تولید می‌کند.

    فعال کردن LTO در لینوکس تا ۱۰٪ افزایش سرعت ایجاد کرده است.

    تخصیص‌دهندهٔ حافظه

    استفاده از یک تخصیص‌دهندهٔ حافظهٔ متفاوت برای rustc می‌تواند مزایای کارایی قابل‌توجهی داشته باشد. اگر می‌خواهید تخصیص‌دهندهٔ jemalloc را فعال کنید، می‌توانید گزینهٔ build.allocator را روی jemalloc در bootstrap.toml تنظیم کنید:

    build.allocator = "jemalloc"

    توجه کنید که این گزینه در حال حاضر فقط برای هدف‌های لینوکس و macOS پشتیبانی می‌شود.

    واحدهای codegen

    کاهش تعداد واحدهای codegen در هر crate از rustc می‌تواند ساخت سریع‌تری از کامپایلر تولید کند. می‌توانید تعداد واحدهای codegen را برای rustc و libstd در bootstrap.toml با گزینه‌های زیر تغییر دهید:

    rust.codegen-units = 1
rust.codegen-units-std = 1

    مجموعه دستورالعمل

    به‌طور پیش‌فرض، rustc برای یک معماری مجموعه دستورالعمل عمومی (و محافظه‌کارانه) (بسته به هدف انتخاب‌شده) کامپایل می‌شود تا از تا حد امکان CPUهای بیشتری پشتیبانی کند. اگر می‌خواهید rustc را برای یک معماری مجموعه دستورالعمل مشخص کامپایل کنید، می‌توانید گزینهٔ کامپایلر target_cpu را در RUSTFLAGS تنظیم کنید:

    RUSTFLAGS="-C target_cpu=x86-64-v3" ./x build ...

    اگر می‌خواهید LLVM را هم برای یک مجموعه دستورالعمل مشخص کامپایل کنید، می‌توانید flagهای llvm را در bootstrap.toml تنظیم کنید:

    llvm.cxxflags = "-march=x86-64-v3"
llvm.cflags = "-march=x86-64-v3"

    بهینه‌سازی مبتنی بر پروفایل

    اعمال بهینه‌سازی‌های مبتنی بر پروفایل (یا به‌طور کلی‌تر، بهینه‌سازی‌های هدایت‌شده با بازخورد) می‌تواند کارایی rustc را تا ۱۵٪ به‌طور چشمگیری افزایش دهد (1، 2). با این حال، این تکنیک‌ها صرفاً با یک گزینهٔ پیکربندی فعال نمی‌شوند، بلکه به یک روند ساخت پیچیده نیاز دارند که rustc را چندین بار کامپایل می‌کند و آن را روی benchmarkهای انتخاب‌شده پروفایل می‌کند.

    ابزاری به نام opt-dist وجود دارد که برای بهینه‌سازی rustc با PGO (بهینه‌سازی‌های مبتنی بر پروفایل) و BOLT (یک بهینه‌ساز باینری پس از لینک) در ساخت‌هایی که برای کاربران نهایی توزیع می‌شوند به کار می‌رود. می‌توانید این ابزار را که در src/tools/opt-dist قرار دارد بررسی کنید و بر پایهٔ آن یک روند ساخت PGO سفارشی بسازید، یا سعی کنید مستقیماً از آن استفاده کنید. توجه کنید که این ابزار در حال حاضر کاملاً به شیوه‌ای که در روندهای یکپارچه‌سازی پیوستهٔ Rust از آن استفاده می‌کنیم وابسته است، و ممکن است برای کار کردن در یک محیط متفاوت به تغییراتی سفارشی نیاز داشته باشد.

    برای استفاده از این ابزار باید برخی وابستگی‌های خارجی را فراهم کنید:

    • یک مفسر Python3 (برای اجرای x.py).
    • toolchain کامپایل‌شدهٔ LLVM، همراه با باینری llvm-profdata. به‌صورت اختیاری، اگر می‌خواهید از BOLT استفاده کنید، باینری‌های llvm-bolt و merge-fdata باید در toolchain موجود باشند.

    این وابستگی‌ها توسط یک پیاده‌سازی از ساختار Environment به opt-dist داده می‌شوند. این ساختار پوشه‌هایی را مشخص می‌کند که خط لولهٔ PGO/BOLT در آنها اجرا می‌شود، و همچنین وابستگی‌های خارجی مانند Python یا LLVM را.

    در اینجا مثالی از نحوهٔ استفادهٔ محلی از opt-dist (خارج از CI) آمده است:

    1. در فایل bootstrap.toml خود metrics را فعال کنید، چون opt-dist انتظار دارد فعال باشد: toml build.metrics = true 
      build.metrics = true
    2. ابزار را با دستور زیر بسازید: 
      ./x build tools/opt-dist
    3. ابزار را با حالت local اجرا کنید و پارامترهای لازم را بدهید: 
      ./build/host/stage1-tools-bin/opt-dist local \
  --target-triple <target> \ # select target, e.g. "x86_64-unknown-linux-gnu"
  --checkout-dir <path>    \ # path to rust checkout, e.g. "."
  --llvm-dir <path>        \ # path to built LLVM toolchain, e.g. "/foo/bar/llvm/install"
  -- ./x dist       # pass the actual build command
      می‌توانید --help را اجرا کنید تا پارامترهای دیگری را که می‌توانید تغییر دهید ببینید.

    توجه: اگر می‌خواهید به‌جای اجرای محلی opt-dist، خط لولهٔ واقعی CI را اجرا کنید، می‌توانید cargo run --manifest-path src/ci/citool/Cargo.toml run-local dist-x86_64-linux را اجرا کنید.
