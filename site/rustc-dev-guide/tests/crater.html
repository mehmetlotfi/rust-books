    Crater

    Crater ابزاری است برای کامپایل و اجرای تست‌های هر crate در crates.io (و چند crate در GitHub). عمدتاً برای بررسی میزان شکستگی هنگام پیاده‌سازی تغییرات بالقوه شکننده و تضمین نبود شکستگی با اجرای نسخهٔ beta در برابر stable کامپایلر به‌کار می‌رود.

    چه وقت Crater را اجرا کنیم

    اگر PR شما تغییرات بزرگی در کامپایلر ایجاد می‌کند یا می‌تواند باعث شکستگی شود، باید درخواست اجرای Crater بدهید. اگر مطمئن نیستید، بی‌تعارف از بازبین PR خود بپرسید.

    Requesting Crater Runs

    تیم Rust چند ماشین نگه می‌دارد که می‌توان برای اجرای Crater روی تغییرات یک PR از آن‌ها استفاده کرد. اگر PR شما به اجرای Crater نیاز دارد، در رشتهٔ PR یک کامنت برای تیم triage بگذارید. لطفاً به تیم بگویید آیا اجرای Crater از نوع «فقط بررسی (check-only)»، «فقط ساخت (build only)» یا «ساخت و تست (build-and-test)» لازم دارید. تفاوت عمدتاً در زمان است؛ اگر مطمئن نیستید، ساخت و تست را انتخاب کنید. اگر تغییراتی می‌دهید که فقط در زمان کامپایل اثر دارند (مثلاً پیاده‌سازی trait جدید)، فقط اجرای بررسی لازم دارید.

    PR شما توسط تیم triage در صف قرار می‌گیرد و نتایج هنگام آماده‌شدن ارسال می‌شوند. اجراهای بررسی حدود ۳ تا ۴ روز طول می‌کشند و دو نوع دیگر به‌طور متوسط ۵ تا ۶ روز.

    هرچند Crater واقعاً مفید است، مهم است از چند محدودیت آگاه باشید:

    • همهٔ کدها در crates.io نیستند! کد زیادی در مخازن GitHub و جاهای دیگر هست. همچنین ممکن است شرکت‌ها نخواهند کدشان را منتشر کنند. بنابراین اجرای موفق Crater به معنای نبود شکستگی نیست؛ همچنان باید محتاط باشید.

    • Crater فقط ساخت‌های لینوکس روی x86_64 را اجرا می‌کند. بنابراین معماری‌ها و پلتفرم‌های دیگر تست نمی‌شوند. مهم‌تر اینکه این شامل ویندوز می‌شود.

    • بسیاری از crateها تست نمی‌شوند. این می‌تواند دلایل زیادی داشته باشد، از جمله اینکه crate دیگر کامپایل نمی‌شود (مثلاً از قابلیت‌های قدیمی nightly استفاده می‌کرده)، تست‌های شکسته یا flaky دارد، به دسترسی شبکه نیاز دارد، یا دلایل دیگر.

    • پیش از اجرای Crater، @bors try باید در ساخت آرتیفکت‌ها موفق شود. یعنی اگر کد شما کامپایل نمی‌شود، نمی‌توانید Crater را اجرا کنید.
