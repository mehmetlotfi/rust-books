    RUSTC_BOOTSTRAP و پایداری

    این یک جزئیات پیاده‌سازی در bootstrap/کامپایلر است، اما می‌تواند برای تست هم مفید باشد:

    • RUSTC_BOOTSTRAP=1 «تقلب» می‌کند و بررسی معمول پایداری را دور می‌زند، و اجازه می‌دهد از قابلیت‌ها و پرچم‌های cli ناپایدار روی rustc stable استفاده کنید.
    • RUSTC_BOOTSTRAP=-1 یک rustc مشخص را مجبور می‌کند وانمود کند کامپایلر stable است، حتی اگر در واقع rustc از نوع nightly باشد. این مفید است چون برخی رفتارهای کامپایلر (مثلاً پیام‌های تشخیصی) بسته به اینکه کامپایلر nightly است یا نه می‌توانند فرق کنند.

    توجه کنید که تنظیم RUSTC_BOOTSTRAP در تست‌های ui (مثلاً از طریق //@ rustc-env) بی‌معنی است چون تست‌های ui متغیر محیطی bootstrap را از bootstrap به ارث می‌برند (پس به‌طور پیش‌فرض روی 1 تنظیم است)، و چون خود compiletest پرچم‌های -Z می‌دهد (پس -1 تست را می‌شکند). برای تست رفتار فقط‌stable باید به‌جای آن تست run-make بنویسید.

    برای تست‌های run-make/run-make-cargo، //@ rustc-env پشتیبانی نمی‌شود. برای فراخوانی‌های جداگانهٔ rustc می‌توانید کاری شبیه این بکنید.

    use run_make_support::rustc;

fn main() {
    rustc()
        // Pretend that I am very stable
        .env("RUSTC_BOOTSTRAP", "-1")
        //...
        .run();
}
