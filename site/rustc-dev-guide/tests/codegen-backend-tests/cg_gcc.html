    GCC codegen backend

    ما زیرمجموعه‌ای از مجموعهٔ تست کامپایلر را با backend تولید کد GCC در CI اجرا می‌کنیم تا تغییراتی را که می‌توانند یکپارچگی این backend با کامپایلر را بشکنند پیدا کنیم.

    اگر با هر باگ یا مشکلی در backend تولید کد GCC روبه‌رو شدید، تردید نکنید و issue را در مخزن rustc_codegen_gcc باز کنید.

    توجه کنید که این backend فعلاً فقط از هدف x86_64-unknown-linux-gnu پشتیبانی می‌کند.

    مواجهه با خطاهای CI مربوط به backend در GCC

    اگر با خطایی مرتبط با تست‌های اجراشده با backend تولید کد GCC در CI در job با نام test-x86_64-gnu-gcc روبه‌رو شدید، می‌توانید از دستور زیر برای اجرای محلی تست‌های UI با backend مربوط به GCC استفاده کنید که آنچه را در CI رخ می‌دهد بازتولید می‌کند:

    ./x test tests/ui \
  --set 'rust.codegen-backends = ["llvm", "gcc"]' \
  --set 'rust.debug-assertions = false' \
  --test-codegen-backend gcc

    اگر مجموعهٔ تست دیگری در CI شکست خورده، باید بخش tests/ui را تغییر دهید.

    برای بازتولید کل job در CI به‌صورت محلی می‌توانید cargo run --manifest-path src/ci/citool/Cargo.toml run-local test-x86_64-gnu-gcc را اجرا کنید. برای اطلاعات بیشتر تست با Docker را ببینید.

    اگر job مربوط به GCC شکست خورد چه کنیم؟

    اگر تست job مربوط به GCC شکست خورد و به نظر می‌رسد شکست می‌تواند ناشی از backend مربوط به GCC باشد، می‌توانید با @rust-lang/wg-gcc-backend گروه کاری cg-gcc را ping کنید

    اگر رفع یک تست کامپایلر که با backend مربوط به GCC شکست می‌خورد ساده نیست، می‌توانید با directive در compiletest به شکل //@ ignore-backends: gcc آن تست را هنگام اجرا با cg_gcc نادیده بگیرید.

    انتخاب اینکه کدام backendهای تولید کد ساخته شوند

    گزینهٔ bootstrap با نام rust.codegen-backends = [...] بر اینکه کدام backendهای تولید کد ساخته و در sysroot مربوط به rustc تولیدشده گنجانده شوند اثر می‌گذارد. برای استفاده از backend تولید کد GCC، باید "gcc" در این آرایه در bootstrap.toml باشد:

    rust.codegen-backends = ["llvm", "gcc"]

    اگر نمی‌خواهید فایل bootstrap.toml خود را تغییر دهید، می‌توانید دستورهای x را با --set 'rust.codegen-backends=["llvm", "gcc"]' اجرا کنید. برای مثال:

    ./x build --set 'rust.codegen-backends=["llvm", "gcc"]'

    اولین backend در آرایهٔ codegen-backends تعیین می‌کند کدام backend به‌عنوان backend پیش‌فرض rustc ساخته‌شده به‌کار رود. این همچنین تعیین می‌کند کدام backend برای کامپایل کتابخانهٔ استاندارد stage 1 (یا هر چیزی که در stage 2 به بعد ساخته می‌شود) استفاده شود. برای تولید rustcای که به‌طور پیش‌فرض از backend مربوط به GCC استفاده می‌کند، می‌توانید "gcc" را اولین عنصر این آرایه بگذارید:

    ./x build --set 'rust.codegen-backends=["gcc"]' library

    انتخاب backend تولید کدی که در تست‌ها استفاده می‌شود

    برای اجرای تست‌های کامپایلر با backend تولید کد GCC برای ساخت برنامه‌های Rust تست، می‌توانید از پرچم --test-codegen-backend استفاده کنید:

    ./x test tests/ui --test-codegen-backend gcc

    توجه کنید که برای کارکردن این، کامپایلر تست‌شده باید backend تولید کد GCC را در پوشهٔ sysroot خود در دسترس داشته باشد.

    دانلود GCC از CI

    گزینهٔ bootstrap با نام gcc.download-ci-gcc کنترل می‌کند GCC (که وابستگی backend تولید کد GCC است) از CI دانلود شود یا به‌صورت محلی ساخته شود. مقدار پیش‌فرض true است که GCC را از CI دانلود می‌کند اگر هیچ تغییر محلی در منابع GCC نباشد و هدف میزبان داده‌شده در CI در دسترس باشد.

    ارائهٔ GCC شخصی خودتان

    مواردی هست که می‌خواهید فایل libgccjit.so خودتان را ارائه دهید. یک مورد وقتی است که می‌خواهید rustc را برای هدف دیگری cross-compile کنید چون GCC کامپایلر چندهدفه نیست. برای پشتیبانی از این مورد، گزینهٔ bootstrap با نام gcc.libgccjit-libs-dir هست. این گزینه gcc.download-ci-gcc را بازنویسی می‌کند، یعنی libgccjit.so توسط bootstrap دانلود یا به‌صورت محلی ساخته نخواهد شد. ساختار پوشهٔ آن <host>/<target>/libgccjit.so است، برای مثال:

    .
├── m68k-unknown-linux-gnu
│   └── m68k-unknown-linux-gnu
│       └── libgccjit.so
└── x86_64-unknown-linux-gnu
    ├── m68k-unknown-linux-gnu
    │   └── libgccjit.so
    └── x86_64-unknown-linux-gnu
        └── libgccjit.so

    اجرای تست‌های خود backend

    علاوه بر اجرای مجموعه‌های تست کامپایلر با backend تولید کد GCC، می‌توانید مجموعهٔ تست خود backend را هم اجرا کنید.

    اکنون این کار را با دستور زیر انجام می‌دهید:

    ./x test rustc_codegen_gcc

    برای کارکردن این، backend باید فعال شده باشد.
