    Performance testing

    Performance considerations

    عملکرد کامپایلر مهم است. در چند سال گذشته تلاش زیادی صرف بهبود تدریجی آن کرده‌ایم.

    اگر گمان می‌کنید تغییر شما ممکن است باعث رگرسیون (یا بهبود) عملکرد شود، می‌توانید «perf run» درخواست کنید (و بازبین شما هم ممکن است پیش از تأیید درخواست کند). این ربات دیگری است که مجموعه‌ای از benchmarkها را روی کامپایلری با تغییرات شما کامپایل می‌کند. عددها اینجا گزارش می‌شوند، و می‌توانید مقایسهٔ تغییرات خود با آخرین main را ببینید.

    برای آشنایی با عملکرد کد Rust به‌طور کلی که برای توسعهٔ rustc هم مفید است، کتاب عملکرد Rust را ببینید.

    rustc-perf

    کار زیادی صرف بهبود عملکرد کامپایلر و جلوگیری از رگرسیون عملکرد می‌شود.

    پروژهٔ rustc-perf چند سرویس برای تست و پیگیری عملکرد فراهم می‌کند. زیرساخت میزبانی‌شده‌ای برای اجرای benchmarkها به‌صورت سرویس ارائه می‌دهد. در حال حاضر فقط ساخت‌های x86_64-unknown-linux-gnu پیگیری می‌شوند.

    «perf run» برای مقایسهٔ عملکرد کامپایلر در پیکربندی‌های مختلف برای مجموعهٔ بزرگی از crateهای محبوب به‌کار می‌رود. پیکربندی‌های مختلف شامل «ساخت‌های تازه»، ساخت‌ها با کامپایل افزایشی و مانند آن است.

    نتیجهٔ یک perf run مقایسه‌ای بین دو نسخه از کامپایلر است (با commit hash آن‌ها).

    همچنین می‌توانید از rustc-perf برای benchmark و profile دستی کامپایلر به‌صورت محلی استفاده کنید.

    Automatic perf runs

    پس از merge شدن هر PR، مجموعه‌ای از benchmarkها روی کامپایلر اجرا می‌شود. نتایج در طول زمان در وب‌سایت https://perf.rust-lang.org/ پیگیری می‌شوند. هر تغییری در کامنتی روی PR ذکر می‌شود.

    Manual perf runs

    علاوه بر این، تست‌های عملکرد را می‌توان پیش از merge شدن یک PR بنا به نیاز اجرا کرد. اگر PR شما ممکن است بر عملکرد اثر بگذارد، باید درخواست perf run بدهید، به‌ویژه اگر می‌تواند عملکرد را بدتر کند.

    برای ارزیابی اثر عملکردی یک PR، این کامنت را روی PR بنویسید:

    @bors try @rust-timer queue

    نکته: فقط کاربرانی که مجوز اجرای perf دارند می‌توانند این کامنت را بگذارند. تیم‌هایی که مجاز به استفاده از آن هستند در مخزن Teams با مقدار perf = true در بخش [permissions] پیگیری می‌شوند (و مجوزهای bors هم لازم است). اگر عضو یکی از آن تیم‌ها نیستید، از کسی بخواهید برایتان بگذارد (در Zulip یا از بازبین تعیین‌شده).

    این ابتدا به bors می‌گوید یک ساخت «try» انجام دهد که ساخت کامل release برای x86_64-unknown-linux-gnu است. پس از پایان ساخت، آن را در صف اجرای مجموعهٔ عملکرد قرار می‌دهد. پس از پایان تست‌های عملکرد، ربات روی PR کامنتی با خلاصه و پیوند به گزارش کامل می‌گذارد.

    اگر می‌خواهید perf run را برای آرتیفکتی که از قبل ساخته شده (مثلاً برای ساخت try قبلی که هنوز benchmark نشده) انجام دهید، می‌توانید به‌جای آن این را اجرا کنید:

    @rust-timer build <commit-sha>

    البته نمی‌توانید یک آرتیفکت را دو بار benchmark کنید.

    اطلاعات بیشتر دربارهٔ دستورهای در دسترس ربات perf را اینجا می‌یابید.
