راهنمای توسعهٔ rustcrustc Development Guide

    تست‌کردن کامپایلر

    پروژهٔ Rust طیف گسترده‌ای از تست‌های مختلف را اجرا می‌کند، که توسط سامانهٔ ساخت (./x test) هماهنگ می‌شوند. این بخش نمای کلی کوتاهی از ابزارهای مختلف تست ارائه می‌دهد. فصل‌های بعدی به اجرای تست‌ها و افزودن تست‌های جدید می‌پردازند.

    انواع تست‌ها

    چند نوع تست برای محک‌زدن بخش‌های مختلف توزیع Rust وجود دارد. تقریباً همهٔ آن‌ها با ./x test اجرا می‌شوند، با چند استثنا که در ادامه آمده است.

    Compiletest

    تست‌هارنس اصلی برای تست خود کامپایلر ابزاری به نام compiletest است.

    compiletest از اجرای سبک‌های مختلف تست پشتیبانی می‌کند، که در مجموعه‌های تست (test suites) سازمان‌دهی شده‌اند. حالت تست (test mode) می‌تواند پیش‌تنظیم‌ها/رفتار مشترکی را برای مجموعه‌ای از مجموعه‌های تست فراهم کند. تست‌هایی که compiletest پشتیبانی می‌کند در پوشهٔ tests قرار دارند.

    فصل Compiletest به جزئیات نحوهٔ استفاده از این ابزار می‌پردازد.

    Example: ./x test tests/ui

    Package tests

    کتابخانهٔ استاندارد و بسیاری از بسته‌های کامپایلر شامل تست‌های واحد #[test] معمول Rust، تست‌های یکپارچگی و تست‌های مستندات هستند. می‌توانید برای تقریباً هر بسته در پوشهٔ library/ یا compiler/ مسیری به ./x test بدهید، و x اساساً cargo test را روی آن بسته اجرا می‌کند.

    Examples:

    CommandDescription
    ./x test library/stdفقط تست‌های std را اجرا می‌کند
    ./x test library/coreفقط تست‌های core را اجرا می‌کند
    ./x test compiler/rustc_data_structuresتست‌های rustc_data_structures را اجرا می‌کند

    کتابخانهٔ استاندارد برای پوشش قابلیت‌هایش به‌شدت به تست‌های مستندات (doctest) تکیه دارد. اما در صورت نیاز می‌توان از تست‌های واحد و یکپارچگی هم استفاده کرد. تقریباً همهٔ بسته‌های کامپایلر doctestها را غیرفعال دارند.

    همهٔ تست‌های واحد کتابخانهٔ استاندارد و کامپایلر در فایل جداگانهٔ tests قرار می‌گیرند (که در tidy اعمال می‌شود). این تضمین می‌کند وقتی فایل تست تغییر می‌کند، crate نیازی به کامپایل مجدد ندارد. برای مثال:

    #[cfg(test)]
mod tests;

    اگر این‌طور نبود، و روی چیزی مثل core کار می‌کردید، لازم می‌شد کل کتابخانهٔ استاندارد و کل rustc دوباره کامپایل شود.

    ./x test چند گزینهٔ خط فرمان برای کنترل رفتار این تست‌های بسته دارد:

    • --doc — فقط تست‌های مستندات بسته را اجرا می‌کند.
    • --all-targets — همهٔ تست‌ها را به‌جز تست‌های مستندات اجرا می‌کند.
    • --tests — فقط تست‌های واحد و یکپارچگی را اجرا می‌کند

    Tidy

    Tidy ابزاری سفارشی برای اعتبارسنجی سبک کد منبع و قراردادهای قالب‌بندی است، مثل رد‌کردن خطوط طولانی. اطلاعات بیشتر در بخش قراردادهای کدنویسی یا Readme مربوط به Tidy هست.

    Examples: ./x test tidy

    Formatting

    Rustfmt با سامانهٔ ساخت یکپارچه شده است تا سبک یکنواختی را در کل کامپایلر اعمال کند. بررسی قالب‌بندی به‌طور خودکار توسط ابزار Tidy که بالا ذکر شد اجرا می‌شود.

    Examples:

    CommandDescription
    ./x fmt --checkقالب‌بندی را بررسی می‌کند و اگر نیاز به قالب‌بندی باشد با خطا خارج می‌شود.
    ./x fmtrustfmt را روی کل کدبیس اجرا می‌کند.
    ./x test tidy --blessابتدا rustfmt را برای قالب‌بندی کدبیس اجرا می‌کند، سپس بررسی‌های tidy را اجرا می‌کند.

    Book documentation tests

    همهٔ کتاب‌هایی که منتشر می‌شوند تست‌های خودشان را دارند، عمدتاً برای اعتبارسنجی اینکه مثال‌های کد Rust می‌گذرند. در پشت صحنه، این‌ها اساساً از rustdoc --test روی فایل‌های markdown استفاده می‌کنند. تست‌ها را می‌توان با دادن مسیر یک کتاب به ./x test اجرا کرد.

    Example: ./x test src/doc/book

    Documentation link checker

    پیوندها در همهٔ مستندات با ابزار بررسی‌کنندهٔ پیوند اعتبارسنجی می‌شوند، و می‌توان آن را این‌طور فراخوانی کرد:

    ./x test linkchecker

    این نیازمند ساخت همهٔ مستندات است، که ممکن است مدتی طول بکشد.

    distcheck

    distcheck تأیید می‌کند tarball توزیع منبعی که سامانهٔ ساخت می‌سازد باز می‌شود، ساخته می‌شود و همهٔ تست‌ها را اجرا می‌کند.

    ./x test distcheck

    Tool tests

    بسته‌هایی که همراه Rust می‌آیند همهٔ تست‌هایشان هم اجرا می‌شود. این شامل چیزهایی مثل cargo، clippy، rustfmt، miri، bootstrap (تست خود سامانهٔ ساخت Rust) و غیره است.

    بیشتر ابزارها در پوشهٔ src/tools قرار دارند. برای اجرای تست‌های یک ابزار، فقط مسیر آن را به ./x test بدهید.

    Example: ./x test src/tools/cargo

    معمولاً این ابزارها شامل اجرای cargo test درون پوشهٔ ابزار هستند.

    اگر می‌خواهید فقط مجموعهٔ مشخصی از تست‌ها را اجرا کنید، --test-args FILTER_NAME را به دستور اضافه کنید.

    Example: ./x test src/tools/miri --test-args padding

    در CI برخی ابزارها اجازهٔ شکست دارند. شکست‌ها به تیم‌های مربوطه اعلان می‌فرستند و در وب‌سایت toolstate پیگیری می‌شوند. اطلاعات بیشتر در مستندات toolstate هست.

    Ecosystem testing

    Rust یکپارچگی را با کد دنیای واقعی تست می‌کند تا رگرسیون‌ها را بگیرد و دربارهٔ تکامل زبان تصمیم‌های آگاهانه بگیرد. چند نوع تست اکوسیستم وجود دارد، از جمله Crater. برای جزئیات بیشتر فصل تست اکوسیستم را ببینید.

    Performance testing

    زیرساخت جداگانه‌ای برای تست و پیگیری عملکرد کامپایلر به‌کار می‌رود. برای جزئیات بیشتر فصل تست عملکرد را ببینید.

    Codegen backend testing

    تست backend تولید کد را ببینید.
