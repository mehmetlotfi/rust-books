    مجموعهٔ تست rustdoc-json

    این صفحه مخصوص مجموعهٔ تستی به نام rustdoc-json است که خروجی JSON در rustdoc را تست می‌کند. برای مجموعه‌های تست دیگر مربوط به rustdoc، §مجموعه‌های تست Rustdoc را ببینید.

    تست‌ها با compiletest اجرا می‌شوند و به مجموعهٔ معمول directiveها دسترسی دارند. directiveهای پرکاربرد اینجا عبارت‌اند از:

    • //@ aux-build برای داشتن وابستگی‌ها.
    • //@ edition: 2021 (یا edition دیگر).
    • //@ compile-flags: --document-hidden-items برای فعال‌کردن مستندسازی آیتم‌های خصوصی.

    خروجی JSON هر crate توسط ۲ برنامه بررسی می‌شود: jsondoclint و jsondocck.

    jsondoclint

    jsondoclint بررسی می‌کند همهٔ Idها در index (یا paths) وجود دارند. این تضمین می‌کند Id معلق (dangling) نداریم.

    jsondocck

    jsondocck directiveهایی را که در کامنت‌ها آمده پردازش می‌کند تا تأیید کند مقادیر خروجی مورد انتظارند. از این نظر بسیار شبیه htmldocck است.

    از JSONPath به‌عنوان زبان کوئری استفاده می‌کند، که یک مسیر می‌گیرد و فهرستی از مقادیری را که آن مسیر با آن‌ها مطابقت دارد برمی‌گرداند.

    Directives

    • //@ has <path>: بررسی می‌کند <path> وجود دارد، یعنی دست‌کم با ۱ مقدار مطابقت دارد.
    • //@ !has <path>: بررسی می‌کند <path> وجود ندارد، یعنی با ۰ مقدار مطابقت دارد.
    • //@ has <path> <value>: بررسی می‌کند <path> وجود دارد و دست‌کم یکی از تطابق‌ها با <value> داده‌شده برابر است.
    • //@ !has <path> <value>: بررسی می‌کند <path> وجود دارد، اما هیچ‌یک از تطابق‌ها با <value> داده‌شده برابر نیستند.
    • //@ is <path> <value>: بررسی می‌کند <path> دقیقاً با یک مقدار مطابقت دارد و آن با <value> داده‌شده برابر است.
    • //@ is <path> <value> <value>...: بررسی می‌کند <path> دقیقاً با همهٔ <value>های داده‌شده مطابقت دارد. ترتیب اینجا اهمیتی ندارد.
    • //@ !is <path> <value>: بررسی می‌کند <path> دقیقاً با یک مقدار مطابقت دارد و آن مقدار با <value> داده‌شده برابر نیست.
    • //@ count <path> <number>: بررسی می‌کند <path> با <number> مقدار مطابقت دارد.
    • //@ set <name> = <path>: بررسی می‌کند <path> دقیقاً با یک مقدار مطابقت دارد و آن مقدار را در متغیری به نام <name> ذخیره می‌کند.

    این‌ها در directive.rs تعریف شده‌اند.

    Values

    مقدارها می‌توانند مقادیر JSON یا متغیر باشند.

    • مقادیر JSON literalهای JSON هستند، مثل true، "string"، {"key": "value"}. این‌ها اغلب باید با ' نقل‌قول شوند تا به‌عنوان ۱ مقدار پردازش شوند. §تقسیم آرگومان‌ها را ببینید

    • متغیرها را می‌توان برای ذخیرهٔ مقدار در یک مسیر و استفاده از آن در کوئری‌های بعدی به‌کار برد. با directive با نام //@ set <name> = <path> تنظیم و با $<name> دسترسی داده می‌شوند

      //@ set foo = $some.path
//@ is $.some.other.path $foo

    Argument splitting

    آرگومان‌های directiveها با crate با نام shlex تقسیم می‌شوند که escape کردن به سبک shell در POSIX را پیاده‌سازی می‌کند. دلیل این است که هر دو آرگومان <path> و <value> در directiveها اغلب هم فاصله و هم علامت نقل‌قول دارند.

    برای استفاده از @ is با <path> برابر $.index[?(@.docs == "foo")].some.field و مقدار "bar" 1، می‌نویسید:

    //@ is '$.is[?(@.docs == "foo")].some.field' '"bar"'

    1. مقدار باید پس از تقسیم shlex برابر "bar" باشد، چون باید مقدار رشتهٔ JSON باشد. ↩
