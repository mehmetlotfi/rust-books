    اشکال‌زدایی و تست وابستگی‌ها

    تست گراف وابستگی

    راه‌های مختلفی برای نوشتن تست روی گراف وابستگی هست. ساده‌ترین سازوکارها annotationهای #[rustc_if_this_changed] و #[rustc_then_this_would_need] هستند. این‌ها در تست‌های ui برای آزمودن اینکه آیا مجموعهٔ مورد انتظار مسیرها در گراف وابستگی وجود دارد استفاده می‌شوند.

    برای مثال، tests/ui/dep-graph/dep-graph-caller-callee.rs یا تست‌های زیر را ببینید.

    #[rustc_if_this_changed]
fn foo() { }

#[rustc_then_this_would_need(TypeckTables)] //~ ERROR OK
fn bar() { foo(); }

    این باید این‌طور خوانده شود

    اگر این (foo) تغییر کند، آن‌گاه TypeckTables مربوط به این (یعنی bar) باید تغییر کند.

    از نظر فنی، آنچه رخ می‌دهد این است که انتظار می‌رود تست رشتهٔ «OK» را روی stderr، مرتبط با همین خط، صادر کند.

    همچنین می‌توانید خطوط زیر را اضافه کنید

    #[rustc_then_this_would_need(TypeckTables)] //~ ERROR no path
fn baz() { }

    که معنایش این است

    اگر foo تغییر کند، آن‌گاه TypeckTables مربوط به baz لازم نیست تغییر کند. ماکرو باید خطا صادر کند و پیام خطا باید «no path» را در بر داشته باشد.

    به یاد داشته باشید //~ ERROR OK از دید کد Rust‌ای که تست می‌کنیم کامنت است، اما از دید خود تست معنادار است.

    اشکال‌زدایی گراف وابستگی

    dump‌کردن گراف

    کامپایلر می‌تواند برای لذت اشکال‌زدایی شما گراف وابستگی را هم dump کند. برای این کار، پرچم -Z dump-dep-graph را بدهید. گراف در dep_graph.{txt,dot} در پوشهٔ فعلی dump می‌شود. می‌توانید نام فایل را با متغیر محیطی RUST_DEP_GRAPH بازنویسی کنید.

    اما اغلب، گراف کامل وابستگی بسیار طاقت‌فرساست و چندان مفید نیست. بنابراین کامپایلر اجازهٔ فیلترکردن گراف را هم می‌دهد. سه راه برای فیلترکردن دارید:

    1. همهٔ یال‌هایی که از مجموعهٔ مشخصی از گره‌ها (معمولاً یک گره) شروع می‌شوند.
    2. همهٔ یال‌هایی که به مجموعهٔ مشخصی از گره‌ها می‌رسند.
    3. همهٔ یال‌هایی که بین گره‌های شروع و پایان داده‌شده قرار دارند.

    برای فیلترکردن از متغیر محیطی RUST_DEP_GRAPH_FILTER استفاده کنید که باید شبیه یکی از این‌ها باشد:

    source_filter     // nodes originating from source_filter
-> target_filter  // nodes that can reach target_filter
source_filter -> target_filter // nodes in between source_filter and target_filter

    source_filter و target_filter فهرستی از رشته‌ها هستند که با & جدا شده‌اند. گره وقتی با فیلتر مطابقت دارد که همهٔ آن رشته‌ها در برچسبش ظاهر شوند. برای مثال:

    RUST_DEP_GRAPH_FILTER='-> TypeckTables'

    مقدم‌های (predecessor) همهٔ گره‌های TypeckTables را انتخاب می‌کند. اما معمولاً گرهٔ TypeckTables برای تابع مشخصی را می‌خواهید، پس ممکن است بنویسید:

    RUST_DEP_GRAPH_FILTER='-> TypeckTables & bar'

    این فقط مقدم‌های گره‌های TypeckTables را برای توابعی که bar در نامشان دارند انتخاب می‌کند.

    شاید می‌بینید وقتی foo را تغییر می‌دهید باید bar را دوباره type-check کنید، اما فکر نمی‌کنید باید این‌طور باشد. در آن صورت می‌توانید این کار را بکنید:

    RUST_DEP_GRAPH_FILTER='Hir & foo -> TypeckTables & bar'

    این همهٔ گره‌هایی را که از Hir(foo) به TypeckTables(bar) می‌رسند dump می‌کند، که از آن‌ها (امیدواریم) می‌توانید منبع یال اشتباه را ببینید.

    ردیابی یال‌های نادرست

    گاهی پس از dump‌کردن گراف وابستگی، مسیری می‌یابید که نباید وجود داشته باشد، اما مطمئن نیستید چگونه پدید آمده. وقتی کامپایلر با debug assertions ساخته شده باشد، می‌تواند در ردیابی آن کمک کند. فقط متغیر محیطی RUST_FORBID_DEP_GRAPH_EDGE را روی یک فیلتر تنظیم کنید. هر یالی که در dep-graph ساخته شود با آن فیلتر آزمایش می‌شود — اگر مطابقت داشت، bug! گزارش می‌شود تا به‌آسانی backtrace را ببینید (RUST_BACKTRACE=1).

    نحو این فیلترها همان است که در بخش قبل شرح داده شد. اما توجه کنید این فیلتر برخلاف بخش قبل روی هر یال اعمال می‌شود و مسیرهای طولانی‌تر در گراف را مدیریت نمی‌کند.

    Example:

    می‌یابید مسیری از Hir مربوط به foo به type check مربوط به bar هست و فکر نمی‌کنید باید باشد. گراف وابستگی را همان‌طور که در بخش قبل شرح داده شد dump می‌کنید و dep-graph.txt را باز می‌کنید تا چیزی شبیه این ببینید:

    Hir(foo) -> Collect(bar)
Collect(bar) -> TypeckTables(bar)

    آن یال اول برایتان مشکوک است. پس RUST_FORBID_DEP_GRAPH_EDGE را روی Hir&foo -> Collect&bar تنظیم می‌کنید، دوباره اجرا می‌کنید و سپس backtrace را می‌بینید. بفرمایید، باگ رفع شد!
