    پارامترهای Ty/Const/Region

    درون آیتم‌های جنریک می‌توان نوع‌هایی نوشت که از پارامترهای جنریکِ در دامنه استفاده می‌کنند، برای مثال fn foo<'a, T>(_: &'a Vec<T>). در این مورد خاص، نوع &'a Vec<T> در داخل به این صورت نمایش داده می‌شود:

    TyKind::Ref(
  RegionKind::LateParam(DefId(foo), DefId(foo::'a), "'a"),
  TyKind::Adt(Vec, &[TyKind::Param("T", 0)])
)

    سه روش جداگانه برای نمایش استفاده از پارامترهای جنریک داریم:

    • TyKind::Param/ConstKind::Param/RegionKind::EarlyParam برای پارامترهای جنریک early bound (توجه: همهٔ پارامترهای نوع و ثابت early bound در نظر گرفته می‌شوند؛ برای اطلاعات بیشتر فصل پارامترهای early در برابر late bound را ببینید)
    • TyKind::Bound/ConstKind::Bound/RegionKind::Bound برای ارجاع به پارامترهایی که از طریق قیدهای مرتبهٔ بالاتر یا نوع‌های مرتبهٔ بالاتر معرفی شده‌اند، یعنی for<'a> fn(&'a u32) یا for<'a> T: Trait<'a>. این در فصل مربوط به Binderها بحث شده است.
    • RegionKind::LateParam برای پارامترهای طول عمر late bound؛ دربارهٔ LateParam در فصل نمونه‌سازی Binderها بحث شده است.

    این فصل فقط TyKind::Param، ConstKind::Param و RegionKind::EarlyParam را پوشش می‌دهد.

    پارامترهای Ty/Const

    از آنجا که TyKind::Param و ConstKind::Param به‌طور یکسان پیاده‌سازی شده‌اند، این بخش برای سادگی فقط به TyKind::Param اشاره می‌کند. با این حال به خاطر داشته باشید که هر آنچه در اینجا می‌آید دربارهٔ ConstKind::Param هم صادق است

    هر TyKind::Param دو چیز دارد: نام پارامتر و یک اندیس (index).

    مثال ملموس زیر را از کاربرد TyKind::Param ببینید:

    struct Foo<T>(Vec<T>);

    نوع Vec<T> به‌صورت TyKind::Adt(Vec, &[GenericArgKind::Type(Param("T", 0))]) نمایش داده می‌شود.

    نام تا حدی گویاست؛ نام پارامتر نوع است. اندیس پارامتر نوع عددی صحیح است که جایگاه آن را در فهرست پارامترهای جنریکِ در دامنه نشان می‌دهد. توجه کنید که این شامل پارامترهای تعریف‌شده روی آیتم‌هایی در دامنه‌های بیرونی‌تر از آیتمی که پارامتر روی آن تعریف شده نیز می‌شود. مثال‌های زیر را در نظر بگیرید:

    struct Foo<A, B> {
  // A would have index 0
  // B would have index 1

  .. // some fields
}
impl<X, Y> Foo<X, Y> {
  fn method<Z>() {
    // inside here, X, Y and Z are all in scope
    // X has index 0
    // Y has index 1
    // Z has index 2
  }
}

    به‌طور مشخص، با داشتن ty::Generics آیتمی که پارامتر روی آن تعریف شده، اگر اندیس 2 باشد و از parent ریشه شروع کنیم، سومین پارامتری خواهد بود که معرفی می‌شود. برای مثال در مثال بالا، Z اندیس 2 دارد و سومین پارامتر جنریکی است که با شروع از بلوک impl معرفی می‌شود.

    اندیس، Ty را به‌طور کامل تعریف می‌کند و تنها بخشی از TyKind::Param است که برای استدلال دربارهٔ کدی که کامپایل می‌کنیم اهمیت دارد.

    به‌طور کلی نام برایمان مهم نیست و فقط از اندیس استفاده می‌کنیم. نام برای تشخیص‌ها (diagnostics) و لاگ‌های اشکال‌زدایی گنجانده شده، چون در غیر این صورت درک خروجی فوق‌العاده دشوار می‌شد، یعنی Vec<Param(0)>: Sized در برابر Vec<T>: Sized. در خروجی اشکال‌زدایی، نوع‌های پارامتر اغلب به‌صورت {name}/#{index} چاپ می‌شوند؛ برای مثال در تابع foo اگر Vec<T> را چاپ اشکال‌زدایی کنیم به‌صورت Vec<T/#0> نوشته می‌شود.

    یک نمایش جایگزین این بود که فقط نام را داشته باشیم. با این حال استفاده از اندیس کارآمدتر است، زیرا یعنی هنگام نمونه‌سازی پارامترهای جنریک با آرگومان‌ها می‌توانیم در GenericArgs اندیس بزنیم. در غیر این صورت باید GenericArgs را به‌صورت HashMap<Symbol, GenericArg> ذخیره می‌کردیم و هر بار که از آیتمی جنریک استفاده می‌کردیم یک جست‌وجوی hashmap انجام می‌دادیم.

    در نظریه، اندیس همچنین اجازه می‌دهد چند پارامتر متمایز با نام یکسان داشته باشیم، مثلاً impl<A> Foo<A> { fn bar<A>() { .. } }. قواعد مخالف shadowing این کار را دشوار می‌کنند، اما آن قواعد زبان ممکن است در آینده تغییر کنند.

    پارامترهای طول عمر

    برخلاف Ty/Const که هر یک فقط یک حالت Param دارند (یعنی همان Param منفرد)، طول عمرها دو حالت برای نمایش پارامترهای ناحیه (region) دارند: RegionKind::EarlyParam و RegionKind::LateParam. دلیل این است که توابع میان پارامترهای early و late bound تمایز قائل می‌شوند که در فصلی پیشین بحث شده است (پیوند را ببینید).

    RegionKind::EarlyParam دقیقاً مانند Ty/Const که حالت Param دارد ساختار یافته است؛ فقط یک اندیس u32 و یک Symbol است. برای پارامترهای طول عمر تعریف‌شده روی آیتم‌های غیرتابع، همیشه از ReEarlyParam استفاده می‌کنیم. برای توابع، از ReEarlyParam برای هر پارامتر early bound و از ReLateParam برای هر پارامتر late bound استفاده می‌کنیم. توجه کنید که درست مانند پارامترهای Ty و Const، اغلب آن‌ها را به‌صورت 'SYMBOL/#INDEX برای اشکال‌زدایی قالب‌بندی می‌کنیم.

    یک مثال:

    // This function would have its signature represented as:
//
// ```
// fn(
//     T/#2,
//     Ref('a/#0, Ref(ReLateParam(...), u32))
// ) -> Ref(ReLateParam(...), u32)
// ```
fn foo<'a, 'b, T: 'a>(one: T, two: &'a &'b u32) -> &'b u32 {
    ...
}

    RegionKind::LateParam بیشتر در فصل نمونه‌سازی binderها بحث شده است.
