    EarlyBinder و نمونه‌سازی پارامترها (instantiating)

    فرض کنید آیتمی پارامتر جنریک T معرفی می‌کند. هر وقت از بیرون foo به نوع‌های درون آن (یعنی نوع بازگشتی یا نوع آرگومان‌ها) ارجاع می‌دهیم باید مراقب مدیریت پارامترهای جنریک تعریف‌شده روی foo باشیم. برای مثال:

    fn foo<T, U>(a: T, _b: U) -> T { a }

fn main() {
    let c = foo::<i32, u128>(1, 2);
}

    هنگام type checking در main نمی‌توانیم ساده‌لوحانه به نوع بازگشتی foo نگاه کنیم و نوع T را به متغیر c بدهیم. تابع main هیچ پارامتر جنریکی تعریف نمی‌کند، پس T در این زمینه کاملاً بی‌معناست. به‌طور کلی‌تر، هر وقت آیتمی پارامتر جنریک معرفی (bind) کند، هنگام دسترسی به نوع‌های درون آیتم از بیرون، پارامترهای جنریک باید با مقادیر آیتم بیرونی نمونه‌سازی شوند.

    در rustc این را از طریق نوع EarlyBinder ردیابی می‌کنیم؛ نوع بازگشتی foo به‌صورت EarlyBinder<Ty> نمایش داده می‌شود و تنها راه دسترسی به Ty دادن آرگومان برای هر پارامتر جنریکی است که Ty ممکن است استفاده کند. این با متد EarlyBinder::instantiate پیاده‌سازی شده که binder را باز می‌کند (discharge) و مقدار درون را با همهٔ پارامترهای جنریک جایگزین‌شده توسط آرگومان‌های داده‌شده برمی‌گرداند.

    برای بازگشت به مثال، هنگام type checking در main نوع بازگشتی foo به‌صورت EarlyBinder(T/#0) نمایش داده می‌شود. سپس چون تابع را با i32, u128 به‌عنوان آرگومان‌های جنریک فراخوانی کرده‌ایم، EarlyBinder::instantiate را روی نوع بازگشتی با [i32, u128] به‌عنوان args فراخوانی می‌کنیم. نتیجه نوع بازگشتی نمونه‌سازی‌شدهٔ i32 است که می‌توانیم به‌عنوان نوع local با نام c به‌کار ببریم.

    چند مثال دیگر:

    fn foo<T>() -> Vec<(u32, T)> { Vec::new() }
fn bar() {
    // the return type of `foo` before instantiating it would be:
    // `EarlyBinder(Adt(Vec, &[Tup(&[u32, T/#=0])]))`
    // we then instantiate the binder with `[u64]` resulting in the type:
    // `Adt(Vec, &[Tup(&[u32, u64])])`
    let a = foo::<u64>();
}
    struct Foo<A, B> {
    x: Vec<A>,
    ..
}

fn bar(foo: Foo<u32, f32>) { 
    // the type of `foo`'s `x` field before instantiating it would be:
    // `EarlyBinder(Vec<A/#0>)`
    // we then instantiate the binder with `[u32, f32]` as those are the
    // generic arguments to the `Foo` struct. This results in a type of:
    // `Vec<u32>`
    let y = foo.x;
}

    در کامپایلر فراخوانی instantiate برای این در FieldDef::ty (منبع) انجام می‌شود؛ در نقطه‌ای هنگام type checking در bar برای گرفتن نوع foo.x به FieldDef::ty(x, &[u32, f32]) می‌رسیم.

    نکته دربارهٔ اندیس‌ها: اگر اندیس یک Param با آنچه EarlyBinder bind می‌کند مطابقت نداشته باشد باگ است. برای مثال، اگر اندیس خارج از محدوده باشد یا اندیس یک طول‌عمر مربوط به پارامتر نوع باشد. این نوع خطاها زودتر در کامپایلر هنگام name resolution گرفته می‌شوند، جایی که ارجاع به پارامترهای جنریک معرفی‌شده توسط آیتم‌هایی که نباید توسط آیتم درونی قابل‌نام‌بردن باشند ممنوع است.

    همان‌طور که پیش‌تر گفته شد، وقتی بیرون آیتم هستیم مهم است EarlyBinder را پیش از دسترسی به مقدار درون با آرگومان‌های جنریک نمونه‌سازی کنیم، اما وقتی مفهوماً از قبل درون binder هستیم راه‌اندازی کمی متفاوت است.

    برای مثال:

    impl<T> Trait for Vec<T> {
    fn foo(&self, b: Self) {}
}

    هنگام ساخت Ty برای نمایش نوع پارامتر b باید نوع Self را روی impl‌ای که درونش هستیم بگیریم. این را می‌توان با فراخوانی کوئری type_of با DefId مربوط به impl به دست آورد، اما این EarlyBinder<Ty> برمی‌گرداند چون بلوک impl پارامترهای جنریکی را bind می‌کند که اگر بیرون impl باشیم باید discharge شوند.

    نوع EarlyBinder تابع instantiate_identity را برای باز‌کردن binder وقتی «از قبل درون آن» هستید فراهم می‌کند. این اساساً نسخهٔ کارآمدتر نوشتن EarlyBinder::instantiate(GenericArgs::identity_for_item(..)) است. از نظر مفهومی binder را با نمونه‌سازی با جانگهدارها در universe ریشه discharge می‌کند (در چند فصل بعد دربارهٔ معنای آن صحبت می‌کنیم). در عمل اما فقط مقدار درون را بدون هیچ تغییری برمی‌گرداند.
