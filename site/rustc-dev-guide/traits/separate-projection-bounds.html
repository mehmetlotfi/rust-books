    داشتنِ قیدهای Trait و Projection به‌صورت جداگانه

    با داشتن قید where به شکل T: Foo<AssocA = u32, AssocB = i32>، در حال حاضر آن را به یک قید Trait(Foo<T>) و دو قید جداگانهٔ Projection(<T as Foo>::AssocA, u32) و Projection(<T as Foo>::AssocB, i32) تبدیل (lower) می‌کنیم. چرا آن را به‌جای این کار، به‌صورت یک قید واحد مانند Trait(Foo[T], [AssocA = u32, AssocB = u32] نمایش نمی‌دهیم؟

    روشی که قیدهای Projection را اثبات می‌کنیم مستقیماً به اثبات قید Trait متناظر وابسته است: حل‌گر قدیمی حل‌گر جدید.

    به نظر می‌رسد منطقی‌تر باشد که فقط یک پیاده‌سازی واحد داشته باشیم که بررسی می‌کند آیا یک صفت (trait) پیاده‌سازی شده است یا نه و (راهی برای محاسبهٔ) نوع‌های وابستهٔ آن را برمی‌گرداند.

    متأسفانه این کار بسیار دشوار است، چون ممکن است برای norm از یک candidate متفاوت با candidate مربوط به قید صفتِ متناظر استفاده کنیم. alias-bound در برابر where-bound و global where-bound در برابر impl را ببینید.

    دلایل ظریف دیگری هم وجود دارد که چرا نمی‌توانیم چنین کنیم. احمقانه‌ترین آن‌ها این است که برای aliasهای rigid، تلاش برای نرمال‌سازی آن‌ها هیچ‌یک از قیدهای طول عمر ناشی از اثبات قید صفت را در نظر نمی‌گیرد. این کار به‌دلیل نبودِ مفروضات روی binderها ضروری است - https://github.com/rust-lang/trait-system-refactor-initiative/issues/177 - و باید در بلندمدت برطرف شود.

    مشکل جداگانهٔ دیگر این است که در حال حاضر، دریافت type_of نوع‌های وابسته برای goalهای Trait یا در candidateهای Projection سایه‌خورده (shadowed) می‌تواند برای RPITIT باعث چرخه‌های query شود. https://github.com/rust-lang/trait-system-refactor-initiative/issues/185 را ببینید.

    همچنین میان candidateهای برخی از implهای داخلی (builtin) تفاوت‌های جزئی وجود دارد؛ همهٔ این‌ها به‌طور کلی نامطلوب به نظر می‌رسند و من آن‌ها را باگ می‌دانم که اگر در اینجا رویکردی یکپارچه داشتیم برطرف می‌شدند.

    در نهایت، نداشتنِ این تفکیک، تبدیل (lowering) بندهای where را آزاردهنده‌تر می‌کند. در سامانهٔ فعلی، داشتن بندهای where تکراری مشکلی نیست و هنگام elaborate کردن قیدهای super trait به‌راحتی رخ می‌دهد. اگر تفکیک نباشد، باید مطمئن شویم همهٔ قیدهای نوع وابسته را ادغام می‌کنیم، برای مثال:

    trait Super {
    type A;
    type B;
}

trait Trait: Super<A = i32> {}
// how to elaborate Trait<B = u32>

    یا حتی بدتر

    trait Super<'a> {
    type A;
    type B;
}

trait Trait<'a>: Super<'a, A = i32> {}
// how to elaborate
// T: Trait<'a> + for<'b> Super<'b, B = u32>
