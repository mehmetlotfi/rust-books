    کران‌های صفت مرتبهٔ بالاتر

    یکی از مفاهیم ظریف‌تر در تفکیک صفت (trait resolution)، کران‌های صفت مرتبهٔ بالاتر (higher-ranked trait bounds) است. نمونه‌ای از چنین کرانی for<'a> MyTrait<&'a isize> است. بیایید ببینیم انتخاب (selection) روی ارجاع‌های صفت مرتبهٔ بالاتر چگونه کار می‌کند.

    تطبیق پایه و نشت Placeholder

    فرض کنید صفتی به نام Foo داریم:

    trait Foo<X> {
    fn foo(&self, x: X) { }
}

    فرض کنید تابعی به نام want_hrtb داریم که نوعی می‌خواهد که Foo<&'a isize> را برای هر 'a پیاده‌سازی کرده باشد:

    fn want_hrtb<T>() where T : for<'a> Foo<&'a isize> { ... }

    حال ساختاری به نام AnyInt داریم که Foo<&'a isize> را برای هر 'a پیاده‌سازی می‌کند:

    struct AnyInt;
impl<'a> Foo<&'a isize> for AnyInt { }

    و پرسش این است که آیا AnyInt : for<'a> Foo<&'a isize> برقرار است؟ می‌خواهیم پاسخ «بله» باشد. الگوریتم تشخیص آن ارتباط نزدیکی با زیرنوع‌سازی (subtyping) برای نوع‌های مرتبهٔ بالاتر دارد (که اینجا توضیح داده شده و همچنین در مقاله‌ای از SPJ آمده است. اگر می‌خواهید زیرنوع‌سازی مرتبهٔ بالاتر را بفهمید، توصیه می‌کنیم آن مقاله را بخوانید). این الگوریتم چند بخش دارد:

    1. ناحیه‌های مقید (bound regions) در تعهد (obligation) را با placeholderها جایگزین کن.
    2. impl را با تعهدِ دارای placeholder تطبیق بده.
    3. نشت placeholder (placeholder leaks) را بررسی کن.

    پس بیایید مثال خود را مرحله به مرحله پیش ببریم.

    1. نخستین کاری که انجام می‌دهیم این است که ناحیهٔ مقید در تعهد را با یک placeholder جایگزین کنیم و AnyInt : Foo<&'0 isize> به دست آوریم (در اینجا '0 نمایندهٔ ناحیهٔ placeholder شمارهٔ ۰ است). توجه کنید که اکنون هیچ سور (quantifier) ای نداریم؛ از نظر نوع‌های کامپایلر، این به معنای تغییر از ty::PolyTraitRef به TraitRef است. سپس TraitRef را از impl می‌سازیم و برای ناحیه‌های مقید آن از متغیرهای تازه استفاده می‌کنیم (و به این ترتیب Foo<&'$a isize> به دست می‌آید، که در آن '$a متغیر استنتاج برای 'a است).

    2. سپس این دو ارجاع صفت (trait ref) را به هم مرتبط می‌کنیم و گرافی با این قید به دست می‌آوریم که '0 == '$a.

    3. در نهایت، «نشت»‌های placeholder را بررسی می‌کنیم – نشت در اصل هر تلاشی است برای مرتبط‌کردن یک ناحیهٔ placeholder با ناحیهٔ placeholder دیگر، یا با هر ناحیه‌ای که پیش از تطبیق impl وجود داشته است. بررسی نشت (leak check) با جست‌وجو از ناحیهٔ placeholder انجام می‌شود تا مجموعهٔ ناحیه‌هایی که به هر نحو با آن مرتبط‌اند پیدا شود. این مجموعه «مجموعهٔ آلوده» (taint set) نام دارد. برای قبول‌شدن در بررسی، این مجموعه باید صرفاً از خود آن ناحیه و متغیرهای ناحیهٔ impl تشکیل شده باشد. اگر مجموعهٔ آلوده هر ناحیهٔ دیگری را شامل شود، تطبیق شکست می‌خورد. در این مورد، مجموعهٔ آلوده برای '0 برابر {'0, '$a} است و بنابراین بررسی موفق می‌شود.

    حال یک حالت شکست را بررسی کنیم. تصور کنید ساختار زیر را هم داریم

    struct StaticInt;
impl Foo<&'static isize> for StaticInt;

    می‌خواهیم تعهد StaticInt : for<'a> Foo<&'a isize> برآورده‌نشده در نظر گرفته شود. بررسی دقیقاً مانند قبل آغاز می‌شود. 'a با یک placeholder به نام '0 جایگزین می‌شود و ارجاع صفت impl به Foo<&'static isize> نمونه‌سازی می‌شود. وقتی این دو را به هم مرتبط می‌کنیم، قیدی مانند 'static == '0 به دست می‌آید. این یعنی مجموعهٔ آلوده برای '0 برابر {'0, 'static} است که در بررسی نشت رد می‌شود.

    تعهدهای صفت مرتبهٔ بالاتر

    پس از انجام تطبیق پایه، به موضوع جالب دیگری می‌رسیم: چگونه با تعهدهای impl برخورد کنیم. در اینجا یک مثال ساده را مرحله به مرحله بررسی می‌کنم. تصور کنید صفت‌های Foo و Bar و یک impl وابسته به آن‌ها داریم:

    trait Foo<X> {
    fn foo(&self, x: X) { }
}

trait Bar<X> {
    fn bar(&self, x: X) { }
}

impl<X,F> Foo<X> for F
    where F : Bar<X>
{
}

    حال فرض کنید تعهد Baz: for<'a> Foo<&'a isize> را داریم و این impl را با آن تطبیق می‌دهیم. در نتیجه چه تعهدی تولید می‌شود؟ می‌خواهیم Baz: for<'a> Bar<&'a isize> را به دست آوریم، اما این چگونه رخ می‌دهد؟

    پس از تطبیق، در وضعیتی هستیم که یک جانشینی placeholder مانند X => &'0 isize داریم. اگر این جانشینی را روی تعهدهای impl اعمال کنیم، F : Bar<&'0 isize> به دست می‌آید. بدیهی است که این مستقیماً قابل استفاده نیست، زیرا ناحیهٔ placeholder به نام '0 نباید از محاسبهٔ ما بیرون نشت کند.

    کاری که می‌کنیم این است که یک نگاشت معکوس از مجموعهٔ آلودهٔ '0 به ناحیهٔ مقید اصلی (که در اینجا 'a است) که '0 از آن پدید آمده بود، می‌سازیم. (این کار در higher_ranked::plug_leaks انجام می‌شود.) می‌دانیم که بررسی نشت موفق بوده است، پس این مجموعهٔ آلوده صرفاً از خود ناحیهٔ placeholder به‌علاوهٔ چند متغیر ناحیهٔ میانی تشکیل شده است. سپس ارجاع صفت را پیمایش می‌کنیم و هر ناحیه در آن مجموعهٔ آلوده را دوباره به یک ناحیهٔ late-bound تبدیل می‌کنیم، به‌طوری که در این مورد به Baz: for<'a> Bar<&'a isize> می‌رسیم.
