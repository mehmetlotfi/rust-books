    اشکال‌زدایی کامپایلر

    این فصل چند نکته برای اشکال‌زدایی کامپایلر دارد. این نکات برای مفید‌بودن مستقل از اینکه روی چه چیزی کار می‌کنید نوشته شده‌اند. برخی فصل‌های دیگر نصیحت‌هایی دربارهٔ بخش‌های مشخصی از کامپایلر دارند (مثلاً فصل اشکال‌زدایی و تست کوئری‌ها یا فصل اشکال‌زدایی LLVM).

    پیکربندی کامپایلر

    به‌طور پیش‌فرض، rustc بدون بیشتر اطلاعات اشکال‌زدایی ساخته می‌شود. برای فعال‌کردن اطلاعات اشکال‌زدایی، در bootstrap.toml مقدار rust.debug = true را تنظیم کنید.

    تنظیم rust.debug = true گزینه‌های اشکال‌زدایی متعددی را فعال می‌کند (مثل debug-assertions، debug-logging و غیره) که در صورت تمایل می‌توان جداگانه تنظیمشان کرد، اما بسیاری از افراد فقط rust.debug = true را تنظیم می‌کنند.

    اگر می‌خواهید از GDB برای اشکال‌زدایی rustc استفاده کنید، لطفاً bootstrap.toml را با این گزینه‌ها تنظیم کنید:

    rust.debug = true
rust.debuginfo-level = 2

    نکته: این فضای دیسک زیادی مصرف می‌کند (بیش از ۳۵ گیگابایت)، و زمان کامپایل بسیار بیشتری لازم دارد. با debuginfo-level = 1 (پیش‌فرض وقتی debug = true است)، می‌توانید مسیر اجرا را دنبال کنید، اما اطلاعات نمادها برای اشکال‌زدایی را از دست می‌دهید.

    پیکربندی پیش‌فرض symbol-mangling-version نسخهٔ v0 را فعال می‌کند. این دست‌کم GDB نسخهٔ v10.2 را لازم دارد، در غیر این صورت باید symbol-mangling-version جدید را در bootstrap.toml غیرفعال کنید.

    rust.new-symbol-mangling = false

    برای اطلاعات بیشتر کامنت‌های bootstrap.example.toml را ببینید.

    پس از تغییر هر گزینهٔ پیکربندی باید کامپایلر را دوباره بسازید.

    سرکوب فایل ICE

    به‌طور پیش‌فرض، اگر rustc با خطای داخلی کامپایلر (ICE) روبه‌رو شود، محتوای ICE را در یک فایل ICE درون پوشهٔ کاری فعلی با نام rustc-ice-<timestamp>-<pid>.txt dump می‌کند. اگر این مطلوب نیست، می‌توانید با RUSTC_ICE=0 از ساخت فایل ICE جلوگیری کنید.

    گرفتن backtrace

    وقتی ICE دارید (panic در کامپایلر)، می‌توانید RUST_BACKTRACE=1 را تنظیم کنید تا مثل برنامه‌های عادی Rust ردیابی پشتهٔ panic! را بگیرید. به یاد دارم backtraceها روی MinGW کار نمی‌کنند، متأسفم. اگر مشکل دارید یا backtraceها پر از unknown هستند، شاید بخواهید راهی برای استفاده از لینوکس، Mac یا MSVC در ویندوز بیابید.

    در پیکربندی پیش‌فرض (بدون تنظیم debug روی true)، شمارهٔ خطوط فعال نیست، پس backtrace این‌طور به نظر می‌رسد:

    -Z flags

    کامپایلر مجموعه‌ای پرچم -Z * دارد. این‌ها پرچم‌های ناپایدارند که فقط روی nightly فعال‌اند. بسیاری از آن‌ها برای اشکال‌زدایی مفیدند. برای گرفتن فهرست کامل پرچم‌های -Z از -Z help استفاده کنید.

    یک پرچم مفید -Z verbose-internals است، که معمولاً چاپ اطلاعات بیشتری را فعال می‌کند که می‌تواند برای اشکال‌زدایی مفید باشد.

    درست در ادامه توضیحات مفصلی دربارهٔ چند مورد منتخب می‌یابید.

    گرفتن backtrace برای خطاها

    اگر می‌خواهید backtrace را تا نقطه‌ای که کامپایلر پیام خطا صادر می‌کند بگیرید، می‌توانید -Z treat-err-as-bug=n را بدهید که کامپایلر را وادار می‌کند در خطای nام panic کند. اگر =n را حذف کنید، کامپایلر برای n مقدار 1 را فرض می‌کند و در نتیجه در اولین خطایی که ببیند panic می‌کند.

    1 + ();

    Debugging delayed bugs

    گزینهٔ -Z eagerly-emit-delayed-bugs اشکال‌زدایی باگ‌های به‌تأخیرافتاده (delayed bugs) را آسان می‌کند. آن‌ها را به خطاهای عادی تبدیل می‌کند، یعنی قابل‌مشاهده‌شان می‌کند. این را می‌توان همراه با -Z treat-err-as-bug به‌کار برد تا در یک delayed bug مشخص متوقف شد و backtrace گرفت.

    گرفتن محل ایجاد خطا

    -Z track-diagnostics می‌تواند به یافتن محل صدور خطاها کمک کند. برای این از #[track_caller] استفاده می‌کند و محل را کنار خطا چاپ می‌کند:

    این شبیه اما متفاوت با -Z treat-err-as-bug است:

    • محل همهٔ خطاهای صادرشده را چاپ می‌کند
    • نیازی به کامپایلر ساخته‌شده با نمادهای اشکال‌زدایی ندارد
    • لازم نیست یک ردیابی پشتهٔ بزرگ را بخوانید.

    Getting logging output

    کامپایلر برای لاگ‌کردن از crate با نام tracing استفاده می‌کند.

    برای جزئیات فصل tracing را ببینید.

    Narrowing (bisecting) regressions

    ابزار cargo-bisect-rustc راهی سریع و آسان برای یافتن اینکه دقیقاً کدام PR باعث تغییر رفتار rustc شده است. به‌طور خودکار آرتیفکت‌های PR مربوط به rustc را دانلود و با پروژه‌ای که ارائه می‌دهید تست می‌کند تا رگرسیون را بیابد. سپس می‌توانید PR را ببینید تا زمینهٔ بیشتری دربارهٔ اینکه چرا تغییر کرده به دست آورید. برای نحوهٔ استفاده این آموزش را ببینید.

    دانلود آرتیفکت‌ها از CI مربوط به Rust

    ابزار rustup-toolchain-install-master از kennytm می‌تواند برای دانلود آرتیفکت‌های تولیدشده توسط CI مربوط به Rust برای یک SHA1 مشخص به‌کار رود — این اساساً با land شدن موفق یک PR متناظر است — و سپس آن‌ها را برای استفادهٔ محلی شما راه‌اندازی می‌کند. این برای آرتیفکت‌های تولیدشده توسط @bors try هم کار می‌کند. وقتی می‌خواهید ساخت حاصل از یک PR را بدون ساخت خودتان بررسی کنید مفید است.

    #[rustc_*] TEST attributes

    کامپایلر تعداد زیادی attribute داخلی (دائماً ناپایدار) تعریف می‌کند که برخی از آن‌ها برای اشکال‌زدایی با dump‌کردن اطلاعات داخلی اضافی کامپایلر مفیدند. این‌ها پیشوند rustc_ دارند و پشت قابلیت داخلی rustc_attrs قرار گرفته‌اند (که مثلاً با #![feature(rustc_attrs)] فعال می‌شود).

    برای فهرست کامل و به‌روز builtin_attrs را ببینید. به‌طور مشخص‌تر، آن‌هایی که با TEST علامت‌گذاری شده‌اند. در ادامه چند مورد قابل‌توجه آمده است:

    AttributeDescription
    rustc_dump_def_parentsزنجیرهٔ والدهای DefId برخی تعریف‌ها را dump می‌کند.
    rustc_dump_def_pathdef_path_str یک آیتم را dump می‌کند.
    rustc_dump_genericsgenerics یک آیتم را dump می‌کند.
    rustc_dump_hidden_type_of_opaquesنوع پنهان هر نوع opaque را در crate dump می‌کند.
    rustc_dump_inferred_outlivesimplied boundهای یک آیتم را dump می‌کند. دقیق‌تر، inferred_outlives_of یک آیتم.
    rustc_dump_item_boundsitem_bounds یک آیتم را dump می‌کند.
    rustc_dump_layoutاین بخش را ببینید.
    rustc_dump_object_lifetime_defaultsپیش‌فرض‌های طول عمر trait object یک آیتم را dump می‌کند.
    rustc_dump_clausesclauses_of یک آیتم را dump می‌کند.
    rustc_dump_symbol_namesymbol_name یک آیتم را هم به‌شکل mangled و هم demangled dump می‌کند.
    rustc_dump_variancesواریانس‌های یک آیتم را dump می‌کند.
    rustc_dump_vtableچیدمان vtable یک impl، یا یک type alias از نوع dyn را dump می‌کند.
    rustc_regionsنیازمندی‌های ناحیهٔ closure در NLL را dump می‌کند.

    درست در ادامه توضیحات مفصلی دربارهٔ چند مورد منتخب می‌یابید.

    قالب‌بندی خروجی Graphviz (فایل‌های .dot)

    برخی گزینه‌های کامپایلر برای اشکال‌زدایی قابلیت‌های مشخص، گراف graphviz تولید می‌کنند — مثلاً attribute با نام #[rustc_mir(borrowck_graphviz_postflow="suffix.dot")] روی یک تابع، گراف‌های مختلف جریان داده borrow-checker را همراه با -Zdump-mir-dataflow dump می‌کند.

    همهٔ این‌ها فایل‌های .dot تولید می‌کنند. برای مشاهدهٔ این فایل‌ها، graphviz را نصب کنید (مثلاً apt-get install graphviz) و سپس دستورهای زیر را اجرا کنید:

    $ dot -T pdf maybe_init_suffix.dot > maybe_init_suffix.pdf
$ firefox maybe_init_suffix.pdf # Or your favorite pdf viewer

    Graphviz همچنین یک برنامهٔ پیش‌پردازش به نام unflatten دارد که گاهی کمک می‌کند خروجی‌ها کمتر عجیب پخش‌شده به نظر برسند. یک فایل dot را می‌خواند و فایل dot دیگری خروجی می‌دهد، پس می‌توانید در pipe از آن استفاده کنید، مثلاً:

    $ unflatten mir_dump/*.foo.-------.nll.0.regioncx.all.dot | dot -Tpdf  -o foo-outlives.pdf

    این به‌ویژه برای گراف‌های پیچیدهٔ region outlives از borrow checker مفید است.

    یک ویرایشگر و نمایشگر آنلاین Graphviz هم در دسترس است.

    اشکال‌زدایی borrow checker فصل جداگانهٔ خودش را دارد.

    پیکربندی CodeLLDB برای اشکال‌زدایی rustc

    اگر از VSCode استفاده می‌کنید و bootstrap.toml را برای درخواست سطح اشکال‌زدایی 1 یا 2 برای بخش‌هایی از کد که به آن‌ها علاقه‌مندید ویرایش کرده‌اید، باید بتوانید با افزونهٔ CodeLLDB در VSCode آن را اشکال‌زدایی کنید.

    در ادامه نمونه‌ای از فایل launch.json آمده که برای اجرای کامپایلر stage 1 مستقیماً از پوشه‌ای که در آن ساخته شده به‌کار می‌رود (لازم نیست «نصب» شده باشد):

    // .vscode/launch.json
{
    "version": "0.2.0",
    "configurations": [
      {
        "type": "lldb",
        "request": "launch",
        "name": "Launch",
        "args": [],  // array of string command-line arguments to pass to compiler
        "program": "${workspaceFolder}/build/host/stage1/bin/rustc",
        "windows": {  // applicable if using windows
            "program": "${workspaceFolder}/build/host/stage1/bin/rustc.exe"
        },
        "cwd": "${workspaceFolder}",  // current working directory at program start
        "stopOnEntry": false,
        "sourceLanguages": ["rust"]
      }
    ]
  }
