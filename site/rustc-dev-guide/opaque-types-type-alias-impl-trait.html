    نوع‌های Opaque (نام مستعار نوع impl Trait)

    نوع‌های Opaque نحوی برای تعریف یک نام مستعار نوعِ مات (opaque) هستند که تنها مجموعه‌ای مشخص از صفت‌ها (trait) را به‌عنوان رابط خود در معرض دید قرار می‌دهد؛ نوع مشخصِ پشت‌صحنه از روی مجموعه‌ای معین از «محل‌های استفاده» از نوع Opaque استنتاج می‌شود.

    این مفهوم با به‌کار بردن impl Trait درون نام‌های مستعار نوع بیان می‌شود، برای مثال:

    type Foo = impl Bar;

    این کد یک نوع Opaque با نام Foo اعلام می‌کند که تنها اطلاعاتی که از آن در دست است این است که Bar را پیاده‌سازی می‌کند. بنابراین هر بخشی از رابط Bar را می‌توان روی یک Foo به کار برد، اما چیز دیگری را نمی‌توان (صرف‌نظر از اینکه نوع مشخص، صفت‌های دیگری را پیاده‌سازی کند یا نه).

    از آنجا که باید یک نوع مشخصِ پشت‌صحنه وجود داشته باشد، می‌توانید (تا مهٔ 2025) آن نوع را با به‌کار بردن نوع Opaque در یک «محل استفادهٔ تعریف‌کننده» (defining use site) بیان کنید.

    struct Struct;
impl Bar for Struct { /* stuff */ }
#[define_opaque(Foo)]
fn foo() -> Foo {
    Struct
}

    هر «محل استفادهٔ تعریف‌کنندهٔ» دیگر باید دقیقاً همان نوع را تولید کند.

    توجه کنید که تعریف یک نام مستعار نوع برای یک نوع Opaque یک قابلیت ناپایدار است. برای استفاده از آن به nightly و حاشیه‌نویسی‌های #![feature(type_alias_impl_trait)] روی فایل و #[define_opaque(Foo)] روی متدی نیاز دارید که نوع Opaque را به نوع مشخص پیوند می‌دهد. مثال کامل:

    #![feature(type_alias_impl_trait)]

trait Bar { /* stuff */ }

type Foo = impl Bar;

struct Struct;

impl Bar for Struct { /* stuff */ }

#[define_opaque(Foo)]
fn foo() -> Foo {
    Struct
}

    محل(های) استفادهٔ تعریف‌کننده

    در حال حاضر تنها مقدار بازگشتی یک تابع می‌تواند محل استفادهٔ تعریف‌کنندهٔ یک نوع Opaque باشد (و آن هم فقط اگر نوع بازگشتی آن تابع شامل نوع Opaque باشد).

    استفادهٔ تعریف‌کنندهٔ یک نوع Opaque می‌تواند هر کدی درون والدِ تعریف نوع Opaque باشد. این شامل همهٔ هم‌نیاهای (siblings) نوع Opaque و همهٔ فرزندان آن هم‌نیاها می‌شود.

    ابتکار عملِ «جلوگیری از وارد شدن آسیب مغزی مهلک به توسعه‌دهندگان در اثر اجرای ناخواستهٔ حلقه‌های بی‌پایان در ذهنشان هنگام تلاش برای درک اینکه سامانهٔ نوع چه می‌کند» تصمیم گرفته است که فرزندانِ نوع‌های Opaque را از محل استفادهٔ تعریف‌کننده بودن منع کند.

    نوع‌های Opaque وابسته

    نوع‌های Opaque وابسته را می‌توان با هر آیتم وابستهٔ دیگری در همان impl صفت، یا فرزندی از آن آیتم‌های وابسته تعریف کرد. برای نمونه:

    trait Baz {
    type Foo;
    fn foo() -> Self::Foo;
}

struct Quux;

impl Baz for Quux {
    type Foo = impl Bar;
    fn foo() -> Self::Foo { ... }
}

    برای این کار نیز به nightly و حاشیه‌نویسی (متفاوتِ) #![feature(impl_trait_in_assoc_type)] نیاز دارید. توجه کنید که دیگر به #[define_opaque(Foo)] روی متد نیازی ندارید، زیرا نوع Opaque در امضای تابع (پشت نوع وابسته) ذکر شده است. مثال کامل:

    #![feature(impl_trait_in_assoc_type)]

trait Bar {}
struct Zap;

impl Bar for Zap {}

trait Baz {
    type Foo;
    fn foo() -> Self::Foo;
}

struct Quux;

impl Baz for Quux {
    type Foo = impl Bar;
    fn foo() -> Self::Foo { Zap }
}
