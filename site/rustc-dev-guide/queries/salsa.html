    Salsa چگونه کار می‌کند

    این فصل بر اساس توضیحی است که نیکو ماتساکیس در این ویدیو دربارهٔ Salsa ارائه داده است. برای اطلاع بیشتر ممکن است بخواهید Salsa In More Depth را هم ببینید، که آن هم از نیکو ماتساکیس است.

    تا نوامبر 2022، هرچند Salsa (از جمله) از سامانهٔ کوئری rustc الهام گرفته، مستقیماً در rustc استفاده نمی‌شود. در chalk استفاده می‌شود، که پیاده‌سازی سامانهٔ trait در Rust است، و به‌طور گسترده در rust-analyzer، پیاده‌سازی رسمی پروتکل language server برای Rust، اما هیچ برنامهٔ مشخص میان‌مدت یا بلندمدتی برای یکپارچه‌کردن آن در کامپایلر نیست.

    Salsa چیست؟

    Salsa کتابخانه‌ای برای محاسبهٔ مجدد افزایشی است. یعنی اجازه می‌دهد محاسباتی را که در گذشته انجام شده‌اند دوباره استفاده کنیم تا کارایی محاسبات آینده افزایش یابد.

    اهداف Salsa این‌هاست:

    • فراهم‌کردن این قابلیت به شکل خودکار، به‌طوری که استفادهٔ مجدد از محاسبات قدیمی خودکار توسط کتابخانه انجام شود.
    • انجام این کار به شکل «sound» یا «درست»، یعنی منجر به همان نتایجی شود که اگر از ابتدا انجام شده بود.

    مدل واقعی Salsa بسیار غنی‌تر است و انواع ورودی‌ها و خروجی‌های متفاوت را مجاز می‌کند. برای مثال، یکپارچه‌کردن Salsa با یک IDE می‌تواند یعنی ورودی‌ها می‌توانند manifestها (Cargo.toml، rust-toolchain.toml)، فایل‌های منبع کامل (foo.rs)، تکه‌کدها و غیره باشند. خروجی‌های چنین یکپارچگی می‌تواند از فایل اجرایی دودویی تا lintها، نوع‌ها (مثلاً اگر کاربر متغیر مشخصی را انتخاب کند و بخواهد نوع آن را ببیند)، تکمیل‌های خودکار و غیره متغیر باشد.

    چگونه کار می‌کند؟

    اولین کاری که Salsa باید بکند شناسایی «ورودی‌های پایه» است که چیزی محاسبه‌شده نیستند بلکه به‌عنوان ورودی داده می‌شوند.

    سپس Salsa باید مقادیر میانی «مشتق‌شده» را هم شناسایی کند، که چیزی هستند که کتابخانه تولید می‌کند، اما برای هر مقدار مشتق‌شده یک تابع «خالص» هست که آن را محاسبه می‌کند.

    برای مثال ممکن است تابعی مثل ast(x: Path) -> AST باشد. درخت نحو انتزاعی (AST) تولیدشده مقدار نهایی نیست؛ مقدار میانی‌ای است که کتابخانه برای محاسبه از آن استفاده می‌کند.

    یعنی وقتی با کتابخانه محاسبه می‌کنید، Salsa مقادیر مشتق‌شدهٔ مختلفی را محاسبه می‌کند و در نهایت ورودی را می‌خواند و نتیجهٔ محاسبهٔ درخواست‌شده را تولید می‌کند.

    در جریان محاسبه، Salsa ردیابی می‌کند کدام ورودی‌ها دسترسی شدند و کدام مقادیر مشتق‌شده‌اند. این اطلاعات برای تعیین اینکه با تغییر ورودی‌ها چه می‌شود به‌کار می‌رود: آیا مقادیر مشتق‌شده هنوز معتبرند؟

    این لزوماً یعنی هر محاسبهٔ پایین‌دست ورودی بررسی می‌شود، که می‌تواند پرهزینه باشد. Salsa فقط باید هر محاسبهٔ پایین‌دست را تا یافتن محاسبه‌ای که تغییر نکرده بررسی کند. در آن نقطه، محاسبات مشتق‌شدهٔ دیگر را بررسی نمی‌کند چون نیازی به تغییر ندارند.

    مفید است به این به‌صورت گرافی با گره‌ها فکر کنیم. هر مقدار مشتق‌شده به مقادیر دیگر وابستگی دارد، که خودشان می‌توانند پایه یا مشتق‌شده باشند. مقادیر پایه وابستگی ندارند.

    I <- A <- C ...
          |
J <- B <--+

    وقتی ورودی I تغییر می‌کند، مقدار مشتق‌شدهٔ A می‌تواند تغییر کند. مقدار مشتق‌شدهٔ B، که به I، A یا هر مقدار مشتق‌شده از A یا I وابسته نیست، در معرض تغییر نیست. بنابراین Salsa می‌تواند محاسبه‌ای را که در گذشته برای B انجام شده دوباره استفاده کند، بدون اینکه مجبور به محاسبهٔ دوبارهٔ آن باشد.

    محاسبه می‌تواند زودتر هم تمام شود. با حفظ همان گراف قبلی، فرض کنید ورودی I به نحوی تغییر کرده است (و ورودی J نه)، اما هنگام محاسبهٔ دوبارهٔ A، معلوم می‌شود A نسبت به محاسبهٔ قبلی تغییر نکرده است. این به «خاتمهٔ زودهنگام» می‌انجامد، چون نیازی نیست بررسی کنیم آیا C باید تغییر کند، چون هر دو ورودی مستقیم C، یعنی A و B، تغییر نکرده‌اند.

    Key Salsa concepts

    Query

    کوئری مقداری است که Salsa در جریان محاسبه می‌تواند به آن دسترسی داشته باشد. هر کوئری می‌تواند تعدادی کلید داشته باشد (از ۰ تا چند)، و همهٔ کوئری‌ها نتیجه دارند، شبیه توابع. کوئری‌های 0-key «کوئری ورودی (input)» نامیده می‌شوند.

    Database

    پایگاه‌داده اساساً زمینهٔ کل محاسبه است، قرار است حالت داخلی Salsa، همهٔ مقادیر میانی هر کوئری و هر چیز دیگری را که محاسبه ممکن است لازم داشته باشد ذخیره کند. پایگاه‌داده باید همهٔ کوئری‌هایی را که کتابخانه قرار است انجام دهد پیش از ساخته‌شدن بشناسد، اما لازم نیست در یک جا مشخص شوند.

    پس از تشکیل پایگاه‌داده، می‌توان با کوئری‌هایی بسیار شبیه توابع به آن دسترسی داشت. چون نتیجهٔ هر کوئری در پایگاه‌داده ذخیره می‌شود، وقتی کوئری N بار فراخوانی شود، N نتیجهٔ clone‌شده برمی‌گرداند، بدون اینکه مجبور به محاسبهٔ دوبارهٔ کوئری باشد (مگر اینکه ورودی به شکلی تغییر کرده باشد که محاسبهٔ مجدد را توجیه کند).

    برای هر کوئری ورودی (0-key)، یک متد «set» تولید می‌شود که به کاربر اجازه می‌دهد خروجی چنین کوئری را تغییر دهد و باعث شود مقادیر memoize‌شدهٔ قبلی به‌طور بالقوه باطل شوند.

    Query Groups

    گروه کوئری مجموعه‌ای از کوئری‌هاست که با هم به‌عنوان یک واحد تعریف شده‌اند. پایگاه‌داده با ترکیب گروه‌های کوئری تشکیل می‌شود. گروه‌های کوئری شبیه «ماژول‌های Salsa» هستند.

    مجموعهٔ کوئری‌ها در یک گروه کوئری فقط مجموعه‌ای از متدها در یک trait هستند.

    برای ساخت گروه کوئری باید traitی ساخته شود که با attribute مشخصی (#[salsa::query_group(...)]) annotate شده باشد.

    همچنین باید آرگومانی به آن attribute داده شود چون Salsa از آن برای ساخت structی استفاده می‌کند که بعداً هنگام ساخت پایگاه‌داده به‌کار می‌رود.

    مثال گروه کوئری ورودی:

    /// This attribute will process this tree, produce this tree as output, and produce
/// a bunch of intermediate stuff that Salsa also uses. One of these things is a
/// "StorageStruct", whose name we have specified in the attribute.
///
/// This query group is a bunch of **input** queries, that do not rely on any
/// derived input.
#[salsa::query_group(InputsStorage)]
pub trait Inputs {
    /// This attribute (`#[salsa::input]`) indicates that this query is a base
    /// input, therefore `set_manifest` is going to be auto-generated
    #[salsa::input]
    fn manifest(&self) -> Manifest;

    #[salsa::input]
    fn source_text(&self, name: String) -> String;
}

    برای ساخت گروه کوئری مشتق‌شده، باید مشخص کنیم این گروه به کدام گروه‌های کوئری دیگر وابسته است، با تعیین آن‌ها به‌صورت supertrait، همان‌طور که در مثال زیر دیده می‌شود:

    /// This query group is going to contain queries that depend on derived values.
/// A query group can access another query group's queries by specifying the
/// dependency as a supertrait. Query groups can be stacked as much as needed using
/// that pattern.
#[salsa::query_group(ParserStorage)]
pub trait Parser: Inputs {
    /// This query `ast` is not an input query, it's a derived query this means
    /// that a definition is necessary.
    fn ast(&self, name: String) -> String;
}

    هنگام ساخت کوئری مشتق‌شده، پیاده‌سازی آن کوئری باید بیرون از trait تعریف شود. تعریف باید پارامتر پایگاه‌داده را به‌صورت impl Trait (یا dyn Trait) بگیرد، که trait همان گروه کوئری‌ای است که تعریف به آن تعلق دارد، علاوه بر کلیدهای دیگر.

    /// This is going to be the definition of the `ast` query in the `Parser` trait.
/// So, when the query `ast` is invoked, and it needs to be recomputed, Salsa is
/// going to call this function and it's going to give it the database as `impl
/// Parser`. The function doesn't need to be aware of all the queries of all the
/// query groups
fn ast(db: &impl Parser, name: String) -> String {
    //! Note, `impl Parser` is used here but `dyn Parser` works just as well
    /* code */
    ///By passing an `impl Parser`, this is allowed
    let source_text = db.input_file(name);
    /* do the actual parsing */
    return ast;
}

    در نهایت، پس از تعریف همهٔ گروه‌های کوئری، می‌توان پایگاه‌داده را با اعلان یک struct ساخت.

    برای مشخص‌کردن اینکه کدام گروه‌های کوئری بخشی از پایگاه‌داده خواهند بود باید یک attribute (#[salsa::database(...)]) اضافه شود. آرگومان آن attribute فهرستی از identifierهاست که ذخیره‌گاه‌های (storages) گروه‌های کوئری را مشخص می‌کند.

    ///This attribute specifies which query groups are going to be in the database
#[salsa::database(InputsStorage, ParserStorage)]
#[derive(Default)] //optional!
struct MyDatabase {
    ///You also need this one field
    runtime : salsa::Runtime<MyDatabase>,
}
///And this trait has to be implemented
impl salsa::Database for MyDatabase {
    fn salsa_runtime(&self) -> &salsa::Runtime<MyDatabase> {
        &self.runtime
    }
}

    Example usage:

    fn main() {
    let db = MyDatabase::default();
    db.set_manifest(...);
    db.set_source_text(...);
    loop {
        db.ast(...); //will reuse results
        db.set_source_text(...);
    }
}
