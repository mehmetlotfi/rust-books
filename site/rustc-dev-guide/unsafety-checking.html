    بررسی ایمنی

    برخی عبارت‌ها در Rust می‌توانند ایمنی حافظه را نقض کنند و به همین دلیل باید درون یک بلاک یا تابع unsafe قرار بگیرند. کامپایلر همچنین هشدار می‌دهد اگر یک بلاک unsafe بدون هیچ عملیات ناامن متناظری استفاده شده باشد.

    مرور کلی

    بررسی ایمنی در ماژول check_unsafety قرار دارد. این بررسی یک پیمایش روی THIR یک تابع و همهٔ closureها و ثابت‌های درون‌خطی (inline constant) آن انجام می‌دهد. بررسی، زمینهٔ ناامن (unsafe context) را دنبال می‌کند: اینکه آیا وارد یک بلاک unsafe شده است یا نه. اگر یک عملیات ناامن بیرون از بلاک unsafe استفاده شود، خطا گزارش می‌شود. اگر یک عملیات ناامن درون یک بلاک unsafe استفاده شود، آن بلاک برای lint unused_unsafe به‌عنوان «استفاده‌شده» علامت‌گذاری می‌شود.

    بررسی ایمنی به اطلاعات نوع نیاز دارد، بنابراین می‌توانست روی HIR (با استفاده از نتایج typeck)، THIR یا MIR انجام شود. THIR انتخاب شده است، زیرا حالت‌های کمتری نسبت به HIR باید در نظر گرفته شوند؛ برای مثال فراخوانی تابع ناامن و فراخوانی متد ناامن در THIR بازنمایی یکسانی دارند. این بررسی روی MIR انجام نمی‌شود، زیرا بررسی‌های ایمنی به جریان کنترل وابسته نیستند، پس نیازی به استفاده از MIR نیست. همچنین، MIR برای برخی عبارت‌ها span دقیق کافی ندارد.

    بیشتر عملیات ناامن را می‌توان با بررسی ExprKind در THIR و بررسی نوع آرگومان شناسایی کرد. برای مثال، ارجاع‌زدایی (dereference) از یک اشاره‌گر خام متناظر با ExprKind::Derefهایی است که آرگومانی با نوع اشاره‌گر خام دارند.

    جست‌وجوی دسترسی‌های ناامن به فیلد Union کمی پیچیده‌تر است، زیرا نوشتن در یک فیلد یونیون ایمن است. بررسی‌کننده دنبال می‌کند که چه زمانی در حال بازدید از سمت چپ یک عبارت انتساب است و اجازه می‌دهد فیلدهای یونیون مستقیماً در آنجا ظاهر شوند، اما در همهٔ حالت‌های دیگر خطا می‌دهد. دسترسی به فیلد یونیون می‌تواند در الگوها نیز رخ دهد، بنابراین آن‌ها هم باید پیمایش شوند.

    lint unused_unsafe

    lint unused_unsafe بلاک‌های unsafeای را گزارش می‌کند که می‌توان آن‌ها را حذف کرد. بررسی‌کنندهٔ ایمنی هر زمان عملیاتی را بیابد که به unsafe نیاز دارد، آن را ثبت می‌کند. سپس lint در یکی از این دو حالت گزارش می‌شود:

    • یک بلاک unsafe هیچ عملیات ناامنی نداشته باشد
    • یک بلاک unsafe درون بلاک unsafe دیگری باشد و بلاک بیرونی «استفاده‌نشده» تلقی نشود
    #![deny(unused_unsafe)]
let y = 0;
let x: *const u8 = core::ptr::addr_of!(y);
unsafe { // lint reported for this block
    unsafe {
        let z = *x;
    }
    let safe_expr = 123;
}
unsafe {
    unsafe { // lint reported for this block
        let z = *x;
    }
    let unsafe_expr = *x;
}

    سایر بررسی‌های مربوط به unsafe

    صفت‌های ناامن (unsafe trait) برای پیاده‌سازی به unsafe impl نیاز دارند و بررسی آن به‌عنوان بخشی از بررسی انسجام (coherence) انجام می‌شود. lint unsafe_code به‌صورت یک lint pass روی AST اجرا می‌شود و بلاک‌ها، توابع و پیاده‌سازی‌های unsafe و نیز برخی attributeهای ناامن را جست‌وجو می‌کند.
