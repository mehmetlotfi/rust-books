    Apple notification group

    برچسب‌های GitHub: O-macos، O-ios، O-tvos، O-watchos و O-visionos
    دستور ping: @rustbot ping apple

    این فهرست برای درخواست کمک هم در تشخیص و تست مسائل مرتبط با Apple و هم پیشنهادهایی برای حل پرسش‌های جالب دربارهٔ پشتیبانی ما از macOS/iOS/tvOS/watchOS/visionOS به‌کار می‌رود.

    برای تصور بهتر از کاری که گروه انجام می‌دهد، در ادامه مثال‌هایی از انواع پرسش‌هایی آمده که برای تعیین بهترین مسیر اقدام از گروه مشورت می‌خواستیم:

    • بالا بردن حداقل نسخه‌های پشتیبانی‌شده (مثلاً #104385)
    • اهداف Apple اضافی (مثلاً #121419)
    • جزئیات مبهم لینکر Xcode (مثلاً #121430)

    Deployment targets

    پلتفرم‌های Apple مفهومی به نام «deployment target» دارند که با متغیرهای محیطی *_DEPLOYMENT_TARGET کنترل می‌شود و حداقل نسخهٔ سیستم‌عاملی را مشخص می‌کند که فایل دودویی روی آن اجرا می‌شود.

    استفاده از API نسخهٔ جدیدتر سیستم‌عامل در کتابخانهٔ استاندارد نسبت به پیش‌فرضی که rustc به‌کار می‌برد باعث خطای لینکر استاتیک یا پویا می‌شود. به همین دلیل، سعی کنید پیشنهاد دهید افراد روی APIهای extern "C" مستند کنند در کدام نسخهٔ سیستم‌عامل معرفی شده‌اند، و اگر از پیش‌فرض فعلی rustc جدیدتر است، پیشنهاد دهید از weak linking استفاده شود.

    App Store و APIهای خصوصی

    Apple نسبت به استفاده از APIهای مستندنشده بسیار سخت‌گیر است، پس مهم است هر وقت تغییری از تابع جدیدی استفاده می‌کند، بررسی شود واقعاً API عمومی باشد، چون حتی صرف ذکر APIهای مستندنشده در فایل دودویی (بدون فراخوانی آن‌ها) می‌تواند به رد شدن از App Store منجر شود.

    برای مثال، Darwin / هستهٔ XNU در واقع syscallهای futex دارد، اما نمی‌توانیم آن‌ها را در std استفاده کنیم چون API عمومی نیستند.

    عموماً برای اینکه API از نظر Apple عمومی به حساب بیاید، باید:

    • در یک header عمومی ظاهر شود (یعنی headerی که با Xcode توزیع می‌شود و برای پلتفرم مشخص زیر xcrun --show-sdk-path --sdk $SDK یافت می‌شود).
    • attribute مربوط به availability داشته باشد (مثل __API_AVAILABLE، API_AVAILABLE یا مشابه).
