    پیوند دادن به آیتم‌ها با نام

    Rustdoc می‌تواند با استفاده از مسیر یک آیتم به‌عنوان پیوند، مستقیماً به صفحه‌های rustdoc دیگر پیوند دهد. به این کار «پیوند درون‌مستندی» (intra-doc link) گفته می‌شود.

    برای مثال، در کد زیر همهٔ پیوندها به صفحهٔ rustdoc مربوط به Bar پیوند می‌دهند:

    /// This struct is not [Bar]
pub struct Foo1;

/// This struct is also not [bar](Bar)
pub struct Foo2;

/// This struct is also not [bar][b]
///
/// [b]: Bar
pub struct Foo3;

/// This struct is also not [`Bar`]
pub struct Foo4;

/// This struct *is* [`Bar`]!
pub struct Bar;

    برخلاف Markdown معمولی، نحو bar نیز بدون نیاز به پیوند مرجع [Bar]: ... پشتیبانی می‌شود.

    backtickهای دور پیوند حذف می‌شوند، بنابراین [`Option`] به‌درستی به Option پیوند می‌دهد.

    پیوندهای معتبر

    می‌توانید به هر چیزی که در دامنه است اشاره کنید و از مسیرها استفاده کنید، از جمله Self، self، super و crate. آیتم‌های وابسته (توابع، نوع‌ها و ثابت‌ها) پشتیبانی می‌شوند، اما برای پیاده‌سازی‌های فراگیر (blanket) صفت‌ها پشتیبانی نمی‌شوند. Rustdoc همچنین از پیوند دادن به همهٔ نوع‌های اولیه‌ای که در مستندات کتابخانهٔ استاندارد فهرست شده‌اند پشتیبانی می‌کند.

    همچنین می‌توانید به آیتم‌هایی با پارامترهای جنریک مانند Vec<T> اشاره کنید. پیوند طوری حل می‌شود که گویی [`Vec<T>`](https://github.com/rust-lang/rust/issues/74563) را نوشته‌اید. با این حال، نحو کاملاً مشخص (fully-qualified) (برای مثال، <Vec as IntoIterator>::into_iter()) هنوز پشتیبانی نمی‌شود.

    use std::sync::mpsc::Receiver;

/// This is a version of [`Receiver<T>`] with support for [`std::future`].
///
/// You can obtain a [`std::future::Future`] by calling [`Self::recv()`].
pub struct AsyncReceiver<T> {
    sender: Receiver<T>
}

impl<T> AsyncReceiver<T> {
    pub async fn recv() -> T {
        unimplemented!()
    }
}

    Rustdoc اجازه می‌دهد از مشخص‌کننده‌های fragment در URL استفاده کنید، درست مانند یک پیوند معمولی:

    /// This is a special implementation of [positional parameters].
///
/// [positional parameters]: std::fmt#formatting-parameters
struct MySpecialFormatter;

    فضاهای نام و رفع‌کننده‌های ابهام

    مسیرها در Rust سه فضای نام دارند: نوع، مقدار و ماکرو. نام آیتم‌ها باید درون فضای نام خود یکتا باشد، اما می‌تواند با آیتم‌های فضاهای نام دیگر هم‌پوشانی داشته باشد. در صورت ابهام، rustdoc دربارهٔ ابهام هشدار می‌دهد و یک رفع‌کنندهٔ ابهام (disambiguator) پیشنهاد می‌کند.

    /// See also: [`Foo`](struct@Foo)
struct Bar;

/// This is different from [`Foo`](fn@Foo)
struct Foo {}

fn Foo() {}

    این پیشوندها هنگام نمایش در مستندات حذف می‌شوند، بنابراین [struct@Foo] به‌صورت Foo نمایش داده می‌شود. پیشوندهای زیر در دسترس‌اند: struct، enum، trait، union، mod، module، const، constant، fn، function، field، variant، method، derive، type، value، macro، tyalias، typealias، prim یا primitive.

    همچنین می‌توانید برای توابع با افزودن () پس از نام تابع، یا برای ماکروها با افزودن ! پس از نام ماکرو، ابهام را برطرف کنید. پس از ! در ماکرو می‌توان ()، {} یا [] آورد. مثال:

    /// This is different from [`foo!()`].
fn foo() {}

/// This is different from [`foo()`]
macro_rules! foo {
  () => {}
}

    یک مورد وجود دارد که رفع ابهام در آن به‌طور خودکار انجام می‌شود: اگر یک پیوند درون‌مستندی هم‌زمان به‌عنوان یک صفت و هم به‌عنوان یک ماکروی رویه‌ای derive حل شود. در این حالت، همیشه پیوندی به صفت تولید می‌کند و هشدار «missing disambiguation» صادر نمی‌کند. یک نمونهٔ خوب از این حالت زمانی است که به صفت Clone پیوند می‌دهید: یک ماکروی رویه‌ای Clone هم وجود دارد، اما در این حالت آن را نادیده می‌گیرد. اگر می‌خواهید به ماکروی رویه‌ای پیوند دهید، می‌توانید از رفع‌کنندهٔ ابهام macro@ استفاده کنید.

    هشدارها، بازصادرکردن‌ها و دامنه

    پیوندها در دامنهٔ ماژولی که آیتم در آن تعریف شده حل می‌شوند، حتی وقتی آیتم بازصادر (re-export) شده باشد. اگر پیوندی از crate دیگر حل نشود، هیچ هشداری داده نمی‌شود.

    mod inner {
    /// Link to [f()]
    pub struct S;
    pub fn f() {}
}
pub use inner::S; // the link to `f` will still resolve correctly

    هنگام بازصادر کردن یک آیتم، rustdoc اجازه می‌دهد مستندات اضافی به آن افزوده شود. آن مستندات اضافی در دامنهٔ بازصادرکردن حل می‌شوند، نه دامنهٔ اصلی، و این به شما اجازه می‌دهد به آیتم‌های crate جدید پیوند دهید. پیوندهای جدید در صورت ناکامی در حل شدن همچنان هشدار می‌دهند.

    /// See also [foo()]
pub use std::process::Command;

pub fn foo() {}

    این مورد به‌ویژه برای ماکروهای رویه‌ای مفید است که همیشه باید در crate اختصاصی خودشان تعریف شوند.

    نکته: به دلیل نحوهٔ تعیین دامنهٔ ماکروهای macro_rules! در Rust، پیوندهای درون‌مستندی یک ماکروی macro_rules! نسبت به ریشهٔ crate حل می‌شوند، نه نسبت به ماژولی که در آن تعریف شده است.

    اگر پیوندها «به‌اندازهٔ کافی شبیه» یک پیوند درون‌مستندی نباشند، نادیده گرفته می‌شوند و هیچ هشداری داده نمی‌شود، حتی اگر پیوند حل نشود. برای مثال، هر پیوندی که حاوی نویسهٔ / یا [] باشد نادیده گرفته می‌شود.

    وقتی پیوند درون‌مستندی قابل تولید نباشد چه می‌شود

    در برخی موارد (برای مثال آیتم‌هایی پشت یک cfg)، نمی‌توان پیوند درون‌مستندی به آیتم تولید کرد. روش‌های مختلفی برای ساخت پیوند در markdown وجود دارد و بسته به روشی که استفاده کنید، در این حالت به شکل متفاوتی نمایش داده می‌شود:

    1. [a]
2. [b][c]
3. [d](e)
4. [f]

[f]: g

    1. و 2. در مستندات تولیدشده همان‌طور که هستند نمایش داده می‌شوند (یعنی [a] و b)، در حالی که 3. و 4. با پیوندی جایگزین می‌شوند که برای d به e و برای [f] به g اشاره می‌کند.
