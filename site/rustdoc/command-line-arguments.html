کتاب rustdocThe rustdoc Book

    آرگومان‌های خط فرمان

    در اینجا فهرست آرگومان‌هایی که می‌توانید به rustdoc بدهید آمده است:

    -h/--help: راهنما

    استفاده از این پرچم به این شکل است:

    $ rustdoc -h
$ rustdoc --help

    این کار راهنمای داخلی rustdoc را نشان می‌دهد که عمدتاً شامل فهرستی از پرچم‌های ممکن خط فرمان است.

    برخی از پرچم‌های rustdoc ناپایدارند؛ این صفحه فقط گزینه‌های پایدار را نشان می‌دهد، اما --help همهٔ آن‌ها را نمایش می‌دهد.

    -V/--version: اطلاعات نسخه

    استفاده از این پرچم به این شکل است:

    $ rustdoc -V
$ rustdoc --version

    این کار نسخهٔ rustdoc را نشان می‌دهد که چیزی شبیه این خواهد بود:

    rustdoc 1.17.0 (56124baa9 2017-04-24)

    -v/--verbose: خروجی مفصل‌تر

    استفاده از این پرچم به این شکل است:

    $ rustdoc -v src/lib.rs
$ rustdoc --verbose src/lib.rs

    این پرچم «حالت مفصل (verbose)» را فعال می‌کند، یعنی اطلاعات بیشتری روی خروجی استاندارد نوشته می‌شود. اینکه چه چیزی نوشته شود به پرچم‌های دیگری که داده‌اید بستگی دارد. برای مثال، با --version:

    $ rustdoc --verbose --version
rustdoc 1.17.0 (56124baa9 2017-04-24)
binary: rustdoc
commit-hash: hash
commit-date: date
host: host-tuple
release: 1.17.0
LLVM version: 3.9

    -o/--out-dir: مسیر پوشهٔ خروجی

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs -o target/doc
$ rustdoc src/lib.rs --out-dir target/doc

    به‌طور پیش‌فرض، خروجی rustdoc در پوشه‌ای به نام doc در پوشهٔ کاری فعلی قرار می‌گیرد. با این پرچم، تمام خروجی را در پوشه‌ای که مشخص می‌کنید قرار می‌دهد.

    --crate-name: کنترل نام crate

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --crate-name mycrate

    به‌طور پیش‌فرض، rustdoc فرض می‌کند که نام crate شما همان نام فایل .rs است. --crate-name به شما اجازه می‌دهد این فرض را با هر نامی که انتخاب می‌کنید جایگزین کنید.

    --document-private-items: نمایش آیتم‌هایی که عمومی نیستند

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --document-private-items

    به‌طور پیش‌فرض، rustdoc فقط آیتم‌هایی را مستندسازی می‌کند که به‌صورت عمومی در دسترس‌اند.

    pub fn public() {} // this item is public and will be documented
mod private { // this item is private and will not be documented
    pub fn unreachable() {} // this item is public, but unreachable, so it will not be documented
}

    --document-private-items همهٔ آیتم‌های غیرعمومی را به‌جز آیتم‌های #[doc(hidden)] در مستندات تولیدشده می‌گنجاند. آیتم‌های خصوصی با آیکون 🔒 نمایش داده می‌شوند.

    -L/--library-path: محل جستجو برای وابستگی‌ها

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs -L target/debug/deps
$ rustdoc src/lib.rs --library-path target/debug/deps

    اگر crate شما وابستگی دارد، rustdoc باید بداند که آن‌ها را کجا پیدا کند. دادن --library-path فهرستی از مکان‌ها را برای جستجوی این وابستگی‌ها در اختیار rustdoc قرار می‌دهد.

    این پرچم هر تعداد پوشه را به‌عنوان آرگومان می‌پذیرد و هنگام جستجو از همهٔ آن‌ها استفاده می‌کند.

    --cfg: ارسال پرچم‌های پیکربندی

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --cfg feature="foo"

    این پرچم همان مقادیری را می‌پذیرد که rustc --cfg می‌پذیرد و از آن برای پیکربندی کامپایل استفاده می‌کند. مثال بالا از feature استفاده می‌کند، اما هر یک از مقادیر cfg قابل قبول است.

    --check-cfg: بررسی پرچم‌های پیکربندی

    این پرچم همان مقادیری را می‌پذیرد که rustc --check-cfg می‌پذیرد و از آن برای بررسی پرچم‌های پیکربندی استفاده می‌کند.

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --check-cfg='cfg(my_cfg, values("foo", "bar"))'

    مثال بالا تمام نام‌ها و مقادیر شناخته‌شده (target_os، doc، test، …) را بررسی می‌کند و مقادیر my_cfg یعنی foo و bar را نیز بررسی می‌کند.

    --extern: مشخص کردن محل یک وابستگی

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --extern lazy-static=/path/to/lazy-static

    مشابه --library-path، پرچم --extern نیز دربارهٔ مشخص کردن محل یک وابستگی است. --library-path پوشه‌هایی را برای جستجو فراهم می‌کند، اما --extern به شما اجازه می‌دهد دقیقاً مشخص کنید کدام وابستگی در کجا قرار دارد.

    -C/--codegen: ارسال گزینه‌های codegen به rustc

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs -C target_feature=+avx
$ rustdoc src/lib.rs --codegen target_feature=+avx

$ rustdoc --test src/lib.rs -C target_feature=+avx
$ rustdoc --test src/lib.rs --codegen target_feature=+avx

$ rustdoc --test README.md -C target_feature=+avx
$ rustdoc --test README.md --codegen target_feature=+avx

    وقتی rustdoc مستندات تولید می‌کند، به دنبال آزمون‌های مستندات می‌گردد یا آزمون‌های مستندات را اجرا می‌کند، لازم است مقداری کد Rust را دست‌کم تا حدی کامپایل کند. این پرچم به شما اجازه می‌دهد به rustdoc بگویید هنگام اجرای این کامپایل‌ها چند گزینهٔ codegen اضافی به rustc بدهد. در بیشتر موارد این گزینه‌ها بر یک اجرای معمول تولید مستندات اثر نمی‌گذارند، اما اگر چیزی به فعال بودن قابلیت‌های هدف (target features) وابسته باشد یا آزمون‌های مستندات نیاز به گزینه‌های اضافی داشته باشند، این پرچم به شما امکان می‌دهد بر آن اثر بگذارید.

    آرگومان‌های این پرچم همان آرگومان‌های پرچم -C در rustc هستند. برای دریافت فهرست کامل، rustc -C help را اجرا کنید.

    --remap-path-prefix: بازنگاشت مسیرهای منبع در خروجی

    این پرچم معادل همان پرچم rustc یعنی --remap-path-prefix است.

    $ rustdoc src/lib.rs --remap-path-prefix="$PWD=/foo"

    این پرچم اجازه می‌دهد (در حد امکان) پیشوند مسیرهای منبع در همهٔ خروجی‌ها، از جمله تشخیص‌ها (diagnostics)، اطلاعات اشکال‌زدایی، بسط ماکروها، مستندات تولیدشده و غیره بازنگاشت شود. این پرچم مقداری به شکل FROM=TO می‌گیرد که در آن پیشوند مسیری برابر با FROM به مقدار TO بازنویسی می‌شود.

    --test: اجرای مثال‌های کد به‌عنوان آزمون

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --test

    این پرچم مثال‌های کد شما را به‌عنوان آزمون اجرا می‌کند. برای اطلاعات بیشتر، فصل مربوط به آزمون‌های مستندات را ببینید.

    همچنین --test-args و --test-run-directory را ببینید.

    --test-args: ارسال گزینه‌ها به اجراکنندهٔ آزمون

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --test --test-args ignored

    این پرچم هنگام اجرای آزمون‌های مستندات، گزینه‌ها را به اجراکنندهٔ آزمون (test runner) می‌فرستد. برای اطلاعات بیشتر، فصل مربوط به آزمون‌های مستندات را ببینید.

    همچنین --test را ببینید.

    --test-run-directory: اجرای مثال‌های کد در یک پوشهٔ مشخص

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --test --test-run-directory=/path/to/working/directory

    این پرچم مثال‌های کد شما را در پوشهٔ کاری مشخص‌شده اجرا می‌کند. برای اطلاعات بیشتر، فصل مربوط به آزمون‌های مستندات را ببینید.

    همچنین --test را ببینید.

    --test-runtool، --test-runtool-arg: برنامه‌ای برای اجرای آزمون‌ها و آرگومان‌های آن

    یک برنامهٔ پوششی (wrapper) برای doctest را می‌توان با پرچم --test-runtool مشخص کرد. Rustdoc هنگام اجرای آزمون‌ها به‌جای فایل اجرایی doctest، آن wrapper را اجرا می‌کند. نخستین آرگومان‌های wrapper هر آرگومانی خواهد بود که با پرچم --test-runtool-arg مشخص شده باشد و پس از آن مسیر فایل اجرایی doctest که باید اجرا شود.

    استفاده از این گزینه‌ها به این شکل است:

    $ rustdoc src/lib.rs --test-runtool path/to/runner --test-runtool-arg --do-thing --test-runtool-arg --do-other-thing

    برای مثال، اگر بخواهید doctestهای خود را زیر valgrind اجرا کنید، می‌توانید این را اجرا کنید:

    $ rustdoc src/lib.rs --test-runtool valgrind

    یک کاربرد دیگر اجرای یک آزمون درون یک شبیه‌ساز یا از طریق یک ماشین مجازی است.

    --target: تولید مستندات برای سه‌گانهٔ هدف مشخص‌شده

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --target x86_64-pc-windows-gnu

    مشابه پرچم --target در rustc، این پرچم مستندات را برای یک سه‌گانهٔ هدف (target triple) که با سه‌گانهٔ میزبان شما متفاوت است تولید می‌کند.

    همهٔ هشدارها و ملاحظات معمول کامپایل متقابل (cross-compiling) کد در اینجا هم صادق است.

    --default-theme: تنظیم پوستهٔ پیش‌فرض

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --default-theme=ayu

    پوستهٔ (theme) پیش‌فرض را تنظیم می‌کند (برای کاربرانی که مرورگرشان انتخاب قبلی پوسته را از انتخاب‌گر پوستهٔ درون صفحه به خاطر نسپرده است).

    مقدار داده‌شده باید نسخهٔ با حروف کوچک نام پوسته باشد. مجموعهٔ پوسته‌های در دسترس را می‌توان در انتخاب‌گر پوسته در خروجی تولیدشده دید.

    توجه کنید که مجموعهٔ پوسته‌های در دسترس — و ظاهر آن‌ها — لزوماً از یک نسخهٔ rustdoc تا نسخهٔ بعدی پایدار نیست. اگر پوستهٔ درخواستی وجود نداشته باشد، به‌جای آن پیش‌فرض داخلی (در حال حاضر light) استفاده می‌شود.

    --markdown-css: افزودن فایل‌های CSS بیشتر هنگام رندر کردن markdown

    استفاده از این پرچم به این شکل است:

    $ rustdoc README.md --markdown-css foo.css

    هنگام رندر کردن فایل‌های Markdown، این پرچم یک عنصر <link> در بخش <head> از HTML تولیدشده ایجاد می‌کند. برای مثال، با فراخوانی بالا،

    <link rel="stylesheet" type="text/css" href="foo.css">

    اضافه خواهد شد.

    هنگام رندر کردن فایل‌های Rust، این پرچم نادیده گرفته می‌شود.

    --html-in-header: افزودن HTML بیشتر در <head>

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --html-in-header header.html
$ rustdoc README.md --html-in-header header.html

    این پرچم فهرستی از فایل‌ها می‌گیرد و آن‌ها را در بخش <head> مستندات رندرشده درج می‌کند.

    --html-before-content: افزودن HTML بیشتر پیش از محتوا

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --html-before-content extra.html
$ rustdoc README.md --html-before-content extra.html

    این پرچم فهرستی از فایل‌ها می‌گیرد و آن‌ها را درون تگ <body> اما پیش از محتوای دیگری که rustdoc به‌طور معمول در مستندات رندرشده تولید می‌کرد، درج می‌کند.

    --html-after-content: افزودن HTML بیشتر پس از محتوا

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --html-after-content extra.html
$ rustdoc README.md --html-after-content extra.html

    این پرچم فهرستی از فایل‌ها می‌گیرد و آن‌ها را پیش از تگ </body> اما پس از محتوای دیگری که rustdoc به‌طور معمول در مستندات رندرشده تولید می‌کرد، درج می‌کند.

    --markdown-playground-url: کنترل نشانی playground

    استفاده از این پرچم به این شکل است:

    $ rustdoc README.md --markdown-playground-url https://play.rust-lang.org/

    هنگام رندر کردن یک فایل Markdown، این پرچم نشانی پایهٔ Rust Playground را مشخص می‌کند تا برای تولید دکمه‌های Run استفاده شود.

    --markdown-no-toc: عدم تولید فهرست مطالب

    استفاده از این پرچم به این شکل است:

    $ rustdoc README.md --markdown-no-toc

    هنگام تولید مستندات از یک فایل Markdown، به‌طور پیش‌فرض rustdoc یک فهرست مطالب تولید می‌کند. این پرچم آن را متوقف می‌کند و هیچ فهرست مطالبی (TOC) تولید نخواهد شد.

    -e/--extend-css: گسترش CSS مربوط به rustdoc

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs -e extra.css
$ rustdoc src/lib.rs --extend-css extra.css

    با این پرچم، محتوای فایل‌هایی که می‌دهید در انتهای فایل theme.css گنجانده می‌شود.

    --sysroot: بازنویسی ریشهٔ سیستم

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --sysroot /path/to/sysroot

    مشابه rustc --sysroot، این پرچم به شما اجازه می‌دهد sysrootی را که rustdoc هنگام کامپایل کد شما استفاده می‌کند تغییر دهید.

    --edition: کنترل edition مستندات و doctestها

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --edition 2018
$ rustdoc --test src/lib.rs --edition 2018

    این پرچم به rustdoc اجازه می‌دهد کد Rust شما را مطابق edition داده‌شده در نظر بگیرد. doctestها را نیز با همان edition کامپایل می‌کند. مانند rustc، edition پیش‌فرضی که rustdoc استفاده می‌کند 2015 (نخستین edition) است.

    --theme: افزودن یک پوسته به خروجی مستندات

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --theme /path/to/your/custom-theme.css

    خروجی پیش‌فرض rustdoc شامل دو پوسته است: light (پیش‌فرض) و dark. این پرچم به شما اجازه می‌دهد پوسته‌های سفارشی به خروجی اضافه کنید. دادن یک فایل CSS به این پرچم آن را به‌عنوان یک گزینهٔ پوستهٔ اضافی به مستندات شما می‌افزاید. نام پوسته از نام فایل آن تعیین می‌شود؛ یک فایل پوسته با نام custom-theme.css پوسته‌ای با نام custom-theme به مستندات اضافه می‌کند.

    --check-theme: تأیید پوسته‌های سفارشی در برابر پوستهٔ پیش‌فرض

    استفاده از این پرچم به این شکل است:

    $ rustdoc --check-theme /path/to/your/custom-theme.css

    اگرچه خروجی HTML مربوط به rustdoc میان نسخه‌ها کم‌وبیش ثابت است، تضمینی وجود ندارد که یک فایل پوسته همان اثر را داشته باشد. پرچم --theme همچنان به شما اجازه می‌دهد پوسته را به مستندات خود اضافه کنید، اما برای اطمینان از اینکه پوستهٔ شما مطابق انتظار کار می‌کند، می‌توانید از این پرچم برای تأیید اینکه همان قواعد CSS پوستهٔ رسمی light را پیاده‌سازی می‌کند استفاده کنید.

    --check-theme یک حالت مجزا در rustdoc است. وقتی rustdoc پرچم --check-theme را ببیند، همهٔ پرچم‌های دیگر را کنار می‌گذارد و فقط عملیات مقایسهٔ قواعد CSS را انجام می‌دهد.

    --crate-version: کنترل نسخهٔ crate

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --crate-version 1.3.37

    وقتی rustdoc این پرچم را دریافت کند، عبارت اضافی «Version (version)» را در نوار کناری مستندات ریشهٔ crate چاپ می‌کند. می‌توانید از این پرچم برای تمایز میان نسخه‌های مختلف مستندات کتابخانهٔ خود استفاده کنید.

    --emit: کنترل انواع خروجی‌ای که rustdoc تولید می‌کند

    این پرچم انواع خروجی rustdoc را کنترل می‌کند. فهرستی از مقادیر جداشده با ویرگول را می‌پذیرد و می‌توان آن را چندین بار مشخص کرد. انواع معتبر emit عبارت‌اند از:

    • html-static-files — فایل‌های ایستای مشترکی تولید می‌کند که محتوایشان به نسخهٔ مشخصی از toolchain وابسته است. این فایل‌ها با نام فایلی نوشته می‌شوند که شامل یک هش از محتوایشان است، بنابراین می‌توان با اطمینان آن‌ها را کش کرد و در صورت تغییر نسخهٔ toolchain یا محتوایشان نام جدیدی می‌گیرند، یا می‌توان از دستور Cache-Control: immutable استفاده کرد.
    • html-non-static-files — فایل‌هایی بر اساس crate یا crateهایی که مستندسازی می‌شوند تولید می‌کند. نام این فایل‌ها باید قطعی (deterministic) باشد، بنابراین هش محتوا در نام فایل‌هایشان وجود ندارد.
    • dep-info — فایلی با نحو Makefile تولید می‌کند که تمام فایل‌های منبعی را که برای مستندسازی crate بارگذاری شده‌اند نشان می‌دهد. نام فایل خروجی پیش‌فرض CRATE_NAME.d است. پس از این نوع emit می‌توان به‌صورت اختیاری = آورد تا مسیر خروجی صریحی مشخص شود، برای مثال، --emit=dep-info=/path/to/foo.d. با مشخص کردن - به‌عنوان مسیر می‌توان خروجی را به stdout فرستاد (مثلاً --emit=dep-info=-).

    استفاده از این پرچم به این شکل است:

    $ rustdoc src/lib.rs --emit=html-static-files,html-non-static-files,dep-info=/path/to/build/cache/foo.d

    اگر مشخص نشود، انواع emit پیش‌فرض --emit=html-static-files,html-non-static-files خواهند بود.

    فایل‌های خروجی در پوشهٔ فعلی نوشته می‌شوند مگر اینکه از پرچم --out-dir استفاده شود.

    -: بارگذاری کد منبع از ورودی استاندارد

    اگر - را به‌عنوان INPUT در خط فرمان مشخص کنید، rustdoc به‌جای سیستم فایل با مسیری که به‌طور دیگری مشخص شده باشد، کد منبع را از stdin (جریان ورودی استاندارد) تا EOF می‌خواند.

    @path: بارگذاری پرچم‌های خط فرمان از یک مسیر

    اگر @path را در خط فرمان مشخص کنید، path را باز می‌کند و گزینه‌های خط فرمان را از آن می‌خواند. این گزینه‌ها یکی در هر خط هستند؛ یک خط خالی نشان‌دهندهٔ یک گزینهٔ خالی است. فایل می‌تواند از پایان‌دهندهٔ خط به سبک Unix یا Windows استفاده کند و باید با UTF-8 کدگذاری شده باشد.

    --passes: افزودن گذرهای rustdoc بیشتر

    این پرچم منسوخ‌شده است. برای جزئیات بیشتر دربارهٔ گذرها (passes)، فصل مربوط به آن‌ها را ببینید.

    --no-defaults: عدم اجرای گذرهای پیش‌فرض

    این پرچم منسوخ‌شده است. برای جزئیات بیشتر دربارهٔ گذرها (passes)، فصل مربوط به آن‌ها را ببینید.

    -r/--input-format: قالب ورودی

    این پرچم منسوخ‌شده است و هیچ اثری ندارد.

    Rustdoc فقط از کد منبع Rust و قالب‌های ورودی Markdown پشتیبانی می‌کند. اگر فایل به .md یا .markdown ختم شود، rustdoc آن را فایل Markdown در نظر می‌گیرد. در غیر این صورت فرض می‌کند فایل ورودی Rust است.
