کتاب rustdocThe rustdoc Book

    Lintها

    rustdoc چند lint فراهم می‌کند تا در نوشتن و آزمودن مستندات به شما کمک کند. می‌توانید آن‌ها را مانند هر lint دیگری به این شکل به کار ببرید:

    #![allow(rustdoc::broken_intra_doc_links)] // allows the lint, no diagnostics will be reported
#![warn(rustdoc::broken_intra_doc_links)] // warn if there are broken intra-doc links
#![deny(rustdoc::broken_intra_doc_links)] // error if there are broken intra-doc links

    توجه کنید که به‌جز missing_docs، این lintها فقط هنگام اجرای rustdoc در دسترس‌اند، نه rustc.

    فهرست lintهایی که rustdoc فراهم می‌کند در ادامه آمده است:

    broken_intra_doc_links

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint زمانی را تشخیص می‌دهد که یک پیوند درون‌مستندی نتواند حل شود. برای مثال:

    /// I want to link to [`Nonexistent`] but it doesn't exist!
pub fn foo() {}

    هشداری با این مضمون دریافت می‌کنید:

    warning: unresolved link to `Nonexistent`
 --> test.rs:1:24
  |
1 | /// I want to link to [`Nonexistent`] but it doesn't exist!
  |                        ^^^^^^^^^^^^^ no item named `Nonexistent` in `test`

    همچنین وقتی ابهامی وجود داشته باشد هشدار می‌دهد و پیشنهاد می‌کند چگونه ابهام را برطرف کنید:

    /// [`Foo`]
pub fn function() {}

pub enum Foo {}

pub fn Foo(){}
    warning: `Foo` is both an enum and a function
 --> test.rs:1:6
  |
1 | /// [`Foo`]
  |      ^^^^^ ambiguous link
  |
  = note: `#[warn(rustdoc::broken_intra_doc_links)]` on by default
help: to link to the enum, prefix with the item type
  |
1 | /// [`enum@Foo`]
  |      ^^^^^^^^^^
help: to link to the function, add parentheses
  |
1 | /// [`Foo()`]
  |      ^^^^^^^

    private_intra_doc_links

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint زمانی را تشخیص می‌دهد که پیوندهای درون‌مستندی از آیتم‌های عمومی به آیتم‌های خصوصی اشاره کنند. برای مثال:

    #![warn(rustdoc::private_intra_doc_links)] // note: unnecessary - warns by default.

/// [private]
pub fn public() {}
fn private() {}

    این کد هشداری می‌دهد که پیوند هنگام نمایش در مستندات شما شکسته خواهد بود:

    warning: public documentation for `public` links to private item `private`
 --> priv.rs:1:6
  |
1 | /// [private]
  |      ^^^^^^^ this item is private
  |
  = note: `#[warn(rustdoc::private_intra_doc_links)]` on by default
  = note: this link will resolve properly if you pass `--document-private-items`

    توجه کنید که رفتار این lint بسته به این‌که --document-private-items را بدهید یا نه، متفاوت است! اگر آیتم‌های خصوصی را مستند کنید، با وجود هشدار، باز هم پیوند تولید می‌شود:

    warning: public documentation for `public` links to private item `private`
 --> priv.rs:1:6
  |
1 | /// [private]
  |      ^^^^^^^ this item is private
  |
  = note: `#[warn(rustdoc::private_intra_doc_links)]` on by default
  = note: this link resolves only because you passed `--document-private-items`, but will break without

    missing_docs

    این lint به‌طور پیش‌فرض مجاز است. این lint آیتم‌هایی را که مستندات ندارند تشخیص می‌دهد. برای مثال:

    #![warn(missing_docs)]

pub fn undocumented() {}
fn main() {}

    آنگاه تابع undocumented هشدار زیر را خواهد داشت:

    warning: missing documentation for a function
  --> your-crate/lib.rs:3:1
   |
 3 | pub fn undocumented() {}
   | ^^^^^^^^^^^^^^^^^^^^^

    توجه کنید که برخلاف سایر lintهای rustdoc، این lint مستقیماً از rustc نیز در دسترس است.

    missing_crate_level_docs

    این lint به‌طور پیش‌فرض مجاز است. این lint تشخیص می‌دهد که آیا در ریشهٔ crate مستنداتی وجود ندارد یا نه. برای مثال:

    #![warn(rustdoc::missing_crate_level_docs)]

    این کد هشدار زیر را تولید می‌کند:

    warning: no documentation found for this crate's top-level module
  |
  = help: The following guide may be of use:
          https://doc.rust-lang.org/nightly/rustdoc/how-to-write-documentation.html

    این lint در حال حاضر به‌طور پیش‌فرض «allow» است، اما قصد این است که در آینده به یک هشدار تبدیل شود. هدف از آن، آشنا کردن کاربران تازه‌وارد با چگونگی مستند کردن crate خودشان است، به این صورت که آن‌ها را به دستورالعمل‌هایی برای شروع کار راهنمایی می‌کند، بی‌آن‌که هشدارهای طاقت‌فرسایی مانند missing_docs تولید کند.

    missing_doc_code_examples

    این lint به‌طور پیش‌فرض مجاز است و فقط در nightly در دسترس است. این lint زمانی را تشخیص می‌دهد که یک بلوک مستندات مثال کد نداشته باشد. برای مثال:

    #![warn(rustdoc::missing_doc_code_examples)]

/// There is no code example!
pub fn no_code_example() {}
fn main() {}

    آنگاه تابع no_code_example هشدار زیر را خواهد داشت:

    warning: Missing code example in this documentation
  --> your-crate/lib.rs:3:1
   |
LL | /// There is no code example!
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

    برای رفع این lint، باید یک مثال کد به بلوک مستندات اضافه کنید:

    /// There is no code example!
///
/// ```
/// println!("calling no_code_example...");
/// no_code_example();
/// println!("we called no_code_example!");
/// ```
pub fn no_code_example() {}

    این lint برای آیتم‌های زیر صادر نمی‌شود:

    • بلوک‌های impl (هم صفت و هم ذاتی)
    • واریانت‌های شمارش
    • فیلدهای ساختار یا union
    • نام‌های مستعار نوع، از جمله نوع‌های وابسته
    • staticها و ثابت‌ها
    • ماژول‌ها (از جمله ماژول سطح بالای یک crate)
    • آیتم‌های خارجی حاصل از بازصادرکردن (re-export) (توابع، staticها، نوع‌ها و غیره)

    private_doc_tests

    این lint به‌طور پیش‌فرض مجاز است. این lint آزمون‌های مستنداتی را که روی یک آیتم خصوصی قرار دارند تشخیص می‌دهد. برای مثال:

    #![warn(rustdoc::private_doc_tests)]

mod foo {
    /// private doc test
    ///
    /// ```
    /// assert!(false);
    /// ```
    fn bar() {}
}
fn main() {}

    که این خروجی را می‌دهد:

    warning: Documentation test in private item
  --> your-crate/lib.rs:4:1
   |
 4 | /     /// private doc test
 5 | |     ///
 6 | |     /// ```
 7 | |     /// assert!(false);
 8 | |     /// ```
   | |___________^

    invalid_codeblock_attributes

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint attributeهای بلوک کد را در مثال‌های مستندات که احتمالاً مقدارشان اشتباه تایپ شده است تشخیص می‌دهد. برای مثال:

    #![warn(rustdoc::invalid_codeblock_attributes)]  // note: unnecessary - warns by default.

/// Example.
///
/// ```should-panic
/// assert_eq!(1, 2);
/// ```
pub fn foo() {}

    که این خروجی را می‌دهد:

    warning: unknown attribute `should-panic`. Did you mean `should_panic`?
 --> src/lib.rs:1:1
  |
1 | / /// Example.
2 | | ///
3 | | /// ```should-panic
4 | | /// assert_eq!(1, 2);
5 | | /// ```
  | |_______^
  |
  = note: `#[warn(rustdoc::invalid_codeblock_attributes)]` on by default
  = help: the code block will either not be tested if not marked as a rust one or won't fail if it doesn't panic when running

    در مثال بالا، شکل درست should_panic است. این lint به تشخیص اشتباهات تایپی در برخی attributeهای رایج کمک می‌کند.

    invalid_html_tags

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint تگ‌های HTML بسته‌نشده یا نامعتبر را تشخیص می‌دهد. برای مثال:

    #![warn(rustdoc::invalid_html_tags)]

/// <h1>
/// </script>
pub fn foo() {}

    که این خروجی را می‌دهد:

    warning: unopened HTML tag `script`
 --> foo.rs:1:1
  |
1 | / /// <h1>
2 | | /// </script>
  | |_____________^
  |
  note: the lint level is defined here
 --> foo.rs:1:9
  |
1 | #![warn(rustdoc::invalid_html_tags)]
  |         ^^^^^^^^^^^^^^^^^^^^^^^^^^

warning: unclosed HTML tag `h1`
 --> foo.rs:1:1
  |
1 | / /// <h1>
2 | | /// </script>
  | |_____________^

warning: 2 warnings emitted

    invalid_rust_codeblocks

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint بلوک‌های کد Rust را در مثال‌های مستندات که نامعتبرند (مثلاً خالی‌اند یا به‌عنوان Rust قابل تجزیه نیستند) تشخیص می‌دهد. برای مثال:

    /// Empty code blocks (with and without the `rust` marker):
///
/// ```rust
/// ```
///
/// Invalid syntax in code blocks:
///
/// ```rust
/// '<
/// ```
pub fn foo() {}

    که این خروجی را می‌دهد:

    warning: Rust code block is empty
 --> lint.rs:3:5
  |
3 |   /// ```rust
  |  _____^
4 | | /// ```
  | |_______^
  |
  = note: `#[warn(rustdoc::invalid_rust_codeblocks)]` on by default

warning: could not parse code block as Rust code
  --> lint.rs:8:5
   |
8  |   /// ```rust
   |  _____^
9  | | /// '<
10 | | /// ```
   | |_______^
   |
   = note: error from rustc: unterminated character literal

    bare_urls

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint نشانی‌های URL ای را که پیوند نیستند تشخیص می‌دهد. برای مثال:

    #![warn(rustdoc::bare_urls)] // note: unnecessary - warns by default.

/// http://example.org
/// [http://example.net]
pub fn foo() {}

    که این خروجی را می‌دهد:

    warning: this URL is not a hyperlink
 --> links.rs:1:5
  |
1 | /// http://example.org
  |     ^^^^^^^^^^^^^^^^^^ help: use an automatic link instead: `<http://example.org>`
  |
  = note: `#[warn(rustdoc::bare_urls)]` on by default

warning: this URL is not a hyperlink
 --> links.rs:3:6
  |
3 | /// [http://example.net]
  |      ^^^^^^^^^^^^^^^^^^ help: use an automatic link instead: `<http://example.net>`

warning: 2 warnings emitted

    unescaped_backticks

    این lint به‌طور پیش‌فرض مجاز است. این lint backtickهای (`) escape‌نشده را تشخیص می‌دهد. این معمولاً به معنای کد درون‌خطی شکسته است. برای مثال:

    #![warn(rustdoc::unescaped_backticks)]

/// `add(a, b) is the same as `add(b, a)`.
pub fn add(a: i32, b: i32) -> i32 { a + b }

    که این خروجی را می‌دهد:

    warning: unescaped backtick
 --> src/lib.rs:3:41
  |
3 | /// `add(a, b) is the same as `add(b, a)`.
  |                                         ^
  |
note: the lint level is defined here
 --> src/lib.rs:1:9
  |
1 | #![warn(rustdoc::unescaped_backticks)]
  |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
help: a previous inline code might be longer than expected
  |
3 | /// `add(a, b)` is the same as `add(b, a)`.
  |               +
help: if you meant to use a literal backtick, escape it
  |
3 | /// `add(a, b) is the same as `add(b, a)\`.
  |                                         +

warning: 1 warning emitted

    redundant_explicit_links

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint پیوندهای صریحی را که با پیوندهای خودکار محاسبه‌شده یکسان‌اند تشخیص می‌دهد. این معمولاً به معنای قابل‌حذف بودن پیوندهای صریح است. برای مثال:

    #![warn(rustdoc::redundant_explicit_links)] // note: unnecessary - warns by default.

/// add takes 2 [`usize`](usize) and performs addition
/// on them, then returns result.
pub fn add(left: usize, right: usize) -> usize {
    left + right
}

    که این خروجی را می‌دهد:

    error: redundant explicit rustdoc link
  --> src/lib.rs:3:27
   |
3  | /// add takes 2 [`usize`](usize) and performs addition
   |                           ^^^^^
   |
   = note: Explicit link does not affect the original link
note: the lint level is defined here
  --> src/lib.rs:1:9
   |
1  | #![deny(rustdoc::redundant_explicit_links)]
   |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   = help: Remove explicit link instead

    invalid_markdown_table

    این lint به‌طور پیش‌فرض هشدار می‌دهد. این lint علامت‌های pipe (|) بدون escape را در ردیف‌های جدول تشخیص می‌دهد که باعث نادیده گرفته شدن برخی سلول‌های ردیف می‌شوند. برای مثال:

    //! | col1 |
//! | ---- |
//! | `code_with(|arg| arg)` |

    که این خروجی را می‌دهد:

    error: table row has too many columns

   |
5  | //! | `code_with(|arg| arg)` |

note: the lint level is defined here
