کتاب rustdocThe rustdoc Book

    rustdoc چیست؟

    توزیع استاندارد Rust با ابزاری به نام rustdoc همراه است. وظیفهٔ آن تولید مستندات برای پروژه‌های Rust است. در سطح بنیادی، Rustdoc یا ریشهٔ یک crate یا یک فایل Markdown را به‌عنوان آرگومان می‌گیرد و HTML، CSS و JavaScript تولید می‌کند.

    استفادهٔ پایه

    بیایید امتحانش کنیم! یک پروژهٔ جدید با Cargo بسازید:

    $ cargo new docs --lib
$ cd docs

    در src/lib.rs، Cargo مقداری کد نمونه تولید کرده است. آن را حذف کنید و این را جایگزینش کنید:

    /// foo is a function
fn foo() {}

    بیایید rustdoc را روی کدمان اجرا کنیم. برای این کار، می‌توانیم آن را با مسیر ریشهٔ crate این‌گونه فراخوانی کنیم:

    $ rustdoc src/lib.rs

    این کار یک پوشهٔ جدید به نام doc می‌سازد که درونش یک وب‌سایت قرار دارد! در مورد ما، صفحهٔ اصلی در doc/lib/index.html قرار دارد. اگر آن را در یک مرورگر وب باز کنید، صفحه‌ای با یک نوار جستجو و عبارت «Crate lib» در بالای آن، بدون هیچ محتوایی خواهید دید.

    همچنین می‌توانید از cargo doc برای تولید مستندات کل پروژه استفاده کنید. استفاده از rustdoc همراه با Cargo را ببینید.

    پیکربندی rustdoc

    دو مشکل در اینجا وجود دارد: اول، چرا فکر می‌کند نام crate ما «lib» است؟ دوم، چرا هیچ محتوایی ندارد؟

    مشکل اول به این دلیل است که rustdoc می‌خواهد کمک‌کننده باشد؛ مانند rustc، فرض می‌کند نام crate ما همان نام فایل ریشهٔ crate است. برای رفع این مشکل، می‌توانیم یک پرچم خط فرمان بدهیم:

    $ rustdoc src/lib.rs --crate-name docs

    اکنون doc/docs/index.html تولید می‌شود و صفحه «Crate docs» را نشان می‌دهد.

    مشکل دوم به این دلیل است که تابع foo ما عمومی نیست؛ rustdoc به‌طور پیش‌فرض فقط برای توابع عمومی مستندات تولید می‌کند. اگر کدمان را تغییر دهیم…

    /// foo is a function
pub fn foo() {}

    … و سپس دوباره rustdoc را اجرا کنیم:

    $ rustdoc src/lib.rs --crate-name docs

    اکنون مقداری مستندات تولیدشده داریم. doc/docs/index.html را باز کنید و ببینید! باید پیوندی به صفحهٔ تابع foo نشان دهد که در doc/docs/fn.foo.html قرار دارد. در آن صفحه، عبارت «foo is a function» را خواهید دید که درون توضیح مستنداتی crate خود نوشته بودیم.

    استفاده از rustdoc همراه با Cargo

    Cargo هم یکپارچگی با rustdoc دارد تا تولید مستندات را آسان‌تر کند. به‌جای دستور rustdoc، می‌توانستیم این کار را بکنیم:

    $ cargo doc

    اگر می‌خواهید cargo مستندات تولیدشده را به‌طور خودکار باز کند، می‌توانید از این استفاده کنید:

    $ cargo doc --open

    در پشت صحنه، cargo doc به این شکل rustdoc را فراخوانی می‌کند:

    $ rustdoc --crate-name docs src/lib.rs -o <path>/docs/target/doc -L
dependency=<path>/docs/target/debug/deps

    می‌توانید این را با cargo doc --verbose ببینید.

    این دستور --crate-name درست را برای ما تولید می‌کند و همچنین به src/lib.rs اشاره می‌کند. اما آن آرگومان‌های دیگر چه هستند؟

    • -o مسیر خروجی (output) مستندات ما را کنترل می‌کند. به‌جای یک پوشهٔ سطح بالای doc، توجه کنید که Cargo مستندات تولیدشده را زیر target قرار می‌دهد. این جای متعارف برای فایل‌های تولیدشده در پروژه‌های Cargo است.
    • پرچم -L به rustdoc کمک می‌کند وابستگی‌هایی را که کد شما به آن‌ها تکیه دارد پیدا کند. اگر پروژهٔ ما از وابستگی‌هایی استفاده می‌کرد، برای آن‌ها هم مستندات می‌گرفتیم!

    مستندات بیرونی و درونی

    نحو /// برای مستندسازی آیتمی به کار می‌رود که پس از آن می‌آید. به همین دلیل به آن مستندات بیرونی گفته می‌شود. نحو دیگری هم وجود دارد: //!، که برای مستندسازی آیتمی به کار می‌رود که درون آن قرار دارد. به آن مستندات درونی گفته می‌شود. اغلب هنگام مستندسازی کل crate استفاده می‌شود، چون هیچ چیزی پیش از آن نمی‌آید: آن ریشهٔ crate است. بنابراین برای مستندسازی کل یک crate، باید از نحو //! استفاده کنید. برای مثال:

    //! This is my first rust crate

    وقتی در ریشهٔ crate استفاده شود، آیتمی را که درون آن قرار دارد مستند می‌کند، که خود crate است.

    برای اطلاعات بیشتر دربارهٔ نحو //!، کتاب را ببینید.

    استفاده از فایل‌های Markdown مستقل

    rustdoc می‌تواند از فایل‌های Markdown مستقل هم HTML تولید کند. بیایید امتحانش کنیم: یک فایل README.md با این محتوا بسازید:

    # Docs

This is a project to test out `rustdoc`.

[Here is a link!](https://www.rust-lang.org)

## Example

```rust
fn foo() -> i32 {
    1 + 1
}
```

    و rustdoc را روی آن اجرا کنید:

    $ rustdoc README.md

    یک فایل HTML در docs/doc/README.html خواهید یافت که از محتوای Markdown آن تولید شده است.

    متأسفانه Cargo در حال حاضر فایل‌های Markdown مستقل را درک نمی‌کند.
