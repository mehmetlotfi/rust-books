کتاب ClippyThe Clippy Book

    استفاده

    این فصل توضیح می‌دهد چگونه از Clippy استفاده کنید تا بیشترین بهره را از آن ببرید. Clippy را می‌توان به‌عنوان زیردستور cargo یا، مانند rustc، مستقیماً با فایل اجرایی clippy-driver به کار برد.

    Note

    نکته: این فصل فرض می‌کند که Clippy را از قبل نصب کرده‌اید. اگر مطمئن نیستید، فصل نصب را ببینید.

    زیردستور Cargo

    ساده‌ترین و رایج‌ترین راه اجرای Clippy از طریق cargo است. برای این کار کافی است این دستور را اجرا کنید:

    cargo clippy

    پیکربندی lintها

    دستور بالا مجموعهٔ پیش‌فرض lintها را اجرا می‌کند که در گروه lint با نام clippy::all قرار دارند. ممکن است بخواهید از lintهای بیشتری استفاده کنید، یا ممکن است با همهٔ lintهای Clippy موافق نباشید؛ برای این منظور راه‌هایی برای پیکربندی سطح lintها وجود دارد.

    Note

    نکته: Clippy قرار است همراه با استفادهٔ فراوان از #[allow(..)] در کد شما به کار رود. بنابراین اگر با یک lint موافق نیستید، از غیرفعال کردن آن‌ها برای بخشی از کد یا کل پروژه ناراحت نشوید.

    خط فرمان

    می‌توانید سطح lintها را در خط فرمان با افزودن -A/W/D clippy::lint_name به این شکل پیکربندی کنید:

    cargo clippy -- -Aclippy::style -Wclippy::box_default -Dclippy::perf

    ارتقای هشدارها به خطا

    برای CI می‌توان همهٔ هشدارها را به خطا ارتقا داد؛ در نتیجه ساخت شکست می‌خورد و Clippy با کدی غیر از 0 خارج می‌شود.

    از Cargo نسخهٔ 1.97 به بعد، روش توصیه‌شده برای این کار استفاده از گزینهٔ پیکربندی build.warnings است.

    این گزینه را می‌توان در خط فرمان با استفاده از متغیر محیطی فعال کرد:

    CARGO_BUILD_WARNINGS=deny cargo clippy

    .. یا به‌طور دائمی در .cargo/config.toml:

    # .cargo/config.toml
[build]
warnings = "deny"

    Note

    نکته: استفاده از CARGO_BUILD_WARNINGS=deny (یا -D warnings) باعث می‌شود اگر هر هشداری در کد شما پیدا شود، ساخت شکست بخورد. این شامل هشدارهایی که rustc پیدا می‌کند (مثلاً dead_code و غیره) نیز می‌شود.

    اگر از نسخهٔ قدیمی‌تر Cargo استفاده می‌کنید، می‌توانید به‌جای آن از دستور زیر استفاده کنید:

    cargo clippy -- -Dwarnings

    با این حال توجه داشته باشید که این کار کش‌های ساخت را باطل می‌کند و بنابراین توصیه نمی‌شود.

    برای اطلاعات بیشتر دربارهٔ پیکربندی سطح lintها، مستندات rustc را ببینید.

    lintهای بیشتر

    Clippy گروه‌های lintی دارد که به‌طور پیش‌فرض allow هستند. این یعنی باید lintهای این گروه‌ها را خودتان به‌صورت دستی فعال کنید.

    برای فهرست کامل همهٔ lintها همراه با توضیح و مثال، به فهرست lintهای Clippy مراجعه کنید. دو گروه مهم‌تر که به‌طور پیش‌فرض allow هستند در ادامه توضیح داده شده‌اند:

    clippy::pedantic

    گروه اول، گروه pedantic است. این گروه شامل lintهای بسیار جانب‌دارانه‌ای است که برای جلوگیری از منفی‌های کاذب ممکن است مثبت‌های کاذب عمدی داشته باشند. بنابراین هرچند این گروه برای استفاده در محیط تولید آماده است، باید انتظار داشته باشید که چندین #[allow(..)] در کد خود بگذارید. اگر مثبت کاذبی پیدا کردید، همچنان خوشحال می‌شویم آن را برای بهبودهای آینده به ما گزارش دهید.

    برای اطلاع: Clippy از کل این گروه برای lint کردن خودش استفاده می‌کند.

    clippy::restriction

    گروه دوم، گروه restriction است. این گروه شامل lintهایی است که زبان را به نوعی «محدود» می‌کنند. برای مثال lint با نام clippy::unwrap از این گروه اجازه نمی‌دهد در کد خود از .unwrap() استفاده کنید. شاید بخواهید lintهای این گروه را مرور کنید و آن‌هایی را که با نیاز شما سازگارند فعال کنید.

    Note

    نکته: نباید کل این گروه lint را فعال کنید، بلکه باید lintها را جداگانه از این گروه انتخاب کنید. برخی lintهای این گروه حتی با دیگر lintهای Clippy در تضادند!

    lintهای بیش از حد

    جانب‌دارانه‌ترین گروهِ هشداردهنده به‌طور پیش‌فرض در Clippy گروه clippy::style است. برخی افراد ترجیح می‌دهند این گروه را به‌طور کامل غیرفعال کنند و سپس چند lint دلخواه را از آن جداگانه فعال کنند. البته همین کار با هر یک از گروه‌های lint دیگر Clippy نیز ممکن است.

    Note

    نکته: ما تلاش می‌کنیم گروه‌های هشداردهنده به‌طور پیش‌فرض را از مثبت کاذب (FP) خالی نگه داریم. اگر دیدید که یک lint به اشتباه فعال می‌شود، لطفاً آن را در یک issue گزارش کنید (در صورتی که از قبل issue ای برای آن FP وجود ندارد)

    کد منبع

    می‌توانید سطح lintها را در کد منبع به همان روشی پیکربندی کنید که lintهای rustc را پیکربندی می‌کنید:

    #![allow(clippy::style)]

#[warn(clippy::box_default)]
fn main() {
    let _ = Box::<String>::new(Default::default());
    // ^ warning: `Box::new(_)` of default value
}

    اعمال خودکار پیشنهادهای Clippy

    Clippy می‌تواند برخی از پیشنهادهای lint را، درست مانند کامپایلر، به‌طور خودکار اعمال کند. توجه داشته باشید که --fix به‌طور ضمنی --all-targets را هم در بر می‌گیرد، بنابراین تا جایی که بتواند کد بیشتری را اصلاح می‌کند.

    cargo clippy --fix

    Workspaceها

    همهٔ گزینه‌های معمول workspace باید با Clippy کار کنند. برای مثال دستور زیر Clippy را روی crate با نام example در workspace شما اجرا می‌کند:

    cargo clippy -p example

    مانند cargo check، این دستور شامل وابستگی‌هایی هم می‌شود که عضو workspace هستند، مانند وابستگی‌های path. اگر می‌خواهید Clippy را فقط روی crate مشخص‌شده اجرا کنید، از گزینهٔ --no-deps به این شکل استفاده کنید:

    cargo clippy -p example -- --no-deps

    استفاده از Clippy بدون cargo: ‏clippy-driver

    Clippy را می‌توان در پروژه‌هایی که از cargo استفاده نمی‌کنند هم به کار برد. برای این کار، clippy-driver را با همان آرگومان‌هایی اجرا کنید که برای rustc به کار می‌برید. برای مثال:

    clippy-driver --edition 2018 -Cpanic=abort foo.rs

    Note

    نکته: clippy-driver برای اجرای Clippy طراحی شده است و نباید به‌عنوان جایگزینی عمومی برای rustc استفاده شود. برای مثال، clippy-driver ممکن است مصنوعاتی (artifact) تولید کند که آن‌طور که انتظار می‌رود بهینه نیستند.
