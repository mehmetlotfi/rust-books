    تعریف lintهای جدید

    نخستین گام در مسیر یک lint جدید، تعریف و ثبت lint در کدبیس Clippy است. می‌توانیم برای انجام این گام از ابزارهای توسعهٔ Clippy استفاده کنیم، چون راه‌اندازی lint مستلزم مقداری کد تکراری (boilerplate) است.

    نوع‌های lint

    نوع lint، دستهٔ آیتم‌ها و عبارت‌هایی است که lint شما روی آن‌ها تمرکز دارد.

    در زمان نگارش این به‌روزرسانی مستندات، علاوه بر lintهای مستقل فراوانی که در clippy_lints/src/ قرار دارند، ۱۱ نوع lint وجود دارد:

    • cargo
    • casts
    • functions
    • loops
    • matches
    • methods
    • misc_early
    • operators
    • transmute
    • types
    • unit_types

    این نوع‌ها lintهایی را که رفتارهای مشترکی دارند با هم گروه‌بندی می‌کنند. برای مثال، functions lintهایی را گروه‌بندی می‌کند که با برخی جنبه‌های توابع در Rust سروکار دارند، مانند تعریف‌ها، امضاها و attributeها.

    برای اطلاعات بیشتر، می‌توانید فایل‌های lint در هر دسته را با همهٔ lintهای Clippy مقایسه کنید یا از یکی از نگهدارندگان بپرسید.

    نام lint

    یک نام خوب برای lint مهم است؛ حتماً راهنمای نام‌گذاری lint را بررسی کنید. نگران نباشید، اگر نام lint مناسب نباشد، یکی از اعضای تیم Clippy در فرایند PR به شما اطلاع می‌دهد.

    ما lint نمونهٔ خود را که توابعی با نام «foo» را شناسایی می‌کند foo_functions می‌نامیم. برای اینکه ببینید چرا این نام منطقی است، راهنمای نام‌گذاری lint را بررسی کنید.

    افزودن و ثبت lint

    اکنون که نام انتخاب شد، باید foo_functions را به‌عنوان یک lint در کدبیس ثبت کنیم. برای ثبت یک lint دو راه وجود دارد.

    مستقل

    اگر معتقدید این lint جدید یک lint مستقل است (و به هیچ نوع خاصی مانند functions یا loops تعلق ندارد)، می‌توانید دستور زیر را در پروژهٔ Clippy خود اجرا کنید:

    $ cargo dev new_lint --name=lint_name --pass=late --category=pedantic

    در اینجا دو نکته وجود دارد:

    1. --pass: در این دستور --pass=late را تنظیم می‌کنیم تا یک گذر lint از نوع late انجام شود. جایگزین آن گذر lint از نوع early است. دربارهٔ این تفاوت در فصل گذرهای lint صحبت خواهیم کرد.
    2. --category: اگر مشخص نشود، category این lint جدید به‌طور پیش‌فرض nursery خواهد بود.

    دستور cargo dev new_lint یک فایل جدید به نام clippy_lints/src/foo_functions.rs ایجاد می‌کند و همچنین lint را ثبت می‌کند.

    در مجموع، باید ببینید که فایل‌های زیر تغییر کرده یا ایجاد شده‌اند:

    نوع مشخص

    توجه: نوع‌های lint در بخش “نوع‌های lint” فهرست شده‌اند

    اگر معتقدید این lint جدید به نوع خاصی از lintها تعلق دارد، می‌توانید cargo dev new_lint را با گزینهٔ --type اجرا کنید.

    از آنجا که lint ما یعنی foo_functions به فراخوانی توابع مربوط است، می‌توان استدلال کرد که باید آن را در گروهی از lintها قرار دهیم که برخی رفتارهای توابع را شناسایی می‌کنند؛ پس می‌توانیم آن را در گروه functions بگذاریم.

    بیایید دستور زیر را در پروژهٔ Clippy خود اجرا کنیم:

    $ cargo dev new_lint --name=foo_functions --type=functions --category=pedantic

    این دستور، از جمله، یک فایل جدید ایجاد می‌کند: clippy_lints/src/{type}/foo_functions.rs. در مورد ما، مسیر آن clippy_lints/src/functions/foo_functions.rs خواهد بود.

    توجه کنید که این دستور به جای --pass یک پرچم --type دارد. برخلاف تعریف مستقل، این lint به معنای سنتی ثبت نمی‌شود. در عوض، شما lint خود را از درون گذر lint آن نوع که در clippy_lints/src/{type}/mod.rs قرار دارد فراخوانی می‌کنید.

    یک نوع فقط نام یک پوشه در clippy_lints/src است، مانند functions در دستور نمونه. Clippy برخی lintها را که رفتارهای مشترکی دارند با هم گروه‌بندی می‌کند، پس اگر lint شما در یکی از آن‌ها جا می‌گیرد، بهتر است آن را به همان نوع اضافه کنید.

    در مجموع، باید ببینید که فایل‌های زیر تغییر کرده یا ایجاد شده‌اند:

    ماکروی declare_clippy_lint

    پس از cargo dev new_lint، باید ماکرویی با نام declare_clippy_lint ببینید. اگر یک lint مستقل تعریف کرده باشید، در همان فایل قرار دارد و اگر یک lint مختص یک نوع تعریف کرده باشید، در mod.rs خواهد بود.

    این ماکرو چیزی شبیه به این است:

    declare_clippy_lint! {
    /// ### What it does
    ///
    /// // Describe here what does the lint do.
    ///
    /// Triggers when detects...
    ///
    /// ### Why is this bad?
    ///
    /// // Describe why this pattern would be bad
    ///
    /// It can lead to...
    ///
    /// ### Example
    /// ```rust
    /// // example code where Clippy issues a warning
    /// ```
    /// Use instead:
    /// ```rust
    /// // example code which does not raise Clippy warning
    /// ```
    #[clippy::version = "1.70.0"] // <- In which version was this implemented, keep it up to date!
    pub LINT_NAME, // <- The lint name IN_ALL_CAPS
    pedantic, // <- The lint group
    "default lint description" // <- A lint description, e.g. "A function has an unit return type."
}

    ثبت lint

    اگر دستور cargo dev new_lint را برای یک lint جدید اجرا کنیم، lint به‌طور خودکار ثبت می‌شود و کار دیگری لازم نیست.

    با این حال، گاهی ممکن است بخواهیم یک lint جدید را دستی اعلام کنیم. در این صورت، پس از آن از دستور cargo dev update_lints استفاده می‌کنیم.

    وقتی یک lint به‌صورت دستی اعلام می‌شود، ممکن است لازم باشد گذر lint را نیز دستی ثبت کنیم؛ برای این کار یک ورودی به فراخوانی ماکروی late_lint_methods! در clippy_lints/src/lib.rs و در محل نشانگر // add late passes here اضافه می‌کنیم:

    FooFunctions: foo_functions::FooFunctions = foo_functions::FooFunctions,

    همان‌طور که شاید حدس زده باشید، جایی که چیزی «late» هست، چیزی «early» هم هست: در Clippy ماکروی early_lint_methods! نیز وجود دارد. اطلاعات بیشتر دربارهٔ گذرهای early در برابر late را در فصل گذرهای lint ببینید.

    بدون یک ورودی در early_lint_methods! یا late_lint_methods!، گذر lint موردنظر اجرا نخواهد شد.
