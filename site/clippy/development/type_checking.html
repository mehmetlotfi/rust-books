    بررسی نوع

    وقتی روی یک lint جدید کار می‌کنیم یا یک lint موجود را بهبود می‌دهیم، ممکن است به دلایل گوناگون بخواهیم نوع Ty یک عبارت Expr را به دست آوریم. این کار با استفاده از LateContext که برای LateLintPass در دسترس است انجام می‌شود.

    LateContext و TypeckResults

    زمینهٔ lint یعنی LateContext و TypeckResults (که توسط LateContext::typeck_results برگردانده می‌شود) دو ساختار دادهٔ بسیار مفید در LateLintPass هستند. آن‌ها به ما اجازه می‌دهند به تعریف نوع‌ها و دیگر مراحل کامپایل مانند HIR برویم.

    Note

    توجه: مقدار بازگشتی LateContext.typeck_results از نوع TypeckResults است و در مرحلهٔ بررسی نوع ساخته می‌شود؛ شامل اطلاعات مفیدی مانند نوع عبارت‌ها، روش‌های تحلیل متدها و غیره است.

    TypeckResults متدهای مفیدی مانند expr_ty دارد که به ما امکان دسترسی به ساختار زیربنایی Ty یک عبارت مشخص را می‌دهد.

    pub fn expr_ty(&self, expr: &Expr<'_>) -> Ty<'tcx>

    به‌عنوان نکته‌ای جانبی، افزون بر expr_ty، TypeckResults متدی به نام pat_ty() هم دارد که برای به دست آوردن نوع از یک الگو مفید است.

    Ty

    ساختار Ty اطلاعات نوع یک عبارت را در خود دارد. بیایید برای بررسی این ساختار نگاهی به ساختار Ty در rustc_middle بیندازیم:

    pub struct Ty<'tcx>(Interned<'tcx, WithStableHash<TyS<'tcx>>>);

    در نگاه اول، این ساختار بسیار رمزآلود به نظر می‌رسد. اما با دقت بیشتر می‌بینیم که این ساختار متدهای مفید فراوانی برای بررسی نوع دارد.

    برای مثال، is_char بررسی می‌کند که آیا Ty داده‌شده با نوع ابتدایی نویسه مطابقت دارد.

    استفاده از is_*

    در برخی سناریوها، تنها کاری که لازم است بکنیم بررسی این است که Ty یک عبارت نوع مشخصی است، مثلاً نوع char، و می‌توانیم این‌گونه بنویسیم:

    impl LateLintPass<'_> for MyStructLint {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {
        // Get type of `expr`
        let ty = cx.typeck_results().expr_ty(expr);

        // Check if the `Ty` of this expression is of character type
        if ty.is_char() {
            println!("Our expression is a char!");
        }
    }
}

    افزون بر این، اگر کد منبع تابع is_char را بررسی کنیم، به چیز بسیار جالبی برمی‌خوریم:

    #[inline]
pub fn is_char(self) -> bool {
    matches!(self.kind(), Char)
}

    در واقع، همین الان متد kind() مربوط به Ty را کشف کردیم که TyKind مربوط به یک Ty را در اختیار ما می‌گذارد.

    TyKind

    TyKind گونه‌های نوع‌ها را در سامانهٔ نوع Rust تعریف می‌کند. اگر نگاهی به مستندات TyKind بیندازیم، می‌بینیم که یک شمارش با بیش از ۲۵ حالت است، شامل آیتم‌هایی مانند Bool، Int، Ref و غیره.

    استفاده از kind

    TyKind مربوط به یک Ty با فراخوانی متد Ty.kind() برگردانده می‌شود. ما اغلب از این متد برای الگوسازی (pattern matching) در Clippy استفاده می‌کنیم.

    برای مثال، اگر بخواهیم یک struct را بررسی کنیم، می‌توانیم ببینیم که آیا ty.kind با یک Adt (نوع داده‌ای جبری) مطابقت دارد و آیا AdtDef آن یک ساختار است:

    impl LateLintPass<'_> for MyStructLint {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {
        // Get type of `expr`
        let ty = cx.typeck_results().expr_ty(expr);
        // Match its kind to enter the type
        match ty.kind() {
            ty::Adt(adt_def, _) if adt_def.is_struct() => println!("Our `expr` is a struct!"),
            _ => ()
        }
    }
}

    hir::Ty و ty::Ty

    تا اینجا همیشه دربارهٔ ty::Ty صحبت کرده‌ایم و به hir::Ty نپرداخته‌ایم، اما درک مورد دوم نیز مهم است.

    hir::Ty نشان می‌دهد کاربر چه نوشته است، در حالی که ty::Ty نشان می‌دهد کامپایلر نوع را چگونه می‌بیند و اطلاعات بیشتری دارد. مثال:

    fn foo(x: u32) -> u32 { x }

    در اینجا HIR نوع‌ها را بدون «فکر کردن» دربارهٔ آن‌ها می‌بیند؛ می‌داند که تابع یک u32 می‌گیرد و یک u32 برمی‌گرداند. تا جایی که به hir::Ty مربوط است، ممکن است این دو نوع متفاوت باشند. اما در سطح ty::Ty، کامپایلر می‌فهمد که آن‌ها یک نوع‌اند، همراه با جزئیات طول عمرها و غیره…

    برای رسیدن از hir::Ty به ty::Ty، می‌توانید بیرون از بدنه‌ها از تابع lower_ty یا درون بدنه‌ها از متد TypeckResults::node_type() استفاده کنید.

    هشدار: درون بدنه‌ها از lower_ty استفاده نکنید، زیرا ممکن است باعث ICE شود.

    ساخت نوع‌ها به‌صورت برنامه‌نویسی‌شده

    یک مورد کاربرد رایج برای ساخت برنامه‌نویسی‌شدهٔ نوع‌ها، وقتی است که می‌خواهیم بررسی کنیم یک نوع صفتی را پیاده‌سازی می‌کند یا نه (نگاه کنید به بررسی صفت).

    در اینجا مثالی از نحوهٔ ساخت یک Ty برای برشی از u8 یعنی [u8] آمده است

    use rustc_middle::ty::Ty;
// assume we have access to a LateContext
let ty = Ty::new_slice(cx.tcx, Ty::new_u8());

    به‌طور کلی، ما به متدهای Ty::new_* تکیه می‌کنیم. این متدها بلوک‌های سازندهٔ پایه‌ای را تعریف می‌کنند که سامانهٔ نوع و سامانهٔ صفت برای تعریف و فهم کد نوشته‌شده به کار می‌برند.
