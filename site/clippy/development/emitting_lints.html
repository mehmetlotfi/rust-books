    صدور یک lint

    پس از آنکه یک lint را تعریف کردیم، آزمون‌های UI را نوشتیم و گذر lint مناسب lint را انتخاب کردیم، می‌توانیم پیاده‌سازی منطق lint را آغاز کنیم تا بتوانیم آن را صادر کنیم و به‌تدریج به lintی برسیم که مطابق انتظار رفتار می‌کند.

    توجه کنید که در این فصل وارد پیاده‌سازی عملی منطق یک lint نمی‌شویم. جزئیات را در فصل‌های بعدی و همچنین در دو نمونه از lintهای واقعی Clippy بررسی خواهیم کرد.

    برای صدور یک lint، باید یک گذر (به گذرهای lint نگاه کنید) برای lintی که اعلام کرده‌ایم پیاده‌سازی کنیم. در این مثال یک lint از نوع «late» را پیاده‌سازی می‌کنیم، پس مستندات LateLintPass را ببینید که تعداد زیادی متد برای پیاده‌سازی در lint ما فراهم می‌کند.

    pub trait LateLintPass<'tcx>: LintPass {
    // Trait methods
}

    متدی که با اختلاف بیشترین استفاده را در lintهای Clippy دارد متد check_expr است؛ دلیلش این است که Rust یک زبان مبتنی بر عبارت است و اغلب lintی که می‌خواهیم رویش کار کنیم باید عبارت‌ها را بررسی کند.

    Note

    اگر به‌طور کامل نمی‌دانید عبارت‌ها (expressions) در Rust چیستند، نگاهی به مستندات رسمی دربارهٔ عبارت‌ها بیندازید

    از متدهای رایج دیگر می‌توان متد check_fn و متد check_item را نام برد.

    صدور یک lint

    درون متد صفتی که پیاده‌سازی می‌کنیم، می‌توانیم منطق lint را بنویسیم و lint را همراه با پیشنهادها صادر کنیم.

    بخش diagnostics در Clippy تعداد قابل‌توجهی تابع تشخیصی برای صدور lintها فراهم می‌کند. مستندات را ببینید و تابعی را انتخاب کنید که بهترین تطابق را با نیازهای lint شما دارد. برخی از تابع‌های رایجی که در مخزن Clippy با آن‌ها روبه‌رو می‌شوید عبارت‌اند از:

    • span_lint: یک lint را بدون ارائهٔ هیچ اطلاعات دیگری صادر می‌کند
    • span_lint_and_note: یک lint را صادر می‌کند و یک یادداشت (note) اضافه می‌کند
    • span_lint_and_help: یک lint را صادر می‌کند و یک پیام راهنما ارائه می‌دهد
    • span_lint_and_sugg: یک lint را صادر می‌کند و پیشنهادی برای اصلاح کد ارائه می‌دهد
    • span_lint_and_then: مانند span_lint است، اما امکان سفارشی‌سازی گستردهٔ خروجی را فراهم می‌کند.
    impl<'tcx> LateLintPass<'tcx> for LintName {
    fn check_expr(&mut self, cx: &LateContext<'tcx>, expr: &'tcx Expr<'_>)  {
        // Imagine that `some_lint_expr_logic` checks for requirements for emitting the lint
        if some_lint_expr_logic(expr) {
            span_lint_and_help(
                cx, // < The context
                LINT_NAME, // < The name of the lint in ALL CAPS
                expr.span, // < The span to lint
                "message on why the lint is emitted",
                None, // < An optional help span (to highlight something in the lint)
                "message that provides a helpful suggestion",
            );
        }
    }
}

    Note

    توجه: پیام باید واقعیت‌محور باشد و از حروف بزرگ و علائم نگارشی پرهیز کند. اگر چند جمله لازم است، پیام‌ها احتمالاً باید به یک پیام خطا و یک پیام راهنما / یادداشت / پیشنهاد تقسیم شوند.

    پیشنهادها: اصلاح‌های خودکار

    برخی lintها می‌دانند برای اصلاح کد چه چیزی را باید تغییر داد. برای مثال، lint با نام range_plus_one دربارهٔ بازه‌هایی هشدار می‌دهد که کاربر به جای استفاده از بازهٔ شامل (x..=y)، عبارت x..y + 1 را نوشته است. اصلاح این کد تغییر عبارت x..y + 1 به x..=y است. اینجاست که پیشنهادها وارد می‌شوند.

    پیشنهاد، تغییری است که lint برای رفع مشکلی که روی آن lint می‌کند ارائه می‌دهد. خروجی چیزی شبیه این است (از مثال پیشین):

    error: an inclusive range would be more readable
  --> tests/ui/range_plus_minus_one.rs:37:14
   |
LL |     for _ in 1..1 + 1 {}
   |              ^^^^^^^^ help: use: `1..=1`

    قابلیت اعمال

    همهٔ پیشنهادها همیشه درست نیستند؛ برخی به نظارت انسان نیاز دارند و به همین دلیل Applicability را داریم.

    Applicability میزان اطمینان به درستی پیشنهاد را نشان می‌دهد؛ برخی همیشه درست‌اند (Applicability::MachineApplicable)، اما برای پیشنهادی که ممکن است نادرست باشد از Applicability::MaybeIncorrect و موارد دیگر استفاده می‌کنیم.

    مثال

    همان lint یعنی LINT_NAME که یک پیشنهاد صادر می‌کند چیزی شبیه این خواهد بود:

    impl<'tcx> LateLintPass<'tcx> for LintName {
    fn check_expr(&mut self, cx: &LateContext<'tcx>, expr: &'tcx Expr<'_>)  {
        // Imagine that `some_lint_expr_logic` checks for requirements for emitting the lint
        if some_lint_expr_logic(expr) {
            span_lint_and_then( // < Note this change
                cx,
                LINT_NAME,
                expr.span,
                "message on why the lint is emitted",
                |diag| {
                    // v Build and emit the suggestion
                    let mut app = Applicability::MachineApplicable;
                    let expr_snippet = snippet_with_applicability(cx, expr.span, "_", &mut app);
                    let sugg = format!("foo + {expr_snippet} * bar");
                    diag.span_suggestion(expr.span, "use", sugg, app);
                }
            );
        }
    }
}

    پیشنهادها معمولاً از ماکروی format! برای درج مقادیر قدیمی در مقادیر جدید استفاده می‌کنند. برای اطلاعات دربارهٔ دریافت تکه‌کدها، Snippets را ببینید.

    چگونه بین یادداشت‌ها، پیام‌های راهنما و پیشنهادها انتخاب کنیم

    یادداشت‌ها جدا از پیام اصلی lint نمایش داده می‌شوند و اطلاعات مفیدی را که کاربر برای درک دلیل فعال شدن lint نیاز دارد ارائه می‌دهند. وقتی به یک span متصل شوند بیشترین کمک را می‌کنند.

    مثال‌ها:

    یادداشت‌ها

    پیام‌های راهنما

    پیام‌های راهنما به‌طور مشخص برای کمک به کاربر هستند. در موقعیتی به کار می‌روند که نمی‌توانید پیشنهاد مشخصی ارائه دهید که ماشین بتواند آن را اعمال کند. این پیام‌ها نیز می‌توانند به یک span متصل شوند.

    مثال:

    error: constant division of 0.0 with 0.0 will always result in NaN
  --> tests/ui/zero_div_zero.rs:6:25
   |
6  |     let other_f64_nan = 0.0f64 / 0.0;
   |                         ^^^^^^^^^^^^
   |
   = help: consider using `f64::NAN` if you would like a constant representing NaN

    پیشنهادها

    پیشنهادها از همه مفیدترند؛ آن‌ها تغییراتی در کد منبع برای رفع خطا هستند. جادوی پیشنهادها این است که ابزارهایی مانند rustfix می‌توانند آن‌ها را شناسایی کنند و کد شما را به‌طور خودکار اصلاح کنند.

    مثال:

    error: This `.fold` can be more succinctly expressed as `.any`
--> tests/ui/methods.rs:390:13
    |
390 |     let _ = (0..3).fold(false, |acc, x| acc || x > 2);
    |                   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ help: try: `.any(|x| x > 2)`
    |

    Snippets

    Snippetها تکه‌هایی از کد منبع (به‌صورت رشته) هستند که معمولاً با استفاده از تابع‌های مختلف snippet_* از clippy_utils::source استخراج می‌شوند.

    اگر از snippetها نه برای ساخت یک پیشنهاد استفاده می‌کنید، معمولاً استفاده از snippet کافی است؛ این تابع span آیتم و همچنین یک رشتهٔ جایگزین (fallback) را می‌پذیرد (به Fallback string نگاه کنید).

    برای مثال، اگر می‌خواهید بدانید یک آیتم چه شکلی است (و span آن آیتم را می‌دانید)، می‌توانید از snippet(cx, span, "_") استفاده کنید.

    اگر snippet را برای یک پیشنهاد به کار می‌برید، توصیه می‌شود به جای آن از snippet_with_applicability استفاده کنید. این کار باعث می‌شود Clippy در صورتی که نتوانست snippet را «به‌طور تمیز» استخراج کند، applicability پیشنهاد را کاهش دهد؛ برای اطلاعات بیشتر مستندات این تابع را ببینید.

    اغلب لازم است برای ساخت یک پیشنهاد چند snippet ایجاد شود که در این صورت الگوی زیر را خواهید داشت:

    // inside `span_lint_and_then`

// 1. Create initial applicability.
let mut app = Applicability::MachineApplicable;

// 2. Use it to create all the snippets
let foo_snippet = snippet_with_applicability(cx, foo.span, "_", &mut app);
let bar_snippet = snippet_with_applicability(cx, bar.span, "_", &mut app);
let sugg = format!("{foo_snippet} + {bar_snippet}"); // or whatever

// 3. Use it to emit the final suggestion
diag.span_suggestion(span, msg, sugg, app);

    رشتهٔ جایگزین (fallback)

    این رشته‌ای است که وقتی کد منبعی که span به آن اشاره می‌کند در دسترس نیست، برای snippet استفاده می‌شود. این اتفاق بیشتر فقط وقتی رخ می‌دهد که proc-macroها spanها را نادرست مدیریت کنند – بخش مربوط به proc-macroها را ببینید.

    در بیشتر موارد، snippetهای یک پیشنهاد از (span) یک عبارت واحد می‌آیند و بنابراین "_" یک رشتهٔ جایگزین مناسب است. اگر به جای آن متوجه شدید که پیشنهاد درج چند دستور یا یک بلوک را می‌دهید – یعنی در اصل هر چیزی «بزرگ» – استفاده از ".." را در نظر بگیرید.

    گام پایانی: اجرای آزمون‌های UI برای صدور lint

    اکنون، اگر آزمون UI خود را اجرا کنیم، باید ببینیم Clippy خروجی‌ای تولید می‌کند که شامل پیام lintی است که طراحی کرده‌ایم.

    گام بعدی پیاده‌سازی درست منطق است که جزئیاتی است که در فصل‌های بعدی به آن می‌پردازیم.
