    ابزارهای رایج برای نوشتن lintها

    ممکن است برای انجام عملیات رایج به نکته‌های زیر نیاز داشته باشید.

    • ابزارهای رایج برای نوشتن lintها
      • دریافت نوع یک عبارت
      • بررسی اینکه آیا یک expr متد مشخصی را فراخوانی می‌کند
      • بررسی یک نوع مشخص
      • بررسی اینکه آیا یک نوع صفت مشخصی را پیاده‌سازی می‌کند
      • بررسی اینکه آیا یک نوع متد مشخصی را تعریف می‌کند
      • کار با ماکروها

    پیوندهای مفید از راهنمای توسعهٔ Rustc:

    • مراحل کامپایل
    • آیتم‌های تشخیصی
    • بررسی نوع
    • ماژول Ty

    دریافت نوع یک عبارت

    گاهی ممکن است بخواهید نوع Ty یک عبارت Expr را به دست آورید، مثلاً برای پاسخ به پرسش‌های زیر:

    • این عبارت با کدام نوع متناظر است (با استفاده از TyKind آن)؟
    • آیا یک نوع دارای اندازه (sized) است؟
    • آیا یک نوع اولیه (primitive) است؟
    • آیا صفتی را پیاده‌سازی می‌کند؟

    این عملیات با استفاده از متد expr_ty() از ساختار TypeckResults انجام می‌شود که به ساختار زیربنایی Ty دسترسی می‌دهد.

    نمونهٔ استفاده:

    impl LateLintPass<'_> for MyStructLint {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {
        // Get type of `expr`
        let ty = cx.typeck_results().expr_ty(expr);
        // Match its kind to enter its type
        match ty.kind() {
            ty::Adt(adt_def, _) if adt_def.is_struct() => println!("Our `expr` is a struct!"),
            _ => ()
        }
    }
}

    به‌طور مشابه، در میان متدهای TypeckResults، متد pat_ty() را دارید که نوع را از یک الگو دریافت می‌کند.

    دو نکتهٔ قابل توجه در اینجا:

    • cx همان بافت lint یعنی LateContext است. دو ساختار داده‌ای که در این بافت بیشترین کاربرد را دارند tcx و TypeckResults هستند که توسط LateContext::typeck_results برگردانده می‌شود و به ما اجازه می‌دهند به تعریف نوع‌ها و دیگر مراحل کامپایل مانند HIR برویم.
    • مقدار بازگشتی typeck_results از نوع TypeckResults است و توسط مرحلهٔ بررسی نوع ایجاد می‌شود؛ این مقدار اطلاعات مفیدی مانند نوع عبارت‌ها، روش‌های تحلیل (resolve) متدها و غیره را در بر دارد.

    بررسی اینکه آیا یک expr متد مشخصی را فراخوانی می‌کند

    با شروع از یک expr، می‌توانید بررسی کنید که آیا متد مشخصی مانند some_method را فراخوانی می‌کند:

    impl<'tcx> LateLintPass<'tcx> for MyStructLint {
    fn check_expr(&mut self, cx: &LateContext<'tcx>, expr: &'tcx hir::Expr<'_>) {
        // Check our expr is calling a method
        if let hir::ExprKind::MethodCall(path, _, _self_arg, ..) = &expr.kind
            // Check the name of this method is `some_method`
            && path.ident.name == sym::some_method
            // Optionally, check the type of the self argument.
            // - See "Checking for a specific type"
        {
                // ...
        }
    }
}

    بررسی یک نوع مشخص

    سه روش برای بررسی اینکه نوع یک عبارت همان نوع موردنظر ماست وجود دارد. همهٔ این روش‌ها فقط نوع پایه را بررسی می‌کنند و آرگومان‌های جنریک باید جداگانه بررسی شوند.

    use clippy_utils::{paths, sym};
use clippy_utils::res::MaybeDef;
use rustc_attr_ir::lang_items::LangItem;

impl LateLintPass<'_> for MyStructLint {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {
        // Getting the expression type
        let ty = cx.typeck_results().expr_ty(expr);

        // 1. Using diagnostic items
        // The last argument is the diagnostic item to check for
        if ty.is_diag_item(cx, sym::Option) {
            // The type is an `Option`
        }

        // 2. Using lang items
        if ty.is_lang_item(cx, LangItem::RangeFull) {
            // The type is a full range like `.drain(..)`
        }

        // 3. Using the type path
        // This method should be avoided if possible
        if paths::RESULT.matches_ty(cx, ty) {
            // The type is a `core::result::Result`
        }
    }
}

    در صورت امکان از آیتم‌های تشخیصی (diagnostic items) و lang itemها استفاده کنید.

    بررسی اینکه آیا یک نوع صفت مشخصی را پیاده‌سازی می‌کند

    سه روش برای این کار وجود دارد که بسته به این است که صفت موردنظر دارای diagnostic item، lang item یا هیچ‌کدام باشد.

    use clippy_utils::sym;
use clippy_utils::ty::implements_trait;

impl LateLintPass<'_> for MyStructLint {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {

        // 1. Get the `DefId` of the trait.
        // via lang items
        let trait_id = cx.tcx.lang_items().drop_trait();
        // via diagnostic items
        let trait_id = cx.tcx.get_diagnostic_item(sym::Eq);

        // 2. Check for the trait implementation via the `implements_trait` util.
        let ty = cx.typeck_results().expr_ty(expr);
        if trait_id.is_some_and(|id| implements_trait(cx, ty, id, &[])) {
            // `ty` implements the trait.
        }

        // 3. If the trait requires additional generic arguments
        let trait_id = cx.tcx.lang_items().eq_trait();
        if trait_id.is_some_and(|id| implements_trait(cx, ty, id, &[ty])) {
            // `ty` implements `PartialEq<Self>`
        }
    }
}

    در صورتی که صفت موردنظر diagnostic item یا lang item دارد، استفاده از آن‌ها را ترجیح دهید.

    به lang itemها از طریق بافت نوع tcx دسترسی پیدا می‌کنیم. tcx از نوع TyCtxt است و در crate با نام rustc_middle تعریف شده است. فهرستی از مسیرهای تعریف‌شده برای Clippy را می‌توانید در paths.rs بیابید.

    بررسی اینکه آیا یک نوع متد مشخصی را تعریف می‌کند

    برای بررسی اینکه آیا نوع ما متدی به نام some_method را تعریف می‌کند:

    use clippy_utils::ty::is_type_lang_item;
use clippy_utils::{sym, return_ty};

impl<'tcx> LateLintPass<'tcx> for MyTypeImpl {
    fn check_impl_item(&mut self, cx: &LateContext<'tcx>, impl_item: &'tcx ImplItem<'_>) {
        // Check if item is a method/function
        if let ImplItemKind::Fn(ref signature, _) = impl_item.kind
            // Check the method is named `some_method`
            //
            // Add `some_method` to `clippy_utils::sym` if it's not already there
            && impl_item.ident.name == sym::some_method
            // We can also check it has a parameter `self`
            && signature.decl.implicit_self.has_implicit_self()
            // We can go further and even check if its return type is `String`
            && return_ty(cx, impl_item.hir_id).is_lang_item(cx, LangItem::String)
        {
            // ...
        }
    }
}

    کار با ماکروها و گسترش‌ها

    به یاد داشته باشید که ماکروها پیش از این گسترش یافته‌اند و desugaring نیز پیش از این روی نمایش کدی که در Clippy با آن کار می‌کنید اعمال شده است. این موضوع متأسفانه باعث بروز تعداد زیادی مثبت کاذب می‌شود، زیرا گسترش ماکروها «نامرئی» هستند مگر اینکه به‌طور فعال آن‌ها را بررسی کنید. به‌طور کلی، Clippy باید کدی را که گسترش ماکرو دارد نادیده بگیرد، چون چنین کدی می‌تواند به شیوه‌هایی پویا باشد که دیدنشان دشوار یا غیرممکن است. برای کار با ماکروها از توابع زیر استفاده کنید:

    • span.from_expansion(): تشخیص می‌دهد که آیا یک span از گسترش ماکرو یا desugaring آمده است. بررسی این مورد معمولاً نخستین گام در یک lint است.

      if expr.span.from_expansion() {
    // just forget it
    return;
}

    • span.ctxt(): بافت یک span نشان می‌دهد که آیا از گسترش آمده است یا نه، و اگر آمده، کدام فراخوانی ماکرو آن را گسترش داده است. گاهی بررسی برابر بودن بافت دو span مفید است.

      // expands to `1 + 0`, but don't lint
1 + mac!()
      if left.span.ctxt() != right.span.ctxt() {
    // the coder most likely cannot modify this expression
    return;
}

      Note

      توجه: کدی که از گسترش نیامده باشد در بافت «ریشه» قرار دارد. بنابراین می‌توان فرض کرد همهٔ spanهایی که from_expansion برای آن‌ها true برمی‌گرداند بافت یکسانی دارند. به همین دلیل، استفادهٔ صرف از span.from_expansion() اغلب کافی است.

    • span.in_external_macro(sm): تشخیص می‌دهد که آیا span داده‌شده از ماکرویی آمده است که در یک crate خارجی تعریف شده است. اگر می‌خواهید lint روی کد تولیدشده با ماکرو هم کار کند، این بررسی خط دفاع بعدی برای پرهیز از ماکروهایی است که در crate فعلی تعریف نشده‌اند. lint کردن کدی که برنامه‌نویس نمی‌تواند آن را تغییر دهد معنایی ندارد.

      مثلاً ممکن است بخواهید از آن استفاده کنید تا lint روی ماکروهای crateهای دیگر شروع به کار نکند

      use a_crate_with_macros::foo;

// `foo` is defined in `a_crate_with_macros`
foo!("bar");

// if we lint the `match` of `foo` call and test its span
assert_eq!(match_span.in_external_macro(cx.sess().source_map()), true);

    • span.ctxt(): بافت یک span نشان می‌دهد که آیا از گسترش آمده است یا نه، و اگر آمده، چه چیزی آن را گسترش داده است

      یکی از کاربردهای SpanContext بررسی این است که آیا دو span در یک بافت قرار دارند یا نه. برای مثال، در a == b، a و b بافت یکسانی دارند. در یک macro_rules! با a == $b، عبارت $b به عبارتی با بافتی متفاوت از a گسترش می‌یابد.

      macro_rules! m {
    ($a:expr, $b:expr) => {
        if $a.is_some() {
            $b;
        }
    }
}

let x: Option<u32> = Some(42);
m!(x, x.unwrap());

// These spans are not from the same context
// x.is_some() is from inside the macro
// x.unwrap() is from outside the macro
assert_eq!(x_is_some_span.ctxt(), x_unwrap_span.ctxt());
