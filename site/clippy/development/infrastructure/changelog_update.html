    به‌روزرسانی Changelog

    اگر می‌خواهید در به‌روزرسانی changelog کمک کنید، به جای درستی آمده‌اید.

    چه زمانی به‌روزرسانی کنیم

    اصلاح غلط‌های تایپی و دیگر اصلاح‌ها/افزودنی‌های کوچک همیشه خوش‌آمد هستند.

    هنگام به‌روزرسانی changelog برای یک انتشار جدید Rust باید دقت ویژه‌ای کرد. به همین منظور، بهتر است changelog در هفتهٔ پیش از یک انتشار stable پیش‌رو به‌روزرسانی شود. تاریخ انتشارها را می‌توانید در Rust Forge بیابید.

    در بیشتر موارد فقط لازم است changelog را برای انتشارهای فرعی (minor) Rust به‌روزرسانی کنیم. بسیار نادر بوده است که تغییرات Clippy در یک انتشار وصله‌ای (patch) گنجانده شوند.

    راهنمای گام‌به‌گام به‌روزرسانی changelog

    \۱. یافتن کامیت‌های مرتبط Clippy

    هر انتشار Rust با نسخهٔ خاص خودش از Clippy عرضه می‌شود. زیردرخت (subtree) مربوط به Clippy را می‌توانید در پوشهٔ tools مخزن Rust بیابید.

    بسته به زمان فعلی و اینکه دقیقاً چه چیزی را می‌خواهید به‌روزرسانی کنید، نکته‌های زیر می‌توانند مفید باشند:

    • هنگام نوشتن یادداشت‌های انتشار برای انتشار stable پیش‌رو، باید کامیت Clippy در شاخهٔ beta فعلی Rust را checkout کنید. پیوند
    • هنگام نوشتن یادداشت‌های انتشار برای انتشار beta پیش‌رو، باید کامیت Clippy در main فعلی Rust را checkout کنید. پیوند
    • هنگام نوشتن یادداشت‌های انتشار (فراموش‌شده) برای یک انتشار stable گذشته، باید تگ انتشار Rust مربوط به آن انتشار stable را checkout کنید. پیوند

    معمولاً می‌خواهید changelog انتشار stable پیش‌رو را بنویسید. با این حال مطمئن شوید که beta از پیش در مخزن Rust شاخه‌سازی شده باشد.

    برای یافتن هش کامیت، دستور زیر را هنگامی که در یک checkout از rust-lang/rust هستید (در بیشتر موارد روی شاخهٔ upstream/beta) اجرا کنید:

    git log --oneline -- src/tools/clippy/ | grep -o "Merge commit '[a-f0-9]*' into .*" | head -1 | sed -e "s/Merge commit '\([a-f0-9]*\)' into .*/\1/g"

    \۲. دریافت PRهای میان آن کامیت‌ها

    وقتی بازهٔ کامیت‌های درست را به دست آوردید، دستور زیر را اجرا کنید

    util/fetch_prs_between.sh start_commit end_commit > changes.txt

    که در آن end_commit هش کامیتی است که از دستور قبلی به دست آمده و start_commit هش کامیت از فایل CHANGELOG فعلی است. فایل changes.txt را در ویرایشگر دلخواه خود باز کنید.

    \۳. نگارش changelog نهایی

    اسکریپت بالا باید همهٔ PRهای مرتبط را در فایلی که مشخص کرده‌اید ریخته باشد. این اسکریپت باید بیشتر PRهای نامرتبط را از پیش فیلتر کرده باشد، اما بهتر است یک گذر پاک‌سازی دستی انجام دهید و PRهای ارزشمند را انتخاب کنید. اگر دربارهٔ برخی PRها مطمئن نیستید، آن‌ها را برای بازبینی باقی بگذارید و بازخورد بخواهید.

    پس از فیلتر شدن PRها، می‌توانید هر PR را بردارید و محتوای changelog: آن را به CHANGELOG.md منتقل کنید. عبارت‌بندی را به صلاح‌دید خود تطبیق دهید، اما سعی کنید تا حدی منسجم بماند.

    ترتیب بخش‌ها تقریباً باید این‌گونه باشد:

    ### New Lints
* Added [`LINT`] to `GROUP`

### Moves and Deprecations
* Moved [`LINT`] to `GROUP` (From `GROUP`, now LEVEL-by-default)
* Renamed `LINT` to [`LINT`]

### Enhancements
### False Positive Fixes
### ICE Fixes
### Documentation Improvements
### Others

    لطفاً حتماً بخش Unreleased/Beta/In Rust Nightly را نیز در بالای فایل با بازه‌های کامیت مرتبط به‌روزرسانی کنید و بخش Rust <version> را با تاریخ انتشار و بازه‌های PR اضافه کنید.

    \۴. گنجاندن PRهای beta-accepted

    برچسب beta-accepted را جست‌وجو کنید و حتماً PRهای دارای آن برچسب را نیز در changelog بگنجانید. اگر می‌توانید، برچسب‌های beta-accepted را پس از ادغام شدن PR مربوط به changelog حذف کنید.

    Note

    توجه: برخی از آن PRها ممکن است حتی به beta قبلی بک‌پورت شوند. این‌ها باید در changelog انتشار قبلی گنجانده شوند.

    \۵. به‌روزرسانی attributeهای clippy::version

    سپس، مطمئن شوید که attributeهای #[clippy::version] برای lintهای افزوده‌شده نسخهٔ درست را دارند. برای یافتن lintهایی که نیاز به به‌روزرسانی نسخه دارند، lintهای بخش «New Lints» را مرور کنید و دستور زیر را برای هر نام lint اجرا کنید:

    grep -rB1 "pub $LINT_NAME" .

    نسخهٔ نمایش‌داده‌شده باید با نسخهٔ انتشاری که changelog برای آن نوشته می‌شود مطابقت داشته باشد. اگر نداشت، نسخه را به نسخهٔ changelog به‌روزرسانی کنید.
