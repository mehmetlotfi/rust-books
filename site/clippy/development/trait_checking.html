    بررسی صفت

    افزون بر بررسی نوع، هنگام پیاده‌سازی یک lint ممکن است بخواهیم بررسی کنیم که آیا نوع مشخصی مانند Ty صفت معینی را پیاده‌سازی می‌کند یا نه. برای این کار سه رویکرد وجود دارد، بسته به اینکه صفت هدفی که می‌خواهیم بررسی کنیم diagnostic item دارد، lang item دارد، یا هیچ‌کدام.

    استفاده از Diagnostic Itemها

    همان‌طور که در راهنمای توسعهٔ کامپایلر Rust توضیح داده شده است، diagnostic itemها برای شناسایی نوع‌ها از طریق Symbolها معرفی شده‌اند.

    برای مثال، اگر بخواهیم بررسی کنیم که آیا یک عبارت صفت Iterator را پیاده‌سازی می‌کند، کافی است کد زیر را بنویسیم و LateContext (یعنی cx)، عبارت مورد نظرمان، و نماد (symbol) صفت مورد نظر را به آن بدهیم:

    use clippy_utils::sym;
use clippy_utils::ty::implements_trait;
use rustc_hir::Expr;
use rustc_lint::{LateContext, LateLintPass};

impl LateLintPass<'_> for CheckIteratorTraitLint {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {
        let implements_iterator = (cx.tcx.get_diagnostic_item(sym::Iterator))
            .is_some_and(|id| implements_trait(cx, cx.typeck_results().expr_ty(expr), id, &[]));
        if implements_iterator {
            // [...]
        }

    }
}

    توجه: برای همهٔ Symbolهای تعریف‌شده به این فهرست مراجعه کنید.

    استفاده از Lang Itemها

    افزون بر diagnostic itemها، می‌توانیم از lang_items نیز استفاده کنیم. با نگاهی به مستندات درمی‌یابید که LanguageItems شامل همهٔ آیتم‌های زبانی است که در کامپایلر تعریف شده‌اند.

    با استفاده از یکی از متدهای *_trait آن، می‌توانیم DefId هر آیتم مشخصی را به دست آوریم، مانند Clone، Copy، Drop و Eq که برای بسیاری از Rustaceanها آشنا هستند.

    برای مثال، اگر بخواهیم بررسی کنیم که آیا عبارت expr صفت Drop را پیاده‌سازی می‌کند، می‌توانیم از طریق TyCtxt مربوط به LateContext به LanguageItems دسترسی پیدا کنیم؛ TyCtxt متدی به نام lang_items دارد که شناسهٔ صفت Drop را به ما برمی‌گرداند. سپس با فراخوانی تابع کمکی implements_trait در Clippy می‌توانیم بررسی کنیم که Ty مربوط به expr این صفت را پیاده‌سازی می‌کند:

    use clippy_utils::ty::implements_trait;
use rustc_hir::Expr;
use rustc_lint::{LateContext, LateLintPass};

impl LateLintPass<'_> for CheckDropTraitLint {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {
        let ty = cx.typeck_results().expr_ty(expr);
        if cx.tcx.lang_items()
            .drop_trait()
            .map_or(false, |id| implements_trait(cx, ty, id, &[])) {
                println!("`expr` implements `Drop` trait!");
            }
    }
}

    استفاده از مسیر نوع

    اگر نه diagnostic item در دسترس باشد و نه lang item، می‌توانیم از clippy_utils::paths برای به دست آوردن DefId یک صفت استفاده کنیم.

    توجه: در صورت امکان باید از این رویکرد پرهیز کرد؛ بهترین کار این است که یک PR به rust-lang/rust بفرستید و یک diagnostic item اضافه کنید.

    در ادامه بررسی می‌کنیم که آیا expr داده‌شده core::iter::Step را پیاده‌سازی می‌کند:

    use clippy_utils::paths;
use clippy_utils::ty::implements_trait;
use rustc_hir::Expr;
use rustc_lint::{LateContext, LateLintPass};

impl LateLintPass<'_> for CheckIterStep {
    fn check_expr(&mut self, cx: &LateContext<'_>, expr: &Expr<'_>) {
        let ty = cx.typeck_results().expr_ty(expr);
        if let Some(trait_def_id) = paths::ITER_STEP.first(cx)
            && implements_trait(cx, ty, trait_def_id, &[])
        {
            println!("`expr` implements the `core::iter::Step` trait!");
        }
    }
}

    ساخت نوع‌ها به‌صورت برنامه‌نویسی‌شده

    صفت‌ها اغلب نسبت به یک پارامتر نوع جنریک هستند؛ برای مثال Borrow<T> نسبت به T جنریک است. Rust به ما اجازه می‌دهد یک صفت را برای یک نوع مشخص پیاده‌سازی کنیم. برای مثال، می‌توانیم Borrow<[u8]> را برای نوعی فرضی به نام Foo پیاده‌سازی کنیم. فرض کنید می‌خواهیم بدانیم آیا نوع ما واقعاً Borrow<[u8]> را پیاده‌سازی می‌کند.

    برای این کار می‌توانیم از همان تابع implements_trait بالا استفاده کنیم و یک پارامتر نوع که نمایندهٔ [u8] است به آن بدهیم. از آنجا که [u8] یک تخصیص (specialization) از [T] است، می‌توانیم با متد Ty::new_slice نوعی بسازیم که نمایندهٔ [T] باشد و u8 را به‌عنوان پارامتر نوع به آن بدهیم. برای ساخت یک ty::Ty به‌صورت برنامه‌نویسی‌شده، از متدهای Ty::new_* استفاده می‌کنیم. این متدها یک TyKind می‌سازند و سپس آن را در ساختار Ty قرار می‌دهند. یعنی به همهٔ نوع‌های ابتدایی دسترسی داریم، مانند Ty::new_char، Ty::new_bool، Ty::new_int و غیره. همچنین می‌توانیم با این بلوک‌های سازندهٔ پایه، نوع‌های پیچیده‌تری مانند برش‌ها (slice)، چندتایی‌ها (tuple) و ارجاع‌ها بسازیم.

    برای بررسی صفت، ساختن نوع‌ها کافی نیست؛ باید آن‌ها را به GenericArg تبدیل کنیم. در rustc، یک جنریک موجودیتی است که کامپایلر آن را می‌فهمد و سه گونه دارد: نوع، ثابت (const) و طول عمر. با فراخوانی .into() روی یک Ty ساخته‌شده، نوع را در یک جنریک می‌پیچیم که سپس سامانهٔ کوئری می‌تواند با آن تصمیم بگیرد که آیا صفتِ تخصیص‌یافته پیاده‌سازی شده است یا نه.

    کد زیر نشان می‌دهد چگونه این کار را انجام دهیم:

    
use rustc_middle::ty::Ty;
use clippy_utils::sym;
use clippy_utils::ty::implements_trait;

let ty = todo!("Get the `Foo` type to check for a trait implementation");
let borrow_id = cx.tcx.get_diagnostic_item(sym::Borrow).unwrap(); // avoid unwrap in real code
let slice_of_bytes_t = Ty::new_slice(cx.tcx, cx.tcx.types.u8);
let generic_param = slice_of_bytes_t.into();
if implements_trait(cx, ty, borrow_id, &[generic_param]) {
    todo!("Rest of lint implementation")
}

    در اصل، ساختار Ty به ما اجازه می‌دهد نوع‌ها را به‌صورت برنامه‌نویسی‌شده و در قالبی بسازیم که کامپایلر و موتور کوئری بتوانند از آن استفاده کنند. سپس از rustc_middle::Ty نوع مورد نظرمان استفاده می‌کنیم و از کامپایلر می‌پرسیم که آیا واقعاً صفت مورد نظرمان را پیاده‌سازی می‌کند یا نه.
