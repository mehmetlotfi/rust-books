    RAII

    متغیرها در راست فقط داده را روی پشته نگه نمی‌دارند، بلکه مالک منابع نیز هستند؛ برای نمونه Box<T> مالک حافظه‌ای در هیپ است. راست الگوی RAII، یعنی «دریافت منبع همان مقداردهی اولیه است»، را اعمال می‌کند. بنابراین هرگاه یک شیء از محدوده خارج شود، تخریب‌گر آن فراخوانی و منابع تحت مالکیتش آزاد می‌شوند.

    این رفتار از خطاهای نشت منبع جلوگیری می‌کند؛ پس نیازی نیست حافظه را دستی آزاد کنید یا نگران نشت حافظه باشید. یک نمونهٔ کوتاه:

    // raii.rs
fn create_box() {
    // Allocate an integer on the heap
    let _box1 = Box::new(3i32);

    // `_box1` is destroyed here, and memory gets freed
}

fn main() {
    // Allocate an integer on the heap
    let _box2 = Box::new(5i32);

    // A nested scope:
    {
        // Allocate an integer on the heap
        let _box3 = Box::new(4i32);

        // `_box3` is destroyed here, and memory gets freed
    }

    // Creating lots of boxes just for fun
    // There's no need to manually free memory!
    for _ in 0u32..1_000 {
        create_box();
    }

    // `_box2` is destroyed here, and memory gets freed
}

    تخریب‌گر

    مفهوم تخریب‌گر (destructor) در راست از طریق صفت Drop فراهم می‌شود. تخریب‌گر وقتی فراخوانی می‌شود که منبع از دامنه خارج شود. لازم نیست این صفت برای هر نوعی پیاده‌سازی شود؛ فقط در صورتی آن را برای نوع خود پیاده‌سازی کنید که به منطق تخریب‌گر اختصاصی نیاز دارید.

    مثال زیر را اجرا کنید تا ببینید صفت Drop چگونه کار می‌کند. وقتی متغیر درون تابع main از دامنه خارج شود، تخریب‌گر سفارشی فراخوانی می‌شود.

    struct ToDrop;

impl Drop for ToDrop {
    fn drop(&mut self) {
        println!("ToDrop is being dropped");
    }
}

fn main() {
    let x = ToDrop;
    println!("Made a ToDrop!");
}
