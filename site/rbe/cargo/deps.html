Rust با مثالRust By Example

    وابستگی‌ها

    بیشتر برنامه‌ها به برخی کتابخانه‌ها وابسته‌اند. اگر تاکنون وابستگی‌ها را دستی مدیریت کرده باشید، می‌دانید این کار چقدر دردسر دارد. خوشبختانه زیست‌بوم راست به‌صورت استاندارد همراه cargo ارائه می‌شود! cargo می‌تواند وابستگی‌های یک پروژه را مدیریت کند.

    برای ساخت یک پروژهٔ تازهٔ راست:

    # A binary
cargo new foo

# A library
cargo new --lib bar

    در ادامهٔ فصل فرض می‌کنیم یک فایل اجرایی می‌سازیم، نه کتابخانه؛ بااین‌حال همهٔ مفاهیم یکسان‌اند.

    پس از اجرای دستورهای بالا باید سلسله‌مراتبی مانند این ببینید:

    .
├── bar
│   ├── Cargo.toml
│   └── src
│       └── lib.rs
└── foo
    ├── Cargo.toml
    └── src
        └── main.rs

    فایل main.rs فایل منبع ریشهٔ پروژهٔ تازهٔ foo است. Cargo.toml نیز فایل پیکربندی cargo برای پروژه است و محتوایی شبیه نمونهٔ زیر دارد:

    [package]
name = "foo"
version = "0.1.0"
authors = ["mark"]

[dependencies]

    فیلد name زیر بخش [package] نام پروژه را تعیین می‌کند. اگر کریت را منتشر کنید، crates.io از این نام استفاده خواهد کرد. فایل اجرایی خروجی نیز هنگام کامپایل همین نام را خواهد داشت.

    فیلد version شمارهٔ نسخهٔ کریت را بر اساس نسخه‌بندی معنایی مشخص می‌کند.

    فیلد authors فهرست پدیدآورندگان کریت برای زمان انتشار است.

    بخش [dependencies] برای افزودن وابستگی‌های پروژه به کار می‌رود.

    فرض کنید می‌خواهیم برنامهٔ ما رابط خط فرمان خوبی داشته باشد. بسته‌های فراوانی در crates.io، مخزن رسمی بسته‌های راست، وجود دارند. یکی از گزینه‌های محبوب clap است. در زمان نگارش این متن، تازه‌ترین نسخهٔ منتشرشدهٔ clap برابر 2.27.1 است. برای افزودن این وابستگی کافی است زیر [dependencies] در Cargo.toml بنویسیم clap = "2.27.1". حالا می‌توانید از clap در برنامه استفاده کنید.

    cargo از انواع دیگر وابستگی‌ها نیز پشتیبانی می‌کند. چند نمونه:

    [package]
name = "foo"
version = "0.1.0"
authors = ["mark"]

[dependencies]
clap = "2.27.1" # from crates.io
rand = { git = "https://github.com/rust-lang-nursery/rand" } # from online repo
bar = { path = "../bar" } # from a path in the local filesystem

    cargo چیزی فراتر از مدیر وابستگی است. همهٔ گزینه‌های پیکربندی موجود در مشخصات قالب Cargo.toml فهرست شده‌اند.

    برای ساخت پروژه می‌توانیم cargo build را در هر جای پوشهٔ پروژه، حتی زیرفولدرها، اجرا کنیم. cargo run نیز پروژه را می‌سازد و اجرا می‌کند. این دستورها همهٔ وابستگی‌ها را حل می‌کنند، در صورت نیاز کریت‌ها را دریافت می‌کنند و همه‌چیز، از جمله کریت شما، را می‌سازند. مشابه make فقط بخش‌هایی دوباره ساخته می‌شوند که پیش‌تر ساخته نشده‌اند یا تغییر کرده‌اند.

    تمام شد؛ به همین سادگی!
