    آزمون مستندات

    روش اصلی مستندسازی یک پروژهٔ Rust حاشیه‌نویسی کد منبع است. کامنت‌های مستندات به مشخصات CommonMark Markdown نوشته می‌شوند و از بلوک‌های کد در آن‌ها پشتیبانی می‌کنند. Rust مراقب درستی است، به همین دلیل این بلوک‌های کد کامپایل می‌شوند و به‌عنوان آزمون‌های مستندات به‌کار می‌روند.

    /// First line is a short summary describing function.
///
/// The next lines present detailed documentation. Code blocks start with
/// triple backquotes and have implicit `fn main()` inside
/// and `extern crate <cratename>`. Assume we're testing a `playground` library
/// crate or using the Playground's Test action:
///
/// ```
/// let result = playground::add(2, 3);
/// assert_eq!(result, 5);
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

/// Usually doc comments may include sections "Examples", "Panics" and "Failures".
///
/// The next function divides two numbers.
///
/// # Examples
///
/// ```
/// let result = playground::div(10, 2);
/// assert_eq!(result, 5);
/// ```
///
/// # Panics
///
/// The function panics if the second argument is zero.
///
/// ```rust,should_panic
/// // panics on division by zero
/// playground::div(10, 0);
/// ```
pub fn div(a: i32, b: i32) -> i32 {
    if b == 0 {
        panic!("Divide-by-zero error");
    }

    a / b
}

    انگیزهٔ آزمون مستندات

    هدف اصلی آزمون مستندات، ارائهٔ مثال‌هایی است که واقعاً قابلیت موردنظر را اجرا می‌کنند؛ این یکی از مهم‌ترین راهنمودها است. در نتیجه مثال‌های مستندات می‌توانند قطعه‌کدهای کامل باشند. اما استفاده از ? چون main نوع unit برمی‌گرداند باعث شکست کامپایل می‌شود. پنهان‌کردن برخی خطوط راه‌گشاست: می‌توان fn try_main() -> Result<(), ErrorType> را نوشت، آن را پنهان کرد و در main پنهان unwrap نمود. پیچیده به‌نظر می‌رسد؟ این مثال را ببینید:

    /// Using hidden `try_main` in doc tests.
///
/// ```
/// # // hidden lines start with `#` symbol, but they're still compilable!
/// # fn try_main() -> Result<(), String> { // line that wraps the body shown in doc
/// let res = playground::try_div(10, 2)?;
/// # Ok(()) // returning from try_main
/// # }
/// # fn main() { // starting main that'll unwrap()
/// #    try_main().unwrap(); // calling try_main and unwrapping
/// #                         // so that test will panic in case of error
/// # }
/// ```
pub fn try_div(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        Err(String::from("Divide-by-zero"))
    } else {
        Ok(a / b)
    }
}
