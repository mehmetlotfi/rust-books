    آزمون یکپارچه‌سازی

    آزمون‌های واحد هر بار یک ماژول را جداگانه می‌آزمایند؛ کوچک‌اند و به کد خصوصی دسترسی دارند. آزمون‌های یکپارچه‌سازی بیرون crate قرار دارند و مانند هر مصرف‌کنندهٔ دیگری فقط از رابط عمومی استفاده می‌کنند. هدفشان اطمینان از همکاری درست بخش‌های مختلف کتابخانه است.

    Cargo آزمون‌های یکپارچه‌سازی را در پوشهٔ tests کنار src جست‌وجو می‌کند.

    فایل src/lib.rs:

    // Define this in a crate called `adder`.
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

    فایل آزمون tests/integration_test.rs:

    #[test]
fn test_add() {
    assert_eq!(adder::add(3, 2), 5);
}

    اجرای آزمون‌ها با cargo test:

    هر فایل منبع Rust در پوشهٔ tests به‌صورت crate جداگانه کامپایل می‌شود. برای اشتراک کد میان آزمون‌ها می‌توان ماژولی با توابع عمومی ساخت و آن را در آزمون‌ها وارد کرد.

    فایل tests/common/mod.rs:

    pub fn setup() {
    // some setup code, like creating required files/directories, starting
    // servers, etc.
}

    فایل آزمون tests/integration_test.rs:

    // importing common module.
mod common;

#[test]
fn test_add() {
    // using common code.
    common::setup();
    assert_eq!(adder::add(3, 2), 5);
}

    ساخت ماژول به شکل tests/common.rs هم کار می‌کند، اما توصیه نمی‌شود؛ زیرا اجراکننده آن را crate آزمون می‌پندارد و می‌کوشد آزمون‌های درونش را اجرا کند.
