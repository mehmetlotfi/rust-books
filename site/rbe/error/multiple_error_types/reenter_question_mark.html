    کاربردهای دیگر ?

    در مثال قبل، بلافاصله پس از فراخوانی parse خطای کتابخانه را با map به خطای درون Box تبدیل کردیم:

    .and_then(|s| s.parse::<i32>())
    .map_err(|e| e.into())

    چون این عملیات ساده و رایج است، حذف نوشتن صریح آن مفید بود. and_then انعطاف کافی ندارد، اما می‌توانیم از ? استفاده کنیم.

    پیش‌تر ? را معادل unwrap یا return Err(err) دانستیم، اما تعریف دقیق‌تر unwrap یا return Err(From::from(err)) است. چون From::from نوع‌ها را تبدیل می‌کند، اگر خطا به نوع بازگشتی قابل تبدیل باشد، ? آن را خودکار تبدیل می‌کند.

    اینجا مثال قبل را با ? بازنویسی می‌کنیم. وقتی From::from برای نوع خطای ما پیاده‌سازی شود، map_err حذف می‌شود:

    use std::error;
use std::fmt;

// Change the alias to use `Box<dyn error::Error>`.
type Result<T> = std::result::Result<T, Box<dyn error::Error>>;

#[derive(Debug)]
struct EmptyVec;

impl fmt::Display for EmptyVec {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "invalid first item to double")
    }
}

impl error::Error for EmptyVec {}

// The same structure as before but rather than chain all `Results`
// and `Options` along, we `?` to get the inner value out immediately.
fn double_first(vec: Vec<&str>) -> Result<i32> {
    let first = vec.first().ok_or(EmptyVec)?;
    let parsed = first.parse::<i32>()?;
    Ok(2 * parsed)
}

fn print(result: Result<i32>) {
    match result {
        Ok(n)  => println!("The first doubled is {}", n),
        Err(e) => println!("Error: {}", e),
    }
}

fn main() {
    let numbers = vec!["42", "93", "18"];
    let empty = vec![];
    let strings = vec!["tofu", "93", "18"];

    print(double_first(numbers));
    print(double_first(empty));
    print(double_first(strings));
}

    اکنون این کد واقعاً نسبتاً تمیز است. در مقایسه با panic اولیه، تقریباً مانند جایگزین‌کردن فراخوانی‌های unwrap با ? است، با این تفاوت که نوع‌های بازگشتی Result هستند. در نتیجه باید در سطح بالا ساختارشکنی شوند.
