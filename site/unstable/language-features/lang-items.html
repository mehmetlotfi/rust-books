    lang_items

    مسئلهٔ پیگیری (tracking issue) این ویژگی: ندارد.

    کامپایلر rustc عملیات «قابل اتصال» (pluggable) مشخصی دارد؛ یعنی قابلیت‌هایی که در خود زبان به‌صورت سخت‌کد (hard-coded) تعریف نشده‌اند، بلکه در کتابخانه‌ها پیاده‌سازی می‌شوند و با یک نشانگر ویژه به کامپایلر اطلاع داده می‌شود که وجود دارند. این نشانگر attribute به شکل #[lang = "..."] است و ... مقادیر مختلفی می‌گیرد، یعنی «lang itemهای» مختلف. بیشتر آن‌ها را فقط یک بار می‌توان تعریف کرد.

    کامپایلر lang itemها را به‌صورت تنبل (lazy) بارگذاری می‌کند؛ مثلاً اگر هرگز از Box استفاده نکنید، لازم نیست تابعی برای exchange_malloc تعریف کنید. rustc وقتی به آیتمی نیاز باشد اما در crate فعلی یا crateهای مورد وابستگی آن یافت نشود، خطا صادر می‌کند.

    برخی از قابلیت‌هایی که lang itemها فراهم می‌کنند:

    • سربارگذاری عملگرها از طریق صفت‌ها (trait): صفت‌های متناظر با عملگرهای ==، <، dereference (*) و + (و غیره) همگی با lang item علامت‌گذاری شده‌اند؛ آن چهار مورد مشخص به ترتیب eq، partial_ord، deref/deref_mut و add هستند.
    • panic کردن: lang itemهای panic و panic_impl و موارد دیگر.
    • بازکردن پشته (stack unwinding): lang item به نام eh_personality تابعی است که سازوکارهای شکست (failure) کامپایلر از آن استفاده می‌کنند. این اغلب به تابع personality در GCC نگاشت می‌شود (برای اطلاعات بیشتر پیاده‌سازی std را ببینید)، اما برنامه‌هایی که panic ایجاد نمی‌کنند می‌توانند مطمئن باشند که این تابع هرگز فراخوانی نمی‌شود.
    • صفت‌های موجود در core::marker که برای نشان دادن انواع مختلف نوع‌ها به کار می‌روند؛ مثلاً lang itemهای sized، sync و copy.
    • تخصیص حافظه، که در ادامه آمده است.

    بیشتر lang itemها در core تعریف شده‌اند، اما اگر بخواهید یک فایل اجرایی را بدون crate به نام std بسازید، ممکن است به تعریف lang itemها نیاز پیدا کنید.

    مثال: پیاده‌سازی Box

    اشاره‌گرهای Box به دو lang item نیاز دارند: یکی برای خود نوع و دیگری برای تخصیص حافظه. برنامهٔ مستقل (freestanding) زیر از شکر نحوی Box برای تخصیص پویا از طریق malloc و free استفاده می‌کند:

    #![feature(lang_items, core_intrinsics, rustc_private, panic_unwind, rustc_attrs)]
#![allow(internal_features)]
#![no_std]
#![no_main]

extern crate libc;
extern crate unwind;

use core::ffi::{c_int, c_void};
use core::intrinsics;
use core::panic::PanicInfo;
use core::ptr::NonNull;

pub struct Global; // the global allocator
struct Unique<T>(NonNull<T>);

#[lang = "owned_box"]
pub struct Box<T, A = Global>(Unique<T>, A);

impl<T> Box<T> {
    pub fn new(x: T) -> Self {
        #[rustc_box]
        Box::new(x)
    }
}

impl<T, A> Drop for Box<T, A> {
    fn drop(&mut self) {
        unsafe {
            libc::free(self.0.0.as_ptr() as *mut c_void);
        }
    }
}

#[lang = "exchange_malloc"]
unsafe fn allocate(size: usize, _align: usize) -> *mut u8 {
    let p = libc::malloc(size) as *mut u8;

    // Check if `malloc` failed:
    if p.is_null() {
        intrinsics::abort_immediate();
    }

    p
}

#[no_mangle]
extern "C" fn main(_argc: c_int, _argv: *const *const u8) -> c_int {
    let _x = Box::new(1);

    0
}

#[lang = "eh_personality"]
fn rust_eh_personality() {}

#[panic_handler]
fn panic_handler(_info: &PanicInfo) -> ! { intrinsics::abort_immediate() }

    به استفاده از abort توجه کنید: فرض بر این است که lang item به نام exchange_malloc یک اشاره‌گر معتبر برمی‌گرداند، و بنابراین باید بررسی را در درون خود انجام دهد.
