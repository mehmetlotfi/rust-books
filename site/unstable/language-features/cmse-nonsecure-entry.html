    cmse_nonsecure_entry

    issue ردیابی این قابلیت: #75835

    قابلیت TrustZone-M برای هدف‌هایی با نیمرخ معماری Armv8-M (که در نام هدفشان thumbv8m وجود دارد) در دسترس است. LLVM، کامپایلر Rust و لینکر از قابلیت TrustZone-M پشتیبانی می‌کنند.

    یکی از چیزهایی که با این قابلیت ناپایدار ارائه می‌شود ABI به نام “cmse-nonsecure-entry” است. این ABI یک تابع Secure را به‌عنوان تابع ورودی (entry) علامت‌گذاری می‌کند (برای جزئیات به بخش 5.4 نگاه کنید). با این ABI، کامپایلر کارهای زیر را انجام می‌دهد:

    • یک نماد (symbol) ویژه روی تابع اضافه می‌کند که از پیشوند __acle_se_ و نام استاندارد تابع تشکیل می‌شود
    • تعداد پارامترها را محدود می‌کند تا از استفاده از پشته‌ی Non-Secure اجتناب شود
    • پیش از بازگشت از تابع، ثبات‌هایی (registers) را که ممکن است اطلاعات Secure داشته باشند پاک می‌کند
    • برای بازگشت از دستور BXNS استفاده می‌کند

    از آنجا که برای پاس‌دادن پارامترها نمی‌توان از پشته استفاده کرد، در موارد زیر خطاهای کامپایل رخ می‌دهد:

    • اندازه‌ی کل همه‌ی پارامترها بیش از حد بزرگ باشد (برای مثال، بیش از چهار عدد صحیح 32 بیتی)

    نماد ویژه‌ی __acle_se_ توسط لینکر برای تولید یک secure gateway veneer به کار می‌رود.

    #![no_std]
#![feature(cmse_nonsecure_entry)]

#[no_mangle]
pub extern "cmse-nonsecure-entry" fn entry_function(input: u32) -> u32 {
    input + 6
}
