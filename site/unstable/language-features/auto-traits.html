    auto_traits

    issue ردیابی این قابلیت #13231 است.

    قابلیت auto_traits به شما اجازه می‌دهد صفت‌های خودکار (auto trait) تعریف کنید.

    Auto traitها، مانند Send یا Sync در کتابخانهٔ استاندارد، traitهای نشانگر (marker) هستند که به‌طور خودکار برای هر نوعی پیاده‌سازی می‌شوند، مگر اینکه آن نوع یا نوعی که در خود دارد از طریق یک پیاده‌سازی منفی (negative impl) صراحتاً از آن انصراف داده باشد. (پیاده‌سازی‌های منفی جداگانه توسط قابلیت negative_impls کنترل می‌شوند.)

    impl !Trait for Type {}

    مثال:

    #![feature(negative_impls)]
#![feature(auto_traits)]

auto trait Valid {}

struct True;
struct False;

impl !Valid for False {}

struct MaybeValid<T>(T);

fn must_be_valid<T: Valid>(_t: T) { }

fn main() {
    // works
    must_be_valid( MaybeValid(True) );

    // compiler error - trait bound not satisfied
    // must_be_valid( MaybeValid(False) );
}

    پیاده‌سازی‌های خودکار صفت

    وقتی نوعی به‌صورت auto trait اعلام شود، برای هر struct/enum/union به‌طور خودکار پیاده‌سازی ایجاد می‌کنیم، مگر اینکه پیاده‌سازی صریحی ارائه شده باشد. این پیاده‌سازی‌های خودکار برای هر فیلد یک عبارت where به شکل T: AutoTrait دارند، که در آن T نوع فیلد و AutoTrait همان صفت خودکار مورد نظر است. به‌عنوان مثال، struct به نام List و صفت خودکار Send را در نظر بگیرید:

    struct List<T> {
  data: T,
  next: Option<Box<List<T>>>,
}

    با فرض اینکه هیچ پیاده‌سازی صریحی از Send برای List وجود نداشته باشد، کامپایلر یک پیاده‌سازی خودکار به شکل زیر فراهم می‌کند:

    struct List<T> {
  data: T,
  next: Option<Box<List<T>>>,
}

unsafe impl<T> Send for List<T>
where
  T: Send, // from the field `data`
  Option<Box<List<T>>>: Send, // from the field `next`
{ }

    پیاده‌سازی‌های صریح می‌توانند مثبت یا منفی باشند. شکل آن‌ها به این صورت است:

    impl<...> AutoTrait for StructName<..> { }
impl<...> !AutoTrait for StructName<..> { }

    هم‌استقرایی (Coinduction): صفت‌های خودکار تطبیق دوری را مجاز می‌کنند

    برخلاف تطبیق معمول صفت‌ها، صفت‌های خودکار هم‌استقرایی (coinductive) هستند. این یعنی، به‌اختصار، دورهایی که در تطبیق صفت رخ می‌دهند قابل‌قبول‌اند. به‌عنوان مثال، struct بازگشتی List را که در بخش قبل معرفی شد در نظر بگیرید. هنگام تلاش برای تعیین اینکه آیا List: Send برقرار است، به یک دور می‌رسیم: برای اعمال پیاده‌سازی باید نشان دهیم که Option<Box<List>>: Send، که به نوبه‌ی خود به Box<List>: Send و سپس در نهایت دوباره به List: Send نیاز دارد. در تطبیق معمول صفت، این دور یک خطا خواهد بود، اما برای یک صفت خودکار تطبیق موفق به حساب می‌آید.

    آیتم‌ها

    صفت‌های خودکار نمی‌توانند هیچ آیتم صفتی مانند متد یا نوع وابسته (associated type) داشته باشند. این تضمین می‌کند که بتوانیم پیاده‌سازی‌های پیش‌فرض تولید کنیم.

    Supertraitها (ابَرصفت‌ها)

    صفت‌های خودکار نمی‌توانند ابَرصفت داشته باشند. دلیل این امر صحت (soundness) است، چون تعامل هم‌استقرا با کران‌های ضمنی (implied bounds) به‌سختی قابل‌تطبیق است.
