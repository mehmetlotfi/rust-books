    transparent_unions

    issue ردیابی این ویژگی #60405 است

    ویژگی transparent_unions به شما اجازه می‌دهد unionها را با #[repr(transparent)] علامت‌گذاری کنید. یک union دقیقاً در همان شرایطی می‌تواند #[repr(transparent)] باشد که یک struct می‌تواند #[repr(transparent)] باشد (به طور کلی، یعنی union باید دقیقاً یک فیلد با اندازهٔ غیرصفر داشته باشد). در ادامه چند نمونهٔ عینی آمده است.

    #![feature(transparent_unions)]

// This union has the same representation as `f32`.
#[repr(transparent)]
union SingleFieldUnion {
    field: f32,
}

// This union has the same representation as `usize`.
#[repr(transparent)]
union MultiFieldUnion {
    field: usize,
    nothing: (),
}

    برای سازگاری با structهای شفاف، unionها باید دقیقاً یک فیلد با اندازهٔ غیرصفر داشته باشند. اگر همهٔ فیلدها اندازهٔ صفر داشته باشند، union نباید #[repr(transparent)] باشد:

    #![feature(transparent_unions)]

// This (non-transparent) union is already valid in stable Rust:
pub union GoodUnion {
    pub nothing: (),
}

// Error: transparent union needs exactly one non-zero-sized field, but has 0
// #[repr(transparent)]
// pub union BadUnion {
//     pub nothing: (),
// }

    تنها استثنا این است که اگر union روی T جنریک باشد و فیلدی از نوع T داشته باشد، حتی اگر T یک نوع با اندازهٔ صفر باشد هم می‌تواند #[repr(transparent)] باشد:

    #![feature(transparent_unions)]

// This union has the same representation as `T`.
#[repr(transparent)]
pub union GenericUnion<T: Copy> { // Unions with non-`Copy` fields are unstable.
    pub field: T,
    pub nothing: (),
}

// This is okay even though `()` is a zero-sized type.
pub const THIS_IS_OKAY: GenericUnion<()> = GenericUnion { field: () };

    مانند structهای شفاف، یک union شفاف از نوع U همان چیدمان، اندازه و ABI فیلد تنها و غیر ZST خود را دارد. اگر روی نوع T جنریک باشد و همهٔ فیلدهایش ZST باشند، به جز دقیقاً یک فیلد از نوع T، آنگاه چیدمان و ABI آن با T یکسان است (حتی اگر T پس از monomorphization یک ZST باشد).

    مانند structهای شفاف، unionهای شفاف تنها در صورتی FFI-safe هستند که نوع بازنمایی زیربنایی‌شان نیز FFI-safe باشد.

    ممکن است یک union واجد شرایط همان بهینه‌سازی‌های از نوع nonnull نباشد که یک struct یا enum (با همان فیلدها) واجد شرایط آن‌ها است. افزودن #[repr(transparent)] به union این وضعیت را تغییر نمی‌دهد. برای ارائهٔ مثالی عینی‌تر، مشخص نشده است که آیا size_of::<T>() با size_of::<Option<T>>() برابر است یا نه، وقتی T یک union باشد (چه شفاف باشد چه نباشد). کامپایلر Rust در صورت امکان آزاد است این بهینه‌سازی را انجام دهد، اما ملزم به این کار نیست، و نسخه‌های مختلف کامپایلر ممکن است در اعمال این بهینه‌سازی‌ها با هم تفاوت داشته باشند.
