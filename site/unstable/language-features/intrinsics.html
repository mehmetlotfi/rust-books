    intrinsics

    مسئلهٔ پیگیری (tracking issue) این ویژگی: ندارد.

    intrinsicها به‌ندرت قرار است مستقیماً پایدار باشند، اما معمولاً به نوعی به شکل پایدار صادر (export) می‌شوند. هر زمان که می‌توانید، به‌جای استفادهٔ مستقیم از intrinsic، از رابط‌های پایدار استفاده کنید.

    intrinsicهای دارای منطق جایگزین (fallback)

    بسیاری از intrinsicها را می‌توان با Rust خالص نوشت، هرچند ناکارآمد یا بدون پشتیبانی از برخی قابلیت‌هایی که فقط در برخی backendها وجود دارند. backendها می‌توانند آن intrinsicها را پیاده‌سازی نکنند، بدون آنکه باعث کامپایل نادرست کد یا شکست در کامپایل شود. بدنهٔ جایگزین همهٔ intrinsicها به‌طور خودکار توسط backend تولید کد (codegen) میان‌crateای قابل inline شدن می‌شود (مانند #[inline])، اما توسط inliner در MIR نه.

    #![feature(intrinsics)]
#![allow(internal_features)]

#[rustc_intrinsic]
const unsafe fn const_deallocate(_ptr: *mut u8, _size: usize, _align: usize) {}

    از آنجا که این‌ها فقط توابع معمولی هستند، ایجاد دوبارهٔ intrinsic کاملاً مجاز است:

    #![feature(intrinsics)]
#![allow(internal_features)]

#[rustc_intrinsic]
const unsafe fn const_deallocate(_ptr: *mut u8, _size: usize, _align: usize) {}

mod foo {
    #[rustc_intrinsic]
    const unsafe fn const_deallocate(_ptr: *mut u8, _size: usize, _align: usize) {
        panic!("noisy const dealloc")
    }
}

    رفتار روی backendهایی که intrinsic را بازنویسی (override) می‌کنند دقیقاً همان است. روی backendهای دیگر، رفتار intrinsic به این بستگی دارد که کدام پیاده‌سازی فراخوانی شود، درست مانند هر تابع معمولی.

    intrinsicهای تبدیل‌شده به دستورهای MIR

    برای بسیاری از intrinsicها عملیات MIR بومی متناظری وجود دارد. به‌جای آنکه از backendها بخواهیم هم intrinsic و هم عملیات MIR را پیاده‌سازی کنند، گذر lower_intrinsics فراخوانی‌ها را به عملیات MIR تبدیل می‌کند. backendها اصلاً لازم نیست از این intrinsicها خبر داشته باشند. این intrinsicها فقط بدون بدنه معنا دارند و می‌توان آن‌ها را به‌صورت #[rustc_intrinsic] تعریف کرد. بدنه هرگز استفاده نمی‌شود، چون گذر lowering پشتیبانی از همهٔ backendها را پیاده می‌کند و بنابراین هیچ‌گاه لازم نیست از منطق جایگزین استفاده کنیم.
