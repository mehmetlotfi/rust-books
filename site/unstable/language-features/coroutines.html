    coroutines

    issue ردیابی این قابلیت: #43122

    قابلیت coroutines در Rust به شما اجازه می‌دهد coroutine یا literalهای coroutine تعریف کنید. coroutine یک «تابع قابل‌ازسرگیری» است که از نظر نحوی شبیه closure است، اما در خود کامپایلر به معناشناسی (semantics) بسیار متفاوتی کامپایل می‌شود. ویژگی اصلی coroutine این است که می‌تواند در حین اجرا معلق شود تا در زمانی بعد از سر گرفته شود. coroutineها از کلیدواژه‌ی yield برای «بازگرداندن» استفاده می‌کنند و سپس فراخواننده می‌تواند با resume اجرای coroutine را درست پس از کلیدواژه‌ی yield از سر بگیرد.

    coroutineها در حال حاضر قابلیتی فوق‌العاده ناپایدار در کامپایلر هستند. این قابلیت در RFC 2033 اضافه شد و فعلاً بیشتر به‌عنوان مرحله‌ای برای جمع‌آوری اطلاعات و محدودیت‌ها در نظر گرفته شده است. هدف این است که پیش از پایدارسازی واقعی بتوان روی کامپایلر nightly آزمایش کرد. برای پایدارسازی coroutineها یک RFC دیگر لازم خواهد بود که احتمالاً حداقل چند تغییر کوچک در طراحی کلی را هم در بر خواهد داشت.

    یک مثال نحوی از coroutine:

    #![feature(coroutines, coroutine_trait, stmt_expr_attributes)]

use std::ops::{Coroutine, CoroutineState};
use std::pin::Pin;

fn main() {
    let mut coroutine = #[coroutine] || {
        yield 1;
        return "foo"
    };

    match Pin::new(&mut coroutine).resume(()) {
        CoroutineState::Yielded(1) => {}
        _ => panic!("unexpected value from resume"),
    }
    match Pin::new(&mut coroutine).resume(()) {
        CoroutineState::Complete("foo") => {}
        _ => panic!("unexpected value from resume"),
    }
}

    coroutineها literalهایی شبیه closure هستند که با #[coroutine] حاشیه‌نویسی می‌شوند و می‌توانند شامل دستور yield باشند. دستور yield یک عبارت اختیاری می‌گیرد که مقداری است که از coroutine بیرون داده می‌شود. همه‌ی literalهای coroutine صفت Coroutine را در ماژول std::ops پیاده‌سازی می‌کنند. صفت Coroutine یک متد اصلی دارد، resume، که اجرای coroutine را از نقطه‌ی تعلیق قبلی از سر می‌گیرد.

    نمونه‌ای از جریان کنترل coroutineها این است که مثال زیر همه‌ی اعداد را به‌ترتیب چاپ می‌کند:

    #![feature(coroutines, coroutine_trait, stmt_expr_attributes)]

use std::ops::Coroutine;
use std::pin::Pin;

fn main() {
    let mut coroutine = #[coroutine] || {
        println!("2");
        yield;
        println!("4");
    };

    println!("1");
    Pin::new(&mut coroutine).resume(());
    println!("3");
    Pin::new(&mut coroutine).resume(());
    println!("5");
}

    در حال حاضر کاربرد اصلی coroutineها پیاده‌سازی یک پایه (primitive) برای نحو async/await و gen است، اما coroutineها احتمالاً در آینده به پایه‌های دیگر هم گسترش خواهند یافت. بازخورد درباره‌ی طراحی و کاربرد همیشه قدردانی می‌شود!

    صفت Coroutine

    صفت Coroutine در std::ops در حال حاضر به این شکل است:

    #![feature(arbitrary_self_types, coroutine_trait)]
use std::ops::CoroutineState;
use std::pin::Pin;

pub trait Coroutine<R = ()> {
    type Yield;
    type Return;
    fn resume(self: Pin<&mut Self>, resume: R) -> CoroutineState<Self::Yield, Self::Return>;
}

    نوع Coroutine::Yield نوع مقادیری است که می‌توان با دستور yield بیرون داد. نوع Coroutine::Return نوع مقدار بازگشتی coroutine است. این معمولاً آخرین عبارت در تعریف coroutine یا هر مقداری است که در coroutine به return داده می‌شود. تابع resume نقطه‌ی ورود برای اجرای خود Coroutine است.

    مقدار بازگشتی resume، یعنی CoroutineState، به این شکل است:

    pub enum CoroutineState<Y, R> {
    Yielded(Y),
    Complete(R),
}

    حالت Yielded نشان می‌دهد که coroutine را می‌توان بعداً از سر گرفت. این متناظر با یک نقطه‌ی yield در coroutine است. حالت Complete نشان می‌دهد که coroutine تمام شده و دیگر نمی‌توان آن را از سر گرفت. فراخوانی resume پس از اینکه coroutine مقدار Complete برگردانده، احتمالاً به panic برنامه می‌انجامد.

    معناشناسی شبیه closure

    نحو شبیه closure برای coroutineها به این واقعیت اشاره دارد که آن‌ها معناشناسی شبیه closure هم دارند. یعنی:

    • هنگام ایجاد، coroutine هیچ کدی اجرا نمی‌کند. literal یک closure هنگام ساخت هیچ‌یک از کدهای closure را اجرا نمی‌کند، و به همین ترتیب literal یک coroutine هم هنگام ساخت هیچ کدی را درون coroutine اجرا نمی‌کند.

    • coroutineها می‌توانند متغیرهای بیرونی را با ارجاع یا با move بگیرند (capture)، و این را می‌توان با کلیدواژه‌ی move در ابتدای closure تغییر داد. مانند closureها، همه‌ی coroutineها یک محیط ضمنی دارند که توسط کامپایلر استنتاج می‌شود. متغیرهای بیرونی را می‌توان به درون coroutine move کرد تا با پیشرفت coroutine از آن‌ها استفاده شود.

    • literalهای coroutine مقداری با یک نوع یکتا تولید می‌کنند که صفت std::ops::Coroutine را پیاده‌سازی می‌کند. این کار هم اجرای واقعی coroutine را از طریق متد Coroutine::resume ممکن می‌کند و هم امکان نام‌بردن از آن در نوع‌های بازگشتی و مانند آن را.

    • صفت‌هایی مانند Send و Sync بسته به متغیرهای capture‌شده‌ی محیط، به‌طور خودکار برای Coroutine پیاده‌سازی می‌شوند. برخلاف closureها، coroutineها به متغیرهایی هم که در سراسر نقاط تعلیق زنده‌اند وابسته‌اند. یعنی اگرچه محیط پیرامون ممکن است Send یا Sync باشد، خود coroutine ممکن است نباشد، چون متغیرهای داخلی که در سراسر نقاط yield زنده‌اند ممکن است Send یا Sync نباشند. توجه کنید که coroutineها صفت‌هایی مانند Copy یا Clone را به‌طور خودکار پیاده‌سازی نمی‌کنند.

    • هرگاه یک coroutine drop شود، همه‌ی متغیرهای محیطِ capture‌شده را drop می‌کند.

    coroutineها به‌عنوان ماشین حالت

    در کامپایلر، coroutineها در حال حاضر به‌صورت ماشین حالت (state machine) کامپایل می‌شوند. هر عبارت yield متناظر با یک حالت متفاوت است که همه‌ی متغیرهای زنده در آن نقطه‌ی تعلیق را ذخیره می‌کند. از سرگیری یک coroutine بر اساس حالت فعلی انشعاب می‌کند و سپس در درون اجرا می‌شود تا به یک yield برسد؛ در آن نقطه همه‌ی حالت در coroutine ذخیره و یک مقدار برگردانده می‌شود.

    بیایید یک مثال را ببینیم تا بفهمیم اینجا چه می‌گذرد:

    #![feature(coroutines, coroutine_trait, stmt_expr_attributes)]

use std::ops::Coroutine;
use std::pin::Pin;

fn main() {
    let ret = "foo";
    let mut coroutine = #[coroutine] move || {
        yield 1;
        return ret
    };

    Pin::new(&mut coroutine).resume(());
    Pin::new(&mut coroutine).resume(());
}

    این literal مربوط به coroutine به چیزی شبیه این کامپایل می‌شود:

    #![feature(arbitrary_self_types, coroutine_trait)]

use std::ops::{Coroutine, CoroutineState};
use std::pin::Pin;

fn main() {
    let ret = "foo";
    let mut coroutine = {
        enum __Coroutine {
            Start(&'static str),
            Yield1(&'static str),
            Done,
        }

        impl Coroutine for __Coroutine {
            type Yield = i32;
            type Return = &'static str;

            fn resume(mut self: Pin<&mut Self>, resume: ()) -> CoroutineState<i32, &'static str> {
                use std::mem;
                match mem::replace(&mut *self, __Coroutine::Done) {
                    __Coroutine::Start(s) => {
                        *self = __Coroutine::Yield1(s);
                        CoroutineState::Yielded(1)
                    }

                    __Coroutine::Yield1(s) => {
                        *self = __Coroutine::Done;
                        CoroutineState::Complete(s)
                    }

                    __Coroutine::Done => {
                        panic!("coroutine resumed after completion")
                    }
                }
            }
        }

        __Coroutine::Start(ret)
    };

    Pin::new(&mut coroutine).resume(());
    Pin::new(&mut coroutine).resume(());
}

    به‌ویژه در اینجا می‌بینیم که کامپایلر یک نوع تازه تولید می‌کند، در این مورد __Coroutine. این نوع تعدادی حالت دارد (که اینجا به‌صورت یک enum نمایش داده شده‌اند) و هر یک متناظر با یکی از حالت‌های مفهومی coroutine است. در ابتدا متغیر بیرونی foo را می‌بندیم (close over) و سپس آن متغیر در سراسر نقطه‌ی yield هم زنده است، پس در هر دو حالت ذخیره می‌شود.

    وقتی coroutine شروع می‌شود بلافاصله 1 را yield می‌کند، اما درست پیش از آن حالتش را ذخیره می‌کند تا نشان دهد به نقطه‌ی yield رسیده است. هنگام از سرگیری دوباره، return ret اجرا می‌شود که حالت Complete را برمی‌گرداند.

    اینجا همچنین می‌توان توجه کرد که حالت Done، اگر از سر گرفته شود، بلافاصله panic می‌کند، چون از سرگیری یک coroutine تمام‌شده نامعتبر است. همچنین شایان ذکر است که این فقط یک desugaring تقریبی است، نه مشخصاتی هنجاری (normative) از کاری که کامپایلر انجام می‌دهد.
