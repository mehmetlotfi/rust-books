    rustc_private

    issue ردیابی این ویژگی: #27812

    این ویژگی امکان دسترسی به crateهای داخلی ناپایدار کامپایلر مانند rustc_driver را فراهم می‌کند.

    وجود این ویژگی روش محاسبهٔ قالب پیوند (linkage) برای dylibها را به شکلی تغییر می‌دهد که برای پیوند دادن با dylibهایی که std را به صورت ایستا پیوند می‌دهند (مانند rustc_driver) لازم است. این موضوع باعث می‌شود این ویژگی از نظر پیوند «مسری» باشد؛ استفاده از آن در یک crate، استفاده از آن را در crateهای وابسته‌ای که به آن پیوند می‌خورند نیز الزامی می‌کند (از جمله آزمون‌های یکپارچگی که به صورت crateهای جداگانه ساخته می‌شوند).

    خطاهای رایج پیوندده مربوط به نبود کتابخانه‌های LLVM

    هنگام استفاده از rustc-private با toolchainهای رسمی

    هنگام استفاده از ویژگی rustc_private با toolchainهای رسمی که از طریق rustup توزیع می‌شوند، باید این موارد را نصب کنید:

    1. مؤلفهٔ rustc-dev (کتابخانه‌های کامپایلر را فراهم می‌کند)
    2. مؤلفهٔ llvm-tools (کتابخانه‌های LLVM لازم برای پیوند را فراهم می‌کند)

    می‌توانید این مؤلفه‌ها را با rustup نصب کنید:

    rustup component add rustc-dev llvm-tools

    بدون مؤلفهٔ llvm-tools ممکن است با خطاهای پیوندی مانند خطای زیر روبه‌رو شوید:

    error: linking with `cc` failed: exit status: 1
  |
  = note: rust-lld: error: unable to find library -lLLVM-{version}

    هنگام استفاده از rustc-private با toolchainهای سفارشی

    برای toolchainهای سفارشی یا محیط‌هایی که از rustup استفاده نمی‌کنند، ممکن است پیکربندی متفاوتی لازم باشد:

    • مطمئن شوید کتابخانه‌های LLVM در مسیرهای جست‌وجوی کتابخانهٔ شما در دسترس هستند
    • بسته به نحوهٔ نصب LLVM، ممکن است لازم باشد مسیرهای کتابخانه را به طور صریح پیکربندی کنید
