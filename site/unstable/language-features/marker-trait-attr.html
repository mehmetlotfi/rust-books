    marker_trait_attr

    issue ردیابی این ویژگی: #29864

    Rust معمولاً اجازه نمی‌دهد پیاده‌سازی‌هایی از یک صفت اضافه کنید که ممکن است با هم همپوشانی داشته باشند، چون مشخص نخواهد بود کدام یک باید استفاده شود. اما این ویژگی یک استثنا برای این قاعده ایجاد می‌کند: یک صفت می‌تواند خودش انتخاب کند که پیاده‌سازی‌های همپوشان داشته باشد، به این بها که آن پیاده‌سازی‌ها اجازهٔ بازنویسی (override) هیچ چیزی را ندارند (و در نتیجه خود صفت نمی‌تواند هیچ آیتم وابسته‌ای داشته باشد، زیرا وقتی قرار است برای هر نوع کار یکسانی انجام دهند، وجودشان بی‌معنی است).

    #![feature(marker_trait_attr)]

#[marker] trait CheapToClone: Clone {}

impl<T: Copy> CheapToClone for T {}

// These could potentially overlap with the blanket implementation above,
// so are only allowed because CheapToClone is a marker trait.
impl<T: CheapToClone, U: CheapToClone> CheapToClone for (T, U) {}
impl<T: CheapToClone> CheapToClone for std::ops::Range<T> {}

fn cheap_clone<T: CheapToClone>(t: T) -> T {
    t.clone()
}

    انتظار می‌رود این ویژگی جایگزین ویژگی ناپایدار overlapping_marker_traits شود که برای همهٔ صفت‌های خالی اعمال می‌شد (بدون اینکه نیازی به انتخاب صریح باشد).
