کتاب قابلیت‌های ناپایدارThe Unstable Book

    RUSTC_OVERRIDE_VERSION_STRING

    این قابلیت برای همیشه ناپایدار (perma-unstable) است و issue ردیابی ندارد.

    متغیر محیطی RUSTC_OVERRIDE_VERSION_STRING نسخه‌ای را که rustc --version گزارش می‌کند بازنویسی می‌کند. برای مثال:

    $ rustc --version
rustc 1.87.0-nightly (43f0014ef 2025-03-25)
$ env RUSTC_OVERRIDE_VERSION_STRING=1.81.0-nightly rustc --version
rustc 1.81.0-nightly

    توجه کنید که رشتهٔ نسخه به‌طور کامل بازنویسی می‌شود؛ یعنی rustc اطلاعات هش commit و تاریخ commit را حذف می‌کند، مگر این‌که صراحتاً در متغیر محیطی گنجانده شده باشند. این رشته فقط به بخش «release» نسخه اعمال می‌شود؛ برای مثال:

    $ RUSTC_OVERRIDE_VERSION_STRING="1.81.0-nightly (aaaaaaaaa 2025-03-22)" rustc -vV
rustc 1.81.0-nightly (aaaaaaaaa 2025-03-22)
binary: rustc
commit-hash: 43f0014ef0f242418674f49052ed39b70f73bc1c
commit-date: 2025-03-25
host: x86_64-unknown-linux-gnu
release: 1.81.0-nightly (aaaaaaaaa 2025-03-22)
LLVM version: 20.1.1

    توجه کنید که در این‌جا commit-hash و commit-date با مقادیر موجود در رشته مطابقت ندارند، و release شامل هش و تاریخ جعلی است.

    این متغیر بر مجاز بودن یا نبودن استفاده از قابلیت‌های ناپایدار تأثیری ندارد. فقط خروجی --version را تغییر می‌دهد.

    چرا این متغیر محیطی وجود دارد؟

    کتابخانه‌های crate مختلفی تشخیص قابلیت ناقص یا نادرستی دارند. این متغیر محیطی امکان bisect کردن crateهایی را می‌دهد که با version_check::supports_feature تشخیص نادرستی انجام می‌دهند.

    این متغیر برای هیچ مورد دیگری در نظر گرفته نشده است (و جز برای bisect کردن، چندان مفید نیست).

    برای بحث بیشتر، https://github.com/rust-lang/rust/pull/124339 را ببینید.
