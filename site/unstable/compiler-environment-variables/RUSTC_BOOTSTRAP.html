    RUSTC_BOOTSTRAP

    این قابلیت برای همیشه ناپایدار (perma-unstable) است و issue ردیابی ندارد.

    متغیر محیطی RUSTC_BOOTSTRAP به rustc می‌گوید طوری رفتار کند که گویی یک کامپایلر nightly است؛ به‌طور مشخص، حتی در کانال انتشار stable هم اجازهٔ استفاده از attributeهای #![feature(...)] و پرچم‌های -Z را می‌دهد.

    تنظیم RUSTC_BOOTSTRAP=1 به rustc دستور می‌دهد این رفتار را برای همهٔ crateها فعال کند. تنظیم RUSTC_BOOTSTRAP=crate_name به rustc دستور می‌دهد آن را فقط برای crateهایی به نام crate_name اعمال کند. تنظیم RUSTC_BOOTSTRAP=-1 به rustc دستور می‌دهد حتی در کانال انتشار nightly هم مانند یک کامپایلر stable رفتار کند. Cargo اجازه نمی‌دهد cargo::rustc-env=RUSTC_BOOTSTRAP در اسکریپت‌های ساخت تنظیم شود. سیستم‌های ساخت می‌توانند قابلیت‌هایی را که فعال می‌کنند با -Z allow-features=feature1,feature2 محدود کنند. crateها می‌توانند با استفاده از #![forbid(unstable_features)] در ریشهٔ crate (یا هر روش دیگر فعال‌سازی lintها، مانند -F unstable-features) به‌طور کامل از قابلیت‌های ناپایدار صرف‌نظر کنند.

    چرا این متغیر محیطی وجود دارد؟

    RUSTC_BOOTSTRAP، همان‌طور که از نامش پیداست، برای بوت‌استرپ کردن کامپایلر از یک نسخهٔ قدیمی‌تر به کار می‌رود. به‌طور مشخص، nightly با beta ساخته می‌شود و beta با stable. از آن‌جا که کتابخانهٔ استاندارد و کامپایلر هر دو از قابلیت‌های ناپایدار استفاده می‌کنند، RUSTC_BOOTSTRAP لازم است تا بتوانیم از نسخهٔ قبلی برای ساخت آن‌ها استفاده کنیم.

    چرا استفاده از این متغیر محیطی برای افرادی که عضو پروژهٔ Rust نیستند این‌قدر آسان است؟

    در ابتدا RUSTC_BOOTSTRAP لازم داشت که هش نسخهٔ قبلی کامپایلر به آن داده شود، تا از به‌کار بردن آن برای هر هدفی غیر از بوت‌استرپ جلوگیری شود. این محدودیت بعدها برداشته شد؛ برای بحثی که در آن زمان انجام شد، https://github.com/rust-lang/rust/issues/36548 را ببینید.

    افراد در زمان‌های مختلف پیشنهاد کرده‌اند که محدودیت‌های فنی دوباره اضافه شوند. اما انجام این کار برای چند پروژهٔ بزرگ که بسیار مایلیم استفاده از آخرین نسخهٔ toolchain پایدار را برایشان حفظ کنیم، مانند Firefox، Rust for Linux و Chromium، به‌شدت اختلال‌زا است. تا زمانی که جایگزینی پیدا نکنیم که بزرگ‌ترین ذی‌نفعان ما را دچار اختلال نکند، به مجاز بودن RUSTC_BOOTSTRAP ادامه می‌دهیم.

    سیاست پایداری

    با وجود این‌که این قابلیت روی stable قابل استفاده است، یک قابلیت ناپایدار است. مانند هر قابلیت ناپایدار دیگر، ما حق تغییر یا حذف این قابلیت و نیز هر قابلیت ناپایدار دیگری را که فعال می‌کند در آینده برای خود محفوظ می‌داریم. استفاده از این قابلیت شما را از تضمین معمول پایداری و سازگاری رو‌به‌عقب stable خارج می‌کند.

    هرچند ما اقدام فنی‌ای برای جلوگیری از استفاده از آن انجام نمی‌دهیم، به‌شدت از به‌کار بردن این قابلیت منصرف می‌کنیم. اگر ممکن است، به‌جای دور زدن سیاست پایداری پروژهٔ Rust، لطفاً در پایدارسازی قابلیت‌هایی که برایتان مهم‌اند مشارکت کنید.

    برای crateهای کتابخانه‌ای، به‌ویژه از استفاده از این قابلیت منصرف می‌کنیم. crateهایی که به شما وابسته‌اند نمی‌دانند که شما از این قابلیت استفاده می‌کنید، اگر خراب شود چاره‌ای ندارند، و ممکن است در زمینه‌هایی به کار روند که پیش‌بینی آن‌ها دشوار است.

    برای کتابخانه‌هایی که واقعاً از این قابلیت استفاده می‌کنند، لطفاً نسخه‌هایی را که پشتیبانی می‌کنید (شامل یک نسخهٔ حداکثر و نیز حداقل) و سازوکاری برای غیرفعال کردن آن مستند کنید. اگر سازوکاری برای غیرفعال کردن استفاده از RUSTC_BOOTSTRAP ندارید، حذف کامل استفاده از آن را در نظر بگیرید، تا افراد فقط در صورتی بتوانند از کتابخانهٔ شما استفاده کنند که از قبل از toolchain نسخهٔ nightly استفاده می‌کنند. به این ترتیب، انتخاب این‌که از تضمین‌های پایداری Rust صرف‌نظر شود یا نه، بر عهدهٔ کاربر نهایی‌ای می‌ماند که کد خود را می‌سازد.
