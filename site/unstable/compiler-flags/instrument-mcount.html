    instrument-mcount

    در ورودی هر تابع، فراخوانی‌هایی به یک تابع شمارنده درج می‌کند. به‌طور سنتی نام این تابع mcount بود، اما نام دقیق ممکن است بسته به هدف و گزینه‌های استفاده‌شده متفاوت باشد.

    تابع شمارنده یک تابع ویژه است که معمولاً از ABI هدف پیروی نمی‌کند. به‌طور کلی دو آرگومان می‌گیرد: نشانی تابع فراخواننده و نشانی تابع فراخوانی‌شده. در ابتدا برای پروفایل‌گیری (profiling) از برنامه‌ها به کار می‌رفت، اما کاربردهایش گسترش یافته است (برای مثال ftrace در لینوکس).

    گزینه‌های پشتیبانی‌شده:

    • no، n، off: ابزارگذاری را فعال نکن. این گزینه‌ی پیش‌فرض است. این گزینه تولید frame pointer را لازم دارد و فعال می‌کند.
    • yes، y، on: ابزارگذاری تابع‌ها بر پایه‌ی mcount را فعال کن.
    • fentry: ابزارگذاری تابع‌ها بر پایه‌ی fentry را در جایی که پشتیبانی می‌شود فعال کن. قرارداد فراخوانی (calling convention) این روش با mcount فرق دارد، سربار کمتری دارد و به frame pointer نیاز ندارد. نام این تابع شمارنده همیشه __fentry__ است. این گزینه فقط روی هدف‌های x86 و s390x در دسترس است.
    • fentry-nop-record و fentry-record: این گزینه‌ها گزینه‌ی fentry را با ثبت هر محل فراخوانی در بخشی به نام __mcount_loc در فایل شیء خروجی گسترش می‌دهند و در صورت لزوم فراخوانی __fentry__ را با یک nop جایگزین می‌کنند. این گزینه‌ها برای همه‌ی هدف‌ها پیاده‌سازی نشده‌اند. پشتیبانی در ستون «supports fentry recording» جدول زیر مشخص شده است.

    در هدف‌های arm eabi، تابع mcount معمولاً __gnu_mcount_nc نامیده می‌شود، هرچند برخی هدف‌ها ممکن است نام‌های متفاوتی به کار ببرند. پیاده‌سازان تابع شمارنده باید برای آگاهی از ویژگی‌های خاص ABI هر تابع، مستندات مخصوص هدف را مطالعه کنند.

    1. در x86-64، mcount و fentry باید ثبات‌های آرگومان rax، rcx، rdx، rsi، rdi، r8، r9 را حفظ کنند. هنگام استفاده از fentry، ممکن است لازم باشد اشاره‌گر پشته‌ی rsp برای برآوردن الزامات ABI تراز شود.

    پیاده‌سازی تابع‌های شمارنده‌ی سفارشی

    در اصل، این کار پیاده‌سازی تابع fn mcount(caller: *const std::ffi::c_void, callee: *const std::ffi::c_void) است. قرارداد فراخوانی mcount از ABI مخصوص خودش پیروی می‌کند که معمولاً ABI استاندارد هدف نیست، اما با یک قرارداد از پیش موجود اعمال می‌شود.

    یک نمونه‌ی ساده روی x86_64-unknown-linux-gnu چیزی شبیه زیر است. ویژگی #[instrument_fn] را می‌توان برای غیرفعال‌کردن پروفایل‌گیری به کار برد تا نوشتن تابع‌های شمارنده ساده‌تر شود، اما پیاده‌سازان باید هنگام فراخوانی تابع‌های دیگر (یا closureهایی که درون‌خطی نمی‌شوند) بسیار دقت کنند، چون آن‌ها هم ممکن است mcount را فراخوانی کنند.

    نمونه‌ی زیر را می‌توان با -Zinstrument-mcount=yes یا -Zinstrument-mcount=fentry روی هدف x86_64-unknown-linux-gnu کامپایل کرد. لینک‌کردن شیءهایی با کاربردهای مختلف -Zinstrument-mcount هم مجاز است، اما انجام این کار در هدف‌هایی که هر دو را پشتیبانی می‌کنند مستلزم پیاده‌سازی هر دو __fentry__ و mcount است.

    #![feature(instrument_fn)]

fn main() {
    // Ensure all the early startup occurs before attempting to call this trivial, single-threaded
    // counting function.
    unsafe {
        PROFILING_ENABLED = true;
    }
    println!("main() called");
    unsafe {
        PROFILING_ENABLED = false;
    }
}

// This example is not threadsafe.
pub static mut IN_MCOUNT: isize = 0;
pub static mut PROFILING_ENABLED: bool = false;

#[unsafe(no_mangle)]
#[instrument_fn = "off"]
unsafe extern "C" fn __count_fn(caller: u64, callee: u64) {
    unsafe {
        if IN_MCOUNT == 0 && PROFILING_ENABLED {
            IN_MCOUNT += 1;
            {
                println!("mcount: call from 0x{caller:x} to 0x{callee:x}");
            }
            IN_MCOUNT -= 1;
        }
    }
}

// Define a custom mcount function. This may partially or fully override the glibc
// implementation depending on linker options.
#[unsafe(naked)]
#[unsafe(no_mangle)]
#[cfg(all(target_os = "linux", target_arch = "x86_64"))]
unsafe extern "custom" fn mcount() {
    core::arch::naked_asm!(
        // A simplified version based on the glibc x86-64 mcount wrapper.
        // Save register arguments to the stack, and call the mcount above.
        "push rax",
        "push rcx",
        "push rdx",
        "push rsi",
        "push rdi",
        "push r8",
        "push r9",
        "mov rsi, 56[rsp]",
        "mov rdi, 8[rbp]",
        "call __count_fn",
        "pop r9",
        "pop r8",
        "pop rdi",
        "pop rsi",
        "pop rdx",
        "pop rcx",
        "pop rax",
        "ret",
    )
}

// Supply a custom __fentry__ instead of glibc's. This has the same linker
// restrictions as noted with mcount, but does not require a frame pointer.
#[unsafe(naked)]
#[unsafe(no_mangle)]
#[cfg(all(target_os = "linux", target_arch = "x86_64"))]
unsafe extern "custom" fn __fentry__() {
    core::arch::naked_asm!(
        // __fentry__ is called before any other prologue actions, be careful
        // with stack alignment. The stack slots look something like:
        // [...]
        // [caller return address]
        // [callee return address] <- top of stack
        "sub rsp, 8",
        "push rax",
        "push rcx",
        "push rdx",
        "push rsi",
        "push rdi",
        "push r8",
        "push r9",
        "mov rsi, 64[rsp]",
        "mov rdi, 72[rsp]",
        "call __count_fn",
        "pop r9",
        "pop r8",
        "pop rdi",
        "pop rsi",
        "pop rdx",
        "pop rcx",
        "pop rax",
        "add rsp, 8",
        "ret",
    )
}
