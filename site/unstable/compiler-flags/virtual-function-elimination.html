    virtual-function-elimination

    این گزینه مشخص می‌کند LLVM بهینه‌سازی حذف تابع مجازی (Virtual Function Elimination یا VFE) را اجرا کند یا نه. این بهینه‌سازی فقط همراه با LTO در دسترس است، بنابراین این پرچم فقط زمانی قابل استفاده است که -Clto هم داده شده باشد.

    VFE امکان می‌دهد توابعی از vtableها حذف شوند که بقیهٔ کد هرگز به‌صورت پویا آن‌ها را فراخوانی نمی‌کند. بدون این پرچم، LLVM فرضی بسیار محافظه‌کارانه می‌کند: اگر هر تابعی در یک vtable فراخوانی شود، هیچ تابعی که این vtable به آن ارجاع دارد قابل حذف نیست. با این پرچم، اطلاعات بیشتری به LLVM داده می‌شود تا بتواند تشخیص دهد کدام توابع واقعاً فراخوانی می‌شوند و توابع استفاده‌نشده را حذف کند.

    محدودیت‌ها

    در زمان نگارش، این پرچم ممکن است توابع vtable را بیش از حد زودهنگام حذف کند. یک نمونه از این وضعیت در این کد دیده می‌شود:

    trait Foo { fn foo(&self) { println!("foo") } }

impl Foo for usize {}

pub struct FooBox(Box<dyn Foo>);

pub fn make_foo() -> FooBox { FooBox(Box::new(0)) }

#[inline]
pub fn f(a: FooBox) { a.0.foo() }

    در کد بالا صفت Foo خصوصی است، بنابراین فرض می‌شود توابع آن فقط از crate فعلی دیده/فراخوانی می‌شوند و در نتیجه در صورت استفاده‌نشدن می‌توانند بهینه‌سازی و حذف شوند. اما با make_foo می‌توان یک نوع dyn Foo بسته‌بندی‌شده را بیرون از crate فعلی تولید کرد و سپس در f به کار برد. به‌دلیل inline شدن f، آنگاه Foo::foo می‌تواند از یک crate خارجی فراخوانی شود. این وضعیت می‌تواند به کامپایل نادرست (miscompilation) منجر شود.
