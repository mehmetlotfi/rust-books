    on-broken-pipe

    issue ردیابی این قابلیت: #97889

    نکته: رابط کاربری این قابلیت پیش‌تر یک attribute به نام #[unix_sigpipe = "..."] بود.

    نمای کلی

    پرچم کامپایلر -Zon-broken-pipe=... را می‌توان برای مشخص کردن اینکه libstd پیش از فراخوانی fn main() چگونه SIGPIPE را در پلتفرم‌های یونیکس تنظیم کند به کار برد. این پرچم در هدف‌های غیر یونیکس نادیده گرفته می‌شود. پرچم را می‌توان با سه مقدار مختلف به کار برد یا به‌کلی حذف کرد. این پرچم بر SIGPIPE پیش از fn main() و پیش از exec() شدن فرزندان تأثیر می‌گذارد:

    پرچم کامپایلرSIGPIPE پیش از fn main()SIGPIPE پیش از exec() فرزند
    استفاده نشدهSIG_IGNSIG_DFL
    -Zon-broken-pipe=killSIG_DFLدست‌نخورده
    -Zon-broken-pipe=errorSIG_IGNدست‌نخورده
    -Zon-broken-pipe=inheritدست‌نخوردهدست‌نخورده

    وقتی -Zon-broken-pipe استفاده نشود

    اگر -Zon-broken-pipe به کار نرود، libstd همان رفتاری را دارد که از سال ۲۰۱۴ و پیش از Rust 1.0 داشته است. SIGPIPE پیش از fn main() روی SIG_IGN تنظیم می‌شود و در نتیجه خطاهای EPIPE پدید می‌آیند که به std::io::ErrorKind::BrokenPipe تبدیل می‌شوند.

    هنگام ایجاد پردازه‌های فرزند، SIGPIPE پیش از اجرای فراخوانی سیستمی exec() روی SIG_DFL تنظیم می‌شود.

    -Zon-broken-pipe=kill

    کنترل‌کنندهٔ SIGPIPE را پیش از فراخوانی fn main() روی SIG_DFL قرار می‌دهد. نتیجه این است که اگر برنامهٔ شما سعی کند در یک pipe بسته‌شده بنویسد، کشته می‌شود. اگر برنامهٔ شما خروجی متنی تولید می‌کند، معمولاً همین را می‌خواهید.

    هنگام ایجاد پردازه‌های فرزند، SIGPIPE دست نمی‌خورد. این معمولاً به این معناست که پردازه‌های فرزند SIG_DFL را برای SIGPIPE به ارث می‌برند.

    مثال

    fn main() {
    loop {
        println!("hello world");
    }
}
    $ rustc -Zon-broken-pipe=kill main.rs
$ ./main | head -n1
hello world

    -Zon-broken-pipe=error

    کنترل‌کنندهٔ SIGPIPE را پیش از فراخوانی fn main() روی SIG_IGN قرار می‌دهد. نتیجه این است که اگر برنامهٔ شما سعی کند در یک pipe بسته‌شده بنویسد، خطاهای ErrorKind::BrokenPipe رخ می‌دهند. برای مثال اگر سرورهای سوکت، کلاینت‌های سوکت یا همتاهای pipe می‌نویسید، معمولاً همین را می‌خواهید.

    هنگام ایجاد پردازه‌های فرزند، SIGPIPE دست نمی‌خورد. این معمولاً به این معناست که پردازه‌های فرزند SIG_IGN را برای SIGPIPE به ارث می‌برند.

    مثال

    fn main() {
    loop {
        println!("hello world");
    }
}
    $ rustc -Zon-broken-pipe=error main.rs
$ ./main | head -n1
hello world
thread 'main' panicked at library/std/src/io/stdio.rs:1118:9:
failed printing to stdout: Broken pipe (os error 32)
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

    -Zon-broken-pipe=inherit

    SIGPIPE را پیش از ورود به fn main() دست‌نخورده باقی می‌گذارد. مگر آنکه پردازهٔ والد کنترل‌کنندهٔ پیش‌فرض SIGPIPE را از SIG_DFL به چیز دیگری تغییر داده باشد، رفتار این حالت با -Zon-broken-pipe=kill یکسان است.

    هنگام ایجاد پردازه‌های فرزند، SIGPIPE دست نمی‌خورد. این معمولاً به این معناست که پردازه‌های فرزند SIG_DFL را برای SIGPIPE به ارث می‌برند.
