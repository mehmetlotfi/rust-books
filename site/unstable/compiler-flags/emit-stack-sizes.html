    emit-stack-sizes

    مسئله‌ی پیگیری (tracking issue) این قابلیت: #54192

    پرچم rustc با نام -Z emit-stack-sizes باعث می‌شود LLVM فراداده‌ی اندازه‌ی پشته (stack) را تولید کند.

    توجه: این قابلیت LLVM از LLVM 8.0 به بعد فقط از قالب شیء ELF پشتیبانی می‌کند. استفاده از این پرچم با هدف‌هایی که از قالب‌های شیء دیگر استفاده می‌کنند (مثلاً macOS و Windows) باعث نادیده گرفته شدن آن می‌شود.

    این crate را در نظر بگیرید:

    #![crate_type = "lib"]

use std::ptr;

pub fn foo() {
    // this function doesn't use the stack
}

pub fn bar() {
    let xs = [0u32; 2];

    // force LLVM to allocate `xs` on the stack
    unsafe { ptr::read_volatile(&xs.as_ptr()); }
}

    استفاده از پرچم -Z emit-stack-sizes بخش‌های (section) اضافی لینکر را در فایل شیء خروجی تولید می‌کند.

    از LLVM 7.0 به بعد، داده‌ها در بخشی به نام .stack_sizes نوشته می‌شوند و قالب آن «آرایه‌ای از جفت‌های مقدار نماد تابع (به اندازه‌ی اشاره‌گر) و اندازه‌ی پشته (LEB128 بدون علامت)» است.

    مهم است بدانید که لینکرها به‌طور پیش‌فرض این بخش لینکر را دور می‌اندازند. برای حفظ این بخش می‌توانید از یک اسکریپت لینکر مانند نمونه‌ی زیر استفاده کنید.

    /* file: keep-stack-sizes.x */
SECTIONS
{
  /* `INFO` makes the section not allocatable so it won't be loaded into memory */
  .stack_sizes (INFO) :
  {
    KEEP(*(.stack_sizes));
  }
}

    اسکریپت لینکر باید با یک پرچم rustc مانند -C link-arg به لینکر داده شود.

    // file: src/main.rs
use std::ptr;

#[inline(never)]
fn main() {
    let xs = [0u32; 2];

    // force LLVM to allocate `xs` on the stack
    unsafe { ptr::read_volatile(&xs.as_ptr()); }
}

    $ RUSTFLAGS="-Z emit-stack-sizes" cargo build --release

$ size -A target/release/hello | grep stack_sizes || echo section was not found
section was not found

$ RUSTFLAGS="-Z emit-stack-sizes" cargo rustc --release -- \
    -C link-arg=-Wl,-Tkeep-stack-sizes.x \
    -C link-arg=-N

    یادداشت نویسنده: کاملاً مطمئن نیستم چرا در این حالت علاوه بر -Tkeep-stack-sizes.x، وجود -N هم لازم است. برای مثال، هنگام تولید فایل‌های لینک‌شده‌ی ایستا برای معماری ARM Cortex-M به آن نیازی نیست.
