زبان برنامه‌نویسی RustThe Rust Programming Language

    برنامه‌نویسی یک بازی حدس عدد

    بیایید با کار روی یک پروژه عملی، همراه یکدیگر وارد دنیای Rust شویم! این فصل با نشان دادن کاربرد چند مفهوم رایج Rust در یک برنامه واقعی، شما را با آن‌ها آشنا می‌کند. درباره let، match، متدها، تابع‌های وابسته (associated functions)، crateهای خارجی و موارد دیگر خواهید آموخت! در فصل‌های بعدی این ایده‌ها را با جزئیات بیشتری بررسی می‌کنیم. در این فصل فقط مبانی را تمرین می‌کنید.

    ما یک مسئله کلاسیک برنامه‌نویسی برای مبتدیان را پیاده‌سازی می‌کنیم: بازی حدس عدد. روش کار چنین است: برنامه یک عدد صحیح تصادفی بین ۱ تا ۱۰۰ تولید می‌کند. سپس از بازیکن می‌خواهد حدسی وارد کند. پس از وارد شدن حدس، برنامه نشان می‌دهد که حدس بیش از حد کوچک است یا بیش از حد بزرگ. اگر حدس درست باشد، بازی پیام تبریک چاپ می‌کند و خارج می‌شود.

    راه‌اندازی یک پروژه جدید

    برای راه‌اندازی یک پروژه جدید، به پوشه projects که در فصل ۱ ساختید بروید و با استفاده از Cargo یک پروژه جدید به این صورت بسازید:

    $ cargo new guessing_game
$ cd guessing_game

    دستور اول، cargo new، نام پروژه (guessing_game) را به عنوان اولین آرگومان می‌گیرد. دستور دوم به پوشه پروژه جدید می‌رود.

    فایل Cargo.toml تولیدشده را ببینید:

    نام فایل: Cargo.toml

    [package]
name = "guessing_game"
version = "0.1.0"
edition = "2024"

[dependencies]

    همان‌طور که در فصل ۱ دیدید، cargo new یک برنامه «Hello, world!» برای شما تولید می‌کند. فایل src/main.rs را بررسی کنید:

    نام فایل: src/main.rs

    fn main() {
    println!("Hello, world!");
}

    حالا بیایید این برنامه «Hello, world!» را با دستور cargo run در یک مرحله کامپایل و اجرا کنیم:

    $ cargo run
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/guessing_game`
Hello, world!

    دستور run زمانی به کار می‌آید که لازم است روی یک پروژه سریع تکرار کنید، همان‌طور که در این بازی انجام می‌دهیم، یعنی هر تکرار را پیش از رفتن به تکرار بعدی سریع آزمایش کنید.

    فایل src/main.rs را دوباره باز کنید. تمام کد را در این فایل خواهید نوشت.

    پردازش یک حدس

    بخش اول برنامه بازی حدس عدد از کاربر ورودی می‌گیرد، آن ورودی را پردازش می‌کند و بررسی می‌کند که ورودی به شکل مورد انتظار باشد. برای شروع، به بازیکن اجازه می‌دهیم یک حدس وارد کند. کد لیستینگ ۲-۱ را در src/main.rs وارد کنید.

    این کد اطلاعات زیادی دارد، پس آن را خط به خط بررسی می‌کنیم. برای دریافت ورودی کاربر و سپس چاپ نتیجه به عنوان خروجی، باید کتابخانه ورودی/خروجی io را به دامنه بیاوریم. کتابخانه io از کتابخانه استاندارد می‌آید که با نام std شناخته می‌شود:

    use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

    Rust به‌طور پیش‌فرض مجموعه‌ای از آیتم‌ها را که در کتابخانه استاندارد تعریف شده‌اند به دامنه هر برنامه می‌آورد. این مجموعه prelude نامیده می‌شود و می‌توانید همه محتویات آن را در مستندات کتابخانه استاندارد ببینید.

    اگر نوعی که می‌خواهید استفاده کنید در prelude نباشد، باید آن نوع را با یک دستور use به‌صراحت به دامنه بیاورید. استفاده از کتابخانه std::io امکانات مفید زیادی در اختیار شما می‌گذارد، از جمله امکان پذیرفتن ورودی کاربر.

    همان‌طور که در فصل ۱ دیدید، تابع main نقطه ورود به برنامه است:

    use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

    سینتکس fn یک تابع جدید اعلام می‌کند؛ پرانتزها، ()، نشان می‌دهند که پارامتری وجود ندارد؛ و آکولاد باز، {، بدنه تابع را آغاز می‌کند.

    همچنین همان‌طور که در فصل ۱ آموختید، println! ماکرویی است که یک رشته را روی صفحه چاپ می‌کند:

    use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

    این کد یک پیام راهنما چاپ می‌کند که بازی را معرفی می‌کند و از کاربر ورودی می‌خواهد.

    ذخیره مقادیر با متغیرها

    سپس یک متغیر برای ذخیره ورودی کاربر می‌سازیم، به این صورت:

    use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

    حالا برنامه دارد جالب می‌شود! در همین یک خط کوچک اتفاقات زیادی در جریان است. از دستور let برای ساخت متغیر استفاده می‌کنیم. این هم مثال دیگری:

    let apples = 5;

    این خط یک متغیر جدید با نام apples می‌سازد و آن را به مقدار 5 متصل می‌کند. در Rust متغیرها به‌طور پیش‌فرض تغییرناپذیر (immutable) هستند، یعنی وقتی به متغیر مقداری بدهیم، آن مقدار تغییر نخواهد کرد. این مفهوم را در بخش «متغیرها و تغییرپذیری» در فصل ۳ به تفصیل بحث می‌کنیم. برای تغییرپذیر کردن یک متغیر، پیش از نام متغیر mut را اضافه می‌کنیم:

    let apples = 5; // immutable
let mut bananas = 5; // mutable

    نکته: سینتکس // یک توضیح (comment) را آغاز می‌کند که تا انتهای خط ادامه دارد. Rust هر چیزی را که در توضیحات باشد نادیده می‌گیرد. درباره توضیحات در فصل ۳ با جزئیات بیشتری بحث خواهیم کرد.

    با بازگشت به برنامه بازی حدس عدد، اکنون می‌دانید که let mut guess یک متغیر تغییرپذیر به نام guess معرفی می‌کند. علامت مساوی (=) به Rust می‌گوید که می‌خواهیم اکنون چیزی را به متغیر متصل کنیم. در سمت راست علامت مساوی، مقداری قرار دارد که guess به آن متصل می‌شود؛ این مقدار نتیجه فراخوانی String::new است، تابعی که یک نمونه جدید از String برمی‌گرداند. String نوع رشته‌ای است که کتابخانه استاندارد فراهم می‌کند و یک متن قابل رشد با کدگذاری UTF-8 است.

    سینتکس :: در خط ::new نشان می‌دهد که new یک تابع وابسته (associated function) از نوع String است. تابع وابسته تابعی است که روی یک نوع پیاده‌سازی شده است، که در این مورد String است. این تابع new یک رشته جدید و خالی می‌سازد. تابع new را در بسیاری از نوع‌ها خواهید یافت، زیرا نام رایجی برای تابعی است که یک مقدار جدید از نوعی خاص می‌سازد.

    در مجموع، خط let mut guess = String::new(); یک متغیر تغییرپذیر ساخته است که اکنون به یک نمونه جدید و خالی از String متصل است. اوه، چه کار طولانی‌ای!

    دریافت ورودی کاربر

    به یاد بیاورید که قابلیت ورودی/خروجی را از کتابخانه استاندارد با use std::io; در خط اول برنامه وارد کردیم. اکنون تابع stdin از ماژول io را فراخوانی می‌کنیم که به ما اجازه می‌دهد ورودی کاربر را مدیریت کنیم:

    use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

    اگر ماژول io را با use std::io; در ابتدای برنامه وارد نکرده بودیم، باز هم می‌توانستیم با نوشتن این فراخوانی به شکل std::io::stdin از تابع استفاده کنیم. تابع stdin یک نمونه از std::io::Stdin برمی‌گرداند که نوعی است که یک دستگیره (handle) به ورودی استاندارد ترمینال شما را نمایش می‌دهد.

    سپس، خط .read_line(&mut guess) متد read_line را روی دستگیره ورودی استاندارد فراخوانی می‌کند تا از کاربر ورودی بگیرد. همچنین &mut guess را به عنوان آرگومان به read_line می‌دهیم تا به آن بگوییم ورودی کاربر را در کدام رشته ذخیره کند. کار کامل read_line این است که هر چه کاربر در ورودی استاندارد تایپ می‌کند را بگیرد و به یک رشته اضافه کند (بدون بازنویسی محتوای آن)، بنابراین آن رشته را به عنوان آرگومان می‌دهیم. آرگومان رشته‌ای باید تغییرپذیر باشد تا متد بتواند محتوای رشته را تغییر دهد.

    علامت & نشان می‌دهد که این آرگومان یک ارجاع است، که راهی به شما می‌دهد تا چند بخش از کدتان بدون نیاز به کپی کردن چندباره آن داده در حافظه، به یک تکه داده دسترسی داشته باشند. ارجاع‌ها ویژگی پیچیده‌ای هستند و یکی از مزیت‌های اصلی Rust این است که استفاده از ارجاع‌ها چقدر ایمن و آسان است. برای تکمیل این برنامه لازم نیست جزئیات زیادی از آن‌ها بدانید. فعلاً فقط باید بدانید که ارجاع‌ها نیز مانند متغیرها به‌طور پیش‌فرض تغییرناپذیر هستند. از این رو برای تغییرپذیر کردن آن باید &mut guess بنویسید، نه &guess. (فصل ۴ ارجاع‌ها را کامل‌تر توضیح می‌دهد.)

    مدیریت شکست احتمالی با Result

    هنوز روی همین خط کد کار می‌کنیم. اکنون درباره سومین خط متن بحث می‌کنیم، اما توجه کنید که این هنوز بخشی از یک خط منطقی کد است. بخش بعدی این متد است:

    use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

    می‌توانستیم این کد را به این صورت بنویسیم:

    io::stdin().read_line(&mut guess).expect("Failed to read line");

    با این حال، یک خط طولانی خواندنش دشوار است، پس بهتر است آن را تقسیم کنیم. هنگام فراخوانی متد با سینتکس .method_name()، اغلب عاقلانه است که یک خط جدید و فاصله‌های خالی دیگر وارد کنیم تا خطوط طولانی شکسته شوند. حالا بیایید بحث کنیم که این خط چه کاری انجام می‌دهد.

    همان‌طور که پیش‌تر گفته شد، read_line هر چه کاربر وارد می‌کند را در رشته‌ای که به آن می‌دهیم قرار می‌دهد، اما یک مقدار Result هم برمی‌گرداند. Result یک شمارش (enumeration) است که اغلب enum نامیده می‌شود و نوعی است که می‌تواند در یکی از چند حالت ممکن باشد. هر حالت ممکن را یک واریانت (variant) می‌نامیم.

    فصل ۶ شمارش‌ها را با جزئیات بیشتری پوشش می‌دهد. هدف این نوع‌های Result رمزگذاری اطلاعات مدیریت خطا است.

    واریانت‌های Result عبارت‌اند از Ok و Err. واریانت Ok نشان می‌دهد که عملیات موفق بوده است و حاوی مقدار تولیدشده با موفقیت است. واریانت Err یعنی عملیات شکست خورده است و حاوی اطلاعاتی درباره چگونگی یا چرایی شکست است.

    مقادیر نوع Result، مانند مقادیر هر نوع دیگر، متدهایی دارند که روی آن‌ها تعریف شده است. یک نمونه از Result یک متد expect دارد که می‌توانید آن را فراخوانی کنید. اگر این نمونه Result یک مقدار Err باشد، expect باعث می‌شود برنامه از کار بیفتد و پیامی را که به عنوان آرگومان به expect داده‌اید نمایش دهد. اگر متد read_line یک Err برگرداند، احتمالاً نتیجه خطایی است که از سیستم‌عامل زیربنایی می‌آید. اگر این نمونه Result یک مقدار Ok باشد، expect مقدار بازگشتی‌ای را که Ok نگه داشته است می‌گیرد و فقط همان مقدار را به شما برمی‌گرداند تا بتوانید از آن استفاده کنید. در این مورد، آن مقدار تعداد بایت‌های ورودی کاربر است.

    اگر expect را فراخوانی نکنید، برنامه کامپایل می‌شود، اما یک هشدار دریافت خواهید کرد:

    $ cargo build

  --> src/main.rs:10:5
   |

   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   |

   = note: `#[warn(unused_must_use)]` (part of `#[warn(unused)]`) on by default

    Rust هشدار می‌دهد که از مقدار Result که read_line برگردانده است استفاده نکرده‌اید، که نشان می‌دهد برنامه یک خطای احتمالی را مدیریت نکرده است.

    راه درست خاموش کردن هشدار این است که واقعاً کد مدیریت خطا بنویسید، اما در مورد ما فقط می‌خواهیم هنگام بروز مشکل این برنامه از کار بیفتد، پس می‌توانیم از expect استفاده کنیم. درباره بازیابی از خطاها در فصل ۹ خواهید آموخت.

    چاپ مقادیر با جانگهدارهای println!

    جدا از آکولاد بسته، تنها یک خط دیگر در کدی که تا اینجا نوشته‌ایم باقی مانده است که باید درباره‌اش بحث کنیم:

    use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

    این خط رشته‌ای را که اکنون حاوی ورودی کاربر است چاپ می‌کند. مجموعه آکولادهای {} یک جانگهدار (placeholder) است: {} را مانند انبرک‌های کوچک خرچنگ تصور کنید که یک مقدار را در جای خود نگه می‌دارند. هنگام چاپ مقدار یک متغیر، نام متغیر می‌تواند درون آکولادها قرار بگیرد. هنگام چاپ نتیجه ارزیابی یک عبارت، آکولادهای خالی را در رشته قالب قرار دهید، سپس پس از رشته قالب فهرستی از عبارت‌ها را که با ویرگول جدا شده‌اند بیاورید تا به همان ترتیب در هر جانگهدار آکولاد خالی چاپ شوند. چاپ یک متغیر و نتیجه یک عبارت در یک فراخوانی println! به این شکل خواهد بود:

    let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);

    این کد x = 5 and y + 2 = 12 را چاپ می‌کند.

    در این مرحله بخش اول بازی تمام شده است: از صفحه‌کلید ورودی می‌گیریم و سپس آن را چاپ می‌کنیم.

    تولید یک عدد مخفی

    سپس باید یک عدد مخفی تولید کنیم که کاربر سعی کند آن را حدس بزند. عدد مخفی باید هر بار متفاوت باشد تا بازی بیش از یک بار هم سرگرم‌کننده باشد. از یک عدد تصادفی بین ۱ و ۱۰۰ استفاده می‌کنیم تا بازی خیلی دشوار نباشد. Rust هنوز قابلیت تولید عدد تصادفی را در کتابخانه استاندارد خود ندارد. با این حال، تیم Rust یک crate با نام rand با این قابلیت ارائه می‌دهد.

    افزایش قابلیت‌ها با یک crate

    به یاد داشته باشید که crate مجموعه‌ای از فایل‌های کد منبع Rust است. پروژه‌ای که تا اینجا ساخته‌ایم یک crate باینری است، یعنی یک فایل اجرایی. crate با نام rand یک crate کتابخانه‌ای است که حاوی کدی است که قرار است در برنامه‌های دیگر استفاده شود و به‌تنهایی قابل اجرا نیست.

    هماهنگی Cargo در مدیریت crateهای خارجی جایی است که Cargo واقعاً می‌درخشد. پیش از اینکه بتوانیم کدی بنویسیم که از rand استفاده کند، باید فایل Cargo.toml را تغییر دهیم تا crate با نام rand را به عنوان وابستگی شامل کند. اکنون آن فایل را باز کنید و خط زیر را به انتهای آن، زیر سرفصل بخش [dependencies] که Cargo برای شما ساخته است، اضافه کنید. حتماً rand را دقیقاً همان‌طور که اینجا آمده است و با همین شماره نسخه مشخص کنید، وگرنه ممکن است مثال‌های کد این آموزش کار نکنند:

    نام فایل: Cargo.toml

    [dependencies]
rand = "0.10.1"

    در فایل Cargo.toml، هر چیزی که پس از یک سرفصل می‌آید بخشی از آن قسمت است که تا شروع قسمت دیگر ادامه دارد. در [dependencies] به Cargo می‌گویید پروژه شما به کدام crateهای خارجی وابسته است و به کدام نسخه‌های آن crateها نیاز دارید. در این مورد، crate با نام rand را با مشخصه نسخه معنایی 0.10.1 تعیین می‌کنیم. Cargo نسخه‌گذاری معنایی (Semantic Versioning، که گاهی SemVer نامیده می‌شود) را می‌فهمد که استانداردی برای نوشتن شماره نسخه‌هاست. مشخصه 0.10.1 در واقع کوتاه‌نویسی برای ^0.10.1 است، که یعنی هر نسخه‌ای که دست‌کم 0.10.1 باشد اما کمتر از 0.11.0 باشد.

    Cargo این نسخه‌ها را دارای API عمومی سازگار با نسخه 0.10.1 می‌داند، و این مشخصه تضمین می‌کند که آخرین نسخه وصله (patch) را دریافت می‌کنید که همچنان با کد این فصل کامپایل شود. هر نسخه 0.11.0 یا بالاتر تضمین نمی‌شود API یکسانی با آنچه مثال‌های بعدی استفاده می‌کنند داشته باشد.

    حالا، بدون تغییر دادن هیچ بخشی از کد، بیایید پروژه را ساخت (build) کنیم، همان‌طور که در لیستینگ ۲-۲ نشان داده شده است.

    ممکن است شماره نسخه‌های متفاوتی ببینید (اما به لطف SemVer همه آن‌ها با کد سازگار خواهند بود!) و خطوط متفاوتی هم ببینید (بسته به سیستم‌عامل)، و ممکن است خطوط به ترتیب دیگری باشند.

    وقتی یک وابستگی خارجی اضافه می‌کنیم، Cargo آخرین نسخهٔ هر چیزی را که آن وابستگی نیاز دارد از رجیستری (registry) دریافت می‌کند؛ رجیستری رونوشتی از داده‌های Crates.io است. Crates.io جایی است که افراد در اکوسیستم Rust پروژه‌های متن‌بازِ Rust خود را برای استفادهٔ دیگران منتشر می‌کنند.

    پس از به‌روزرسانی رجیستری، Cargo بخش [dependencies] را بررسی می‌کند و هر crateای را که فهرست شده و هنوز دانلود نشده است دانلود می‌کند. در این مورد، اگرچه ما فقط rand را به عنوان وابستگی فهرست کرده‌ایم، Cargo crateهای دیگری را نیز که rand برای کار کردن به آن‌ها وابسته است برداشت. پس از دانلود crateها، Rust آن‌ها را کامپایل می‌کند و سپس پروژه را با وابستگی‌های در دسترس کامپایل می‌کند.

    اگر بدون هیچ تغییری بلافاصله دوباره cargo build را اجرا کنید، به جز خط Finished خروجی دیگری نخواهید گرفت. Cargo می‌داند که وابستگی‌ها را پیش‌تر دانلود و کامپایل کرده است و شما هم در فایل Cargo.toml چیزی درباره آن‌ها تغییر نداده‌اید. Cargo همچنین می‌داند که چیزی در کد شما تغییر نکرده است، بنابراین آن را هم دوباره کامپایل نمی‌کند. چون کاری برای انجام دادن نیست، به سادگی خارج می‌شود.

    اگر فایل src/main.rs را باز کنید، یک تغییر ناچیز در آن بدهید، سپس ذخیره کنید و دوباره ساخت را اجرا کنید، فقط دو خط خروجی خواهید دید:

    $ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s

    این خطوط نشان می‌دهند که Cargo ساخت را فقط با تغییر کوچک شما در فایل src/main.rs به‌روز می‌کند. وابستگی‌های شما تغییر نکرده‌اند، پس Cargo می‌داند که می‌تواند از آنچه را که پیش‌تر برای آن‌ها دانلود و کامپایل کرده است دوباره استفاده کند.

    اطمینان از ساخت‌های قابل بازتولید

    Cargo سازوکاری دارد که تضمین می‌کند هر بار که شما یا هر کس دیگری کد شما را می‌سازد، می‌توانید همان مصنوع (artifact) را دوباره بسازید: Cargo فقط از نسخه‌هایی از وابستگی‌ها استفاده می‌کند که شما مشخص کرده‌اید، مگر اینکه خلاف آن را اعلام کنید. برای مثال، فرض کنید هفته آینده نسخه 0.10.2 از crate با نام rand منتشر شود و آن نسخه یک رفع اشکال مهم داشته باشد، اما یک پسرفت (regression) هم داشته باشد که کد شما را خراب می‌کند. برای مدیریت این وضعیت، Rust فایل Cargo.lock را اولین باری که cargo build را اجرا می‌کنید می‌سازد، پس اکنون این فایل را در پوشه guessing_game داریم.

    وقتی پروژه‌ای را برای اولین بار می‌سازید، Cargo همه نسخه‌های وابستگی‌ها را که با معیارها سازگارند مشخص می‌کند و سپس آن‌ها را در فایل Cargo.lock می‌نویسد. وقتی در آینده پروژه‌تان را می‌سازید، Cargo می‌بیند که فایل Cargo.lock وجود دارد و به جای انجام دوباره همه کار تعیین نسخه‌ها، از نسخه‌های مشخص‌شده در آن استفاده می‌کند. این کار به‌طور خودکار یک ساخت قابل بازتولید به شما می‌دهد. به عبارت دیگر، به لطف فایل Cargo.lock، پروژه شما تا زمانی که به‌صراحت ارتقا ندهید در نسخه 0.10.1 باقی می‌ماند. چون فایل Cargo.lock برای ساخت‌های قابل بازتولید مهم است، اغلب همراه با بقیه کد پروژه شما در سیستم کنترل نسخه ثبت می‌شود.

    به‌روزرسانی یک crate برای دریافت نسخه جدید

    وقتی می‌خواهید یک crate را به‌روز کنید، Cargo دستور update را فراهم می‌کند که فایل Cargo.lock را نادیده می‌گیرد و همه آخرین نسخه‌هایی را که با مشخصات شما در Cargo.toml جور هستند پیدا می‌کند. سپس Cargo آن نسخه‌ها را در فایل Cargo.lock می‌نویسد. در غیر این صورت، به‌طور پیش‌فرض Cargo فقط نسخه‌های بزرگ‌تر از 0.10.1 و کوچک‌تر از 0.11.0 را جست‌وجو می‌کند. اگر crate با نام rand دو نسخه جدید 0.10.2 و 0.999.0 را منتشر کرده باشد و cargo update را اجرا کنید، موارد زیر را خواهید دید:

    $ cargo update
    Updating crates.io index
     Locking 1 package to latest Rust 1.96.0 compatible version
    Updating rand v0.10.1 -> v0.10.2 (available: v0.999.0)

    Cargo نسخه 0.999.0 را نادیده می‌گیرد. در این مرحله، تغییری هم در فایل Cargo.lock خود خواهید دید که نشان می‌دهد نسخه crate با نام rand که اکنون استفاده می‌کنید 0.10.2 است. برای استفاده از rand نسخه 0.999.0 یا هر نسخه‌ای در سری 0.999.x، باید فایل Cargo.toml را به جای آن به شکل زیر تغییر دهید (در واقع این تغییر را اعمال نکنید، زیرا مثال‌های بعدی فرض می‌کنند از rand نسخه 0.10 استفاده می‌کنید):

    [dependencies]
rand = "0.999.0"

    دفعه بعد که cargo build را اجرا کنید، Cargo رجیستری crateهای موجود را به‌روز می‌کند و نیازمندی‌های rand شما را بر اساس نسخه جدیدی که مشخص کرده‌اید دوباره ارزیابی می‌کند.

    درباره Cargo و اکوسیستم آن چیزهای بسیار بیشتری برای گفتن هست که در فصل ۱۴ بحث می‌کنیم، اما فعلاً این همان چیزی است که باید بدانید. Cargo استفاده مجدد از کتابخانه‌ها را بسیار آسان می‌کند، بنابراین Rustaceanها می‌توانند پروژه‌های کوچک‌تری بنویسند که از تعدادی بسته (package) مونتاژ شده‌اند.

    تولید یک عدد تصادفی

    بیایید شروع کنیم به استفاده از rand برای تولید عددی که باید حدس زده شود. گام بعدی به‌روزرسانی src/main.rs است، همان‌طور که در لیستینگ ۲-۳ نشان داده شده است.

    ابتدا خط use rand::prelude::*; را اضافه می‌کنیم. ماژول prelude پرکاربردترین بخش‌های crate با نام rand را در بر دارد و use آن آیتم‌ها را در دامنه برنامه ما در دسترس قرار می‌دهد.

    سپس دو خط را در میانه اضافه می‌کنیم. در خط اول، تابع rand::rng را فراخوانی می‌کنیم که مولد عدد تصادفی خاصی را که می‌خواهیم استفاده کنیم به ما می‌دهد: مولدی که محلی برای نخ اجرای فعلی است و توسط سیستم‌عامل مقداردهی اولیه (seed) می‌شود. سپس متد random_range را روی مولد عدد تصادفی فراخوانی می‌کنیم. این متد توسط صفت RngExt تعریف شده است که بخشی از ماژول rand::prelude است که با دستور use rand::prelude::*; به دامنه آورده‌ایم. متد random_range یک عبارت بازه را به عنوان آرگومان می‌گیرد و یک عدد تصادفی در آن بازه تولید می‌کند. نوع عبارت بازه‌ای که اینجا استفاده می‌کنیم به شکل start..=end است و کران‌های پایین و بالا را شامل می‌شود، بنابراین برای درخواست عددی بین ۱ و ۱۰۰ باید 1..=100 را مشخص کنیم.

    نکته: خودتان به‌طور شهودی نمی‌دانید که از یک crate چه چیزی را باید به دامنه بیاورید و کدام متدها و تابع‌ها را باید فراخوانی کنید، پس هر crate مستنداتی با دستورالعمل استفاده از آن دارد. ویژگی جالب دیگر Cargo این است که اجرای دستور cargo doc --open مستنداتی را که همه وابستگی‌های شما فراهم کرده‌اند به‌صورت محلی می‌سازد و در مرورگر شما باز می‌کند. برای مثال، اگر به قابلیت‌های دیگر crate با نام rand علاقه‌مند هستید، cargo doc --open را اجرا کنید و در نوار کناری سمت چپ روی rand کلیک کنید.

    خط جدید دوم عدد مخفی را چاپ می‌کند. این کار در حین توسعه برنامه برای اینکه بتوانیم آن را آزمایش کنیم مفید است، اما آن را از نسخه نهایی حذف می‌کنیم. اگر برنامه به محض شروع پاسخ را چاپ کند، چندان بازی به حساب نمی‌آید!

    مقایسهٔ حدس با عدد مخفی

    اکنون که ورودی کاربر و یک عدد تصادفی داریم، می‌توانیم آن‌ها را مقایسه کنیم. این گام در لیستینگ ۲-۴ نشان داده شده است. توجه کنید که این کد هنوز کامپایل نمی‌شود، همان‌طور که توضیح خواهیم داد.

    ابتدا یک دستور use دیگر اضافه می‌کنیم که نوعی به نام std::cmp::Ordering را از کتابخانه استاندارد به دامنه می‌آورد. نوع Ordering یک enum دیگر است و واریانت‌های Less، Greater و Equal را دارد. این‌ها سه نتیجه ممکن هنگام مقایسه دو مقدار هستند.

    سپس پنج خط جدید در پایین اضافه می‌کنیم که از نوع Ordering استفاده می‌کنند. متد cmp دو مقدار را مقایسه می‌کند و می‌تواند روی هر چیزی که قابل مقایسه باشد فراخوانی شود. این متد یک ارجاع به هر چیزی که می‌خواهید با آن مقایسه کنید می‌گیرد: اینجا guess را با secret_number مقایسه می‌کند. سپس یکی از واریانت‌های شمارش Ordering را که با دستور use به دامنه آوردیم برمی‌گرداند. ما از عبارت match استفاده می‌کنیم تا بر اساس اینکه کدام واریانت Ordering از فراخوانی cmp با مقادیر guess و secret_number برگردانده شده است، تصمیم بگیریم بعد چه کاری انجام دهیم.

    عبارت match از بازوها (arms) ساخته شده است. هر بازو شامل یک الگو (pattern) برای تطبیق و کدی است که اگر مقدار داده‌شده به match با الگوی آن بازو جور باشد باید اجرا شود. Rust مقدار داده‌شده به match را می‌گیرد و الگوی هر بازو را به ترتیب بررسی می‌کند. الگوها و ساختار match ویژگی‌های قدرتمند Rust هستند: به شما اجازه می‌دهند موقعیت‌های متنوعی را که کدتان ممکن است با آن‌ها روبه‌رو شود بیان کنید و مطمئن می‌شوند که همه آن‌ها را مدیریت کرده‌اید. این ویژگی‌ها به ترتیب در فصل ۶ و فصل ۱۹ با جزئیات پوشش داده خواهند شد.

    بیایید مثالی را با عبارت match که اینجا استفاده می‌کنیم مرور کنیم. فرض کنید کاربر ۵۰ را حدس زده است و عدد مخفی تصادفی که این بار تولید شده ۳۸ است.

    وقتی کد ۵۰ را با ۳۸ مقایسه می‌کند، متد cmp مقدار Ordering::Greater را برمی‌گرداند، زیرا ۵۰ از ۳۸ بزرگ‌تر است. عبارت match مقدار Ordering::Greater را می‌گیرد و شروع به بررسی الگوی هر بازو می‌کند. به الگوی بازوی اول، یعنی Ordering::Less، نگاه می‌کند و می‌بیند که مقدار Ordering::Greater با Ordering::Less جور نیست، پس کد آن بازو را نادیده می‌گیرد و به بازوی بعدی می‌رود. الگوی بازوی بعدی Ordering::Greater است که با Ordering::Greater جور است! کد وابسته در آن بازو اجرا می‌شود و Too big! را روی صفحه چاپ می‌کند. عبارت match پس از اولین تطبیق موفق پایان می‌یابد، پس در این سناریو به بازوی آخر نگاه نمی‌کند.

    هسته خطا بیان می‌کند که نوع‌ها ناسازگارند (mismatched types). Rust یک سیستم نوع ایستای قوی دارد. با این حال، استنتاج نوع هم دارد. وقتی نوشتیم let mut guess = String::new()، Rust توانست استنتاج کند که guess باید یک String باشد و ما را مجبور به نوشتن نوع نکرد. در مقابل، secret_number یک نوع عددی است. چند نوع عددی Rust می‌توانند مقداری بین ۱ تا ۱۰۰ داشته باشند: i32، یک عدد ۳۲ بیتی؛ u32، یک عدد ۳۲ بیتی بدون علامت؛ i64، یک عدد ۶۴ بیتی؛ و دیگر انواع. مگر اینکه خلاف آن مشخص شود، Rust به‌طور پیش‌فرض i32 را انتخاب می‌کند که نوع secret_number است، مگر اینکه در جای دیگری اطلاعات نوعی اضافه کنید که باعث شود Rust نوع عددی متفاوتی را استنتاج کند. دلیل خطا این است که Rust نمی‌تواند یک رشته و یک نوع عددی را با هم مقایسه کند.

    در نهایت، می‌خواهیم String ای را که برنامه به عنوان ورودی می‌خواند به یک نوع عددی تبدیل کنیم تا بتوانیم آن را به‌صورت عددی با عدد مخفی مقایسه کنیم. این کار را با افزودن این خط به بدنه تابع main انجام می‌دهیم:

    نام فایل: src/main.rs

    use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    println!("Please input your guess.");

    // --snip--

        .expect("Failed to read line");

        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),

    آن خط این است:

    let guess: u32 = guess.trim().parse().expect("Please type a number!");

    یک متغیر با نام guess می‌سازیم. اما صبر کنید، مگر برنامه از پیش متغیری به نام guess ندارد؟ دارد، اما Rust مفید است و به ما اجازه می‌دهد مقدار قبلی guess را با یک مقدار جدید سایه (shadow) کنیم. سایه‌زنی (shadowing) به ما اجازه می‌دهد نام متغیر guess را دوباره استفاده کنیم، به جای اینکه مجبور شویم دو متغیر یکتا مثلاً guess_str و guess بسازیم. این را در فصل ۳ با جزئیات بیشتری پوشش می‌دهیم، اما فعلاً بدانید که این ویژگی اغلب زمانی استفاده می‌شود که می‌خواهید مقداری را از یک نوع به نوع دیگر تبدیل کنید.

    این متغیر جدید را به عبارت guess.trim().parse() متصل می‌کنیم. guess در این عبارت به متغیر اصلی guess اشاره می‌کند که ورودی را به صورت رشته در خود داشت. متد trim روی یک نمونه String هر فضای خالی را در ابتدا و انتها حذف می‌کند، که باید پیش از تبدیل رشته به u32 انجام دهیم، چون u32 فقط می‌تواند داده عددی داشته باشد. کاربر باید enter را بزند تا read_line ارضا شود و حدسش را وارد کند، که یک نویسه خط جدید به رشته اضافه می‌کند. برای مثال، اگر کاربر 5 را تایپ کند و enter را بزند، guess به این شکل است: 5\n. نماد \n «خط جدید» (newline) را نشان می‌دهد. (در ویندوز، زدن enter به یک carriage return و یک خط جدید، یعنی \r\n، می‌انجامد.) متد trim مقدار \n یا \r\n را حذف می‌کند و فقط 5 باقی می‌ماند.

    متد parse روی رشته‌ها یک رشته را به نوع دیگری تبدیل می‌کند. اینجا از آن برای تبدیل رشته به عدد استفاده می‌کنیم. باید با استفاده از let guess: u32 به Rust بگوییم دقیقاً چه نوع عددی می‌خواهیم. دو نقطه (:) بعد از guess به Rust می‌گوید که نوع متغیر را مشخص (annotate) خواهیم کرد. Rust چند نوع عددی داخلی دارد؛ u32 که اینجا دیده می‌شود یک عدد صحیح ۳۲ بیتی بدون علامت است. انتخاب پیش‌فرض خوبی برای یک عدد مثبت کوچک است. درباره نوع‌های عددی دیگر در فصل ۳ خواهید آموخت.

    علاوه بر این، حاشیه‌نویسی u32 در این برنامه نمونه و مقایسه با secret_number یعنی Rust استنتاج می‌کند که secret_number هم باید u32 باشد. بنابراین اکنون مقایسه بین دو مقدار از یک نوع خواهد بود!

    متد parse فقط روی نویسه‌هایی کار می‌کند که منطقاً بتوانند به عدد تبدیل شوند و بنابراین به‌آسانی می‌تواند باعث بروز خطا شود. برای مثال، اگر رشته حاوی A👍% بود، هیچ راهی برای تبدیل آن به عدد نبود. چون ممکن است شکست بخورد، متد parse یک نوع Result برمی‌گرداند، دقیقاً مانند متد read_line (که پیش‌تر در «مدیریت شکست احتمالی با Result» بحث شد). با این Result هم به همان شیوه رفتار می‌کنیم و دوباره از متد expect استفاده می‌کنیم. اگر parse به این دلیل که نتوانسته از رشته عددی بسازد واریانت Err از Result را برگرداند، فراخوانی expect بازی را از کار می‌اندازد و پیامی را که به آن داده‌ایم چاپ می‌کند. اگر parse بتواند با موفقیت رشته را به عدد تبدیل کند، واریانت Ok از Result را برمی‌گرداند و expect عددی را که می‌خواهیم از مقدار Ok برمی‌گرداند.

    مدیریت ورودی نامعتبر

    برای اصلاح بیشتر رفتار بازی، به جای از کار انداختن برنامه هنگامی که کاربر ورودی غیرعددی وارد می‌کند، بیایید بازی را طوری کنیم که ورودی غیرعددی را نادیده بگیرد تا کاربر بتواند به حدس زدن ادامه دهد. می‌توانیم این کار را با تغییر خطی که guess را از String به u32 تبدیل می‌کند انجام دهیم، همان‌طور که در لیستینگ ۲-۵ نشان داده شده است.

    از فراخوانی expect به یک عبارت match روی می‌آوریم تا از از کار افتادن در برابر خطا به مدیریت خطا برسیم. به یاد داشته باشید که parse یک نوع Result برمی‌گرداند و Result یک enum است که واریانت‌های Ok و Err را دارد. ما اینجا از عبارت match استفاده می‌کنیم، همان‌طور که با نتیجه Ordering متد cmp انجام دادیم.

    اگر parse بتواند با موفقیت رشته را به عدد تبدیل کند، یک مقدار Ok برمی‌گرداند که حاوی عدد حاصل است. آن مقدار Ok با الگوی بازوی اول جور می‌شود و عبارت match فقط مقدار num را که parse تولید کرده و درون مقدار Ok گذاشته است برمی‌گرداند. آن عدد دقیقاً همان جایی که می‌خواهیم، در متغیر جدید guess که می‌سازیم، قرار می‌گیرد.

    اگر parse نتواند رشته را به عدد تبدیل کند، یک مقدار Err برمی‌گرداند که حاوی اطلاعات بیشتری درباره خطاست. مقدار Err با الگوی Ok(num) در بازوی اول match جور نمی‌شود، اما با الگوی Err(_) در بازوی دوم جور می‌شود. زیرخط، _، یک مقدار فراگیر (catch-all) است؛ در این مثال می‌گوییم می‌خواهیم با همه مقادیر Err تطبیق دهیم، مهم نیست چه اطلاعاتی درون آن‌ها باشد. پس برنامه کد بازوی دوم، یعنی continue، را اجرا می‌کند که به برنامه می‌گوید به تکرار بعدی loop برود و حدس دیگری بخواهد. بنابراین عملاً برنامه همه خطاهایی را که parse ممکن است با آن‌ها مواجه شود نادیده می‌گیرد!

    خلاصه

    این پروژه روشی عملی بود برای آشنا کردن شما با بسیاری از مفاهیم جدید Rust: let، match، تابع‌ها، استفاده از crateهای خارجی و موارد دیگر. در چند فصل بعدی درباره این مفاهیم با جزئیات بیشتری خواهید آموخت. فصل ۳ مفاهیمی را که بیشتر زبان‌های برنامه‌نویسی دارند، مانند متغیرها، نوع‌های داده و تابع‌ها، پوشش می‌دهد و نشان می‌دهد چگونه در Rust از آن‌ها استفاده کنیم. فصل ۴ مالکیت را بررسی می‌کند، ویژگی‌ای که Rust را از زبان‌های دیگر متمایز می‌کند. فصل ۵ ساختارها و سینتکس متد را بحث می‌کند و فصل ۶ توضیح می‌دهد شمارش‌ها چگونه کار می‌کنند.
