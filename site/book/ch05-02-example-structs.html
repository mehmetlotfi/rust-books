زبان برنامه‌نویسی RustThe Rust Programming Language

    یک برنامه نمونه با استفاده از ساختارها

    برای اینکه بفهمیم چه زمانی ممکن است بخواهیم از ساختارها استفاده کنیم، برنامه‌ای می‌نویسیم که مساحت یک مستطیل را محاسبه می‌کند. کار را با استفاده از متغیرهای جداگانه شروع می‌کنیم و سپس برنامه را بازآرایی (refactor) می‌کنیم تا در نهایت به‌جای آن‌ها از ساختارها استفاده کنیم.

    بیایید با Cargo یک پروژه باینری جدید به نام rectangles بسازیم که عرض و ارتفاع یک مستطیل را بر حسب پیکسل دریافت کند و مساحت آن را محاسبه کند. لیست ۵-۸ برنامه‌ای کوتاه را نشان می‌دهد که دقیقاً همین کار را به یک روش در فایل src/main.rs پروژه ما انجام می‌دهد.

    حالا این برنامه را با cargo run اجرا کنید:

    $ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.42s
     Running `target/debug/rectangles`
The area of the rectangle is 1500 square pixels.

    این کد با فراخوانی تابع area برای هر یک از ابعاد، با موفقیت مساحت مستطیل را به دست می‌آورد، اما می‌توانیم کارهای بیشتری انجام دهیم تا این کد واضح‌تر و خواناتر شود.

    مشکل این کد در امضای تابع area آشکار است:

    fn main() {
    let width1 = 30;
    let height1 = 50;

    println!(
        "The area of the rectangle is {} square pixels.",
        area(width1, height1)
    );
}

fn area(width: u32, height: u32) -> u32 {
    width * height
}

    تابع area قرار است مساحت یک مستطیل را محاسبه کند، اما تابعی که نوشتیم دو پارامتر دارد و در هیچ جای برنامه‌ی ما روشن نیست که این پارامترها به هم مرتبط هستند. گروه‌بندی عرض و ارتفاع در کنار یکدیگر، هم خواناتر و هم قابل‌مدیریت‌تر خواهد بود. پیش‌تر در بخش «نوع تاپل» از فصل ۳ یک راه برای انجام این کار را بررسی کردیم: استفاده از تاپل‌ها.

    بازآرایی با تاپل‌ها

    لیست ۵-۹ نسخه‌ی دیگری از برنامه‌ی ما را نشان می‌دهد که از تاپل‌ها استفاده می‌کند.

    از یک جهت، این برنامه بهتر است. تاپل‌ها به ما اجازه می‌دهند کمی ساختار اضافه کنیم و اکنون فقط یک آرگومان ارسال می‌کنیم. اما از جهت دیگر، این نسخه واضح‌تر نیست: تاپل‌ها برای عناصر خود نام تعیین نمی‌کنند، بنابراین باید با اندیس به بخش‌های تاپل دسترسی پیدا کنیم و همین باعث می‌شود محاسبه‌ی ما کمتر آشکار باشد.

    جابه‌جا کردن عرض و ارتفاع برای محاسبه‌ی مساحت اهمیتی ندارد، اما اگر بخواهیم مستطیل را روی صفحه رسم کنیم، اهمیت پیدا می‌کند! باید به خاطر داشته باشیم که width همان اندیس 0 تاپل و height همان اندیس 1 است. اگر شخص دیگری از کد ما استفاده کند، فهمیدن و به خاطر سپردن این موضوع برای او حتی دشوارتر خواهد بود. چون معنای داده‌هایمان را در کد منتقل نکرده‌ایم، اکنون ایجاد خطا آسان‌تر است.

    بازآرایی با ساختارها

    ما از ساختارها استفاده می‌کنیم تا با برچسب‌گذاری داده‌ها به آن‌ها معنا ببخشیم. می‌توانیم تاپلی را که استفاده می‌کنیم به یک ساختار تبدیل کنیم که هم برای کل مجموعه نامی دارد و هم برای اجزای آن، همان‌طور که در لیست ۵-۱۰ نشان داده شده است.

    در اینجا یک ساختار تعریف کرده و نام آن را Rectangle گذاشته‌ایم. داخل آکولادها، فیلدها را با نام‌های width و height تعریف کرده‌ایم که هر دو از نوع u32 هستند. سپس در main یک نمونه‌ی مشخص از Rectangle ساخته‌ایم که عرض آن 30 و ارتفاع آن 50 است.

    تابع area ما اکنون با یک پارامتر تعریف شده است که نام آن را rectangle گذاشته‌ایم و نوع آن یک قرض‌گیری تغییرناپذیر از یک نمونه‌ی ساختار Rectangle است. همان‌طور که در فصل ۴ گفته شد، می‌خواهیم به‌جای گرفتن مالکیت ساختار، آن را قرض بگیریم. به این ترتیب main مالکیت خود را حفظ می‌کند و می‌تواند به استفاده از rect1 ادامه دهد؛ و به همین دلیل است که از & هم در امضای تابع و هم در محل فراخوانی آن استفاده می‌کنیم.

    تابع area به فیلدهای width و height نمونه‌ی Rectangle دسترسی پیدا می‌کند (توجه کنید که دسترسی به فیلدهای یک نمونه‌ی قرض‌گرفته‌شده‌ی ساختار، مقادیر فیلدها را move نمی‌کند، و به همین دلیل است که اغلب قرض‌گیری از ساختارها را می‌بینید). امضای تابع area ما اکنون دقیقاً همان چیزی را می‌گوید که منظورمان است: مساحت Rectangle را با استفاده از فیلدهای width و height آن محاسبه کن. این امضا نشان می‌دهد که عرض و ارتفاع به هم مرتبط هستند و به‌جای استفاده از اندیس‌های 0 و 1 تاپل، نام‌هایی توصیفی به مقادیر می‌دهد. این یک پیروزی برای وضوح است.

    افزودن قابلیت با صفت‌های مشتق‌شده

    مفید است که هنگام اشکال‌زدایی برنامه بتوانیم یک نمونه از Rectangle را چاپ کنیم و مقادیر همه‌ی فیلدهای آن را ببینیم. لیست ۵-۱۱ تلاش می‌کند همان‌طور که در فصل‌های قبل استفاده کرده‌ایم، از ماکروی println! استفاده کند. اما این کار جواب نمی‌دهد.

    وقتی این کد را کامپایل می‌کنیم، خطایی با این پیام اصلی دریافت می‌کنیم:

    error[E0277]: `Rectangle` doesn't implement `std::fmt::Display`

    ماکروی println! می‌تواند انواع مختلفی از قالب‌بندی را انجام دهد و به‌طور پیش‌فرض، آکولادها به println! می‌گویند از قالب‌بندی‌ای به نام Display استفاده کند: خروجی‌ای که برای مصرف مستقیم کاربر نهایی در نظر گرفته شده است. نوع‌های اولیه‌ای که تاکنون دیده‌ایم به‌طور پیش‌فرض Display را پیاده‌سازی می‌کنند، زیرا فقط یک راه وجود دارد که بخواهید 1 یا هر نوع اولیه‌ی دیگری را به کاربر نشان دهید. اما در مورد ساختارها، نحوه‌ی قالب‌بندی خروجی توسط println! کمتر روشن است، چون امکانات نمایش بیشتری وجود دارد: آیا ویرگول می‌خواهید یا نه؟ آیا می‌خواهید آکولادها چاپ شوند؟ آیا باید همه‌ی فیلدها نشان داده شوند؟ به دلیل همین ابهام، Rust سعی نمی‌کند حدس بزند ما چه می‌خواهیم، و ساختارها پیاده‌سازی پیش‌فرضی از Display برای استفاده با println! و جای‌نگهدار {} ندارند.

    اگر خواندن خطاها را ادامه دهیم، این یادداشت مفید را پیدا می‌کنیم:

    help: the trait `std::fmt::Display` is not implemented for `Rectangle`
  --> src/main.rs:1:1

    بیایید امتحانش کنیم! فراخوانی ماکروی println! اکنون به این شکل خواهد بود: println!("rect1 is {rect1:?}");. قرار دادن مشخص‌کننده‌ی :? داخل آکولادها به println! می‌گوید که می‌خواهیم از قالب خروجی‌ای به نام Debug استفاده کنیم. صفت Debug به ما امکان می‌دهد ساختارمان را به شیوه‌ای چاپ کنیم که برای توسعه‌دهندگان مفید است تا هنگام اشکال‌زدایی کد، مقدار آن را ببینیم.

    کد را با این تغییر کامپایل کنید. افسوس! هنوز هم خطا می‌گیریم:

    error[E0277]: `Rectangle` doesn't implement `Debug`

    اما باز هم کامپایلر یک یادداشت مفید به ما می‌دهد:

       |                        required by this formatting parameter
   |

    Rust در واقع قابلیت چاپ اطلاعات اشکال‌زدایی را دارد، اما باید صراحتاً آن را برای ساختارمان فعال کنیم. برای این کار، درست قبل از تعریف ساختار، ویژگی بیرونی (outer attribute) به نام #[derive(Debug)] را اضافه می‌کنیم، همان‌طور که در لیست ۵-۱۲ نشان داده شده است.

    اکنون وقتی برنامه را اجرا می‌کنیم، هیچ خطایی دریافت نمی‌کنیم و خروجی زیر را می‌بینیم:

    $ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle { width: 30, height: 50 }

    عالی! این زیباترین خروجی نیست، اما مقادیر همه‌ی فیلدهای این نمونه را نشان می‌دهد که قطعاً در اشکال‌زدایی کمک می‌کند. وقتی ساختارهای بزرگ‌تری داریم، مفید است که خروجی کمی خواناتر باشد؛ در چنین مواردی می‌توانیم در رشته‌ی println! به‌جای {:?} از {:#?} استفاده کنیم. در این مثال، استفاده از سبک {:#?} خروجی زیر را تولید می‌کند:

    $ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle {
    width: 30,
    height: 50,
}

    راه دیگر برای چاپ یک مقدار با قالب Debug استفاده از ماکروی dbg! است که مالکیت یک عبارت را می‌گیرد (برخلاف println! که یک ارجاع می‌گیرد)، نام فایل و شماره‌ی خطی را که فراخوانی ماکروی dbg! در کد شما در آن رخ می‌دهد همراه با مقدار حاصل از آن عبارت چاپ می‌کند و مالکیت مقدار را برمی‌گرداند.

    نکته: فراخوانی ماکروی dbg! در جریان کنسول خطای استاندارد (stderr) چاپ می‌کند، برخلاف println! که در جریان کنسول خروجی استاندارد (stdout) چاپ می‌کند. در بخش «هدایت خطاها به خطای استاندارد» در فصل ۱۲ درباره‌ی stderr و stdout بیشتر صحبت خواهیم کرد.

    در اینجا مثالی داریم که در آن به مقداری که به فیلد width اختصاص داده می‌شود و همچنین به مقدار کل ساختار در rect1 علاقه‌مندیم:

    #[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let scale = 2;
    let rect1 = Rectangle {
        width: dbg!(30 * scale),
        height: 50,
    };

    dbg!(&rect1);
}

    می‌توانیم dbg! را دور عبارت 30 * scale قرار دهیم و چون dbg! مالکیت مقدار عبارت را برمی‌گرداند، فیلد width همان مقداری را می‌گیرد که اگر فراخوانی dbg! آنجا نبود می‌گرفت. نمی‌خواهیم dbg! مالکیت rect1 را بگیرد، بنابراین در فراخوانی بعدی از یک ارجاع به rect1 استفاده می‌کنیم. خروجی این مثال به این شکل است:

    $ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.61s
     Running `target/debug/rectangles`
[src/main.rs:10:16] 30 * scale = 60
[src/main.rs:14:5] &rect1 = Rectangle {
    width: 60,
    height: 50,
}

    می‌بینیم که اولین بخش خروجی از خط ۱۰ فایل src/main.rs آمده است، جایی که عبارت 30 * scale را اشکال‌زدایی می‌کنیم، و مقدار حاصل از آن 60 است (قالب‌بندی Debug که برای اعداد صحیح پیاده‌سازی شده فقط مقدار آن‌ها را چاپ می‌کند). فراخوانی dbg! در خط ۱۴ فایل src/main.rs مقدار &rect1 را که همان ساختار Rectangle است، خروجی می‌دهد. این خروجی از قالب‌بندی زیبای Debug نوع Rectangle استفاده می‌کند. ماکروی dbg! می‌تواند واقعاً مفید باشد، وقتی می‌خواهید بفهمید کدتان چه کاری انجام می‌دهد!

    علاوه بر صفت Debug، Rust تعدادی صفت دیگر برای استفاده با attribute به نام derive در اختیار ما گذاشته است که می‌توانند رفتارهای مفیدی به نوع‌های سفارشی ما اضافه کنند. این صفت‌ها و رفتارهای آن‌ها در پیوست ج فهرست شده‌اند. در فصل ۱۰ توضیح خواهیم داد که چگونه این صفت‌ها را با رفتار سفارشی پیاده‌سازی کنیم و چگونه صفت‌های خودمان را بسازیم. علاوه بر derive، attributeهای بسیار دیگری هم وجود دارند؛ برای اطلاعات بیشتر به بخش «Attributes» در مرجع Rust مراجعه کنید.

    تابع area ما بسیار اختصاصی است: فقط مساحت مستطیل‌ها را محاسبه می‌کند. خوب است که این رفتار را نزدیک‌تر به ساختار Rectangle خود پیوند دهیم، چون با هیچ نوع دیگری کار نمی‌کند. بیایید ببینیم چگونه می‌توانیم با تبدیل تابع area به یک متد area که روی نوع Rectangle تعریف می‌شود، بازآرایی این کد را ادامه دهیم.
