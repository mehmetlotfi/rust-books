    ضمیمهٔ ج: Traitهای قابل اشتقاق

    در جاهای مختلف کتاب دربارهٔ attribute با نام derive صحبت کرده‌ایم که می‌توانید آن را روی تعریف یک struct یا enum به کار ببرید. attribute با نام derive کدی تولید می‌کند که یک trait را با پیاده‌سازی پیش‌فرض خودش روی نوعی که با نحو derive حاشیه‌نویسی کرده‌اید پیاده‌سازی می‌کند.

    در این ضمیمه، همهٔ Traitهای کتابخانهٔ استاندارد را که می‌توان با derive به کار برد معرفی می‌کنیم. هر بخش این موارد را پوشش می‌دهد:

    • اشتقاق Trait چه عملگرها و متدهایی را در دسترس قرار می‌دهد
    • پیاده‌سازی تولیدشده به‌دست derive چه کاری انجام می‌دهد
    • پیاده‌سازی Trait چه معنایی دربارهٔ نوع دارد
    • در چه شرایطی مجاز یا غیرمجاز به پیاده‌سازی آن هستید
    • نمونه‌هایی از عملیات‌هایی که به آن Trait نیاز دارند

    اگر رفتاری متفاوت با پیاده‌سازی تولیدشده به‌دست derive می‌خواهید، برای جزئیات پیاده‌سازی دستی هر Trait به مستندات کتابخانهٔ استاندارد مراجعه کنید.

    Traitهای این فهرست تنها Traitهای تعریف‌شده در کتابخانهٔ استاندارد هستند که می‌توان آن‌ها را با derive برای نوع‌های خود پیاده‌سازی کرد. دیگر Traitهای کتابخانهٔ استاندارد رفتار پیش‌فرض معقول و همگانی ندارند؛ بنابراین باید آن‌ها را متناسب با هدف خودتان پیاده‌سازی کنید.

    برای نمونه، Display که قالب‌بندی خروجی برای کاربر نهایی را مدیریت می‌کند، قابل اشتقاق نیست. شما باید تصمیم بگیرید یک نوع چگونه به کاربر نمایش داده شود: کاربر اجازه دارد کدام بخش‌ها را ببیند، چه اطلاعاتی برایش مهم است و چه قالبی مناسب‌تر خواهد بود؟ کامپایلر Rust چنین شناختی ندارد و نمی‌تواند رفتار پیش‌فرض مناسبی ارائه کند.

    فهرست traitهای قابل اشتقاق در این پیوست جامع نیست: کتابخانه‌ها می‌توانند derive را برای traitهای خودشان پیاده‌سازی کنند، و به این ترتیب فهرست traitهایی که می‌توانید با derive به کار ببرید واقعاً باز و نامحدود است. پیاده‌سازی derive مستلزم استفاده از یک ماکروی رویه‌ای (procedural macro) است که در بخش «ماکروهای derive سفارشی» در فصل ۲۰ توضیح داده شده است.

    Debug برای خروجی ویژهٔ برنامه‌نویسان

    Traitِ Debug قالب‌بندی اشکال‌زدایی را در رشته‌های قالب فعال می‌کند؛ آن را با افزودن :? درون جای‌نگهدار {} مشخص می‌کنید.

    Debug اجازه می‌دهد نمونه‌های یک نوع را برای اشکال‌زدایی چاپ کنید تا شما و دیگر برنامه‌نویسان استفاده‌کننده از آن نوع بتوانید وضعیت یک نمونه را در نقطه‌ای از اجرای برنامه ببینید.

    برای نمونه، ماکروی assert_eq! به Debug نیاز دارد. اگر بررسی برابری شکست بخورد، این ماکرو مقادیر آرگومان‌ها را چاپ می‌کند تا برنامه‌نویس دلیل نابرابری دو نمونه را ببیند.

    PartialEq و Eq برای مقایسهٔ برابری

    Traitِ PartialEq امکان مقایسهٔ نمونه‌های یک نوع از نظر برابری و استفاده از عملگرهای == و != را فراهم می‌کند.

    اشتقاق PartialEq متد eq را پیاده‌سازی می‌کند. وقتی PartialEq روی structها اشتقاق داده شود، دو نمونه فقط در صورتی برابرند که همهٔ فیلدها برابر باشند، و اگر هر فیلدی برابر نباشد، آن دو نمونه نابرابرند. وقتی روی enumها اشتقاق داده شود، هر variant با خودش برابر و با variantهای دیگر نابرابر است.

    برای مثال، ماکروی assert_eq! به PartialEq نیاز دارد تا بتواند دو نمونه از یک نوع را با هم مقایسه کند.

    Traitِ Eq هیچ متدی ندارد. هدف آن اعلام این نکته است که هر مقدار از نوع مشخص‌شده با خودش برابر است. Eq فقط روی نوع‌هایی قابل اعمال است که PartialEq را نیز پیاده‌سازی کرده باشند؛ هرچند همهٔ نوع‌های دارای PartialEq نمی‌توانند Eq داشته باشند. یک نمونه، عددهای ممیز شناورند: مطابق پیاده‌سازی آن‌ها، دو نمونه از مقدار «نه یک عدد» (NaN) با یکدیگر برابر نیستند.

    یکی از جاهایی که Eq لازم است کلیدهای HashMap<K, V> است تا HashMap<K, V> بتواند یکسان‌بودن دو کلید را تشخیص دهد.

    PartialOrd و Ord برای مقایسهٔ ترتیب

    Traitِ PartialOrd اجازه می‌دهد نمونه‌های یک نوع را برای مرتب‌سازی مقایسه کنید. نوعی که PartialOrd را پیاده‌سازی می‌کند می‌تواند با عملگرهای <، >، <= و >= به کار رود. PartialOrd فقط روی نوع‌هایی قابل اعمال است که PartialEq را نیز پیاده‌سازی کنند.

    اشتقاق PartialOrd متد partial_cmp را پیاده‌سازی می‌کند. این متد یک Option<Ordering> بازمی‌گرداند که اگر مقادیر ترتیب مشخصی نداشته باشند None است. NaN نمونه‌ای از چنین مقداری است: هرچند بیشتر مقدارهای ممیز شناور قابل مقایسه‌اند، فراخوانی partial_cmp با هر عدد ممیز شناور و NaN مقدار None می‌دهد.

    برای structها، پیاده‌سازی اشتقاقی PartialOrd دو نمونه را با مقایسهٔ مقدار فیلدها به ترتیب حضورشان در تعریف struct می‌سنجد. برای enumها، واریانت‌هایی که زودتر تعریف شده‌اند کوچک‌تر از واریانت‌های بعدی در نظر گرفته می‌شوند.

    برای نمونه، متد gen_range از crateِ rand که مقداری تصادفی در بازهٔ مشخص‌شده تولید می‌کند، به PartialOrd نیاز دارد.

    Traitِ Ord تضمین می‌کند برای هر دو مقدار از نوع مشخص‌شده یک ترتیب معتبر وجود دارد. Ord متد cmp را پیاده‌سازی می‌کند که به‌جای Option<Ordering> یک Ordering بازمی‌گرداند، زیرا همیشه ترتیب معتبری وجود دارد. Ord فقط روی نوع‌هایی قابل اعمال است که PartialOrd و Eq را نیز پیاده‌سازی کنند؛ خود Eq هم به PartialEq نیاز دارد. برای structها و enumها، رفتار cmp همان رفتار پیاده‌سازی اشتقاقی partial_cmp در PartialOrd است.

    هنگام ذخیرهٔ مقدارها در BTreeSet<T>—ساختار داده‌ای که داده را بر پایهٔ ترتیب مقدارها نگه می‌دارد—به Ord نیاز داریم.

    Clone و Copy برای تکثیر مقدارها

    trait Clone به شما اجازه می‌دهد صریحاً یک کپی عمیق (deep copy) از یک مقدار بسازید، و فرایند تکثیر ممکن است شامل اجرای کد دلخواه و کپی‌کردن داده‌های heap باشد. برای اطلاعات بیشتر دربارهٔ Clone بخش «متغیرها و داده‌ها در تعامل با Clone» در فصل ۴ را ببینید.

    اشتقاق Clone متد clone را پیاده‌سازی می‌کند که وقتی برای کل نوع پیاده‌سازی شود، clone را روی هر یک از اجزای نوع فراخوانی می‌کند. یعنی برای اشتقاق Clone، همهٔ فیلدها یا مقدارهای درون نوع نیز باید Clone را پیاده‌سازی کرده باشند.

    برای نمونه، فراخوانی متد to_vec روی یک slice به Clone نیاز دارد. slice مالک نمونه‌های درون خود نیست، اما بردار بازگردانده‌شده از to_vec باید مالک نمونه‌هایش باشد؛ پس to_vec روی هر عضو clone را فراخوانی می‌کند. در نتیجه نوع ذخیره‌شده در slice باید Clone را پیاده‌سازی کند.

    trait Copy به شما اجازه می‌دهد یک مقدار را فقط با کپی‌کردن بیت‌های ذخیره‌شده روی پشته (stack) تکثیر کنید؛ هیچ کد دلخواهی لازم نیست. برای اطلاعات بیشتر دربارهٔ Copy بخش «داده‌های فقط-پشته: Copy» در فصل ۴ را ببینید.

    Copy هیچ متدی تعریف نمی‌کند تا برنامه‌نویسان نتوانند متدهایش را با رفتاری دلخواه بازتعریف و فرض «اجرانشدن کد دلخواه» را نقض کنند. در نتیجه همه می‌توانند فرض کنند کپی یک مقدار بسیار سریع است.

    می‌توانید Copy را روی هر نوعی که همهٔ اجزایش Copy را پیاده‌سازی می‌کنند اشتقاق دهید. نوعی که Copy را پیاده‌سازی می‌کند باید Clone را هم پیاده‌سازی کند، زیرا نوعی که Copy را پیاده‌سازی می‌کند یک پیاده‌سازی بدیهی از Clone دارد که همان کار Copy را انجام می‌دهد.

    به‌ندرت یک API صریحاً به Copy نیاز دارد. نوع‌های دارای Copy بهینه‌سازی‌هایی دارند که شما را از فراخوانی clone بی‌نیاز و کد را کوتاه‌تر می‌کند.

    هر کاری را که با Copy می‌توان انجام داد با Clone نیز می‌توان انجام داد، اما ممکن است کد کندتر شود یا در جاهایی به فراخوانی clone نیاز داشته باشد.

    Hash برای نگاشت مقدار به مقداری با اندازهٔ ثابت

    trait Hash به شما اجازه می‌دهد نمونه‌ای از یک نوع با اندازهٔ دلخواه را بگیرید و آن را با یک تابع هش (hash function) به مقداری با اندازهٔ ثابت نگاشت کنید. اشتقاق Hash متد hash را پیاده‌سازی می‌کند. پیاده‌سازی اشتقاق‌شدهٔ متد hash نتیجهٔ فراخوانی hash روی هر یک از اجزای نوع را با هم ترکیب می‌کند، یعنی برای اشتقاق Hash، همهٔ فیلدها یا مقدارها نیز باید Hash را پیاده‌سازی کنند.

    برای نمونه، ذخیرهٔ کارآمد کلیدها در HashMap<K, V> به Hash نیاز دارد.

    Default برای مقدارهای پیش‌فرض

    trait Default به شما اجازه می‌دهد برای یک نوع مقدار پیش‌فرض بسازید. اشتقاق Default تابع default را پیاده‌سازی می‌کند. پیاده‌سازی اشتقاق‌شدهٔ تابع default، تابع default را روی هر جزء نوع فراخوانی می‌کند، یعنی برای اشتقاق Default، همهٔ فیلدها یا مقدارهای درون نوع نیز باید Default را پیاده‌سازی کنند.

    تابع Default::default معمولاً همراه نگارش به‌روزرسانی struct به کار می‌رود که در بخش «ساخت نمونه از نمونه‌های دیگر با نگارش به‌روزرسانی Struct» فصل ۵ بررسی شد. می‌توانید چند فیلد struct را شخصی‌سازی و با ..Default::default() مقدار پیش‌فرض را برای بقیهٔ فیلدها تنظیم کنید.

    trait Default برای مثال وقتی لازم است که از متد unwrap_or_default روی نمونه‌های Option<T> استفاده کنید. اگر Option<T> برابر None باشد، متد unwrap_or_default نتیجهٔ Default::default را برای نوع T که در Option<T> ذخیره شده است برمی‌گرداند.
