    قواعد Cargo.toml

    قواعد قالب‌بندی

    از همان عرض خط و تورفتگی‌ای استفاده کنید که برای کد Rust به کار می‌برید.

    بین آخرین جفت کلید-مقدار یک بخش و سرنویس بخش بعدی یک خط خالی بگذارید. بین سرنویس یک بخش و جفت‌های کلید-مقدار آن، یا بین جفت‌های کلید-مقدار یک بخش، خط خالی نگذارید.

    نام کلیدها را در هر بخش به‌ترتیب مرتب‌سازی نسخه‌ای بچینید، به‌جز بخش [package]. بخش [package] را در بالای فایل قرار دهید؛ در ابتدای این بخش، کلیدهای name و version به همین ترتیب می‌آیند، سپس بقیهٔ کلیدها به ترتیب (به‌جز description) و در پایان بخش، description قرار می‌گیرد.

    برای نام کلیدهای استاندارد از نقل‌قول استفاده نکنید و از کلیدهای خام (bare) بهره ببرید. فقط برای کلیدهای غیراستاندارد که نامشان به آن نیاز دارد از کلیدهای داخل نقل‌قول استفاده کنید و تا جای ممکن از معرفی چنین نام‌هایی پرهیز کنید. برای جزئیات، مشخصات TOML را ببینید.

    قبل و بعد از = بین کلید و مقدار یک فاصلهٔ واحد بگذارید. نام کلیدها را تورفتگی ندهید؛ همهٔ نام کلیدها از ابتدای خط شروع شوند.

    برای مقادیر رشته‌ای که چند خطی هستند، مانند توضیح crate، از رشته‌های چندخطی (به‌جای دنباله‌های escape برای خط جدید) استفاده کنید.

    برای مقادیر آرایه‌ای، مانند فهرست featureها، اگر جا شود کل فهرست را در همان خط کلید بنویسید. در غیر این صورت از تورفتگی بلوکی استفاده کنید: بعد از کروشهٔ بازکننده یک خط جدید بگذارید، هر آیتم را یک سطح تورفتگی دهید، بعد از هر آیتم (از جمله آخرین آیتم) کاما بگذارید، و کروشهٔ بستن را به‌تنهایی در ابتدای یک خط بعد از آخرین آیتم قرار دهید.

    some_feature = [
    "another_feature",
    "yet_another_feature",
    "some_dependency?/some_feature",
]

    برای مقادیر جدولی، مانند یک وابستگی crate با مسیر، اگر جا شود کل جدول را با آکولاد و کاما در همان خط کلید بنویسید. اگر کل جدول در همان خط کلید جا نشود، آن را به بخش جداگانه‌ای با جفت‌های کلید-مقدار تبدیل کنید:

    [dependencies]
crate1 = { path = "crate1", version = "1.2.3" }

[dependencies.extremely_long_crate_name_goes_here]
path = "extremely_long_path_name_goes_right_here"
version = "4.5.6"

    قواعد فرادده (metadata)

    فهرست نویسندگان، در صورت وجود، باید از رشته‌هایی تشکیل شود که هر کدام شامل نام نویسنده و به‌دنبال آن نشانی ایمیل داخل علامت‌های کوچک‌تر و بزرگ‌تر باشد: Full Name <email@address>. این فهرست نباید نشانی ایمیل بدون نام یا نام بدون نشانی ایمیل داشته باشد. (فهرست نویسندگان ممکن است نشانی یک فهرست پستی بدون نام مرتبط را هم شامل شود.)

    فیلد license باید یک عبارت SPDX معتبر باشد که از نام‌های معتبر مجوز SPDX استفاده می‌کند. (به‌عنوان استثنا و طبق قرارداد رایج، فیلد license می‌تواند به‌جای OR از / استفاده کند؛ برای مثال MIT/Apache-2.0.)

    اگر فیلد homepage وجود دارد، باید دقیقاً یک URL باشد که scheme را هم شامل شود (مثلاً https://example.org/، نه فقط example.org).

    در فیلد description متن را در ۸۰ ستون بشکنید. فیلد description را با نام crate شروع نکنید (مثلاً «cratename is a …»)؛ فقط خود crate را توصیف کنید. اگر توضیح چندجمله‌ای می‌دهید، جملهٔ اول باید در یک خط مستقل باشد و crate را خلاصه کند، مانند موضوع یک ایمیل یا پیام commit؛ جمله‌های بعدی می‌توانند crate را با جزئیات بیشتری توصیف کنند.
