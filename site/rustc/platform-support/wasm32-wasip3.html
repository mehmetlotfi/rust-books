    wasm32-wasip3

    سطح: 2

    هدف wasm32-wasip3 مرحلهٔ بعدیِ تکامل هدف wasm32-wasip2 است. هدف wasm32-wasip3 به کتابخانهٔ استاندارد Rust امکان می‌دهد برای پیاده‌سازی بخش‌های مختلف قابلیت‌های خود از APIهای WASIp3 استفاده کند. WASIp3 نسبت به WASIp2 پشتیبانی بومی از async را به همراه می‌آورد که به‌خوبی با اکوسیستم async در Rust یکپارچه می‌شود. علاوه بر این، نسخه‌ای از هدف wasm32-wasip3 در Rust در آینده از threadingِ همکارانه و APIهای std::thread پشتیبانی خواهد کرد.

    پیشنهاد اولیهٔ افزودن این هدف در rust-lang/compiler-team#1001 قابل مشاهده است و این هدف نخستین بار در Rust 1.100.0 روی نسخهٔ stable در دسترس است. یک تغییر عمدهٔ قابل‌توجه نسبت به اهداف تاریخی WebAssembly این است که ABI این هدف اندکی متفاوت است. اشاره‌گر پشتهٔ سایه (shadow stack) حافظهٔ خطی در یک slot از زمینهٔ وظیفه (task context) در component model ذخیره می‌شود، نه در یک global از WebAssembly. همچنین اشاره‌گر پایهٔ TLS به شیوه‌ای متفاوت از سایر اهداف مدیریت می‌شود. این تغییرات برای امکان‌پذیر کردن چندنخی همکارانه در این هدف انجام شده‌اند.

    نکته: از تاریخ 2026-09-03، چندنخی همکارانه هنوز در Rust روی این هدف پشتیبانی نمی‌شود. مشخصات component model و کار روی پشتیبانی کتابخانه‌ای آن در حال توسعه است و هنوز کامل نشده، اما انتظار می‌رود پیش از پایان سال کامل شود. تا آن زمان، ایجاد یک نخ از طریق std::thread خطا برمی‌گرداند. با این حال توجه کنید که این پشتیبانی را می‌توان از طریق دستورالعمل‌های زیر آزمایش کرد.

    نگهدارندگان هدف

    @alexcrichton @yoshuawuyts

    الزامات

    این هدف به‌صورت cross-compile ساخته می‌شود. این هدف از std به‌طور کامل پشتیبانی می‌کند. استفاده از این هدف به LLVM 23 نیاز دارد و علاوه بر آن، اگر آن را به‌صورت محلی می‌سازید یا به‌صورت خارجی به آن لینک می‌کنید، به wasi-sdk-34 یا جدیدتر نیاز دارد.

    الزامات پلتفرم

    زمان‌اجراهای WebAssembly که می‌خواهند componentهای کامپایل‌شده برای این هدف را اجرا کنند، باید از WASI 0.3.0 و قابلیت‌های لازمِ component model (به‌ویژه async) پشتیبانی کنند. دو نمونه زمان‌اجرا برای WASIp3 عبارت‌اند از Wasmtime و Jco.

    ساخت هدف

    برای ساخت این هدف ابتدا یک نسخه از wasi-sdk را تهیه کنید. در حال حاضر نسخهٔ 34 حداقل نسخهٔ لازم است.

    سپس متغیر محیطی WASI_SDK_PATH را طوری تنظیم کنید که به محل نصب آن اشاره کند. برای مثال:

    export WASI_SDK_PATH=/path/to/wasi-sdk-34.0

    سپس هنگام ساخت Rust از روی سورس حتماً LLD را فعال کنید، زیرا برای لینک کردن کد WebAssembly به درایور wasm-ld از LLVM برای LLD نیاز است. سیستم ساخت Rust به‌طور خودکار هر باینری و برنامهٔ لازم را از WASI_SDK_PATH برمی‌دارد.

    آزمون

    این هدف در حال حاضر در CI آزمون نمی‌شود. به‌صورت محلی می‌توان آن را با یک باینری wasmtime در PATH به این شکل آزمون کرد:

    ./x.py test --target wasm32-wasip3 tests/ui

    کامپایل شرطی کد

    توصیه می‌شود کد را برای این هدف به این شکل به‌صورت شرطی کامپایل کنید:

    #[cfg(all(target_os = "wasi", target_env = "p3"))]

    ویژگی‌های فعال WebAssembly

    مجموعهٔ پیش‌فرض ویژگی‌های WebAssembly که برای کامپایل فعال است، در حال حاضر با wasm32-unknown-unknown یکسان است. برای اطلاعات بیشتر به مستندات آن‌جا مراجعه کنید.

    آزمایش چندنخی همکارانه

    مشخصات component model در حال افزودن intrinsicهایی برای پشتیبانی از چندنخی همکارانه در یک guest از نوع component است. این intrinsicها را می‌توان در explainer یافت و همگی با ایموجی 🧵 قفل‌گذاری (gate) شده‌اند. پشتیبانی از چندنخی همکارانه در حال توسعه است و هنوز کامل نشده، اما افراد ماجراجو می‌توانند این هدف را پیکربندی کنند تا همین حالا آن را امتحان کنند.

    بیشتر تغییرات لازم برای راه‌اندازی چندنخی همکارانه در وابستگی wasi-libc مربوط به Rust قرار دارد. این یعنی برای آزمایش چندنخی همکارانه باید از ساختی متفاوت از wasi-libc پیش‌فرض استفاده شود. از wasi-sdk-34 به بعد یک sysroot موقت وجود دارد که شامل پشتیبانی از یک هدف wasip3 با چندنخی فعال در wasi-libc است. برای آزمایش هدف Rust یعنی wasm32-wasip3 همراه با نخ‌ها، باید کامپایل شما طوری پیکربندی شود که از این sysroot استفاده کند.

    نمونه‌ای از این کار، برنامهٔ زیر است:

    fn main() {
    std::thread::spawn(|| {
        println!("hi");
    })
    .join()
    .unwrap();
}

    که به‌صورت پیش‌فرض این‌گونه کامپایل و اجرا می‌شود:

    $ rustc foo.rs --target wasm32-wasip3
$ wasmtime foo.wasm

thread 'main' (1) panicked at library/std/src/thread/functions.rs:131:29:
failed to spawn thread: Os { code: 58, kind: Unsupported, message: "Not supported" }
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
Error: failed to run main module `foo.wasm`

...

    و نشان می‌دهد که به‌صورت پیش‌فرض نمی‌توان نخ ایجاد کرد. اما با پیکربندی یک sysroot سفارشی:

    $ rustc foo.rs --target wasm32-wasip3 \
    -Clink-self-contained=n \
    -Clinker=$WASI_SDK_PATH/bin/wasm32-wasip3-clang \
    -Clink-arg=--sysroot=$WASI_SDK_PATH/share/wasi-sysroot/experimental-coop-threads \
    -Clink-arg=-Wl,--export=cabi_realloc
$ wasmtime -W component-model-threading foo.wasm
hi

    در این‌جا -Clink-self-contained=n از فایل‌های vendor‌شدهٔ کتابخانهٔ استاندارد که از ساختی از wasi-libc ناسازگار با چندنخی همکارانه آمده‌اند جلوگیری می‌کند. پرچم -Clinker به استفاده از clang تغییر می‌کند تا بتوان آرگومان --sysroot سفارشی را پاس داد و از منطق آن برای شیءهای راه‌اندازی (startup objects) پیروی کرد. پرچم --sysroot سپس به sysroot آزمایشی برای نخ‌های همکارانه اشاره می‌کند و --export در حال حاضر به‌عنوان یک راه‌حل موقت جزئی لازم است.

    هنگام کامپایل با Cargo می‌توانید از این متغیرهای محیطی استفاده کنید:

    $ export CARGO_TARGET_WASM32_WASIP3_LINKER=$WASI_SDK_PATH/bin/wasm32-wasip3-clang
$ export CARGO_TARGET_WASM32_WASIP3_RUNNER='wasmtime -W component-model-threading'
$ export CARGO_TARGET_WASM32_WASIP3_RUSTFLAGS="\
    -Clink-self-contained=n \
    -Clink-arg=--sysroot=$WASI_SDK_PATH/share/wasi-sysroot/experimental-coop-threads \
    -Clink-arg=-Wl,--export=cabi_realloc"
$ cargo run --target wasm32-wasip3
hi

    ابزارهای همگام‌سازی استاندارد در std::thread و std::sync باید همگی روی این هدف با چندنخی همکارانه کار کنند. اگر با مشکلی روبه‌رو شدید، لطفاً بی‌درنگ یک issue ثبت کنید و نگهدارندگان هدف را cc کنید.

    توجه کنید که در حال حاضر قصد بر این است که تا پایان 2026 همهٔ این پشتیبانی به‌صورت پیش‌فرض فعال شود و این بخش از مستندات حذف گردد، چرا که کار با نخ‌ها باید «خودبه‌خود کار کند».
