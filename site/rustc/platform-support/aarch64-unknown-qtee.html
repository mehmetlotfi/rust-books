    aarch64-unknown-qtee

    سطح (Tier): ۳

    پشتیبانی از هدف برای محیط اجرای مورداعتماد کوالکام (QTEE)، که برنامه‌های مورداعتماد (Trusted Applications یا TAها) را در TrustZone شرکت ARM اجرا می‌کند.

    نگهدارندگان هدف

    • @atmartorana
    • Gaurav Kashyap
    • Neal Haas
    • به‌عنوان راه جایگزین: rustzone@qti.qualcomm.com

    الزامات

    این هدف به‌صورت cross-compile ساخته می‌شود و از host-tools پشتیبانی نمی‌کند.

    پشتیبانی QTEE از کتابخانهٔ استاندارد در دست توسعه است: alloc به‌طور کامل پشتیبانی خواهد شد و std پشتیبانی‌ای خواهد داشت که مواردی مانند ورودی/خروجی شبکه و ایجاد فرایندها / نخ‌ها (thread) را شامل نمی‌شود (زیرا QTEE تک‌نخی است). دسترسی به سامانهٔ فایل به سامانهٔ فایل امن QTEE (SFS) محدود است، نه یک سامانهٔ فایل همه‌منظوره. توصیف‌گرهای فایل (file descriptor) برای مقاصد IPC پشتیبانی می‌شوند. ورودی/خروجی به خروجی استاندارد و ثبت لاگ در خطای استاندارد محدود است.

    QTEE از قالب ELF استفاده می‌کند. هر TA به‌صورت یک فایل اجرایی وابسته به موقعیت (position-dependent) پیوند داده می‌شود و باید نماد TA_APP_NAME را صادر (export) کند که آن را به بارگذار (loader) QTEE معرفی می‌کند.

    راه‌اندازی

    برای پشتیبانی در زمان اجرا، به یک نسخه از QTEE SDK و artifactهای ساخته‌شده نیاز خواهد بود.

    ساخت هدف

    Rust هنوز artifactهای از پیش کامپایل‌شده برای این هدف ارائه نمی‌کند. برای کامپایل، یا باید Rust را با فعال‌بودن این هدف بسازید (مثال زیر را ببینید)، یا از build-std برای کامپایل std از روی سورس توسط خودتان استفاده کنید.

    برای ساخت یک toolchain از Rust، برای نمونه یک فایل bootstrap.toml با محتوای زیر ایجاد کنید:

    [build]
target = ["x86_64-unknown-linux-gnu", "aarch64-unknown-qtee"]

[target.aarch64-unknown-qtee]
profiler = false
sanitizers = false
cc = "/path/to/llvm/bin/clang"
cxx = "/path/to/llvm/bin/clang++"
linker = "/path/to/llvm/bin/clang"
ar = "/path/to/llvm/bin/llvm-ar"
ranlib = "/path/to/llvm/bin/llvm-ranlib"

The upstream LLVM build packaged with Rust is sufficient to compile for the target.

## Building Rust programs

Compiling binaries for this target requires some additional linker inputs supplied from the QTEE SDK,
primarily:

- `libcmnlib.so`
- `applib.lib`
- `common_applib.o`

The directory containing these objects can optionally be set when building the Rust toolchain
for the target itself. For example setting the directory containing these objects from the prebuilts
directory of the QTEE SDK, via the `qtee-dist-path` target option in `bootstrap.toml`:

```toml
[target.aarch64-unknown-qtee]
qtee-dist-path = "/path/to/qteesdk/prebuilts/x86-64/"

Building the `aarch64-unknown-qtee` compiler and standard library does not require these objects
at all - they are only consumed when self-contained linking copies them into the target's lib
directory for an actual TA binary. If `qtee-dist-path` is unset this copy step is skipped
and the toolchain will still build. However, compiling a TA will then fail at the linker stage.

To build executables and on-target tests:

```shell
$ rustc --target aarch64-unknown-qtee your-code.rs
