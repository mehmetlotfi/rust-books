    amdgcn-amd-amdhsa

    سطح: 3

    هدف GPU شرکت AMD برای محاسبات/HSA (Heterogeneous System Architecture).

    نگهدارندگان هدف

    @Flakebi

    الزامات

    می‌توان GPUهای AMD را از طریق کامپایل متقاطع هدف قرار داد. GPUهای پشتیبانی‌شده به نسخهٔ LLVM مورد استفادهٔ Rust بستگی دارند. به‌طور کلی، بیشتر GPUها از gfx7 (Sea Islands/CI) به بعد به‌عنوان هدف کامپایل پشتیبانی می‌شوند، هرچند GPUهای قدیمی‌تر توسط جدیدترین runtime میزبان پشتیبانی نمی‌شوند. جزئیات GPUهای پشتیبانی‌شده را می‌توان در مستندات LLVM و مستندات ROCm یافت.

    فایل‌های دودویی را می‌توان توسط HIP یا توسط runtime مربوط به HSA که در ROCR-Runtime پیاده‌سازی شده بارگذاری کرد. قالب فایل‌های دودویی یک ELF پیوندخورده است.

    فایل‌های دودویی باید با no-std ساخته شوند. آن‌ها می‌توانند از core و alloc استفاده کنند (alloc فقط در صورتی که یک تخصیص‌دهنده فراهم شود). دست‌کم یک تابع باید از قرارداد فراخوانی "gpu-kernel" استفاده کند و با no_mangle یا export_name علامت‌گذاری شود. توابعی که از قرارداد فراخوانی "gpu-kernel" استفاده می‌کنند، نقاط ورود کرنل هستند و می‌توان آن‌ها را از runtime میزبان راه‌اندازی کرد.

    ساخت هدف

    این هدف در rustc گنجانده شده است.

    ساخت برنامه‌های Rust

    هدف amdgpu از نسل‌های سخت‌افزاری بسیاری پشتیبانی می‌کند که به فایل‌های دودویی متفاوتی نیاز دارند. این نسل‌ها در backend به‌صورت target-cpuهای مختلف ارائه می‌شوند. از آنجا که تعداد آن‌ها زیاد است، Rust کتابخانه‌های از پیش کامپایل‌شده‌ای برای این هدف ارائه نمی‌کند. بنابراین باید با استفاده از cargo -Zbuild-std=core یا روشی مشابه، نسخهٔ خودتان از core را بسازید.

    یک تخصیص‌دهنده و پشتیبانی از println!() توسط crate با نام amdgpu-device-libs فراهم می‌شود. هر دو ویژگی به runtime مربوط به HIP وابسته‌اند.

    برای ساخت یک فایل دودویی، یک کتابخانهٔ no-std ایجاد کنید:

    // src/lib.rs
#![feature(abi_gpu_kernel)]
#![no_std]

#[panic_handler]
fn panic(_: &core::panic::PanicInfo) -> ! {
    loop {}
}

#[no_mangle]
pub extern "gpu-kernel" fn kernel(/* Arguments */) {
    // Code
}

    کتابخانه را به‌صورت cdylib بسازید:

    # Cargo.toml
[lib]
crate-type = ["cdylib"]

    target-cpu1 باید از فهرست پشتیبانی‌شده توسط LLVM باشد (یا با rustc --target amdgcn-amd-amdhsa --print target-cpus چاپ شود). نسخهٔ GPU روی سیستم فعلی را می‌توان مثلاً با rocminfo یافت. برای سری‌ای از GPUها که پشتیبانی xnack دارد اما GPU هدف آن را ندارد، باید target-feature با نام -xnack-support فعال شود. یعنی اگر اطلاعات ISA که با rocminfo چاپ می‌شود چیزی دربارهٔ xnack- بگوید، مثلاً gfx1010:xnack-، گزینهٔ -Ctarget-feature=-xnack-support را به rustflags اضافه کنید.

    نمونه فایل .cargo/config.toml برای تعیین هدف و نسل GPU:

    # .cargo/config.toml
[build]
target = "amdgcn-amd-amdhsa"
rustflags = ["-Ctarget-cpu=gfx1100"]
# Add "-Ctarget-feature=-xnack-support" for xnack- GPUs (see above)

[unstable]
build-std = ["core"] # Optional: "alloc"

    اجرای برنامه‌های Rust

    برای اجرای یک فایل دودویی روی GPU شرکت AMD، به یک runtime میزبان نیاز است. در Linux و Windows می‌توان از HIP برای بارگذاری و اجرای فایل‌های دودویی استفاده کرد. کد نمونه دربارهٔ نحوهٔ بارگذاری و اجرای یک فایل دودویی کامپایل‌شده در نمونه‌های ROCm موجود است.

    در Linux، فایل‌های دودویی را می‌توان از طریق runtime مربوط به HSA که در ROCR-Runtime پیاده‌سازی شده نیز اجرا کرد.

    اطلاعات بیشتر

    اطلاعات بیشتر را می‌توان در صفحهٔ LLVM برای amdgpu یافت.

    1. برای این هدف، crateهایی که مقادیر متفاوتی برای -C target-cpu دارند با یکدیگر سازگار برای پیوند نیستند. به همین دلیل، کامپایلر اطمینان می‌دهد که همهٔ crateهایی که با هم پیوند می‌خورند با یک target-cpu یکسان کامپایل شده باشند. هنگام استفاده از دستورهای rustc برای ساخت باید این موضوع را در نظر گرفت. این موضوع برای Cargo اهمیت کمتری دارد، زیرا Cargo عموماً برای همهٔ crateهای یک ساخت از یک target-cpu یکسان استفاده می‌کند. ↩
