    nvptx64-nvidia-cuda

    سطح: 2

    این هدف برای استقرار کد روی شتاب‌دهنده‌های Nvidia® مبتنی بر پلتفرم CUDA آن‌ها در نظر گرفته شده است.

    نگهدارندگان هدف

    @kjetilkjeka @kulst

    الزامات

    این هدف no_std است و به‌طور پیش‌فرض از llvm-bitcode-linker استفاده می‌کند. برای خروجی PTX، با نوع crate برابر cdylib بسازید. مؤلفه‌های لازم برای این روند کاری عبارت‌اند از:

    • rustup toolchain add nightly
    • rustup component add llvm-tools --toolchain nightly
    • rustup component add llvm-bitcode-linker --toolchain nightly

    برای استفاده از کتابخانهٔ core دو گزینه وجود دارد:

    • rustup component add rust-src --toolchain nightly و ساخت با -Z build-std=core.
    • rustup target add nvptx64-nvidia-cuda --toolchain nightly

    هدف و ویژگی‌ها

    اغلب مفید است که معماری SM هدف را مشخص کنید، مثلاً -C target-cpu=sm_89، زیرا حالت پیش‌فرض به‌جای کارایی، سازگاری گسترده را در اولویت قرار می‌دهد. انجام این کار نسخهٔ PTX را نیز برابر بیشینهٔ این دو مقدار انتخاب می‌کند: (الف) قدیمی‌ترین نسخهٔ PTX که از پردازندهٔ هدف انتخاب‌شده پشتیبانی می‌کند (به این جدول نگاه کنید) و (ب) قدیمی‌ترین نسخهٔ PTX که toolchain مربوط به Rust پشتیبانی می‌کند؛ این کار سازگاری با درایور را به بیشترین حد می‌رساند. می‌توان از -C target-feature=+ptx80 برای انتخاب نسخهٔ PTX جدیدتر بدون تغییر معماری SM هدف استفاده کرد (در این حالت پیش‌فرض، یعنی ptx78، به درایور CUDA نسخهٔ 11.8 نیاز دارد، در حالی که ptx80 به درایور نسخهٔ 12.0 نیاز دارد). نسخه‌های جدیدتر PTX ممکن است تولید کد کارآمدتری را ممکن کنند.

    برای این هدف، کامپایلر اعمال می‌کند که همهٔ crateهایی که در یک فایل دودویی ساخته می‌شوند مقدار یکسانی برای -C target-cpu داشته باشند. بنابراین اگر مقداری متفاوت از پیش‌فرض فعلی (sm_70) تعیین می‌کنید، لازم است core را هم با همین مقدار به‌صورت دستی بسازید. این کار با فراخوانی cargo با -Z build-std=core و استفاده از toolchain نایتلی ممکن است. هرچند Rust مانند LLVM ptx* و sm_* را به‌صورت target feature نشان می‌دهد، باید آن‌ها را دارای granularity دودویی نیز دانست. با این حال، کامپایلر این را اعمال نمی‌کند. هنگام ساخت هم‌زمان crateها، باید مقدار یکسانی برای همهٔ crateها از طریق -C target-feature تعیین شود. اگرچه کامپایلر #[target_feature(enable = "ptx80", enable = "sm_89")] را می‌پذیرد، این حالت پشتیبانی نمی‌شود، ممکن است مطابق انتظار رفتار نکند و در آینده ممکن است خطا شود.

    حداقل پشتیبانی SM و PTX بر اساس نسخهٔ Rust

    پشتیبانی از معماری‌های سخت‌افزاری قدیمی و نسخه‌های PTX ISA به‌صورت دوره‌ای حذف می‌شود. این جدول حداقل نسخه‌های پشتیبانی‌شده را برای هر نسخهٔ Rust نشان می‌دهد.

    Rustحداقل SMحداقل PTX ISA
    - 1.962.03.2
    1.97 - TBD7.0 (Volta+)7.0 (CUDA 11+)

    برای نمای کلی کامل از اینکه کدام GPUها از کد ساخته‌شده برای یک نسخهٔ مشخص SM پشتیبانی می‌کنند، مستندات CUDA GPU Compute Capability را ببینید.

    ساخت kernelهای Rust

    یک crate از نوع no_std که شامل یک یا چند تابع با extern "ptx-kernel" باشد را می‌توان با دستوری مانند دستور زیر به PTX کامپایل کرد.

    $ RUSTFLAGS='-Ctarget-cpu=sm_89' cargo +nightly rustc --target=nvptx64-nvidia-cuda -Zbuild-std=core --crate-type=cdylib

    intrinsicهای موجود در core::arch::nvptx ممکن است از #[cfg(target_feature = "...")] استفاده کنند، بنابراین لازم است -Zbuild-std=core را با RUSTFLAGS مناسب به کار ببرید. مؤلفه‌های زیر برای این روند کاری لازم هستند:

    $ rustup component add rust-src --toolchain nightly
$ rustup component add llvm-tools --toolchain nightly
$ rustup component add llvm-bitcode-linker --toolchain nightly

    محدودیت‌های مخصوص هدف

    معماری مجموعه دستورالعمل PTX الزامات ویژه‌ای دربارهٔ آنچه مجاز است و آنچه مجاز نیست دارد. برای جلوگیری از تولید PTX نامعتبر یا ایجاد رفتار تعریف‌نشده توسط LLVM، هنگام کامپایل برای این هدف برخی قابلیت‌های زبان Rust مجاز نیستند.

    مقداردهنده‌های اولیهٔ static باید غیرچرخه‌ای باشند

    مقداردهندهٔ اولیهٔ یک static نباید با خودش یا با مقداردهندهٔ اولیهٔ static دیگری چرخه تشکیل دهد. بنابراین کامپایلر نه‌تنها static خودارجاع A را رد می‌کند، بلکه همهٔ staticهای زیر را نیز رد می‌کند.

    struct Foo(&'static Foo);

static A: Foo = Foo(&A); //~ ERROR static initializer forms a cycle involving `A`

static B0: Foo = Foo(&B1); //~ ERROR static initializer forms a cycle involving `B0`
static B1: Foo = Foo(&B0);

static C0: Foo = Foo(&C1); //~ ERROR static initializer forms a cycle involving `C0`
static C1: Foo = Foo(&C2);
static C2: Foo = Foo(&C0);

    مقداردهنده‌های اولیهٔ غیرچرخه‌ای مجاز هستند:

    struct Bar(&'static u32);

static BAR: Bar = Bar(&INT); // is allowed
static INT: u32 = 42u32; // also allowed
