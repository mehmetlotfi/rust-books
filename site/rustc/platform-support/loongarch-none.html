    loongarch*-unknown-none*

    فایل‌های دودویی LoongArch به‌صورت freestanding/bare-metal در قالب ELF: میان‌افزار (firmware)، هسته‌ها (kernel) و غیره.

    هدفتوضیحاتسطح
    loongarch32-unknown-noneLoongArch ۳۲ بیتی، ABI نوع ILP32D (freestanding، hard-float)سطح ۲
    loongarch32-unknown-none-softfloatLoongArch ۳۲ بیتی، ABI نوع ILP32S (freestanding، soft-float)سطح ۲
    loongarch64-unknown-noneLoongArch ۶۴ بیتی، ABI نوع LP64D (freestanding، hard-float)سطح ۲
    loongarch64-unknown-none-softfloatLoongArch ۶۴ بیتی، ABI نوع LP64S (freestanding، soft-float)سطح ۲

    نگهدارندگان هدف

    @heiher @xen0n

    الزامات

    این هدف cross-compile می‌شود. از std پشتیبانی نمی‌شود. تخصیص‌دهنده (allocator) پیش‌فرضی وجود ندارد، اما با فراهم کردن یک allocator می‌توان از alloc استفاده کرد.

    هدف *-softfloat وجود FPU یا هر افزونه ISA دیگر LoongArch را فرض نمی‌کند و از هیچ ثبات غیر GPR استفاده نمی‌کند. این کار به کد تولیدشده اجازه می‌دهد در محیط‌هایی مانند هسته‌ها اجرا شود که ممکن است لازم باشد از چنین ثبات‌هایی دوری کنند یا ملاحظات ویژه‌ای درباره استفاده از آن‌ها داشته باشند (مثلاً ذخیره و بازیابی آن‌ها تا کد فضای کاربر که از همان ثبات‌ها استفاده می‌کند خراب نشود). می‌توانید با گزینه‌های codegen به نام -C target-feature= در rustc یا با سازوکار #[target_feature] در کد Rust، تولید کد را برای استفاده از ویژگی‌های اضافی CPU تغییر دهید.

    به‌طور پیش‌فرض، کدی که با هدف soft-float تولید می‌شود باید روی هر سخت‌افزار LoongArch اجرا شود، در حالی که هدف hard-float علاوه بر آن به FPU نیاز دارد؛ فعال کردن ویژگی‌های اضافی هدف ممکن است این خط پایه را بالا ببرد.

    کدی که با این اهداف تولید می‌شود به‌طور پیش‌فرض از مدل کد medium استفاده می‌کند. می‌توانید این را با گزینه -C code-model= در rustc تغییر دهید.

    روی loongarch*-unknown-none*، extern "C" از قرارداد فراخوانی استاندارد معماری استفاده می‌کند.

    این اهداف فایل‌های دودویی را در قالب ELF تولید می‌کنند. هر قالب جایگزین یا ملاحظات ویژه برای چیدمان فایل دودویی به گزینه‌های لینکر یا اسکریپت‌های لینکر نیاز خواهد داشت.

    ساخت هدف

    می‌توانید Rust را با پشتیبانی از این اهداف بسازید؛ برای این کار آن‌ها را به فهرست target در bootstrap.toml اضافه کنید:

    [build]
build-stage = 1
target = [
  "loongarch32-unknown-none",
  "loongarch32-unknown-none-softfloat",
  "loongarch64-unknown-none",
  "loongarch64-unknown-none-softfloat",
]

    آزمون

    از آنجا که این اهداف از محیط‌های متنوعی پشتیبانی می‌کنند و از std پشتیبانی نمی‌کنند، از اجرای مجموعه آزمون‌های Rust پشتیبانی نمی‌کنند.

    ساخت برنامه‌های Rust

    loongarch32-unknown-none*

    اهداف loongarch32-unknown-none* در Tier 3 هستند، بنابراین برای استفاده از آن‌ها باید کامپایلر Rust را از سورس بسازید.

    # target flag may be used with any cargo or rustc command
cargo build --target loongarch32-unknown-none
cargo build --target loongarch32-unknown-none-softfloat

    loongarch64-unknown-none*

    از Rust 1.74 به بعد، artifactهای از پیش کامپایل‌شده از طریق rustup ارائه می‌شوند:

    # install cross-compile toolchain
rustup target add loongarch64-unknown-none
rustup target add loongarch64-unknown-none-softfloat
# target flag may be used with any cargo or rustc command
cargo build --target loongarch64-unknown-none
cargo build --target loongarch64-unknown-none-softfloat

    toolchainهای cross-compilation و کد C

    برای cross buildها، برای لینک کردن به یک toolchain سی/سی‌پلاس‌پلاس مناسب برای LoongArch نیاز دارید، یا اگر می‌خواهید کد C را همراه با Rust کامپایل کنید (مثلاً برای crateهای Rust که وابستگی C دارند).

    ممکن است Rust بتواند از یک toolchain به‌شکل loongarch{32,64}-unknown-linux-{gnu,musl}- همراه با پرچم‌های مستقل (standalone) مناسب برای ساخت برای این هدف استفاده کند (بسته به فرض‌های آن toolchain، پایین‌تر را ببینید)، یا ممکن است بخواهید از یک toolchain جداگانه loongarch{32,64}-unknown-none استفاده کنید.

    روی برخی میزبان‌های LoongArch که از فایل‌های دودویی ELF استفاده می‌کنند، ممکن است بتوانید از toolchain C خود میزبان استفاده کنید، به شرط آنکه فرض‌هایی درباره محیط میزبان وارد نکند که با انتظارات یک محیط standalone سازگار نیست. در غیر این صورت، ممکن است برای توسعه standalone/freestanding به یک toolchain جداگانه نیاز داشته باشید، درست مثل زمانی که از یک پلتفرم غیر LoongArch cross-compile می‌کنید.
