    @Ghost @octocat

    الزامات

    آیا هدف از ابزارهای میزبان (host tools) پشتیبانی می‌کند یا فقط از کامپایل متقابل؟ آیا هدف از std یا alloc پشتیبانی می‌کند (چه با یک تخصیص‌دهندهٔ پیش‌فرض، چه در صورتی که کاربر خودش تخصیص‌دهنده را فراهم کند)؟

    انتظارات از باینری‌های ساخته‌شده برای این هدف را مستند کنید. آیا باینری‌ها ویژگی‌های حداقلی مشخصی فراتر از پایهٔ CPU/محیط و غیره را فرض می‌کنند؟ چه نسخه‌ای از سیستم‌عامل یا محیط را انتظار دارند؟

    آیا مقادیر قابل‌توجهی از #[target_feature(...)] یا -C target-feature= وجود دارد که برنامه‌ها ممکن است بخواهند از آن‌ها استفاده کنند؟

    extern "C" در این هدف از کدام قرارداد فراخوانی (calling convention) استفاده می‌کند؟ به‌روزترین مستندات قرارداد فراخوانی و ABI را کجا می‌توان یافت؟ اگر این اطلاعات به‌صورت عمومی در دسترس است، لطفاً پیوند آن را بدهید.

    باینری‌ها به‌طور پیش‌فرض از چه قالبی استفاده می‌کنند؟ ELF، PE یا چیز دیگری؟ اگر قالب استاندارد نیست، پیوندهای مربوط را ارائه دهید.

    ساخت هدف

    اگر Rust این هدف را به‌طور پیش‌فرض نمی‌سازد، کاربران چگونه می‌توانند آن را بسازند؟ آیا کاربران می‌توانند آن را به فهرست target در bootstrap.toml اضافه کنند؟

    ساخت برنامه‌های Rust

    Rust هنوز آرتیفکت‌های از پیش کامپایل‌شده‌ای برای این هدف ارائه نمی‌کند. برای کامپایل برای این هدف، یا باید Rust را با فعال‌بودن این هدف بسازید (به «ساخت هدف» در بالا مراجعه کنید)، یا نسخهٔ خودتان از core را با استفاده از build-std یا روشی مشابه بسازید.

    آزمایش

    آیا هدف از اجرای باینری‌ها پشتیبانی می‌کند، یا باینری‌ها انتظارات متفاوتی دارند که مانع از وجود یک روش استاندارد برای اجرای آن‌ها می‌شود؟ اگر کاربران می‌توانند باینری‌ها را اجرا کنند، آیا این کار را می‌توانند در یک شبیه‌ساز رایج انجام دهند یا به سخت‌افزار بومی نیاز دارند؟ آیا هدف از اجرای مجموعه آزمون‌های Rust پشتیبانی می‌کند؟

    زنجیره‌ابزارهای کامپایل متقابل و کد C

    آیا هدف از کد C پشتیبانی می‌کند؟ اگر بله، کاربران برای ساخت کد C سازگار باید از کدام هدف زنجیره‌ابزار استفاده کنند؟ (این ممکن است با target triple یکی باشد، یا زنجیره‌ابزاری برای target triple دیگری باشد، احتمالاً با گزینه‌ها یا ملاحظات خاص.)
