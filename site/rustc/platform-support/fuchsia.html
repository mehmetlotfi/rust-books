    الزامات

    این هدف از یک محیط میزبان به‌صورت متقاطع کامپایل می‌شود. به یک نسخهٔ جدید از Fuchsia SDK نیاز دارید که ابزارها، کتابخانه‌ها و فایل‌های دودویی لازم برای ساخت و لینک برنامه‌های Fuchsia را فراهم می‌کند.

    توسعه را می‌توان از روی درخت سورس نیز انجام داد.

    اهداف Fuchsia از std پشتیبانی می‌کنند و روی x86_64 از قرارداد فراخوانی sysv64 پیروی می‌کنند. فایل‌های دودویی Fuchsia از قالب فایل ELF استفاده می‌کنند.

    ساختار راهنمای گام‌به‌گام

    این راهنما موارد زیر را پوشش می‌دهد:

    1. کامپایل یک برنامه Rust برای Fuchsia.
    2. ساختن یک بسته Fuchsia.
    3. انتشار و اجرای یک بسته Fuchsia روی یک شبیه‌ساز Fuchsia.

    برای اهداف این راهنما، فقط x86_64-unknown-fuchsia را هدف قرار می‌دهیم.

    کامپایل یک برنامه Rust برای Fuchsia

    امروزه برای ساخت یک برنامه Rust که با استفاده از Fuchsia SDK به Fuchsia هدف‌گیری می‌شود، دو روش اصلی وجود دارد:

    1. اجازه دهید rustup نصب اهداف Fuchsia را برای شما انجام دهد.
    2. یک toolchain را به‌صورت محلی بسازید که بتواند Fuchsia را هدف قرار دهد.

    هدف‌گیری Fuchsia با rustup و cargo

    ساده‌ترین روش برای ساخت یک برنامهٔ Rust برای Fuchsia این است که بگذارید rustup نصب اهداف Fuchsia را برای شما انجام دهد. این کار با اجرای دستورهای زیر انجام می‌شود:

    rustup target add x86_64-unknown-fuchsia
rustup target add aarch64-unknown-fuchsia

    پس از نصب اهداف Fuchsia، اکنون می‌توانیم یک برنامه Rust را که Fuchsia را هدف قرار می‌دهد کامپایل کنیم.

    برای ساخت پروژه Rust می‌توانیم از cargo به‌صورت زیر استفاده کنیم:

    از دایرکتوری کاری پایه

    cargo new hello_fuchsia

    ادامه این راهنما از داخل hello_fuchsia انجام می‌شود، پس همین حالا وارد آن دایرکتوری می‌شویم:

    cd hello_fuchsia

    توجه: از این نقطه به بعد، همه دستورها از داخل دایرکتوری hello_fuchsia/ اجرا می‌شوند و برای اختصار، پیشوند hello_fuchsia/ از همه ارجاعات حذف شده است.

    می‌توانیم فایل src/main.rs را ویرایش کنیم تا یک آزمون هم در آن باشد:

    src/main.rs

    fn main() {
    println!("Hello Fuchsia!");
}

#[test]
fn it_works() {
    assert_eq!(2 + 2, 4);
}

    علاوه بر workspace استانداردی که ساخته شده است، باید یک فایل .cargo/config.toml بسازیم تا کتابخانه‌های لازم هنگام کامپایل لینک شوند:

    .cargo/config.toml

    [target.x86_64-unknown-fuchsia]

rustflags = [
    "-Lnative=<SDK_PATH>/arch/x64/lib",
    "-Lnative=<SDK_PATH>/arch/x64/sysroot/lib"
]

    توجه: مطمئن شوید که <SDK_PATH> را با مسیر Fuchsia SDK دانلودشده جایگزین می‌کنید.

    این گزینه‌ها موارد زیر را پیکربندی می‌کنند:

    • -Lnative=${SDK_PATH}/arch/${ARCH}/lib: لینک با کتابخانه‌های Fuchsia از SDK
    • -Lnative=${SDK_PATH}/arch/${ARCH}/sysroot/lib: لینک با کتابخانه‌های sysroot Fuchsia از SDK

    در مجموع، پروژه جدید ما به این شکل خواهد بود:

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┣━ src/
┃  ┗━ main.rs
┣━ Cargo.toml
┗━ .cargo/
   ┗━ config.toml

    در نهایت می‌توانیم برنامه Rust خود را به این صورت بسازیم:

    cargo build --target x86_64-unknown-fuchsia

    اکنون یک برنامه Rust در مسیر target/x86_64-unknown-fuchsia/debug/hello_fuchsia داریم که هدف Fuchsia مورد نظر ما را هدف قرار می‌دهد.

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┣━ src/
┃  ┗━ main.rs
┣━ target/
┃  ┗━ x86_64-unknown-fuchsia/
┃     ┗━ debug/
┃        ┗━ hello_fuchsia
┣━ Cargo.toml
┗━ .cargo/
   ┗━ config.toml

    هدف‌گیری Fuchsia با کامپایلری که از سورس ساخته شده است

    روش جایگزین برای روش اول این است که Fuchsia را با استفاده از rustc ساخته‌شده از سورس هدف قرار دهیم.

    پیش از ساخت Rust برای Fuchsia، به یک toolchain از clang نیاز دارید که از Fuchsia هم پشتیبانی کند. یک نسخه جدید (۱۴ به بالا) از clang برای کامپایل Rust برای Fuchsia کافی است.

    اهداف Fuchsia برای x86-64، AArch64 و riscv64gc را می‌توان با پیکربندی زیر در bootstrap.toml فعال کرد:

    [build]
target = ["<host_platform>", "aarch64-unknown-fuchsia", "x86_64-unknown-fuchsia", "riscv64gc-unknown-fuchsia"]

[rust]
lld = true

[llvm]
download-ci-llvm = false

[target.x86_64-unknown-fuchsia]
cc = "clang"
cxx = "clang++"

[target.aarch64-unknown-fuchsia]
cc = "clang"
cxx = "clang++"

[target.riscv64gc-unknown-fuchsia]
cc = "clang"
cxx = "clang++"

    اگرچه الزامی نیست، ممکن است بخواهید برای هدف میزبان خود نیز از clang استفاده کنید:

    [target.<host_platform>]
cc = "clang"
cxx = "clang++"

    به‌طور پیش‌فرض، کامپایلر Rust در بیشتر سیستم‌های UNIX خود را در /usr/local نصب می‌کند. ممکن است بخواهید با تعیین یک prefix سفارشی در bootstrap.toml آن را در مکان دیگری (مثلاً یک دایرکتوری محلی به نام install) نصب کنید:

    [install]
# Make sure to use the absolute path to your install directory
prefix = "<RUST_SRC_PATH>/install"

    سپس باید متغیرهای محیطی زیر پیکربندی شوند. برای مثال، با استفاده از یک اسکریپت به نام config-env.sh:

    # Configure this environment variable to be the path to the downloaded SDK
export SDK_PATH="<SDK path goes here>"

export CFLAGS_aarch64_unknown_fuchsia="--target=aarch64-unknown-fuchsia --sysroot=${SDK_PATH}/arch/arm64/sysroot -I${SDK_PATH}/pkg/fdio/include"
export CXXFLAGS_aarch64_unknown_fuchsia="--target=aarch64-unknown-fuchsia --sysroot=${SDK_PATH}/arch/arm64/sysroot -I${SDK_PATH}/pkg/fdio/include"
export LDFLAGS_aarch64_unknown_fuchsia="--target=aarch64-unknown-fuchsia --sysroot=${SDK_PATH}/arch/arm64/sysroot -L${SDK_PATH}/arch/arm64/lib"
export CARGO_TARGET_AARCH64_UNKNOWN_FUCHSIA_RUSTFLAGS="-C link-arg=--sysroot=${SDK_PATH}/arch/arm64/sysroot -Lnative=${SDK_PATH}/arch/arm64/sysroot/lib -Lnative=${SDK_PATH}/arch/arm64/lib"
export CFLAGS_x86_64_unknown_fuchsia="--target=x86_64-unknown-fuchsia --sysroot=${SDK_PATH}/arch/x64/sysroot -I${SDK_PATH}/pkg/fdio/include"
export CXXFLAGS_x86_64_unknown_fuchsia="--target=x86_64-unknown-fuchsia --sysroot=${SDK_PATH}/arch/x64/sysroot -I${SDK_PATH}/pkg/fdio/include"
export LDFLAGS_x86_64_unknown_fuchsia="--target=x86_64-unknown-fuchsia --sysroot=${SDK_PATH}/arch/x64/sysroot -L${SDK_PATH}/arch/x64/lib"
export CARGO_TARGET_X86_64_UNKNOWN_FUCHSIA_RUSTFLAGS="-C link-arg=--sysroot=${SDK_PATH}/arch/x64/sysroot -Lnative=${SDK_PATH}/arch/x64/sysroot/lib -Lnative=${SDK_PATH}/arch/x64/lib"
export CFLAGS_riscv64gc_unknown_fuchsia="--target=riscv64gc-unknown-fuchsia --sysroot=${SDK_PATH}/arch/riscv64/sysroot -I${SDK_PATH}/pkg/fdio/include"
export CXXFLAGS_riscv64gc_unknown_fuchsia="--target=riscv64gc-unknown-fuchsia --sysroot=${SDK_PATH}/arch/riscv64/sysroot -I${SDK_PATH}/pkg/fdio/include"
export LDFLAGS_riscv64gc_unknown_fuchsia="--target=riscv64gc-unknown-fuchsia --sysroot=${SDK_PATH}/arch/riscv64/sysroot -L${SDK_PATH}/arch/riscv64/lib"
export CARGO_TARGET_RISCV64GC_UNKNOWN_FUCHSIA_RUSTFLAGS="-C link-arg=--sysroot=${SDK_PATH}/arch/riscv64/sysroot -Lnative=${SDK_PATH}/arch/riscv64/sysroot/lib -Lnative=${SDK_PATH}/arch/riscv64/lib"

    در نهایت، کامپایلر Rust را می‌توان ساخت و نصب کرد:

    (source config-env.sh && ./x.py install)

    پس از نصب rustc، می‌توانیم یک دایرکتوری کاری جدید به نام hello_fuchsia همراه با hello_fuchsia/src بسازیم تا در آن کار کنیم:

    mkdir hello_fuchsia
cd hello_fuchsia
mkdir src

    توجه: از این نقطه به بعد، همه دستورها از داخل دایرکتوری hello_fuchsia/ اجرا می‌شوند و برای اختصار، پیشوند hello_fuchsia/ از همه ارجاعات حذف شده است.

    در آنجا می‌توانیم فایل جدیدی به نام src/hello_fuchsia.rs بسازیم:

    src/hello_fuchsia.rs

    fn main() {
    println!("Hello Fuchsia!");
}

#[test]
fn it_works() {
    assert_eq!(2 + 2, 4);
}

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┗━ src/
    ┗━ hello_fuchsia.rs

    با استفاده از rustc که تازه نصب کرده‌اید، می‌توانید با گزینه‌های زیر یک برنامه برای Fuchsia کامپایل کنید:

    • --target x86_64-unknown-fuchsia / --target aarch64-unknown-fuchsia / --target riscv64gc-unknown-fuchsia: پلتفرم Fuchsia مورد نظر شما را هدف قرار می‌دهد
    • -Lnative ${SDK_PATH}/arch/${ARCH}/lib: لینک با کتابخانه‌های Fuchsia از SDK
    • -Lnative ${SDK_PATH}/arch/${ARCH}/sysroot/lib: لینک با کتابخانه‌های sysroot Fuchsia از SDK

    همه را کنار هم بگذاریم:

    # Configure these for the Fuchsia target of your choice
TARGET_ARCH="<x86_64-unknown-fuchsia|aarch64-unknown-fuchsia|riscv64gc-unknown-fuchsia>"
ARCH="<x64|aarch64|riscv64>"

rustc \
    --target ${TARGET_ARCH} \
    -Lnative=${SDK_PATH}/arch/${ARCH}/lib \
    -Lnative=${SDK_PATH}/arch/${ARCH}/sysroot/lib \
    --out-dir bin src/hello_fuchsia.rs

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┣━ src/
┃   ┗━ hello_fuchsia.rs
┗━ bin/
   ┗━ hello_fuchsia

    ساخت یک بسته Fuchsia

    پیش از ادامه، ساختار دایرکتوری خود را دوباره بررسی کنید:

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┣━ src/                         (if using rustc)
┃   ┗━ hello_fuchsia.rs         ...
┣━ bin/                         ...
┃  ┗━ hello_fuchsia             ...
┣━ src/                         (if using cargo)
┃  ┗━ main.rs                   ...
┗━ target/                      ...
   ┗━ x86_64-unknown-fuchsia/   ...
      ┗━ debug/                 ...
         ┗━ hello_fuchsia       ...

    اکنون که برنامه Rust ساخته شده است، می‌توانیم به سراغ ساخت یک بسته Fuchsia برویم. در Fuchsia، بسته واحد توزیع نرم‌افزار است. باید یک دایرکتوری بسته جدید بسازیم که فایل‌هایی مانند برنامه نهایی و هر داده‌ای که ممکن است لازم داشته باشد را در آن قرار دهیم.

    برای شروع، دایرکتوری‌های pkg و pkg/meta را بسازید:

    mkdir pkg
mkdir pkg/meta

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┗━ pkg/
   ┗━ meta/

    حالا فایل‌های زیر را در آن بسازید:

    pkg/meta/package

    {
  "name": "hello_fuchsia",
  "version": "0"
}

    فایل package نام و شماره نسخه بسته ما را توصیف می‌کند. هر بسته باید یکی از این فایل‌ها را داشته باشد.

    pkg/hello_fuchsia.manifest در صورت استفاده از cargo

    bin/hello_fuchsia=target/x86_64-unknown-fuchsia/debug/hello_fuchsia
lib/ld.so.1=<SDK_PATH>/arch/x64/sysroot/dist/lib/ld.so.1
lib/libfdio.so=<SDK_PATH>/arch/x64/dist/libfdio.so
meta/package=pkg/meta/package
meta/hello_fuchsia.cm=pkg/meta/hello_fuchsia.cm

    pkg/hello_fuchsia.manifest در صورت استفاده از rustc

    bin/hello_fuchsia=bin/hello_fuchsia
lib/ld.so.1=<SDK_PATH>/arch/x64/sysroot/dist/lib/ld.so.1
lib/libfdio.so=<SDK_PATH>/arch/x64/dist/libfdio.so
meta/package=pkg/meta/package
meta/hello_fuchsia.cm=pkg/meta/hello_fuchsia.cm

    توجه: مسیرهای نسبی manifest از دایرکتوری کاری ffx حل می‌شوند. مطمئن شوید که <SDK_PATH> را با مسیر SDK دانلودشده جایگزین می‌کنید.

    فایل .manifest برای توصیف محتویات بسته استفاده می‌شود و مکان هر فایل را هنگام نصب به مکان آن در سیستم فایل ربط می‌دهد. ورودی bin/hello_fuchsia= بسته به اینکه برنامه Rust شما چگونه ساخته شده است متفاوت خواهد بود، پس مطابق آن انتخاب کنید.

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┗━ pkg/
   ┣━ meta/
   ┃  ┗━ package
   ┗━ hello_fuchsia.manifest

    ساخت یک کامپوننت Fuchsia

    در Fuchsia، کامپوننت‌ها به یک manifest کامپوننت نیاز دارند که به زبان نشانه‌گذاری Fuchsia به نام CML نوشته می‌شود. سایت توسعه‌دهندگان Fuchsia یک مرور کلی از CML و یک مرجع قالب فایل دارد. در اینجا یک نمونهٔ ساده را می‌بینید که می‌تواند برنامهٔ تک‌فایلی ما را اجرا کند:

    pkg/hello_fuchsia.cml

    {
    include: [ "syslog/client.shard.cml" ],
    program: {
        runner: "elf",
        binary: "bin/hello_fuchsia",
    },
}

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┗━ pkg/
   ┣━ meta/
   ┃  ┗━ package
   ┣━ hello_fuchsia.manifest
   ┗━ hello_fuchsia.cml

    اکنون می‌توانیم آن CML را به یک manifest کامپوننت کامپایل کنیم:

    ${SDK_PATH}/tools/${ARCH}/cmc compile \
    pkg/hello_fuchsia.cml \
    --includepath ${SDK_PATH}/pkg \
    -o pkg/meta/hello_fuchsia.cm

    توجه: --includepath به کامپایلر می‌گوید که includeهای CML ما را از کجا پیدا کند. در مورد ما فقط از syslog/client.shard.cml استفاده می‌کنیم.

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┗━ pkg/
   ┣━ meta/
   ┃  ┣━ package
   ┃  ┗━ hello_fuchsia.cm
   ┣━ hello_fuchsia.manifest
   ┗━ hello_fuchsia.cml

    ساختن بسته Fuchsia

    سپس یک manifest بسته را مطابق manifest خود می‌سازیم:

    ${SDK_PATH}/tools/${ARCH}/ffx package build \
    --api-level $(${SDK_PATH}/tools/${ARCH}/ffx --machine json version | jq .tool_version.api_level) \
    --out pkg/hello_fuchsia_manifest \
    pkg/hello_fuchsia.manifest

    این دستور pkg/hello_fuchsia_manifest/ را تولید می‌کند که یک manifest بسته است و می‌توانیم آن را مستقیماً در یک مخزن منتشر کنیم.

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┗━ pkg/
   ┣━ meta/
   ┃  ┣━ package
   ┃  ┗━ hello_fuchsia.cm
   ┣━ hello_fuchsia_manifest/
   ┃  ┗━ ...
   ┣━ hello_fuchsia.manifest
   ┣━ hello_fuchsia.cml
   ┗━ hello_fuchsia_package_manifest

    اکنون آماده انتشار بسته هستیم.

    انتشار یک بسته Fuchsia

    با آماده بودن manifest بسته و manifest کامپوننت، اکنون می‌توانیم بسته خود را منتشر کنیم. گام نخست ایجاد یک مخزن بسته Fuchsia است تا بسته را در آن منتشر کنیم.

    ایجاد یک مخزن بسته Fuchsia

    مخزن را می‌توانیم با دستور زیر راه‌اندازی کنیم:

    ${SDK_PATH}/tools/${ARCH}/ffx repository create pkg/repo

    ساختار فعلی دایرکتوری

    hello_fuchsia/
┗━ pkg/
   ┣━ meta/
   ┃  ┣━ package
   ┃  ┗━ hello_fuchsia.cm
   ┣━ hello_fuchsia_manifest/
   ┃  ┗━ ...
   ┣━ repo/
   ┃  ┗━ ...
   ┣━ hello_fuchsia.manifest
   ┣━ hello_fuchsia.cml
   ┗━ hello_fuchsia_package_manifest

    انتشار بسته Fuchsia در مخزن

    بسته جدید خود را می‌توانیم با دستور زیر در آن مخزن منتشر کنیم:

    ${SDK_PATH}/tools/${ARCH}/ffx repository publish \
    --package pkg/hello_fuchsia_package_manifest \
    pkg/repo

    اجرای یک کامپوننت Fuchsia روی شبیه‌ساز

    در این مرحله آماده‌ایم کامپوننت Fuchsia خود را اجرا کنیم. برای مرجع، ساختار نهایی دایرکتوری ما به این شکل خواهد بود:

    ساختار نهایی دایرکتوری

    hello_fuchsia/
┣━ src/                         (if using rustc)
┃   ┗━ hello_fuchsia.rs         ...
┣━ bin/                         ...
┃  ┗━ hello_fuchsia             ...
┣━ src/                         (if using cargo)
┃  ┗━ main.rs                   ...
┣━ target/                      ...
┃  ┗━ x86_64-unknown-fuchsia/   ...
┃     ┗━ debug/                 ...
┃        ┗━ hello_fuchsia       ...
┗━ pkg/

   ┃  ┣━ package

   ┃  ┗━ ...
   ┣━ repo/
   ┃  ┗━ ...

   ┣━ hello_fuchsia.cml
   ┗━ hello_fuchsia_package_manifest

    راه‌اندازی شبیه‌ساز Fuchsia

    یک شبیه‌ساز Fuchsia را در یک ترمینال جدید با دستورهای زیر راه‌اندازی کنید:

    ${SDK_PATH}/tools/${ARCH}/ffx product-bundle get workstation_eng.qemu-${ARCH}
${SDK_PATH}/tools/${ARCH}/ffx emu start workstation_eng.qemu-${ARCH} --headless

    مشاهده لاگ‌های شبیه‌ساز

    پس از اجرای شبیه‌ساز، یک ترمینال جداگانه باز کنید تا لاگ‌های شبیه‌ساز را مشاهده کنید:

    در ترمینال جداگانه

    ${SDK_PATH}/tools/${ARCH}/ffx log \
    --since now

    سرو کردن یک بسته Fuchsia

    اکنون یک سرور مخزن بسته را راه‌اندازی کنید تا بسته ما را به شبیه‌ساز ارائه دهد:

    ${SDK_PATH}/tools/${ARCH}/ffx repository server start \
    --background --repository hello-fuchsia --repo-path pkg-repo

    پس از آنکه سرور مخزن بالا آمد و در حال اجراست، آن را در سیستم Fuchsia هدف که در شبیه‌ساز اجرا می‌شود ثبت کنید:

    ${SDK_PATH}/tools/${ARCH}/ffx target repository register \
    --repository hello-fuchsia

    اجرای یک کامپوننت Fuchsia

    در پایان، کامپوننت را اجرا کنید:

    ${SDK_PATH}/tools/${ARCH}/ffx component run \
    /core/ffx-laboratory:hello_fuchsia \
    fuchsia-pkg://hello-fuchsia/hello_fuchsia_manifest#meta/hello_fuchsia.cm

    برای اجراهای مجدد کامپوننت، ممکن است لازم باشد آرگومان --recreate نیز داده شود.

    ${SDK_PATH}/tools/${ARCH}/ffx component run \
    --recreate \
    /core/ffx-laboratory:hello_fuchsia \
    fuchsia-pkg://hello-fuchsia/hello_fuchsia_manifest#meta/hello_fuchsia.cm

    افزونه‌های .gitignore

    به‌صورت اختیاری می‌توانیم فایل .gitignore را بسازیم یا گسترش دهیم تا فایل‌ها و دایرکتوری‌هایی که ردیابی‌شان فایده‌ای ندارد نادیده گرفته شوند:

    pkg/repo
pkg/meta/hello_fuchsia.cm
pkg/hello_fuchsia_manifest

    آزمون

    اجرای آزمون‌های واحد

    آزمون‌ها را می‌توان مانند یک برنامه معمولی اجرا کرد.

    • اگر از cargo استفاده می‌کنید، کافی است test --no-run را به فراخوانی cargo بدهید و سپس بسته Fuchsia را دوباره بسته‌بندی و اجرا کنید. در مثال قبلی ما، این کار به شکل cargo test --target x86_64-unknown-fuchsia --no-run خواهد بود و مسیر فایل اجرایی که در خط Executable unittests src/main.rs (target/x86_64-unknown-fuchsia/debug/deps/hello_fuchsia-<HASH>) پیدا می‌شود باید در pkg/hello_fuchsia.manifest قرار گیرد.

    • اگر از rustc کامپایل‌شده استفاده می‌کنید، کافی است --test را به فراخوانی rustc بدهید و سپس بسته Fuchsia را دوباره بسته‌بندی و اجرا کنید.

    harness آزمون، آزمون‌های واحد مربوط را اجرا می‌کند.

    اغلب هنگام آزمون ممکن است بخواهید آرگومان‌های خط فرمان اضافی را به برنامه خود بدهید. آرگومان‌های اضافی را می‌توان در manifest کامپوننت تعیین کرد:

    pkg/hello_fuchsia.cml

    {
    include: [ "syslog/client.shard.cml" ],
    program: {
        runner: "elf",
        binary: "bin/hello_fuchsia",
        args: ["it_works"],
    },
}

    این کار آرگومان it_works را به برنامه می‌دهد و آزمون‌ها را فقط به آن‌هایی که با این الگو مطابقت دارند محدود می‌کند. گزینه‌های پیکربندی بسیار بیشتری در CML در دسترس است، از جمله متغیرهای محیطی. مستندات بیشتر در سایت توسعه‌دهندگان Fuchsia موجود است.

    اجرای مجموعه آزمون‌های کامپایلر

    دستورهای این بخش فرض می‌کنند که از داخل نسخه محلی سورس Rust شما اجرا می‌شوند:

    cd ${RUST_SRC_PATH}

    برای اجرای مجموعه آزمون‌های Rust روی یک دستگاه Fuchsia شبیه‌سازی‌شده، باید یک نسخه از Fuchsia SDK را هم دانلود کنید. حداقل نسخه SDK که در حال حاضر پشتیبانی می‌شود 20.20240412.3.1 است.

    test runner مربوط به Fuchsia با شبیه‌ساز Fuchsia تعامل می‌کند و در src/ci/docker/scripts/fuchsia-test-runner.py قرار دارد. نخست، متغیرهای زیر را به config-env.sh موجود خود اضافه کنید:

    # TEST_TOOLCHAIN_TMP_DIR can point anywhere, but it:
#  - must be less than 108 characters, otherwise qemu can't handle the path
#  - must be consistent across calls to this file (don't use `mktemp -d` here)
export TEST_TOOLCHAIN_TMP_DIR="/tmp/rust-tmp"

# Keep existing contents of `config-env.sh` from earlier, including SDK_PATH

    سپس می‌توانیم از این اسکریپت برای راه‌اندازی محیط آزمون استفاده کنیم:

    ( \
    source config-env.sh &&                                                  \
    src/ci/docker/scripts/fuchsia-test-runner.py start                       \
    --rust-build ${RUST_SRC_PATH}/build                                      \
    --sdk ${SDK_PATH}                                                        \
    --target {x86_64-unknown-fuchsia|aarch64-unknown-fuchsia|riscv64gc-unknown-fuchsia} \
    --verbose                                                                \
)

    که در آن ${RUST_SRC_PATH}/build همان build-dir تعیین‌شده در bootstrap.toml است.

    پس از راه‌اندازی محیط، می‌توانیم آزمون‌هایمان را مثل همیشه با x.py اجرا کنیم. اسکریپت test runner آزمون‌های کامپایل‌شده را روی یک دستگاه Fuchsia شبیه‌سازی‌شده اجرا می‌کند. برای اجرای مجموعه کامل آزمون‌های tests/ui:

    ( \
    source config-env.sh &&                                                   \
    ./x.py                                                                    \
    --config bootstrap.toml                                                   \
    --stage=2                                                                 \
    test tests/ui                                                             \
    --target x86_64-unknown-fuchsia                                           \
    --run=always                                                              \
    --test-args --target-rustcflags                                           \
    --test-args -Lnative=${SDK_PATH}/arch/{x64|arm64}/sysroot/lib             \
    --test-args --target-rustcflags                                           \
    --test-args -Lnative=${SDK_PATH}/arch/{x64|arm64}/lib                     \
    --test-args --target-rustcflags                                           \
    --test-args -Clink-arg=--undefined-version                                \
    --test-args --remote-test-client                                          \
    --test-args src/ci/docker/scripts/fuchsia-test-runner.py                  \
)

    به‌طور پیش‌فرض، x.py فایل‌های دودویی آزمون را با panic=unwind کامپایل می‌کند. اگر toolchain خود را با -Cpanic=abort ساخته‌اید، باید به x.py بگویید که فایل‌های دودویی آزمون را هم با panic=abort کامپایل کند:

        --test-args --target-rustcflags                                           \
    --test-args -Cpanic=abort                                                 \
    --test-args --target-rustcflags                                           \
    --test-args -Zpanic_abort_tests                                           \

    پس از پایان آزمون، می‌توان از test runner برای توقف محیط آزمون استفاده کرد:

    src/ci/docker/scripts/fuchsia-test-runner.py stop

    اشکال‌زدایی

    zxdb

    اشکال‌زدایی کامپوننت‌هایی که روی شبیه‌ساز Fuchsia اجرا می‌شوند با اشکال‌زدای حالت کنسول، یعنی zxdb، امکان‌پذیر است. نشان می‌دهیم که چگونه مسیرهای لازم برای symbolها را متصل کنیم تا کامپوننت hello-fuchsia خود را اشکال‌زدایی کنیم.

    اتصال zxdb

    در یک ترمینال جداگانه، دستور زیر را از دایرکتوری hello_fuchsia اجرا کنید تا zxdb راه‌اندازی شود:

    در ترمینال جداگانه

    ${SDK_PATH}/tools/${ARCH}/ffx debug connect -- \
    --symbol-path target/x86_64-unknown-fuchsia/debug
    • --symbol-path مسیرهای لازم symbol را دریافت می‌کند که برای گام‌به‌گام اجرا کردن برنامه ضروری هستند.

    بخش «نمایش کد منبع در zxdb» توضیح می‌دهد چگونه می‌توانید کد منبع Rust و/یا Fuchsia را در نشست اشکال‌زدایی خود نمایش دهید.

    استفاده از zxdb

    پس از راه‌اندازی، پنجره زیر به شما نشان داده می‌شود:

    ${SDK_PATH}/tools/${ARCH}/ffx component run \
    --recreate \
    fuchsia-pkg://hello-fuchsia/hello_fuchsia_manifest#meta/hello_fuchsia.cm

    پس از اجرای کامپوننت، پنجره zxdb ما همان‌طور که می‌خواستیم اجرا را در main متوقف می‌کند:

    نمایش کد منبع در zxdb

    به‌طور پیش‌فرض، اشکال‌زدا هنگام اشکال‌زدایی نمی‌تواند کد منبع را نمایش دهد. برای کد کاربر خودمان، با اشاره دادن اشکال‌زدا به فایل دودویی debug از طریق آرگومان --symbol-path کد منبع را نمایش دادیم. برای نمایش کد منبع کتابخانه‌ها در اشکال‌زدا، باید با --build-dir مسیرهای منبع را مشخص کنید. برای مثال، برای نمایش کد منبع Rust و Fuchsia:

    ${SDK_PATH}/tools/${ARCH}/ffx debug connect -- \
    --symbol-path target/x86_64-unknown-fuchsia/debug \
    --build-dir ${RUST_SRC_PATH}/rust \
    --build-dir ${FUCHSIA_SRC_PATH}/fuchsia/out/default
    • --build-dir به مسیرهای کد منبع لینک می‌دهد؛ این مسیرها برای اشکال‌زدایی الزاماً لازم نیستند، اما برای نمایش کد منبع در zxdb مفیدند.

    لینک دادن به یک checkout از Fuchsia می‌تواند به اشکال‌زدایی کتابخانه‌های Fuchsia، مانند fdio، کمک کند.

    اشکال‌زدایی مجموعه آزمون‌های کامپایلر

    اشکال‌زدایی مجموعه آزمون‌های کامپایلر به پیکربندی ویژه‌ای نیاز دارد:

    نخست باید zxdb را درست پیکربندی کنیم تا بتواند symbolهای اشکال‌زدایی و اطلاعات کد منبع آزمون ما را پیدا کند. test runner می‌تواند این کار را برای ما با دستور زیر انجام دهد:

    src/ci/docker/scripts/fuchsia-test-runner.py debug                            \
    --rust-src ${RUST_SRC_PATH}                                               \
    --fuchsia-src ${FUCHSIA_SRC_PATH}                                         \
    --test ${TEST}

    که در آن ${TEST} نسبت به دایرکتوری tests در Rust است (مثلاً ui/abi/...).

    این کار یک نشست zxdb را راه‌اندازی می‌کند که برای آزمونِ در حال اجرا به‌درستی پیکربندی شده است. هر سه آرگومان اختیاری‌اند، بنابراین اگر نسخه‌ای از --fuchsia-src را دانلود نکرده‌اید می‌توانید آن را حذف کنید. حالا زمان مناسبی است که breakpointهای دلخواه را تنظیم کنید، مثلاً b main.

    سپس باید به x.py بگوییم که symbolهای اشکال‌زدایی فایل‌های دودویی مجموعه آزمون را بهینه‌سازی نکند و حذف نکند. این کار را می‌توان با دادن چند آرگومان جدید به rustc از طریق فراخوانی x.py انجام داد. فراخوانی کامل چنین است:

    ( \
    source config-env.sh &&                                                   \
    ./x.py                                                                    \
    --config bootstrap.toml                                                      \
    --stage=2                                                                 \
    test tests/${TEST}                                                        \
    --target x86_64-unknown-fuchsia                                           \
    --run=always                                                              \
    --test-args --target-rustcflags                                           \
    --test-args -Lnative=${SDK_PATH}/arch/{x64|arm64}/sysroot/lib             \
    --test-args --target-rustcflags                                           \
    --test-args -Lnative=${SDK_PATH}/arch/{x64|arm64}/lib                     \
    --test-args --target-rustcflags                                           \
    --test-args -Clink-arg=--undefined-version                                \
    --test-args --target-rustcflags                                           \
    --test-args -Cdebuginfo=2                                                 \
    --test-args --target-rustcflags                                           \
    --test-args -Copt-level=0                                                 \
    --test-args --target-rustcflags                                           \
    --test-args -Cstrip=none                                                  \
    --test-args --remote-test-client                                          \
    --test-args src/ci/docker/scripts/fuchsia-test-runner.py                  \
)

    اگر toolchain خود را با panic=abort ساخته‌اید، حتماً پرچم‌های قبلی را هم بیاورید تا فایل‌های دودویی آزمون شما نیز با panic=abort کامپایل شوند.

    با اجرای این دستور، فایل دودویی مجموعه آزمون اجرا می‌شود و zxdb به آن متصل می‌شود و هر symbol اشکال‌زدایی مرتبط را بارگذاری می‌کند.
