    s390x-unknown-linux-gnu

    سطح (Tier): ۲ (همراه با ابزارهای میزبان)

    اهداف معماری IBM z/Architecture ‏(s390x)، از جمله IBM Z و LinuxONE، که Linux روی آن‌ها اجرا می‌شود.

    نگهدارندگان هدف

    @uweigand @cuviper

    الزامات

    این هدف به موارد زیر نیاز دارد:

    • هستهٔ Linux نسخهٔ 3.2 یا بالاتر
    • glibc نسخهٔ 2.17 یا بالاتر

    کدی که این هدف تولید می‌کند از ISA مربوط به z/Architecture استفاده می‌کند، با فرض حداقل سطح معماری z10 (ویرایش هشتم «اصول عملکرد z/Architecture»)، و با ABI از نوع ELF برای s390x سازگار است.

    مواد مرجع:

    • اصول عملکرد z/Architecture (Principles of Operation)
    • رابط دودویی برنامه کاربردی ELF برای z/Architecture

    ساخت هدف

    این هدف از طریق rustup توزیع می‌شود و جز این به پیکربندی خاصی نیاز ندارد.

    اگر به هر دلیلی لازم است Rust خودتان را بسازید، می‌توانید هدف را در bootstrap.toml فعال کنید. برای مثال:

    [build]
target = ["s390x-unknown-linux-gnu"]

    ساخت برنامه‌های Rust

    روی میزبان Linux از نوع s390x، هدف s390x-unknown-linux-gnu باید به‌طور خودکار نصب شود و به‌صورت پیش‌فرض مورد استفاده قرار بگیرد.

    روی میزبانی که s390x نیست، هدف را اضافه کنید:

    rustup target add s390x-unknown-linux-gnu

    سپس crateها را با دستور زیر cross-compile کنید:

    cargo build --target s390x-unknown-linux-gnu

    آزمون

    برای آزمون و اجرای این هدف هیچ الزام خاصی وجود ندارد. برای آزمون ساخت‌های cross روی میزبان، لطفاً به بخش «toolchainهای cross-compilation و کد C» در ادامه مراجعه کنید.

    اگر می‌خواهید آزمون بومی انجام دهید اما ماشین s390x اختصاصی خودتان را ندارید، چند راه برای دسترسی به چنین ماشینی وجود دارد:

    • IBM LinuxONE Community Cloud یک پورتال سلف‌سرویس ارائه می‌کند که در آن می‌توانید نمونه‌های ماشین مجازی s390x بسازید. این نمونه‌ها برای استفاده موقت در نظر گرفته شده‌اند (حداکثر ۱۲۰ روز).

    • IBM LinuxONE Open Source Cloud دسترسی دائمی به ماشین‌های s390x فراهم می‌کند. این کار به تأیید IBM نیاز دارد که معمولاً اگر قصد داشته باشید از ماشین برای کار روی یک پروژه متن‌باز مرتبط با اکوسیستم IBM Z استفاده کنید، داده می‌شود - کامپایلر Rust قطعاً شرایط لازم را دارد.

    toolchainهای cross-compilation و کد C

    کد Rust که با این هدف ساخته شده باشد با کد C که با GCC یا Clang و با سه‌گانه هدف s390x-unknown-linux-gnu کامپایل شده سازگار است (چه به‌صورت بومی و چه با cross-compilation).

    روی Ubuntu می‌توان یک cross-toolchain برای s390x را با دستور زیر نصب کرد:

    apt install gcc-s390x-linux-gnu g++-s390x-linux-gnu libc6-dev-s390x-cross

    بسته به سیستم شما، ممکن است لازم باشد هدف را طوری پیکربندی کنید که از لینکر GNU GCC استفاده کند. برای استفاده از آن، موارد زیر را به .cargo/config.toml خود اضافه کنید:

    [target.s390x-unknown-linux-gnu]
linker = "s390x-linux-gnu-gcc"

    اگر toolchain با نام s390x-linux-gnu-* در PATH شما نیست، ممکن است لازم باشد تنظیمات بیشتری را پیکربندی کنید:

    [target.s390x-unknown-linux-gnu]
# Adjust the paths to point at your toolchain
cc = "/TOOLCHAIN_PATH/bin/s390x-linux-gnu-gcc"
cxx = "/TOOLCHAIN_PATH/bin/s390x-linux-gnu-g++"
ar = "/TOOLCHAIN_PATH/bin/s390x-linux-gnu-ar"
ranlib = "/TOOLCHAIN_PATH/bin/s390x-linux-gnu-ranlib"
linker = "/TOOLCHAIN_PATH/bin/s390x-linux-gnu-gcc"

    برای آزمون فایل‌های دودویی cross-compile شده روی میزبانی که s390x نیست، می‌توانید از qemu استفاده کنید. روی Ubuntu می‌توان یک شبیه‌ساز s390x را با دستور زیر به دست آورد:

    apt install qemu-system-s390x

    سپس در .cargo/config.toml مقدار runner را تنظیم کنید:

    [target.s390x-unknown-linux-gnu]
runner = "qemu-s390x-static -L /usr/s390x-linux-gnu"
