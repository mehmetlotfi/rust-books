    wasm32-unknown-emscripten

    سطح: 2

    هدف wasm32-unknown-emscripten یک هدف کامپایل WebAssembly است که از toolchain کامپایلر Emscripten استفاده می‌کند. Emscripten یک toolchain برای C/C++ است که طراحی شده تا انتقال کد C/C++ نوشته‌شده برای Linux به اجرا روی وب یا در دیگر محیط‌های اجرای JavaScript مانند Node را تا حد امکان آسان کند. بنابراین پیاده‌سازی‌های libc و libstd سازگار با POSIX (musl) و بسیاری از APIهای Linux، دسترسی به APIهای OpenGL و SDL و توانایی اجرای کد دلخواه JavaScript را ارائه می‌دهد؛ همگی بر پایهٔ APIهای وب با استفاده از کد چسب JS. با هدف wasm32-unknown-emscripten، کد Rust می‌تواند با اکوسیستم Emscripten، کد C/C++ و JS و APIهای وب تعامل داشته باشد.

    یکی از کاربران فعلی این هدف پروژهٔ pyodide است که یک runtime پایتون را در WebAssembly با استفاده از Emscripten فراهم می‌کند و ماژول‌های افزونهٔ پایتون نوشته‌شده با Rust را برای هدف wasm32-unknown-emscripten کامپایل می‌کند.

    اگر می‌خواهید یک فایل دودویی WebAssembly مستقل تولید کنید که به APIهای وب یا کتابخانهٔ استاندارد Rust نیاز نداشته باشد، هدف wasm32-unknown-unknown ممکن است برایتان مناسب‌تر باشد. با این حال، wasm32-unknown-unknown تعامل با کد C/C++ را (به‌آسانی) پشتیبانی نمی‌کند. اگر می‌خواهید با این هدف با JavaScript تعامل داشته باشید، به crate با نام wasm-bindgen مراجعه کنید.

    مانند Emscripten، اهداف WASI یعنی wasm32-wasip1، wasm32-wasip2 و wasm32-wasip3 نیز دسترسی به محیط میزبان را فراهم می‌کنند، تعامل با C/C++ (و زبان‌های دیگر) را پشتیبانی می‌کنند و بیشتر کتابخانهٔ استاندارد Rust را پشتیبانی می‌کنند. اگرچه اهداف WASI میان میزبان‌های مختلف (وب و غیر وب) قابل‌حمل هستند، WASI راه استانداردی برای دسترسی به APIهای وب ندارد، در حالی که Emscripten می‌تواند JS دلخواه را از WASM اجرا کند و به بسیاری از APIهای وب دسترسی داشته باشد. اگر فقط وب را هدف قرار می‌دهید و نیاز به دسترسی به APIهای وب دارید، هدف wasm32-unknown-emscripten ممکن است ارجح باشد.

    الزامات

    این هدف به‌صورت متقاطع کامپایل می‌شود. toolchain کامپایلر Emscripten یعنی emcc باید نصب باشد تا فایل‌های دودویی WASM برای این هدف پیوند شوند. می‌توانید emcc را با این دستورها نصب کنید:

    git clone https://github.com/emscripten-core/emsdk.git --depth 1
./emsdk/emsdk install latest
./emsdk/emsdk activate latest
source ./emsdk/emsdk_env.sh

    برای جزئیات و دستورالعمل‌های بیشتر به https://emscripten.org/docs/getting_started/downloads.html مراجعه کنید.

    ساخت هدف

    ساخت این هدف از این طریق ممکن است:

    • هدف wasm32-unknown-emscripten را برای ساخته شدن پیکربندی کنید.
    • مطمئن شوید backend هدف WebAssembly در LLVM غیرفعال نشده است.

    همهٔ این‌ها از طریق گزینه‌های bootstrap.toml کنترل می‌شوند. باید بتوان این هدف را روی هر پلتفرمی ساخت. یک پیکربندی نمونهٔ حداقلی چنین است:

    [llvm]
targets = "WebAssembly"

[build]
build-stage = 1
target = ["wasm32-unknown-emscripten"]

    ساخت برنامه‌های Rust

    برنامه‌های Rust را می‌توان با افزودن این هدف از طریق rustup کامپایل کرد:

    $ rustup target add wasm32-unknown-emscripten

    و سپس با هدف کامپایل کرد:

    $ rustc foo.rs --target wasm32-unknown-emscripten
$ file foo.wasm

    کامپایل متقاطع

    این هدف را می‌توان از هر میزبانی به‌صورت متقاطع کامپایل کرد.

    سازگاری ABI در Emscripten

    toolchain کامپایلر Emscripten از طرح نسخه‌گذاری معنایی (semantic versioning) پیروی نمی‌کند که به‌روشنی نشان دهد چه زمانی می‌توان تغییرات ناسازگار در ABI ایجاد کرد. علاوه بر این، Emscripten حتی برای یک نسخهٔ واحد از Emscripten، بسته به پرچم‌های پیوندگر مورد استفاده، ABIهای متفاوت بسیاری ارائه می‌دهد؛ مثلاً -fwasm-exceptions و -sWASM_BIGINT. اگر ABIها مطابقت نداشته باشند، کد شما ممکن است رفتار تعریف‌نشده بروز دهد.

    برای اطمینان از اینکه ABIهای کد Rust شما، کتابخانهٔ استاندارد Rust و دیگر کدهای کامپایل‌شده برای Emscripten همگی با هم مطابقت دارند، باید کتابخانهٔ استاندارد Rust را با نسخه و تنظیمات محلی Emscripten خود دوباره بسازید:

    cargo +nightly -Zbuild-std build

    اگر باز هم می‌خواهید از std از پیش کامپایل‌شده در rustup استفاده کنید، باید مطمئن شوید Emscripten محلی شما با نسخهٔ مورد استفادهٔ Rust مطابقت دارد و مراقب هر -C link-argای باشید که کد Rust خود را با آن کامپایل کرده‌اید.

    آزمون

    این هدف در CI مخزن rust-lang/rust به‌طور گسترده آزمون نمی‌شود. می‌توان آن را به‌صورت محلی آزمود، برای مثال با:

    EMCC_CFLAGS="-s MAXIMUM_MEMORY=2GB" ./x.py test --target wasm32-unknown-emscripten --skip src/tools/linkchecker

    برای اجرای این آزمون‌ها، هم emcc و هم node باید در $PATH شما باشند. می‌توانید node را مثلاً با nvm و با پیروی از دستورالعمل‌های https://github.com/nvm-sh/nvm#install–update-script نصب کنید.

    اگر نیاز دارید سازگاری WebAssembly را به‌طور کلی آزمون کنید، توصیه می‌شود به‌جای آن هدف wasm32-wasip1 را آزمون کنید.

    کامپایل شرطی کد

    توصیه می‌شود کد را برای این هدف با این شکل به‌صورت شرطی کامپایل کنید:

    #[cfg(target_os = "emscripten")]

    گاهی ممکن است لازم باشد کد را برای اهداف WASM که از emscripten استفاده نمی‌کنند به‌صورت شرطی کامپایل کرد، که با این شکل ممکن است:

    #[cfg(all(target_family = "wasm", not(target_os = "emscripten)))]

    قابلیت‌های فعال‌شدهٔ WebAssembly

    WebAssembly یک استاندارد در حال تکامل است که با گذشت زمان قابلیت‌های جدیدی مانند دستورالعمل‌های جدید به آن اضافه می‌کند. مجموعهٔ پیش‌فرض قابلیت‌های WebAssembly پشتیبانی‌شده در این هدف نیز با گذشت زمان تغییر خواهد کرد. هدف wasm32-unknown-emscripten تنظیمات پیش‌فرض LLVM را به ارث می‌برد که معمولاً، اما نه لزوماً، با تنظیمات پیش‌فرض Emscripten نیز مطابقت دارد. در زمان پیوند، emcc پیوندگر را طوری پیکربندی می‌کند که از تنظیمات Emscripten استفاده کند.

    برای اینکه Rust به‌طور پیش‌فرض کدام قابلیت‌های WebAssembly را فعال می‌کند، چگونه می‌توان قابلیت‌ها را غیرفعال کرد و چگونه می‌توان کد Rust را بر اساس قابلیت‌های فعال‌شده به‌صورت شرطی کامپایل کرد، به مستندات هدف wasm32-unknown-unknown مراجعه کنید.

    توجه کنید که کد Rust که برای wasm32-unknown-emscripten کامپایل می‌شود در حال حاضر به‌طور پیش‌فرض -fwasm-exceptions (استثناهای قدیمی WASM) را فعال می‌کند، مگر اینکه کد Rust با -Cpanic=abort کامپایل شود.

    برای اطمینان از اینکه قابلیت‌های فعال‌شده باعث ناسازگاری ABI میان کد Rust شما، کتابخانهٔ استاندارد از پیش کامپایل‌شدهٔ Rust و دیگر کدهای کامپایل‌شده برای Emscripten نمی‌شوند، به بخش سازگاری ABI در Emscripten مراجعه کنید.
