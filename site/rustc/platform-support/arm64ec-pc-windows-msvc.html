    arm64ec-pc-windows-msvc

    Tier: 2

    Arm64EC («سازگار با شبیه‌سازی»، Emulation Compatible) برای برنامه‌های با معماری ترکیبی (AArch64 و x86_64) روی Windows 11 مبتنی بر AArch64. به https://learn.microsoft.com/en-us/windows/arm/arm64ec مراجعه کنید.

    نگهدارندگان هدف

    @dpaoliello

    الزامات

    کتابخانه‌های ایستا و پویا و فایل‌های اجرایی Arm64EC را می‌سازد که روی دستگاه‌های Windows 11 مبتنی بر AArch64 قابل اجرا هستند. کتابخانه‌های ایستای Arm64EC را می‌توان به کتابخانه‌های پویا و فایل‌های اجرایی Arm64X نیز پیوند داد.

    تنها بک‌اند پشتیبانی‌شده LLVM نسخهٔ 18 یا بالاتر است:

    • نسخهٔ 18.1.0 پشتیبانی اولیه از Arm64EC را اضافه کرد.
    • نسخهٔ 18.1.2 تولید کتابخانهٔ import را اصلاح کرد (برای پشتیبانی از raw-dylib لازم است).
    • نسخهٔ 18.1.4 مشکل پیوند (linking) برخی intrinsic‌ها را که در compiler_builtins پیاده‌سازی شده‌اند رفع کرد.

    Visual Studio 2022 (یا بالاتر) با مؤلفهٔ «ARM64/ARM64EC built tools» و Windows 11 SDK لازم است.

    استفادهٔ مجدد از کد معماری‌های دیگر: x86_64 یا AArch64؟

    Arm64EC از arm64ec به‌عنوان target_arch خود استفاده می‌کند، اما در بیشتر موارد می‌توان کدِ وابسته به معماریِ موجود را دوباره به کار برد. بهترین مدل ذهنی برای تصمیم‌گیری دربارهٔ اینکه کدام معماری را دوباره به کار ببریم، این است که Arm64EC را فرایندی x86_64 تصور کنیم که اتفاقاً از مجموعه دستورالعمل AArch64 استفاده می‌کند (با چند قید و شرط) و ABI کاملاً سفارشی دارد.

    برای عملی کردن این مدل:

    • Arm64EC با سیستم‌عامل، فرایندهای دیگر و DLL‌های دیگر مانند x86_64 تعامل می‌کند.
      • برای مثال، در backtrace از نسخه‌های x86_64 مربوط به CONTEXT و RtlVirtualUnwind استفاده می‌کنیم.
      • اگر مسیر جست‌وجویی برای یافتن DLL‌ها پیکربندی می‌کنید (مثلاً برای بارگذاری افزونه‌ها در برنامه‌تان)، باید از همان مسیر نسخهٔ x86_64 برنامه‌تان استفاده کنید، نه مسیر AArch64 (زیرا فرایندهای Arm64EC (یعنی x86_64) نمی‌توانند DLL‌های بومی AArch64 را بارگذاری کنند).
    • Arm64EC از intrinsic‌های AArch64 استفاده می‌کند.
      • برای مثال، https://github.com/rust-lang/portable-simd/commit/ca4033f49b1f6019561b8b161b4097b4a07f2e1b و https://github.com/rust-lang/stdarch/commit/166ef7ba22b6a1d908d4b29a36e68ceca324808a.
    • اسمبلی AArch64 ممکن است برای Arm64EC قابل استفادهٔ مجدد باشد، اما قیدوشرط‌های زیادی دارد. برای جزئیات کامل مستندات Microsoft دربارهٔ ABI در Arm64EC را ببینید، اما به‌طور خلاصه:
      • Arm64EC زیرمجموعه‌ای از ثبات‌های AArch64 را به کار می‌برد.
      • Arm64EC از طرح name mangling متفاوتی نسبت به AArch64 استفاده می‌کند.
      • Arm64EC لازم دارد برای برخی توابع thunk‌های ورودی و خروجی تولید شوند.
      • فراخوانی‌های غیرمستقیم باید از طریق یک call checker انجام شوند.
      • Control Flow Guard و بررسی‌های پشته از توابعی متفاوت از AArch64 استفاده می‌کنند.

    ساخت هدف

    می‌توانید با افزودن این هدف به فهرست target در bootstrap.toml، Rust را با پشتیبانی از آن بسازید:

    [build]
target = ["arm64ec-pc-windows-msvc"]

    ساخت برنامه‌های Rust

    این اهداف از طریق rustup توزیع می‌شوند و در غیر این صورت به هیچ پیکربندی ویژه‌ای نیاز ندارند.

    آزمون

    آزمون‌ها را می‌توان روی دستگاه‌های Windows 11 مبتنی بر AArch64 اجرا کرد.

    زنجیرابزارهای cross-compilation و کد C

    کد C را می‌توان با زنجیرابزار MSVC یا Clang که Arm64 را هدف می‌گیرد ساخت.

    برای کامپایل:

    cl /arm64EC /c ...

    برای پیوند دادن (link):

    link /MACHINE:ARM64EC ...

    برای مطالعهٔ بیشتر: https://learn.microsoft.com/en-us/windows/arm/arm64ec-build
