    armv6k-nintendo-3ds

    Tier: 3

    پلتفرم Nintendo 3DS که پردازندهٔ Armv6k دارد، و سیستم‌عامل مرتبط با آن (horizon).

    پشتیبانی Rust از این هدف وابسته به Nintendo نیست، و از هیچ SDK رسمی Nintendo مشتق نشده و با آن به کار نمی‌رود.

    نگهدارندگان هدف

    این هدف را اعضای سازمان @rust3ds نگه‌داری می‌کنند:

    @Meziu @AzureMarker @ian-h-chamberlain

    الزامات

    این هدف cross-compile می‌شود. پیوند پویا (dynamic linking) پشتیبانی نمی‌شود.

    crate‌های #![no_std] را می‌توان با استفاده از build-std برای ساخت core و در صورت لزوم alloc، و یکی از panic_abort یا panic_unwind ساخت.

    std به‌صورت جزئی پشتیبانی می‌شود، اما بیشتر کار می‌کند. برخی API‌ها پیاده‌سازی نشده‌اند و صرفاً خطا برمی‌گردانند، مانند std::process. به‌طور پیش‌فرض یک تخصیص‌دهنده (allocator) ارائه می‌شود.

    برای پشتیبانی از برخی API‌ها، فایل‌های باینری باید با libc نوشته‌شده برای این هدف و با استفاده از یک لینکر برای این هدف پیوند داده شوند. این‌ها را زنجیرابزار devkitARM فراهم می‌کند. برای جزئیات بیشتر زنجیرابزارهای cross-compilation و کد C را ببینید.

    علاوه بر این، برخی crate‌های کمکی پیاده‌سازی بعضی توابع libc را که std به کار می‌برد و در غیر این صورت ممکن است موجود نباشند فراهم می‌کنند. برای استفاده از std به این‌ها یا به پیاده‌سازی جایگزینی از توابع مربوط نیاز است:

    • pthread-3ds API‌های pthread را برای std::thread فراهم می‌کند.
    • shim-3ds برخی دیگر از API‌های libc را که موجود نیستند (مثلاً getrandom) تأمین می‌کند.

    فایل‌های باینری ساخته‌شده برای این هدف باید با همهٔ گونه‌های سخت‌افزار و میان‌افزار 3DS (و 2DS) سازگار باشند، اما آزمایش محدود است و ممکن است برخی نسخه‌ها درست کار نکنند.

    این هدف فایل‌های باینری را در قالب ELF تولید می‌کند.

    ساخت هدف

    می‌توانید با افزودن این هدف به فهرست target در bootstrap.toml و مشخص کردن مسیر زنجیرابزار devkitARM، Rust را با پشتیبانی از آن بسازید.

    [build]
build-stage = 1
target = ["armv6k-nintendo-3ds"]

[target.armv6k-nintendo-3ds]
cc = "/opt/devkitpro/devkitARM/bin/arm-none-eabi-gcc"
cxx = "/opt/devkitpro/devkitARM/bin/arm-none-eabi-g++"
ar = "/opt/devkitpro/devkitARM/bin/arm-none-eabi-ar"
ranlib = "/opt/devkitpro/devkitARM/bin/arm-none-eabi-ranlib"
linker = "/opt/devkitpro/devkitARM/bin/arm-none-eabi-gcc"

    همچنین برای ساخت compiler_builtins برای این هدف، پیش از ساخت زنجیرابزار Rust این پرچم‌ها را export کنید:

    export CFLAGS_armv6k_nintendo_3ds="-mfloat-abi=hard -mtune=mpcore -mtp=soft -march=armv6k"

    ساخت برنامه‌های Rust

    Rust هنوز مصنوعات (artifact) از پیش کامپایل‌شده‌ای برای این هدف ارائه نمی‌کند.

    روش پیشنهادی برای ساخت فایل‌های باینری استفاده از ابزار cargo-3ds است که از build-std استفاده می‌کند و دستورهایی فراهم می‌کند که مانند cargo run، cargo build و مانند آن‌ها کار می‌کنند. دستور cargo 3ds new به‌طور خودکار پروژهٔ جدیدی را همراه با وابستگی‌های لازم برای ساخت یک فایل باینری ساده راه‌اندازی می‌کند.

    همچنین می‌توانید Rust را با فعال بودن این هدف بسازید (بخش ساخت هدف را در بالا ببینید).

    همان‌طور که در الزامات گفته شد، برنامه‌هایی که از std استفاده می‌کنند باید هم با زنجیرابزار devkitARM و هم با کتابخانه‌هایی که API‌های libc مورد استفادهٔ std را فراهم می‌کنند پیوند داده شوند. یک crate کاربردی عمومی برای کار با API‌های غیراستاندارد ارائه‌شده توسط سیستم‌عامل وجود دارد: ctru-rs. برای استفاده از آن در برنامه‌تان آن را به Cargo.toml اضافه کنید:

    [dependencies]
ctru-rs = { git = "https://github.com/rust3ds/ctru-rs.git" }

    وابسته بودن به ctru-rs تضمین می‌کند که همهٔ نمادهای (symbol) لازم در زمان پیوند در دسترس هستند.

    آزمون

    فایل‌های باینری ساخته‌شده برای این هدف را می‌توان در یک شبیه‌ساز (که رایج‌ترین آن Citra است) اجرا کرد، یا با استفاده از ابزاری مانند 3dslink در devkitARM به یک دستگاه فرستاد. همچنین می‌توان آن‌ها را به‌سادگی روی یک کارت SD کپی کرد تا در دستگاه قرار گیرد.

    ابزار cargo-3ds که در ساخت برنامه‌های Rust ذکر شد، از استفاده از 3dslink با cargo 3ds run پشتیبانی می‌کند. اجراکنندهٔ آزمون پیش‌فرض Rust پشتیبانی نمی‌شود، اما چارچوب‌های آزمون سفارشی را می‌توان با cargo 3ds test برای اجرای آزمون‌های واحد روی دستگاه به کار برد.

    مجموعه آزمون Rust برای library/std هنوز پشتیبانی نمی‌شود.

    زنجیرابزارهای cross-compilation و کد C

    کد C را برای این هدف می‌توان با زنجیرابزار devkitARM ساخت. این زنجیرابزار arm-none-eabi-gcc را فراهم می‌کند که لینکر مورد استفاده برای پیوند برنامه‌های Rust نیز هست.

    این زنجیرابزار یک پیاده‌سازی libc نیز فراهم می‌کند که std برای بسیاری از API‌های خود به آن نیاز دارد، و یک کتابخانهٔ کمکی libctru که چند crate از crate‌های کمکی فهرست‌شده در الزامات از آن استفاده می‌کنند. با این حال، این زنجیرابزار همهٔ API‌های مورد انتظار std را شامل نمی‌شود و API‌های باقی‌مانده را pthread-3ds و linker-fix-3ds پیاده‌سازی می‌کنند.
