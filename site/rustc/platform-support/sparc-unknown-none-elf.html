    sparc-unknown-none-elf

    سطح (Tier): ۳

    Rust برای سیستم‌های bare-metal ‏۳۲ بیتی SPARC V7 و V8، مانند Gaisler LEON3.

    هدفتوضیحات
    sparc-unknown-none-elfSPARC V7 ۳۲ بیتی (freestanding، hardfloat)

    نگهدارندگان هدف

    @jonathanpallant

    الزامات

    این هدف cross-compile می‌شود. از std پشتیبانی نمی‌شود. هیچ allocator پیش‌فرضی وجود ندارد، اما با فراهم کردن یک allocator می‌توان از alloc استفاده کرد.

    به‌طور پیش‌فرض، کدی که با این هدف تولید می‌شود باید روی هر سخت‌افزار SPARC اجرا شود؛ فعال کردن ویژگی‌های اضافی هدف ممکن است این سطح پایه را بالاتر ببرد.

    • -Ctarget-cpu=v8 دستورهای اضافی SPARC V8 را اضافه می‌کند.

    • -Ctarget-cpu=leon3 دستورهای SPARC V8 را اضافه می‌کند و زمان‌بندی را متناسب با Gaisler Leon3 تنظیم می‌کند.

    توابعی که با extern "C" علامت‌گذاری شده‌اند از قرارداد فراخوانی استاندارد معماری SPARC استفاده می‌کنند.

    این هدف فایل‌های دودویی ELF تولید می‌کند. هر قالب جایگزین یا ملاحظات ویژه برای چیدمان فایل دودویی به گزینه‌های لینکر یا اسکریپت‌های لینکر نیاز خواهد داشت.

    ساخت هدف

    می‌توانید Rust را با پشتیبانی از این هدف بسازید؛ برای این کار آن را به فهرست target در bootstrap.toml اضافه کنید:

    [build]
build-stage = 1
host = ["<target for your host>"]
target = ["<target for your host>", "sparc-unknown-none-elf"]

    <target for your host> را با x86_64-unknown-linux-gnu یا هر مقدار مناسب دیگر برای ماشین میزبان خود جایگزین کنید.

    ساخت برنامه‌های Rust

    برای ساخت با این هدف، آن را به آرگومان --target بدهید، مانند:

    cargo build --target sparc-unknown-none-elf

    این هدف از GCC به‌عنوان لینکر استفاده می‌کند، بنابراین به یک toolchain مناسب sparc-unknown-none سازگار با GCC نیاز دارید. فایل دودویی لینکر پیش‌فرض sparc-elf-gcc است، اما می‌توانید آن را در پیکربندی پروژه خود به این صورت تغییر دهید:

    .cargo/config.toml:

    [target.sparc-unknown-none-elf]
linker = "sparc-custom-elf-gcc"

    آزمون

    از آنجا که sparc-unknown-none-elf از محیط‌های متنوعی پشتیبانی می‌کند و از std پشتیبانی نمی‌کند، این هدف از اجرای مجموعه آزمون‌های Rust پشتیبانی نمی‌کند.

    toolchainهای cross-compilation و کد C

    این هدف در ابتدا با استفاده از BCC2 از Gaisler، همراه با شبیه‌ساز پردازنده Leon3 به نام TSIM آزمایش شد. هم BCC2 GCC و هم BCC2 Clang کار کرده‌اند. برای کار با این ابزارها، پیکربندی پروژه شما باید چیزی شبیه به این داشته باشد:

    .cargo/config.toml:

    [target.sparc-unknown-none-elf]
linker = "sparc-gaisler-elf-gcc"
runner = "tsim-leon3"

[build]
target = ["sparc-unknown-none-elf"]
rustflags = "-Ctarget-cpu=leon3"

    با این پیکربندی، اجرای cargo run کد شما را برای پردازنده Gaisler Leon3 سازگار با SPARC V8 کامپایل می‌کند و سپس شبیه‌ساز tsim-leon3 را راه‌اندازی می‌کند. libcore در جریان کامپایل rustc با استفاده از سطح پایه SPARC V7 از پیش کامپایل شده است، اما اگر از toolchain نایتلی (nightly) استفاده می‌کنید، می‌توانید با گزینه -Z build-std=core libcore را از روی کد منبع دوباره بسازید. این کار می‌تواند مفید باشد اگر بخواهید آن را برای SPARC V8 کامپایل کنید و از دستورهای اضافی بهره ببرید.

    .cargo/config.toml:

    [target.sparc-unknown-none-elf]
linker = "sparc-gaisler-elf-gcc"
runner = "tsim-leon3"

[build]
target = ["sparc-unknown-none-elf"]
rustflags = "-Ctarget-cpu=leon3"

[unstable]
build-std = ["core"]

    در هر دو حالت، وقتی شبیه‌ساز در حال اجراست، کافی است دستور run را وارد کنید تا اجرای کد در شبیه‌ساز آغاز شود.

    کتابخانه‌های پیش‌فرض toolchain زبان C لینک می‌شوند، بنابراین با toolchain مربوط به Gaisler BCC2 و با استفاده از BSP پیش‌فرض Leon3 آن، می‌توانید تابع putchar زبان C و توابع مشابه را برای خروجی به کنسول شبیه‌ساز فراخوانی کنید. اسکریپت لینکر پیش‌فرض نیز برای شبیه‌ساز Leon3 مناسب است، بنابراین به هیچ اسکریپت لینکری نیاز نیست.

    در ادامه یک مثال کامل با استفاده از فایل پیکربندی بالا آمده است:

    #![no_std]
#![no_main]

extern "C" {
    fn putchar(ch: i32);
    fn _exit(code: i32) -> !;
}

#[no_mangle]
extern "C" fn main() -> i32 {
    let message = "Hello, this is Rust!";
    for b in message.bytes() {
        unsafe {
            putchar(b as i32);
        }
    }
    0
}

#[panic_handler]
fn panic(_panic: &core::panic::PanicInfo) -> ! {
    unsafe {
        _exit(1);
    }
}
