    اهدافی برای ماشین مجازی BPF ۶۴ بیتی.

    نگهدارندگان هدف

    @nagisa @vadorovsky

    الزامات

    اهداف BPF به یک toolchain از Rust با مؤلفهٔ rust-src نیاز دارند. علاوه بر این، باید bpf-linker را نصب کنید.

    این اهداف از std و alloc پشتیبانی نمی‌کنند و برای محیط no_std در نظر گرفته شده‌اند.

    extern "C" از قرارداد فراخوانی ABI در BPF استفاده می‌کند.

    فایل‌های دودویی تولیدشده از قالب ELF استفاده می‌کنند.

    ماشین‌های مجازی BPF یک کامپایلر JIT ارائه می‌دهند که bytecode مربوط به BPF را به معماری بومی میزبان کامپایل می‌کند.

    اجرای برنامه‌های BPF روی بیشتر معماری‌های میزبان به Linux kernel نسخه 4.18، که BTF را معرفی کرد، یا جدیدتر نیاز دارد. روی میزبان‌های RISC-V این الزام به 5.7 افزایش می‌یابد، روی PowerPC32 به 5.13 و روی LoongArch به 6.1.

    ساخت هدف

    می‌توانید Rust را با پشتیبانی از اهداف BPF بسازید؛ کافی است آن‌ها را به فهرست target در config.toml اضافه کنید:

    [build]
target = ["bpfeb-unknown-none", "bpfel-unknown-none"]

    ساخت برنامه‌های Rust

    Rust هنوز artifactهای از پیش کامپایل‌شده برای این هدف ارائه نمی‌کند. برای کامپایل برای این هدف، یا باید Rust را با فعال بودن هدف بسازید (بخش «ساخت هدف» در بالا را ببینید)، یا با استفاده از build-std یا روشی مشابه نسخهٔ خودتان از core را بسازید.

    ساخت برای هدف BPF مستلزم تعیین صریح آن است. کاربران می‌توانند یا آن را به فهرست target در config.toml اضافه کنند:

    [build]
target = ["bpfel-unknown-none"]

    یا آن را مستقیماً در فراخوانی cargo build مشخص کنند:

    cargo +nightly build -Z build-std=core --target bpfel-unknown-none

    BPF قالب اطلاعات اشکال‌زدایی مخصوص خود را دارد که BTF نام دارد.

    اهداف BPF از bpf-linker استفاده می‌کنند، که یک پیوندگر bitcode برای LLVM است. در آینده ممکن است به نوع GNU پیوندگر مهاجرت کنند؛ جزئیات را در issue زیر ببینید.

    مدیریت خطا

    در BPF مفهوم باز کردن پشته (stack unwinding) وجود ندارد؛ بنابراین انتظار می‌رود برنامه‌های BPF خطاها را به شیوه‌ای قابل‌بازیابی مدیریت کنند. به همین دلیل بیشتر برنامه‌های BPF که با Rust نوشته می‌شوند از پیاده‌سازی panic handler زیر استفاده می‌کنند:

    #[cfg(not(test))]
#[panic_handler]
fn panic(_info: &core::panic::PanicInfo) -> ! {
    loop {}
}

    حلقه‌های بی‌نهایت توسط BPF verifier ممنوع هستند. بنابراین اگر برنامه شامل هر کدی باشد که بتواند panic کند، ماشین مجازی BPF از بارگذاری آن خودداری می‌کند.

    آزمون

    bytecode مربوط به BPF باید روی یک ماشین مجازی BPF اجرا شود، مانند ماشینی که Linux kernel ارائه می‌دهد یا یکی از پیاده‌سازی‌های فضای کاربر مانند rbpf. هیچ‌کدام از آن‌ها اجرای توابع #[test] در Rust را پشتیبانی نمی‌کنند. یکی از دلایل آن نبود پشتیبانی از panic است.

    بنابراین آزمون‌های واحد باید روی سیستم میزبان اجرا شوند. این الزام را می‌توان با بررسی شرطی زیر اعمال کرد:

    #[cfg(all(not(target_arch = "bpf"), test))]
mod test {}

    toolchainهای کامپایل متقاطع

    برنامه‌های BPF همیشه از یک میزبان (مثلاً x86_64-unknown-linux-*) برای یک هدف BPF (مثلاً bpfel-unknown-none) به‌صورت متقاطع کامپایل می‌شوند.

    endianness هدف BPF انتخاب‌شده باید با endianness میزبان ماشین مجازی BPF که قرار است برنامه روی آن اجرا شود مطابقت داشته باشد.

    معماری میزبان ماشین مجازی BPF اغلب بر نوع‌هایی که برنامه‌های BPF باید استفاده کنند تأثیر دارد. برای مثال kprobes، fprobes و uprobes ردیابی پویای توابع و دسترسی به ثبات‌های میزبان را از طریق ساختار pt_regs ممکن می‌کنند که در معماری‌های مختلف تفاوت دارد.

    این تفاوت همچنان دغدغهٔ کامپایلر نیست. در عوض، باید توسط توسعه‌دهندگان مدیریت شود. Aya (کتابخانه‌ای برای نوشتن برنامه‌های Linux BPF و مصرف‌کنندهٔ اصلی اهداف BPF در Rust) این کار را با ارائهٔ crate با نام aya-ebpf-cty انجام می‌دهد که نوع‌های مستعار (type alias) مشابه نوع‌های ارائه‌شده در core:ffi دارد. aya-ebpf-cty امکان تعیین هدف ماشین مجازی را از طریق متغیر محیطی CARGO_CFG_BPF_TARGET_ARCH می‌دهد (مثلاً CARGO_CFG_BPF_TARGET_ARCH=aarch64).

    کد C

    می‌توان یک پروژهٔ Rust BPF را به فایل‌های bitcode یا شیء که از کد C با clang ساخته شده‌اند پیوند داد. این کار با استفاده از یک دستور rustc-link-lib در build.rs انجام می‌شود. مثال:

    use std::{env, process::Command};

let out_dir = env::var("OUT_DIR").unwrap();
let c_module = "my_module.bpf.c";
let s = Command::new("clang")
    .arg("-I")
    .arg("src/")
    .arg("-O2")
    .arg("-emit-llvm")
    .arg("-target")
    .arg("bpf")
    .arg("-c")
    .arg("-g")
    .arg(c_module)
    .arg("-o")
    .arg(format!("{out_dir}/my_module.bpf.o"))
    .status()
    .unwrap();
assert!(s.success());
println!("cargo:rustc-link-search=native={out_dir}");
println!("cargo:rustc-link-lib=link-arg={out_dir}/my_module.bpf.o");
