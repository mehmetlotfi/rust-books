    x86_64-unknown-none

    Tier: 2

    باینری‌های مستقل/bare-metal برای x86-64 با فرمت ELF: میان‌افزار (firmware)، هسته‌ها (kernel) و مانند آن.

    نگهدارندگان target

    @haraldh @mikeleany

    الزامات

    این target به‌صورت متقابل کامپایل می‌شود. از std پشتیبانی نمی‌شود. تخصیص‌دهندهٔ پیش‌فرضی وجود ندارد، اما با ارائهٔ یک تخصیص‌دهنده می‌توان از alloc استفاده کرد.

    به‌طور پیش‌فرض، کد Rust تولیدشده برای این target از هیچ رجیستر برداری یا ممیز شناور (مثلاً SSE و AVX) استفاده نمی‌کند. این امر به کد تولیدشده اجازه می‌دهد در محیط‌هایی مانند هسته‌ها اجرا شود که ممکن است نیاز داشته باشند از چنین رجیسترهایی دوری کنند یا ملاحظات ویژه‌ای دربارهٔ استفاده از آن‌ها داشته باشند (مثلاً ذخیره و بازیابی آن‌ها برای جلوگیری از خراب‌شدن کد فضای کاربر که از همان رجیسترها استفاده می‌کند). می‌توانید تولید کد را با گزینه‌های codegen به نام -C target-feature= در rustc، یا با سازوکار #[target_feature] در کد Rust، به‌گونه‌ای تغییر دهید که از قابلیت‌های اضافی CPU استفاده کند.

    به‌طور پیش‌فرض، کد تولیدشده با این target باید روی هر سخت‌افزار x86_64 اجرا شود؛ فعال‌کردن target featureهای اضافی ممکن است این حداقل را بالاتر ببرد.

    کد تولیدشده با این target به‌طور پیش‌فرض از مدل کد kernel استفاده می‌کند. می‌توانید این را با گزینهٔ -C code-model= در rustc تغییر دهید.

    در x86_64-unknown-none، extern "C" از قرارداد فراخوانی استاندارد System V و بدون red zone استفاده می‌کند.

    این target باینری‌ها را با فرمت ELF تولید می‌کند. هر فرمت جایگزین یا ملاحظهٔ ویژه برای چیدمان باینری به گزینه‌های لینکر یا اسکریپت‌های لینکر نیاز دارد.

    ساخت target

    می‌توانید Rust را با پشتیبانی از این target بسازید؛ کافی است آن را به فهرست target در bootstrap.toml اضافه کنید:

    [build]
build-stage = 1
target = ["x86_64-unknown-none"]

    ساخت برنامه‌های Rust

    از Rust 1.62 به بعد، artifactهای از پیش کامپایل‌شده از طریق rustup ارائه می‌شوند:

    # install cross-compile toolchain
rustup target add x86_64-unknown-none
# target flag may be used with any cargo or rustc command
cargo build --target x86_64-unknown-none

    آزمون

    از آنجا که x86_64-unknown-none از محیط‌های متنوعی پشتیبانی می‌کند و از std پشتیبانی نمی‌کند، این target از اجرای مجموعه آزمون‌های Rust پشتیبانی نمی‌کند.

    ابزارهای cross-compilation و کد C

    اگر می‌خواهید کد C را همراه با Rust کامپایل کنید (مثلاً برای crateهای Rust دارای وابستگی به C)، به یک toolchain مناسب x86_64 نیاز دارید.

    ممکن است Rust بتواند با پرچم‌های مستقل (standalone) مناسب از toolchain با پیشوند x86_64-linux-gnu- برای ساخت برای این target استفاده کند (بسته به فرض‌های آن toolchain، پایین را ببینید)، یا ممکن است بخواهید از یک toolchain جداگانهٔ x86_64-unknown-none (یا با پیشوند x86_64-elf-) استفاده کنید.

    در برخی میزبان‌های x86_64 که از باینری‌های ELF استفاده می‌کنند، ممکن است بتوانید از toolchain C میزبان استفاده کنید، به شرط آنکه فرض‌هایی دربارهٔ محیط میزبان وارد نکند که با انتظارات یک محیط مستقل (standalone) سازگار نباشد. در غیر این صورت، ممکن است برای توسعهٔ مستقل/freestanding به یک toolchain جداگانه نیاز داشته باشید، درست مانند cross-compilation از یک پلتفرم غیر x86_64.
