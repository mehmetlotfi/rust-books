    lint‌ها

    در مهندسی نرم‌افزار، «lint» ابزاری است که به بهبود کد منبع شما کمک می‌کند. کامپایلر Rust شامل تعدادی lint است و هنگام کامپایل کد شما، lint‌ها را نیز اجرا می‌کند. این lint‌ها بسته به نحوهٔ پیکربندی شما ممکن است یک هشدار، یک خطا یا اصلاً هیچ‌چیز تولید نکنند.

    در اینجا یک مثال کوچک آمده است:

    $ cat main.rs
fn main() {
    let x = 5;
}
$ rustc main.rs
warning: unused variable: `x`
 --> main.rs:2:9
  |
2 |     let x = 5;
  |         ^
  |
  = note: `#[warn(unused_variables)]` on by default
  = note: to avoid this warning, consider using `_x` instead

    این همان lint با نام unused_variables است و به شما می‌گوید متغیری تعریف کرده‌اید که در کد خود از آن استفاده نمی‌کنید. این کار اشتباه نیست، پس خطا محسوب نمی‌شود، اما ممکن است یک باگ باشد، بنابراین یک هشدار دریافت می‌کنید.

    lint‌های ناسازگار با آینده

    گاهی لازم است کامپایلر تغییر کند تا مشکلی برطرف شود که ممکن است باعث شود کدهای موجود دیگر کامپایل نشوند. در چنین مواردی lint‌های «ناسازگار با آینده» (future-incompatible) صادر می‌شوند تا کاربران Rust انتقال روانی به رفتار جدید داشته باشند. در ابتدا، کامپایلر همچنان کد مشکل‌دار را می‌پذیرد و یک هشدار صادر می‌کند. این هشدار شامل توضیح مشکل، اطلاع از اینکه در آینده به یک خطا تبدیل خواهد شد، و پیوندی به یک issue پیگیری است که اطلاعات تفصیلی و فرصتی برای ارائهٔ بازخورد فراهم می‌کند. این کار به کاربران مدتی فرصت می‌دهد تا کد خود را با تغییر سازگار کنند. پس از مدتی، ممکن است هشدار به یک خطا تبدیل شود.

    نمونهٔ زیر نشان می‌دهد یک lint ناسازگار با آینده چه شکلی دارد:

    warning: borrow of packed field is unsafe and requires unsafe function or block (error E0133)
  --> lint_example.rs:11:13
   |
11 |     let y = &x.data.0;
   |             ^^^^^^^^^
   |
   = note: `#[warn(safe_packed_borrows)]` on by default
   = warning: this was previously accepted by the compiler but is being phased out; it will become a hard error in a future release!
   = note: for more information, see issue #46043 <https://github.com/rust-lang/rust/issues/46043>
   = note: fields of packed structs might be misaligned: dereferencing a misaligned pointer or even just creating a misaligned reference is undefined behavior

    برای اطلاعات بیشتر دربارهٔ فرایند و سیاست تغییرات ناسازگار با آینده، به RFC 1589 مراجعه کنید.
