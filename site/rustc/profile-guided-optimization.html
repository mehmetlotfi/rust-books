    بهینه‌سازی مبتنی بر پروفایل (Profile-guided Optimization)

    rustc از بهینه‌سازی مبتنی بر پروفایل (PGO) پشتیبانی می‌کند. این فصل توضیح می‌دهد PGO چیست، چه کاربردی دارد و چگونه می‌توان از آن استفاده کرد.

    بهینه‌سازی مبتنی بر پروفایل چیست؟

    ایدهٔ اصلی PGO این است که دادهٔ مربوط به اجرای معمول یک برنامه (مثلاً اینکه به احتمال زیاد کدام شاخه‌ها را طی می‌کند) جمع‌آوری شود و سپس از این داده برای هدایت بهینه‌سازی‌هایی مانند inlining، چیدمان کد ماشین، تخصیص رجیستر و مانند آن استفاده شود. برای استفاده از بهینه‌سازی مبتنی بر پروفایل، سطوح بهینه‌سازی -Copt-level=2 و بالاتر توصیه می‌شوند.

    rustc از بهینه‌سازی مبتنی بر پروفایل با دو نوع مختلف پروفایل‌گیری پشتیبانی می‌کند. یک پروفایلر نمونه‌برداری (sampling) می‌تواند پروفایلی با سربار بسیار کم در زمان اجرا تولید کند، یا می‌توانید نسخه‌ای ابزارگذاری‌شده (instrumented) از کد بسازید که اطلاعات پروفایل دقیق‌تری جمع می‌کند. هر دو نوع پروفایل می‌توانند تعداد اجرای دستورالعمل‌های کد و اطلاعاتی دربارهٔ شاخه‌های طی‌شده و فراخوانی تابع‌ها را فراهم کنند.

    روش‌های مختلفی برای جمع‌آوری داده دربارهٔ اجرای یک برنامه وجود دارد. یکی این است که برنامه درون یک پروفایلر (مانند perf) اجرا شود و دیگری ساخت یک باینری ابزارگذاری‌شده، یعنی باینری‌ای که جمع‌آوری داده در آن تعبیه شده است، و اجرای آن.

    تفاوت میان ابزارگذاری و نمونه‌برداری

    اگرچه هر دو تکنیک برای اهداف مشابهی به کار می‌روند، تفاوت‌های مهمی میان آن‌ها وجود دارد:

    1. دادهٔ پروفایل تولیدشده با یکی را نمی‌توان با دیگری به کار برد و هیچ ابزار تبدیلی برای تبدیل یکی به دیگری وجود ندارد. بنابراین پروفایلی که با -Cprofile-generate تولید شده باید با -Cprofile-use به کار رود. به‌همین ترتیب، پروفایل‌های نمونه‌برداری تولیدشده توسط پروفایلرهای خارجی باید تبدیل شوند و با -Cprofile-sample-use به کار روند.
    2. پروفایل‌های نمونه‌برداری باید توسط یک ابزار خارجی تولید شوند. پروفایل تولیدشده توسط آن ابزار سپس باید به قالبی تبدیل شود که LLVM بتواند بخواند. بخش مربوط به پروفایلرهای نمونه‌برداری یکی از قالب‌های پروفایل نمونه‌برداری پشتیبانی‌شده را شرح می‌دهد.

    پروفایل‌گیری با ابزارگذاری

    تولید یک برنامهٔ بهینه‌شده با PGO شامل پیروی از یک گردش کار چهارمرحله‌ای است:

    1. برنامه را با فعال‌بودن ابزارگذاری کامپایل کنید (مثلاً rustc -Cprofile-generate=/tmp/pgo-data -O main.rs)
    2. برنامهٔ ابزارگذاری‌شده را اجرا کنید (مثلاً ./main) که یک فایل default_<id>.profraw تولید می‌کند
    3. فایل .profraw را با ابزار llvm-profdata از LLVM به یک فایل .profdata تبدیل کنید
    4. برنامه را دوباره کامپایل کنید، این بار با استفاده از دادهٔ پروفایل (مثلاً rustc -Cprofile-use=merged.profdata -O main.rs)

    یک برنامهٔ ابزارگذاری‌شده یک یا چند فایل .profraw ایجاد می‌کند، یکی برای هر باینری ابزارگذاری‌شده. مثلاً یک فایل اجرایی ابزارگذاری‌شده که در زمان اجرا دو کتابخانهٔ پویای ابزارگذاری‌شده را بارگذاری می‌کند، سه فایل .profraw تولید می‌کند. در مقابل، اجرای چندبارهٔ یک باینری ابزارگذاری‌شده از فایل‌های .profraw مربوط به خودش دوباره استفاده می‌کند و آن‌ها را درجا به‌روزرسانی می‌کند.

    این فایل‌های .profraw پیش از آنکه دوباره به کامپایلر داده شوند باید پس‌پردازش شوند. این کار با ابزار llvm-profdata انجام می‌شود. این ابزار به‌آسانی از این طریق نصب می‌شود

    rustup component add llvm-tools-preview

    توجه کنید که نصب مؤلفهٔ llvm-tools-preview ابزار llvm-profdata را به PATH اضافه نمی‌کند. در عوض، این ابزار در این مسیر یافت می‌شود:

    ~/.rustup/toolchains/<toolchain>/lib/rustlib/<target-triple>/bin/

    به‌طور جایگزین، llvm-profdataای که همراه نسخهٔ جدید LLVM یا Clang می‌آید معمولاً کار می‌کند.

    ابزار llvm-profdata چند فایل .profraw را در یک فایل .profdata ادغام می‌کند که سپس می‌توان آن را از طریق -Cprofile-use به کامپایلر برگرداند:

    # STEP 1: Compile the binary with instrumentation
rustc -Cprofile-generate=/tmp/pgo-data -O main.rs

# STEP 2: Run the binary a few times, maybe with common sets of args.
# Each run will create or update `.profraw` files in /tmp/pgo-data
./main mydata1.csv
./main mydata2.csv
./main mydata3.csv

# STEP 3: Merge and post-process all the `.profraw` files in /tmp/pgo-data
llvm-profdata merge -o merged.profdata /tmp/pgo-data

# STEP 4: Use the merged `.profdata` file during optimization. All `rustc`
# flags have to be the same.
rustc -Cprofile-use=./merged.profdata -O main.rs

    یک گردش کار کامل با Cargo

    استفاده از این قابلیت با Cargo بسیار شبیه استفادهٔ مستقیم از rustc است. دوباره یک باینری ابزارگذاری‌شده تولید می‌کنیم، آن را برای تولید داده اجرا می‌کنیم، داده‌ها را ادغام می‌کنیم و به کامپایلر برمی‌گردانیم. چند نکتهٔ قابل‌توجه:

    • از متغیر محیطی RUSTFLAGS استفاده می‌کنیم تا پرچم‌های کامپایلر مربوط به PGO به کامپایل همهٔ crateهای برنامه منتقل شوند.

    • پرچم --target را به Cargo می‌دهیم که مانع از انتقال آرگومان‌های RUSTFLAGS به اسکریپت‌های ساخت Cargo می‌شود. نمی‌خواهیم اسکریپت‌های ساخت تعداد زیادی فایل .profraw تولید کنند.

    • --release را به Cargo می‌دهیم زیرا PGO بیشترین معنا را در همین حالت دارد. در تئوری، PGO را می‌توان روی ساخت‌های debug نیز انجام داد، اما دلیل چندانی برای این کار وجود ندارد.

    • توصیه می‌شود برای آرگومان -Cprofile-generate و -Cprofile-use از مسیرهای مطلق استفاده شود. Cargo می‌تواند rustc را با دایرکتوری‌های کاری متفاوت فراخوانی کند، به این معنا که rustc نمی‌تواند فایل .profdata داده‌شده را پیدا کند. با مسیرهای مطلق این مشکل پیش نمی‌آید.

    • تمرین خوبی است که مطمئن شوید هیچ دادهٔ پروفایل باقی‌مانده‌ای از نشست‌های کامپایل قبلی وجود ندارد. حذف دایرکتوری روشی ساده برای این کار است (STEP 0 را در ادامه ببینید).

    کل گردش کار این‌گونه به نظر می‌رسد:

    # STEP 0: Make sure there is no left-over profiling data from previous runs
rm -rf /tmp/pgo-data

# STEP 1: Build the instrumented binaries
RUSTFLAGS="-Cprofile-generate=/tmp/pgo-data" \
    cargo build --release --target=x86_64-unknown-linux-gnu

# STEP 2: Run the instrumented binaries with some typical data
./target/x86_64-unknown-linux-gnu/release/myprogram mydata1.csv
./target/x86_64-unknown-linux-gnu/release/myprogram mydata2.csv
./target/x86_64-unknown-linux-gnu/release/myprogram mydata3.csv

# STEP 3: Merge the `.profraw` files into a `.profdata` file
llvm-profdata merge -o /tmp/pgo-data/merged.profdata /tmp/pgo-data

# STEP 4: Use the `.profdata` file for guiding optimizations
RUSTFLAGS="-Cprofile-use=/tmp/pgo-data/merged.profdata" \
    cargo build --release --target=x86_64-unknown-linux-gnu

    عیب‌یابی

    • توصیه می‌شود در مرحلهٔ -Cprofile-use گزینهٔ -Cllvm-args=-pgo-warn-missing-function را بدهید. LLVM به‌طور پیش‌فرض در صورت نیافتن دادهٔ پروفایل برای یک تابع هشدار نمی‌دهد. فعال‌کردن این هشدار تشخیص خطاهای پیکربندی شما را آسان‌تر می‌کند.

    • یک مشکل شناخته‌شده در Cargo پیش از نسخهٔ 1.39 وجود دارد که مانع از درست کار کردن PGO می‌شود. هنگام استفاده از PGO حتماً از Cargo 1.39 یا جدیدتر استفاده کنید.

    پروفایل‌گیری با نمونه‌برداری

    پروفایلرهای نمونه‌برداری برای جمع‌آوری اطلاعات زمان اجرا، مانند شمارنده‌های سخت‌افزاری، هنگام اجرای برنامهٔ شما به کار می‌روند. این پروفایلرها معمولاً بسیار کارآمدند و سربار زمان اجرای زیادی ایجاد نمی‌کنند. دادهٔ نمونه‌ای که پروفایلر جمع می‌کند می‌تواند هنگام کامپایل برای تشخیص پراجراترین بخش‌های کد به کار رود.

    استفاده از دادهٔ یک پروفایلر نمونه‌برداری مستلزم تغییراتی در شیوهٔ ساخت برنامه است. پیش از آنکه کامپایلر بتواند از اطلاعات پروفایل استفاده کند، کد باید تحت پروفایلر اجرا شود. در ادامه چرخهٔ ساخت معمول هنگام استفاده از پروفایلرهای نمونه‌برداری برای بهینه‌سازی آمده است:

    1. کد را با اطلاعات جدول خطوط منبع بسازید. می‌توانید از همهٔ پرچم‌های ساخت معمولی که همیشه برنامهٔ خود را با آن‌ها می‌سازید استفاده کنید. تنها الزام این است که اطلاعات اشکال‌زدایی DWARF شامل اطلاعات خطوط منبع تولید شود. این اطلاعات DWARF برای آنکه پروفایلر بتواند دستورالعمل‌ها را به موقعیت خطوط منبع نگاشت کند اهمیت دارد. دقت این اطلاعات DWARF را می‌توان با گزینهٔ ناپایدار -Zdebuginfo-for-profiling بهبود داد. برای مثال:
    rustc -Cdebuginfo=line-tables-only -Zdebuginfo-for-profiling -O main.rs

    اطلاعات اضافی که debuginfo-for-profiling تولید می‌کند به کامپایلر کمک می‌کند در طول بهینه‌سازی بلوک‌های پایهٔ مختلف را حتی در صورت داشتن موقعیت خط منبع یکسان از هم تشخیص دهد، که در نتیجه دقت بهینه‌سازی مبتنی بر پروفایل را بهبود می‌بخشد.

    1. فایل اجرایی را تحت یک پروفایلر نمونه‌برداری اجرا کنید. اینکه دقیقاً از کدام پروفایلر استفاده می‌کنید اهمیت چندانی ندارد، به شرط آنکه خروجی آن قابل تبدیل به قالبی باشد که بهینه‌ساز LLVM آن را بفهمد.

    دو نمونه از چنین پروفایلرهایی پروفایلر Linux Perf و Sampling Enabling Product (SEP) شرکت Intel هستند که بخشی از Intel VTune است. در حالی که Perf مختص Linux است، SEP را می‌توان روی Linux، Windows و FreeBSD به کار برد.

    ابزار LLVM به نام llvm-profgen می‌تواند خروجی Perf یا SEP را تبدیل کند. یک پروژهٔ خارجی به نام AutoFDO نیز ابزاری به نام create_llvm_prof ارائه می‌کند که از خروجی Linux Perf پشتیبانی می‌کند.

    هنگام استفاده از Perf:

    perf record -b -e BR_INST_RETIRED.NEAR_TAKEN:uppp ./main

    اگر رویداد بالا در دسترس نباشد، branches:u احتمالاً گزینهٔ بعدی و بهترین است.

    به استفاده از پرچم -b توجه کنید. این پرچم به Perf می‌گوید از Last Branch Record (LBR) برای ثبت زنجیرهٔ فراخوانی‌ها استفاده کند. اگرچه این کار الزاماً لازم نیست، اطلاعات فراخوانی بهتری فراهم می‌کند که دقت دادهٔ پروفایل را بهبود می‌دهد.

    هنگام استفاده از SEP:

    sep -start -out code.tb7 -ec BR_INST_RETIRED.NEAR_TAKEN:precise=yes:pdir \
    -lbr no_filter:usr -perf-script brstack -app ./main

    این کار یک خروجی code.perf.data.script تولید می‌کند که می‌توان آن را با گزینهٔ ورودی --perfscript در llvm-profgen به کار برد.

    1. دادهٔ پروفایل جمع‌آوری‌شده را به قالب پروفایل نمونه‌ای LLVM تبدیل کنید. این کار در حال حاضر از طریق مبدل AutoFDO یعنی create_llvm_prof پشتیبانی می‌شود. پس از ساخت و نصب، می‌توانید فایل perf.data را با این دستور به LLVM تبدیل کنید:
    create_llvm_prof --binary=./main --out=main.prof

    این دستور perf.data و فایل باینری ./main را می‌خواند و دادهٔ پروفایل را در main.prof تولید می‌کند. توجه کنید که اگر perf را بدون پرچم -b اجرا کرده‌اید، باید هنگام فراخوانی create_llvm_prof از --use_lbr=false استفاده کنید.

    به‌طور جایگزین، ابزار LLVM به نام llvm-profgen نیز می‌تواند برای تولید پروفایل نمونه‌ای LLVM به کار رود:

    llvm-profgen --binary=./main --output=main.prof --perfdata=perf.data

    لطفاً توجه کنید، perf.data باید با پرچم -b در Linux perf جمع‌آوری شده باشد تا مرحلهٔ بالا کار کند.

    هنگام استفاده از SEP، خروجی به قالب متنی متناظر با llvm-profgen --perfscript است. برای مثال:

    llvm-profgen --binary=./main --output=main.prof \
    --perfscript=main.perf.data.script
    1. کد را دوباره با استفاده از پروفایل جمع‌آوری‌شده بسازید. این مرحله پروفایل را به بهینه‌سازها برمی‌گرداند. نتیجه باید باینری‌ای باشد که سریع‌تر از نسخهٔ اصلی اجرا می‌شود. توجه کنید که لازم نیست کد را دقیقاً با همان آرگومان‌هایی که در مرحلهٔ اول به کار بردید بسازید. تنها الزام این است که کد را با همان گزینه‌های اطلاعات اشکال‌زدایی و -Cprofile-sample-use بسازید.
    rustc -Cprofile-sample-use=main.prof -Zdebuginfo-for-profiling -O main.rs

    توجه کنید که PGO مبتنی بر نمونه‌برداری در rustc بیشتر روی پلتفرم‌های Linux با معماری x86-64 آزموده شده است. باید روی سایر معماری‌های سخت‌افزاری و سیستم‌عامل‌ها هم کار کند اما هنوز به‌طور گسترده آزمون نشده است.

    مطالعهٔ بیشتر

    پشتیبانی rustc از PGO کاملاً به پیاده‌سازی LLVM از این قابلیت وابسته است و معادل چیزی است که Clang از طریق پرچم‌های -fprofile-generate / -fprofile-use و -fprofile-sample-use ارائه می‌دهد. بنابراین بخش Profile Guided Optimization در مستندات Clang برای هر کسی که می‌خواهد PGO را با Rust به کار ببرد مطالعهٔ جالبی است.

    ابزارهای نگهداری‌شده توسط جامعه

    به‌عنوان جایگزینی برای استفادهٔ مستقیم از کامپایلر برای بهینه‌سازی مبتنی بر پروفایل، می‌توانید cargo-pgo را انتخاب کنید که یک API خط فرمان شهودی دارد و شما را از زحمت انجام همهٔ کارهای دستی رها می‌کند. می‌توانید دربارهٔ آن بیشتر در مخزن cargo-pgo بخوانید. فعلاً cargo-pgo فقط از PGO مبتنی بر ابزارگذاری پشتیبانی می‌کند.

    برای کامل بودن، مراحل متناظر با استفاده از cargo-pgo برای PGO مبتنی بر ابزارگذاری این است:

    # Install if you haven't already
cargo install --locked cargo-pgo

cargo pgo build
cargo pgo optimize

    این مراحل همان کارهای قبلی را انجام می‌دهند:

    1. یک باینری ابزارگذاری‌شده از کد منبع می‌سازند.
    2. باینری ابزارگذاری‌شده را برای جمع‌آوری پروفایل‌های PGO اجرا می‌کنند.
    3. از پروفایل‌های PGO جمع‌آوری‌شده در مرحلهٔ قبل برای ساخت یک باینری بهینه‌شده استفاده می‌کنند.
