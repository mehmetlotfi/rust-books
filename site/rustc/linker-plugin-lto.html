    LTO مبتنی بر افزونهٔ لینکر

    پرچم -C linker-plugin-lto اجازه می‌دهد بهینه‌سازی LTO به مرحلهٔ واقعی لینک‌کردن موکول شود. این کار به نوبهٔ خود امکان انجام بهینه‌سازی‌های بین‌رویه‌ای (interprocedural) را در مرز زبان‌های برنامه‌نویسی فراهم می‌کند، به شرط آنکه همهٔ فایل‌های شیء (object file) که لینک می‌شوند توسط زنجیره‌ابزارهای مبتنی بر LLVM و با همان حالت LTO ساخته شده باشند: یا thin LTO یا fat LTO. نمونه‌های آن لینک‌کردن کد Rust با کد C/C++ کامپایل‌شده توسط Clang و کد Fortran کامپایل‌شده توسط LLVM Flang است.

    نحوهٔ استفاده

    دو حالت اصلی برای استفاده از LTO مبتنی بر افزونهٔ لینکر وجود دارد:

    • کامپایل یک staticlib در Rust که به‌عنوان وابستگی با C ABI استفاده می‌شود
    • کامپایل یک فایل باینری Rust که در آن rustc لینکر را فراخوانی می‌کند

    در هر دو حالت، کد Rust باید با -C linker-plugin-lto کامپایل شود. این پرچم به‌طور پیش‌فرض thin LTO را فعال می‌کند، بنابراین هر کد زبان سازگار دیگر نیز باید در حالت thin LTO کامپایل شود. برای استفاده از fat LTO با LTO مبتنی بر افزونهٔ لینکر، کامپایلر rustc پرچم اضافی -C lto=fat را لازم دارد و زبان سازگار نیز باید به همین ترتیب در حالت fat LTO کامپایل شود. توجه کنید که زبان سازگار باید با زیرساخت LLVM کامپایل شود (جزئیات بیشتر را در سازگاری زنجیره‌ابزار ببینید).

    جدول زیر خلاصه می‌کند که چگونه می‌توان thin LTO و fat LTO را در کامپایلرهای مختلف فعال کرد:

    کامپایلرThin LTOFat LTO
    rustc-Clto=thin-Clto=fat
    clang-flto=thin-flto=full
    clang++-flto=thin-flto=full
    flang-flto=thin (در دست توسعه)-flto=full

    staticlib در Rust به‌عنوان وابستگی در برنامهٔ C/C++

    در این حالت کامپایلر Rust فقط باید مطمئن شود که فایل‌های شیء داخل staticlib در قالب درست هستند. برای لینک‌کردن، باید از لینکری با افزونهٔ LLVM استفاده شود (مثلاً LLD).

    استفادهٔ مستقیم از rustc:

    # Compile the Rust staticlib
rustc --crate-type=staticlib -Clinker-plugin-lto -Copt-level=2 ./lib.rs
# Compile the C code with `-flto=thin`
clang -c -O2 -flto=thin -o cmain.o ./cmain.c
# Link everything, making sure that we use an appropriate linker
clang -flto=thin -fuse-ld=lld -L . -l"name-of-your-rust-lib" -o main -O2 ./cmain.o

    استفاده از cargo:

    # Compile the Rust staticlib
RUSTFLAGS="-Clinker-plugin-lto" cargo build --release
# Compile the C code with `-flto=thin`
clang -c -O2 -flto=thin -o cmain.o ./cmain.c
# Link everything, making sure that we use an appropriate linker
clang -flto=thin -fuse-ld=lld -L . -l"name-of-your-rust-lib" -o main -O2 ./cmain.o

    کد C/C++ به‌عنوان وابستگی در Rust

    در این حالت لینکر توسط rustc فراخوانی می‌شود. در اینجا نیز باید مطمئن شویم که از لینکر مناسب استفاده می‌شود.

    استفادهٔ مستقیم از rustc:

    # Compile C code with `-flto=thin`
clang ./clib.c -flto=thin -c -o ./clib.o -O2
# Create a static library from the C code
ar crus ./libxyz.a ./clib.o

# Invoke `rustc` with the additional arguments
rustc -Clinker-plugin-lto -L. -Copt-level=2 -Clinker=clang -Clink-arg=-fuse-ld=lld ./main.rs

    استفادهٔ مستقیم از cargo:

    # Compile C code with `-flto=thin`
clang ./clib.c -flto=thin -c -o ./clib.o -O2
# Create a static library from the C code
ar crus ./libxyz.a ./clib.o

# Set the linking arguments via RUSTFLAGS
RUSTFLAGS="-Clinker-plugin-lto -Clinker=clang -Clink-arg=-fuse-ld=lld" cargo build --release

    کد Fortran به‌عنوان وابستگی در Rust

    کد Rust را می‌توان با کد Fortran که توسط flang در LLVM کامپایل شده است نیز لینک کرد. مثال‌های زیر استفاده از fat LTO را نشان می‌دهند، زیرا flang در LLVM برای thin LTO هنوز در وضعیت WIP (در دست توسعه) است. همین رویکرد را می‌توان برای کامپایل کد C و C++ با fat LTO نیز به کار برد.

    استفادهٔ مستقیم از rustc:

    # Compile Fortran code with `-flto=full`
flang ./ftnlib.f90 -flto=full -c -o ./ftnlib.f90.o -O3
# Create a static library from the Fortran code
ar crus ./libftn.a ./ftnlib.f90.o

# Invoke `rustc` with the additional arguments, `-Clto=fat` is mandatory
rustc -Clinker-plugin-lto -Clto=fat -Clink-arg=path/to/libftn.a -Copt-level=3 -Clinker=flang -C default-linker-libraries=yes -Clink-arg=-fuse-ld=lld ./main.rs

    استفادهٔ مستقیم از cargo:

    # Compile Fortran code with `-flto=full`
flang ./ftnlib.f90 -flto=full -c -o ./ftnlib.f90.o -O3
# Create a static library from the Fortran code
ar crus ./libftn.a ./ftnlib.f90.o

# Set the linking arguments via RUSTFLAGS, `-Clto=fat` is mandatory
RUSTFLAGS="-Clinker-plugin-lto -Clto=fat -Clink-arg=path/to/libftn.a -Clinker=flang -C default-linker-libraries=yes -Clink-arg=-fuse-ld=lld" cargo build --release

    توجه کنید که flang در LLVM را می‌توان از نسخهٔ flang 21.1.8 به بعد به‌عنوان درایور لینکر (linker driver) به کار برد. اگر زمان‌اجرای Fortran لازم نباشد، می‌توان گزینهٔ -C default-linker-libraries=yes را حذف کرد؛ با این حال، بیشتر کدهای Fortran به این زمان‌اجرا وابسته‌اند، بنابراین فعال‌کردن کتابخانه‌های پیش‌فرض لینکر معمولاً ضروری است.

    مشخص‌کردن صریح افزونهٔ لینکر برای استفاده توسط rustc

    اگر بخواهید از لینکری غیر از LLD استفاده کنید، باید افزونهٔ لینکر LLVM را صریحاً مشخص کنید. در غیر این صورت لینکر نمی‌تواند فایل‌های شیء را بخواند. مسیر افزونه به‌عنوان آرگومان به گزینهٔ -Clinker-plugin-lto داده می‌شود:

    rustc -Clinker-plugin-lto="/path/to/LLVMgold.so" -L. -Copt-level=2 ./main.rs

    استفاده با clang-cl و x86_64-pc-windows-msvc

    LTO میان زبان‌ها را می‌توان با هدف x86_64-pc-windows-msvc به کار برد، اما این کار مستلزم استفاده از کامپایلر clang-cl به‌جای cl.exe از MSVC است که همراه Visual Studio Build Tools می‌آید، و لینک‌کردن با lld-link. هم clang-cl و هم lld-link را می‌توان از صفحهٔ دانلود LLVM دریافت کرد. توجه کنید که بیشتر crate‌های موجود در اکوسیستم احتمالاً فرض می‌کنند که در صورت استفاده از این هدف، شما از cl.exe استفاده می‌کنید، و برخی چیزها، مانند vcpkg، با clang-cl چندان خوب کار نمی‌کنند.

    باید مطمئن شوید که نسخهٔ اصلی LLVM در Rust شما با نسخهٔ ابزارهای LLVM نصب‌شده مطابقت دارد، وگرنه احتمالاً با خطاهای لینکر روبه‌رو می‌شوید:

    rustc -V --verbose
clang-cl --version

    اگر proc-macro‌ها را کامپایل می‌کنید، این خطا را دریافت خواهید کرد:

    error: Linker plugin based LTO is not supported together with `-C prefer-dynamic` when
targeting Windows-like targets

    این مشکل با تعیین صریح هدف برطرف می‌شود، برای مثال cargo build --target x86_64-pc-windows-msvc بدون --target صریح، پرچم‌ها به همهٔ فراخوانی‌های کامپایلر (از جمله build script‌ها و proc-macro‌ها) داده می‌شوند؛ مستندات cargo دربارهٔ rustflags را ببینید.

    اگر وابستگی‌هایی دارید که از crate با نام cc استفاده می‌کنند، باید این متغیرهای محیطی را تنظیم کنید:

    set CC=clang-cl
set CXX=clang-cl
set CFLAGS=/clang:-flto=thin /clang:-fuse-ld=lld-link
set CXXFLAGS=/clang:-flto=thin /clang:-fuse-ld=lld-link
REM Needed because msvc's lib.exe crashes on LLVM LTO .obj files
set AR=llvm-lib

    اگر با تنظیم linker = "lld-link.exe" در پیکربندی cargo خود، lld-link را به‌عنوان لینکر مشخص می‌کنید، ممکن است با برخی crate‌ها که کد را با فراخوانی‌های جداگانهٔ cargo کامپایل می‌کنند به مشکل بخورید. باید بتوانید با تنظیم -Clinker=lld-link در RUSTFLAGS از این مشکل عبور کنید

    سازگاری زنجیره‌ابزار

    برای اینکه این نوع LTO کار کند، افزونهٔ لینکر LLVM باید بتواند bitcode مربوط به LLVM را که rustc و کامپایلرهای همهٔ زبان‌های سازگار تولید می‌کنند پردازش کند. یک قاعدهٔ سرانگشتی خوب این است که از افزونهٔ لینکر LLVM با نسخه‌ای استفاده شود که دست‌کم به‌اندازهٔ جدیدترین کامپایلر درگیر، جدید باشد.

    بهترین نتایج با استفاده از rustc و کامپایلرهای LLVM به‌دست می‌آید که بر پایهٔ دقیقاً همان نسخهٔ LLVM باشند. می‌توان از rustc -vV برای مشاهدهٔ LLVM مورد استفادهٔ یک نسخهٔ مشخص از rustc بهره برد. توجه کنید که شمارهٔ نسخه‌ای که در اینجا نشان داده می‌شود فقط یک تخمین است، زیرا Rust گاهی از بازبینی‌های ناپایدار LLVM استفاده می‌کند. با این حال، این تخمین معمولاً قابل اتکاست.
