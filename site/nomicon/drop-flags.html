    پرچم‌های drop

    مثال‌های بخش قبل مسئله‌ی جالبی را برای Rust مطرح کردند. دیدیم که می‌توان مکان‌هایی از حافظه را کاملاً ایمن و به‌صورت شرطی مقداردهی اولیه کرد، مقدار آن‌ها را برداشت و دوباره مقداردهی کرد. برای نوع‌های Copy این موضوع چندان قابل‌توجه نیست، چون آن‌ها فقط تکه‌ای تصادفی از بیت‌ها هستند. اما نوع‌هایی که destructor دارند داستان دیگری دارند: Rust باید بداند که هر زمان به یک متغیر مقداری انتساب داده می‌شود یا یک متغیر از محدوده خارج می‌شود، آیا destructor را فراخوانی کند یا نه. با وجود مقداردهی اولیه‌ی شرطی، این کار چگونه ممکن است؟

    توجه کنید که این مشکلی نیست که همه‌ی انتساب‌ها نگرانش باشند. به‌طور خاص، انتساب از طریق ارجاع‌زدایی همیشه بی‌قیدوشرط drop می‌کند و انتساب در let همیشه بی‌قیدوشرط drop نمی‌کند:

    let mut x = Box::new(0); // let makes a fresh variable, so never need to drop
let y = &mut x;
*y = Box::new(1); // Deref assumes the referent is initialized, so always drops

    این فقط وقتی مشکل است که متغیری که پیش‌تر مقداردهی شده یا یکی از فیلدهای زیرمجموعه‌ی آن بازنویسی شود.

    معلوم می‌شود که Rust در واقع اینکه یک نوع باید drop شود یا نه را در زمان اجرا ردیابی می‌کند. با مقداردهی‌شدن و بی‌مقدار شدن یک متغیر، یک پرچم drop (drop flag) برای آن متغیر تغییر وضعیت می‌دهد. هنگامی که ممکن است یک متغیر نیاز به drop داشته باشد، این پرچم بررسی می‌شود تا معلوم شود باید drop شود یا نه.

    البته اغلب پیش می‌آید که وضعیت مقداردهی یک مقدار در هر نقطه‌ی برنامه به‌صورت ایستا قابل‌شناسایی است. در این صورت کامپایلر از لحاظ نظری می‌تواند کد کارآمدتری تولید کند! برای نمونه، کد خطی (بدون انشعاب) دارای معنای drop ایستا است:

    let mut x = Box::new(0); // x was uninit; just overwrite.
let mut y = x;           // y was uninit; just overwrite and make x uninit.
x = Box::new(0);         // x was uninit; just overwrite.
y = x;                   // y was init; Drop y, overwrite it, and make x uninit!
                         // y goes out of scope; y was init; Drop y!
                         // x goes out of scope; x was uninit; do nothing.

    به همین ترتیب، کدی که شاخه‌دار است و همه‌ی شاخه‌هایش از نظر مقداردهی رفتار یکسانی دارند، دارای معنای drop ایستا است:

    let condition = true;
let mut x = Box::new(0);    // x was uninit; just overwrite.
if condition {
    drop(x)                 // x gets moved out; make x uninit.
} else {
    println!("{}", x);
    drop(x)                 // x gets moved out; make x uninit.
}
x = Box::new(0);            // x was uninit; just overwrite.
                            // x goes out of scope; x was init; Drop x!

    با این حال، کدی مانند نمونه‌ی زیر برای drop صحیح به اطلاعات زمان اجرا نیاز دارد:

    let condition = true;
let x;
if condition {
    x = Box::new(0);        // x was uninit; just overwrite.
    println!("{}", x);
}
                            // x goes out of scope; x might be uninit;
                            // check the flag!

    البته در این مورد، به‌دست‌آوردن معنای drop ایستا کار ساده‌ای است:

    let condition = true;
if condition {
    let x = Box::new(0);
    println!("{}", x);
}

    پرچم‌های drop روی stack ردیابی می‌شوند. در نسخه‌های قدیمی Rust، پرچم‌های drop در یک فیلد پنهان از نوع‌هایی که Drop را پیاده‌سازی می‌کردند نگهداری می‌شدند.
