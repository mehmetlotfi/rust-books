    repr(Rust)

    پیش از هر چیز، همهٔ نوع‌ها یک تراز (alignment) دارند که بر حسب بایت مشخص می‌شود. تراز یک نوع مشخص می‌کند که ذخیرهٔ مقدار در چه آدرس‌هایی معتبر است. مقداری با تراز n فقط باید در آدرسی ذخیره شود که مضرب n باشد. پس تراز ۲ یعنی باید در یک آدرس زوج ذخیره شوید، و ۱ یعنی می‌توانید در هر جایی ذخیره شوید. تراز دست‌کم ۱ است و همیشه توانی از ۲ است.

    نوع‌های اولیه معمولاً به اندازهٔ خودشان تراز می‌شوند، هرچند این رفتار وابسته به پلتفرم است. برای مثال، در x86 نوع‌های u64 و f64 اغلب به ۴ بایت (۳۲ بیت) تراز می‌شوند.

    اندازهٔ یک نوع همیشه باید مضرب ترازش باشد (صفر برای هر ترازی اندازه‌ای معتبر است). این تضمین می‌کند که یک آرایه از آن نوع همیشه با جابه‌جایی به اندازهٔ مضربی از اندازه‌اش قابل اندیس‌گذاری باشد. توجه کنید که اندازه و تراز یک نوع ممکن است در مورد نوع‌های با اندازهٔ پویا به‌صورت ایستا مشخص نباشد.

    Rust راه‌های زیر را برای چیدمان داده‌های مرکب در اختیارتان می‌گذارد:

    • ساختارها (struct؛ نوع‌های حاصل‌ضربی نام‌دار)
    • چندتایی‌ها (tuple؛ نوع‌های حاصل‌ضربی بی‌نام)
    • آرایه‌ها (نوع‌های حاصل‌ضربی همگن)
    • شمارش‌ها (enum؛ نوع‌های حاصل‌جمعی نام‌دار – union‌های برچسب‌دار)
    • union‌ها (union‌های بدون برچسب)

    یک شمارش بدون فیلد (field-less) نامیده می‌شود اگر هیچ‌یک از گونه‌هایش داده‌ای وابسته نداشته باشد.

    به‌طور پیش‌فرض، ساختارهای مرکب ترازی برابر با بیشینهٔ ترازهای فیلدهایشان دارند. در نتیجه Rust هر جا لازم باشد پدینگ درج می‌کند تا مطمئن شود همهٔ فیلدها درست تراز شده‌اند و اندازهٔ کل نوع مضرب ترازش است. برای مثال:

    struct A {
    a: u8,
    b: u32,
    c: u16,
}

    روی هدفی که این نوع‌های اولیه را به اندازهٔ خودشان تراز می‌کند، ۳۲ بیتی تراز خواهد بود. بنابراین کل ساختار اندازه‌ای خواهد داشت که مضرب ۳۲ بیت است. ممکن است چنین شود:

    struct A {
    a: u8,
    _pad1: [u8; 3], // to align `b`
    b: u32,
    c: u16,
    _pad2: [u8; 2], // to make overall size multiple of 4
}

    یا شاید:

    struct A {
    b: u32,
    c: u16,
    a: u8,
    _pad: u8,
}

    برای این نوع‌ها هیچ غیرمستقیمی (indirection) وجود ندارد؛ همهٔ داده‌ها درون ساختار ذخیره می‌شوند، همان‌طور که در C انتظار دارید. با این حال، به‌جز آرایه‌ها (که فشرده و به‌ترتیب چیده می‌شوند)، چیدمان داده به‌طور پیش‌فرض مشخص نشده است. با توجه به دو تعریف ساختار زیر:

    struct A {
    a: i32,
    b: u64,
}

struct B {
    a: i32,
    b: u64,
}

    Rust تضمین می‌کند که دو نمونه از A داده‌هایشان دقیقاً به یک شکل چیده شود. با این حال Rust در حال حاضر تضمین نمی‌کند که یک نمونه از A ترتیب فیلدها یا پدینگی مشابه یک نمونه از B داشته باشد.

    با A و B به همین شکلی که نوشته شده‌اند، این نکته ممکن است موشکافانه به نظر برسد، اما چند ویژگی دیگر Rust باعث می‌شود مطلوب باشد که زبان بتواند با چیدمان داده به شیوه‌های پیچیده بازی کند.

    برای مثال، این ساختار را در نظر بگیرید:

    struct Foo<T, U> {
    count: u16,
    data1: T,
    data2: U,
}

    اکنون monomorphizationهای Foo<u32, u16> و Foo<u16, u32> را در نظر بگیرید. اگر Rust فیلدها را به همان ترتیب مشخص‌شده بچیند، انتظار داریم مقادیر درون ساختار را پدینگ بدهد تا نیازهای ترازشان برآورده شود. پس اگر Rust فیلدها را دوباره مرتب نمی‌کرد، انتظار داشتیم چنین چیزی تولید کند:

    struct Foo<u16, u32> {
    count: u16,
    data1: u16,
    data2: u32,
}

struct Foo<u32, u16> {
    count: u16,
    _pad1: u16,
    data1: u32,
    data2: u16,
    _pad2: u16,
}

    حالت دوم به‌سادگی فضا را هدر می‌دهد. استفادهٔ بهینه از فضا مستلزم آن است که monomorphizationهای مختلف ترتیب فیلد متفاوتی داشته باشند.

    شمارش‌ها این ملاحظه را باز هم پیچیده‌تر می‌کنند. به‌طور ساده‌لوحانه، یک شمارش مانند:

    enum Foo {
    A(u32),
    B(u64),
    C(u8),
}

    ممکن است به این شکل چیده شود:

    struct FooRepr {
    data: u64, // this is either a u64, u32, or u8 based on `tag`
    tag: u8,   // 0 = A, 1 = B, 2 = C
}

    و در واقع تقریباً به همین شکل چیده می‌شود (با صرف‌نظر از اندازه و موقعیت tag).

    با این حال چند حالت وجود دارد که چنین بازنمایی ناکارآمد است. حالت کلاسیک آن «بهینه‌سازی اشاره‌گر تهی» در Rust است: یک شمارش متشکل از یک گونهٔ واحد بیرونی بدون داده (مثلاً None) و یک گونهٔ اشاره‌گر غیرتهی (که ممکن است تودرتو باشد) (مثلاً Some(&T)) نیاز به tag را از بین می‌برد. یک اشاره‌گر تهی را می‌توان با اطمینان به‌عنوان گونهٔ بدون داده (None) تفسیر کرد. نتیجهٔ نهایی این است که، برای مثال، size_of::<Option<&T>>() == size_of::<&T>().

    انواع زیادی در Rust وجود دارند که اشاره‌گر غیرتهی هستند یا دارند، مانند Box<T>، Vec<T>، String، &T و &mut T. به‌طور مشابه، می‌توان شمارش‌های تودرتویی را تصور کرد که tagهایشان را در یک مشخصهٔ (discriminant) واحد ادغام می‌کنند، چون طبق تعریف دامنهٔ محدودی از مقادیر معتبر دارند. در اصل، شمارش‌ها می‌توانند از الگوریتم‌های نسبتاً پیچیده‌ای استفاده کنند تا بیت‌ها را در سراسر نوع‌های تودرتو با مقادیر ممنوع ذخیره کنند. به همین دلیل به‌ویژه مطلوب است که امروز چیدمان شمارش را نامشخص بگذاریم.
