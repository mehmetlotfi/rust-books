    محدودیت‌های طول عمر

    کد زیر را در نظر بگیرید:

    #[derive(Debug)]
struct Foo;

impl Foo {
    fn mutate_and_share(&mut self) -> &Self { &*self }
    fn share(&self) {}
}

fn main() {
    let mut foo = Foo;
    let loan = foo.mutate_and_share();
    foo.share();
    println!("{:?}", loan);
}

    ممکن است انتظار داشته باشید که کامپایل شود. ما mutate_and_share را فراخوانی می‌کنیم که foo را موقتاً به‌صورت تغییرپذیر قرض می‌گیرد، اما سپس فقط یک ارجاع مشترک برمی‌گرداند. بنابراین انتظار داریم foo.share() موفق شود، چون foo دیگر نباید به‌صورت تغییرپذیر قرض‌گرفته شده باشد.

    اما وقتی سعی می‌کنیم آن را کامپایل کنیم:

    error[E0502]: cannot borrow `foo` as immutable because it is also borrowed as mutable
  --> src/main.rs:12:5
   |
11 |     let loan = foo.mutate_and_share();
   |                --- mutable borrow occurs here
12 |     foo.share();
   |     ^^^ immutable borrow occurs here
13 |     println!("{:?}", loan);

    چه اتفاقی افتاد؟ در واقع همان استدلالی را که برای مثال ۲ در بخش قبل داشتیم دوباره می‌بینیم. برنامه را desugar می‌کنیم و به این می‌رسیم:

    struct Foo;

impl Foo {
    fn mutate_and_share<'a>(&'a mut self) -> &'a Self { &'a *self }
    fn share<'a>(&'a self) {}
}

fn main() {
    'b: {
        let mut foo: Foo = Foo;
        'c: {
            let loan: &'c Foo = Foo::mutate_and_share::<'c>(&'c mut foo);
            'd: {
                Foo::share::<'d>(&'d foo);
            }
            println!("{:?}", loan);
        }
    }
}

    سیستم طول عمر مجبور می‌شود &mut foo را به‌دلیل طول عمر loan و امضای mutate_and_share تا طول عمر 'c گسترش دهد. سپس وقتی می‌خواهیم share را فراخوانی کنیم، می‌بیند که می‌خواهیم آن &'c mut foo را alias کنیم و جلوی چشممان منفجر می‌شود!

    این برنامه طبق معناشناسی ارجاعی که واقعاً به آن اهمیت می‌دهیم به‌روشنی درست است، اما سیستم طول عمر برای مدیریت آن بیش از حد درشت‌دانه است.
