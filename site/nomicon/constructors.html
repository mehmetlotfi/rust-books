    سازنده‌ها (Constructors)

    دقیقاً یک راه برای ساختن نمونه‌ای از یک نوع تعریف‌شده توسط کاربر وجود دارد: نام بردن از آن و مقداردهی همه‌ی فیلدهایش به‌صورت یک‌جا:

    struct Foo {
    a: u8,
    b: u32,
    c: bool,
}

enum Bar {
    X(u32),
    Y(bool),
}

struct Unit;

let foo = Foo { a: 0, b: 1, c: false };
let bar = Bar::X(0);
let empty = Unit;

    همین. هر راه دیگری که برای ساخت نمونه‌ای از یک نوع به کار می‌برید، صرفاً فراخوانی یک تابع کاملاً معمولی است که کارهایی انجام می‌دهد و در نهایت به آن «تنها سازنده‌ی حقیقی» (The One True Constructor) ختم می‌شود.

    برخلاف C++، Rust با انبوهی از انواع سازنده‌ی داخلی همراه نیست. هیچ سازنده‌ی Copy، Default، Assignment، Move یا مشابه آن وجود ندارد. دلایل این موضوع متنوع است، اما عمدتاً به فلسفه‌ی Rust یعنی صریح بودن برمی‌گردد.

    سازنده‌های move در Rust بی‌معنی‌اند چون ما به نوع‌ها اجازه نمی‌دهیم نسبت به مکانشان در حافظه «اهمیت بدهند». هر نوعی باید آماده باشد که کورکورانه به جای دیگری از حافظه memcopy شود. این یعنی لیست‌های پیوندی intrusive که کاملاً روی پشته هستند اما همچنان قابل جابه‌جایی‌اند، در Rust (به‌صورت امن) به‌سادگی ممکن نیستند.

    سازنده‌های انتساب و کپی نیز به‌طور مشابه وجود ندارند چون معناشناسی move تنها معناشناسی در Rust است. x = y حداکثر فقط بیت‌های y را به متغیر x منتقل می‌کند. Rust دو امکان برای فراهم کردن معناشناسی کپی‌محورِ C++ ارائه می‌دهد: Copy و Clone. Clone معادل اخلاقی سازنده‌ی کپی ماست، اما هرگز به‌طور ضمنی فراخوانی نمی‌شود. باید clone را به‌صراحت روی عنصری که می‌خواهید کلون شود فراخوانی کنید. Copy حالت خاصی از Clone است که در آن پیاده‌سازی فقط «کپی کردن بیت‌ها» است. نوع‌های Copy هر بار که move شوند به‌طور ضمنی کلون می‌شوند، اما به‌دلیل تعریف Copy این فقط به معنای آن است که نسخه‌ی قدیمی مقداردهی‌نشده تلقی نمی‌شود – یعنی یک عمل بی‌اثر.

    با اینکه Rust صفت Default را برای مشخص کردن معادل اخلاقی سازنده‌ی پیش‌فرض فراهم می‌کند، استفاده از این صفت فوق‌العاده نادر است. دلیلش این است که متغیرها به‌طور ضمنی مقداردهی نمی‌شوند. Default اساساً فقط برای برنامه‌نویسی جنریک مفید است. در زمینه‌های مشخص، یک نوع برای هر نوع سازنده‌ی «پیش‌فرض» یک متد ایستای new فراهم می‌کند. این با new در زبان‌های دیگر ارتباطی ندارد و معنای خاصی ندارد. فقط یک قرارداد نام‌گذاری است.
