    زیر std

    این بخش ویژگی‌هایی را مستند می‌کند که معمولاً crate با نام std فراهم می‌کند و توسعه‌دهندگان #![no_std] برای ساخت crateهای باینری #![no_std] باید با آن‌ها سروکار داشته باشند (یعنی خودشان فراهمشان کنند).

    استفاده از libc

    برای ساخت یک فایل اجرایی #[no_std] به libc به‌عنوان وابستگی نیاز خواهیم داشت. می‌توانیم این را در فایل Cargo.toml مشخص کنیم:

    [dependencies]
libc = { version = "0.2.146", default-features = false }

    توجه کنید که feature های پیش‌فرض غیرفعال شده‌اند. این یک گام حیاتی است - feature های پیش‌فرض libc شامل crate با نام std هستند و بنابراین باید غیرفعال شوند.

    به‌طور جایگزین، می‌توانیم از feature ناپایدار و خصوصی rustc_private همراه با اعلان extern crate libc; استفاده کنیم، همان‌طور که در مثال‌های زیر نشان داده شده است. توجه کنید که هدف‌های windows-msvc به libc نیاز ندارند و بر همین اساس هیچ crate با نام libc در sysroot آن‌ها وجود ندارد. ما به extern crate libc; زیر نیازی نداریم، و داشتن آن روی یک هدف windows-msvc خطای کامپایل خواهد بود.

    نوشتن یک فایل اجرایی بدون std

    احتمالاً برای تولید یک فایل اجرایی #![no_std] به نسخه‌ی nightly کامپایلر نیاز خواهیم داشت، زیرا در بسیاری از پلتفرم‌ها باید lang item با نام eh_personality را فراهم کنیم که ناپایدار است.

    باید یک نماد (symbol) برای نقطه‌ی ورود تعریف کنید که برای هدف شما مناسب باشد. برای مثال main، _start، WinMain، یا هر نقطه‌ی شروعی که برای هدف شما مرتبط است. علاوه بر این، باید از attribute با نام #![no_main] استفاده کنید تا کامپایلر تلاش نکند خودش یک نقطه‌ی ورود تولید کند.

    همچنین لازم است یک تابع panic handler تعریف شود.

    #![feature(lang_items, core_intrinsics, rustc_private)]
#![allow(internal_features)]
#![no_std]
#![no_main]

// Necessary for `panic = "unwind"` builds on cfg(unix) platforms.
#![feature(panic_unwind)]
extern crate unwind;

// Pull in the system libc library for what crt0.o likely requires.
#[cfg(not(windows))]
extern crate libc;

use core::ffi::{c_char, c_int};
use core::panic::PanicInfo;

// Entry point for this program.
#[unsafe(no_mangle)] // ensure that this symbol is included in the output as `main`
extern "C" fn main(_argc: c_int, _argv: *const *const c_char) -> c_int {
    0
}

// These functions are used by the compiler, but not for an empty program like this.
// They are normally provided by `std`.
#[lang = "eh_personality"]
fn rust_eh_personality() {}
#[panic_handler]
fn panic_handler(_info: &PanicInfo) -> ! { core::intrinsics::abort_immediate() }

    اگر با هدفی (target) کار می‌کنید که نسخه‌های باینری کتابخانهٔ استاندارد برایش از طریق rustup در دسترس نیست (احتمالاً یعنی خودتان crate با نام core را می‌سازید) و به intrinsicهای compiler-rt نیاز دارید (یعنی احتمالاً هنگام ساخت فایل اجرایی با خطاهای لینکر مواجه می‌شوید: undefined reference to `__aeabi_memcpy')، باید برای دریافت آن intrinsicها و رفع خطاهای لینکر، به‌صورت دستی با crate با نام compiler_builtins لینک کنید.
