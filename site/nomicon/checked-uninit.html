    حافظهٔ مقداردهی‌نشدهٔ بررسی‌شده (Checked Uninitialized Memory)

    مانند C، همه‌ی متغیرهای پشته در Rust تا زمانی که مقداری به‌صراحت به آن‌ها انتساب نشود مقداردهی‌نشده‌اند. برخلاف C، Rust به‌صورت ایستا از خواندن آن‌ها پیش از انتساب جلوگیری می‌کند:

    fn main() {
    let x: i32;
    println!("{}", x);
}
      |
3 |     println!("{}", x);
  |                    ^ use of possibly uninitialized `x`

    این بر پایه‌ی یک تحلیل شاخه‌ی ساده است: هر شاخه باید پیش از نخستین استفاده از x مقداری به آن انتساب دهد. به اختصار، می‌گوییم «x مقداردهی‌شده (init) است» یا «x مقداردهی‌نشده (uninit) است».

    جالب است که اگر هر شاخه دقیقاً یک بار انتساب دهد، Rust برای انجام مقداردهی تأخیری لازم نمی‌داند که متغیر تغییرپذیر باشد. با این حال این تحلیل از تحلیل ثابت‌ها یا چیزی شبیه آن بهره نمی‌برد. بنابراین این کد کامپایل می‌شود:

    fn main() {
    let x: i32;

    if true {
        x = 1;
    } else {
        x = 2;
    }

    println!("{}", x);
}

    اما این یکی نمی‌شود:

    fn main() {
    let x: i32;
    if true {
        x = 1;
    }
    println!("{}", x);
}
      |
6 |     println!("{}", x);
  |                    ^ use of possibly uninitialized `x`

    در حالی که این یکی می‌شود:

    fn main() {
    let x: i32;
    if true {
        x = 1;
        println!("{}", x);
    }
    // Don't care that there are branches where it's not initialized
    // since we don't use the value in those branches
}

    البته، با اینکه این تحلیل مقادیر واقعی را در نظر نمی‌گیرد، درک نسبتاً پیچیده‌ای از وابستگی‌ها و جریان کنترل دارد. برای مثال، این کار می‌کند:

    let x: i32;

loop {
    // Rust doesn't understand that this branch will be taken unconditionally,
    // because it relies on actual values.
    if true {
        // But it does understand that it will only be taken once because
        // we unconditionally break out of it. Therefore `x` doesn't
        // need to be marked as mutable.
        x = 0;
        break;
    }
}
// It also knows that it's impossible to get here without reaching the break.
// And therefore that `x` must be initialized here!
println!("{}", x);

    اگر مقداری از یک متغیر منتقل (move) شود، آن متغیر از نظر منطقی مقداردهی‌نشده می‌شود، به شرطی که نوع مقدار Copy نباشد. یعنی:

    fn main() {
    let x = 0;
    let y = Box::new(0);
    let z1 = x; // x is still valid because i32 is Copy
    let z2 = y; // y is now logically uninitialized because Box isn't Copy
}

    با این حال، انتساب مجدد به y در این مثال نیاز دارد که y تغییرپذیر علامت‌گذاری شود، چون یک برنامه‌ی Safe Rust می‌تواند تغییر مقدار y را مشاهده کند:

    fn main() {
    let mut y = Box::new(0);
    let z = y; // y is now logically uninitialized because Box isn't Copy
    y = Box::new(1); // reinitialize y
}

    در غیر این صورت، مثل این است که y یک متغیر کاملاً جدید است.
