    عملگر نقطه

    عملگر نقطه کارهای جادویی زیادی برای تبدیل نوع‌ها انجام می‌دهد. این عملگر تا زمانی که نوع‌ها با هم مطابقت پیدا کنند، ارجاع‌گیری خودکار، ارجاع‌زدایی خودکار و coercion انجام می‌دهد. سازوکار دقیق جست‌وجوی متد اینجا تعریف شده است، اما در ادامه مروری کوتاه می‌آید که مراحل اصلی را توضیح می‌دهد.

    فرض کنید تابعی به نام foo داریم که یک گیرنده (receiver) دارد (یعنی پارامتری از نوع self، &self یا &mut self). اگر value.foo() را فراخوانی کنیم، کامپایلر باید پیش از آنکه بتواند پیاده‌سازی درست تابع را صدا بزند، تعیین کند که Self چه نوعی است. در این مثال فرض می‌کنیم value از نوع T است.

    برای اینکه دقیقاً روشن باشد تابع را روی کدام نوع فراخوانی می‌کنیم، از نحو کاملاً مشخص (fully-qualified) استفاده خواهیم کرد.

    • ابتدا کامپایلر بررسی می‌کند که آیا می‌تواند T::foo(value) را مستقیماً فراخوانی کند. این همان فراخوانی متد «با مقدار» (by value) نامیده می‌شود.
    • اگر نتواند این تابع را فراخوانی کند (برای مثال چون تابع نوع نادرستی دارد یا یک صفت برای Self پیاده‌سازی نشده است)، کامپایلر تلاش می‌کند یک ارجاع خودکار اضافه کند. یعنی <&T>::foo(value) و <&mut T>::foo(value) را امتحان می‌کند. این همان فراخوانی متد «autoref» نامیده می‌شود.
    • اگر هیچ‌یک از این گزینه‌ها کار نکرد، T را ارجاع‌زدایی می‌کند و دوباره تلاش می‌کند. این کار از صفت Deref استفاده می‌کند؛ اگر T: Deref<Target = U> برقرار باشد، به‌جای T با نوع U دوباره تلاش می‌کند. اگر نتواند T را ارجاع‌زدایی کند، می‌تواند unsizing را نیز روی T امتحان کند. این یعنی اگر T پارامتر اندازه‌ای داشته باشد که در زمان کامپایل معلوم است، آن را برای هدف حل‌کردن متدها «فراموش» می‌کند. برای مثال، این مرحله‌ی unsizing می‌تواند با «فراموش‌کردن» اندازه‌ی آرایه، [i32; 2] را به [i32] تبدیل کند.

    این هم مثالی از الگوریتم جست‌وجوی متد:

    let array: Rc<Box<[T; 3]>> = ...;
let first_entry = array[0];

    کامپایلر وقتی آرایه پشت این‌همه لایه‌ی غیرمستقیم قرار دارد، array[0] را واقعاً چگونه محاسبه می‌کند؟ نخست، array[0] در حقیقت فقط شکر نحوی برای صفت Index است؛ کامپایلر array[0] را به array.index(0) تبدیل می‌کند. سپس کامپایلر بررسی می‌کند که آیا array صفت Index را پیاده‌سازی کرده است تا بتواند تابع را فراخوانی کند.

    پس از آن، کامپایلر بررسی می‌کند که آیا Rc<Box<[T; 3]>> صفت Index را پیاده‌سازی کرده است، که نکرده است؛ &Rc<Box<[T; 3]>> و &mut Rc<Box<[T; 3]>> هم پیاده‌سازی نکرده‌اند. چون هیچ‌کدام کار نکرد، کامپایلر Rc<Box<[T; 3]>> را به Box<[T; 3]> ارجاع‌زدایی می‌کند و دوباره تلاش می‌کند. Box<[T; 3]>، &Box<[T; 3]> و &mut Box<[T; 3]> صفت Index را پیاده‌سازی نمی‌کنند، پس دوباره ارجاع‌زدایی می‌کند. [T; 3] و autorefهای آن نیز Index را پیاده‌سازی نمی‌کنند. [T; 3] را نمی‌توان ارجاع‌زدایی کرد، بنابراین کامپایلر آن را unsize می‌کند و [T] به دست می‌آید. سرانجام [T] صفت Index را پیاده‌سازی می‌کند، پس اکنون می‌تواند تابع واقعی index را فراخوانی کند.

    مثال پیچیده‌تر زیر را از عملکرد عملگر نقطه در نظر بگیرید:

    fn do_stuff<T: Clone>(value: &T) {
    let cloned = value.clone();
}

    نوع cloned چیست؟ نخست کامپایلر بررسی می‌کند که آیا می‌تواند با مقدار فراخوانی کند. نوع value برابر &T است و بنابراین تابع clone امضای fn clone(&T) -> T را دارد. کامپایلر می‌داند که T: Clone برقرار است، پس نتیجه می‌گیرد که cloned: T.

    اگر قید T: Clone حذف شود چه می‌شود؟ کامپایلر نمی‌تواند با مقدار فراخوانی کند، زیرا هیچ پیاده‌سازی‌ای از Clone برای T وجود ندارد. بنابراین کامپایلر تلاش می‌کند با autoref فراخوانی کند. در این حالت، چون Self = &T، تابع امضای fn clone(&&T) -> &T را دارد. کامپایلر می‌بیند که &T: Clone برقرار است و سپس نتیجه می‌گیرد که cloned: &T.

    این هم مثال دیگری که در آن رفتار autoref اثرهای ظریفی ایجاد می‌کند:

    use std::sync::Arc;

#[derive(Clone)]
struct Container<T>(Arc<T>);

fn clone_containers<T>(foo: &Container<i32>, bar: &Container<T>) {
    let foo_cloned = foo.clone();
    let bar_cloned = bar.clone();
}

    نوع foo_cloned و bar_cloned چیست؟ می‌دانیم Container<i32>: Clone برقرار است، بنابراین کامپایلر clone را با مقدار فراخوانی می‌کند و foo_cloned: Container<i32> به دست می‌آید. اما bar_cloned در واقع از نوع &Container<T> است. مطمئناً این منطقی به نظر نمی‌رسد؛ ما #[derive(Clone)] را به Container اضافه کرده‌ایم، پس باید Clone را پیاده‌سازی کرده باشد! با نگاه دقیق‌تر، کدی که ماکروی derive تولید می‌کند (تقریباً) این است:

    impl<T> Clone for Container<T> where T: Clone {
    fn clone(&self) -> Self {
        Self(Arc::clone(&self.0))
    }
}

    پیاده‌سازی مشتق‌شده‌ی Clone فقط در جایی تعریف می‌شود که T: Clone برقرار باشد، بنابراین برای T جنریک هیچ پیاده‌سازی‌ای از Container<T>: Clone وجود ندارد. سپس کامپایلر بررسی می‌کند که آیا &Container<T> صفت Clone را پیاده‌سازی کرده است، که کرده است. پس نتیجه می‌گیرد که clone با autoref فراخوانی می‌شود و در نتیجه bar_cloned از نوع &Container<T> است.

    می‌توانیم این مشکل را با پیاده‌سازی دستی Clone و بدون نیاز به T: Clone برطرف کنیم:

    impl<T> Clone for Container<T> {
    fn clone(&self) -> Self {
        Self(Arc::clone(&self.0))
    }
}

    اکنون بررسی‌کننده‌ی نوع نتیجه می‌گیرد که bar_cloned: Container<T>.
