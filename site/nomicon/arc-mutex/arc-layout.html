    چیدمان

    بیایید با ساختن چیدمان پیاده‌سازی Arc شروع کنیم.

    یک Arc<T> مالکیت مشترکِ ایمن برای نخ‌ها را بر مقداری از نوع T فراهم می‌کند که در heap تخصیص یافته است. در Rust اشتراک‌گذاری به معنای تغییرناپذیری است، پس لازم نیست چیزی طراحی کنیم که دسترسی به آن مقدار را مدیریت کند، درست است؟ هرچند نوع‌های دارای تغییرپذیری درونی مانند Mutex به کاربران Arc اجازه می‌دهند تغییرپذیری مشترک بسازند، خود Arc لازم نیست درگیر این مسائل شود.

    با این حال یک جا هست که Arc باید به تغییر توجه کند: نابودی. وقتی همهٔ مالکان Arc از بین می‌روند، باید بتوانیم محتوای آن را drop کنیم و تخصیص آن را آزاد کنیم. پس به راهی نیاز داریم تا یک مالک بفهمد آخرین مالک است یا نه، و ساده‌ترین راه برای این کار شمارش مالکان است – یعنی شمارش ارجاع (Reference Counting).

    متأسفانه این شمارندهٔ ارجاع ذاتاً حالتی تغییرپذیر و مشترک است، بنابراین Arc باید به همگام‌سازی فکر کند. می‌توانستیم برای این کار از Mutex استفاده کنیم، اما زیادی است. به جای آن از اتمیک‌ها استفاده می‌کنیم. و چون همه به هر حال به یک اشاره‌گر به تخصیص T نیاز دارند، بهتر است شمارندهٔ ارجاع را هم در همان تخصیص قرار دهیم.

    در ساده‌ترین حالت چیزی شبیه این خواهد بود:

    use std::sync::atomic;

pub struct Arc<T> {
    ptr: *mut ArcInner<T>,
}

pub struct ArcInner<T> {
    rc: atomic::AtomicUsize,
    data: T,
}

    این کد کامپایل می‌شود، اما نادرست است. اول اینکه کامپایلر واریانس بیش از حد سخت‌گیرانه‌ای به ما می‌دهد. برای مثال، Arc<&'static str> را نمی‌توان جایی به کار برد که Arc<&'a str> انتظار می‌رود. مهم‌تر اینکه اطلاعات مالکیت نادرستی به drop checker می‌دهد، چون فرض می‌کند هیچ مقداری از نوع T را مالک نیستیم. از آنجا که این ساختار مالکیت مشترک یک مقدار را فراهم می‌کند، در نقطه‌ای نمونه‌ای از این ساختار وجود خواهد داشت که داده‌اش را به‌طور کامل مالک است. برای همهٔ جزئیات دربارهٔ واریانس و drop check، فصل مالکیت و طول عمرها را ببینید.

    برای رفع مشکل اول می‌توانیم از NonNull<T> استفاده کنیم. توجه کنید که NonNull<T> پوششی روی یک اشاره‌گر خام است که اعلام می‌کند:

    • نسبت به T هم‌وردا (covariant) هستیم
    • اشاره‌گر ما هرگز null نیست

    برای رفع مشکل دوم می‌توانیم یک نشانگر PhantomData شامل ArcInner<T> اضافه کنیم. این به drop checker می‌گوید که ما درکی از مالکیت یک مقدار ArcInner<T> (که خودش شامل مقداری T است) داریم.

    با این تغییرات ساختار نهایی خود را به دست می‌آوریم:

    use std::marker::PhantomData;
use std::ptr::NonNull;
use std::sync::atomic::AtomicUsize;

pub struct Arc<T> {
    ptr: NonNull<ArcInner<T>>,
    phantom: PhantomData<ArcInner<T>>,
}

pub struct ArcInner<T> {
    rc: AtomicUsize,
    data: T,
}
