    کد پایه

    اکنون که چیدمان پیاده‌سازی Arc را تعیین کرده‌ایم، بیایید مقداری کد پایه بنویسیم.

    ساخت Arc

    نخست به راهی برای ساختن یک Arc<T> نیاز داریم.

    این کار نسبتاً ساده است، چون فقط باید ArcInner<T> را در یک box قرار دهیم و یک اشاره‌گر NonNull<T> به آن بگیریم.

    impl<T> Arc<T> {
    pub fn new(data: T) -> Arc<T> {
        // We start the reference count at 1, as that first reference is the
        // current pointer.
        let boxed = Box::new(ArcInner {
            rc: AtomicUsize::new(1),
            data,
        });
        Arc {
            // It is okay to call `.unwrap()` here as we get a pointer from
            // `Box::into_raw` which is guaranteed to not be null.
            ptr: NonNull::new(Box::into_raw(boxed)).unwrap(),
            phantom: PhantomData,
        }
    }
}

    Send و Sync

    چون در حال ساختن یک ابزار همروندی هستیم، باید بتوانیم آن را بین نخ‌ها ارسال کنیم. بنابراین می‌توانیم صفت‌های نشانگر Send و Sync را پیاده‌سازی کنیم. برای اطلاعات بیشتر دربارهٔ آن‌ها، بخش مربوط به Send و Sync را ببینید.

    این کار مجاز است، چون:

    • فقط وقتی می‌توانید ارجاع تغییرپذیر به مقدار درون یک Arc بگیرید که آن Arc تنها Arcی باشد که به آن داده اشاره می‌کند (که فقط در Drop رخ می‌دهد)
    • برای شمارش مشترک و تغییرپذیر ارجاع‌ها از اتمیک‌ها استفاده می‌کنیم
    unsafe impl<T: Sync + Send> Send for Arc<T> {}
unsafe impl<T: Sync + Send> Sync for Arc<T> {}

    به کران T: Sync + Send نیاز داریم، چون اگر این کران‌ها را قرار نمی‌دادیم، می‌شد مقادیر ناایمن برای نخ‌ها را از طریق یک Arc از مرز نخ‌ها عبور داد، که ممکن بود باعث رقابت داده‌ای (data race) یا ناسالمی (unsoundness) شود.

    برای مثال، اگر این کران‌ها وجود نداشتند، Arc<Rc<u32>> نوعی Sync یا Send می‌شد؛ یعنی می‌توانستید Rc را از درون Arc کلون کنید و (بدون ساختن یک Rc کاملاً جدید) آن را به نخی دیگر بفرستید، که چون Rc ایمن برای نخ نیست، رقابت داده‌ای ایجاد می‌کرد.

    گرفتن ArcInner

    برای ارجاع‌زدایی اشاره‌گر NonNull<T> به یک &T می‌توانیم NonNull::as_ref را فراخوانی کنیم. برخلاف تابع as_ref معمول، این تابع unsafe است، بنابراین باید آن را این‌گونه فراخوانی کنیم:

    unsafe { self.ptr.as_ref() }

    این قطعه را چند بار در این کد به کار می‌بریم (معمولاً همراه با یک اتصال let).

    این unsafe بودن اشکالی ندارد، چون تا زمانی که این Arc زنده است، تضمین داریم که اشاره‌گر درونی معتبر است.

    Deref

    بسیار خوب. اکنون می‌توانیم Arc بسازیم (و به‌زودی خواهیم توانست آن‌ها را درست کلون و نابود کنیم)، اما چگونه به داده‌ٔ درون آن دسترسی پیدا کنیم؟

    اکنون به یک پیاده‌سازی از Deref نیاز داریم.

    باید این صفت را import کنیم:

    use std::ops::Deref;

    و این هم پیاده‌سازی:

    impl<T> Deref for Arc<T> {
    type Target = T;

    fn deref(&self) -> &T {
        let inner = unsafe { self.ptr.as_ref() };
        &inner.data
    }
}

    ساده است، نه؟ این کد فقط اشاره‌گر NonNull به ArcInner<T> را ارجاع‌زدایی می‌کند و سپس ارجاعی به داده‌ٔ درون آن می‌گیرد.

    کد

    این هم تمام کد این بخش:

        // current pointer.

            rc: AtomicUsize::new(1),
            data,

            // `Box::into_raw` which is guaranteed to not be null.
            ptr: NonNull::new(Box::into_raw(boxed)).unwrap(),
            phantom: PhantomData,

    }
}
