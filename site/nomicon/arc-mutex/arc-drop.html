    آزادسازی (Dropping)

    اکنون به راهی نیاز داریم که شمارندهٔ ارجاع را کاهش دهد و وقتی به اندازهٔ کافی کم شد، داده را drop کند؛ وگرنه داده برای همیشه روی heap باقی می‌ماند.

    برای این کار می‌توانیم Drop را پیاده‌سازی کنیم.

    در اصل باید:

    1. شمارندهٔ ارجاع را کاهش دهیم
    2. اگر فقط یک ارجاع به داده باقی مانده است، آنگاه:
    3. به‌طور اتمیک روی داده fence بگذاریم تا از جابه‌جایی ترتیب استفاده و حذف داده جلوگیری شود
    4. داده درونی را drop کنیم

    نخست باید به ArcInner دسترسی پیدا کنیم:

    let inner = unsafe { self.ptr.as_ref() };

    اکنون باید شمارندهٔ ارجاع را کاهش دهیم. برای ساده‌تر شدن کد، می‌توانیم در همان‌جا اگر مقدار برگشتیِ fetch_sub (مقدار شمارندهٔ ارجاع پیش از کاهش) برابر 1 نباشد (که وقتی رخ می‌دهد که ما آخرین ارجاع به داده نیستیم)، برگردیم.

    if inner.rc.fetch_sub(1, Ordering::Release) != 1 {
    return;
}

    سپس باید یک fence اتمیک بسازیم تا از جابه‌جایی ترتیب استفاده از داده و حذف آن جلوگیری شود. همان‌طور که در پیاده‌سازی Arc در کتابخانهٔ استاندارد توضیح داده شده است:

    این fence لازم است تا از جابه‌جایی ترتیب استفاده از داده و حذف آن جلوگیری شود. چون علامت Release دارد، کاهش شمارندهٔ ارجاع با این fence از نوع Acquire همگام می‌شود. یعنی استفاده از داده پیش از کاهش شمارندهٔ ارجاع رخ می‌دهد، که پیش از این fence رخ می‌دهد، که پیش از حذف داده رخ می‌دهد.

    همان‌طور که در مستندات Boost توضیح داده شده،

    مهم است که هر دسترسی ممکن به شیء در یک نخ (از طریق یک ارجاع موجود) پیش از حذف شیء در نخی دیگر رخ دهد. این کار با یک عملیات «release» پس از رها کردن یک ارجاع (هر دسترسی به شیء از طریق این ارجاع بدیهی است که باید پیش از آن رخ داده باشد)، و یک عملیات «acquire» پیش از حذف شیء به دست می‌آید.

    به‌طور خاص، هرچند محتوای یک Arc معمولاً تغییرناپذیر است، ممکن است نوشتن‌های درونی روی چیزی مانند Mutex<T> رخ دهد. چون هنگام حذف یک Mutex قفل آن گرفته نمی‌شود، نمی‌توانیم به منطق همگام‌سازی آن تکیه کنیم تا نوشتن‌های نخ A برای یک مخرب (destructor) که در نخ B اجرا می‌شود قابل مشاهده شوند.

    همچنین توجه کنید که fence از نوع Acquire در اینجا احتمالاً می‌تواند با یک بار‌خوانی Acquire جایگزین شود، که ممکن است عملکرد را در موقعیت‌های با رقابت زیاد بهبود دهد. 2 را ببینید.

    برای این کار، به این صورت عمل می‌کنیم:

    use std::sync::atomic::Ordering;
use std::sync::atomic;
atomic::fence(Ordering::Acquire);

    سرانجام می‌توانیم خود داده را drop کنیم. از Box::from_raw برای drop کردن ArcInner<T> درون box و داده‌اش استفاده می‌کنیم. این تابع یک *mut T می‌گیرد، نه NonNull<T>، بنابراین باید با NonNull::as_ptr تبدیل کنیم.

    unsafe { Box::from_raw(self.ptr.as_ptr()); }

    این کار ایمن است، چون می‌دانیم آخرین اشاره‌گر به ArcInner را داریم و اشاره‌گر آن معتبر است.

    اکنون همهٔ این‌ها را درون پیاده‌سازی Drop جمع می‌کنیم:

    impl<T> Drop for Arc<T> {
    fn drop(&mut self) {
        let inner = unsafe { self.ptr.as_ref() };
        if inner.rc.fetch_sub(1, Ordering::Release) != 1 {
            return;
        }
        // This fence is needed to prevent reordering of the use and deletion
        // of the data.
        atomic::fence(Ordering::Acquire);
        // This is safe as we know we have the last pointer to the `ArcInner`
        // and that its pointer is valid.
        unsafe { Box::from_raw(self.ptr.as_ptr()); }
    }
}
