    کلون‌کردن

    اکنون که مقداری کد پایه آماده کرده‌ایم، به راهی برای کلون‌کردن Arc نیاز داریم.

    در اصل باید:

    1. شمارندهٔ ارجاع اتمیک را افزایش دهیم
    2. یک نمونهٔ جدید از Arc را از اشاره‌گر درونی بسازیم

    نخست باید به ArcInner دسترسی پیدا کنیم:

    let inner = unsafe { self.ptr.as_ref() };

    می‌توانیم شمارندهٔ ارجاع اتمیک را این‌گونه به‌روزرسانی کنیم:

    let old_rc = inner.rc.fetch_add(1, Ordering::???);

    اما اینجا از چه ترتیبی (ordering) باید استفاده کنیم؟ در واقع هنگام کلون‌کردن کدی نداریم که به همگام‌سازی اتمیک نیاز داشته باشد، چون مقدار درونی را هنگام کلون‌کردن تغییر نمی‌دهیم. بنابراین می‌توانیم اینجا از ترتیب Relaxed استفاده کنیم که رابطهٔ happens-before ایجاد نمی‌کند، اما اتمیک است. با این حال هنگام Drop کردن Arc، به هنگام کاستن از شمارندهٔ ارجاع باید به‌طور اتمیک همگام‌سازی کنیم. این موضوع بیشتر در بخش مربوط به پیاده‌سازی Drop برای Arc توضیح داده شده است. برای اطلاعات بیشتر دربارهٔ روابط اتمیک و ترتیب Relaxed، بخش اتمیک‌ها را ببینید.

    بنابراین کد به این شکل درمی‌آید:

    let old_rc = inner.rc.fetch_add(1, Ordering::Relaxed);

    برای استفاده از Ordering باید import دیگری اضافه کنیم:

    use std::sync::atomic::Ordering;

    با این حال، اکنون یک مشکل در این پیاده‌سازی داریم. اگر کسی تصمیم بگیرد تعداد زیادی Arc را با mem::forget فراموش کند چه؟ کدی که تاکنون نوشته‌ایم (و خواهیم نوشت) فرض می‌کند شمارندهٔ ارجاع به‌درستی نشان می‌دهد چند Arc در حافظه وجود دارد، اما با mem::forget این فرض نادرست است. بنابراین وقتی Arcهای بیشتری از این Arc کلون شوند بدون اینکه Drop شوند و شمارندهٔ ارجاع کاهش یابد، ممکن است سرریز رخ دهد! این باعث use-after-free می‌شود که فوق‌العاده بد است!

    برای رسیدگی به این مشکل باید بررسی کنیم که شمارندهٔ ارجاع از یک مقدار دلخواه (کمتر از usize::MAX، چون شمارندهٔ ارجاع را در یک AtomicUsize نگه می‌داریم) فراتر نرود، و کاری بکنیم.

    پیاده‌سازی کتابخانهٔ استاندارد تصمیم گرفته است اگر شمارندهٔ ارجاع در هر نخی به isize::MAX (حدود نصف usize::MAX) برسد، برنامه را فقط abort کند (چون در کد معمولی حالتی بسیار نامحتمل است و اگر رخ دهد، برنامه احتمالاً به‌شدت منحط است)، با این فرض که احتمالاً حدود ۲ میلیارد نخ (یا روی برخی ماشین‌های ۶۴ بیتی حدود ۹ کوینتیلیون) به‌طور همزمان شمارندهٔ ارجاع را افزایش نمی‌دهند. ما هم همین کار را می‌کنیم.

    پیاده‌سازی این رفتار بسیار ساده است:

    if old_rc >= isize::MAX as usize {
    std::process::abort();
}

    سپس باید یک نمونهٔ جدید از Arc را برگردانیم:

    Self {
    ptr: self.ptr,
    phantom: PhantomData
}

    اکنون همهٔ این‌ها را درون پیاده‌سازی Clone جمع می‌کنیم:

    use std::sync::atomic::Ordering;

impl<T> Clone for Arc<T> {
    fn clone(&self) -> Arc<T> {
        let inner = unsafe { self.ptr.as_ref() };
        // Using a relaxed ordering is alright here as we don't need any atomic
        // synchronization here as we're not modifying or accessing the inner
        // data.
        let old_rc = inner.rc.fetch_add(1, Ordering::Relaxed);

        if old_rc >= isize::MAX as usize {
            std::process::abort();
        }

        Self {
            ptr: self.ptr,
            phantom: PhantomData,
        }
    }
}
