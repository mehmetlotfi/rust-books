کتاب برنامه‌های خط فرمانCommand Line Applications in Rust

    خروجی

    چاپ «Hello World»

    println!("Hello World");

    خب، این آسان بود. عالی! برویم سراغ موضوع بعدی.

    استفاده از println!

    تقریباً می‌توانید هر چیزی را که دوست دارید با ماکروی println! چاپ کنید. این ماکرو قابلیت‌های بسیار شگفت‌انگیزی دارد، اما سینتکس خاصی هم دارد. به‌عنوان پارامتر اول، یک رشتهٔ لفظی (literal) را انتظار دارد که شامل جانگهدارها (placeholder) باشد. این رشته با مقادیر پارامترهایی که بعد از آن به‌عنوان آرگومان می‌آیند پر می‌شود.

    برای مثال:

    let x = 42;
println!("My lucky number is {}.", x);

    این چاپ خواهد کرد:

    My lucky number is 42.

    آکولادهای ({}) درون رشتهٔ بالا یکی از این جانگهدارها هستند. این نوع جانگهدار پیش‌فرض است و تلاش می‌کند مقدار داده‌شده را به شکلی خوانا برای انسان چاپ کند. برای اعداد و رشته‌ها، این به‌خوبی کار می‌کند، اما همهٔ نوع‌ها نمی‌توانند چنین کاری کنند. به همین دلیل یک «نمایش اشکال‌زدایی (debug)» نیز وجود دارد که با پر کردن آکولادهای جانگهدار به این شکل به دست می‌آید: {:?}.

    برای مثال:

    let xs = vec![1, 2, 3];
println!("The list is: {:?}", xs);

    این چاپ خواهد کرد:

    The list is: [1, 2, 3]

    اگر می‌خواهید نوع‌های داده‌ای خودتان برای اشکال‌زدایی و لاگ‌گیری قابل چاپ باشند، معمولاً می‌توانید #[derive(Debug)] را بالای تعریفشان اضافه کنید.

    توجه: چاپ «کاربرپسند» با استفاده از trait با نام Display انجام می‌شود و خروجی debug (خوانا برای انسان اما هدف‌گرفته‌شده برای توسعه‌دهندگان) از trait با نام Debug استفاده می‌کند. اطلاعات بیشتر دربارهٔ سینتکسی که می‌توانید در println! به کار ببرید را در مستندات ماژول std::fmt می‌یابید.

    چاپ خطاها

    خطاها باید از طریق stderr چاپ شوند تا کار برای کاربران و ابزارهای دیگر آسان‌تر شود و بتوانند خروجی‌هایشان را به فایل‌ها یا ابزارهای بیشتر پایپ کنند.

    توجه: در بیشتر سیستم‌عامل‌ها، یک برنامه می‌تواند روی دو جریان خروجی بنویسد: stdout و stderr. stdout برای خروجی واقعی برنامه است در حالی که stderr اجازه می‌دهد خطاها و پیام‌های دیگر جدا از stdout نگه داشته شوند. به این ترتیب، خروجی را می‌توان در یک فایل ذخیره کرد یا به برنامهٔ دیگری پایپ کرد در حالی که خطاها به کاربر نشان داده می‌شوند.

    در Rust، این کار با println! و eprintln! انجام می‌شود، که اولی روی stdout و دومی روی stderr چاپ می‌کند.

    println!("This is information");
eprintln!("This is an error! :(");

    احتیاط کنید: چاپ کدهای escape می‌تواند خطرناک باشد و ترمینال کاربر را به وضعیتی عجیب بیندازد. هنگام چاپ دستی آن‌ها همیشه دقت کنید!

    در حالت ایده‌آل، هنگام کار با کدهای escape خام باید از crateای مانند ansi_term استفاده کنید تا کار خودتان (و کاربرانتان) را آسان‌تر کنید.

    نکته‌ای دربارهٔ کارایی چاپ

    چاپ در ترمینال به‌طرز شگفت‌آوری کند است! اگر مواردی مانند println! را در یک حلقه فراخوانی کنید، به‌آسانی می‌تواند به گلوگاه برنامه‌ای تبدیل شود که در غیر این صورت سریع است. برای سریع‌تر کردن آن، دو کار می‌توانید انجام دهید.

    اول، شاید بخواهید تعداد نوشتن‌هایی را کاهش دهید که واقعاً در ترمینال «flush» می‌شوند. println! به سیستم می‌گوید هر بار در ترمینال flush کند چون چاپ هر خط جدید رایج است. اگر به آن نیازی ندارید، می‌توانید دستگیرهٔ stdout خود را در یک BufWriter بپیچید، که به‌طور پیش‌فرض تا ۸ کیلوبایت بافر می‌کند. هنگامی که می‌خواهید فوراً چاپ کنید، همچنان می‌توانید .flush() را روی این BufWriter فراخوانی کنید.

    use std::io::{self, Write};

let stdout = io::stdout(); // get the global stdout entity
let mut handle = io::BufWriter::new(stdout); // optional: wrap that handle in a buffer
writeln!(handle, "foo: {}", 42); // add `?` if you care about errors here

    دوم، مفید است که روی stdout (یا stderr) یک قفل بگیرید و با writeln! مستقیم روی آن چاپ کنید. این کار مانع می‌شود که سیستم بارها و بارها stdout را قفل و باز کند.

    use std::io::{self, Write};

let stdout = io::stdout(); // get the global stdout entity
let mut handle = stdout.lock(); // acquire a lock on it
writeln!(handle, "foo: {}", 42); // add `?` if you care about errors here

    همچنین می‌توانید این دو رویکرد را با هم ترکیب کنید.

    نمایش نوار پیشرفت

    برخی برنامه‌های CLI کمتر از یک ثانیه اجرا می‌شوند، در حالی که برخی دیگر دقیقه‌ها یا ساعت‌ها طول می‌کشند. اگر از نوع دوم برنامه‌ها می‌نویسید، شاید بخواهید به کاربر نشان دهید که چیزی در حال رخ دادن است. برای این کار، باید تلاش کنید به‌روزرسانی‌های وضعیت مفید چاپ کنید، ترجیحاً به شکلی که به‌آسانی قابل مصرف باشد.

    با استفاده از crate با نام indicatif می‌توانید به برنامهٔ خود نوار پیشرفت و چرخان‌های کوچک (spinner) اضافه کنید. این یک مثال سریع است:

    fn main() {
    let pb = indicatif::ProgressBar::new(100);
    for i in 0..100 {
        do_hard_work();
        pb.println(format!("[+] finished #{}", i));
        pb.inc(1);
    }
    pb.finish_with_message("done");
}

    برای اطلاعات بیشتر، مستندات و مثال‌ها را ببینید.

    لاگ‌گیری

    برای اینکه درک آنچه در برنامهٔ ما رخ می‌دهد آسان‌تر شود، شاید بخواهیم چند دستور لاگ اضافه کنیم. این کار معمولاً هنگام نوشتن برنامه آسان است، و وقتی شش ماه بعد دوباره این برنامه را اجرا کنید فوق‌العاده مفید خواهد بود. از جهاتی، لاگ‌گیری همان استفاده از println! است با این تفاوت که می‌توانید اهمیت پیام را مشخص کنید. سطح‌هایی که معمولاً می‌توانید استفاده کنید error، warn، info، debug و trace هستند (error بالاترین اولویت و trace پایین‌ترین را دارد).

    برای افزودن لاگ‌گیری ساده به برنامهٔ خود، به دو چیز نیاز دارید: crate با نام log (که ماکروهایی به نام سطح‌های لاگ در خود دارد) و یک آداپتور که لاگ را واقعاً در جایی مفید می‌نویسد. داشتن امکان استفاده از آداپتورهای لاگ بسیار انعطاف‌پذیر است: برای مثال، می‌توانید از آن‌ها استفاده کنید تا لاگ‌ها را نه‌فقط در ترمینال، بلکه در syslog یا یک سرور مرکزی لاگ نیز بنویسید.

    از آنجا که فقط به نوشتن یک برنامهٔ CLI اهمیت می‌دهیم، یک آداپتور آسان برای استفاده env_logger است. به آن لاگر «env» می‌گویند چون می‌توانید با یک متغیر محیطی مشخص کنید کدام بخش‌های برنامه‌تان را می‌خواهید لاگ کنید و در چه سطحی آن‌ها را لاگ کنید. این آداپتور پیش از پیام‌های لاگ شما یک مهر زمانی و ماژولی را که پیام‌های لاگ از آن می‌آیند می‌افزاید. از آنجا که کتابخانه‌ها نیز می‌توانند از log استفاده کنند، خروجی لاگ آن‌ها را هم به‌آسانی می‌توانید پیکربندی کنید.

    این یک مثال سریع است:

    use log::{info, warn};

fn main() {
    env_logger::init();
    info!("starting up");
    warn!("oops, nothing implemented!");
}

    با فرض اینکه این فایل را به‌صورت src/bin/output-log.rs دارید، در Linux و macOS می‌توانید آن را این‌گونه اجرا کنید:

    $ env RUST_LOG=info cargo run --bin output-log
    Finished dev [unoptimized + debuginfo] target(s) in 0.17s
     Running `target/debug/output-log`
[2018-11-30T20:25:52Z INFO  output_log] starting up
[2018-11-30T20:25:52Z WARN  output_log] oops, nothing implemented!

    در Windows PowerShell می‌توانید آن را این‌گونه اجرا کنید:

    $ $env:RUST_LOG="info"
$ cargo run --bin output-log
    Finished dev [unoptimized + debuginfo] target(s) in 0.17s
     Running `target/debug/output-log.exe`
[2018-11-30T20:25:52Z INFO  output_log] starting up
[2018-11-30T20:25:52Z WARN  output_log] oops, nothing implemented!

    در Windows CMD می‌توانید آن را این‌گونه اجرا کنید:

    $ set RUST_LOG=info
$ cargo run --bin output-log
    Finished dev [unoptimized + debuginfo] target(s) in 0.17s
     Running `target/debug/output-log.exe`
[2018-11-30T20:25:52Z INFO  output_log] starting up
[2018-11-30T20:25:52Z WARN  output_log] oops, nothing implemented!

    RUST_LOG نام متغیر محیطی‌ای است که می‌توانید برای تنظیم پیکربندی لاگ خود از آن استفاده کنید. env_logger یک سازنده (builder) هم دارد تا بتوانید این تنظیمات را به‌صورت برنامه‌نویسی‌شده تغییر دهید، مثلاً نمایش پیام‌های سطح info به‌طور پیش‌فرض.

    آداپتورهای لاگ جایگزین بسیار زیادی وجود دارند و نیز جایگزین‌ها و افزونه‌هایی برای log. اگر می‌دانید برنامهٔ شما چیزهای زیادی برای لاگ کردن خواهد داشت، حتماً آن‌ها را بررسی کنید و زندگی کاربرانتان را آسان‌تر کنید.

    نکته: تجربه نشان داده است که حتی برنامه‌های CLI با فایدهٔ اندک هم ممکن است سال‌ها مورد استفاده قرار گیرند، به‌ویژه اگر قرار بوده راه‌حلی موقت باشند. اگر برنامهٔ شما کار نمی‌کند و کسی (مثلاً خودتان در آینده) باید بفهمد چرا، امکان دادن --verbose برای گرفتن خروجی لاگ بیشتر می‌تواند تفاوت میان چند دقیقه و چند ساعت اشکال‌زدایی را رقم بزند. crate با نام clap-verbosity-flag راه سریعی را در خود دارد برای افزودن --verbose به پروژه‌ای که از clap استفاده می‌کند.
