کتاب برنامه‌های خط فرمانCommand Line Applications in Rust

    تجزیهٔ آرگومان‌های خط فرمان

    یک فراخوانی معمول ابزار CLI ما چنین به نظر می‌رسد:

    $ grrs foobar test.txt

    انتظار داریم برنامه‌مان به test.txt نگاه کند و خط‌هایی را که شامل foobar هستند چاپ کند. اما این دو مقدار را چگونه به دست بیاوریم؟

    متنی که بعد از نام برنامه می‌آید اغلب «آرگومان‌های خط فرمان» یا «پرچم‌های خط فرمان» نامیده می‌شود (به‌ویژه وقتی شبیه --this باشند). در درون، سیستم‌عامل معمولاً آن‌ها را به‌صورت فهرستی از رشته‌ها نمایش می‌دهد. معمولاً با فاصله از هم جدا می‌شوند.

    راه‌های بسیاری برای فکر کردن به این آرگومان‌ها و تجزیهٔ آن‌ها به چیزی که کار با آن آسان‌تر باشد وجود دارد. همچنین باید به کاربران برنامه‌تان بگویید چه آرگومان‌هایی را باید بدهند و انتظار می‌رود در چه قالبی باشند.

    گرفتن آرگومان‌ها

    کتابخانهٔ استاندارد تابع std::env::args() را دارد که یک iterator از آرگومان‌های داده‌شده به شما می‌دهد. نخستین مورد (در اندیس 0) نامی است که برای فراخوانی برنامه‌تان به کار رفته (مثلاً grrs). موارد بعدی آن چیزی هستند که کاربر پس از آن نوشته است.

    گرفتن آرگومان‌های خام به این روش سرراست است (در فایل src/main.rs):

    fn main() {
    let pattern = std::env::args().nth(1).expect("no pattern given");
    let path = std::env::args().nth(2).expect("no path given");

    println!("pattern: {:?}, path: {:?}", pattern, path)
}

    می‌توانیم آن را با cargo run اجرا کنیم و آرگومان‌ها را با نوشتن آن‌ها بعد از -- بدهیم:

    $ cargo run -- some-pattern some-file
    Finished dev [unoptimized + debuginfo] target(s) in 0.11s
     Running `target/debug/grrs some-pattern some-file`
pattern: "some-pattern", path: "some-file"

    آرگومان‌های CLI به‌عنوان نوع‌های داده

    به‌جای اینکه به آن‌ها به چشم مجموعه‌ای متن نگاه کنیم، اغلب ارزش دارد آرگومان‌های CLI را یک نوع دادهٔ سفارشی در نظر بگیریم که ورودی‌های برنامهٔ شما را نمایش می‌دهد.

    اگر به grrs foobar test.txt نگاه کنیم، دو آرگومان وجود دارد: اول pattern (رشته‌ای که باید جست‌وجو شود)، و سپس path (فایلی که باید در آن جست‌وجو شود).

    دربارهٔ آن‌ها چه چیز دیگری می‌توانیم بگوییم؟ برای شروع، هر دو الزامی هستند. دربارهٔ هیچ مقدار پیش‌فرضی صحبت نکرده‌ایم، پس انتظار داریم کاربران همیشه دو مقدار بدهند. علاوه بر این، می‌توانیم چیزی دربارهٔ نوع آن‌ها بگوییم: انتظار می‌رود الگو یک رشته باشد در حالی که آرگومان دوم مسیر یک فایل است.

    در Rust، ساختاردهی برنامه‌ها پیرامون داده‌هایی که مدیریت می‌کنند رایج است، بنابراین این شیوهٔ نگاه به آرگومان‌های CLI بسیار مناسب است. بیایید با این شروع کنیم (در فایل src/main.rs، قبل از fn main() {):

    struct Cli {
    pattern: String,
    path: std::path::PathBuf,
}

    این یک ساختار جدید (یک struct) تعریف می‌کند که دو فیلد برای ذخیرهٔ داده دارد: pattern و path.

    توجه: PathBuf مانند String است، اما برای مسیرهای سیستم فایل که به‌صورت چندسکویی کار می‌کنند.

    اکنون هنوز باید آرگومان‌های واقعی را به این شکل تبدیل کنیم. یک گزینه این است که فهرست رشته‌هایی را که از سیستم‌عامل می‌گیریم خودمان به‌صورت دستی تجزیه کنیم و ساختار را بسازیم. چیزی شبیه این خواهد بود:

    fn main() {
    let pattern = std::env::args().nth(1).expect("no pattern given");
    let path = std::env::args().nth(2).expect("no path given");

    let args = Cli {
        pattern,
        path: std::path::PathBuf::from(path),
    };

    println!("pattern: {:?}, path: {:?}", args.pattern, args.path);
}

    این کار می‌کند، اما چندان راحت نیست. چگونه با نیاز به پشتیبانی از --pattern="foo" یا --pattern "foo" برخورد می‌کردید؟ --help را چگونه پیاده‌سازی می‌کردید؟

    تجزیهٔ آرگومان‌های CLI با Clap

    راه راحت‌تر استفاده از یکی از کتابخانه‌های فراوان موجود است. محبوب‌ترین کتابخانه برای تجزیهٔ آرگومان‌های خط فرمان clap نام دارد. همهٔ قابلیت‌هایی را که انتظار دارید دارد، از جمله پشتیبانی از زیرفرمان‌ها، تکمیل خودکار پوسته و پیام‌های راهنمای عالی.

    بیایید ابتدا با افزودن clap = { version = "4.0", features = ["derive"] } به بخش [dependencies] فایل Cargo.toml خود، clap را وارد کنیم.

    اکنون می‌توانیم در کدمان use clap::Parser; را بنویسیم و #[derive(Parser)] را درست بالای struct Cli اضافه کنیم. بیایید در این بین چند کامنت مستندسازی هم بنویسیم.

    چنین به نظر می‌رسد (در فایل src/main.rs، قبل از fn main() {):

    use clap::Parser;

/// Search for a pattern in a file and display the lines that contain it.
#[derive(Parser)]
struct Cli {
    /// The pattern to look for
    pattern: String,
    /// The path to the file to read
    path: std::path::PathBuf,
}

    توجه: ویژگی‌های سفارشی (attribute) بسیاری وجود دارد که می‌توانید به فیلدها اضافه کنید. برای مثال، برای اینکه بگویید می‌خواهید این فیلد برای آرگومان بعد از -o یا --output استفاده شود، باید #[arg(short = 'o', long = "output")] را اضافه کنید. برای اطلاعات بیشتر، مستندات clap را ببینید.

    درست زیر ساختار Cli، قالب ما تابع main آن را دارد. وقتی برنامه شروع به کار می‌کند، این تابع را فراخوانی می‌کند:

    fn main() {
    let args = Cli::parse();

    println!("pattern: {:?}, path: {:?}", args.pattern, args.path)
}

    این تلاش می‌کند آرگومان‌ها را به ساختار Cli ما تجزیه کند.

    اما اگر این شکست بخورد چه؟ زیبایی این رویکرد همین‌جاست: Clap می‌داند چه فیلدهایی را انتظار داشته باشد و قالب مورد انتظار آن‌ها چیست. می‌تواند به‌طور خودکار یک پیام --help زیبا تولید کند و نیز خطاهای بسیار خوبی بدهد که وقتی --putput نوشته‌اید پیشنهاد کند --output را بدهید.

    توجه: متد parse برای استفاده در تابع main شما در نظر گرفته شده است. وقتی شکست بخورد، یک پیام خطا یا راهنما چاپ می‌کند و بلافاصله از برنامه خارج می‌شود. از آن در جاهای دیگر استفاده نکنید!

    جمع‌بندی

    کد شما اکنون باید این‌گونه باشد:

    use clap::Parser;

/// Search for a pattern in a file and display the lines that contain it.
#[derive(Parser)]
struct Cli {
    /// The pattern to look for
    pattern: String,
    /// The path to the file to read
    path: std::path::PathBuf,
}

fn main() {
    let args = Cli::parse();

    println!("pattern: {:?}, path: {:?}", args.pattern, args.path)
}

    اجرای آن بدون هیچ آرگومانی:

    $ cargo run
    Finished dev [unoptimized + debuginfo] target(s) in 10.16s
     Running `target/debug/grrs`
error: The following required arguments were not provided:
    <pattern>
    <path>

USAGE:
    grrs <pattern> <path>

For more information try --help

    اجرای آن با دادن آرگومان‌ها:

    $ cargo run -- some-pattern some-file
    Finished dev [unoptimized + debuginfo] target(s) in 0.11s
     Running `target/debug/grrs some-pattern some-file`
pattern: "some-pattern", path: "some-file"

    این خروجی نشان می‌دهد برنامهٔ ما با موفقیت آرگومان‌ها را به ساختار Cli تجزیه کرد.
