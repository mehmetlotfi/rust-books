کتاب برنامه‌های خط فرمانCommand Line Applications in Rust

    ارتباط با ماشین‌ها

    قدرت ابزارهای خط فرمان وقتی واقعاً خودش را نشان می‌دهد که بتوانید آن‌ها را با هم ترکیب کنید. این ایدهٔ جدیدی نیست: در واقع، این جمله‌ای از فلسفهٔ یونیکس است:

    انتظار داشته باشید خروجی هر برنامه به ورودی برنامه‌ای دیگر تبدیل شود، برنامه‌ای که هنوز ناشناخته است.

    اگر برنامه‌های ما این انتظار را برآورده کنند، کاربرانمان راضی خواهند بود. برای اطمینان از اینکه این کار خوب عمل می‌کند، باید نه‌فقط خروجی زیبا برای انسان‌ها، بلکه نسخه‌ای متناسب با نیاز برنامه‌های دیگر نیز ارائه دهیم. ببینیم چگونه می‌توانیم این کار را انجام دهیم.

    توجه: ابتدا حتماً فصل مربوط به خروجی CLI را در آموزش بخوانید. آن فصل توضیح می‌دهد که چگونه خروجی را در ترمینال بنویسید.

    چه کسی این را می‌خواند؟

    نخستین پرسشی که باید بپرسیم این است: آیا خروجی ما برای انسانی است که پشت یک ترمینال رنگی نشسته، یا برای برنامه‌ای دیگر؟ برای پاسخ به این پرسش، می‌توانیم از trait با نام IsTerminal استفاده کنیم:

    use std::io::IsTerminal;

if std::io::stdout().is_terminal() {
    println!("I'm a terminal");
} else {
    println!("I'm not");
}

    بسته به اینکه چه کسی خروجی ما را خواهد خواند، می‌توانیم اطلاعات اضافه‌ای بیفزاییم. انسان‌ها معمولاً رنگ را دوست دارند، برای مثال، اگر ls را در یک پروژهٔ تصادفی Rust اجرا کنید، ممکن است چیزی شبیه این ببینید:

    $ ls
CODE_OF_CONDUCT.md   LICENSE-APACHE       examples
CONTRIBUTING.md      LICENSE-MIT          proptest-regressions
Cargo.lock           README.md            src
Cargo.toml           convey_derive        target

    از آنجا که این سبک برای انسان‌ها ساخته شده، در بیشتر پیکربندی‌ها حتی برخی از نام‌ها (مانند src) را رنگی چاپ می‌کند تا نشان دهد پوشه هستند. اگر در عوض آن را به یک فایل، یا برنامه‌ای مانند cat پایپ کنید، ls خروجی‌اش را تطبیق می‌دهد. به‌جای استفاده از ستون‌هایی که در پنجرهٔ ترمینال من جا شوند هر ورودی را در خط خودش چاپ می‌کند. همچنین هیچ رنگی تولید نمی‌کند.

    $ ls | cat
CODE_OF_CONDUCT.md
CONTRIBUTING.md
Cargo.lock
Cargo.toml
LICENSE-APACHE
LICENSE-MIT
README.md
convey_derive
examples
proptest-regressions
src
target

    قالب‌های خروجی ساده برای ماشین‌ها

    از قدیم، تنها نوع خروجی‌ای که ابزارهای خط فرمان تولید می‌کردند رشته بود. این معمولاً برای افرادی که پشت ترمینال نشسته‌اند مشکلی ندارد، چون می‌توانند متن را بخوانند و دربارهٔ معنای آن استدلال کنند. اما برنامه‌های دیگر معمولاً چنین توانایی‌ای ندارند: تنها راه برای آن‌ها تا خروجی ابزاری مانند ls را بفهمند این است که نویسندهٔ برنامه یک تجزیه‌گر (parser) گنجانده باشد که برای هر چیزی که ls تولید می‌کند کار کند.

    این اغلب به آن معنا است که خروجی به چیزهایی محدود می‌شد که تجزیهٔ آن‌ها آسان است. قالب‌هایی مانند TSV (مقادیر جداشده با تب)، که در آن هر رکورد در خط خودش است و هر خط شامل محتوای جداشده با تب است، بسیار محبوب هستند. این قالب‌های ساده مبتنی بر خطوط متن اجازه می‌دهند ابزارهایی مانند grep روی خروجی ابزارهایی مانند ls به کار روند. | grep Cargo اهمیتی نمی‌دهد که خطوط شما از ls آمده‌اند یا از فایل، فقط خط‌به‌خط فیلتر می‌کند.

    اشکال این روش آن است که نمی‌توانید با یک فراخوانی ساده از grep همهٔ پوشه‌هایی را که ls به شما داده فیلتر کنید. برای این کار، هر آیتم پوشه باید داده‌های اضافی با خود حمل کند.

    خروجی JSON برای ماشین‌ها

    مقادیر جداشده با تب روشی ساده برای خروجی دادن داده‌های ساخت‌یافته است اما از برنامهٔ دیگر می‌خواهد بداند چه فیلدهایی را باید انتظار داشته باشد (و به چه ترتیبی) و خروجی دادن پیام‌هایی از انواع مختلف در آن دشوار است. برای مثال، فرض کنید برنامهٔ ما می‌خواهد به مصرف‌کننده پیام بدهد که در حال حاضر منتظر یک دانلود است، و پس از آن پیامی را خروجی دهد که داده‌های دریافت‌شده را توصیف می‌کند. این‌ها انواع بسیار متفاوتی از پیام هستند و تلاش برای یکپارچه کردن آن‌ها در خروجی TSV ما را وادار می‌کند راهی برای تمایز میان آن‌ها اختراع کنیم. وقتی بخواهیم پیامی چاپ کنیم که شامل دو فهرست از آیتم‌هایی با طول‌های متفاوت است نیز همین مشکل پیش می‌آید.

    با این حال، ایدهٔ خوبی است که قالبی را انتخاب کنیم که در بیشتر زبان‌های برنامه‌نویسی/محیط‌ها به‌آسانی قابل تجزیه باشد. از این رو، در سال‌های اخیر بسیاری از برنامه‌ها توانایی خروجی دادن داده‌هایشان را با JSON به دست آورده‌اند. این قالب آن‌قدر ساده است که تقریباً برای هر زبانی تجزیه‌گر دارد و در عین حال آن‌قدر قدرتمند است که در موارد بسیاری مفید باشد. با اینکه قالبی متنی است که انسان‌ها می‌توانند بخوانند، افراد بسیاری نیز روی پیاده‌سازی‌هایی کار کرده‌اند که در تجزیهٔ داده‌های JSON و سریال‌سازی داده‌ها به JSON بسیار سریع هستند.

    در توضیح بالا، از «پیام‌هایی» صحبت کردیم که برنامهٔ ما می‌نویسد. این شیوهٔ خوبی برای فکر کردن به خروجی است: برنامهٔ شما لزوماً فقط یک توده داده را خروجی نمی‌دهد بلکه ممکن است در واقع در حین اجرا اطلاعات بسیار متفاوتی منتشر کند. یک راه ساده برای پشتیبانی از این رویکرد هنگام خروجی دادن JSON این است که برای هر پیام یک سند JSON بنویسید و هر سند JSON را در یک خط جدید قرار دهید (که گاهی JSON خط‌به‌خط نامیده می‌شود). این کار می‌تواند پیاده‌سازی را تا حد استفاده از یک println! معمولی ساده کند.

    این یک مثال ساده است که از ماکروی json! در serde_json استفاده می‌کند تا به‌سرعت JSON معتبر را در کد منبع Rust بنویسد:

    use clap::Parser;
use serde_json::json;

/// Search for a pattern in a file and display the lines that contain it.
#[derive(Parser)]
struct Cli {
    /// Output JSON instead of human readable messages
    #[arg(long = "json")]
    json: bool,
}

fn main() {
    let args = Cli::parse();
    if args.json {
        println!(
            "{}",
            json!({
                "type": "message",
                "content": "Hello world",
            })
        );
    } else {
        println!("Hello world");
    }
}

    و این هم خروجی آن:

    $ cargo run -q
Hello world
$ cargo run -q -- --json
{"content":"Hello world","type":"message"}

    (اجرای cargo با -q خروجی معمول آن را سرکوب می‌کند. آرگومان‌های بعد از -- به برنامهٔ ما داده می‌شوند.)

    چگونه با ورودی پایپ‌شده به برنامه برخورد کنیم

    فرض کنید برنامه‌ای داریم که تعداد کلمات یک فایل را می‌خواند:

    use clap::Parser;
use std::path::PathBuf;

/// Count the number of lines in a file
#[derive(Parser)]
#[command(arg_required_else_help = true)]
struct Cli {
    /// The path to the file to read
    file: PathBuf,
}

fn main() {
    let args = Cli::parse();
    let mut word_count = 0;
    let file = args.file;

    for line in std::fs::read_to_string(&file).unwrap().lines() {
        word_count += line.split(' ').count();
    }

    println!("Words in {}: {}", file.to_str().unwrap(), word_count)
}

    این برنامه مسیر یک فایل را می‌گیرد، آن را خط‌به‌خط می‌خواند و تعداد کلماتی را که با فاصله از هم جدا شده‌اند می‌شمارد.

    وقتی آن را اجرا کنید، مجموع کلمات فایل را در خروجی چاپ می‌کند:

    $ cargo run README.md
Words in README.md: 47

    اما اگر بخواهیم تعداد کلماتی را بشماریم که به برنامه پایپ شده‌اند چه؟ برنامه‌های Rust می‌توانند داده‌هایی را که از طریق stdin می‌رسند بخوانند، با ساختار Stdin که می‌توانید آن را از طریق تابع stdin در کتابخانهٔ استاندارد به دست آورید. مانند خواندن خطوط یک فایل، می‌تواند خطوط را از stdin بخواند.

    این برنامه‌ای است که کلمات ورودی پایپ‌شده از طریق stdin را می‌شمارد

    use clap::{CommandFactory, Parser};
use std::{
    fs::File,
    io::{BufRead, BufReader, IsTerminal, stdin},
    path::PathBuf,
};

/// Count the number of lines in a file or stdin
#[derive(Parser)]
#[command(arg_required_else_help = true)]
struct Cli {
    /// The path to the file to read, use - to read from stdin (must not be a tty)
    file: PathBuf,
}

fn main() {
    let args = Cli::parse();

    let word_count;
    let mut file = args.file;

    if file == PathBuf::from("-") {
        if stdin().is_terminal() {
            Cli::command().print_help().unwrap();
            ::std::process::exit(2);
        }

        file = PathBuf::from("<stdin>");
        word_count = words_in_buf_reader(BufReader::new(stdin().lock()));
    } else {
        word_count = words_in_buf_reader(BufReader::new(File::open(&file).unwrap()));
    }

    println!("Words from {}: {}", file.to_string_lossy(), word_count)
}

fn words_in_buf_reader<R: BufRead>(buf_reader: R) -> usize {
    let mut count = 0;
    for line in buf_reader.lines() {
        count += line.unwrap().split(' ').count()
    }
    count
}

    اگر آن برنامه را با متنی که از طریق پایپ به آن داده شده اجرا کنید، و با - نشان دهید که قصد دارید از stdin بخوانید، تعداد کلمات را در خروجی چاپ می‌کند:

    $ echo "hi there friend" | cargo run -- -
Words from stdin: 3

    این برنامه لازم دارد که stdin تعاملی نباشد، چون ورودی‌ای را انتظار داریم که به برنامه پایپ می‌شود، نه متنی که هنگام اجرا تایپ می‌شود. اگر stdin یک tty باشد، مستندات راهنما را خروجی می‌دهد تا روشن شود چرا کار نمی‌کند.
