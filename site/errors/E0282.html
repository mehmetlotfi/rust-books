راهنمای خطاهای کامپایلرCompiler Error Index

    کامپایلر نتوانست یک نوع را استنتاج کند و یک حاشیه‌نویسی نوع (type annotation) خواست.

    کد دارای خطا:

    let x = Vec::new();

    این خطا نشان می‌دهد که استنتاج نوع به یک نوع ممکن یکتا نرسیده و اطلاعات بیشتری لازم است. در بیشتر موارد می‌توان این اطلاعات را با افزودن یک حاشیه‌نویسی نوع فراهم کرد. گاهی لازم است پارامتر نوع جنریک را دستی مشخص کنید.

    در مثال بالا، نوع Vec یک پارامتر نوع T دارد. هنگام فراخوانی Vec::new، مگر اینکه در ادامه استفاده دیگری از متغیر x وجود داشته باشد که به کامپایلر اجازه دهد نوع T را استنتاج کند، باید نوع آن به کامپایلر گفته شود.

    نوع را می‌توان روی متغیر مشخص کرد:

    let x: Vec<i32> = Vec::new();

    نوع را همچنین می‌توان در مسیر عبارت مشخص کرد:

    let x = Vec::<i32>::new();

    در موارد دارای نوع‌های پیچیده‌تر، لازم نیست نوع کامل حاشیه‌نویسی شود. پس از رفع ابهام، کامپایلر می‌تواند بقیه را استنتاج کند:

    let x: Vec<_> = "hello".chars().rev().collect();

    راه دیگر برای دادن اطلاعات کافی به کامپایلر، مشخص کردن پارامتر نوع جنریک است:

    let x = "hello".chars().rev().collect::<Vec<char>>();

    باز هم، اگر کامپایلر بتواند نوع را استنتاج کند، لازم نیست نوع کامل را مشخص کنید:

    let x = "hello".chars().rev().collect::<Vec<_>>();

    جدا از متد یا تابعی که پارامتر نوع جنریک دارد، این خطا می‌تواند زمانی رخ دهد که پارامتر نوع یک ساختار یا صفت (trait) قابل استنتاج نباشد. در این حالت همیشه نمی‌توان از حاشیه‌نویسی نوع استفاده کرد، زیرا همه گزینه‌ها نوع بازگشتی یکسانی دارند. برای مثال:

    struct Foo<T> {
    num: T,
}

impl<T> Foo<T> {
    fn bar() -> i32 {
        0
    }

    fn baz() {
        let number = Foo::bar();
    }
}

    این کد شکست می‌خورد، زیرا کامپایلر نمی‌داند bar را روی کدام نمونه از Foo فراخوانی کند. برای رفع خطا، Foo::bar() را به Foo::<T>::bar() تغییر دهید.
