راهنمای خطاهای کامپایلرCompiler Error Index

    این خطا نشان می‌دهد که یک طول عمر (lifetime) در یک نوع وجود ندارد. اگر این خطا درون امضای یک تابع رخ داده باشد، ممکن است مشکل از رعایت نکردن قواعد حذف طول عمر (lifetime elision) باشد (در ادامه را ببینید).

    نمونه‌های کدی که خطا می‌دهند:

    struct Foo1 { x: &bool }
              // ^ expected lifetime parameter
struct Foo2<'a> { x: &'a bool } // correct

struct Bar1 { x: Foo2 }
              // ^^^^ expected lifetime parameter
struct Bar2<'a> { x: Foo2<'a> } // correct

enum Baz1 { A(u8), B(&bool), }
                  // ^ expected lifetime parameter
enum Baz2<'a> { A(u8), B(&'a bool), } // correct

type MyStr1 = &str;
           // ^ expected lifetime parameter
type MyStr2<'a> = &'a str; // correct

    حذف طول عمر (lifetime elision) نوعی استنتاج ویژه و محدود برای طول عمرها در امضای تابع‌ها است که اجازه می‌دهد در برخی موارد طول عمرها را ننویسید. برای اطلاعات بیشتر درباره‌ی حذف طول عمر، کتاب را ببینید.

    قواعد حذف طول عمر می‌گویند هر امضای تابعی که طول عمر خروجی آن حذف شده باشد، باید یکی از این دو حالت را داشته باشد:

    • دقیقاً یک طول عمر ورودی داشته باشد
    • یا چند طول عمر ورودی داشته باشد، اما تابع باید متدی با گیرنده‌ی &self یا &mut self باشد

    در حالت اول، طول عمر خروجی برابر با تنها طول عمر ورودی استنتاج می‌شود. در حالت دوم، طول عمر به‌جای آن برابر با طول عمر &self یا &mut self استنتاج می‌شود.

    در اینجا چند نمونه از خطاهای حذف طول عمر آمده است:

    // error, no input lifetimes
fn foo() -> &str { }

// error, `x` and `y` have distinct lifetimes inferred
fn bar(x: &str, y: &str) -> &str { }

// error, `y`'s lifetime is inferred to be distinct from `x`'s
fn baz<'a>(x: &'a str, y: &str) -> &str { }
