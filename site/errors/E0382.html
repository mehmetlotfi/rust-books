    یک متغیر پس از آنکه محتوای آن به جای دیگری منتقل (move) شده، استفاده شده است.

    نمونه کد خطادار:

    struct MyStruct { s: u32 }

fn main() {
    let mut x = MyStruct{ s: 5u32 };
    let y = x;
    x.s = 6;
    println!("{}", x.s);
}

    از آنجا که MyStruct نوعی است که با Copy علامت‌گذاری نشده، هنگام مقداردهی y داده از x بیرون منتقل می‌شود. این موضوع در بنیاد سیستم مالکیت Rust قرار دارد: جز با راه‌حل‌هایی مانند Rc، یک مقدار نمی‌تواند بیش از یک متغیر مالک داشته باشد.

    گاهی لازم نیست مقدار را منتقل کنیم. با استفاده از ارجاع می‌توانیم بدون تغییر مالکیت، اجازه دهیم تابع دیگری مقدار را قرض بگیرد. در مثال زیر، در واقع لازم نیست رشته خود را به calculate_length منتقل کنیم؛ می‌توانیم به‌جای آن با & یک ارجاع به آن بدهیم.

    fn main() {
    let s1 = String::from("hello");

    let len = calculate_length(&s1);

    println!("The length of '{}' is {}.", s1, len);
}

fn calculate_length(s: &String) -> usize {
    s.len()
}

    یک ارجاع تغییرپذیر را می‌توان با &mut ساخت.

    گاهی ارجاع نمی‌خواهیم، بلکه یک نسخه مجزا می‌خواهیم. همه انواعی که با Clone علامت‌گذاری شده‌اند را می‌توان با فراخوانی .clone() تکثیر کرد. تغییرات بعدی روی نسخه کلون‌شده بر متغیر اصلی اثر نمی‌گذارد.

    بیشتر انواع کتابخانه استاندارد با Clone علامت‌گذاری شده‌اند. مثال زیر استفاده از clone() روی یک رشته را نشان می‌دهد. ابتدا s1 برابر “many” قرار داده می‌شود و سپس در s2 کپی می‌شود. بعد نخستین نویسه s1 حذف می‌شود، بدون اینکه بر s2 اثر بگذارد. “any many” در کنسول چاپ می‌شود.

    fn main() {
    let mut s1 = String::from("many");
    let s2 = s1.clone();
    s1.remove(0);
    println!("{} {}", s1, s2);
}

    اگر تعریف یک نوع در اختیار ما باشد، می‌توانیم با #[derive(Clone)] خودمان Clone را برای آن پیاده‌سازی کنیم.

    برخی انواع اصلاً معنای مالکیتی ندارند و تکثیر آن‌ها ساده است. نمونه آن i32 و دیگر انواع عددی است. برای کلون کردن آن‌ها لازم نیست .clone() را فراخوانی کنیم، چون علاوه بر Clone با Copy هم علامت‌گذاری شده‌اند. در این حالت کلون ضمنی راحت‌تر است. اگر همه اعضای نوع‌های خودمان نیز با Copy علامت‌گذاری شده باشند، می‌توانیم آن‌ها را هم Copy کنیم.

    در مثال زیر، نوع Point را پیاده‌سازی می‌کنیم. چون این نوع فقط دو عدد صحیح را نگه می‌دارد، با Copy از معنای مالکیتی صرف‌نظر می‌کنیم. سپس می‌توانیم let p2 = p1 را بنویسیم بدون اینکه p1 منتقل شود.

    #[derive(Copy, Clone)]
struct Point { x: i32, y: i32 }

fn main() {
    let mut p1 = Point{ x: -1, y: 2 };
    let p2 = p1;
    p1.x = 1;
    println!("p1: {}, {}", p1.x, p1.y);
    println!("p2: {}, {}", p2.x, p2.y);
}

    از طرف دیگر، اگر تعریف ساختار در اختیار ما نیست یا مالکیت مشترک تغییرپذیر واقعاً لازم است، می‌توانیم از Rc و RefCell استفاده کنیم:

    use std::cell::RefCell;
use std::rc::Rc;

struct MyStruct { s: u32 }

fn main() {
    let mut x = Rc::new(RefCell::new(MyStruct{ s: 5u32 }));
    let y = x.clone();
    x.borrow_mut().s = 6;
    println!("{}", x.borrow().s);
}

    در این رویکرد، x و y مالکیت داده را از طریق Rc (نوع شمارنده ارجاع، reference count) به‌اشتراک می‌گذارند. RefCell در عمل بررسی قرض‌گیری را در زمان اجرا انجام می‌دهد: یعنی تضمین می‌کند که در هر لحظه حداکثر یک نویسنده یا چند خواننده بتوانند به داده دسترسی داشته باشند.

    اگر می‌خواهید درباره‌ی مالکیت در Rust بیشتر بیاموزید، با فصل Understanding Ownership در کتاب (Book) شروع کنید.
