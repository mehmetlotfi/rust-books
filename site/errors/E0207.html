راهنمای خطاهای کامپایلرCompiler Error Index

    یک پارامتر نوع، ثابت (const) یا طول عمر که برای impl مشخص شده است، مقید (constrained) نشده است.

    نمونه کد دارای خطا:

    struct Foo;

impl<T: Default> Foo {
    // error: the type parameter `T` is not constrained by the impl trait, self
    // type, or predicates [E0207]
    fn get(&self) -> T {
        <T as Default>::default()
    }
}

    هر پارامتر نوع یا ثابت در یک impl باید دست‌کم یکی از معیارهای زیر را برآورده کند:

    • در نوع پیاده‌سازی‌شونده (implementing type) در impl ظاهر شود، مثلاً impl<T> Foo<T>
    • برای پیاده‌سازی صفت، در صفت پیاده‌سازی‌شده ظاهر شود، مثلاً impl<T> SomeTrait<T> for Foo
    • به‌عنوان یک نوع وابسته قید شده باشد، مثلاً impl<T, U> SomeTrait for T where T: AnotherTrait<AssocType=U>

    هر پارامتر طول عمر مقید‌نشده در یک impl در صورتی که پارامتر طول عمر توسط یک نوع وابسته استفاده شود، پشتیبانی نمی‌شود.

    نمونه خطای ۱

    فرض کنید ساختاری به نام Foo داریم و می‌خواهیم برایش چند متد تعریف کنیم. نمونه کد قبلی تعریفی دارد که به خطای کامپایلر منجر می‌شود:

    مشکل این است که پارامتر T در نوع پیاده‌سازی‌شونده (Foo) در impl ظاهر نمی‌شود. در این حالت می‌توانیم با انتقال پارامتر نوع از impl به متد get خطا را برطرف کنیم:

    struct Foo;

// Move the type parameter from the impl to the method
impl Foo {
    fn get<T: Default>(&self) -> T {
        <T as Default>::default()
    }
}

    نمونه خطای ۲

    به‌عنوان مثال دیگر، فرض کنید صفتی به نام Maker داریم و می‌خواهیم نوعی به نام FooMaker بسازیم که Fooها را تولید می‌کند:

    trait Maker {
    type Item;
    fn make(&mut self) -> Self::Item;
}

struct Foo<T> {
    foo: T
}

struct FooMaker;

impl<T: Default> Maker for FooMaker {
// error: the type parameter `T` is not constrained by the impl trait, self
// type, or predicates [E0207]
    type Item = Foo<T>;

    fn make(&mut self) -> Foo<T> {
        Foo { foo: <T as Default>::default() }
    }
}

    این کد کامپایل نمی‌شود، زیرا T نه در صفت ظاهر شده است و نه در نوع پیاده‌سازی‌شونده.

    یک راه برای دور زدن این مشکل، افزودن یک پارامتر نوع فانتوم (phantom) به FooMaker است، به این صورت:

    use std::marker::PhantomData;

trait Maker {
    type Item;
    fn make(&mut self) -> Self::Item;
}

struct Foo<T> {
    foo: T
}

// Add a type parameter to `FooMaker`
struct FooMaker<T> {
    phantom: PhantomData<T>,
}

impl<T: Default> Maker for FooMaker<T> {
    type Item = Foo<T>;

    fn make(&mut self) -> Foo<T> {
        Foo {
            foo: <T as Default>::default(),
        }
    }
}

    راه دیگر این است که نوع وابسته در Maker را کنار بگذاریم و به‌جای آن از یک پارامتر نوع ورودی استفاده کنیم:

    // Use a type parameter instead of an associated type here
trait Maker<Item> {
    fn make(&mut self) -> Item;
}

struct Foo<T> {
    foo: T
}

struct FooMaker;

impl<T: Default> Maker<Foo<T>> for FooMaker {
    fn make(&mut self) -> Foo<T> {
        Foo { foo: <T as Default>::default() }
    }
}

    نمونه خطای ۳

    فرض کنید ساختاری به نام Foo داریم و می‌خواهیم برایش چند متد تعریف کنیم. نمونه کد زیر تعریفی دارد که به خطای کامپایلر منجر می‌شود:

    struct Foo;

impl<const T: i32> Foo {
    // error: the const parameter `T` is not constrained by the impl trait, self
    // type, or predicates [E0207]
    fn get(&self) -> i32 {
        i32::default()
    }
}

    مشکل این است که پارامتر ثابت T در نوع پیاده‌سازی‌شونده (Foo) در impl ظاهر نمی‌شود. در این حالت می‌توانیم با انتقال پارامتر نوع از impl به متد get خطا را برطرف کنیم:

    struct Foo;

// Move the const parameter from the impl to the method
impl Foo {
    fn get<const T: i32>(&self) -> i32 {
        i32::default()
    }
}

    نمونه خطای ۴

    فرض کنید ساختاری به نام Foo و ساختاری به نام Bar داریم که از طول عمر 'a استفاده می‌کند. می‌خواهیم صفت Contains را برای Foo پیاده‌سازی کنیم. صفت Contains نوع وابسته B را دارد. نمونه کد زیر تعریفی دارد که به خطای کامپایلر منجر می‌شود:

    struct Foo;
struct Bar<'a>;

trait Contains {
    type B;

    fn get(&self) -> i32;
}

impl<'a> Contains for Foo {
    type B = Bar<'a>;

    // error: the lifetime parameter `'a` is not constrained by the impl trait,
    // self type, or predicates [E0207]
    fn get(&self) -> i32 {
        i32::default()
    }
}

    لطفاً توجه کنید که پارامترهای طول عمر مقید‌نشده در صورتی که توسط یک نوع وابسته استفاده شوند، پشتیبانی نمی‌شوند.

    در مواردی که قرار است طول عمر نوع وابسته به نوع self گره بخورد و هیچ‌یک از متدهای صفت به مالکیت یا قابلیت تغییر متفاوت نیاز نداشته باشند، یک گزینه این است که صفت را روی یک نوع قرض‌گرفته‌شده پیاده‌سازی کنید:

    struct Foo(i32);

trait Contents {
    type Item;

    fn get(&self) -> Self::Item;
}

// Note the lifetime `'a` is used both for the self type...
impl<'a> Contents for &'a Foo {
    // ...and the associated type.
    type Item = &'a i32;

    fn get(&self) -> Self::Item {
        &self.0
    }
}
