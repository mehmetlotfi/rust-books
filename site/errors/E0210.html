راهنمای خطاهای کامپایلرCompiler Error Index

    این خطا نشان‌دهنده نقض یکی از قوانین یتیم (orphan rules) در Rust برای پیاده‌سازی صفت‌هاست. این قاعده به استفاده از پارامترهای نوع در پیاده‌سازی یک صفت خارجی (صفتی که در crate دیگری تعریف شده است) مربوط می‌شود و بیان می‌کند که پارامترهای نوع باید توسط یک نوع محلی «پوشش داده شوند» (covered).

    هنگام پیاده‌سازی یک صفت خارجی برای یک نوع خارجی، صفت باید یک یا چند پارامتر نوع داشته باشد. یک نوع محلی در crate شما باید پیش از هر استفاده از پارامترهای نوع ظاهر شود.

    برای درک معنای این موضوع، بررسی چند مثال شاید آسان‌تر باشد.

    اگر ForeignTrait صفتی باشد که در یک crate خارجی به نام foo تعریف شده است، آنگاه impl صفت زیر خطا است:

    # #[cfg(for_demonstration_only)]
extern crate foo;
# #[cfg(for_demonstration_only)]
use foo::ForeignTrait;
# use std::panic::UnwindSafe as ForeignTrait;

impl<T> ForeignTrait for T { } // error
# fn main() {}

    برای دور زدن این مشکل، می‌توان آن را با یک نوع محلی به نام MyType پوشش داد:

    # use std::panic::UnwindSafe as ForeignTrait;
struct MyType<T>(T);
impl<T> ForeignTrait for MyType<T> { } // Ok

    توجه کنید که یک نام مستعار نوع (type alias) کافی نیست.

    برای مثال دیگری از خطا، فرض کنید صفت دیگری در foo به نام ForeignTrait2 تعریف شده است که دو پارامتر نوع می‌گیرد. در این صورت این impl به همان نقض قاعده منجر می‌شود:

    struct MyType2;
impl<T> ForeignTrait2<T, MyType<T>> for MyType2 { } // error

    دلیل این است که پارامتر نوع T دو بار در سرآیند impl ظاهر شده است، هر دو بار به‌عنوان پارامتر ForeignTrait2. ظاهر شدن اول بدون پوشش (uncovered) است و بنابراین با قاعده‌ی یتیم (orphan rule) در تضاد قرار می‌گیرد.

    یک مثال دیگر را در نظر بگیرید:

    impl<T> ForeignTrait2<MyType<T>, T> for MyType2 { } // Ok

    این مثال فقط در این تفاوت با impl قبلی دارد که پارامترهای T و MyType<T> برای ForeignTrait2 جابه‌جا شده‌اند. این مثال قانون یتیم را نقض نمی‌کند و مجاز است.

    برای فهمیدن اینکه چرا آخرین مثال مجاز بود، باید قاعده کلی را بدانید. متأسفانه بیان این قاعده کمی پیچیده است. یک impl را در نظر بگیرید:

    impl<P1, ..., Pm> ForeignTrait<T1, ..., Tn> for T0 { ... }

    که در آن P1, ..., Pm پارامترهای نوع impl و T0, ..., Tn نوع‌ها هستند. یکی از نوع‌های T0, ..., Tn باید یک نوع محلی باشد (این قانون یتیم دیگری است؛ توضیح E0117 را ببینید).

    هر دو شرط زیر باید برقرار باشند:

    1. دست‌کم یکی از نوع‌های T0..=Tn باید یک نوع محلی باشد. فرض کنید Ti اولین چنین نوعی باشد.
    2. هیچ پارامتر نوع پوشش‌داده‌نشده‌ای از P1..=Pm نباید در T0..Ti (به‌جز Ti) ظاهر شود.

    برای اطلاعات درباره طراحی قوانین یتیم، RFC 2451 و RFC 1023 را ببینید.
