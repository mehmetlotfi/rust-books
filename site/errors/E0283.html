راهنمای خطاهای کامپایلرCompiler Error Index

    کامپایلر نتوانست یک نوع را استنتاج کند و یک حاشیه‌نویسی نوع (type annotation) خواست.

    کد دارای خطا:

    let x = "hello".chars().rev().collect();

    این خطا نشان می‌دهد که استنتاج نوع به یک نوع ممکن یکتا نرسیده و اطلاعات بیشتری لازم است. در بیشتر موارد می‌توان این اطلاعات را با افزودن یک حاشیه‌نویسی نوع فراهم کرد. گاهی لازم است پارامتر نوع جنریک را دستی مشخص کنید.

    یک مثال رایج، متد collect روی Iterator است. این متد یک پارامتر نوع جنریک با قید FromIterator دارد که برای یک iterator از char، از جمله توسط Vec و String پیاده‌سازی شده است. قطعه کد زیر را در نظر بگیرید که کاراکترهای یک رشته را معکوس می‌کند:

    در مثال کد اول، کامپایلر نمی‌تواند استنتاج کند که نوع x باید چه باشد: هم Vec<char> و هم String گزینه‌های مناسبی هستند. برای مشخص کردن اینکه کدام نوع به کار رود، می‌توانید روی x یک حاشیه‌نویسی نوع بگذارید:

    let x: Vec<char> = "hello".chars().rev().collect();

    لازم نیست نوع کامل حاشیه‌نویسی شود. پس از رفع ابهام، کامپایلر می‌تواند بقیه را استنتاج کند:

    let x: Vec<_> = "hello".chars().rev().collect();

    راه دیگر برای دادن اطلاعات کافی به کامپایلر، مشخص کردن پارامتر نوع جنریک است:

    let x = "hello".chars().rev().collect::<Vec<char>>();

    باز هم، اگر کامپایلر بتواند نوع را استنتاج کند، لازم نیست نوع کامل را مشخص کنید:

    let x = "hello".chars().rev().collect::<Vec<_>>();

    یک مثال مستقل در ادامه آمده است:

    struct Foo;

impl Into<u32> for Foo {
    fn into(self) -> u32 { 1 }
}

let foo = Foo;
let bar: u32 = foo.into() * 1u32;

    این خطا را می‌توان با افزودن حاشیه‌نویسی‌های نوعی که اطلاعات ازدست‌رفته را در اختیار کامپایلر می‌گذارند برطرف کرد. در این مورد، راه‌حل مشخص کردن پارامتر نوع صفت است:

    struct Foo;

impl Into<u32> for Foo {
    fn into(self) -> u32 { 1 }
}

let foo = Foo;
let bar: u32 = Into::<u32>::into(foo) * 1u32;
