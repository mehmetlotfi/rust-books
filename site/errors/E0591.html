راهنمای خطاهای کامپایلرCompiler Error Index

    بر اساس RFC 401، اگر یک اعلان تابع foo داشته باشید:

    struct S;

// For the purposes of this explanation, all of these
// different kinds of `fn` declarations are equivalent:

fn foo(x: S) { /* ... */ }
# #[cfg(for_demonstration_only)]
extern "C" {
    fn foo(x: S);
}
# #[cfg(for_demonstration_only)]
impl S {
    fn foo(self) { /* ... */ }
}

    نوع foo برخلاف انتظار fn(S) نیست. بلکه یک نوع نشانگر منحصربه‌فرد با اندازه‌ی صفر است که در اینجا به‌صورت typeof(foo) نوشته می‌شود. با این حال، typeof(foo) را می‌توان به یک اشاره‌گر تابع fn(S) تبدیل (coerce) کرد، به همین دلیل به‌ندرت متوجه این موضوع می‌شوید:

    # struct S;
# fn foo(_: S) {}
let x: fn(S) = foo; // OK, coerces

    دلیل اهمیت این موضوع آن است که نوع fn(S) مختص هیچ تابع خاصی نیست: این یک اشاره‌گر تابع است. بنابراین فراخوانی x() به یک فراخوانی مجازی (virtual call) منجر می‌شود، در حالی که foo() به‌صورت ایستا ارسال (dispatch) می‌شود، چون نوع foo دقیقاً مشخص می‌کند که کدام تابع فراخوانی می‌شود.

    همان‌طور که گفته شد، تبدیل‌های خودکار باعث می‌شوند بیشتر کدها نیازی نداشته باشند نگران این تمایز باشند. با این حال، وقتی از transmute برای تبدیل یک آیتم fn به یک اشاره‌گر fn استفاده می‌کنید، می‌توانید تفاوت را ببینید.

    این کار گاهی به‌عنوان بخشی از FFI انجام می‌شود:

    extern "C" fn foo(userdata: Box<i32>) {
    /* ... */
}

# fn callback(_: extern "C" fn(*mut i32)) {}
# use std::mem::transmute;
unsafe {
    let f: extern "C" fn(*mut i32) = transmute(foo);
    callback(f);
}

    در اینجا transmute برای تبدیل نوع آرگومان‌های fn استفاده شده است. این الگو نادرست است، زیرا نوع foo یک آیتم تابع (typeof(foo)) است که اندازه‌ی صفر دارد، در حالی که نوع هدف (fn()) یک اشاره‌گر تابع است که اندازه‌ی صفر ندارد. این الگو باید بازنویسی شود. چند راه ممکن برای این کار وجود دارد:

    • اعلان اصلی fn را تغییر دهید تا با امضای مورد انتظار مطابقت داشته باشد و تبدیل را در بدنه‌ی fn انجام دهید (گزینه‌ی ترجیحی)
    • پیش از فراخوانی transmute، آیتم fn را به یک اشاره‌گر fn تبدیل (cast) کنید، همان‌طور که در اینجا نشان داده شده است:
    # extern "C" fn foo(_: Box<i32>) {}
# use std::mem::transmute;
# unsafe {
let f: extern "C" fn(*mut i32) = transmute(foo as extern "C" fn(_));
let f: extern "C" fn(*mut i32) = transmute(foo as usize); // works too
# }

    همین موضوع درباره‌ی transmuteها به *mut fn() که در عمل مشاهده شده‌اند نیز صدق می‌کند. البته توجه کنید که استفاده از این نوع معمولاً نادرست است. هدف معمولاً توصیف یک اشاره‌گر تابع است، اما خودِ fn() به‌تنهایی برای این منظور کافی است. *mut fn() یک اشاره‌گر به یک اشاره‌گر fn است. (با این حال، از آنجا که این مقادیر معمولاً فقط به کد C پاس داده می‌شوند، در عمل به‌ندرت تفاوتی ایجاد می‌کند.)
