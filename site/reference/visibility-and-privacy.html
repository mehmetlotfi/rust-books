    [vis.intro]

    این دو اصطلاح اغلب به‌جای یکدیگر استفاده می‌شوند و می‌خواهند پاسخ این پرسش را بیان کنند: «آیا می‌توان این آیتم را در این محل به‌کار برد؟»

    [vis.name-hierarchy]

    تفکیک نام در Rust روی یک سلسله‌مراتب سراسری از فضاهای نام کار می‌کند. هر سطح این سلسله‌مراتب را می‌توان یک آیتم دانست. آیتم‌ها شامل مواردی هستند که پیش‌تر گفته شد و crateهای خارجی را نیز دربرمی‌گیرند. اعلان یا تعریف ماژول جدید را می‌توان مانند درج یک درخت جدید در محل تعریف در این سلسله‌مراتب تصور کرد.

    [vis.privacy]

    Rust برای کنترل امکان استفاده از رابط‌ها میان ماژول‌ها، هر استفاده از یک آیتم را بررسی می‌کند تا مجازبودن آن را تعیین کند. هشدارهای حریم خصوصی در همین مرحله تولید می‌شوند؛ یعنی «از آیتم خصوصی ماژول دیگری استفاده کرده‌اید و اجازه نداشته‌اید».

    [vis.default]

    به‌طور پیش‌فرض همه‌چیز خصوصی است، با دو استثنا: آیتم‌های وابسته در یک Trait از نوع pub به‌طور پیش‌فرض عمومی‌اند و گونه‌های enum در یک enum از نوع pub نیز به‌طور پیش‌فرض عمومی‌اند. آیتم اعلان‌شده با pub برای دنیای بیرون دسترس‌پذیر است. برای مثال:

    fn main() {}
// Declare a private struct
struct Foo;

// Declare a public struct with a private field
pub struct Bar {
    field: i32,
}

// Declare a public enum with two public variants
pub enum State {
    PubliclyAccessibleState,
    PubliclyAccessibleState2,
}
    [vis.access]

    با درنظرگرفتن عمومی یا خصوصی بودن آیتم، Rust در دو حالت اجازهٔ دسترسی می‌دهد:

    1. اگر آیتم عمومی باشد، از ماژول m در بیرون زمانی دسترس‌پذیر است که همهٔ ماژول‌های نیای آیتم از m قابل دسترسی باشند. همچنین ممکن است بتوان آیتم را از طریق بازصادرات نام برد؛ ادامه را ببینید.
    2. اگر آیتم خصوصی باشد، ماژول جاری و فرزندانش می‌توانند به آن دسترسی داشته باشند.

    این دو حالت برای ساخت سلسله‌مراتب ماژولی که API عمومی را آشکار و جزئیات پیاده‌سازی داخلی را پنهان می‌کند، بسیار قدرتمندند. چند کاربرد و پیامد آن‌ها:

    • توسعه‌دهندهٔ کتابخانه باید قابلیت‌هایی را برای crateهای پیوندشونده به کتابخانه آشکار کند. بر پایهٔ حالت نخست، هر چیز قابل استفاده در بیرون باید از ریشه تا آیتم مقصد pub باشد. وجود هر آیتم خصوصی در زنجیره، دسترسی بیرونی را ممنوع می‌کند.

    • یک crate به «ماژول کمکی» سراسری برای خودش نیاز دارد، اما نمی‌خواهد آن را API عمومی کند. برای این کار، ریشهٔ سلسله‌مراتب crate ماژولی خصوصی دارد که درون خود یک «API عمومی» ارائه می‌کند. چون کل crate از فرزندان ریشه است، همهٔ crate محلی می‌تواند طبق حالت دوم به این ماژول خصوصی دسترسی پیدا کند.

    • هنگام نوشتن آزمون واحد برای یک ماژول، الگوی رایج این است که فرزند مستقیمی با نام mod test برای ماژول مورد آزمون ساخته شود. طبق حالت دوم، این ماژول می‌تواند به همهٔ آیتم‌های والد دسترسی یابد؛ بنابراین جزئیات پیاده‌سازی داخلی نیز به‌آسانی از ماژول فرزند آزموده می‌شوند.

    در حالت دوم گفته شد آیتم خصوصی برای ماژول جاری و فرزندانش «قابل دسترسی» است، اما معنای دقیق دسترسی به نوع آیتم بستگی دارد.

    [vis.use]

    برای نمونه، دسترسی به ماژول یعنی نگاه‌کردن به درون آن برای واردکردن آیتم‌های بیشتر؛ اما دسترسی به تابع یعنی فراخوانی آن. عبارت‌های مسیر و دستورهای import نیز دسترسی به آیتم محسوب می‌شوند، زیرا فقط زمانی معتبرند که مقصد در حوزهٔ مشاهدهٔ جاری باشد.

    این نمونه‌ای از برنامه‌ای است که سه حالت یادشده در بالا را نشان می‌دهد:

    // This module is private, meaning that no external crate can access this
// module. Because it is private at the root of this current crate, however, any
// module in the crate may access any publicly visible item in this module.
mod crate_helper_module {

    // This function can be used by anything in the current crate
    pub fn crate_helper() {}

    // This function *cannot* be used by anything else in the crate. It is not
    // publicly visible outside of the `crate_helper_module`, so only this
    // current module and its descendants may access it.
    fn implementation_detail() {}
}

// This function is "public to the root" meaning that it's available to external
// crates linking against this one.
pub fn public_api() {}

// Similarly to 'public_api', this module is public so external crates may look
// inside of it.
pub mod submodule {
    use crate::crate_helper_module;

    pub fn my_method() {
        // Any item in the local crate may invoke the helper module's public
        // interface through a combination of the two rules above.
        crate_helper_module::crate_helper();
    }

    // This function is hidden to any module which is not a descendant of
    // `submodule`
    fn my_implementation() {}

    #[cfg(test)]
    mod test {

        #[test]
        fn test_my_implementation() {
            // Because this module is a descendant of `submodule`, it's allowed
            // to access private items inside of `submodule` without a privacy
            // violation.
            super::my_implementation();
        }
    }
}

fn main() {}

    برای عبور یک برنامهٔ Rust از بررسی حریم خصوصی، همهٔ مسیرها باید با توجه به دو قاعدهٔ بالا دسترسی معتبر باشند. این شرط شامل همهٔ دستورهای use، عبارت‌ها، نوع‌ها و مانند آن است.

    [vis.scoped]

    ‏pub(in path)، ‏pub(crate)، ‏pub(super) و pub(self)

    [vis.scoped.intro]

    Rust افزون بر عمومی و خصوصی، اجازه می‌دهد آیتم فقط در حوزه‌ای مشخص قابل مشاهده اعلان شود. قواعد محدودیت‌های pub چنین‌اند:

    [vis.scoped.in]
    • pub(in path) آیتم را درون path داده‌شده قابل مشاهده می‌کند. path باید مسیری ساده باشد که به یکی از ماژول‌های نیای آیتم مورد اعلان تفکیک شود. هر شناسهٔ path باید مستقیماً به یک ماژول اشاره کند، نه نامی که دستور use معرفی کرده است.
    [vis.scoped.crate]
    • pub(crate) آیتم را درون crate جاری قابل مشاهده می‌کند.
    [vis.scoped.super]
    • pub(super) آیتم را برای ماژول والد قابل مشاهده می‌کند و معادل pub(in super) است.
    [vis.scoped.self]
    • pub(self) آیتم را برای ماژول جاری قابل مشاهده می‌کند و معادل pub(in self) یا حذف کامل pub است.
    [vis.scoped.edition2018]

    تفاوت‌های ویرایش 2018 از ویرایش ۲۰۱۸، مسیرهای pub(in path) باید با crate، ‏self یا super آغاز شوند. ویرایش ۲۰۱۵ همچنین مسیرهای آغازشده با :: یا ماژول‌های ریشهٔ crate را می‌پذیرد.

    این یک مثال است:

    pub mod outer_mod {
    pub mod inner_mod {
        // This function is visible within `outer_mod`
        pub(in crate::outer_mod) fn outer_mod_visible_fn() {}
        // Same as above, this is only valid in the 2015 edition.
        pub(in outer_mod) fn outer_mod_visible_fn_2015() {}

        // This function is visible to the entire crate
        pub(crate) fn crate_visible_fn() {}

        // This function is visible within `outer_mod`
        pub(super) fn super_mod_visible_fn() {
            // This function is visible since we're in the same `mod`
            inner_mod_visible_fn();
        }

        // This function is visible only within `inner_mod`,
        // which is the same as leaving it private.
        pub(self) fn inner_mod_visible_fn() {}
    }
    pub fn foo() {
        inner_mod::outer_mod_visible_fn();
        inner_mod::crate_visible_fn();
        inner_mod::super_mod_visible_fn();

        // This function is no longer visible since we're outside of `inner_mod`
        // Error! `inner_mod_visible_fn` is private
        //inner_mod::inner_mod_visible_fn();
    }
}

fn bar() {
    // This function is still visible since we're in the same crate
    outer_mod::inner_mod::crate_visible_fn();

    // This function is no longer visible since we're outside of `outer_mod`
    // Error! `super_mod_visible_fn` is private
    //outer_mod::inner_mod::super_mod_visible_fn();

    // This function is no longer visible since we're outside of `outer_mod`
    // Error! `outer_mod_visible_fn` is private
    //outer_mod::inner_mod::outer_mod_visible_fn();

    outer_mod::foo();
}

fn main() { bar() }

    Note

    نکته این نحو فقط محدودیت دیگری به قابلیت مشاهدهٔ آیتم می‌افزاید و تضمین نمی‌کند آیتم در همهٔ بخش‌های حوزهٔ مشخص‌شده قابل مشاهده باشد. برای دسترسی به آیتم، همهٔ آیتم‌های والد آن تا حوزهٔ جاری نیز باید قابل مشاهده باشند.

    [vis.reexports]

    بازصادرات و قابلیت مشاهده

    [vis.reexports.intro]

    Rust اجازه می‌دهد آیتم‌ها با دستور pub use به‌طور عمومی بازصادر شوند. چون این دستور عمومی است، آیتم طبق قواعد بالا در ماژول جاری قابل استفاده خواهد بود؛ در عمل دسترسی عمومی به آیتم بازصادرشده فراهم می‌کند. برای مثال، برنامهٔ زیر معتبر است:

    pub use self::implementation::api;

mod implementation {
    pub mod api {
        pub fn f() {}
    }
}

fn main() {}

    یعنی هر crate خارجی که به implementation::api::f ارجاع دهد با نقض حریم خصوصی روبه‌رو می‌شود، اما مسیر api::f مجاز است.

    [vis.reexports.private-item]

    بازصادرات یک آیتم خصوصی را می‌توان کوتاه‌کردن «زنجیرهٔ حریم خصوصی» از مسیر بازصادرات دانست، به‌جای آنکه زنجیره مانند حالت عادی از سلسله‌مراتب فضای نام عبور کند.
