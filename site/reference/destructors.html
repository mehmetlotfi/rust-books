    [destructors]

    نابودگرها

    [destructors.intro]

    وقتی یک متغیر مقداردهی‌شده یا مقدار موقت از دامنه خارج می‌شود، نابودگر (destructor) آن اجرا می‌شود یا به عبارتی حذف (drop) می‌شود. انتساب نیز، اگر عملوند سمت چپ مقداردهی شده باشد، نابودگر آن را اجرا می‌کند. اگر متغیری به‌صورت جزئی مقداردهی شده باشد، تنها فیلدهای مقداردهی‌شدهٔ آن حذف می‌شوند.

    [destructors.operation]

    نابودگر نوع T از این مراحل تشکیل می‌شود:

    1. اگر T: Drop باشد، فراخوانی <T as core::ops::Drop>::drop
    2. اجرای بازگشتی نابودگر همهٔ میدان‌ها.
      • میدان‌های یک ساختار به ترتیب اعلان حذف می‌شوند.
      • میدان‌های گونهٔ برشمردنی فعال به ترتیب اعلان حذف می‌شوند.
      • میدان‌های یک تاپل به‌ترتیب حذف می‌شوند.
      • عنصرهای یک آرایه یا برش مالکیت‌شده از نخستین تا آخرین عنصر حذف می‌شوند.
      • متغیرهایی که یک بستار با انتقال می‌گیرد، با ترتیبی نامشخص حذف می‌شوند.
      • اشیای صفت نابودگر نوع زیربنایی را اجرا می‌کنند.
      • نوع‌های دیگر حذف بیشتری ایجاد نمی‌کنند.
    [destructors.drop_in_place]

    اگر لازم باشد نابودگری به‌صورت دستی اجرا شود، مانند زمان پیاده‌سازی اشاره‌گر هوشمند خودتان، می‌توان از core::ptr::drop_in_place استفاده کرد.

    چند نمونه:

    struct PrintOnDrop(&'static str);

impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("{}", self.0);
    }
}

let mut overwritten = PrintOnDrop("drops when overwritten");
overwritten = PrintOnDrop("drops when scope ends");

let tuple = (PrintOnDrop("Tuple first"), PrintOnDrop("Tuple second"));

let moved;
// No destructor run on assignment.
moved = PrintOnDrop("Drops when moved");
// Drops now, but is then uninitialized.
moved;

// Uninitialized does not drop.
let uninitialized: PrintOnDrop;

// After a partial move, only the remaining fields are dropped.
let mut partial_move = (PrintOnDrop("first"), PrintOnDrop("forgotten"));
// Perform a partial move, leaving only `partial_move.0` initialized.
core::mem::forget(partial_move.1);
// When partial_move's scope ends, only the first field is dropped.
    [destructors.scope]

    دامنه‌های حذف

    [destructors.scope.intro]

    هر متغیر یا مقدار موقت به یک دامنهٔ حذف وابسته است. وقتی جریان کنترل دامنهٔ حذف را ترک کند، همهٔ متغیرهای وابسته به آن دامنه با ترتیب معکوس اعلان برای متغیرها، یا معکوس ایجاد برای مقادیر موقت، حذف می‌شوند.

    [destructors.scope.desugaring]

    دامنه‌های حذف را می‌توان با جایگزین کردن عبارت‌های for، if و while با عبارت‌های معادل مبتنی بر match، loop و break تعیین کرد.

    [destructors.scope.operators]

    عملگرهای بارگذاری‌شده از عملگرهای داخلی متمایز نمی‌شوند و حالت‌های مقیدسازی در نظر گرفته نمی‌شوند.

    [destructors.scope.list]

    برای یک تابع یا بستار، دامنهٔ حذف برای موارد زیر وجود دارد:

    [destructors.scope.function]
    • هر دستور
    [destructors.scope.statement]
    • هر دستور
    [destructors.scope.expression]
    • هر عبارت
    [destructors.scope.block]
    • هر بلوک، از جمله بدنهٔ تابع
      • در مورد عبارت بلوک، دامنهٔ بلوک و عبارت یک دامنه هستند.
    [destructors.scope.match-arm]
    • هر بازوی یک عبارت match
    [destructors.scope.nesting]

    دامنه‌های حذف به شکل زیر درون یکدیگر قرار می‌گیرند:

    [destructors.scope.nesting-function]
    • دامنهٔ کل تابع بیرونی‌ترین دامنه است.
    [destructors.scope.nesting-function-body]
    • بلوک بدنهٔ تابع درون دامنهٔ کل تابع قرار دارد.
    [destructors.scope.nesting-expr-statement]
    • والد عبارت در یک دستور عبارتی، دامنهٔ همان دستور است.
    [destructors.scope.nesting-let-initializer]
    • والد مقداردهندهٔ یک دستور let دامنهٔ همان دستور let است.
    [destructors.scope.nesting-statement]
    • والد دامنهٔ یک دستور، دامنهٔ بلوک دربرگیرندهٔ دستور است.
    [destructors.scope.nesting-match-guard]
    • والد عبارت یک نگهبان match، دامنهٔ بازویی است که نگهبان به آن تعلق دارد.
    [destructors.scope.nesting-match-arm]
    • والد عبارت پس از => در عبارت match، دامنهٔ بازویی است که عبارت در آن قرار دارد.
    [destructors.scope.nesting-match]
    • والد دامنهٔ بازو، دامنهٔ عبارت match متناظر است.
    [destructors.scope.nesting-other]
    • والد همهٔ دامنه‌های دیگر، دامنهٔ عبارت بلافاصله دربرگیرنده است.
    [destructors.scope.nesting-drop-order]

    وقتی چند دامنه هم‌زمان ترک شوند، مانند هنگام بازگشت از یک تابع، متغیرها از درون به بیرون حذف می‌شوند.

    [destructors.scope.params]

    دامنهٔ پارامترهای تابع

    همهٔ پارامترهای تابع در دامنهٔ کل بدنهٔ تابع قرار دارند، پس هنگام ارزیابی تابع در پایان حذف می‌شوند. هر پارامتر واقعی تابع پس از مقیدسازی‌های معرفی‌شده در الگوی همان پارامتر حذف می‌شود.

    struct PrintOnDrop(&'static str);
impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("drop({})", self.0);
    }
}
// Drops `y`, then the second parameter, then `x`, then the first parameter
fn patterns_in_parameters(
    (x, _): (PrintOnDrop, PrintOnDrop),
    (_, y): (PrintOnDrop, PrintOnDrop),
) {}

// drop order is 3 2 0 1
patterns_in_parameters(
    (PrintOnDrop("0"), PrintOnDrop("1")),
    (PrintOnDrop("2"), PrintOnDrop("3")),
);
    [destructors.scope.bindings]

    دامنهٔ متغیرهای محلی

    [destructors.scope.bindings.let]

    متغیرهای محلی اعلان‌شده در یک دستور let به دامنهٔ بلوک دربرگیرندهٔ دستور let وابسته‌اند.

    struct PrintOnDrop(&'static str);
impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("drop({})", self.0);
    }
}
let declared_first = PrintOnDrop("Dropped last in outer scope");
{
    let declared_in_block = PrintOnDrop("Dropped in inner scope");
}
let declared_last = PrintOnDrop("Dropped first in outer scope");
    [destructors.scope.bindings.match-arm]

    متغیرهای محلی که در یک عبارت match یا در نگهبان (guard) تطبیق‌الگوی match اعلان می‌شوند، به دامنهٔ بازو (arm scope) همان بازوی match که در آن اعلان شده‌اند وابسته‌اند.

    #![allow(irrefutable_let_patterns)]
struct PrintOnDrop(&'static str);
impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("drop({})", self.0);
    }
}
match PrintOnDrop("Dropped last in the first arm's scope") {
    // When guard evaluation succeeds, control-flow stays in the arm and
    // values may be moved from the scrutinee into the arm's bindings,
    // causing them to be dropped in the arm's scope.
    x if let y = PrintOnDrop("Dropped second in the first arm's scope")
        && let z = PrintOnDrop("Dropped first in the first arm's scope") =>
    {
        let declared_in_block = PrintOnDrop("Dropped in inner scope");
        // Pattern-matching guards' bindings and temporaries are dropped in
        // reverse order, dropping each guard condition operand's bindings
        // before its temporaries. Lastly, variables bound by the arm's
        // pattern are dropped.
    }
    _ => unreachable!(),
}

match PrintOnDrop("Dropped in the enclosing temporary scope") {
    // When guard evaluation fails, control-flow leaves the arm scope,
    // causing bindings and temporaries from earlier pattern-matching
    // guard condition operands to be dropped. This occurs before evaluating
    // the next arm's guard or body.
    _ if let y = PrintOnDrop("Dropped in the first arm's scope")
        && false => unreachable!(),
    // When a guard is executed multiple times due to self-overlapping
    // or-patterns, control-flow leaves the arm scope when the guard fails
    // and re-enters the arm scope before executing the guard again.
    _ | _ if let y = PrintOnDrop("Dropped in the second arm's scope twice")
        && false => unreachable!(),
    _ => {},
}
    [destructors.scope.bindings.patterns]

    متغیرهای درون الگو با ترتیب معکوس اعلان در الگو حذف می‌شوند.

    struct PrintOnDrop(&'static str);
impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("drop({})", self.0);
    }
}
let (declared_first, declared_last) = (
    PrintOnDrop("Dropped last"),
    PrintOnDrop("Dropped first"),
);
    [destructors.scope.bindings.or-patterns]

    برای تعیین ترتیب حذف، الگوهای یا مقیدسازی‌ها را با ترتیب ارائه‌شده در نخستین زیرالگو اعلان می‌کنند.

    struct PrintOnDrop(&'static str);
impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("drop({})", self.0);
    }
}
// Drops `x` before `y`.
fn or_pattern_drop_order<T>(
    (Ok([x, y]) | Err([y, x])): Result<[T; 2], [T; 2]>
//   ^^^^^^^^^^   ^^^^^^^^^^^ This is the second subpattern.
//   |
//   This is the first subpattern.
//
//   In the first subpattern, `x` is declared before `y`. Since it is
//   the first subpattern, that is the order used even if the second
//   subpattern, where the bindings are declared in the opposite
//   order, is matched.
) {}

// Here we match the first subpattern, and the drops happen according
// to the declaration order in the first subpattern.
or_pattern_drop_order(Ok([
    PrintOnDrop("Declared first, dropped last"),
    PrintOnDrop("Declared last, dropped first"),
]));

// Here we match the second subpattern, and the drops still happen
// according to the declaration order in the first subpattern.
or_pattern_drop_order(Err([
    PrintOnDrop("Declared last, dropped first"),
    PrintOnDrop("Declared first, dropped last"),
]));
    [destructors.scope.temporary]

    دامنهٔ مقادیر موقت

    [destructors.scope.temporary.intro]

    دامنهٔ موقت یک عبارت، دامنه‌ای است که برای متغیر موقت نگهدارندهٔ نتیجهٔ آن عبارت هنگام استفاده در بافت مکان به کار می‌رود؛ مگر آنکه عبارت ارتقا یافته باشد.

    [destructors.scope.temporary.enclosing]

    جدا از گسترش طول‌عمر، دامنهٔ موقت یک عبارت کوچک‌ترین دامنه‌ای است که عبارت را در خود دارد و یکی از موارد زیر است:

    • کل تابع.
    • یک دستور.
    • بدنهٔ یک عبارت if، while یا loop.
    • بلوک else یک عبارت if.
    • عبارت شرط بدون تطبیق الگوی یک عبارت if یا while، یا عملوند شرط نگهبان بدون تطبیق الگوی match.
    • نگهبان دارای تطبیق الگو، در صورت وجود، و عبارت بدنهٔ یک بازوی match.
    • هر عملوند یک عبارت بولی تنبل.
    • شرط یا شرط‌های دارای تطبیق الگو و بدنهٔ نتیجهٔ if (destructors.scope.temporary.edition2024).
    • شرط دارای تطبیق الگو و بدنهٔ حلقهٔ while.
    • تمام عبارت پایانی یک بلوک (destructors.scope.temporary.edition2024).

    Note

    نکته عبارت بررسی‌شوندهٔ یک عبارت match دامنهٔ موقت نیست؛ بنابراین مقادیر موقت آن ممکن است پس از عبارت match حذف شوند. برای نمونه، مقدار موقت 1 در match 1 { ref mut z => z }; تا انتهای دستور زنده می‌ماند.

    Note

    نکته بازنویسی انتساب واسازی دامنهٔ موقت عملوند مقدار انتسابی آن (سمت راست) را محدود می‌کند. برای جزئیات expr.assign.destructure.tmp-scopes را ببینید.

    [destructors.scope.temporary.edition2024]

    تفاوت‌های ویرایش 2024 ویرایش ۲۰۲۴ دو قاعدهٔ جدید برای کوچک کردن دامنهٔ موقت افزود: مقادیر موقت if let پیش از بلوک else حذف می‌شوند و مقادیر موقت عبارت‌های پایانی بلوک‌ها بلافاصله پس از ارزیابی عبارت پایانی حذف می‌شوند.

    چند نمونه:

    #![allow(irrefutable_let_patterns)]
struct PrintOnDrop(&'static str);
impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("drop({})", self.0);
    }
}
let local_var = PrintOnDrop("local var");

// Dropped once the condition has been evaluated
if PrintOnDrop("If condition").0 == "If condition" {
    // Dropped at the end of the block
    PrintOnDrop("If body").0
} else {
    unreachable!()
};

if let "if let scrutinee" = PrintOnDrop("if let scrutinee").0 {
    PrintOnDrop("if let consequent").0
    // `if let consequent` dropped here
}
// `if let scrutinee` is dropped here
else {
    PrintOnDrop("if let else").0
    // `if let else` dropped here
};

while let x = PrintOnDrop("while let scrutinee").0 {
    PrintOnDrop("while let loop body").0;
    break;
    // `while let loop body` dropped here.
    // `while let scrutinee` dropped here.
}

// Dropped before the first ||
(PrintOnDrop("first operand").0 == ""
// Dropped before the )
|| PrintOnDrop("second operand").0 == "")
// Dropped before the ;
|| PrintOnDrop("third operand").0 == "";

// Scrutinee is dropped at the end of the function, before local variables
// (because this is the tail expression of the function body block).
match PrintOnDrop("Matched value in final expression") {
    // Non-pattern-matching guards' temporaries are dropped once the
    // condition has been evaluated
    _ if PrintOnDrop("guard condition").0 == "" => (),
    // Pattern-matching guards' temporaries are dropped when leaving the
    // arm's scope
    _ if let "guard scrutinee" = PrintOnDrop("guard scrutinee").0 => {
        let _ = &PrintOnDrop("lifetime-extended temporary in inner scope");
        // `lifetime-extended temporary in inner scope` is dropped here
    }
    // `guard scrutinee` is dropped here
    _ => (),
}
    [destructors.scope.operands]

    عملوندها

    هنگام ارزیابی دیگر عملوندهای یک عبارت، برای نگهداری نتیجهٔ عملوندها نیز مقادیر موقت ساخته می‌شوند. مقادیر موقت به دامنهٔ عبارتی وابسته‌اند که آن عملوند را دارد. چون پس از ارزیابی عبارت، مقدار از این مقادیر موقت منتقل می‌شود، حذف آن‌ها اثری ندارد؛ مگر آنکه یکی از عملوندهای عبارت از عبارت خارج شود، بازگردد یا وحشت کند.

    struct PrintOnDrop(&'static str);
impl Drop for PrintOnDrop {
    fn drop(&mut self) {
        println!("drop({})", self.0);
    }
}
loop {
    // Tuple expression doesn't finish evaluating so operands drop in reverse order
    (
        PrintOnDrop("Outer tuple first"),
        PrintOnDrop("Outer tuple second"),
        (
            PrintOnDrop("Inner tuple first"),
            PrintOnDrop("Inner tuple second"),
            break,
        ),
        PrintOnDrop("Never created"),
    );
}
    [destructors.scope.const-promotion]

    ارتقای ثابت

    ارتقای یک عبارت مقدار به جایگاهی با طول‌عمر 'static هنگامی رخ می‌دهد که عبارت بتواند درون یک ثابت نوشته و قرض گرفته شود و آن قرض در محل اصلی عبارت بدون تغییر رفتار زمان اجرا قابل ارجاع‌زدایی باشد. یعنی عبارت ارتقایافته در زمان کامپایل قابل ارزیابی است و مقدار حاصل تغییرپذیری درونی یا نابودگر ندارد. این ویژگی‌ها در صورت امکان بر پایهٔ خود مقدار تعیین می‌شوند؛ برای نمونه &None همیشه نوع &'static Option<_> دارد، زیرا هیچ چیز غیرمجازی در خود ندارد.

    [destructors.scope.lifetime-extension]

    گسترش طول‌عمر مقادیر موقت

    [destructors.scope.lifetime-extension.intro]

    Note

    نکته قواعد دقیق گسترش طول‌عمر مقادیر موقت ممکن است تغییر کنند. این بخش فقط رفتار کنونی را شرح می‌دهد.

    [destructors.scope.lifetime-extension.let]

    دامنهٔ موقت عبارت‌های درون دستورهای let گاهی تا دامنهٔ بلوک دربرگیرندهٔ دستور let گسترش می‌یابد. این کار بر پایهٔ قواعد نحوی مشخصی و هنگامی انجام می‌شود که دامنهٔ موقت عادی بیش از حد کوچک باشد. برای نمونه:

    let x = &mut 0;
// Usually a temporary would be dropped by now, but the temporary for `0` lives
// to the end of the block.
println!("{}", x);
    [destructors.scope.lifetime-extension.static]

    گسترش طول‌عمر دربارهٔ اقلام static و const نیز اعمال می‌شود و مقادیر موقت را تا پایان برنامه زنده نگه می‌دارد. برای نمونه:

    const C: &Vec<i32> = &Vec::new();
// Usually this would be a dangling reference as the `Vec` would only
// exist inside the initializer expression of `C`, but instead the
// borrow gets lifetime-extended so it effectively has `'static` lifetime.
println!("{:?}", C);
    [destructors.scope.lifetime-extension.sub-expressions]

    اگر یک قرض‌گیری، ارجاع‌زدایی، میدان یا عبارت اندیس‌گذاری تاپل دامنهٔ موقت گسترش‌یافته‌ای داشته باشد، عملوند آن نیز چنین است. اگر یک عبارت اندیس‌گذاری دامنهٔ موقت گسترش‌یافته داشته باشد، عبارت اندیس‌شونده نیز دامنهٔ موقت گسترش‌یافته دارد.

    [destructors.scope.lifetime-extension.patterns]

    گسترش بر پایهٔ الگوها

    [destructors.scope.lifetime-extension.patterns.extending]

    الگوی گسترش‌دهنده یکی از موارد زیر است:

    • الگوی شناسه‌ای که با ارجاع یا ارجاع تغییرپذیر مقید می‌شود.

      fn temp() {}
let ref x = temp(); // Binds by reference.
x;
let ref mut x = temp(); // Binds by mutable reference.
x;

    • یک ساختار، تاپل، ساختار تاپلی، برش یا الگوی یا که دست‌کم یکی از زیرالگوهای مستقیمش الگوی گسترش‌دهنده باشد.

      use core::sync::atomic::{AtomicU64, Ordering::Relaxed};
static X: AtomicU64 = AtomicU64::new(0);
struct W<T>(T);
impl<T> Drop for W<T> { fn drop(&mut self) { X.fetch_add(1, Relaxed); } }
let W { 0: ref x } = W(()); // Struct pattern.
x;
let W(ref x) = W(()); // Tuple struct pattern.
x;
let (W(ref x),) = (W(()),); // Tuple pattern.
x;
let [W(ref x), ..] = [W(())]; // Slice pattern.
x;
let (Ok(W(ref x)) | Err(&ref x)) = Ok(W(())); // Or pattern.
x;
//
// All of the temporaries above are still live here.
assert_eq!(0, X.load(Relaxed));

    بنابراین ref x، V(ref x) و [ref x, y] همگی الگوهای گسترش‌دهنده‌اند، اما x، &ref x و &(ref x,) چنین نیستند.

    [destructors.scope.lifetime-extension.patterns.let]

    اگر الگوی یک دستور let گسترش‌دهنده باشد، دامنهٔ موقت عبارت مقداردهنده گسترش می‌یابد.

    fn temp() {}
// This is an extending pattern, so the temporary scope is extended.
let ref x = *&temp(); // OK
x;
    fn temp() {}
// This is neither an extending pattern nor an extending expression,
// so the temporary is dropped at the semicolon.
let &ref x = *&&temp(); // ERROR
x;
    fn temp() {}
// This is not an extending pattern but it is an extending expression,
// so the temporary lives beyond the `let` statement.
let &ref x = &*&temp(); // OK
x;
    [destructors.scope.lifetime-extension.exprs]

    گسترش بر پایهٔ عبارت‌ها

    [destructors.scope.lifetime-extension.exprs.extending]

    برای یک دستور let دارای مقداردهنده، عبارت گسترش‌دهنده (extending expression) عبارتی است که یکی از موارد زیر باشد:

    • خود عبارت مقداردهنده.
    • عملوند یک عبارت قرض‌گیری گسترش‌دهنده.
    • عملوند یک عبارت قرض‌گیری گسترش‌دهنده.
    • ابرعملوندهای یک عبارت فراخوانی ابرماکرو گسترش‌دهنده.
    • آرگومان‌های عبارت سازندهٔ ساختار تاپلی یا گونهٔ برشمردنی تاپلی گسترش‌دهنده.
    • عبارت پایانی یک عبارت بلوک گسترش‌دهنده، جز عبارت بلوک ناهمگام.
    • عبارت پایانی بلوک نتیجه، else if یا else یک عبارت if گسترش‌دهنده.
    • عبارت یک بازوی match گسترش‌دهنده.

    Note

    نکته بازنویسی یک انتساب واسازی، عملوند مقدار انتسابی آن (سمت راست) را درون بلوکی تازه‌ساخته‌شده به عبارت گسترش‌دهنده تبدیل می‌کند. برای جزئیات expr.assign.destructure.tmp-ext را ببینید.

    بنابراین عبارت‌های قرض‌گیری در &mut 0، (&1, &mut 2) و Some(&mut 3) همگی عبارت گسترش‌دهنده‌اند. قرض‌گیری‌های &0 + &1 و f(&mut 0) چنین نیستند.

    [destructors.scope.lifetime-extension.exprs.borrows]

    دامنهٔ موقت عملوند یک عبارت قرض‌گیری گسترش‌دهنده گسترش داده می‌شود.

    [destructors.scope.lifetime-extension.exprs.super-macros]

    super temporaryهای یک عبارت گسترش‌دهندهٔ فراخوانی ماکروی super، دامنه‌هایشان گسترش داده می‌شود.

    Note

    نکته rustc عملوندهای تکرار آرایه در عبارت‌های آرایه گسترش‌دهنده را عبارت گسترش‌دهنده در نظر نمی‌گیرد. اینکه آیا باید چنین کند یا نه، پرسشی باز است.

    برای جزئیات مسئلهٔ شمارهٔ 146092 در Rust را ببینید.

    مثال‌ها

    این‌ها نمونه‌هایی هستند که عبارت‌ها در آن‌ها دامنهٔ موقت گسترش‌یافته دارند:

    use core::pin::pin;
use core::sync::atomic::{AtomicU64, Ordering::Relaxed};
static X: AtomicU64 = AtomicU64::new(0);
#[derive(Debug)] struct S;
impl Drop for S { fn drop(&mut self) { X.fetch_add(1, Relaxed); } }
const fn temp() -> S { S }
let x = &temp(); // Operand of borrow.
x;
let x = &raw const *&temp(); // Operand of raw borrow.
assert_eq!(X.load(Relaxed), 0);
let x = &temp() as &dyn Send; // Operand of cast.
x;
let x = (&*&temp(),); // Operand of tuple constructor.
x;
struct W<T>(T);
let x = W(&temp()); // Argument to tuple struct constructor.
x;
let x = Some(&temp()); // Argument to tuple enum variant constructor.
x;
let x = { [Some(&temp())] }; // Final expr of block.
x;
let x = const { &temp() }; // Final expr of `const` block.
x;
let x = unsafe { &temp() }; // Final expr of `unsafe` block.
x;
let x = if true { &temp() } else { &temp() };
//              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//           Final exprs of `if`/`else` blocks.
x;
let x = match () { _ => &temp() }; // `match` arm expression.
x;
let x = pin!(temp()); // Super operand of super macro call expression.
x;
let x = pin!({ &mut temp() }); // As above.
x;
let x = format_args!("{:?}", temp()); // As above.
x;
//
// All of the temporaries above are still live here.
assert_eq!(0, X.load(Relaxed));

    این‌ها نمونه‌هایی هستند که عبارت‌ها در آن‌ها دامنهٔ موقت گسترش‌یافته ندارند:

    fn temp() {}
// Arguments to function calls are not extending expressions. The
// temporary is dropped at the semicolon.
let x = core::convert::identity(&temp()); // ERROR
x;
    fn temp() {}
trait Use { fn use_temp(&self) -> &Self { self } }
impl Use for () {}
// Receivers of method calls are not extending expressions.
let x = (&temp()).use_temp(); // ERROR
x;
    fn temp() {}
// Scrutinees of match expressions are not extending expressions.
let x = match &temp() { x => x }; // ERROR
x;
    fn temp() {}
// Final expressions of `async` blocks are not extending expressions.
let x = async { &temp() }; // ERROR
x;
    fn temp() {}
// Final expressions of closures are not extending expressions.
let x = || &temp(); // ERROR
x;
    fn temp() {}
// Operands of loop breaks are not extending expressions.
let x = loop { break &temp() }; // ERROR
x;
    fn temp() {}
// Operands of breaks to labels are not extending expressions.
let x = 'a: { break 'a &temp() }; // ERROR
x;
    use core::pin::pin;
fn temp() {}
// The argument to `pin!` is only an extending expression if the call
// is an extending expression. Since it's not, the inner block is not
// an extending expression, so the temporaries in its trailing
// expression are dropped immediately.
pin!({ &temp() }); // ERROR
    fn temp() {}
// As above.
format_args!("{:?}", { &temp() }); // ERROR
    [destructors.forget]

    اجرا نکردن نابودگرها

    [destructors.manually-suppressing]

    جلوگیری دستی از اجرای نابودگرها

    با core::mem::forget می‌توان از اجرای نابودگر یک متغیر جلوگیری کرد و core::mem::ManuallyDrop پوششی فراهم می‌کند که از حذف خودکار یک متغیر یا میدان جلوگیری می‌کند.

    Note

    نکته جلوگیری از اجرای نابودگر با core::mem::forget یا روش‌های دیگر، حتی برای نوعی که 'static نیست، امن است. جز محل‌هایی که اجرای نابودگر طبق این سند تضمین شده، نوع‌ها برای صحت خود نمی‌توانند با ایمنی به اجرای نابودگر تکیه کنند.

    [destructors.process-termination]

    پایان فرایند بدون بازپیچی

    راه‌هایی برای پایان دادن به فرایند بدون بازپیچی وجود دارد که در آن صورت نابودگرها اجرا نمی‌شوند.

    کتابخانهٔ استاندارد std::process::exit و std::process::abort را برای انجام صریح این کار فراهم می‌کند. همچنین اگر مدیریت‌کنندهٔ وحشت روی abort تنظیم شده باشد، وحشت همیشه فرایند را بدون اجرای نابودگرها پایان می‌دهد.

    یک حالت دیگر نیز باید در نظر گرفته شود: وقتی وحشت به یک مرز ABI بدون بازپیچی برسد، یا هیچ نابودگری اجرا نمی‌شود یا همهٔ نابودگرها تا مرز ABI اجرا می‌شوند.
