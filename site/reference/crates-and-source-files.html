    Note

    نکته هرچند Rust نیز مانند هر زبان دیگری می‌تواند با مفسر یا کامپایلر پیاده‌سازی شود، تنها پیاده‌سازی موجود آن کامپایلر است و طراحی زبان همیشه بر پایهٔ کامپایل‌شدن بوده است. به همین دلیل این بخش وجود یک کامپایلر را فرض می‌کند.

    [crate.compile-time]

    معناشناسی Rust میان زمان کامپایل و زمان اجرا تمایزی مرحله‌ای قائل است.1 قواعد معنایی با تفسیر ایستا موفقیت یا شکست کامپایل را تعیین می‌کنند و قواعد معنایی با تفسیر پویا رفتار برنامه هنگام اجرا را شکل می‌دهند.

    [crate.unit]

    مدل کامپایل بر محصولاتی به نام crate استوار است. هر بار کامپایل یک crate را در قالب منبع پردازش می‌کند و در صورت موفقیت، یک crate دودویی—یک فایل اجرایی یا گونه‌ای کتابخانه—می‌سازد.2

    [crate.module]

    Crate واحد کامپایل و پیوند و همچنین نسخه‌بندی، توزیع و بارگذاری هنگام اجراست. هر crate درختی از محدوده‌های ماژول تودرتو دارد. بالاترین سطح این درخت ماژولی است که از دید مسیرهای درون آن بی‌نام است. هر آیتم داخل crate یک مسیر ماژول استاندارد دارد که جایگاهش را در درخت ماژول crate مشخص می‌کند.

    [crate.input-source]

    کامپایلر Rust همواره با یک فایل منبع به‌عنوان ورودی فراخوانی می‌شود و یک crate خروجی تولید می‌کند. پردازش آن فایل ممکن است باعث بارگذاری فایل‌های منبع دیگری به‌عنوان ماژول شود. پسوند فایل‌های منبع .rs است.

    [crate.module-def]

    هر فایل منبع Rust یک ماژول را توصیف می‌کند. نام و جایگاه این ماژول در درخت ماژول crate جاری، بیرون از خود فایل منبع تعیین می‌شود: یا با یک آیتم صریح Module در فایل منبعی که به آن ارجاع می‌دهد، یا با نام خود crate.

    [crate.inline-module]

    هر فایل منبع یک ماژول است، اما هر ماژول الزاماً فایل منبع جداگانه‌ای ندارد؛ تعریف‌های ماژول می‌توانند در یک فایل تودرتو شوند.

    [crate.items]

    هر فایل منبع دنباله‌ای شامل صفر یا چند تعریف Item دارد و می‌تواند در آغاز خود هر تعداد attribute داشته باشد که روی ماژول دربرگیرنده اعمال می‌شوند. بیشتر این attributeها بر رفتار کامپایلر اثر می‌گذارند.

    [crate.attributes]

    ماژول بی‌نام crate می‌تواند attributeهای دیگری نیز داشته باشد که بر کل crate اعمال می‌شوند.

    Note

    نکته ممکن است پیش از محتوای فایل یک shebang قرار گیرد.

    // Specify the crate name.
#![crate_name = "projx"]

// Specify the type of output artifact.
#![crate_type = "lib"]

// Turn on a warning.
// This can be done in any module, not just the anonymous crate module.
#![warn(non_camel_case_types)]
    [crate.main]

    تابع‌های Main

    [crate.main.executable]

    Crateای که یک تابع main داشته باشد، می‌تواند به فایل اجرایی کامپایل شود.

    [crate.main.restriction]

    اگر تابع main وجود داشته باشد، نباید آرگومان بگیرد، نباید قید Trait یا lifetime یا بند where تعریف کند و نوع بازگشتی آن باید Traitِ Termination را پیاده‌سازی کند.

    fn main() {}
    fn main() -> ! {
    std::process::exit(0);
}
    fn main() -> impl std::process::Termination {
    std::process::ExitCode::SUCCESS
}
    [crate.main.import]

    تابع main می‌تواند import شده باشد؛ برای نمونه از crate خارجی یا از crate جاری.

    mod foo {
    pub fn bar() {
        println!("Hello, world!");
    }
}
use foo::bar as main;

    Note

    نکته نوع‌های دارای پیاده‌سازی Termination در کتابخانهٔ استاندارد عبارت‌اند از:

    • ()
    • !
    • Infallible
    • ExitCode
    • Result<T, E> where T: Termination, E: Debug
    [crate.uncaught-foreign-unwinding]

    Unwind خارجیِ مهارنشده

    اگر یک unwind «خارجی»—برای نمونه exception پرتاب‌شده از کد C++ یا یک panic! در کد Rust با panic handler متفاوت—از تابع main عبور کند، فرایند به‌شکلی ایمن خاتمه می‌یابد. این خاتمه ممکن است به‌صورت abort باشد؛ در این حالت اجرای فراخوانی‌های Drop تضمین نمی‌شود و خروجی خطا ممکن است از حالتی که runtime با یک panic بومی Rust پایان یافته، اطلاعات کمتری داشته باشد.

    برای اطلاعات بیشتر مستندات panic را ببینید.

    [crate.no_main]

    Attributeِ no_main

    می‌توان attributeِ no_main را در سطح crate اعمال کرد تا تولید نماد main برای فایل اجرایی غیرفعال شود. این قابلیت زمانی مفید است که object دیگری که پیوند می‌خورد، main را تعریف کرده باشد.

    [crate.crate_name]

    Attributeِ crate_name

    [crate.crate_name.general]

    می‌توان attributeِ crate_name را با نحو MetaNameValueStr در سطح crate اعمال کرد تا نام crate مشخص شود.

    #![crate_name = "mycrate"]
    [crate.crate_name.restriction]

    نام crate نباید خالی باشد و فقط می‌تواند شامل نویسه‌های حرفی‌عددی Unicode یا _ ‏(U+005F) باشد.

    1. این تمایز در یک مفسر نیز وجود دارد. بررسی‌های ایستا مانند تحلیل نحوی، بررسی نوع و lintها، مستقل از زمان اجرا باید پیش از اجرای برنامه انجام شوند. ↩

    2. یک crate تا اندازه‌ای به assembly در مدل CLI استاندارد ECMA-335، یک library در Compilation Manager سامانهٔ SML/NJ، یک unit در سامانهٔ ماژول Owens و Flatt یا یک configuration در Mesa شباهت دارد. ↩
