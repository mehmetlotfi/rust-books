    [lang-types]

    نوع‌ها و صفت‌های ویژه

    [lang-types.intro]

    کامپایلر Rust برخی نوع‌ها و صفت‌های موجود در کتابخانهٔ استاندارد را می‌شناسد. این فصل قابلیت‌های ویژهٔ آن‌ها را مستند می‌کند.

    [lang-types.box]

    Box<T>

    [lang-types.box.intro]

    [Box<T>] چند قابلیت ویژه دارد که Rust اکنون برای نوع‌های تعریف‌شده توسط کاربر مجاز نمی‌داند.

    [lang-types.box.deref]
    • عملگر ارجاع‌زدایی برای Box<T> مکانی تولید می‌کند که می‌توان مقدار را از آن جابه‌جا کرد. یعنی عملگر * و ویرانگر Box<T> در خود زبان تعبیه شده‌اند.
    [lang-types.box.receiver]
    • متدها می‌توانند Box<Self> را به‌عنوان گیرنده بگیرند.
    [lang-types.box.fundamental]
    • یک صفت می‌تواند در همان crate مربوط به T برای Box<T> پیاده‌سازی شود؛ کاری که قواعد orphan برای دیگر نوع‌های عمومی ممنوع می‌کنند.
    [lang-types.rc]

    Rc<T>

    [lang-types.rc.receiver]

    متدها می‌توانند Rc<Self> را به‌عنوان گیرنده بگیرند.

    [lang-types.arc]

    Arc<T>

    [lang-types.arc.receiver]

    متدها می‌توانند Arc<Self> را به‌عنوان گیرنده بگیرند.

    [lang-types.pin]

    Pin<P>

    [lang-types.pin.receiver]

    متدها می‌توانند Pin<P> را به‌عنوان گیرنده بگیرند.

    [lang-types.unsafe-cell]

    UnsafeCell<T>

    [lang-types.unsafe-cell.interior-mut]

    از std::cell::UnsafeCell<T> برای تغییرپذیری درونی استفاده می‌شود. این نوع تضمین می‌کند کامپایلر بهینه‌سازی‌های نادرست برای چنین نوع‌هایی را انجام ندهد.

    [lang-types.unsafe-cell.read-only-alloc]

    همچنین تضمین می‌کند آیتم‌های static با نوع دارای تغییرپذیری درونی، در حافظهٔ علامت‌گذاری‌شده به‌عنوان فقط‌خواندنی قرار نگیرند.

    [lang-types.phantom-data]

    PhantomData<T>

    [std::marker::PhantomData<T>] نوعی با اندازهٔ صفر و کمترین هم‌ترازی است که برای واریانس، بررسی drop و صفت‌های خودکار، مالک یک T در نظر گرفته می‌شود.

    [lang-types.va-list]

    VaList<'_>

    از VaList برای تابع‌های C با تعداد آرگومان متغیر استفاده می‌شود.

    Note

    نکته VaList با نوع va_list در C سازگاری ABI دارد؛ items.fn.c-variadic.abi-compatibility را ببینید.

    [lang-types.ops]

    صفت‌های عملگر

    صفت‌های std::ops و std::cmp برای سربارگذاری عملگرها، عبارت‌های نمایه‌گذاری و عبارت‌های فراخوانی استفاده می‌شوند.

    [lang-types.deref]

    Deref و DerefMut

    Deref و DerefMut افزون بر سربارگذاری عملگر یگانی *، در تفکیک متد و وادارسازی‌های deref نیز استفاده می‌شوند.

    [lang-types.drop]

    Drop

    صفت Drop یک ویرانگر فراهم می‌کند که هر زمان مقداری از این نوع نابود شود اجرا خواهد شد.

    [lang-types.copy]

    Copy

    [lang-types.copy.intro]

    صفت Copy معنای نوع پیاده‌سازی‌کنندهٔ خود را تغییر می‌دهد.

    [lang-types.copy.behavior]

    مقادیر نوعی که Copy را پیاده‌سازی می‌کند هنگام انتساب به‌جای جابه‌جایی، کپی می‌شوند.

    [lang-types.copy.constraint]

    Copy را تنها می‌توان برای نوع‌هایی پیاده‌سازی کرد که Drop را پیاده‌سازی نمی‌کنند و همهٔ فیلدهایشان Copy هستند. برای enumها، این یعنی همهٔ فیلدهای همهٔ گونه‌ها باید Copy باشند. برای unionها، این یعنی همهٔ گونه‌ها باید Copy باشند.

    [lang-types.copy.builtin-types]

    کامپایلر Copy را برای موارد زیر پیاده‌سازی می‌کند:

    [lang-types.copy.tuple]
    • تاپل‌های متشکل از نوع‌های Copy
    [lang-types.copy.fn-pointer]
    • اشاره‌گرهای تابع
    [lang-types.copy.fn-item]
    • آیتم‌های تابع
    [lang-types.copy.closure]
    • بستارهایی که مقداری تسخیر نمی‌کنند یا فقط مقادیر نوع‌های Copy را تسخیر می‌کنند
    [lang-types.clone]

    Clone

    [lang-types.clone.intro]

    صفت Clone فراصفت Copy است؛ بنابراین آن نیز به پیاده‌سازی‌های تولیدشده توسط کامپایلر نیاز دارد.

    [lang-types.clone.builtin-types]

    کامپایلر آن را برای نوع‌های زیر پیاده‌سازی می‌کند:

    [lang-types.clone.builtin-copy]
    • نوع‌های دارای پیاده‌سازی داخلی Copy که در بالا آمدند
    [lang-types.clone.tuple]
    • تاپل‌های متشکل از نوع‌های Clone
    [lang-types.clone.closure]
    • بستارهایی که فقط مقادیر نوع‌های Clone را تسخیر می‌کنند یا هیچ مقداری از محیط نمی‌گیرند
    [lang-types.send]

    Send

    صفت Send نشان می‌دهد فرستادن مقدار این نوع از یک نخ به نخ دیگر ایمن است.

    [lang-types.sync]

    Sync

    [lang-types.sync.intro]

    صفت Sync نشان می‌دهد اشتراک مقدار این نوع میان چند نخ ایمن است.

    [lang-types.sync.static-constraint]

    همهٔ نوع‌های استفاده‌شده در آیتم‌های static تغییرناپذیر باید این صفت را پیاده‌سازی کنند.

    [lang-types.termination]

    Termination

    صفت Termination نوع‌های بازگشت پذیرفته‌شده برای تابع main و تابع‌های آزمون را نشان می‌دهد.

    [lang-types.auto-traits]

    صفت‌های خودکار

    [lang-types.auto-traits.intro]

    صفت‌های Send، ‏Sync، ‏Unpin، ‏UnwindSafe و RefUnwindSafe صفت خودکار هستند و ویژگی‌های خاصی دارند.

    [lang-types.auto-traits.auto-impl]

    اگر برای یک نوع، پیاده‌سازی صریح یا منفی یک صفت خودکار نوشته نشده باشد، کامپایلر طبق قواعد زیر آن را خودکار پیاده‌سازی می‌کند:

    [lang-types.auto-traits.builtin-composite]
    • &T، ‏&mut T، ‏*const T، ‏*mut T، ‏[T; n] و [T] در صورتی صفت را پیاده‌سازی می‌کنند که T آن را پیاده‌سازی کند.
    [lang-types.auto-traits.fn-item-pointer]
    • نوع‌های آیتم تابع و اشاره‌گرهای تابع صفت را خودکار پیاده‌سازی می‌کنند.
    [lang-types.auto-traits.aggregate]
    • structها، enumها، unionها و تاپل‌ها در صورتی صفت را پیاده‌سازی می‌کنند که همهٔ فیلدهایشان آن را پیاده‌سازی کنند.
    [lang-types.auto-traits.closure]
    • بستارها در صورتی صفت را پیاده‌سازی می‌کنند که نوع همهٔ مقادیر تسخیرشده آن را پیاده‌سازی کند. بستاری که T را با ارجاع اشتراکی و U را با مقدار تسخیر می‌کند، هر صفت خودکاری را پیاده‌سازی می‌کند که هر دو &T و U پیاده‌سازی کنند.
    [lang-types.auto-traits.generic-impl]

    برای نوع‌های عمومی—با احتساب نوع‌های داخلی بالا به‌عنوان عمومی روی T—اگر پیاده‌سازی عمومی موجود باشد، کامپایلر آن صفت را برای نوع‌هایی که فقط به‌دلیل برآورده‌نکردن کران لازم نمی‌توانند از پیاده‌سازی استفاده کنند، خودکار پیاده‌سازی نمی‌کند. برای نمونه، کتابخانهٔ استاندارد Send را برای همهٔ &Tهایی پیاده‌سازی می‌کند که T از نوع Sync است؛ پس اگر T از نوع Send اما نه Sync باشد، کامپایلر Send را برای &T پیاده‌سازی نمی‌کند.

    [lang-types.auto-traits.negative]

    صفت‌های خودکار می‌توانند پیاده‌سازی منفی نیز داشته باشند که در مستندات کتابخانهٔ استاندارد به‌شکل impl !AutoTrait for T دیده می‌شود و پیاده‌سازی خودکار را لغو می‌کند. برای مثال *mut T پیاده‌سازی منفی Send دارد؛ پس حتی اگر T از نوع Send باشد، *mut T چنین نیست. اکنون راه پایداری برای تعیین پیاده‌سازی‌های منفی بیشتر وجود ندارد و آن‌ها فقط در کتابخانهٔ استاندارد هستند.

    [lang-types.auto-traits.trait-object-marker]

    صفت‌های خودکار را می‌توان به‌عنوان کران اضافی به هر شیء صفت افزود، هرچند معمولاً فقط یک صفت مجاز است. برای نمونه Box<dyn Debug + Send + UnwindSafe> نوعی معتبر است.

    [lang-types.sized]

    Sized

    [lang-types.sized.intro]

    صفت Sized نشان می‌دهد اندازهٔ این نوع هنگام کامپایل معلوم است؛ یعنی نوع با اندازهٔ پویا نیست.

    [lang-types.sized.implicit-sized]

    پارامترهای نوع—به‌جز Self در صفت‌ها—به‌طور پیش‌فرض Sized هستند؛ نوع‌های وابسته نیز همین‌طورند.

    [lang-types.sized.implicit-impl]

    Sized همیشه به‌طور خودکار توسط کامپایلر پیاده‌سازی می‌شود، نه با آیتم‌های پیاده‌سازی.

    [lang-types.sized.relaxation]

    این کران‌های ضمنی Sized را می‌توان با کران ویژهٔ ?Sized آسان‌تر کرد.
