    [abi]

    رابط دودویی برنامه (ABI)

    [abi.intro]

    این بخش قابلیت‌هایی را مستند می‌کند که بر ABI خروجی کامپایل‌شدهٔ یک crate اثر می‌گذارند.

    برای چگونگی تعیین ABI تابع‌های صادرشده، تابع‌های extern را ببینید. برای تعیین ABI هنگام پیوند کتابخانه‌های خارجی، بلوک‌های خارجی را ببینید.

    [abi.used]

    ویژگی used

    [abi.used.intro]

    ویژگی used یک static را وادار می‌کند حتی اگر هرگز استفاده نشود یا آیتم دیگری از crate به آن ارجاع ندهد، در فایل شیء خروجی (.o، ‏.rlib و مانند آن، به‌جز فایل‌های دودویی نهایی) حفظ شود. بااین‌حال، پیونددهنده همچنان آزاد است آن را حذف کند.

    مثال

    // lib.rs

// This is kept because of `#[used]`.
#[used]
static S1: u8 = 0;

// This is removable because it's unused.
#[allow(dead_code)]
static S2: u8 = 0;

// This is kept because it's publicly reachable.
pub static S3: u8 = 0;

// This is kept because it's referenced by a publicly
// reachable function.
static S4: u8 = 0;
#[unsafe(no_mangle)] pub fn f4() -> &'static u8 { &S4 }

// This is removable because it's referenced only by a
// private, unused (dead) function.
static S5: u8 = 0;
#[allow(dead_code)]
fn f5() -> &'static u8 { &S5 }
    $ rustc -O --emit=obj --crate-type=rlib lib.rs
$ LC_ALL=C nm -C lib.o
0000000000000000 R lib::S1
0000000000000000 R lib::S3
0000000000000000 r lib::S4
0000000000000000 T f4
    [abi.used.syntax]

    ویژگی used از نحو MetaWord استفاده می‌کند.

    [abi.used.allowed-positions]

    ویژگی used را تنها می‌توان روی آیتم‌های static اعمال کرد.

    [abi.used.duplicates]

    تنها نخستین استفاده از used روی یک آیتم اثر دارد.

    Note

    نکته rustc دربارهٔ استفاده‌های پس از مورد نخست lint صادر می‌کند.

    [abi.no_mangle]

    ویژگی no_mangle

    [abi.no_mangle.intro]

    ویژگی no_mangle درهم‌سازی استاندارد نام نماد را برای یک تابع یا static غیرفعال می‌کند. نماد آیتم همان شناسهٔ آیتم خواهد بود.

    مثال

    #[unsafe(no_mangle)]
extern "C" fn foo() {}
    [abi.no_mangle.syntax]

    ویژگی no_mangle از نحو MetaWord استفاده می‌کند.

    [abi.no_mangle.allowed-positions]

    ویژگی no_mangle را تنها می‌توان روی موارد زیر اعمال کرد:

    • آیتم‌های static
    • تابع‌های آزاد
    • تابع‌های وابستهٔ ذاتی
    • تابع‌های impl صفت

    Note

    نکته rustc دربارهٔ استفاده در موقعیت‌های دیگر lint صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [abi.no_mangle.closures]

    ویژگی no_mangle را نمی‌توان با بستار به‌کار برد.

    [abi.no_mangle.generics]

    ویژگی no_mangle را نمی‌توان روی آیتم دارای پارامتر عمومی به‌کار برد.

    [abi.no_mangle.duplicates]

    تنها نخستین استفاده از no_mangle روی یک آیتم اثر دارد.

    Note

    نکته rustc دربارهٔ استفاده‌های پس از مورد نخست lint صادر می‌کند.

    [abi.no_mangle.export_name]

    اگر ویژگی‌های no_mangle و export_name هر دو روی یک آیتم اعمال شوند، نام نماد از export_name گرفته می‌شود و no_mangle اثری ندارد.

    Note

    نکته rustc دربارهٔ این ترکیب lint صادر می‌کند.

    [abi.no_mangle.unsafe]

    ویژگی no_mangle باید با unsafe علامت‌گذاری شود، زیرا نماد درهم‌سازی‌نشده ممکن است با نماد دیگری به همان نام یا نمادی شناخته‌شده برخورد کند و به رفتار تعریف‌نشده منجر شود.

    [abi.no_mangle.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴ استفاده از ویژگی no_mangle بدون unsafe مجاز بود.

    [abi.no_mangle.publicly-exported]

    ویژگی no_mangle افزون بر غیرفعال‌کردن درهم‌سازی نام، باعث می‌شود نماد مانند ویژگی used به‌طور عمومی از کتابخانه یا فایل شیء تولیدشده صادر شود.

    [abi.no_mangle.ascii-only]

    ویژگی no_mangle تنها روی آیتم‌هایی مجاز است که نامشان فقط نویسه‌های ASCII دارد.

    [abi.link_section]

    ویژگی link_section

    [abi.link_section.intro]

    ویژگی link_section بخشی از فایل شیء را مشخص می‌کند که محتوای یک تابع یا static در آن قرار می‌گیرد.

    [abi.link_section.syntax]

    ویژگی link_section برای مشخص‌کردن نام بخش از نحو MetaNameValueStr استفاده می‌کند.

    #[cfg(target_os = "linux")] {
#[unsafe(no_mangle)]
#[unsafe(link_section = ".example_section")]
pub static VAR1: u32 = 1;
}
    [abi.link_section.unsafe]

    این ویژگی ناامن است، زیرا به کاربر اجازه می‌دهد داده و کد را در بخش‌هایی از حافظه قرار دهد که انتظار آن‌ها را ندارند؛ برای نمونه دادهٔ تغییرپذیر در ناحیهٔ فقط‌خواندنی.

    [abi.link_section.duplicates]

    تنها نخستین استفاده از link_section روی یک آیتم اثر دارد.

    Note

    نکته rustc دربارهٔ استفاده‌های پس از مورد نخست هشدار سازگاری آینده صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [abi.link_section.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴ استفاده از ویژگی link_section بدون مشخص‌کنندهٔ unsafe مجاز بود.

    [abi.export_name]

    ویژگی export_name

    [abi.export_name.intro]

    ویژگی export_name نام نمادی را مشخص می‌کند که برای یک تابع یا static صادر خواهد شد.

    [abi.export_name.syntax]

    ویژگی export_name برای مشخص‌کردن نام نماد از نحو MetaNameValueStr استفاده می‌کند.

    #[unsafe(export_name = "exported_symbol_name")]
pub fn name_in_rust() { }
    [abi.export_name.unsafe]

    این ویژگی ناامن است، زیرا نمادی با نام سفارشی ممکن است با نماد دیگری به همان نام یا نمادی شناخته‌شده برخورد کند و رفتار تعریف‌نشده به‌وجود آورد.

    [abi.export_name.duplicates]

    تنها نخستین استفاده از export_name روی یک آیتم اثر دارد.

    Note

    نکته rustc دربارهٔ استفاده‌های پس از مورد نخست هشدار سازگاری آینده صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [abi.export_name.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴ استفاده از ویژگی export_name بدون مشخص‌کنندهٔ unsafe مجاز بود.
