    [lifetime-elision]

    حذف طول‌عمر

    [lifetime-elision.intro]

    Rust قواعدی دارد که اجازه می‌دهند طول‌عمرها در محل‌های گوناگونی که کامپایلر می‌تواند انتخاب پیش‌فرض معقولی را استنتاج کند، حذف شوند.

    [lifetime-elision.function]

    حذف طول‌عمر در تابع‌ها

    [lifetime-elision.function.intro]

    برای روان‌ترشدن الگوهای رایج، آرگومان‌های طول‌عمر را می‌توان در امضای آیتم تابع، اشاره‌گر تابع و صفت بستار حذف کرد. قواعد زیر پارامترهای طول‌عمر مربوط به طول‌عمرهای حذف‌شده را استنتاج می‌کنند.

    [lifetime-elision.function.lifetimes-not-inferred]

    حذف پارامتر طول‌عمری که قابل استنتاج نیست خطاست.

    [lifetime-elision.function.explicit-placeholder]

    از طول‌عمر جای‌نگهدار '_ نیز می‌توان برای استنتاج طول‌عمر به همین روش استفاده کرد. برای طول‌عمرهای درون مسیر، استفاده از '_ ترجیح دارد.

    [lifetime-elision.function.only-functions]

    طول‌عمر شیء صفت از قواعد متفاوتی پیروی می‌کند که در ادامه آمده‌اند.

    [lifetime-elision.function.implicit-lifetime-parameters]
    • هر طول‌عمر حذف‌شده در پارامترها به یک پارامتر طول‌عمر مجزا تبدیل می‌شود.
    [lifetime-elision.function.output-lifetime]
    • اگر دقیقاً یک طول‌عمر—حذف‌شده یا صریح—در پارامترها استفاده شده باشد، همان طول‌عمر به همهٔ طول‌عمرهای خروجی حذف‌شده اختصاص می‌یابد.
    [lifetime-elision.function.receiver-lifetime]

    در امضای متد یک قاعدهٔ دیگر نیز وجود دارد:

    • اگر گیرنده نوع &Self یا &mut Self داشته باشد، طول‌عمر آن ارجاع به Self به همهٔ پارامترهای طول‌عمر خروجی حذف‌شده اختصاص می‌یابد.

    نمونه‌ها:

    trait T {}
trait ToCStr {}
struct Thing<'a> {f: &'a i32}
struct Command;

trait Example {
fn print1(s: &str);                                   // elided
fn print2(s: &'_ str);                                // also elided
fn print3<'a>(s: &'a str);                            // expanded

fn debug1(lvl: usize, s: &str);                       // elided
fn debug2<'a>(lvl: usize, s: &'a str);                // expanded

fn substr1(s: &str, until: usize) -> &str;            // elided
fn substr2<'a>(s: &'a str, until: usize) -> &'a str;  // expanded

fn get_mut1(&mut self) -> &mut dyn T;                 // elided
fn get_mut2<'a>(&'a mut self) -> &'a mut dyn T;       // expanded

fn args1<T: ToCStr>(&mut self, args: &[T]) -> &mut Command;                  // elided
fn args2<'a, 'b, T: ToCStr>(&'a mut self, args: &'b [T]) -> &'a mut Command; // expanded

fn other_args1<'a>(arg: &str) -> &'a str;             // elided
fn other_args2<'a, 'b>(arg: &'b str) -> &'a str;      // expanded

fn new1(buf: &mut [u8]) -> Thing<'_>;                 // elided - preferred
fn new2(buf: &mut [u8]) -> Thing;                     // elided
fn new3<'a>(buf: &'a mut [u8]) -> Thing<'a>;          // expanded
}

type FunPtr1 = fn(&str) -> &str;                      // elided
type FunPtr2 = for<'a> fn(&'a str) -> &'a str;        // expanded

type FunTrait1 = dyn Fn(&str) -> &str;                // elided
type FunTrait2 = dyn for<'a> Fn(&'a str) -> &'a str;  // expanded
    // The following examples show situations where it is not allowed to elide the
// lifetime parameter.

trait Example {
// Cannot infer, because there are no parameters to infer from.
fn get_str() -> &str;                                 // ILLEGAL

// Cannot infer, ambiguous if it is borrowed from the first or second parameter.
fn frob(s: &str, t: &str) -> &str;                    // ILLEGAL
}
    [lifetime-elision.trait-object]

    طول‌عمرهای پیش‌فرض شیء صفت

    [lifetime-elision.trait-object.intro]

    طول‌عمر مفروض ارجاع‌های نگهداری‌شده توسط شیء صفت، کران پیش‌فرض طول‌عمر شیء نامیده می‌شود. این کران‌ها در RFC 599 تعریف و در RFC 1156 اصلاح شدند.

    [lifetime-elision.trait-object.explicit-bound]

    وقتی کران طول‌عمر کاملاً حذف شده باشد، این کران‌های پیش‌فرض شیء به‌جای قواعد حذف پارامتر طول‌عمر بالا استفاده می‌شوند.

    [lifetime-elision.trait-object.explicit-placeholder]

    اگر '_ به‌عنوان کران طول‌عمر استفاده شود، کران از قواعد عادی حذف پیروی می‌کند.

    [lifetime-elision.trait-object.containing-type]

    اگر شیء صفت به‌عنوان آرگومان نوع یک نوع عمومی استفاده شود، ابتدا نوع دربرگیرنده برای استنتاج کران به‌کار می‌رود.

    [lifetime-elision.trait-object.containing-type-unique]
    • اگر نوع دربرگیرنده دقیقاً یک کران یکتا بدهد، همان کران پیش‌فرض است.
    [lifetime-elision.trait-object.containing-type-explicit]
    • اگر نوع دربرگیرنده بیش از یک کران بدهد، باید کرانی صریح مشخص شود.
    [lifetime-elision.trait-object.trait-bounds]

    اگر هیچ‌یک از این قواعد اعمال نشود، از کران‌های صفت استفاده می‌شود:

    [lifetime-elision.trait-object.trait-unique]
    • اگر صفت با یک کران طول‌عمر واحد تعریف شده باشد، همان کران استفاده می‌شود.
    [lifetime-elision.trait-object.static-lifetime]
    • اگر 'static برای هر کران طول‌عمر استفاده شده باشد، 'static به‌کار می‌رود.
    [lifetime-elision.trait-object.default]
    • اگر صفت کران طول‌عمری نداشته باشد، طول‌عمر در عبارت‌ها استنتاج می‌شود و بیرون عبارت‌ها 'static است.
    // For the following trait...
trait Foo { }

// These two are the same because Box<T> has no lifetime bound on T
type T1 = Box<dyn Foo>;
type T2 = Box<dyn Foo + 'static>;

// ...and so are these:
impl dyn Foo {}
impl dyn Foo + 'static {}

// ...so are these, because &'a T requires T: 'a
type T3<'a> = &'a dyn Foo;
type T4<'a> = &'a (dyn Foo + 'a);

// std::cell::Ref<'a, T> also requires T: 'a, so these are the same
type T5<'a> = std::cell::Ref<'a, dyn Foo>;
type T6<'a> = std::cell::Ref<'a, dyn Foo + 'a>;
    // This is an example of an error.
trait Foo { }
struct TwoBounds<'a, 'b, T: ?Sized + 'a + 'b> {
    f1: &'a i32,
    f2: &'b i32,
    f3: T,
}
type T7<'a, 'b> = TwoBounds<'a, 'b, dyn Foo>;
//                                  ^^^^^^^
// Error: the lifetime bound for this object type cannot be deduced from context
    [lifetime-elision.trait-object.innermost-type]

    توجه کنید که درونی‌ترین شیء کران را تعیین می‌کند؛ بنابراین &'a Box<dyn Foo> همچنان همان &'a Box<dyn Foo + 'static> است.

    // For the following trait...
trait Bar<'a>: 'a { }

// ...these two are the same:
type T1<'a> = Box<dyn Bar<'a>>;
type T2<'a> = Box<dyn Bar<'a> + 'a>;

// ...and so are these:
impl<'a> dyn Bar<'a> {}
impl<'a> dyn Bar<'a> + 'a {}
    [lifetime-elision.const-static]

    حذف در const و static

    [lifetime-elision.const-static.implicit-static]

    اعلان ثابت و static از نوع ارجاع، مگر با طول‌عمر صریح، طول‌عمر 'static ضمنی دارند. بنابراین اعلان‌های ثابت دارای 'static در بالا را می‌توان بدون نوشتن طول‌عمرها نوشت.

    // STRING: &'static str
const STRING: &str = "bitstring";

struct BitsNStrings<'a> {
    mybits: [u32; 2],
    mystring: &'a str,
}

// BITS_N_STRINGS: BitsNStrings<'static>
const BITS_N_STRINGS: BitsNStrings<'_> = BitsNStrings {
    mybits: [1, 2],
    mystring: STRING,
};
    [lifetime-elision.const-static.fn-references]

    اگر آیتم‌های static یا const شامل ارجاع به تابع یا بستار باشند که خودشان ارجاع دارند، کامپایلر ابتدا قواعد استاندارد حذف را امتحان می‌کند. اگر نتواند طول‌عمرها را با قواعد عادی تفکیک کند، خطا می‌دهد. برای مثال:

    struct Foo;
struct Bar;
struct Baz;
fn somefunc(a: &Foo, b: &Bar, c: &Baz) -> usize {42}
// Resolved as `for<'a> fn(&'a str) -> &'a str`.
const RESOLVED_SINGLE: fn(&str) -> &str = |x| x;

// Resolved as `for<'a, 'b, 'c> Fn(&'a Foo, &'b Bar, &'c Baz) -> usize`.
const RESOLVED_MULTIPLE: &dyn Fn(&Foo, &Bar, &Baz) -> usize = &somefunc;
    struct Foo;
struct Bar;
struct Baz;
fn somefunc<'a,'b>(a: &'a Foo, b: &'b Bar) -> &'a Baz {unimplemented!()}
// There is insufficient information to bound the return reference lifetime
// relative to the argument lifetimes, so this is an error.
const RESOLVED_STATIC: &dyn Fn(&Foo, &Bar) -> &Baz = &somefunc;
//                                            ^
// this function's return type contains a borrowed value, but the signature
// does not say whether it is borrowed from argument 1 or argument 2
