    [cfg]

    کامپایل شرطی

    [cfg.syntax]

    Syntax
    ConfigurationPredicate →
          ConfigurationOption
        | ConfigurationAll
        | ConfigurationAny
        | ConfigurationNot
        | true
        | false

    ConfigurationOption →
        IDENTIFIER ( = ( STRING_LITERAL | RAW_STRING_LITERAL ) )?

    ConfigurationAll →
        all ( ConfigurationPredicateList? )

    ConfigurationAny →
        any ( ConfigurationPredicateList? )

    ConfigurationNot →
        not ( ConfigurationPredicate )

    ConfigurationPredicateList →
        ConfigurationPredicate ( , ConfigurationPredicate )* ,?

    [cfg.intro]

    کد منبع با کامپایل شرطی کد منبعی است که تنها تحت شرایط مشخصی کامپایل می‌شود.

    [cfg.attributes-macro]

    می‌توان با ویژگی‌های cfg و cfg_attr و ماکروهای داخلی cfg! و cfg_select!، کد منبع را به‌صورت شرطی کامپایل کرد.

    [cfg.conditional]

    تصمیم کامپایل می‌تواند به معماری هدف کریت در حال کامپایل، مقادیر دلخواه پاس‌داده‌شده به کامپایلر و موارد دیگری که در ادامه شرح داده می‌شوند وابسته باشد.

    [cfg.predicate]

    هر شکل کامپایل شرطی یک گزارهٔ پیکربندی می‌گیرد که به درست یا نادرست ارزیابی می‌شود. گزاره یکی از موارد زیر است:

    [cfg.predicate-option]
    • یک گزینهٔ پیکربندی. اگر گزینه تنظیم شده باشد، گزاره درست و اگر تنظیم نشده باشد نادرست است.
    [cfg.predicate-all]
    • all() با فهرستی جداشده با ویرگول از گزاره‌های پیکربندی. اگر همهٔ گزاره‌های داده‌شده درست باشند یا فهرست خالی باشد، درست است.
    [cfg.predicate-any]
    • any() با فهرستی جداشده با ویرگول از گزاره‌های پیکربندی. اگر دست‌کم یکی از گزاره‌ها درست باشد، درست است. اگر گزاره‌ای وجود نداشته باشد، نادرست است.
    [cfg.predicate-not]
    • not() با یک گزارهٔ پیکربندی. اگر گزاره‌اش نادرست باشد درست، و اگر گزاره‌اش درست باشد نادرست است.
    [cfg.predicate-literal]
    • لفظ‌های true یا false که به‌ترتیب همیشه درست یا نادرست‌اند.
    [cfg.option-spec]

    گزینه‌های پیکربندی یا نام هستند یا جفت کلیدـمقدار، و هر کدام می‌توانند تنظیم‌شده یا تنظیم‌نشده باشند.

    [cfg.option-name]

    نام‌ها به‌صورت یک شناسهٔ واحد مانند unix نوشته می‌شوند.

    [cfg.option-key-value]

    جفت‌های کلیدـمقدار به‌صورت یک شناسه، = و سپس یک رشته نوشته می‌شوند؛ مانند target_arch = "x86_64".

    Note

    نکته فاصله‌های پیرامون = نادیده گرفته می‌شوند؛ بنابراین foo="bar" و foo = "bar" معادل‌اند.

    [cfg.option-key-uniqueness]

    کلیدها لازم نیست یکتا باشند. برای نمونه، feature = "std" و feature = "serde" می‌توانند هم‌زمان تنظیم شوند.

    [cfg.options.set]

    گزینه‌های پیکربندی تنظیم‌شده

    [cfg.options.intro]

    اینکه کدام گزینه‌های پیکربندی تنظیم شده‌اند، هنگام کامپایل کریت به‌صورت ایستا تعیین می‌شود.

    [cfg.options.target]

    برخی گزینه‌ها بر پایهٔ داده‌های مربوط به کامپایل، به‌وسیلهٔ کامپایلر تنظیم می‌شوند.

    [cfg.options.other]

    گزینه‌های دیگر بر پایهٔ ورودی‌ای که بیرون از کد به کامپایلر پاس داده می‌شود، به‌دلخواه تنظیم می‌شوند.

    [cfg.options.crate]

    نمی‌توان یک گزینهٔ پیکربندی را از درون کد منبع کریت در حال کامپایل تنظیم کرد.

    Note

    نکته در rustc، گزینه‌های پیکربندی دلخواه با پرچم --cfg تنظیم می‌شوند. مقادیر پیکربندی برای یک هدف مشخص را می‌توان با rustc --print cfg --target $TARGET نمایش داد.

    Note

    نکته گزینه‌های پیکربندی با کلید feature قراردادی هستند که Cargo برای مشخص کردن گزینه‌های زمان کامپایل و وابستگی‌های اختیاری به کار می‌برد.

    [cfg.target_family]

    target_family

    [cfg.target_family.def]

    گزینهٔ کلیدـمقداری که توصیفی عمومی‌تر از هدف، مانند خانوادهٔ سیستم‌عامل‌ها یا معماری‌هایی که هدف عموماً در آن قرار می‌گیرد، فراهم می‌کند. هر تعداد جفت کلیدـمقدار target_family قابل تنظیم است.

    [cfg.target_family.values]

    نمونهٔ مقادیر:

    • "unix"
    • "windows"
    • "wasm"
    • هم‌زمان "unix" و "wasm"
    [cfg.target_family.unix]

    unix و windows

    اگر target_family = "unix" تنظیم شده باشد، unix نیز تنظیم می‌شود.

    [cfg.target_family.windows]

    اگر target_family = "windows" تنظیم شده باشد، windows نیز تنظیم می‌شود.

    [cfg.target_env]

    target_env

    [cfg.target_env.def]

    گزینهٔ کلیدـمقداری که با اطلاعات بیشتر دربارهٔ ABI یا libc مورد استفاده، ابهام سکوی هدف را برطرف می‌کند. به دلایل تاریخی، این مقدار تنها زمانی غیر از رشتهٔ خالی تعریف می‌شود که واقعاً برای رفع ابهام لازم باشد. بنابراین برای نمونه، در بسیاری از سکوهای GNU این مقدار خالی است. این مقدار مشابه عنصر چهارم سه‌تایی هدف سکو است. یک تفاوت آن است که ABIهای توکار مانند gnueabihf، مقدار target_env را صرفاً "gnu" تعریف می‌کنند.

    [cfg.target_env.values]

    نمونهٔ مقادیر:

    شکل‌های کامپایل شرطی

    [cfg.attr]

    ویژگی cfg

    [cfg.attr.intro]

    ویژگی cfg شکل متصل به خود را بر پایهٔ یک گزارهٔ پیکربندی به‌صورت شرطی در کد می‌گنجاند.

    مثال

    // The function is only included in the build when compiling for macOS
#[cfg(target_os = "macos")]
fn macos_only() {
  // ...
}

// This function is only included when either foo or bar is defined
#[cfg(any(foo, bar))]
fn needs_foo_or_bar() {
  // ...
}

// This function is only included when compiling for a unixish OS with a 32-bit
// architecture
#[cfg(all(unix, target_pointer_width = "32"))]
fn on_32bit_unix() {
  // ...
}

// This function is only included when foo is not defined
#[cfg(not(foo))]
fn needs_not_foo() {
  // ...
}

// This function is only included when the panic strategy is set to unwind
#[cfg(panic = "unwind")]
fn when_unwinding() {
  // ...
}
    [cfg.attr.syntax]

    نحو ویژگی cfg چنین است:

    Syntax
    CfgAttribute → cfg ( ConfigurationPredicate )

    [cfg.attr.allowed-positions]

    ویژگی cfg در هر جایی که ویژگی‌ها مجاز باشند قابل استفاده است.

    [cfg.attr.duplicates]

    ویژگی cfg را می‌توان هر تعداد بار روی یک شکل به کار برد. اگر هر یک از گزاره‌های cfg نادرست باشد، شکل متصل به ویژگی‌ها در کد گنجانده نمی‌شود، جز آنچه در cfg.attr.crate-level-attrs شرح داده شده است.

    [cfg.attr.effect]

    اگر گزاره‌ها درست باشند، شکل به‌گونه‌ای بازنویسی می‌شود که ویژگی‌های cfg روی آن نباشند. اگر هر گزاره‌ای نادرست باشد، شکل از کد منبع حذف می‌شود.

    [cfg.attr.crate-level-attrs]

    وقتی یک cfg در سطح کریت گزاره‌ای نادرست داشته باشد، خود کریت همچنان وجود دارد. همهٔ ویژگی‌های کریت پیش از cfg نگه داشته می‌شوند و همهٔ ویژگی‌های پس از cfg همراه با تمام محتوای بعدی کریت حذف می‌شوند.

    مثال حذف نشدن ویژگی‌های پیشین اجازه می‌دهد کارهایی مانند افزودن #![no_std] را انجام دهید تا حتی اگر #![cfg(...)] محتوای کریت را حذف کرده است، از پیوند std جلوگیری شود. برای نمونه:

    // This `no_std` attribute is kept even though the crate-level `cfg`
// attribute is false.
#![no_std]
#![cfg(false)]

// This function is not included.
pub fn example() {}
    [cfg.cfg_attr]

    ویژگی cfg_attr

    [cfg.cfg_attr.intro]

    ویژگی cfg_attr بر پایهٔ یک گزارهٔ پیکربندی، ویژگی‌ها را به‌صورت شرطی در کد می‌گنجاند.

    مثال ماژول زیر بسته به هدف در linux.rs یا windows.rs پیدا می‌شود.

    #[cfg_attr(target_os = "linux", path = "linux.rs")]
#[cfg_attr(windows, path = "windows.rs")]
mod os;
    [cfg.cfg_attr.syntax]

    نحو ویژگی cfg_attr چنین است:

    Syntax
    CfgAttrAttribute → cfg_attr ( ConfigurationPredicate , CfgAttrs? )

    CfgAttrs → Attr ( , Attr )* ,?

    [cfg.cfg_attr.allowed-positions]

    ویژگی cfg_attr در هر جایی که ویژگی‌ها مجاز باشند قابل استفاده است.

    [cfg.cfg_attr.duplicates]

    ویژگی cfg_attr را می‌توان هر تعداد بار روی یک شکل به کار برد.

    [cfg.cfg_attr.attr-restriction]

    ویژگی‌های crate_type و crate_name را نمی‌توان همراه cfg_attr به کار برد.

    [cfg.cfg_attr.behavior]

    وقتی گزارهٔ پیکربندی درست باشد، cfg_attr به ویژگی‌های فهرست‌شده پس از گزاره گسترش می‌یابد.

    [cfg.cfg_attr.attribute-list]

    می‌توان صفر، یک یا چند ویژگی فهرست کرد. هر یک از چند ویژگی به یک ویژگی جداگانه گسترش می‌یابد.

    مثال

    #[cfg_attr(feature = "magic", sparkles, crackles)]
fn bewitched() {}

// When the `magic` feature flag is enabled, the above will expand to:
#[sparkles]
#[crackles]
fn bewitched() {}

    Note

    نکته cfg_attr می‌تواند به یک cfg_attr دیگر گسترش یابد. برای نمونه، #[cfg_attr(target_os = "linux", cfg_attr(feature = "multithreaded", some_other_attribute))] معتبر است. این مثال با #[cfg_attr(all(target_os = "linux", feature = "multithreaded"), some_other_attribute)] معادل است.

    [cfg.macro]

    ماکروی cfg

    ماکروی داخلی cfg یک گزارهٔ پیکربندی می‌گیرد و اگر گزاره درست باشد به لفظ true، و اگر نادرست باشد به لفظ false ارزیابی می‌شود.

    برای نمونه:

    let machine_kind = if cfg!(unix) {
  "unix"
} else if cfg!(windows) {
  "windows"
} else {
  "unknown"
};

println!("I'm running on a {} machine!", machine_kind);
    [cfg.cfg_select]

    ماکروی cfg_select

    [cfg.cfg_select.intro]

    از ماکروی داخلی cfg_select! می‌توان برای انتخاب کد در زمان کامپایل بر پایهٔ چند گزارهٔ پیکربندی استفاده کرد.

    مثال

    cfg_select! {
    unix => {
        fn foo() { /* unix specific functionality */ }
    }
    target_pointer_width = "32" => {
        fn foo() { /* non-unix, 32-bit functionality */ }
    }
    _ => {
        fn foo() { /* fallback implementation */ }
    }
}

let is_unix_str = cfg_select! {
    unix => "unix",
    _ => "not unix",
};
    [cfg.cfg_select.syntax]

    Syntax
    CfgSelect → CfgSelectArms?

    CfgSelectArms →
        CfgSelectConfigurationPredicate =>
        (
            { ^ TokenTree } ,? CfgSelectArms?
          | ExpressionWithBlockNoAttrs ,? CfgSelectArms?
          | ExpressionWithoutBlockNoAttrs ( , CfgSelectArms? )?
        )

    CfgSelectConfigurationPredicate →
        ConfigurationPredicate | _

    [cfg.cfg_select.first-arm]

    cfg_select به محتوای نخستین بازویی گسترش می‌یابد که گزارهٔ پیکربندی آن درست ارزیابی شود.

    [cfg.cfg_select.braces]

    اگر تمام محتوا درون آکولاد پیچیده شده باشد، آکولادها هنگام گسترش حذف می‌شوند.

    [cfg.cfg_select.wildcard]

    گزارهٔ پیکربندی _ همیشه درست ارزیابی می‌شود.

    [cfg.cfg_select.fallthrough]

    اگر هیچ‌یک از گزاره‌ها درست ارزیابی نشوند، خطای کامپایل رخ می‌دهد.

    [cfg.cfg_select.well-formed]

    هر سمت راست باید برای جایگاهی که ماکرو در آن فراخوانی شده، گسترشی معتبر از نظر نحوی باشد.
