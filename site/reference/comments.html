    توضیحات (Comments)

    [comments.syntax]

    Lexer
    COMMENT →
          LINE_COMMENT
        | INNER_LINE_DOC
        | OUTER_LINE_DOC
        | INNER_BLOCK_DOC
        | OUTER_BLOCK_DOC
        | BLOCK_COMMENT

    LINE_COMMENT →
          // ( ~[/ ! LF] | // ) ~LF*
        | // EOF
        | //immediately followed by LF

    BLOCK_COMMENT →
        /* ^
          ( BLOCK_COMMENT | BLOCK_CHAR )*
        */

    INNER_LINE_DOC →
        //! ^ LINE_DOC_COMMENT_CONTENT ( LF | EOF )

    LINE_DOC_COMMENT_CONTENT → ( !CR ~LF )*

    INNER_BLOCK_DOC →
        /*! ^ ( NESTED_BLOCK_DOC_COMMENT | DOC_BLOCK_CHAR )* */

    OUTER_LINE_DOC →
        /// ^ LINE_DOC_COMMENT_CONTENT ( LF | EOF )

    OUTER_BLOCK_DOC →
        /** ![* /]
          ^
          ~[* CR]
          ( NESTED_BLOCK_DOC_COMMENT | DOC_BLOCK_CHAR )*
        */

    BLOCK_CHAR → !*/ CHAR

    DOC_BLOCK_CHAR → ( !( */ | CR ) CHAR )

    NESTED_BLOCK_DOC_COMMENT →
        /* ( NESTED_BLOCK_DOC_COMMENT | DOC_BLOCK_CHAR )* */

    [comments.normal]

    توضیحات غیرمستند

    [comments.normal.intro]

    توضیحات از سبک عمومی C++ برای شکل خطی (//) و بلوکی (/* ... */) پیروی می‌کنند. توضیحات بلوکی تودرتو نیز پشتیبانی می‌شوند.

    [comments.normal.tokenization]

    توضیحات غیرمستند به‌عنوان شکلی از فضای خالی تفسیر می‌شوند.

    [comments.doc]

    توضیحات مستند

    [comments.doc.syntax]

    توضیحات مستند خطی که دقیقاً با سه ممیز (///) آغاز می‌شوند و توضیحات مستند بلوکی (/** ... */) ــ که هر دو توضیح مستند بیرونی‌اند ــ به‌عنوان نحوی ویژه برای ویژگی‌های doc تفسیر می‌شوند.

    [comments.doc.attributes]

    به بیان دیگر، این توضیحات معادل نوشتن #[doc="..."] پیرامون بدنهٔ توضیح‌اند؛ یعنی /// Foo به #[doc=" Foo"] و /** Bar */ به #[doc=" Bar "] تبدیل می‌شود. بنابراین باید پیش از چیزی قرار گیرند که یک ویژگی بیرونی را می‌پذیرد.

    [comments.doc.inner-syntax]

    توضیحات خطی که با //! آغاز می‌شوند و توضیحات بلوکی /*! ... */، توضیحات مستندی هستند که به والدِ توضیح اعمال می‌شوند، نه به آیتم پس از آن.

    [comments.doc.inner-attributes]

    به بیان دیگر، این توضیحات معادل نوشتن #![doc="..."] پیرامون بدنهٔ توضیح‌اند. توضیحات //! معمولاً برای مستندسازی ماژول‌هایی به کار می‌روند که یک فایل منبع را اشغال می‌کنند.

    [comments.doc.bare-crs]

    نویسهٔ U+000D (CR) در توضیحات مستند مجاز نیست.

    Note

    نکته طبق عرف، توضیحات مستند شامل Markdown مورد انتظار rustdoc هستند. بااین‌حال، نحو توضیح هیچ Markdown درونی را در نظر نمی‌گیرد. در /** `glob = "*/*.rs";` */ توضیح در نخستین */ پایان می‌یابد و کد باقی‌مانده خطای نحوی ایجاد می‌کند. به همین دلیل، محتوای توضیحات مستند بلوکی در مقایسه با توضیحات مستند خطی اندکی محدودتر است.

    Note

    نکته دنبالهٔ U+000D (CR) که بلافاصله U+000A (LF) پس از آن آمده باشد، پیش‌تر به یک U+000A (LF) تبدیل شده است.

    نمونه‌ها

    //! A doc comment that applies to the implicit anonymous module of this crate

pub mod outer_module {

    //!  - Inner line doc
    //!! - Still an inner line doc (but with a bang at the beginning)

    /*!  - Inner block doc */
    /*!! - Still an inner block doc (but with a bang at the beginning) */

    //   - Only a comment
    ///  - Outer line doc (exactly 3 slashes)
    //// - Only a comment

    /*   - Only a comment */
    /**  - Outer block doc (exactly) 2 asterisks */
    /*** - Only a comment */

    pub mod inner_module {}

    pub mod nested_comments {
        /* In Rust /* we can /* nest comments */ */ */

        // All three types of block comments can contain or be nested inside
        // any other type:

        /*   /* */  /** */  /*! */  */
        /*!  /* */  /** */  /*! */  */
        /**  /* */  /** */  /*! */  */
        pub mod dummy_item {}
    }

    pub mod degenerate_cases {
        // empty inner line doc
        //!

        // empty inner block doc
        /*!*/

        // empty line comment
        //

        // empty outer line doc
        ///

        // empty block comment
        /**/

        pub mod dummy_item {}

        // empty 2-asterisk block isn't a doc block, it is a block comment
        /***/

    }

    /* The next one isn't allowed because outer doc comments
       require an item that will receive the doc */

    /// Where is my item?
  mod boo {}
}
