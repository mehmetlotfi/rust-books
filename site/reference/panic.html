    [panic]

    Panic

    [panic.intro]

    Rust سازوکاری فراهم می‌کند که مانع بازگشت عادی یک تابع می‌شود و در عوض آن را دچار «panic» می‌کند. panic واکنشی به یک وضعیت خطاست که معمولاً انتظار نمی‌رود در همان بافتی که رخ داده، بازیابی‌پذیر باشد.

    [panic.lang-ops]

    برخی سازه‌های زبان، مانند اندیس‌گذاری آرایه خارج از محدوده، به‌طور خودکار panic می‌کنند.

    [panic.control]

    امکاناتی در زبان نیز وجود دارند که سطحی از کنترل بر رفتار panic فراهم می‌کنند:

    • یک مدیریت‌کنندهٔ panic رفتار panic را تعریف می‌کند.
    • ABIهای FFI ممکن است رفتار panic را تغییر دهند.

    Note

    نکته کتابخانهٔ استاندارد امکان ایجاد صریح panic را از طریق ماکروی panic! فراهم می‌کند.

    [panic.panic_handler]

    ویژگی panic_handler

    [panic.panic_handler.intro]

    ویژگی panic_handler را می‌توان روی یک تابع اعمال کرد تا رفتار panicها را تعریف کند.

    [panic.panic_handler.allowed-positions]

    ویژگی panic_handler تنها می‌تواند روی تابعی با امضای fn(&PanicInfo) -> ! اعمال شود.

    Note

    نکته ساختار PanicInfo اطلاعاتی دربارهٔ محل panic در خود دارد.

    [panic.panic_handler.unique]

    در نمودار وابستگی باید دقیقاً یک تابع panic_handler وجود داشته باشد.

    در ادامه تابعی از نوع panic_handler نشان داده شده است که پیام panic را ثبت می‌کند و سپس نخ را متوقف نگه می‌دارد.

    #![no_std]

use core::fmt::{self, Write};
use core::panic::PanicInfo;

struct Sink {
    // ..
   _0: (),
}

impl Sink {
    fn new() -> Sink { Sink { _0: () }}
}

impl fmt::Write for Sink {
    fn write_str(&mut self, _: &str) -> fmt::Result { Ok(()) }
}

#[panic_handler]
fn panic(info: &PanicInfo) -> ! {
    let mut sink = Sink::new();

    // logs "panicked at '$reason', src/main.rs:27:4" to some `sink`
    let _ = writeln!(sink, "{}", info);

    loop {}
}
    [panic.panic_handler.std]

    رفتار استاندارد

    [panic.panic_handler.std.kinds]

    std دو مدیریت‌کنندهٔ panic متفاوت فراهم می‌کند:

    • unwind — پشته را باز می‌کند و بالقوه بازیابی‌پذیر است.
    • abort — فرایند را خاتمه می‌دهد و بازیابی‌پذیر نیست.

    ممکن است همهٔ هدف‌ها مدیریت‌کنندهٔ unwind را فراهم نکنند.

    Note

    نکته مدیریت‌کنندهٔ panic مورد استفاده هنگام پیوند با std را می‌توان با پرچم خط فرمان -C panic تعیین کرد. مقدار پیش‌فرض برای بیشتر هدف‌ها unwind است.

    رفتار panic کتابخانهٔ استاندارد را می‌توان در زمان اجرا با تابع std::panic::set_hook تغییر داد.

    [panic.panic_handler.std.no_std]

    پیوند یک فایل اجرایی، dylib، ‏cdylib یا staticlib از نوع no_std مستلزم مشخص‌کردن مدیریت‌کنندهٔ panic خودتان است.

    [panic.strategy]

    راهبرد panic

    [panic.strategy.intro]

    راهبرد panic نوع رفتار panic را تعریف می‌کند که یک crate برای پشتیبانی از آن ساخته شده است.

    Note

    نکته راهبرد panic را می‌توان در rustc با پرچم خط فرمان -C panic انتخاب کرد.

    هنگام تولید فایل اجرایی، dylib، ‏cdylib یا staticlib و پیوند با std، پرچم خط فرمان -C panic بر انتخاب مدیریت‌کنندهٔ panic نیز اثر می‌گذارد.

    Note

    نکته هنگام کامپایل کد با راهبرد panic از نوع abort، بهینه‌ساز می‌تواند فرض کند بازکردن پشته از میان قاب‌های Rust ناممکن است؛ این فرض می‌تواند هم اندازهٔ کد را کاهش دهد و هم سرعت زمان اجرا را بهبود بخشد.

    Note

    نکته برای محدودیت‌های پیوند crateهایی با راهبردهای panic متفاوت، link.unwinding را ببینید. یکی از نتایج این است که crateهای ساخته‌شده با راهبرد unwind می‌توانند از مدیریت‌کنندهٔ panic نوع abort استفاده کنند، اما راهبرد abort نمی‌تواند مدیریت‌کنندهٔ unwind را به‌کار ببرد.

    [panic.unwind]

    بازگشایی پشته (Unwinding)

    [panic.unwind.intro]

    یک panic ممکن است بازیابی‌پذیر یا بازیابی‌ناپذیر باشد، هرچند می‌توان آن را با انتخاب مدیریت‌کننده‌ای که پشته را باز نمی‌کند طوری پیکربندی کرد که همیشه بازیابی‌ناپذیر باشد. عکس این گزاره درست نیست: مدیریت‌کنندهٔ unwind تضمین نمی‌کند همهٔ panicها بازیابی‌پذیر باشند؛ تنها تضمین می‌کند panic ایجادشده از طریق ماکروی panic! و سازوکارهای مشابه کتابخانهٔ استاندارد بازیابی‌پذیر است.

    [panic.unwind.destruction]

    هنگام وقوع panic، مدیریت‌کنندهٔ unwind قاب‌های Rust را «باز می‌کند»، همان‌گونه که throw در C++ قاب‌های C++ را باز می‌کند، تا panic به نقطهٔ بازیابی برسد (برای نمونه، مرز یک نخ). یعنی هنگامی که panic از قاب‌های Rust عبور می‌کند، متد drop اشیای زندهٔ آن قاب‌ها که Drop را پیاده‌سازی می‌کنند فراخوانی می‌شود. بنابراین وقتی اجرای عادی از سر گرفته شود، اشیایی که دیگر دسترس‌پذیر نیستند درست مانند زمانی که به‌طور عادی از حوزه خارج می‌شوند «پاک‌سازی» شده‌اند.

    Note

    نکته تا زمانی که تضمین پاک‌سازی منابع حفظ شود، ممکن است «بازکردن پشته» بدون استفادهٔ واقعی از سازوکار C++ در سکوی هدف پیاده‌سازی شود.

    Note

    نکته کتابخانهٔ استاندارد دو سازوکار برای بازیابی از panic فراهم می‌کند: std::panic::catch_unwind که بازیابی را درون همان نخ دچار panic ممکن می‌کند، و std::thread::spawn که بازیابی از panic را به‌طور خودکار برای نخ ساخته‌شده تنظیم می‌کند تا نخ‌های دیگر بتوانند به اجرا ادامه دهند.

    [panic.unwind.ffi]

    بازکردن پشته از مرزهای FFI

    [panic.unwind.ffi.intro]

    با یک اعلان ABI مناسب می‌توان پشته را از مرزهای FFI باز کرد. این قابلیت با اینکه در برخی موارد سودمند است، فرصت‌های ویژه‌ای برای رفتار تعریف‌نشده ایجاد می‌کند، به‌ویژه زمانی که چند محیط زمان اجرای زبان درگیر باشند.

    [panic.unwind.ffi.undefined]

    بازکردن پشته با ABI نادرست، رفتار تعریف‌نشده است:

    • ایجاد بازشدن پشته به‌سمت کد Rust از یک تابع خارجی که از طریق اعلان تابع یا اشاره‌گری با ABI بدون پشتیبانی از unwind، مانند "C" یا "system"، فراخوانی شده است. برای نمونه، این حالت وقتی رخ می‌دهد که چنین تابعی به زبان C++ استثنایی پرتاب کند که گرفته نشود و به Rust گسترش یابد.
    • فراخوانی یک تابع extern در Rust که پشته را باز می‌کند (با extern "C-unwind" یا ABI دیگری که unwind را مجاز می‌کند) از کدی که از بازکردن پشته پشتیبانی نمی‌کند؛ مانند کدی که با GCC یا Clang و گزینهٔ -fno-exceptions کامپایل شده باشد.
    [panic.unwind.ffi.catch-foreign]

    گرفتن یک عملیات بازکردن پشتهٔ خارجی (مانند استثنای C++) با std::panic::catch_unwind، ‏std::thread::JoinHandle::join، یا اجازه‌دادن به گسترش آن فراتر از تابع main() یا ریشهٔ نخ Rust، یکی از دو رفتار زیر را خواهد داشت و مشخص نشده کدام‌یک رخ می‌دهد:

    • فرایند خاتمه می‌یابد.
    • تابع یک Result::Err حاوی نوعی کدر برمی‌گرداند.

    Note

    نکته برای این تضمین، کد Rust که با نمونهٔ دیگری از کتابخانهٔ استاندارد Rust کامپایل یا پیوند شده باشد «استثنای خارجی» به‌شمار می‌رود. بنابراین کتابخانه‌ای که از panic! استفاده می‌کند و با یک نسخه از کتابخانهٔ استاندارد Rust پیوند خورده، اگر از برنامه‌ای با نسخه‌ای دیگر از کتابخانهٔ استاندارد فراخوانی شود، ممکن است کل برنامه را خاتمه دهد؛ حتی اگر کتابخانه فقط درون یک نخ فرزند استفاده شود.

    [panic.unwind.ffi.dispose-panic]

    در حال حاضر هیچ تضمینی دربارهٔ رفتاری وجود ندارد که هنگام تلاش یک محیط زمان اجرای خارجی برای دورریختن یا پرتاب دوبارهٔ payload یک panic در Rust رخ می‌دهد. به‌عبارت دیگر، بازکردن پشته‌ای که از محیط زمان اجرای Rust آغاز شده است باید یا به خاتمهٔ فرایند منجر شود یا توسط همان محیط زمان اجرا گرفته شود.
