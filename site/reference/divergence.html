    [divergence]

    واگرایی (Divergence)

    [divergence.intro]

    یک عبارت واگرا عبارتی است که اجرای عادی آن هرگز کامل نمی‌شود.

    fn diverges() -> ! {
    panic!("This function never returns!");
}

fn example() {
    let x: i32 = diverges(); // This line never completes.
    println!("This is never printed: {x}");
}

    برای رفتار واگرایی هر نوع عبارت، قواعد زیر را ببینید:

    • expr.block.diverging — عبارت‌های بلوکی.
    • expr.if.diverging — عبارت‌های if.
    • expr.loop.block-labels.type — عبارت‌های بلوکی برچسب‌دار دارای break.
    • expr.loop.break-value.diverging — عبارت‌های loop همراه با break.
    • expr.loop.break.diverging — عبارت‌های break.
    • expr.loop.continue.diverging — عبارت‌های continue.
    • expr.loop.infinite.diverging — عبارت‌های loop بی‌نهایت.
    • expr.match.diverging — عبارت‌های match.
    • expr.match.empty — عبارت‌های match خالی.
    • expr.return.diverging — عبارت‌های return.

    Note

    نکته ماکروی panic! و ماکروهای مرتبطی که باعث panic می‌شوند، مانند unreachable!، نیز نوع ! دارند و واگرا هستند.

    [divergence.never]

    هر عبارت با نوع ! یک عبارت واگراست. بااین‌حال، عبارت‌های واگرا به نوع ! محدود نیستند؛ عبارت‌هایی از نوع‌های دیگر نیز ممکن است واگرا باشند (برای مثال Some(loop {}) نوع Option<!> دارد).

    Note

    نکته هرچند ! نوعی بدون ساکن در نظر گرفته می‌شود، صرفِ بدون ساکن بودن یک نوع برای واگرا بودن آن کافی نیست.

    enum Empty {}
fn make_never() -> ! {loop{}}
fn make_empty() -> Empty {loop{}}

fn diverging() -> ! {
    // This has a type of `!`.
    // So, the entire function is considered diverging.
    make_never();
    // OK: The type of the body is `!` which matches the return type.
}
fn not_diverging() -> ! {
    // This type is uninhabited.
    // However, the entire function is not considered diverging.
    make_empty();
    // ERROR: The type of the body is `()` but expected type `!`.
}

    Note

    نکته واگرایی می‌تواند به بلوک پیرامون گسترش یابد. expr.block.diverging را ببینید.

    [divergence.fallback]

    بازگشت به حالت پیش‌فرض (Fallback)

    اگر نوعی که باید استنتاج شود تنها با عبارت‌های واگرا یک‌پارچه شود، آن نوع ! استنتاج خواهد شد.

    مثال

    fn foo() -> i32 { 22 }
match foo() {
    // ERROR: The trait bound `!: Default` is not satisfied.
    4 => Default::default(),
    _ => return,
};

    Note

    نکته نکتهٔ مهم اینکه یک‌پارچه‌سازی نوع ممکن است به‌صورت ساختاری رخ دهد؛ بنابراین نوع جایگزین ! می‌تواند بخشی از نوعی بزرگ‌تر باشد. کد زیر کامپایل می‌شود:

    fn foo() -> i32 { 22 }
// This has the type `Option<!>`, not `!`
match foo() {
    4 => Default::default(),
    _ => Some(return),
};
