    کران‌های صفت و طول‌عمر

    [bound.intro]

    کران‌های صفت و طول‌عمر راهی برای محدودکردن نوع‌ها و طول‌عمرهایی هستند که آیتم‌های عمومی به‌عنوان پارامتر می‌پذیرند. کران را می‌توان برای هر نوعی در یک بند where نوشت. چند شکل کوتاه برای موارد رایج نیز وجود دارد:

    • کران پس از اعلان پارامتر عمومی: ‏fn f<A: Copy>() {} همان fn f<A>() where A: Copy {} است.
    • در اعلان صفت به‌عنوان فراصفت: ‏trait Circle : Shape {} معادل trait Circle where Self : Shape {} است.
    • در اعلان صفت به‌عنوان کران نوع‌های وابسته: ‏trait A { type B: Copy; } معادل trait A where Self::B: Copy { type B; } است.
    [bound.satisfaction]

    کران‌های یک آیتم باید هنگام استفاده از آیتم برآورده شوند. در بررسی نوع و قرض یک آیتم عمومی، کران‌ها برای تشخیص پیاده‌سازی صفت برای نوع استفاده می‌شوند. برای نمونه با داشتن Ty: Trait:

    • در بدنهٔ یک تابع عمومی، می‌توان متدهای Trait را روی مقدارهایی از نوع Ty فراخوانی کرد. به همین ترتیب می‌توان از ثابت‌های وابستهٔ Trait نیز استفاده کرد.
    • می‌توان از نوع‌های وابستهٔ Trait استفاده کرد.
    • تابع‌ها و نوع‌های عمومی دارای کران T: Trait را می‌توان با قراردادن Ty به‌جای T به‌کار برد.
    type Surface = i32;
trait Shape {
    fn draw(&self, surface: Surface);
    fn name() -> &'static str;
}

fn draw_twice<T: Shape>(surface: Surface, sh: T) {
    sh.draw(surface);           // Can call method because T: Shape
    sh.draw(surface);
}

fn copy_and_draw_twice<T: Copy>(surface: Surface, sh: T) where T: Shape {
    let shape_copy = sh;        // doesn't move sh because T: Copy
    draw_twice(surface, sh);    // Can use generic function because T: Shape
}

struct Figure<S: Shape>(S, S);

fn name_figure<U: Shape>(
    figure: Figure<U>,          // Type Figure<U> is well-formed because U: Shape
) {
    println!(
        "Figure of two {}",
        U::name(),              // Can use associated function
    );
}
    [bound.trivial]

    کران‌هایی که از پارامترهای آیتم یا طول‌عمرهای رتبه‌بالاتر استفاده نمی‌کنند، هنگام تعریف آیتم بررسی می‌شوند. نادرست‌بودن چنین کرانی خطاست.

    [bound.special]

    کران‌های Copy، ‏Clone و Sized برای بعضی نوع‌های عمومی هنگام استفاده از آیتم نیز بررسی می‌شوند، حتی اگر استفاده نوع عینی ارائه نکند. قراردادن Copy یا Clone به‌عنوان کران ارجاع تغییرپذیر، شیء صفت یا برش خطاست. قراردادن Sized به‌عنوان کران شیء صفت یا برش نیز خطاست.

    struct A<'a, T>
where
    i32: Default,           // Allowed, but not useful
    i32: Iterator,          // Error: `i32` is not an iterator
    &'a mut T: Copy,        // (at use) Error: the trait bound is not satisfied
    [T]: Sized,             // (at use) Error: size cannot be known at compilation
{
    f: &'a T,
}
struct UsesA<'a, T>(A<'a, T>);
    [bound.trait-object]

    کران‌های صفت و طول‌عمر برای نامیدن شیءهای صفت نیز استفاده می‌شوند.

    [bound.sized]

    ?Sized

    ? تنها برای آسان‌کردن کران ضمنی صفت Sized روی پارامترهای نوع یا نوع‌های وابسته استفاده می‌شود. ?Sized نمی‌تواند کران نوع‌های دیگر باشد.

    [bound.lifetime]

    کران‌های طول‌عمر

    [bound.lifetime.intro]

    کران طول‌عمر را می‌توان روی نوع‌ها یا طول‌عمرهای دیگر اعمال کرد.

    [bound.lifetime.outlive-lifetime]

    کران 'a: 'b معمولاً به‌صورت «'a از 'b بیشتر عمر می‌کند» (outlives) خوانده می‌شود. 'a: 'b یعنی 'a دست‌کم به‌اندازهٔ 'b دوام دارد، بنابراین ارجاع &'a () هرگاه &'b () معتبر باشد معتبر است.

    fn f<'a, 'b>(x: &'a i32, mut y: &'b i32) where 'a: 'b {
    y = x;                      // &'a i32 is a subtype of &'b i32 because 'a: 'b
    let r: &'b &'a i32 = &&0;   // &'b &'a i32 is well formed because 'a: 'b
}
    [bound.lifetime.outlive-type]

    T: 'a یعنی همهٔ پارامترهای طول‌عمر T از 'a بیشتر عمر می‌کنند. برای مثال، اگر 'a پارامتر طول‌عمر بدون قید باشد، i32: 'static و &'static str: 'a برقرارند، اما Vec<&'a ()>: 'static برقرار نیست.

    [bound.higher-ranked]

    کران‌های صفت رتبه‌بالاتر

    [bound.higher-ranked.syntax]

    Syntax
    ForLifetimes → for GenericParams

    [bound.higher-ranked.intro]

    کران‌های صفت می‌توانند نسبت به طول‌عمرها رتبه‌بالاتر باشند. این کران‌ها شرطی را مشخص می‌کنند که برای همهٔ طول‌عمرها برقرار است. برای مثال، کران for<'a> &'a T: PartialEq<i32> به پیاده‌سازی‌ای مانند زیر نیاز دارد:

    struct T;
impl<'a> PartialEq<i32> for &'a T {
    // ...
   fn eq(&self, other: &i32) -> bool {true}
}

    سپس می‌توان &'a T با هر طول‌عمری را با i32 مقایسه کرد.

    اینجا فقط کران رتبه‌بالاتر قابل استفاده است، زیرا طول‌عمر ارجاع از هر پارامتر طول‌عمر ممکن روی تابع کوتاه‌تر است:

    fn call_on_ref_zero<F>(f: F) where for<'a> F: Fn(&'a i32) {
    let zero = 0;
    f(&zero);
}
    [bound.higher-ranked.trait]

    طول‌عمر رتبه‌بالاتر را می‌توان درست پیش از صفت نیز نوشت. تنها تفاوت حوزهٔ پارامتر طول‌عمر است که به‌جای کل کران، فقط تا پایان صفت بعدی ادامه دارد. تابع زیر معادل مورد پیشین است:

    fn call_on_ref_zero<F>(f: F) where F: for<'a> Fn(&'a i32) {
    let zero = 0;
    f(&zero);
}
    [bound.implied]

    کران‌های ضمنی

    [bound.implied.intro]

    کران‌های طول‌عمر لازم برای خوش‌ساخت‌بودن نوع‌ها گاهی استنتاج می‌شوند.

    fn requires_t_outlives_a<'a, T>(x: &'a T) {}

    برای خوش‌ساخت‌بودن نوع &'a T، پارامتر نوع T باید از 'a بیشتر عمر کند. چون امضای تابع شامل &'a T است که فقط با برقراری T: 'a معتبر است، این شرط استنتاج می‌شود.

    [bound.implied.context]

    کران‌های ضمنی برای همهٔ پارامترها و خروجی‌های تابع افزوده می‌شوند. درون requires_t_outlives_a حتی بدون نوشتن صریح می‌توانید برقراری T: 'a را فرض کنید:

    fn requires_t_outlives_a_not_implied<'a, T: 'a>() {}

fn requires_t_outlives_a<'a, T>(x: &'a T) {
    // This compiles, because `T: 'a` is implied by
    // the reference type `&'a T`.
    requires_t_outlives_a_not_implied::<'a, T>();
}
    fn requires_t_outlives_a_not_implied<'a, T: 'a>() {}
fn not_implied<'a, T>() {
    // This errors, because `T: 'a` is not implied by
    // the function signature.
    requires_t_outlives_a_not_implied::<'a, T>();
}
    [bound.implied.trait]

    فقط کران‌های طول‌عمر ضمنی‌اند؛ کران‌های صفت همچنان باید صریحاً افزوده شوند. بنابراین مثال زیر خطا ایجاد می‌کند:

    use std::fmt::Debug;
struct IsDebug<T: Debug>(T);
// error[E0277]: `T` doesn't implement `Debug`
fn doesnt_specify_t_debug<T>(x: IsDebug<T>) {}
    [bound.implied.def]

    کران‌های طول‌عمر برای تعریف نوع‌ها و بلوک‌های impl هر نوعی نیز استنتاج می‌شوند:

    struct Struct<'a, T> {
    // This requires `T: 'a` to be well-formed
    // which is inferred by the compiler.
    field: &'a T,
}

enum Enum<'a, T> {
    // This requires `T: 'a` to be well-formed,
    // which is inferred by the compiler.
    //
    // Note that `T: 'a` is required even when only
    // using `Enum::OtherVariant`.
    SomeVariant(&'a T),
    OtherVariant,
}

trait Trait<'a, T: 'a> {}

// This would error because `T: 'a` is not implied by any type
// in the impl header.
//     impl<'a, T> Trait<'a, T> for () {}

// This compiles as `T: 'a` is implied by the self type `&'a T`.
impl<'a, T> Trait<'a, T> for &'a T {}
    [bound.use]

    کران‌های Use

    بعضی فهرست‌های کران می‌توانند کران use<..> داشته باشند تا مشخص شود نوع بازگشت انتزاعی از نوع impl Trait کدام پارامترهای عمومی را تسخیر کند. برای جزئیات تسخیر دقیق را ببینید.
