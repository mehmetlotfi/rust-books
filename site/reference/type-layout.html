    [layout]

    چیدمان نوع‌ها

    [layout.intro]

    چیدمان یک نوع شامل اندازه، هم‌ترازی و آفست نسبی فیلدهای آن است. برای برشمردنی‌ها، شیوهٔ چیدمان و تفسیر ممیز نیز بخشی از چیدمان نوع به شمار می‌آید.

    [layout.guarantees]

    چیدمان نوع ممکن است در هر بار کامپایل تغییر کند. به‌جای مستندسازی دقیق کاری که در حال حاضر انجام می‌شود، تنها تضمین‌های امروزی را مستند می‌کنیم.

    توجه کنید حتی نوع‌هایی با چیدمان یکسان نیز ممکن است هنگام عبور از مرز تابع‌ها متفاوت منتقل شوند. برای سازگاری ABI نوع‌ها در فراخوانی تابع، اینجا را ببینید.

    [layout.properties]

    اندازه و هم‌ترازی

    [layout.properties.intro]

    همهٔ مقدارها دارای هم‌ترازی و اندازه هستند.

    [layout.properties.align]

    هم‌ترازی یک مقدار مشخص می‌کند ذخیره‌کردن آن در چه آدرس‌هایی معتبر است. مقداری با هم‌ترازی n تنها باید در آدرسی ذخیره شود که مضربی از n باشد. برای نمونه، مقدار دارای هم‌ترازی ۲ باید در آدرسی زوج ذخیره شود، در حالی که مقدار دارای هم‌ترازی ۱ را می‌توان در هر آدرسی ذخیره کرد. هم‌ترازی با بایت سنجیده می‌شود، دست‌کم ۱ است و همیشه توانی از ۲ خواهد بود. هم‌ترازی یک مقدار را می‌توان با تابع align_of_val بررسی کرد.

    [layout.properties.size]

    اندازهٔ یک مقدار، فاصلهٔ بایتی میان دو عنصر پیاپی در آرایه‌ای از همان نوع عنصر است و فضای پرکنندهٔ هم‌ترازی را نیز در بر می‌گیرد. اندازهٔ مقدار همیشه مضربی از هم‌ترازی آن است. توجه کنید برخی نوع‌ها اندازهٔ صفر دارند؛ صفر مضربی از هر هم‌ترازی در نظر گرفته می‌شود (برای نمونه در بعضی سکوها، نوع [u16; 0] اندازهٔ ۰ و هم‌ترازی ۲ دارد). اندازهٔ یک مقدار را می‌توان با تابع size_of_val بررسی کرد.

    [layout.properties.sized]

    نوع‌هایی که تمام مقدارهایشان اندازه و هم‌ترازی یکسان و معلوم در زمان کامپایل دارند، صفت Sized را پیاده‌سازی می‌کنند و می‌توان آن‌ها را با تابع‌های size_of و align_of بررسی کرد. نوع‌هایی که Sized نیستند، نوع‌های با اندازهٔ پویا نامیده می‌شوند. چون همهٔ مقدارهای یک نوع Sized اندازه و هم‌ترازی مشترکی دارند، این دو مقدار مشترک را به‌ترتیب اندازهٔ نوع و هم‌ترازی نوع می‌نامیم.

    [layout.primitive]

    چیدمان داده‌های ابتدایی

    [layout.primitive.size]

    اندازهٔ بیشتر نوع‌های ابتدایی در جدول زیر آمده است.

    [layout.primitive.size-minimum]

    اندازهٔ usize و isize به‌اندازه‌ای است که هر آدرسی را در سکوی مقصد در خود جای دهد. برای نمونه، این اندازه در مقصد ۳۲ بیتی ۴ بایت و در مقصد ۶۴ بیتی ۸ بایت است.

    [layout.primitive.size-align]

    usize و isize اندازه و هم‌ترازی یکسانی دارند.

    [layout.primitive.platform-specific-alignment]

    هم‌ترازی نوع‌های ابتدایی به سکو وابسته است. در بیشتر موارد هم‌ترازی آن‌ها با اندازه‌شان برابر است، اما ممکن است کمتر باشد. به‌طور خاص، i128 و u128 با وجود اندازهٔ ۱۶ بایتی، اغلب روی ۴ یا ۸ بایت هم‌تراز می‌شوند؛ و در بسیاری از سکوهای ۳۲ بیتی، i64، u64 و f64 تنها روی ۴ بایت هم‌ترازند، نه ۸ بایت.

    [layout.primitive.integer-alignment]

    تضمین می‌شود هم‌ترازی گونه‌های صحیح علامت‌دار و بدون علامتِ با پهنای ثابت و اندازهٔ یکسان برابر باشد؛ یعنی برای اندازهٔ معین N، رابطهٔ align_of::<uN>() == align_of::<iN>() برقرار است.

    [layout.pointer]

    چیدمان اشاره‌گرها و ارجاع‌ها

    [layout.pointer.intro]

    اشاره‌گرها و ارجاع‌ها چیدمان یکسانی دارند. تغییرپذیری اشاره‌گر یا ارجاع، چیدمان را تغییر نمی‌دهد.

    [layout.pointer.thin]

    اشاره‌گرهای نوع‌های اندازه‌دار، اندازه و هم‌ترازی یکسانی با usize دارند.

    [layout.pointer.unsized]

    اشاره‌گرهای نوع‌های بدون اندازه، خود اندازه‌دارند. تضمین می‌شود اندازه و هم‌ترازی اشاره‌گر به یک نوع بدون اندازه، هر کدام بزرگ‌تر یا مساوی اندازه و هم‌ترازی اشاره‌گر به یک نوع اندازه‌دار باشند.

    Note

    نکته هرچند نباید به این موضوع تکیه کنید، در حال حاضر همهٔ اشاره‌گرهای DST دو برابر usize اندازه دارند و هم‌ترازی‌شان با آن یکسان است.

    [layout.array]

    چیدمان آرایه

    یک آرایه از [T; N] اندازه‌ای برابر size_of::<T>() * N و هم‌ترازی یکسان با T دارد. آرایه‌ها طوری چیده می‌شوند که فاصلهٔ عنصر nth آرایه (با شماره‌گذاری از صفر) از ابتدای آرایه برابر n * size_of::<T>() بایت باشد.

    [layout.slice]

    چیدمان برش

    برش‌ها همان چیدمان بخشی از آرایه را دارند که برش می‌دهند.

    Note

    نکته این مطلب دربارهٔ نوع خام [T] است، نه اشاره‌گرهای برش مانند &[T] و Box<[T]>.

    [layout.str]

    چیدمان str

    برش‌های رشته‌ای، نمایش UTF-8 نویسه‌ها هستند و چیدمانی یکسان با برش‌های نوع [u8] دارند. ارجاع &str نیز همان چیدمان ارجاع &[u8] را دارد.

    [layout.tuple]

    چیدمان چندتایی

    [layout.tuple.def]

    چندتایی‌ها مطابق نمایش Rust چیده می‌شوند.

    [layout.tuple.unit]

    استثنا، چندتایی واحد (()) است که تضمین می‌شود به‌عنوان یک نوع با اندازهٔ صفر، اندازهٔ ۰ و هم‌ترازی ۱ داشته باشد.

    [layout.trait-object]

    چیدمان شیء صفت

    اشیای صفت همان چیدمان مقداری را دارند که شیء صفت از آن ساخته شده است.

    Note

    نکته این مطلب دربارهٔ نوع خام شیء صفت است، نه اشاره‌گرهای آن مانند &dyn Trait و Box<dyn Trait>.

    [layout.closure]

    چیدمان بستار

    چیدمان بستارها هیچ تضمینی ندارد.

    [layout.repr]

    نمایش‌ها (Representations)

    [layout.repr.intro]

    همهٔ نوع‌های مرکب تعریف‌شده به‌دست کاربر (struct، enum و union) دارای یک نمایش هستند که چیدمان نوع را مشخص می‌کند.

    [layout.repr.kinds]

    نمایش‌های ممکن برای یک نوع عبارت‌اند از:

    • Rust (پیش‌فرض)
    • C
    • نمایش‌های ابتدایی
    • transparent
    [layout.repr.attribute]

    نمایش نوع را می‌توان با اعمال ویژگی repr تغییر داد. نمونهٔ زیر ساختاری با نمایش C را نشان می‌دهد.

    #[repr(C)]
struct ThreeInts {
    first: i16,
    second: i8,
    third: i32
}
    [layout.repr.align-packed]

    هم‌ترازی را می‌توان به‌ترتیب با اصلاح‌گرهای align و packed افزایش یا کاهش داد. این اصلاح‌گرها نمایش مشخص‌شده در ویژگی را تغییر می‌دهند. اگر نمایشی مشخص نشده باشد، نمایش پیش‌فرض تغییر می‌کند.

    // Default representation, alignment lowered to 2.
#[repr(packed(2))]
struct PackedStruct {
    first: i16,
    second: i8,
    third: i32
}

// C representation, alignment raised to 8
#[repr(C, align(8))]
struct AlignedStruct {
    first: i16,
    second: i8,
    third: i32
}

    Note

    نکته چون نمایش یک ویژگی روی آیتم است، به پارامترهای عام وابسته نیست. هر دو نوع با نام یکسان، نمایش یکسانی دارند. برای نمونه، Foo<Bar> و Foo<Baz> هر دو نمایش یکسانی دارند.

    [layout.repr.inter-field]

    نمایش یک نوع می‌تواند فضای پرکنندهٔ میان فیلدها را تغییر دهد، اما چیدمان خود فیلدها را تغییر نمی‌دهد. برای نمونه، ساختاری با نمایش C که ساختار Inner با نمایش Rust را در خود دارد، چیدمان Inner را تغییر نمی‌دهد.

    [layout.repr.rust]

    نمایش Rust

    [layout.repr.rust.intro]

    نمایش Rust، نمایش پیش‌فرض نوع‌های نام‌دارِ بدون ویژگی repr است. تضمین می‌شود استفادهٔ صریح از این نمایش از راه ویژگی repr، دقیقاً مانند حذف کامل آن ویژگی باشد.

    [layout.repr.rust.layout]

    تنها تضمین‌های چیدمان داده در این نمایش، موارد لازم برای درستی و ایمنی هستند:

    1. آفست هر فیلد بر هم‌ترازی همان فیلد بخش‌پذیر است.
    2. هم‌ترازی نوع دست‌کم برابر بیشترین هم‌ترازی فیلدهای آن است.
    [layout.repr.rust.struct]

    برای ساختارها همچنین تضمین می‌شود که فیلدها روی هم نیفتند. یعنی می‌توان فیلدها را چنان مرتب کرد که آفست هر فیلد به‌اضافهٔ اندازهٔ آن، کوچک‌تر یا مساوی آفست فیلد بعدی در ترتیب باشد. این ترتیب لازم نیست با ترتیب مشخص‌شدن فیلدها در اعلان نوع یکسان باشد.

    توجه داشته باشید این تضمین به معنای متفاوت‌بودن آدرس فیلدها نیست: نوع‌های با اندازهٔ صفر ممکن است با فیلدهای دیگر همان ساختار آدرس یکسانی داشته باشند.

    [layout.repr.rust.struct-zst]

    برشمردنی‌های بدون هیچ گونه‌ای (و بدون نمایش ابتدایی مشخص‌شده) اندازهٔ صفر دارند.

    [layout.repr.rust.enum-empty-zst]

    نکته چنین برشمردنی‌هایی غیرقابل‌سکونت هستند.

    Note

    چنین enumهایی غیرمسکون هستند.

    [layout.repr.rust.enum-struct-like-zst]

    برای برشمردنی‌هایی که نمایش ابتدایی ندارند و تنها یک گونهٔ شبیه ساختار فیلددار، یک گونهٔ شبیه ساختار واحد یا یک گونهٔ شبیه ساختار چندتایی دارند، اگر آن ساختارگونه هیچ فیلدی نداشته باشد یا همهٔ فیلدهایش اندازهٔ صفر باشند، خود برشمردنی نیز اندازهٔ صفر است.

    use core::mem::size_of;
enum E1 {
    V {},
}

enum E2 {
    V { f: () },
}

enum E3 {
    V,
}

enum E4 {
    V(),
}

enum E5 {
    V(()),
}

assert_eq!(size_of::<E1>(), 0);
assert_eq!(size_of::<E2>(), 0);
assert_eq!(size_of::<E3>(), 0);
assert_eq!(size_of::<E4>(), 0);
assert_eq!(size_of::<E5>(), 0);
    [layout.repr.rust.unspecified]

    این نمایش هیچ تضمین دیگری دربارهٔ چیدمان داده ارائه نمی‌کند.

    [layout.repr.c]

    نمایش C

    [layout.repr.c.intro]

    نمایش C با دو هدف طراحی شده است. هدف نخست ساخت نوع‌هایی است که با زبان C تعامل‌پذیر باشند. هدف دوم ساخت نوع‌هایی است که بتوان عملیات متکی بر چیدمان داده، مانند تفسیر دوبارهٔ مقدارها به‌عنوان نوعی دیگر، را به‌شکلی درست روی آن‌ها انجام داد.

    به‌سبب این هدف دوگانه، ممکن است نوع‌هایی ساخته شوند که برای ارتباط با زبان برنامه‌نویسی C سودمند نباشند.

    [layout.repr.c.constraint]

    این نمایش را می‌توان روی ساختارها، اجتماع‌ها و برشمردنی‌ها اعمال کرد. استثنا برشمردنی‌های بدون گونه هستند که نمایش C برای آن‌ها خطاست.

    [layout.repr.c.struct]

    ساختارهای #[repr(C)]

    [layout.repr.c.struct.align]

    هم‌ترازی ساختار برابر هم‌ترازیِ دارای بیشترین هم‌ترازی در میان فیلدهای آن است، یا اگر فیلدی وجود نداشته باشد برابر یک است.

    [layout.repr.c.struct.size-field-offset]

    اندازه و آفست فیلدها با الگوریتم زیر تعیین می‌شود.

    با آفست جاری ۰ بایت آغاز کنید.

    برای هر فیلد به ترتیب اعلان در ساختار، ابتدا اندازه و هم‌ترازی فیلد را تعیین کنید. اگر آفست جاری مضربی از هم‌ترازی فیلد نیست، آن‌قدر بایت پرکننده به آفست جاری بیفزایید تا مضربی از هم‌ترازی فیلد شود. آفست کنونی، آفست آن فیلد است. سپس آفست جاری را به‌اندازهٔ فیلد افزایش دهید.

    در پایان، اندازهٔ ساختار برابر آفست جاری است که به نزدیک‌ترین مضرب بزرگ‌تر یا مساویِ هم‌ترازی ساختار گرد شده است.

    الگوریتم چنین است:

    /// A field of a struct.
#[derive(Debug)]
struct Field {
    alignment: usize,
    size: usize,
}
/// Layout of user-defined structs.
#[derive(Debug)]
struct MockLayout {
    /// Fields stored in declaration order.
    fields: Vec<Field>,
    /// Offset of each field from the start of the struct.
    field_offsets: Vec<usize>,
    /// Overall alignment.
    alignment: usize,
    /// Overall size.
    size: usize,
}

impl MockLayout {
    /// Returns the amount of padding needed after `offset` to ensure that the
    /// following address will be aligned to `alignment`.
    fn padding_needed_for(offset: usize, alignment: usize) -> usize {
        let misalignment = offset % alignment;
        if misalignment > 0 {
            // Round up to next multiple of `alignment`.
            alignment - misalignment
        } else {
            // Already a multiple of `alignment`.
            0
        }
    }

    /// Fields must be in declaration order. By this point, they have already
    /// had their alignments and sizes calculated.
    pub fn from_fields(fields: Vec<Field>) -> Self {
        // "The alignment of the struct is the alignment of the most-aligned
        // field in it, or one if there are no fields."
        let alignment = fields
            .iter()
            .map(|field| field.alignment)
            .max()
            .unwrap_or(1);

        // "Start with a current offset of 0 bytes."
        let mut current_offset = 0;

        let mut field_offsets = vec![];
        for field in &fields {
            // "If the current offset is not a multiple of the field's
            // alignment, then add padding bytes to the current offset until it
            // is a multiple of the field's alignment."
            current_offset += Self::padding_needed_for(
                current_offset,
                field.alignment
            );

            // "The offset for the field is what the current offset is now."
            field_offsets.push(current_offset);

            // "Then increase the current offset by the size of the field."
            current_offset += field.size;
        }

        // "Finally, the size of the struct is the current offset rounded up to
        // the nearest multiple of the struct's alignment."
        let size = current_offset + Self::padding_needed_for(
            current_offset,
            alignment
        );

        MockLayout { fields, field_offsets, alignment, size }
    }
}

#[repr(C)]
struct Demo {
    first: u8,
    second: u32,
    third: u64,
}
macro_rules! fields {
    ( $( $t:ty ),+ ) => {
        vec![
            $( Field {
                alignment: std::mem::align_of::<$t>(),
                size: std::mem::size_of::<$t>(),
            }),+
        ]
    }
}
let fields = fields![u8, u32, u64];
let demo_layout = MockLayout::from_fields(fields);
assert_eq!(std::mem::align_of::<Demo>(), demo_layout.alignment);
assert_eq!(std::mem::size_of::<Demo>(), demo_layout.size);

    Warning

    هشدار این پیاده‌سازی نمونه برای خوانایی از الگوریتمی ساده‌لوحانه استفاده می‌کند که مسائل سرریز را نادیده می‌گیرد. برای محاسبهٔ چیدمان حافظه در کد واقعی از Layout استفاده کنید.

    Note

    نکته این الگوریتم می‌تواند ساختارهای با اندازهٔ صفر تولید کند. در C، اعلان ساختار خالی مانند struct Foo { } غیرمجاز است. با این حال gcc و clang گزینه‌هایی برای فعال‌کردن چنین ساختارهایی دارند و اندازهٔ صفر به آن‌ها می‌دهند. در مقابل، C++ به ساختار خالی اندازهٔ ۱ می‌دهد، مگر آنکه از آن ارث‌بری شده باشد یا فیلدی با ویژگی [[no_unique_address]] باشد؛ در آن صورت اندازهٔ کلی ساختار را افزایش نمی‌دهد.

    [layout.repr.c.union]

    اجتماع‌های #[repr(C)]

    [layout.repr.c.union.intro]

    اجتماعی که با #[repr(C)] اعلان شده باشد، در سکوی مقصد همان اندازه و هم‌ترازی اعلان اجتماع معادل در زبان C را خواهد داشت.

    [layout.repr.c.union.size-align]

    اندازهٔ اجتماع برابر بیشترین اندازهٔ فیلدهایش است که تا هم‌ترازی اجتماع گرد می‌شود، و هم‌ترازی آن برابر بیشترین هم‌ترازی فیلدهایش است. این دو بیشینه ممکن است از فیلدهای متفاوتی بیایند. هر فیلد در آفست بایتی ۰ از ابتدای اجتماع قرار دارد.

    #[repr(C)]
union Union {
    f1: u16,
    f2: [u8; 4],
}

assert_eq!(std::mem::size_of::<Union>(), 4);  // From f2
assert_eq!(std::mem::align_of::<Union>(), 2); // From f1

assert_eq!(std::mem::offset_of!(Union, f1), 0);
assert_eq!(std::mem::offset_of!(Union, f2), 0);

#[repr(C)]
union SizeRoundedUp {
   a: u32,
   b: [u16; 3],
}

assert_eq!(std::mem::size_of::<SizeRoundedUp>(), 8);  // Size of 6 from b,
                                                      // rounded up to 8 from
                                                      // alignment of a.
assert_eq!(std::mem::align_of::<SizeRoundedUp>(), 4); // From a

assert_eq!(std::mem::offset_of!(SizeRoundedUp, a), 0);
assert_eq!(std::mem::offset_of!(SizeRoundedUp, b), 0);
    [layout.repr.c.enum]

    برشمردنی‌های بی‌فیلد #[repr(C)]

    [layout.repr.c.enum.discriminant]

    برای یک برشمردنی بی‌فیلد با نمایش C، همهٔ مقدارهای ممیز باید یا با نوع int در ABI زبان C سکوی مقصد قابل نمایش باشند، یا همگی با نوع unsigned int آن قابل نمایش باشند.

    Note

    نکته ممیزهای برشمردنی repr(C) بدون نمایش ابتدایی، از نوع isize هستند. items.enum.discriminant.type را ببینید. اندازه و هم‌ترازی پس از تبدیل ممیزها به isize، طبق قاعدهٔ زیر از مقدارهایشان تعیین می‌شود.

    Note

    نکته rustc برشمردنی‌هایی را که مقدار ممیزشان این شرط را برآورده نمی‌کند می‌پذیرد، اما برایشان هشدار lint می‌دهد. این وضعیت در آینده به خطا تبدیل خواهد شد.

    [layout.repr.c.enum.size-align]

    یک برشمردنی بی‌فیلد با نمایش C، اندازه و هم‌ترازی یکسانی با برشمردنی C دارای همان مقدارهای ممیز و بدون نوع زیربنایی ثابت دارد.

    use core::ffi::c_int;
use core::mem::{align_of, size_of};
#[repr(C)]
enum E {
    V1,
    V2,
}

#[cfg(target_arch = "x86_64")]
{
    assert_eq!(size_of::<E>(), size_of::<c_int>());
    assert_eq!(align_of::<E>(), align_of::<c_int>());
}

    Note

    نکته نمایش برشمردنی در C به پیاده‌سازی وابسته است، پس این نتیجه در واقع «بهترین حدس» است. به‌ویژه ممکن است وقتی کد C موردنظر با بعضی پرچم‌ها کامپایل شود، نادرست باشد.

    برای بیشترین قابلیت حمل، بهتر است اندازه و هم‌ترازی را در سمت Rust با یک نمایش ابتدایی و در سمت C با یک نوع زیربنایی ثابت (معرفی‌شده در C23) به‌طور صریح تعیین کنید.

    Warning

    تفاوت‌های مهمی میان یک enum در زبان C و enumهای بدون فیلد در Rust با این بازنمایی وجود دارد. یک enum در C عمدتاً یک typedef به‌همراه چند ثابت نام‌دار است؛ به بیان دیگر، یک شیء از نوع enum می‌تواند هر مقدار صحیحی را نگه دارد. برای نمونه، این ویژگی اغلب برای پرچم‌های بیتی (bitflags) در C به‌کار می‌رود. در مقابل، enumهای بدون فیلد در Rust تنها می‌توانند مقدارهای ممیز (discriminant) را به‌صورت معتبر نگه دارند و هر چیز دیگری رفتار تعریف‌نشده است. بنابراین استفاده از enum بدون فیلد در FFI برای مدل‌کردن یک enum در C اغلب نادرست است.

    [layout.repr.c.adt]

    برشمردنی‌های فیلددار #[repr(C)]

    [layout.repr.c.adt.intro]

    نمایش یک برشمردنی فیلددار repr(C)، ساختاری repr(C) با دو فیلد است که در C به آن «اجتماع برچسب‌دار» نیز می‌گویند:

    [layout.repr.c.adt.tag]
    • نسخهٔ repr(C) برشمردنی که همهٔ فیلدهایش حذف شده‌اند («برچسب»)
    [layout.repr.c.adt.fields]
    • اجتماع repr(C) از ساختارهای repr(C) مربوط به فیلدهای هر گونه‌ای که فیلد داشته است («بار»)

    Note

    نکته به‌سبب نمایش ساختارها و اجتماع‌های repr(C)، اگر گونه‌ای تنها یک فیلد داشته باشد، گذاشتن مستقیم آن فیلد در اجتماع با پیچیدن آن در یک ساختار تفاوتی ندارد؛ بنابراین هر سامانه‌ای که بخواهد نمایش چنین enumای را دست‌کاری کند، می‌تواند از هر شکلی که مناسب‌تر یا سازگارتر است استفاده کند.

    // This Enum has the same representation as ...
#[repr(C)]
enum MyEnum {
    A(u32),
    B(f32, u64),
    C { x: u32, y: u8 },
    D,
 }

// ... this struct.
#[repr(C)]
struct MyEnumRepr {
    tag: MyEnumDiscriminant,
    payload: MyEnumFields,
}

// This is the discriminant enum.
#[repr(C)]
enum MyEnumDiscriminant { A, B, C, D }

// This is the variant union.
#[repr(C)]
union MyEnumFields {
    A: MyAFields,
    B: MyBFields,
    C: MyCFields,
    D: MyDFields,
}

#[repr(C)]
#[derive(Copy, Clone)]
struct MyAFields(u32);

#[repr(C)]
#[derive(Copy, Clone)]
struct MyBFields(f32, u64);

#[repr(C)]
#[derive(Copy, Clone)]
struct MyCFields { x: u32, y: u8 }

// This struct could be omitted (it is a zero-sized type), and it must be in
// C/C++ headers.
#[repr(C)]
#[derive(Copy, Clone)]
struct MyDFields;
    [layout.repr.primitive]

    نمایش‌های ابتدایی

    [layout.repr.primitive.intro]

    نمایش‌های ابتدایی نمایش‌هایی هم‌نام با نوع‌های صحیح ابتدایی هستند؛ یعنی u8، u16، u32، u64، u128، usize، i8، i16، i32، i64، i128 و isize.

    [layout.repr.primitive.constraint]

    نمایش‌های ابتدایی را تنها می‌توان روی برشمردنی‌ها اعمال کرد و رفتارشان بسته به فیلددار یا بی‌فیلدبودن برشمردنی متفاوت است. داشتن نمایش ابتدایی برای برشمردنی‌های بدون گونه خطاست. ترکیب دو نمایش ابتدایی با یکدیگر نیز خطاست.

    [layout.repr.primitive.enum]

    نمایش ابتدایی برشمردنی‌های بی‌فیلد

    یک برشمردنی بی‌فیلد با نمایش ابتدایی، اندازه و هم‌ترازی یکسانی با نوع ابتدایی هم‌نام خود دارد.

    Note

    نکته مقدارهای ممیز برشمردنی دارای نمایش ابتدایی، از نوع نام‌برده‌شده در نمایش هستند. items.enum.discriminant.type-primitive را ببینید.

    [layout.repr.primitive.adt]

    نمایش ابتدایی برشمردنی‌های فیلددار

    نمایش برشمردنی دارای نمایش ابتدایی، یک اجتماع repr(C) از ساختارهای repr(C) برای هر گونهٔ فیلددار است. نخستین فیلد هر ساختار در اجتماع، نسخهٔ دارای نمایش ابتداییِ برشمردنی با همهٔ فیلدهای حذف‌شده («برچسب») است و فیلدهای باقی‌مانده، فیلدهای همان گونه هستند.

    Note

    نکته اگر برای روشن‌ترشدن دست‌کاری، برچسب را به‌عنوان عضوی جداگانه در اجتماع قرار دهید، این نمایش تغییری نمی‌کند؛ هرچند برای پیروی از استاندارد C++ عضو برچسب باید در یک struct پیچیده شود.

    Note

    نکته این نمایش با repr(C) برای برشمردنی‌های فیلددار تفاوت زیادی دارد.

    // This enum has the same representation as ...
#[repr(u8)]
enum MyEnum {
    A(u32),
    B(f32, u64),
    C { x: u32, y: u8 },
    D,
 }

// ... this union.
#[repr(C)]
union MyEnumRepr {
    A: MyVariantA,
    B: MyVariantB,
    C: MyVariantC,
    D: MyVariantD,
}

// This is the discriminant enum.
#[repr(u8)]
#[derive(Copy, Clone)]
enum MyEnumDiscriminant { A, B, C, D }

#[repr(C)]
#[derive(Clone, Copy)]
struct MyVariantA(MyEnumDiscriminant, u32);

#[repr(C)]
#[derive(Clone, Copy)]
struct MyVariantB(MyEnumDiscriminant, f32, u64);

#[repr(C)]
#[derive(Clone, Copy)]
struct MyVariantC { tag: MyEnumDiscriminant, x: u32, y: u8 }

#[repr(C)]
#[derive(Clone, Copy)]
struct MyVariantD(MyEnumDiscriminant);
    [layout.repr.primitive-c]

    ترکیب نمایش ابتدایی برشمردنی‌های فیلددار با #[repr(C)]

    برای برشمردنی‌های فیلددار می‌توان repr(C) را با یک نمایش ابتدایی نیز ترکیب کرد (برای نمونه repr(C, u8)). این کار repr(C) را تغییر می‌دهد و نمایش برشمردنی ممیز را به‌جای آن روی نوع ابتدایی انتخاب‌شده می‌گذارد. پس اگر نمایش u8 را برگزینید، برشمردنی ممیز اندازه و هم‌ترازی ۱ بایتی خواهد داشت.

    Note

    نکته این یعنی repr(C, u8) با repr(u8) بسیار متفاوت است! اولی ساختاری با دو فیلد (برچسب و اجتماع گونه‌ها) است؛ دومی اجتماعی است که هر فیلد آن با برچسب آغاز می‌شود.

    برشمردنی ممیزِ نمونهٔ پیشین در این صورت چنین می‌شود:

    #[repr(C, u8)] // `u8` was added
enum MyEnum {
    A(u32),
    B(f32, u64),
    C { x: u32, y: u8 },
    D,
 }

// ...

#[repr(u8)] // So `u8` is used here instead of `C`
enum MyEnumDiscriminant { A, B, C, D }

// ...

    برای نمونه، با یک برشمردنی repr(C, u8) نمی‌توان ۲۵۷ ممیز («برچسب») یکتا داشت؛ در حالی که همان برشمردنی تنها با ویژگی repr(C) بدون مشکل کامپایل می‌شود.

    استفاده از یک نمایش ابتدایی در کنار repr(C) می‌تواند اندازهٔ برشمردنی را نسبت به شکل repr(C) تغییر دهد:

    #[repr(C)]
enum EnumC {
    Variant0(u8),
    Variant1,
}

#[repr(C, u8)]
enum Enum8 {
    Variant0(u8),
    Variant1,
}

#[repr(C, u16)]
enum Enum16 {
    Variant0(u8),
    Variant1,
}

// The size of the C representation is platform dependent
assert_eq!(std::mem::size_of::<EnumC>(), 8);
// One byte for the discriminant and one byte for the value in Enum8::Variant0
assert_eq!(std::mem::size_of::<Enum8>(), 2);
// Two bytes for the discriminant and one byte for the value in Enum16::Variant0
// plus one byte of padding.
assert_eq!(std::mem::size_of::<Enum16>(), 4);
    [layout.repr.alignment]

    اصلاح‌گرهای هم‌ترازی

    [layout.repr.alignment.intro]

    اصلاح‌گرهای align و packed را می‌توان به‌ترتیب برای افزایش یا کاهش هم‌ترازی structها و unionها به کار برد. packed ممکن است فضای پرکنندهٔ میان فیلدها را نیز تغییر دهد، هرچند فضای پرکنندهٔ درون هیچ فیلدی را تغییر نمی‌دهد. align و packed به‌تنهایی هیچ تضمینی دربارهٔ ترتیب فیلدها در چیدمان ساختار یا چیدمان یک گونهٔ برشمردنی نمی‌دهند، اما می‌توان آن‌ها را با نمایش‌هایی مانند C که چنین تضمینی می‌دهند ترکیب کرد.

    [layout.repr.alignment.constraint-alignment]

    هم‌ترازی به‌شکل پارامتر صحیح در #[repr(align(x))] یا #[repr(packed(x))] مشخص می‌شود. مقدار هم‌ترازی باید توانی از دو، از ۱ تا ۲۲۹ باشد. برای packed، اگر مانند #[repr(packed)] مقداری داده نشود، مقدار ۱ در نظر گرفته می‌شود.

    [layout.repr.alignment.align]

    برای align، اگر هم‌ترازی مشخص‌شده کمتر از هم‌ترازی نوع بدون اصلاح‌گر align باشد، هم‌ترازی تغییری نمی‌کند.

    [layout.repr.alignment.packed]

    برای packed، اگر هم‌ترازی مشخص‌شده بزرگ‌تر از هم‌ترازی نوع بدون اصلاح‌گر packed باشد، هم‌ترازی و چیدمان تغییری نمی‌کند.

    [layout.repr.alignment.packed-fields]

    برای جانمایی فیلدها، هم‌ترازی هر فیلد برابر مقدار کوچک‌تر میان هم‌ترازی مشخص‌شده و هم‌ترازی نوع آن فیلد است.

    [layout.repr.alignment.packed-padding]

    تضمین می‌شود فضای پرکنندهٔ میان فیلدها کمینهٔ لازم برای برآوردن هم‌ترازی هر فیلد (که شاید تغییر یافته باشد) باشد؛ البته توجه کنید packed به‌تنهایی دربارهٔ ترتیب فیلدها تضمینی نمی‌دهد. پیامد مهم این قواعد آن است که نوعی با #[repr(packed(1))] یا #[repr(packed)] هیچ فضای پرکننده‌ای میان فیلدها نخواهد داشت.

    [layout.repr.alignment.constraint-exclusive]

    اصلاح‌گرهای align و packed را نمی‌توان هم‌زمان روی یک نوع اعمال کرد و یک نوع packed نیز نمی‌تواند به‌صورت تعدی نوع دیگری با align را در خود داشته باشد. align و packed تنها روی نمایش‌های Rust و C قابل اعمال‌اند.

    [layout.repr.alignment.enum]

    اصلاح‌گر align را می‌توان روی یک enum نیز اعمال کرد. در این حالت، اثر آن بر هم‌ترازی enum همان اثری است که اگر enum درون یک struct از نوع newtype با همان اصلاح‌گر align پیچیده شده بود، داشت.

    Note

    نکته ارجاع به فیلدهای ناهم‌تراز مجاز نیست، زیرا رفتار تعریف‌نشده است. وقتی فیلدها به‌سبب اصلاح‌گر هم‌ترازی ناهم‌ترازند، برای استفاده از ارجاع و ارجاع‌زدایی گزینه‌های زیر را در نظر بگیرید:

    #[repr(packed)]
struct Packed {
    f1: u8,
    f2: u16,
}
let mut e = Packed { f1: 1, f2: 2 };
// Instead of creating a reference to a field, copy the value to a local variable.
let x = e.f2;
// Or in situations like `println!` which creates a reference, use braces
// to change it to a copy of the value.
println!("{}", {e.f2});
// Or if you need a pointer, use the unaligned methods for reading and writing
// instead of dereferencing the pointer directly.
let ptr: *const u16 = &raw const e.f2;
let value = unsafe { ptr.read_unaligned() };
let mut_ptr: *mut u16 = &raw mut e.f2;
unsafe { mut_ptr.write_unaligned(3) }
    [layout.repr.transparent]

    نمایش transparent

    [layout.repr.transparent.constraint-field]

    نمایش transparent تنها روی یک struct یا enum تک‌گونه‌ای قابل استفاده است که موارد زیر را داشته باشد:

    • هر تعداد فیلد با اندازهٔ ۰ و هم‌ترازی ۱ (برای نمونه PhantomData<T>)، و
    • حداکثر یک فیلد دیگر.
    [layout.repr.transparent.layout-abi]

    ساختارها و برشمردنی‌های دارای این نمایش، اگر فیلدی با اندازهٔ غیرصفر یا هم‌ترازی غیر ۱ وجود داشته باشد، همان چیدمان و ABI آن تنها فیلد را دارند؛ و در غیر این صورت چیدمان و ABI نوع واحد را خواهند داشت.

    این با بازنمایی C متفاوت است، زیرا یک struct با بازنمایی C همیشه ABI یک C struct را خواهد داشت، در حالی که برای نمونه یک struct با بازنمایی transparent و یک فیلد ابتدایی (primitive)، ABI همان فیلد ابتدایی را خواهد داشت.

    [layout.repr.transparent.constraint-exclusive]

    چون این نمایش چیدمان نوع را به نوع دیگری واگذار می‌کند، نمی‌توان آن را همراه هیچ نمایش دیگری به کار برد.
