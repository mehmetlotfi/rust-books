    [names.resolution]

    تفکیک نام

    [names.resolution.intro]

    تفکیک نام فرایند پیوند دادن مسیرها و دیگر شناسه‌ها به اعلان موجودیت‌های متناظر است. نام‌ها در فضاهای نام گوناگون جدا می‌شوند تا موجودیت‌های فضاهای نام متفاوت بتوانند بدون تداخل نام یکسانی داشته باشند. هر نام در یک دامنه، یعنی ناحیه‌ای از متن منبع که در آن می‌توان به نام ارجاع داد، معتبر است. دسترسی به نام ممکن است بر پایهٔ نمایانی آن محدود شود.

    تفکیک نام در سراسر فرایند کامپایل به سه مرحله تقسیم می‌شود. مرحلهٔ نخست، تفکیک زمان گسترش، همهٔ اعلان‌های use و فراخوانی‌های ماکرو را تفکیک می‌کند. مرحلهٔ دوم، تفکیک اصلی، همهٔ نام‌هایی را تفکیک می‌کند که هنوز تفکیک نشده‌اند و تفکیکشان به اطلاعات نوع وابسته نیست. مرحلهٔ پایانی، تفکیک نسبی به نوع، پس از در دسترس قرار گرفتن اطلاعات نوع، نام‌های باقی‌مانده را تفکیک می‌کند.

    Note

    نکته تفکیک زمان گسترش با نام تفکیک زودهنگام نیز شناخته می‌شود. تفکیک اصلی نیز تفکیک دیرهنگام نامیده می‌شود.

    [names.resolution.expansion]

    تفکیک نام هنگام گسترش

    [names.resolution.expansion.intro]

    تفکیک نام هنگام گسترش مرحله‌ای است که برای تکمیل گسترش ماکرو و تولید کامل AST یک کریت لازم است. این مرحله به تفکیک فراخوانی‌های ماکرو و اعلان‌های use نیاز دارد. تفکیک اعلان‌های use برای فراخوانی‌های ماکرویی لازم است که از راه دامنهٔ مبتنی بر مسیر تفکیک می‌شوند. تفکیک فراخوانی‌های ماکرو نیز برای گسترش آن‌ها لازم است.

    [names.resolution.expansion.unresolved-invocations]

    پس از تفکیک نام هنگام گسترش، AST نباید هیچ فراخوانی ماکروی گسترش‌نیافته‌ای داشته باشد. هر فراخوانی ماکرو به تعریف معتبری تفکیک می‌شود که در AST نهایی یا یک کریت خارجی وجود دارد.

    m!(); // ERROR: Cannot find macro `m` in this scope.
    [names.resolution.expansion.expansion-order-stability]

    تفکیک نام‌ها باید پایدار باشد. پس از گسترش، نام‌های AST کاملاً گسترش‌یافته باید مستقل از ترتیب گسترش ماکروها و تفکیک واردسازی‌ها به همان تعریف تفکیک شوند.

    [names.resolution.expansion.speculation]

    همهٔ نامزدهای تفکیک نام که هنگام گسترش ماکرو انتخاب می‌شوند، حدسی در نظر گرفته می‌شوند. پس از گسترش کامل کریت، همهٔ تفکیک‌های حدسی واردسازی اعتبارسنجی می‌شوند تا اطمینان حاصل شود گسترش ماکرو ابهام جدیدی وارد نکرده است.

    Note

    نکته به‌دلیل ماهیت تکرارشوندهٔ گسترش ماکرو، این وضعیت به ابهام‌های موسوم به سفر در زمان منجر می‌شود؛ برای نمونه وقتی یک ماکرو یا واردسازی سراسری قلمی معرفی می‌کند که با مسیر پایهٔ خودش مبهم است.

    fn main() {}
macro_rules! f {
    () => {
        mod m {
            pub(crate) use f;
        }
    }
}
f!();

const _: () = {
    // Initially, we speculatively resolve `m` to the module in
    // the crate root.
    //
    // Expansion of `f` introduces a second `m` module inside this
    // body.
    //
    // Expansion-time resolution finalizes resolutions by re-
    // resolving all imports and macro invocations, sees the
    // introduced ambiguity and reports it as an error.
    m::f!(); // ERROR: `m` is ambiguous.
};
    [names.resolution.expansion.imports]

    واردسازی‌ها

    [names.resolution.expansion.imports.intro]

    همهٔ اعلان‌های use در این مرحله از تفکیک به‌طور کامل تفکیک می‌شوند. مسیرهای نسبی به نوع در این مرحله قابل تفکیک نیستند و خطا تولید می‌کنند.

    mod m {
    pub const C: () = ();
    pub enum E { V }
    pub type A = E;
    impl E {
        pub const C: () = ();
    }
}

// Valid imports resolved at expansion-time:
use m::C; // OK.
use m::E; // OK.
use m::A; // OK.
use m::E::V; // OK.

// Valid expressions resolved during type-relative resolution:
let _ = m::A::V; // OK.
let _ = m::E::C; // OK.
    mod m {
    pub const C: () = ();
    pub enum E { V }
    pub type A = E;
    impl E {
        pub const C: () = ();
    }
}
// Invalid type-relative imports that can't resolve at expansion-time:
use m::A::V; // ERROR: Unresolved import `m::A::V`.
use m::E::C; // ERROR: Unresolved import `m::E::C`.
    [names.resolution.expansion.imports.shadowing]

    نام‌هایی که با اعلان‌های use در یک دامنهٔ بیرونی معرفی شده‌اند، به‌وسیلهٔ نامزدهای هم‌نام در همان فضای نام از دامنه‌ای درونی‌تر زیر سایه می‌روند؛ مگر جایی که ابهام‌های تفکیک نام محدودیت دیگری اعمال کنند.

    pub mod m1 {
    pub mod ambig {
        pub const C: u8 = 1;
    }
}

pub mod m2 {
    pub mod ambig {
        pub const C: u8 = 2;
    }
}

// This introduces the name `ambig` in the outer scope.
use m1::ambig;
const _: () = {
    // This shadows `ambig` in the inner scope.
    use m2::ambig;
    // The inner candidate is selected here
    // as the resolution of `ambig`.
    use ambig::C;
    assert!(C == 2);
};
    [names.resolution.expansion.imports.shadowing-shared-scope]

    سایه‌اندازی نام‌های معرفی‌شده با اعلان‌های use در یک دامنهٔ واحد در موقعیت‌های زیر مجاز است:

    • [سایه‌اندازی واردسازی سراسری use]
    • سایه‌اندازی دامنهٔ متنی ماکرو
    [names.resolution.expansion.imports.ambiguity]

    ابهام‌ها

    [names.resolution.expansion.imports.ambiguity.intro]

    در برخی وضعیت‌های تفکیک زمان گسترش، چند تعریف ماکرو، اعلان use یا ماژول وجود دارد که نام یک واردسازی یا فراخوانی ماکرو می‌تواند به آن‌ها اشاره کند و کامپایلر نمی‌تواند به‌طور سازگار تعیین کند کدام نامزد باید دیگری را زیر سایه ببرد. در این وضعیت‌ها سایه‌اندازی مجاز نیست و کامپایلر به‌جای آن خطای ابهام صادر می‌کند.

    [names.resolution.expansion.imports.ambiguity.glob-vs-glob]

    نام‌ها را نمی‌توان از راه واردسازی‌های سراسری مبهم تفکیک کرد. واردسازی‌های سراسری می‌توانند نام‌های متعارض را در یک فضای نام وارد کنند، به شرط آنکه نام استفاده نشود. نام‌های دارای نامزدهای متعارض از واردسازی‌های سراسری مبهم همچنان می‌توانند به‌وسیلهٔ واردسازی‌های غیرسراسری زیر سایه بروند و بدون خطا استفاده شوند. خطا هنگام استفاده رخ می‌دهد، نه هنگام واردسازی.

    mod m1 {
    pub struct Ambig;
}

mod m2 {
    pub struct Ambig;
}

// OK: This brings conficting names in the same namespace into scope
// but they have not been used yet.
use m1::*;
use m2::*;

const _: () = {
    // The error happens when the name with the conflicting candidates
    // is used.
    let x = Ambig; // ERROR: `Ambig` is ambiguous.
};
    mod m1 {
    pub struct Ambig;
}

mod m2 {
    pub struct Ambig;
}

use m1::*;
use m2::*; // OK: No name conflict.
const _: () = {
    // This is permitted, since resolution is not through the
    // ambiguous globs.
    struct Ambig;
    let x = Ambig; // OK.
};

    چند واردسازی سراسری می‌توانند نام یکسانی را وارد کنند و اگر واردسازی‌ها ــ با در نظر گرفتن بازصادرسازی‌ها ــ به همان قلم اشاره کنند، استفاده از آن نام مجاز است. نمایانی نام بیشترین نمایانی میان واردسازی‌ها است.

    mod m1 {
    pub struct Ambig;
}

mod m2 {
    // This reexports the same `Ambig` item from a second module.
    pub use super::m1::Ambig;
}

mod m3 {
    // These both import the same `Ambig`.
    //
    // The visibility of `Ambig` is `pub` because that is the
    // maximum visibility between these two `use` declarations.
    pub use super::m1::*;
    use super::m2::*;
}

mod m4 {
    // `Ambig` can be used through the `m3` globs and still has
    // `pub` visibility.
    pub use crate::m3::Ambig;
}

const _: () = {
    // Therefore, we can use it here.
    let _ = m4::Ambig; // OK.
};
fn main() {}
    [names.resolution.expansion.imports.ambiguity.glob-vs-outer]

    وقتی نامزد دیگری در یک دامنهٔ بیرونی وجود دارد، نام‌های موجود در واردسازی‌ها و فراخوانی‌های ماکرو را نمی‌توان از راه واردسازی‌های سراسری تفکیک کرد.

    [names.resolution.expansion.imports.ambiguity.panic-hack]

    Note

    نکته وقتی یکی از core::panic! یا std::panic! به‌دلیل پیش‌درآمد کتابخانهٔ استاندارد وارد دامنه شده باشد و یک واردسازی سراسری نوشته‌شده به‌وسیلهٔ کاربر دیگری را وارد دامنه کند، rustc در حال حاضر استفاده از panic! را با وجود ابهام مجاز می‌داند. برای رفع این ابهام، واردسازی سراسری کاربر اولویت دارد.

    در Rust 2021 و بعد از آن، core::panic! و std::panic! رفتاری یکسان دارند. اما در ویرایش‌های پیشین متفاوت‌اند؛ فقط std::panic! یک String را به‌عنوان آرگومان قالب می‌پذیرد.

    برای نمونه، این کد خطاست:

    extern crate core;
use ::core::prelude::v1::*;
fn main() {
    panic!(std::string::String::new()); // ERROR.
}

    و این کد پذیرفته می‌شود:

    #![no_std]
extern crate std;
use ::std::prelude::v1::*;
fn main() {
    panic!(std::string::String::new()); // OK.
}

    به این رفتار تکیه نکنید؛ برنامه بر حذف آن است.

    برای جزئیات، مسئلهٔ شمارهٔ 147319 در Rust را ببینید.

    mod glob {
    pub mod ambig {
        pub struct Name;
    }
}

// Outer `ambig` candidate.
pub mod ambig {
    pub struct Name;
}

const _: () = {
    // Cannot resolve `ambig` through this glob
    // because of the outer `ambig` candidate above.
    use glob::*;
    use ambig::Name; // ERROR: `ambig` is ambiguous.
};
    // As above, but with macros.
pub mod m {
    macro_rules! f {
        () => {};
    }
    pub(crate) use f;
}
pub mod glob {
    macro_rules! f {
        () => {};
    }
    pub(crate) use f as ambig;
}

use m::f as ambig;

const _: () = {
    use glob::*;
    ambig!(); // ERROR: `ambig` is ambiguous.
};

    Note

    نکته این خطاهای ابهام ویژهٔ تفکیک زمان گسترش‌اند. وجود چند نامزد برای یک نام در مراحل بعدی تفکیک خطا به شمار نمی‌آید. تا زمانی که خود واردسازی‌ها مبهم نباشند، همیشه یک نزدیک‌ترین تفکیک بدون ابهام وجود دارد.

    mod glob {
    pub const AMBIG: u8 = 1;
}

mod outer {
    pub const AMBIG: u8 = 2;
}

use outer::AMBIG;

const C: () = {
    use glob::*;
    assert!(AMBIG == 1);
    //      ^---- This `AMBIG` is resolved during primary resolution.
};
    [names.resolution.expansion.imports.ambiguity.path-vs-textual-macro]

    نام‌ها را نمی‌توان از راه بازصادرسازی‌های مبهم ماکرو تفکیک کرد. بازصادرسازی‌های ماکرو زمانی مبهم‌اند که روی یک نامزد ماکروی متنی هم‌نام در یک دامنهٔ بیرونی سایه بیندازند.

    // Textual macro candidate.
macro_rules! ambig {
    () => {}
}

// Path-based macro candidate.
macro_rules! path_based {
    () => {}
}

pub fn f() {
    // This reexport of the `path_based` macro definition
    // as `ambig` may not shadow the `ambig` macro definition
    // which is resolved via textual macro scope.
    use path_based as ambig;
    ambig!(); // ERROR: `ambig` is ambiguous.
}

    Note

    نکته این محدودیت به‌دلیل جزئیات پیاده‌سازی کامپایلر، به‌ویژه منطق کنونی پیمایش دامنه و پیچیدگی پشتیبانی از این رفتار، لازم است. ممکن است این خطای ابهام در آینده حذف شود.

    [names.resolution.expansion.macros]

    ماکروها

    [names.resolution.expansion.macros.intro]

    ماکروها با پیمایش دامنه‌های موجود برای یافتن نامزدهای در دسترس تفکیک می‌شوند. ماکروها به دو زیرفضای نام تقسیم می‌شوند: یکی برای ماکروهای تابع‌مانند و دیگری برای ویژگی‌ها و مشتق‌سازی‌ها. نامزدهای تفکیک از زیرفضای نام نادرست نادیده گرفته می‌شوند.

    [names.resolution.expansion.macros.visitation-order]

    گونه‌های دامنهٔ در دسترس با ترتیب زیر پیمایش می‌شوند. هر گونهٔ دامنه نمایندهٔ یک یا چند دامنه است.

    • کمک‌مشتق‌ها
    • ماکروهای دامنهٔ متنی
    • ماکروهای دامنهٔ مبتنی بر مسیر
    • [پیش‌درآمد macro_use]
    • پیش‌درآمد کتابخانهٔ استاندارد
    • ویژگی‌های داخلی

    Note

    نکته کامپایلر تلاش می‌کند کمک‌مشتق‌هایی را تفکیک کند که پیش از معرفی‌شدن به دامنه به‌وسیلهٔ ماکروی وابستهٔ خود استفاده شده‌اند. این دامنه پس از دامنهٔ تفکیک نامزدهای کمک‌مشتقی پیمایش می‌شود که به‌درستی در دامنه قرار دارند. این رفتار برای حذف برنامه‌ریزی شده است.

    برای اطلاعات بیشتر، دامنهٔ کمک‌مشتق را ببینید.

    Note

    نکته ممکن است این ترتیب پیمایش در آینده تغییر کند؛ برای نمونه نامزدهای دامنهٔ متنی و مبتنی بر مسیر بر پایهٔ دامنه‌های واژگانی‌شان به‌صورت درهم‌آمیخته پیمایش شوند.

    تفاوت‌های ویرایش 2018 از ویرایش ۲۰۱۸ به بعد، در حضور #[no_implicit_prelude]، پیش‌درآمد #[macro_use] پیمایش نمی‌شود.

    نام‌های cfg و cfg_attr در زیرفضای نام ویژگی ماکرو رزرو شده‌اند.

    [names.resolution.expansion.macros.ambiguity]

    ابهام‌ها

    [names.resolution.expansion.macros.ambiguity.more-expanded-vs-outer]

    نام‌ها را نمی‌توان از راه نامزدهای مبهم درون گسترش‌های ماکرو تفکیک کرد. نامزدهای درون گسترش ماکرو زمانی مبهم‌اند که روی نامزدی هم‌نام از بیرون گسترش ماکروی نامزد نخست سایه بیندازند و فراخوانی نام در حال تفکیک نیز بیرون از گسترش ماکروی نامزد نخست باشد.

    macro_rules! define_ambig {
    () => {
        macro_rules! ambig {
            () => {}
        }
    }
}

// Introduce outer candidate definition for `ambig` macro invocation.
macro_rules! ambig {
    () => {}
}

// Introduce a second candidate definition for `ambig` inside of a
// macro expansion.
define_ambig!();

// The definition of `ambig` from the second invocation
// of `define_ambig` is the innermost canadidate.
//
// The definition of `ambig` from the first invocation of
// `define_ambig` is the second candidate.
//
// The compiler checks that the first candidate is inside of a macro
// expansion, that the second candidate is not from within the same
// macro expansion, and that the name being resolved is not from
// within the same macro expansion.
ambig!(); // ERROR: `ambig` is ambiguous.

    حالت معکوس مبهم در نظر گرفته نمی‌شود.

    macro_rules! define_ambig {
    () => {
        macro_rules! ambig {
            () => {}
        }
    }
}
// Swap order of definitions.
define_ambig!();
macro_rules! ambig {
    () => {}
}
// The innermost candidate is now less expanded so it may shadow more
// the macro expanded definition above it.
ambig!();

    اگر فراخوانی در حال تفکیک درون گسترش درونی‌ترین نامزد باشد نیز ابهامی وجود ندارد.

    macro_rules! ambig {
    () => {}
}

macro_rules! define_and_invoke_ambig {
    () => {
        // Define innermost candidate.
        macro_rules! ambig {
            () => {}
        }

        // Invocation of `ambig` is in the same expansion as the
        // innermost candidate.
        ambig!(); // OK
    }
}

define_and_invoke_ambig!();

    مهم نیست هر دو تعریف از فراخوانی‌های یک ماکرو آمده باشند؛ نامزد بیرونی‌تر همچنان «کمتر گسترش‌یافته» در نظر گرفته می‌شود، زیرا درون گسترشی که تعریف نامزد درونی‌تر را در خود دارد قرار نگرفته است.

    macro_rules! define_ambig {
    () => {
        macro_rules! ambig {
            () => {}
        }
    }
}
define_ambig!();
define_ambig!();
ambig!(); // ERROR: `ambig` is ambiguous.

    این قاعده دربارهٔ واردسازی‌ها نیز برقرار است، به شرط آنکه درونی‌ترین نامزد نام از درون یک گسترش ماکرو آمده باشد.

    macro_rules! define_ambig {
    () => {
        mod ambig {
            pub struct Name;
        }
    }
}

mod ambig {
    pub struct Name;
}

const _: () = {
    // Introduce innermost candidate for
    // `ambig` mod in this macro expansion.
    define_ambig!();
    use ambig::Name; // ERROR: `ambig` is ambiguous.
};
    [names.resolution.expansion.macros.ambiguity.built-in-attr]

    ویژگی‌های تعریف‌شده توسط کاربر یا ماکروهای مشتق‌سازی نمی‌توانند روی ویژگی‌های داخلی غیرماکرو (مثلاً inline) سایه بیندازند.
