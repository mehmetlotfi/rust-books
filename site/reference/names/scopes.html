    [names.scopes]

    دامنه‌ها

    [names.scopes.intro]

    دامنه ناحیه‌ای از متن منبع است که در آن می‌توان با نام یک موجودیت به آن ارجاع داد. بخش‌های بعد جزئیات قواعد و رفتار دامنه‌بندی را شرح می‌دهند؛ این قواعد به نوع موجودیت و محل اعلان آن بستگی دارند. فرایند تطبیق نام‌ها با موجودیت‌ها در فصل تفکیک نام توضیح داده شده است. اطلاعات بیشتر دربارهٔ «دامنه‌های حذف» که برای اجرای نابودگرها به کار می‌روند، در فصل نابودگرها آمده است.

    [names.scopes.items]

    دامنهٔ اقلام

    [names.scopes.items.module]

    نام یک قلم که مستقیماً در یک ماژول اعلان شده است، از ابتدای ماژول تا انتهای آن دامنه دارد. این اقلام عضو ماژول نیز هستند و می‌توان با مسیری که از ماژولشان آغاز می‌شود به آن‌ها ارجاع داد.

    [names.scopes.items.statement]

    نام قلمی که به‌صورت یک دستور اعلان شده است، از ابتدای بلوکی که دستورِ قلم در آن قرار دارد تا انتهای همان بلوک دامنه دارد.

    [names.scopes.items.duplicate]

    وارد کردن قلمی با نام تکراریِ قلم دیگری در همان فضای نام و درون همان ماژول یا بلوک خطاست. واردسازی‌های سراسری با ستاره برای برخورد با نام‌های تکراری و سایه‌اندازی رفتار ویژه‌ای دارند؛ برای جزئیات بیشتر فصل پیوندشده را ببینید.

    [names.scopes.items.shadow-prelude]

    اقلام یک ماژول می‌توانند روی اقلام یک پیش‌درآمد سایه بیندازند.

    [names.scopes.items.nested-modules]

    نام اقلام ماژول‌های بیرونی درون یک ماژول تودرتو در دامنه نیستند. برای ارجاع به قلمی در ماژول دیگر می‌توان از یک مسیر استفاده کرد.

    [names.scopes.associated-items]

    دامنهٔ اقلام وابسته

    [names.scopes.associated-items.scope]

    اقلام وابسته دامنه‌بندی نمی‌شوند و تنها با استفاده از مسیری که از نوع یا صفت وابسته به آن‌ها آغاز می‌شود، می‌توان به آن‌ها ارجاع داد. به متدها همچنین می‌توان از راه عبارت‌های فراخوانی ارجاع داد.

    [names.scopes.associated-items.duplicate]

    مانند آیتم‌های درون یک ماژول یا بلوک، معرفی آیتمی درون یک trait یا پیاده‌سازی که در همان فضای نام تکراریِ آیتم دیگری از همان trait یا impl باشد، خطا است.

    [names.scopes.pattern-bindings]

    دامنهٔ مقیدسازی الگوها

    [names.scopes.pattern-bindings.intro]

    دامنهٔ مقیدسازی الگوی یک متغیر محلی به محل استفاده از آن بستگی دارد:

    [names.scopes.pattern-bindings.let]
    • اتصال‌های دستور let از بلافاصله پس از دستور let تا پایان بلوکی که در آن اعلان شده است ادامه دارند. r[names.scopes.pattern-bindings.parameter]
    • اتصال‌های پارامتر تابع در بدنهٔ تابع قرار دارند. r[names.scopes.pattern-bindings.closure]
    • اتصال‌های پارامتر بستار در بدنهٔ بستار قرار دارند. r[names.scopes.pattern-bindings.loop]
    • اتصال‌های for در بدنهٔ حلقه قرار دارند. r[names.scopes.pattern-bindings.let-chains]
    • اتصال‌های if let و while let علاوه بر بلوک نتیجه، در شرط‌های بعدی نیز معتبرند. r[names.scopes.pattern-bindings.match-arm]
    • اتصال‌های بازوهای match در نگهبان match و عبارت بازوی match قرار دارند. r[names.scopes.pattern-bindings.match-guard-let]
    • مقیدسازی‌های let در نگهبان match در شرط‌های نگهبانِ پس از خود و عبارت بازوی match معتبرند.
    [names.scopes.pattern-bindings.items]

    دامنهٔ متغیرهای محلی به درون اعلان اقلام گسترش نمی‌یابد.

    سایه‌اندازی مقیدسازی الگوها

    [names.scopes.pattern-bindings.shadow]

    مقیدسازی الگوها اجازه دارد روی هر نام موجود در دامنه سایه بیندازد، جز موارد زیر که خطا هستند:

    • اقلام ایستا
    • آیتم‌های static
    • آیتم‌های const
    • اقلام ثابت

    مثال زیر نشان می‌دهد مقیدسازی‌های محلی چگونه می‌توانند روی اعلان اقلام سایه بیندازند:

    fn shadow_example() {
    // Since there are no local variables in scope yet, this resolves to the function.
    foo(); // prints `function`
    let foo = || println!("closure");
    fn foo() { println!("function"); }
    // This resolves to the local closure since it shadows the item.
    foo(); // prints `closure`
}
    [names.scopes.generic-parameters]

    دامنهٔ پارامترهای عمومی

    [names.scopes.generic-parameters.param-list]

    پارامترهای عمومی در یک فهرست GenericParams اعلان می‌شوند. دامنهٔ یک پارامتر عمومی درون قلمی است که پارامتر روی آن اعلان شده است.

    [names.scopes.generic-parameters.order-independent]

    همهٔ پارامترها، مستقل از ترتیب اعلانشان، درون فهرست پارامترهای عمومی در دامنه هستند. مثال‌های زیر موقعیت‌هایی را نشان می‌دهند که می‌توان پیش از اعلان یک پارامتر به آن ارجاع داد:

    // The 'b bound is referenced before it is declared.
fn params_scope<'a: 'b, 'b>() {}

trait SomeTrait<const Z: usize> {}
// The const N is referenced in the trait bound before it is declared.
fn f<T: SomeTrait<N>, const N: usize>() {}
    [names.scopes.generic-parameters.bounds]

    پارامترهای عمومی در کران‌های نوع و بندهای where نیز در دامنه هستند؛ برای نمونه:

    trait SomeTrait<'a, T> {}
// The <'a, U> for `SomeTrait` refer to the 'a and U parameters of `bounds_scope`.
fn bounds_scope<'a, T: SomeTrait<'a, U>, U>() {}

fn where_scope<'a, T, U>()
    where T: SomeTrait<'a, U>
{}
    [names.scopes.generic-parameters.inner-items]

    اگر اقلامی که داخل یک تابع اعلان شده‌اند به پارامتری عمومی از دامنهٔ بیرونی خود ارجاع دهند، خطاست.

    fn example<T>() {
    fn inner(x: T) {} // ERROR: can't use generic parameters from outer function
}

    سایه‌اندازی پارامترهای عمومی

    [names.scopes.generic-parameters.shadow]

    سایه انداختن روی یک پارامتر عمومی خطاست؛ تنها استثنا این است که اقلام اعلان‌شده درون تابع‌ها اجازه دارند روی نام پارامترهای عمومی تابع سایه بیندازند.

    fn example<'a, T, const N: usize>() {
    // Items within functions are allowed to shadow generic parameter in scope.
    fn inner_lifetime<'a>() {} // OK
    fn inner_type<T>() {} // OK
    fn inner_const<const N: usize>() {} // OK
}
    trait SomeTrait<'a, T, const N: usize> {
    fn example_lifetime<'a>() {} // ERROR: 'a is already in use
    fn example_type<T>() {} // ERROR: T is already in use
    fn example_const<const N: usize>() {} // ERROR: N is already in use
    fn example_mixed<const T: usize>() {} // ERROR: T is already in use
}
    [names.scopes.lifetimes]

    دامنهٔ طول‌عمرها

    [names.scopes.lifetimes.intro]

    پارامترهای طول‌عمر در یک فهرست GenericParams و کران‌های صفت با رتبهٔ بالاتر اعلان می‌شوند.

    [names.scopes.lifetimes.special]

    طول‌عمر 'static و طول‌عمر جای‌نگهدار '_ معنای ویژه‌ای دارند و نمی‌توان آن‌ها را به‌عنوان پارامتر اعلان کرد.

    دامنهٔ پارامترهای عمومی طول‌عمر

    [names.scopes.lifetimes.generic]

    اقلام ثابت و ایستا و بافت‌های ثابت تنها ارجاع‌های دارای طول‌عمر 'static را می‌پذیرند؛ بنابراین هیچ طول‌عمر دیگری نمی‌تواند درون آن‌ها در دامنه باشد. ثابت‌های وابسته اجازه می‌دهند به طول‌عمرهای اعلان‌شده در صفت یا پیاده‌سازی خود ارجاع داده شود.

    دامنهٔ کران‌های صفت با رتبهٔ بالاتر

    [names.scopes.lifetimes.higher-ranked]

    دامنهٔ پارامتر طول‌عمری که به‌صورت یک کران صفت با رتبهٔ بالاتر اعلان شده است، به موقعیت استفادهٔ آن بستگی دارد.

    • در قالب یک TypeBoundWhereClauseItem، طول‌عمرهای اعلان‌شده در نوع و کران‌های نوع در دامنه‌اند.
    • در قالب یک TraitBound، طول‌عمرهای اعلان‌شده در مسیر نوعِ کران در دامنه‌اند.
    • در قالب یک BareFunctionType، طول‌عمرهای اعلان‌شده در پارامترهای تابع و نوع بازگشتی در دامنه‌اند.
    trait Trait<'a>{}

fn where_clause<T>()
    // 'a is in scope in both the type and the type bounds.
    where for <'a> &'a T: Trait<'a>
{}

fn bound<T>()
    // 'a is in scope within the bound.
    where T: for <'a> Trait<'a>
{}

struct Example<'a> {
    field: &'a u32
}

// 'a is in scope in both the parameters and return type.
type FnExample = for<'a> fn(x: Example<'a>) -> Example<'a>;

    محدودیت‌های impl trait

    [names.scopes.lifetimes.impl-trait]

    نوع‌های Impl trait فقط می‌توانند به طول‌عمرهایی ارجاع دهند که روی یک تابع یا پیاده‌سازی اعلان شده‌اند.

    trait Trait1 {
    type Item;
}
trait Trait2<'a> {}

struct Example;

impl Trait1 for Example {
    type Item = Element;
}

struct Element;
impl<'a> Trait2<'a> for Element {}

// The `impl Trait2` here is not allowed to refer to 'b but it is allowed to
// refer to 'a.
fn foo<'a>() -> impl for<'b> Trait1<Item = impl Trait2<'a> + use<'a>> {
    // ...
   Example
}
    [names.scopes.loop-label]

    دامنهٔ برچسب حلقه‌ها

    [names.scopes.loop-label.scope]

    برچسب‌های حلقه را می‌توان با یک عبارت حلقه اعلان کرد. دامنهٔ برچسب حلقه از نقطهٔ اعلان آن تا انتهای عبارت حلقه است. این دامنه به درون اقلام، بستارها، بلوک‌های ناهمگام، آرگومان‌های ثابت، بافت‌های ثابت و عبارت تکرارگرِ حلقهٔ for تعریف‌کننده گسترش نمی‌یابد.

    'a: for n in 0..3 {
    if n % 2 == 0 {
        break 'a;
    }
    fn inner() {
        // Using 'a here would be an error.
        // break 'a;
    }
}

// The label is in scope for the expression of `while` loops.
'a: while break 'a {}         // Loop does not run.
'a: while let _ = break 'a {} // Loop does not run.

// The label is not in scope in the defining `for` loop:
'a: for outer in 0..5 {
    // This will break the outer loop, skipping the inner loop and stopping
    // the outer loop.
    'a: for inner in { break 'a; 0..1 } {
        println!("{}", inner); // This does not run.
    }
    println!("{}", outer); // This does not run, either.
}
    [names.scopes.loop-label.shadow]

    برچسب حلقه‌ها می‌توانند روی برچسب‌های هم‌نام در دامنه‌های بیرونی سایه بیندازند. ارجاع به یک برچسب، به نزدیک‌ترین تعریف اشاره می‌کند.

    // Loop label shadowing example.
'a: for outer in 0..5 {
    'a: for inner in 0..5 {
        // This terminates the inner loop, but the outer loop continues to run.
        break 'a;
    }
}
    [names.scopes.prelude]

    دامنهٔ پیش‌درآمدها

    [names.scopes.prelude.intro]

    پیش‌درآمدها موجودیت‌ها را وارد دامنهٔ همهٔ ماژول‌ها می‌کنند. این موجودیت‌ها عضو ماژول نیستند، اما هنگام تفکیک نام به‌طور ضمنی جست‌وجو می‌شوند.

    [names.scopes.prelude.shadow]

    اعلان‌های یک ماژول می‌توانند روی نام‌های پیش‌درآمد سایه بیندازند.

    [names.scopes.prelude.layers]

    پیش‌درآمدها به‌صورت لایه‌ای قرار گرفته‌اند؛ اگر دو پیش‌درآمد موجودیت‌هایی هم‌نام داشته باشند، یکی روی دیگری سایه می‌اندازد. ترتیب سایه‌اندازی پیش‌درآمدها به شکل زیر است؛ موارد بالاتر می‌توانند روی موارد پایین‌تر سایه بیندازند:

    1. پیش‌درآمد extern
    2. پیش‌درآمد ابزار
    3. [پیش‌درآمد macro_use]
    4. پیش‌درآمد زبان
    5. پیش‌درآمد زبان
    [names.scopes.macro_rules]

    دامنه‌های macro_rules

    دامنهٔ ماکروهای macro_rules در فصل ماکروها با مثال شرح داده شده است. رفتار آن‌ها به استفاده از ویژگی‌های macro_use و macro_export بستگی دارد.

    [names.scopes.derive]

    ویژگی‌های کمکی ماکروی مشتق‌سازی

    [names.scopes.derive.scope]

    ویژگی‌های کمکی ماکروی مشتق‌سازی در قلمی که ویژگی derive متناظرشان روی آن مشخص شده است، در دامنه‌اند. دامنه از بلافاصله پس از ویژگی derive تا انتهای قلم ادامه دارد.

    [names.scopes.derive.shadow]

    ویژگی‌های کمکی روی ویژگی‌های هم‌نامِ موجود در دامنه سایه می‌اندازند.

    [names.scopes.self]

    دامنهٔ Self

    [names.scopes.self.intro]

    هرچند Self کلیدواژه‌ای با معنای ویژه است، به روشی مشابه نام‌های عادی با تفکیک نام تعامل می‌کند.

    [names.scopes.self.def-scope]

    نوع ضمنی Self در تعریف یک ساختار، برشمردنی، اجتماع، صفت یا پیاده‌سازی مشابه یک پارامتر عمومی در نظر گرفته می‌شود و درست مانند یک پارامتر نوع عمومی در دامنه است.

    [names.scopes.self.impl-scope]

    سازندهٔ ضمنی Self در فضای نام مقدارِ یک پیاده‌سازی، درون بدنهٔ پیاده‌سازی (یعنی اقلام وابسته آن) در دامنه است.

    // Self type within struct definition.
struct Recursive {
    f1: Option<Box<Self>>
}

// Self type within generic parameters.
struct SelfGeneric<T: Into<Self>>(T);

// Self value constructor within an implementation.
struct ImplExample();
impl ImplExample {
    fn example() -> Self { // Self type
        Self() // Self value constructor
    }
}
