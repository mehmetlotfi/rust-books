    [attributes]

    ویژگی‌ها

    [attributes.syntax]

    Syntax
    InnerAttribute → # ! [ Attr ]

    OuterAttribute → # [ Attr ]

    Attr →
          SimplePath AttrInput?
        | unsafe ( SimplePath AttrInput? )

    AttrInput →
          DelimTokenTree
        | = Expression

    [attributes.intro]

    ویژگی فراداده‌ای عمومی و آزاد است که بر اساس نام، قرارداد، زبان و نسخهٔ کامپایلر تفسیر می‌شود. ویژگی‌های Rust از Attributes در ECMA-335 الگوبرداری شده‌اند و نحو آن‌ها از ECMA-334 ‏(C#) آمده است.

    [attributes.inner]

    ویژگی درونی بر فرمی اعمال می‌شود که ویژگی درون آن اعلان شده است.

    مثال

    // General metadata applied to the enclosing module or crate.
#![crate_type = "lib"]

// Inner attribute applies to the entire function.
fn some_unused_variables() {
  #![allow(unused_variables)]

  let x = ();
  let y = ();
  let z = ();
}
    [attributes.outer]

    ویژگی بیرونی بر فرمی اعمال می‌شود که پس از ویژگی آمده است.

    مثال

    // A function marked as a unit test
#[test]
fn test_foo() {
    /* ... */
}

// A conditionally-compiled module
#[cfg(target_os = "linux")]
mod bar {
    /* ... */
}

// A lint attribute used to suppress a warning/error
#[allow(non_camel_case_types)]
type int8_t = i8;
    [attributes.input]

    ویژگی از مسیری به ویژگی و سپس یک درخت توکن جداشدهٔ اختیاری تشکیل می‌شود که خود ویژگی تفسیر آن را تعریف می‌کند. ویژگی‌های غیرماکرویی همچنین اجازه می‌دهند ورودی یک علامت مساوی (=) و سپس عبارت باشد. برای جزئیات نحو آیتم متا را ببینید.

    [attributes.safety]

    ممکن است اعمال یک ویژگی ناامن باشد. برای جلوگیری از رفتار تعریف‌نشده هنگام استفاده، باید تعهدهایی برآورده شوند که کامپایلر قادر به بررسی آن‌ها نیست. برای تأیید این تعهد، ویژگی در unsafe(..) قرار می‌گیرد؛ مانند #[unsafe(no_mangle)].

    ویژگی‌های زیر ناامن‌اند:

    • export_name
    • link_section
    • naked
    • no_mangle
    [attributes.kind]

    ویژگی‌ها (attributes) را می‌توان به انواع زیر دسته‌بندی کرد:

    • ویژگی‌های داخلی
    • ویژگی‌ها در رده‌های زیر قرار می‌گیرند:
    • ویژگی‌های داخلی
    • ویژگی‌های ابزار
    [attributes.allowed-position]

    ویژگی را می‌توان روی فرم‌های مختلف زبان اعمال کرد:

    • همهٔ اعلان‌های آیتم ویژگی بیرونی می‌پذیرند و بلوک‌های خارجی، تابع‌ها، پیاده‌سازی‌ها و ماژول‌ها ویژگی درونی نیز می‌پذیرند.
    • بیشتر دستورها ویژگی بیرونی می‌پذیرند؛ برای محدودیت دستور عبارت، ویژگی‌های عبارت را ببینید.
    • عبارت‌های بلوکی ویژگی بیرونی و درونی می‌پذیرند، اما فقط هنگامی که عبارت بیرونی یک دستور عبارت یا عبارت نهایی بلوک دیگری باشند.
    • گونه‌های enum و فیلدهای struct و union ویژگی‌های بیرونی می‌پذیرند.
    • بازوهای عبارت match ویژگی بیرونی می‌پذیرند.
    • پارامتر عمومی طول‌عمر یا نوع ویژگی بیرونی می‌پذیرد.
    • عبارت‌ها در موقعیت‌های محدود ویژگی بیرونی می‌پذیرند؛ ویژگی‌های عبارت را ببینید.
    • پارامترهای تابع، بستار و اشاره‌گر تابع ویژگی بیرونی می‌پذیرند. این حکم پارامترهای متغیر ... در اشاره‌گر تابع و بلوک‌های خارجی را نیز شامل می‌شود.
    • رشته‌های الگو و عملوندهای اسمبلی درون‌خطی ویژگی بیرونی می‌پذیرند. فقط بعضی ویژگی‌ها از نظر معنایی پذیرفته می‌شوند؛ asm.attributes.supported-attributes را ببینید.
    [attributes.meta]

    نحو ویژگی آیتم متا

    [attributes.meta.intro]

    «آیتم متا» نحوی است که بیشتر ویژگی‌های داخلی برای قاعدهٔ Attr به‌کار می‌برند:

    [attributes.meta.syntax]

    Syntax
    MetaItem →
          SimplePath
        | SimplePath = Expression
        | SimplePath ( MetaSeq? )

    MetaSeq →
        MetaItemInner ( , MetaItemInner )* ,?

    MetaItemInner →
          MetaItem
        | Expression

    [attributes.meta.literal-expr]

    عبارت‌های آیتم متا باید با گسترش ماکرو به عبارت لفظی تبدیل شوند و نباید پسوند نوع صحیح یا ممیز شناور داشته باشند. عبارت‌های غیرلفظی از نظر نحوی پذیرفته و می‌توانند به proc-macro داده شوند، اما پس از تجزیه رد خواهند شد.

    [attributes.meta.order]

    اگر ویژگی درون ماکروی دیگری باشد، پس از ماکروی بیرونی گسترش می‌یابد. برای مثال ابتدا proc-macro مربوط به Serialize در کد زیر گسترش می‌یابد و باید فراخوانی include_str! را حفظ کند تا بعداً گسترش یابد:

    #[derive(Serialize)]
struct Foo {
    #[doc = include_str!("x.md")]
    x: u32
}
    [attributes.meta.order-macro]

    همچنین ماکروهای درون ویژگی فقط پس از همهٔ ویژگی‌های دیگر اعمال‌شده روی آیتم گسترش می‌یابند:

    #[macro_attr1] // expanded first
#[doc = mac!()] // `mac!` is expanded fourth.
#[macro_attr2] // expanded second
#[derive(MacroDerive1, MacroDerive2)] // expanded third
fn foo() {}
    [attributes.meta.builtin]

    ویژگی‌های داخلی مختلف برای مشخص‌کردن ورودی از زیرمجموعه‌های متفاوت نحو آیتم متا استفاده می‌کنند. قواعد زیر چند شکل رایج را نشان می‌دهند:

    [attributes.meta.builtin-syntax]

    Syntax
    MetaWord →
        IDENTIFIER

    MetaNameValueStr →
        IDENTIFIER = ( STRING_LITERAL | RAW_STRING_LITERAL )

    MetaListPaths →
        IDENTIFIER ( ( SimplePath ( , SimplePath )* ,? )? )

    MetaListIdents →
        IDENTIFIER ( ( IDENTIFIER ( , IDENTIFIER )* ,? )? )

    MetaListNameValueStr →
        IDENTIFIER ( ( MetaNameValueStr ( , MetaNameValueStr )* ,? )? )

    چند نمونه از آیتم‌های متا:

    سبکنمونه
    MetaWordno_std
    MetaNameValueStrdoc = "example"
    MetaListPathsallow(unused, clippy::inline_always)
    MetaListIdentsmacro_use(foo, bar)
    MetaListNameValueStrlink(name = "CoreFoundation", kind = "framework")
    [attributes.activity]

    ویژگی‌های فعال و غیرفعال

    [attributes.activity.intro]

    یک ویژگی یا فعال است یا غیرفعال. هنگام پردازش، ویژگی فعال خود را از فرمی که روی آن است حذف می‌کند، اما ویژگی غیرفعال باقی می‌ماند.

    ویژگی‌های cfg و cfg_attr و ماکروهای ویژگی فعال‌اند. همهٔ ویژگی‌های دیگر غیرفعال‌اند.

    [attributes.tool]

    ویژگی‌های ابزار

    [attributes.tool.intro]

    کامپایلر می‌تواند ویژگی‌های ابزارهای خارجی را مجاز کند؛ هر ابزار در ماژول خود در پیش‌درآمد ابزار قرار دارد. قطعهٔ نخست مسیر ویژگی نام ابزار است و تفسیر یک یا چند قطعهٔ بعدی بر عهدهٔ ابزار است.

    [attributes.tool.ignored]

    وقتی ابزار استفاده نمی‌شود، ویژگی‌هایش بدون هشدار پذیرفته می‌شوند. هنگام استفاده، پردازش و تفسیر ویژگی‌ها بر عهدهٔ ابزار است.

    [attributes.tool.prelude]

    با استفاده از ویژگی no_implicit_prelude ویژگی‌های ابزار در دسترس نیستند.

    // Tells the rustfmt tool to not format the following element.
#[rustfmt::skip]
struct S {
}

// Controls the "cyclomatic complexity" threshold for the clippy tool.
#[clippy::cyclomatic_complexity = "100"]
pub fn f() {}

    Note

    rustc در حال حاضر ابزارهای «clippy»، «rustfmt»، «diagnostic»، «miri» و «rust_analyzer» را می‌شناسد.

    [attributes.builtin]

    نمایهٔ ویژگی‌های داخلی

    در ادامه نمایهٔ همهٔ ویژگی‌های داخلی آمده است.

    • کامپایل شرطی

      • cfg — کنترل کامپایل شرطی.
      • cfg_attr — افزودن شرطی ویژگی‌ها.

    • آزمون

      • test — علامت‌گذاری تابع به‌عنوان آزمون.
      • ignore — غیرفعال‌کردن تابع آزمون.
      • should_panic — نشان‌دادن اینکه آزمون باید panic ایجاد کند.

    • Derive

      • derive — پیاده‌سازی خودکار صفت.
      • automatically_derived — نشانگر پیاده‌سازی ساخته‌شده با derive.

    • ماکروها

      • macro_export — صادرات ماکروی macro_rules برای استفاده میان crateها.
      • macro_use — گسترش قابلیت مشاهدهٔ ماکرو یا واردکردن ماکرو از crate دیگر.
      • proc_macro — تعریف ماکروی تابع‌مانند.
      • proc_macro_derive — تعریف ماکروی derive.
      • proc_macro_attribute — تعریف ماکروی ویژگی.

    • پیام‌های تشخیصی

      • allow، ‏expect، ‏warn، ‏deny، ‏forbid — تغییر سطح پیش‌فرض lint.
      • deprecated — تولید اعلان منسوخ‌شدن.
      • must_use — تولید lint برای مقدار بدون استفاده.
      • diagnostic::on_unimplemented — راهنمایی کامپایلر برای پیام خطای خاص هنگام پیاده‌سازی‌نشدن صفت.
      • diagnostic::do_not_recommend — راهنمایی کامپایلر برای نمایش‌ندادن یک impl صفت در پیام خطا.

    • ABI، پیوند، نمادها و FFI

      • link — مشخص‌کردن کتابخانهٔ بومی برای پیوند با بلوک extern.
      • link_name — مشخص‌کردن نام نماد تابع یا static در بلوک extern.
      • link_ordinal — مشخص‌کردن شمارهٔ ترتیبی نماد تابع یا static در بلوک extern.
      • no_link — جلوگیری از پیوند extern crate.
      • repr — کنترل چیدمان نوع.
      • crate_type — مشخص‌کردن نوع crate مانند کتابخانه یا فایل اجرایی.
      • no_main — غیرفعال‌کردن تولید نماد main.
      • export_name — مشخص‌کردن نام نماد صادرشده برای تابع یا static.
      • link_section — مشخص‌کردن بخش فایل شیء برای تابع یا static.
      • no_mangle — غیرفعال‌کردن کدگذاری نام نماد.
      • used — وادارکردن کامپایلر به حفظ آیتم static در فایل شیء خروجی.
      • crate_name — مشخص‌کردن نام crate.

    • تولید کد

      • inline — راهنمای درون‌خطی‌کردن کد.
      • cold — راهنمای احتمال کم فراخوانی تابع.
      • naked — جلوگیری از تولید پیش‌درآمد و پس‌درآمد تابع توسط کامپایلر.
      • no_builtins — غیرفعال‌کردن بعضی تابع‌های داخلی.
      • target_feature — پیکربندی تولید کد ویژهٔ سکو.
      • track_caller — دادن محل فراخوانی والد به std::panic::Location::caller().
      • instruction_set — مشخص‌کردن مجموعه دستور مورد استفاده برای تولید کد تابع.

    • مستندسازی

      • doc — مشخص‌کردن مستندات. کتاب Rustdoc را ببینید. توضیح‌های مستندات به ویژگی‌های doc تبدیل می‌شوند.

    • پیش‌درآمدها

      • no_std — حذف std از پیش‌درآمد.
      • no_implicit_prelude — غیرفعال‌کردن جست‌وجوی پیش‌درآمد در ماژول.

    • ماژول‌ها

      • path — مشخص‌کردن نام فایل ماژول.

    • محدودیت‌ها

      • recursion_limit — تعیین حداکثر عمق بازگشت بعضی عملیات زمان کامپایل.
      • type_length_limit — تعیین حداکثر اندازهٔ نوع چندریختی.

    • زمان اجرا

      • panic_handler — تعیین تابع مدیریت panic.
      • global_allocator — تعیین تخصیص‌دهندهٔ سراسری حافظه.
      • windows_subsystem — مشخص‌کردن زیرسامانهٔ Windows برای پیوند.

    • قابلیت‌ها

      • feature — فعال‌کردن قابلیت ناپایدار یا آزمایشی کامپایلر. برای قابلیت‌های rustc، کتاب ناپایدار را ببینید.

    • سیستم نوع

      • non_exhaustive — نشان‌دادن امکان افزودن فیلد یا گونه به نوع در آینده.

    • اشکال‌زدا

      • debugger_visualizer — جاسازی فایل تعیین‌کنندهٔ خروجی اشکال‌زدا برای نوع.
      • collapse_debuginfo — کنترل کدگذاری فراخوانی ماکرو در اطلاعات اشکال‌زدایی.
