    [unsafe]

    کلیدواژهٔ unsafe

    [unsafe.intro]

    کلیدواژهٔ unsafe برای ایجاد یا رفع تعهد اثبات ایمنی چیزی به کار می‌رود. به‌طور مشخص:

    • کدی را علامت می‌زند که شرایط ایمنی اضافه‌ای تعریف می‌کند و باید در جای دیگری رعایت شوند.
      • این موارد شامل unsafe fn، ‏unsafe static و unsafe trait هستند.
    • کدی را علامت می‌زند که برنامه‌نویس ادعا می‌کند شرایط ایمنی تعریف‌شده در جای دیگر را رعایت کرده است.
      • این موارد شامل unsafe {}، ‏unsafe impl، تابع unsafe fn بدون unsafe_op_in_unsafe_fn، ‏unsafe extern و #[unsafe(attr)] هستند.

    در ادامه هر مورد را بررسی می‌کنیم. برای چند نمونهٔ توضیحی، مستندات کلیدواژه را ببینید.

    [unsafe.positions]

    کلیدواژهٔ unsafe می‌تواند در چند زمینه ظاهر شود:

    • تابع‌های ناامن (unsafe fn)
    • بلوک‌های ناامن (unsafe {})
    • Traitهای ناامن (unsafe trait)
    • پیاده‌سازی Trait ناامن (unsafe impl)
    • بلوک‌های خارجی ناامن (unsafe extern)
    • staticهای خارجی ناامن (unsafe static)
    • attributeهای ناامن (#[unsafe(attr)])
    [unsafe.fn]

    تابع‌های ناامن (unsafe fn)

    [unsafe.fn.intro]

    تابع‌های ناامن در همهٔ زمینه‌ها و/یا برای همهٔ ورودی‌های ممکن ایمن نیستند. می‌گوییم این تابع‌ها شرایط ایمنی اضافه دارند؛ الزام‌هایی که همهٔ فراخواننده‌ها باید رعایت کنند و کامپایلر آن‌ها را بررسی نمی‌کند. برای نمونه، get_unchecked این شرط اضافه را دارد که index باید در محدوده باشد. مستندات تابع ناامن باید این شرایط اضافه را توضیح دهند.

    [unsafe.fn.safety]

    پیش از چنین تابعی باید کلیدواژهٔ unsafe قرار گیرد و فقط از درون بلوک unsafe یا درون unsafe fn بدون lintِ unsafe_op_in_unsafe_fn می‌توان آن را فراخواند.

    [unsafe.block]

    بلوک‌های ناامن (unsafe {})

    [unsafe.block.intro]

    می‌توان کلیدواژهٔ unsafe را پیش از یک بلوک کد آورد تا عملیات ناامن تعریف‌شده در فصل ناامنی—مانند فراخوانی تابع‌های ناامن دیگر یا اشاره‌زدایی اشاره‌گر خام—در آن مجاز شوند.

    [unsafe.block.fn-body]

    به‌طور پیش‌فرض بدنهٔ تابع ناامن نیز یک بلوک ناامن محسوب می‌شود؛ با فعال‌کردن lintِ unsafe_op_in_unsafe_fn می‌توان این رفتار را تغییر داد.

    با قراردادن عملیات در بلوک ناامن، برنامه‌نویس اعلام می‌کند شرایط ایمنی اضافهٔ همهٔ عملیات درون بلوک را رعایت کرده است.

    بلوک ناامن دوگان منطقی تابع ناامن است: تابع ناامن تعهد اثباتی تعریف می‌کند که فراخواننده باید رعایت کند؛ بلوک ناامن اعلام می‌کند همهٔ تعهدهای اثبات مرتبط با تابع‌ها یا عملیات فراخوانی‌شده درون بلوک رفع شده‌اند. راه‌های مختلفی برای رفع این تعهدها وجود دارد؛ برای نمونه بررسی‌های هنگام اجرا یا invariantهای ساختمان‌داده می‌توانند درستی قطعی ویژگی‌های لازم را تضمین کنند. همچنین بلوک ناامن ممکن است درون یک unsafe fn باشد و از تعهدهای اثبات همان تابع برای رفع تعهدهای ایجادشده درون بلوک استفاده کند.

    بلوک‌های ناامن برای پوشاندن کتابخانه‌های خارجی، استفادهٔ مستقیم از سخت‌افزار یا پیاده‌سازی قابلیت‌هایی به کار می‌روند که مستقیماً در زبان وجود ندارند. برای نمونه، Rust امکانات لازم برای پیاده‌سازی هم‌روندی ایمن از نظر حافظه را در خود زبان فراهم می‌کند، اما پیاده‌سازی Threadها و پیام‌رسانی در کتابخانهٔ استاندارد از بلوک‌های ناامن استفاده می‌کند.

    سامانهٔ نوع Rust تقریب محافظه‌کارانه‌ای از الزام‌های پویای ایمنی است؛ بنابراین گاهی استفاده از کد امن هزینهٔ کارایی دارد. برای نمونه، فهرست پیوندی دوسویه ساختار درختی نیست و در کد امن تنها با اشاره‌گرهای دارای شمارش مرجع قابل نمایش است. با استفاده از بلوک‌های unsafe برای نمایش پیوندهای معکوس به‌شکل اشاره‌گر خام، می‌توان آن را بدون شمارش مرجع پیاده‌سازی کرد. برای بررسی عمیق‌تر این نمونه، «یادگیری Rust با تعداد بیش‌ازحدی فهرست پیوندی» را ببینید.

    [unsafe.trait]

    Traitهای ناامن (unsafe trait)

    [unsafe.trait.intro]

    Trait ناامن شرایط ایمنی اضافه‌ای دارد که پیاده‌سازی‌های Trait باید رعایت کنند. مستندات Trait ناامن باید این شرایط اضافه را توضیح دهند.

    [unsafe.trait.safety]

    پیش از چنین Traitی باید کلیدواژهٔ unsafe قرار گیرد و فقط بلوک‌های unsafe impl می‌توانند آن را پیاده‌سازی کنند.

    [unsafe.impl]

    پیاده‌سازی Trait ناامن (unsafe impl)

    هنگام پیاده‌سازی Trait ناامن، پیش از پیاده‌سازی باید کلیدواژهٔ unsafe بیاید. برنامه‌نویس با نوشتن unsafe impl اعلام می‌کند شرایط ایمنی اضافهٔ الزامی Trait را رعایت کرده است.

    پیاده‌سازی ناامن دوگان منطقی Trait ناامن است: Trait ناامن تعهد اثباتی تعریف می‌کند که پیاده‌سازی‌ها باید رعایت کنند؛ پیاده‌سازی ناامن اعلام می‌کند همهٔ تعهدهای اثبات مرتبط رفع شده‌اند.

    [unsafe.extern]

    بلوک‌های خارجی ناامن (unsafe extern)

    [unsafe.extern.intro]

    برنامه‌نویسی که یک بلوک خارجی تعریف می‌کند باید درستی امضای آیتم‌های درون آن را تضمین کند. رعایت‌نکردن این الزام ممکن است به رفتار تعریف‌نشده بینجامد. نوشتن unsafe extern نشان می‌دهد این تعهد برآورده شده است.

    [unsafe.extern.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴، بلوک‌های extern بدون مشخص‌کنندهٔ unsafe نیز مجاز بودند.

    [unsafe.attribute]

    Attributeهای ناامن (#[unsafe(attr)])

    Attribute ناامن شرایط ایمنی اضافه‌ای دارد که هنگام استفاده از آن باید رعایت شوند. کامپایلر نمی‌تواند رعایت این شرایط را بررسی کند. برای اعلام رعایت آن‌ها باید attribute درون unsafe(..) قرار گیرد؛ برای نمونه #[unsafe(no_mangle)].
