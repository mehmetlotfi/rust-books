    ماژول‌ها

    [items.mod.intro]

    ماژول ظرفی برای صفر یا چند آیتم است.

    [items.mod.def]

    یک آیتم ماژول، ماژولی نام‌گذاری‌شده و محصور در آکولاد است که کلیدواژهٔ mod پیش از آن می‌آید. آیتم ماژول، یک ماژول نام‌دار جدید را به درخت ماژول‌های سازندهٔ crate معرفی می‌کند.

    [items.mod.nesting]

    ماژول‌ها می‌توانند بدون محدودیت در یکدیگر تودرتو شوند.

    نمونه‌ای از یک ماژول:

    mod math {
    type Complex = (f64, f64);
    fn sin(f: f64) -> f64 {
        /* ... */
      unimplemented!();
    }
    fn cos(f: f64) -> f64 {
        /* ... */
      unimplemented!();
    }
    fn tan(f: f64) -> f64 {
        /* ... */
      unimplemented!();
    }
}
    [items.mod.namespace]

    ماژول‌ها در فضای نام نوع ماژول یا بلوکی که در آن قرار دارند تعریف می‌شوند.

    [items.mod.multiple-items]

    تعریف چند آیتم هم‌نام در یک فضای نام و درون یک ماژول خطاست. برای جزئیات بیشتر دربارهٔ محدودیت‌ها و رفتار سایه‌اندازی، فصل حوزه‌ها را ببینید.

    [items.mod.unsafe]

    از نظر نحوی مجاز است کلیدواژهٔ unsafe پیش از mod ظاهر شود، اما این ترکیب در سطح معنایی رد می‌شود. این امکان به ماکروها اجازه می‌دهد نحو را مصرف کنند، از کلیدواژهٔ unsafe بهره ببرند و سپس آن را از جریان توکن حذف کنند.

    [items.mod.outlined]

    نام فایل‌های منبع ماژول

    [items.mod.outlined.intro]

    ماژولی بدون بدنه از یک فایل خارجی بارگذاری می‌شود. اگر ماژول ویژگی path نداشته باشد، مسیر فایل از مسیر ماژول منطقی پیروی می‌کند.

    [items.mod.outlined.search]

    اجزای مسیر ماژول‌های نیا به‌صورت دایرکتوری هستند و محتوای ماژول در فایلی با نام ماژول و پسوند .rs قرار می‌گیرد. برای مثال، ساختار ماژولی زیر می‌تواند ساختار فایل متناظر نشان‌داده‌شده را داشته باشد:

    مسیر ماژولمسیر فایل‌سیستممحتوای فایل
    cratelib.rsmod util;
    crate::utilutil.rsmod config;
    crate::util::configutil/config.rs
    [items.mod.outlined.search-mod]

    نام فایل ماژول می‌تواند به‌صورت دایرکتوری هم‌نام ماژول نیز باشد که محتوا در فایل mod.rs داخل آن دایرکتوری قرار می‌گیرد. مثال بالا را می‌توان به‌گونه‌ای دیگر نوشت که محتوای crate::util در فایل util/mod.rs باشد. وجود هم‌زمان util.rs و util/mod.rs مجاز نیست.

    Note

    نکته پیش از rustc نسخهٔ 1.30، استفاده از فایل‌های mod.rs روش بارگذاری ماژول دارای فرزندان تودرتو بود. استفاده از قرارداد نام‌گذاری جدید توصیه می‌شود، زیرا سازگارتر است و از وجود فایل‌های متعدد هم‌نام mod.rs در پروژه جلوگیری می‌کند.

    [items.mod.outlined.path]

    ویژگی path

    [items.mod.outlined.path.intro]

    ویژگی path می‌تواند دایرکتوری‌ها و فایل‌های مورد استفاده برای بارگذاری ماژول‌های فایل خارجی را تغییر دهد.

    [items.mod.outlined.path.search]

    برای ویژگی path روی ماژول‌هایی که داخل بلوک ماژول درون‌خطی نیستند، مسیر فایل نسبت به دایرکتوری فایل منبع سنجیده می‌شود. برای مثال، قطعه‌کد زیر بسته به محل قرارگیری خود از مسیرهای نشان‌داده‌شده استفاده می‌کند:

    #[path = "foo.rs"]
mod c;
    فایل منبعمحل فایل cمسیر ماژول c
    src/a/b.rssrc/a/foo.rscrate::a::b::c
    src/a/mod.rssrc/a/foo.rscrate::a::c
    [items.mod.outlined.path.search-nested]

    برای ویژگی‌های path درون بلوک‌های ماژول درون‌خطی، محل نسبی مسیر فایل به نوع فایل منبعی بستگی دارد که ویژگی path در آن قرار گرفته است. فایل‌های منبع «mod-rs» شامل ماژول‌های ریشه (مانند lib.rs یا main.rs) و ماژول‌هایی با فایل mod.rs هستند. فایل‌های منبع «non-mod-rs» همهٔ فایل‌های ماژول دیگرند. مسیر ویژگی path درون بلوک ماژول درون‌خطیِ یک فایل mod-rs نسبت به دایرکتوری همان فایل سنجیده می‌شود و اجزای ماژول درون‌خطی نیز به‌صورت دایرکتوری در مسیر قرار می‌گیرند. در فایل‌های non-mod-rs نیز همین قاعده برقرار است، با این تفاوت که مسیر با دایرکتوری هم‌نام ماژول non-mod-rs آغاز می‌شود. برای مثال، قطعه‌کد زیر بسته به محل خود از مسیرهای نشان‌داده‌شده استفاده می‌کند:

    mod inline {
    #[path = "other.rs"]
    mod inner;
}
    فایل منبعمحل فایل innerمسیر ماژول inner
    src/a/b.rssrc/a/b/inline/other.rscrate::a::b::inline::inner
    src/a/mod.rssrc/a/inline/other.rscrate::a::inline::inner

    نمونه‌ای از ترکیب قواعد بالا برای ویژگی path روی ماژول‌های درون‌خطی و ماژول‌های تودرتوی داخل آن‌ها (قابل اعمال به فایل‌های mod-rs و non-mod-rs):

    #[path = "thread_files"]
mod thread {
    // Load the `local_data` module from `thread_files/tls.rs` relative to
    // this source file's directory.
    #[path = "tls.rs"]
    mod local_data;
}
    [items.mod.attributes]

    ویژگی‌های روی ماژول‌ها

    [items.mod.attributes.intro]

    ماژول‌ها مانند همهٔ آیتم‌ها ویژگی‌های بیرونی را می‌پذیرند. آن‌ها ویژگی‌های درونی را نیز می‌پذیرند: برای ماژول دارای بدنه، پس از {؛ و در فایل منبع، در ابتدای فایل و پس از BOM و shebang اختیاری.

    [items.mod.attributes.supported]

    ویژگی‌های داخلی‌ای که روی ماژول معنا دارند عبارت‌اند از: cfg، ‏deprecated، ‏doc، ویژگی‌های بررسی lint، ‏path و no_implicit_prelude. ماژول‌ها ویژگی‌های ماکرویی را نیز می‌پذیرند.
