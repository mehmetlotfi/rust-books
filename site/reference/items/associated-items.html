    [items.associated.intro]

    اقلام وابسته اقلامی هستند که در صفت‌ها اعلان یا در پیاده‌سازی‌ها تعریف می‌شوند. دلیل این نام آن است که روی یک نوع وابسته ــ نوع موجود در پیاده‌سازی ــ تعریف می‌شوند.

    [items.associated.kinds]

    این اقلام زیرمجموعه‌ای از گونه‌های اقلام قابل اعلان در یک ماژول هستند. به‌طور مشخص، شامل تابع‌های وابسته (از جمله متدها)، نوع‌های وابسته و ثابت‌های وابسته می‌شوند.

    [items.associated.related]

    اقلام وابسته زمانی سودمندند که از نظر منطقی با قلمی که به آن وابسته‌اند ارتباط داشته باشند. برای نمونه، متد is_some روی Option ذاتاً با Optionها مرتبط است و بنابراین باید وابسته باشد.

    [items.associated.decl-def]

    هر گونه قلم وابسته دو شکل دارد: تعریف‌هایی که پیاده‌سازی واقعی را در خود دارند و اعلان‌هایی که امضای تعریف‌ها را اعلان می‌کنند.

    [items.associated.trait-items]

    همین اعلان‌ها هستند که قرارداد صفت‌ها و امکانات در دسترس روی نوع‌های عمومی را تشکیل می‌دهند.

    [items.associated.fn]

    تابع‌ها و متدهای وابسته

    [items.associated.fn.intro]

    تابع‌های وابسته تابع‌هایی هستند که به یک نوع وابسته‌اند.

    [items.associated.fn.decl]

    اعلان تابع وابسته امضایی برای تعریف یک تابع وابسته اعلان می‌کند. این اعلان مانند یک قلم تابع نوشته می‌شود، با این تفاوت که بدنهٔ تابع با ; جایگزین می‌شود.

    [items.associated.name]

    شناسه، نام تابع است.

    [items.associated.same-signature]

    پارامترهای عمومی (generics)، فهرست پارامترها، نوع بازگشتی و بند where تابع وابسته باید با موارد متناظر در اعلان تابع وابسته یکسان باشند.

    [items.associated.fn.def]

    تعریف تابع وابسته تابعی را تعریف می‌کند که به نوع دیگری وابسته است. این تعریف همانند یک قلم تابع نوشته می‌شود.

    Note

    نکته نمونه‌ای رایج، تابع وابسته‌ای به نام new است که مقداری از نوع وابسته به خود را بازمی‌گرداند.

    struct Struct {
    field: i32
}

impl Struct {
    fn new() -> Struct {
        Struct {
            field: 0i32
        }
    }
}

fn main () {
    let _struct = Struct::new();
}
    [items.associated.fn.qualified-self]

    وقتی تابع وابسته روی یک صفت اعلان شود، می‌توان تابع را با مسیری نیز فراخواند که مسیر صفت است و نام تابع به انتهای آن افزوده شده است. در این حالت، مسیر با <_ as Trait>::function_name جایگزین می‌شود.

    trait Num {
    fn from_i32(n: i32) -> Self;
}

impl Num for f64 {
    fn from_i32(n: i32) -> f64 { n as f64 }
}

// These 4 are all equivalent in this case.
let _: f64 = Num::from_i32(42);
let _: f64 = <_ as Num>::from_i32(42);
let _: f64 = <f64 as Num>::from_i32(42);
let _: f64 = f64::from_i32(42);
    [items.associated.fn.method]

    متدها

    [items.associated.fn.method.intro]

    تابع‌های وابسته‌ای که نخستین پارامترشان self نام دارد، متد نامیده می‌شوند و می‌توان آن‌ها را با عملگر فراخوانی متد، برای نمونه x.foo()، و نیز با نگارش عادی فراخوانی تابع اجرا کرد.

    [items.associated.fn.method.self-ty]

    اگر نوع پارامتر self مشخص شود، به نوع‌هایی محدود است که به یکی از نوع‌های تولیدشده با دستور زبان زیر تفکیک شوند ('lt یک طول‌عمر دلخواه را نشان می‌دهد):

    P = &'lt S | &'lt mut S | Box<S> | Rc<S> | Arc<S> | Pin<P>
S = Self | P

    پایانهٔ Self در این دستور زبان نوعی را نشان می‌دهد که به نوع پیاده‌ساز تفکیک می‌شود. این مورد می‌تواند نام مستعار نوع بافتی Self، نام‌های مستعار نوع دیگر یا تصویر نوع وابسته‌ای را نیز شامل شود که به نوع پیاده‌ساز تفکیک می‌شود.

    use std::rc::Rc;
use std::sync::Arc;
use std::pin::Pin;
// Examples of methods implemented on struct `Example`.
struct Example;
type Alias = Example;
trait Trait { type Output; }
impl Trait for Example { type Output = Example; }
impl Example {
    fn by_value(self: Self) {}
    fn by_ref(self: &Self) {}
    fn by_ref_mut(self: &mut Self) {}
    fn by_box(self: Box<Self>) {}
    fn by_rc(self: Rc<Self>) {}
    fn by_arc(self: Arc<Self>) {}
    fn by_pin(self: Pin<&Self>) {}
    fn explicit_type(self: Arc<Example>) {}
    fn with_lifetime<'a>(self: &'a Self) {}
    fn nested<'a>(self: &mut &'a Arc<Rc<Box<Alias>>>) {}
    fn via_projection(self: <Example as Trait>::Output) {}
}
    [associated.fn.method.self-pat-shorthands]

    می‌توان بدون مشخص کردن نوع از نحو کوتاه‌شده استفاده کرد که معادل‌های زیر را دارد:

    شکل کوتاهمعادل
    selfself: Self
    &'lifetime selfself: &'lifetime Self
    &'lifetime mut selfself: &'lifetime mut Self

    Note

    نکته در این شکل کوتاه، طول‌عمرها می‌توانند حذف شوند و معمولاً نیز حذف می‌شوند.

    [associated.fn.method.self-pat-mut]

    اگر پیش از پارامتر self واژهٔ mut بیاید، پارامتر مانند پارامترهای عادی که از یک الگوی شناسه همراه با mut استفاده می‌کنند، به یک متغیر تغییرپذیر تبدیل می‌شود. برای نمونه:

    trait Changer: Sized {
    fn change(mut self) {}
    fn modify(mut self: Box<Self>) {}
}

    به‌عنوان نمونه‌ای از متدهای یک صفت، کد زیر را در نظر بگیرید:

    type Surface = i32;
type BoundingBox = i32;
trait Shape {
    fn draw(&self, surface: Surface);
    fn bounding_box(&self) -> BoundingBox;
}

    این کد صفتی با دو متد تعریف می‌کند. هر مقداری که پیاده‌سازی‌ای از این صفت داشته باشد، تا زمانی که صفت در دامنه باشد، می‌تواند متدهای draw و bounding_box خود را فراخوانی کند.

    type Surface = i32;
type BoundingBox = i32;
trait Shape {
    fn draw(&self, surface: Surface);
    fn bounding_box(&self) -> BoundingBox;
}

struct Circle {
    // ...
}

impl Shape for Circle {
    // ...
  fn draw(&self, _: Surface) {}
  fn bounding_box(&self) -> BoundingBox { 0i32 }
}

impl Circle {
    fn new() -> Circle { Circle{} }
}

let circle_shape = Circle::new();
let bounding_box = circle_shape.bounding_box();

    [items.associated.fn.param-attributes]

    ویژگی‌های پارامترهای متد

    ویژگی‌های پارامترهای متد از همان قواعد و محدودیت‌های پارامترهای عادی تابع پیروی می‌کنند.

    [items.associated.type]

    نوع‌های وابسته

    [items.associated.type.intro]

    نوع‌های وابسته نام‌های مستعار نوعی هستند که به نوع دیگری وابسته‌اند.

    [items.associated.type.restrictions]

    نوع‌های وابسته را نمی‌توان در پیاده‌سازی‌های ذاتی تعریف کرد و در صفت‌ها نیز نمی‌توان برای آن‌ها پیاده‌سازی پیش‌فرض فراهم کرد.

    [items.associated.type.decl]

    اعلان نوع وابسته امضایی برای تعریف‌های نوع وابسته اعلان می‌کند. این اعلان در یکی از شکل‌های زیر نوشته می‌شود؛ Assoc نام نوع وابسته، Params فهرستی جداشده با ویرگول از پارامترهای نوع، طول‌عمر یا ثابت، Bounds فهرستی جداشده با علامت جمع از کران‌های صفتی که نوع وابسته باید برآورده کند و WhereBounds فهرستی جداشده با ویرگول از کران‌هایی است که پارامترها باید برآورده کنند:

    type Assoc;
type Assoc: Bounds;
type Assoc<Params>;
type Assoc<Params>: Bounds;
type Assoc<Params> where WhereBounds;
type Assoc<Params>: Bounds where WhereBounds;
    [items.associated.type.name]

    شناسه، نام type alias اعلان‌شده است.

    [items.associated.type.impl-fulfillment]

    پیاده‌سازی‌های نام مستعار نوع باید کران‌های اختیاری صفت را برآورده کنند.

    [items.associated.type.sized]

    روی نوع‌های وابسته یک کران ضمنی Sized وجود دارد که با کران ویژهٔ ?Sized می‌توان آن را آسان‌گیر کرد.

    [items.associated.type.def]

    تعریف نوع وابسته نام مستعار نوعی را برای پیاده‌سازی یک صفت روی یک نوع تعریف می‌کند.

    [items.associated.type.def-restriction]

    این تعریف مشابه اعلان نوع وابسته نوشته می‌شود، اما نمی‌تواند Bounds داشته باشد و در عوض باید یک Type داشته باشد:

    type Assoc = Type;
type Assoc<Params> = Type; // the type `Type` here may reference `Params`
type Assoc<Params> = Type where WhereBounds;
type Assoc<Params> where WhereBounds = Type; // deprecated, prefer the form above
    [items.associated.type.alias]

    اگر نوع Item یک نوع وابستهٔ Assoc از صفت Trait داشته باشد، آنگاه <Item as Trait>::Assoc نوعی است که نام مستعار نوع مشخص‌شده در تعریف نوع وابسته به شمار می‌آید.

    [items.associated.type.param]

    افزون بر این، اگر Item پارامتر نوع باشد، می‌توان Item::Assoc را در پارامترهای نوع به کار برد.

    [items.associated.type.generic]

    نوع‌های وابسته می‌توانند پارامترهای عمومی و بندهای where داشته باشند؛ این نوع‌ها اغلب نوع‌های وابستهٔ عمومی یا GAT نامیده می‌شوند. اگر نوع Thing از صفت Trait یک نوع وابستهٔ Item با پارامتر عمومی <'a> داشته باشد، می‌توان آن نوع را به‌شکل <Thing as Trait>::Item<'x> نامید که در آن 'x طول‌عمری در دامنه است. در این حالت، هرجا 'a در تعریف نوع وابسته روی impl ظاهر شود، 'x جای آن به کار می‌رود.

    trait AssociatedType {
    // Associated type declaration
    type Assoc;
}

struct Struct;

struct OtherStruct;

impl AssociatedType for Struct {
    // Associated type definition
    type Assoc = OtherStruct;
}

impl OtherStruct {
    fn new() -> OtherStruct {
        OtherStruct
    }
}

fn main() {
    // Usage of the associated type to refer to OtherStruct as <Struct as AssociatedType>::Assoc
    let _other_struct: OtherStruct = <Struct as AssociatedType>::Assoc::new();
}

    نمونه‌ای از نوع‌های وابسته دارای پارامتر عمومی و بندهای where:

    struct ArrayLender<'a, T>(&'a mut [T; 16]);

trait Lend {
    // Generic associated type declaration
    type Lender<'a> where Self: 'a;
    fn lend<'a>(&'a mut self) -> Self::Lender<'a>;
}

impl<T> Lend for [T; 16] {
    // Generic associated type definition
    type Lender<'a> = ArrayLender<'a, T> where Self: 'a;

    fn lend<'a>(&'a mut self) -> Self::Lender<'a> {
        ArrayLender(self)
    }
}

fn borrow<'a, T: Lend>(array: &'a mut T) -> <T as Lend>::Lender<'a> {
    array.lend()
}

fn main() {
    let mut array = [0usize; 16];
    let lender = borrow(&mut array);
}

    نمونهٔ ظرف نوع‌های وابسته

    مثال زیر از یک صفت Container را در نظر بگیرید. توجه کنید که نوع برای استفاده در امضاهای متد در دسترس است:

    trait Container {
    type E;
    fn empty() -> Self;
    fn insert(&mut self, elem: Self::E);
}

    برای اینکه نوعی این صفت را پیاده‌سازی کند، نه‌تنها باید برای همهٔ متدها پیاده‌سازی فراهم کند، بلکه باید نوع E را نیز مشخص کند. این یک پیاده‌سازی Container برای نوع Vec از کتابخانهٔ استاندارد است:

    trait Container {
    type E;
    fn empty() -> Self;
    fn insert(&mut self, elem: Self::E);
}
impl<T> Container for Vec<T> {
    type E = T;
    fn empty() -> Vec<T> { Vec::new() }
    fn insert(&mut self, x: T) { self.push(x); }
}

    رابطهٔ میان Bounds و WhereBounds

    در این مثال:

    use std::fmt::Debug;
trait Example {
    type Output<T>: Ord where T: Debug;
}

    با داشتن ارجاعی به نوع وابسته مانند <X as Example>::Output<Y>، خود نوع وابسته باید Ord و نوع Y باید Debug باشد.

    [items.associated.type.generic-where-clause]

    بندهای where الزامی روی نوع‌های وابستهٔ عمومی

    [items.associated.type.generic-where-clause.intro]

    اعلان نوع‌های وابستهٔ عمومی روی صفت‌ها در حال حاضر ممکن است به فهرستی از بندهای where نیاز داشته باشد که به تابع‌های صفت و شیوهٔ استفاده از GAT وابسته است. ممکن است این قواعد در آینده آسان‌گیرتر شوند؛ به‌روزرسانی‌ها در مخزن طرح نوع‌های وابستهٔ عمومی در دسترس‌اند.

    [items.associated.type.generic-where-clause.valid-fn]

    به‌طور خلاصه، این بندهای where لازم‌اند تا تعریف‌های مجاز نوع وابسته در implها بیشینه شوند. برای این کار، هر بندی که بتوان اثبات کرد برقرار است، روی تابع‌هایی (با استفاده از پارامترهای تابع یا trait) که GAT در ورودی یا خروجی آن‌ها ظاهر می‌شود، باید روی خود GAT نیز نوشته شود.

    trait LendingIterator {
    type Item<'x> where Self: 'x;
    fn next<'a>(&'a mut self) -> Self::Item<'a>;
}

    در کد بالا، روی تابع next می‌توان به‌دلیل کران ضمنی حاصل از &'a mut self ثابت کرد که Self: 'a؛ بنابراین باید کران هم‌ارز آن، یعنی where Self: 'x، را روی خود GAT بنویسیم.

    [items.associated.type.generic-where-clause.intersection]

    وقتی چند تابع در یک صفت از GAT استفاده کنند، به‌جای اجتماع، اشتراک کران‌های تابع‌های مختلف به کار می‌رود.

    trait Check<T> {
    type Checker<'x>;
    fn create_checker<'a>(item: &'a T) -> Self::Checker<'a>;
    fn do_check(checker: Self::Checker<'_>);
}

    در این مثال، هیچ کرانی روی type Checker<'a>; لازم نیست. هرچند روی create_checker می‌دانیم T: 'a، روی do_check چنین دانشی نداریم. با این حال، اگر do_check توضیح‌شده و از کد خارج می‌شد، کران where T: 'x روی Checker الزامی بود.

    [items.associated.type.generic-where-clause.forward]

    کران‌های (bounds) روی نوع‌های وابسته نیز بندهای where الزامی را منتقل می‌کنند.

    trait Iterable {
    type Item<'a> where Self: 'a;
    type Iterator<'a>: Iterator<Item = Self::Item<'a>> where Self: 'a;
    fn iter<'a>(&'a self) -> Self::Iterator<'a>;
}

    در اینجا where Self: 'a به‌دلیل iter روی Item الزامی است. با این حال، چون Item در کران‌های Iterator استفاده شده، بند where Self: 'a در آنجا نیز لازم است.

    [items.associated.type.generic-where-clause.static]

    در پایان، استفاده‌های صریح از 'static روی GATها در صفت، جزو کران‌های الزامی به شمار نمی‌آیند.

    trait StaticReturn {
    type Y<'a>;
    fn foo(&self) -> Self::Y<'static>;
}
    [items.associated.const]

    ثابت‌های وابسته

    [items.associated.const.intro]

    ثابت‌های وابسته ثابت‌هایی هستند که به یک نوع وابسته‌اند.

    [items.associated.const.decl]

    اعلان ثابت وابسته امضایی برای تعریف ثابت‌های وابسته اعلان می‌کند. این اعلان با const، سپس یک شناسه، سپس :، یک نوع و در پایان ; نوشته می‌شود.

    [items.associated.const.name]

    شناسه نام ثابتی است که در مسیر استفاده می‌شود. نوع نیز نوعی است که تعریف باید پیاده کند.

    [items.associated.const.def]

    تعریف ثابت وابسته ثابتی وابسته به یک نوع را تعریف می‌کند. این تعریف همانند یک قلم ثابت نوشته می‌شود.

    [items.associated.const.eval]

    تعریف ثابت‌های وابسته تنها هنگام ارجاع، تحت ارزیابی ثابت قرار می‌گیرد. افزون بر این، تعریف‌های دارای پارامترهای عمومی پس از تک‌ریخت‌سازی ارزیابی می‌شوند.

    struct Struct;
struct GenericStruct<const ID: i32>;

impl Struct {
    // Definition not immediately evaluated
    const PANIC: () = panic!("compile-time panic");
}

impl<const ID: i32> GenericStruct<ID> {
    // Definition not immediately evaluated
    const NON_ZERO: () = if ID == 0 {
        panic!("contradiction")
    };
}

fn main() {
    // Referencing Struct::PANIC causes compilation error
    let _ = Struct::PANIC;

    // Fine, ID is not 0
    let _ = GenericStruct::<1>::NON_ZERO;

    // Compilation error from evaluating NON_ZERO with ID=0
    let _ = GenericStruct::<0>::NON_ZERO;
}
