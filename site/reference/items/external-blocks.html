    [items.extern.intro]

    بلوک‌های خارجی اعلان‌های اقلامی را فراهم می‌کنند که در کریت جاری تعریف نشده‌اند و مبنای رابط تابع خارجی Rust هستند. این اعلان‌ها شبیه واردسازی‌های کنترل‌نشده‌اند.

    [items.extern.allowed-kinds]

    دو گونه اعلان قلم در بلوک خارجی مجاز است: تابع‌ها و اقلام ایستا.

    [items.extern.safety]

    فراخوانی تابع‌های ناامن یا دسترسی به اقلام ایستای ناامنِ اعلان‌شده در بلوک‌های خارجی تنها در یک بافت unsafe مجاز است.

    [items.extern.namespace]

    بلوک خارجی تابع‌ها و اقلام ایستای خود را در فضای نام مقدار ماژول یا بلوکی که در آن قرار دارد تعریف می‌کند.

    [items.extern.unsafe-required]

    از نظر معنایی لازم است کلیدواژهٔ unsafe پیش از کلیدواژهٔ extern در بلوک‌های خارجی بیاید.

    [items.extern.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴، کلیدواژهٔ unsafe اختیاری است. توصیف‌گرهای قلم safe و unsafe تنها زمانی مجازند که خود بلوک خارجی با unsafe علامت‌گذاری شده باشد.

    [items.extern.fn]

    تابع‌ها

    [items.extern.fn.body]

    تابع‌های درون بلوک خارجی همانند دیگر تابع‌های Rust اعلان می‌شوند، جز اینکه نباید بدنه داشته باشند و به‌جای آن با نقطه‌ویرگول پایان می‌یابند.

    [items.extern.fn.param-patterns]

    الگوها در پارامترها مجاز نیستند و فقط می‌توان از IDENTIFIER یا _ استفاده کرد.

    [items.extern.fn.qualifiers]

    توصیف‌گرهای تابع safe و unsafe مجازند، اما دیگر توصیف‌گرها مانند const، async و extern مجاز نیستند. توصیف‌گر safe در بلوک‌های extern "custom" رد می‌شود.

    [items.extern.fn.foreign-abi]

    تابع‌های درون بلوک خارجی را می‌توان درست مانند تابع‌های تعریف‌شده در Rust، از کد Rust فراخواند. کامپایلر Rust به‌طور خودکار میان ABI‏ Rust و ABI خارجی تبدیل انجام می‌دهد.

    [items.extern.fn.safety]

    تابعی که در بلوک extern اعلان شده است، مگر آنکه توصیف‌گر تابع safe را داشته باشد، به‌طور ضمنی unsafe است.

    [items.extern.fn.fn-ptr]

    هنگام واداشته شدن به یک اشاره‌گر تابع، تابعی که در بلوک extern اعلان شده نوع for<'l1, ..., 'lm> extern "abi" fn(A1, ..., An) -> R دارد؛ در آن 'l1 تا 'lm پارامترهای طول‌عمر، A1 تا An نوع‌های اعلان‌شدهٔ پارامترها و R نوع بازگشتی اعلان‌شده هستند.

    [items.extern.static]

    اقلام ایستا

    [items.extern.static.intro]

    اقلام ایستای درون بلوک خارجی همانند اقلام ایستا بیرون از بلوک خارجی اعلان می‌شوند، جز اینکه عبارتی برای مقداردهی اولیهٔ مقدارشان ندارند.

    [items.extern.static.safety]

    مگر آنکه قلم ایستای اعلان‌شده در بلوک extern با safe توصیف شده باشد، دسترسی به آن قلم ــ چه تغییرپذیر باشد و چه نباشد ــ unsafe است. علت آن است که هیچ تضمینی وجود ندارد الگوی بیت در حافظهٔ قلم ایستا برای نوع اعلان‌شدهٔ آن معتبر باشد، زیرا کدی دلخواه (برای نمونه کد C) مسئول مقداردهی اولیهٔ آن است.

    [items.extern.static.mut]

    اقلام ایستای خارجی، مانند اقلام ایستا بیرون از بلوک خارجی، می‌توانند تغییرپذیر یا تغییرناپذیر باشند.

    [items.extern.static.read-only]

    یک قلم ایستای تغییرناپذیر باید پیش از اجرای هر کد Rust مقداردهی اولیه شده باشد؛ کافی نیست که فقط پیش از خواندن آن به‌وسیلهٔ کد Rust مقداردهی شود. پس از آغاز اجرای کد Rust، تغییر دادن یک قلم ایستای تغییرناپذیر (از داخل یا بیرون Rust) رفتاری تعریف‌نشده است، مگر آنکه تغییر روی بایت‌های درون یک UnsafeCell رخ دهد.

    [items.extern.abi]

    ABI

    [items.extern.abi.intro]

    پس از کلیدواژهٔ extern می‌توان یک رشتهٔ اختیاری ABI آورد. ABI قرارداد فراخوانی تابع‌های بلوک را مشخص می‌کند. قرارداد فراخوانی رابط سطح‌پایین تابع‌ها را تعریف می‌کند؛ از جمله اینکه آرگومان‌ها چگونه در ثبات‌ها یا پشته قرار گیرند، مقادیر بازگشتی چگونه پاس داده شوند و مسئول پاک‌سازی پشته چه کسی باشد.

    مثال

    // Interface to the Windows API.
unsafe extern "system" { /* ... */ }
    [items.extern.abi.default]

    اگر رشتهٔ ABI مشخص نشده باشد، مقدار پیش‌فرض آن "C" است.

    Note

    نکته نحو extern بدون ABI صریح در حال کنار گذاشته شدن است؛ بنابراین بهتر است همیشه ABI را صریح بنویسید.

    برای جزئیات بیشتر، مسئلهٔ شمارهٔ 134986 در Rust را ببینید.

    [items.extern.abi.standard]

    رشته‌های ABI زیر روی همهٔ سکوها پشتیبانی می‌شوند:

    [items.extern.abi.rust]
    • unsafe extern "Rust" ــ قرارداد فراخوانی بومی تابع‌ها و بستارهای Rust. وقتی تابعی بدون extern fn اعلان شود، این قرارداد پیش‌فرض است. ABI‏ Rust هیچ تضمینی برای پایداری ندارد.
    [items.extern.abi.c]
    • unsafe extern "C" ــ ABI‏ «C» با ABI پیش‌فرضی مطابقت دارد که کامپایلر غالب C برای هدف انتخاب می‌کند.
    [items.extern.abi.system]

    • unsafe extern "system" ــ با extern "C" یکسان است، جز روی Windows x86_32 که برای تابع‌های غیرمتغیر معادل "stdcall" و برای تابع‌های متغیر معادل "C" است.

      Note

      نکته از آنجا که ABI زیربنایی درست در Windows به هدف وابسته است، هنگام تلاش برای پیوند تابع‌های API‏ Windows که ABI صریحی ندارند بهتر است از extern "system" استفاده کنید.

    [items.extern.abi.unwind]
    • extern "C-unwind" و extern "system-unwind" ــ به‌ترتیب با "C" و "system" یکسان‌اند، اما هنگام بازپیچی تابع فراخوانده‌شده (با وحشت یا پرتاب استثنایی به سبک C++) رفتار متفاوتی دارند.
    [items.extern.abi.custom]
    • unsafe extern "custom" ــ یک ABI سفارشی که برای کامپایلر شناخته‌شده نیست.
    [items.extern.abi.platform]

    چند رشتهٔ ABI وابسته به سکو نیز وجود دارد:

    [items.extern.abi.cdecl]

    • unsafe extern "cdecl" ــ قرارداد فراخوانی‌ای که معمولاً با کد C روی x86_32 استفاده می‌شود.

      • فقط روی هدف‌های x86_32 در دسترس است.
      • متناظر با __cdecl در MSVC و __attribute__((cdecl)) در GCC و clang است.

      Note

      نکته برای جزئیات ببینید:

      • https://learn.microsoft.com/en-us/cpp/cpp/cdecl
      • https://en.wikipedia.org/wiki/X86_calling_conventions#cdecl
    [items.extern.abi.stdcall]

    • unsafe extern "stdcall" ــ قرارداد فراخوانی‌ای که معمولاً API‏ Win32 روی x86_32 به کار می‌برد.

      • فقط روی هدف‌های x86_32 در دسترس است.
      • متناظر با __stdcall در MSVC و __attribute__((stdcall)) در GCC و clang است.

      Note

      نکته برای جزئیات ببینید:

      • https://learn.microsoft.com/en-us/cpp/cpp/stdcall
      • https://en.wikipedia.org/wiki/X86_calling_conventions#stdcall
    [items.extern.abi.win64]

    • unsafe extern "win64" ــ ABI‏ x64 ویندوز.

      • فقط روی هدف‌های x86_64 در دسترس است.
      • "win64" روی هدف‌های Windows x86_64 همان ABI "C" است.
      • متناظر با __attribute__((ms_abi)) در GCC و clang است.

      Note

      نکته برای جزئیات ببینید:

      • https://learn.microsoft.com/en-us/cpp/build/x64-software-conventions
      • https://en.wikipedia.org/wiki/X86_calling_conventions#Microsoft_x64_calling_convention
    [items.extern.abi.sysv64]

    • unsafe extern "sysv64" ــ ABI‏ System V.

      • فقط روی هدف‌های x86_64 در دسترس است.
      • "sysv64" روی هدف‌های x86_64 غیر Windows همان ABI "C" است.
      • متناظر با __attribute__((sysv_abi)) در GCC و clang است.

      Note

      نکته برای جزئیات ببینید:

      • https://wiki.osdev.org/System_V_ABI
      • https://en.wikipedia.org/wiki/X86_calling_conventions#System_V_AMD64_ABI
    [items.extern.abi.aapcs]

    • unsafe extern "aapcs" ــ ABI ممیزشناور نرم برای ARM.

      • فقط روی هدف‌های ARM32 در دسترس است.
      • "aapcs" روی ARM32 با ممیزشناور نرم همان ABI‏ "C" است.
      • متناظر با __attribute__((pcs("aapcs"))) در clang است.

      Note

      نکته برای جزئیات ببینید:

      • استاندارد فراخوانی رویهٔ Arm
    [items.extern.abi.fastcall]

    • unsafe extern "fastcall" ــ گونه‌ای «سریع» از stdcall که برخی آرگومان‌ها را در ثبات‌ها پاس می‌دهد.

      • فقط روی هدف‌های x86_32 در دسترس است.
      • متناظر با __fastcall در MSVC و __attribute__((fastcall)) در GCC و clang است.

      Note

      نکته برای جزئیات ببینید:

      • https://learn.microsoft.com/en-us/cpp/cpp/fastcall
      • https://en.wikipedia.org/wiki/X86_calling_conventions#Microsoft_fastcall
    [items.extern.abi.thiscall]

    • unsafe extern "thiscall" ــ قرارداد فراخوانی‌ای که معمولاً برای تابع‌های عضو کلاس C++ در MSVC روی x86_32 استفاده می‌شود.

      • فقط روی هدف‌های x86_32 در دسترس است.
      • متناظر با __thiscall در MSVC و __attribute__((thiscall)) در GCC و clang است.

      Note

      نکته برای جزئیات ببینید:

      • https://en.wikipedia.org/wiki/X86_calling_conventions#thiscall
      • https://learn.microsoft.com/en-us/cpp/cpp/thiscall
    [items.extern.abi.efiapi]
    • unsafe extern "efiapi" ــ ABI مورد استفاده برای تابع‌های UEFI.
      • فقط روی هدف‌های x86 و ARM (۳۲بیتی و ۶۴بیتی) در دسترس است.
    [items.extern.abi.platform-unwind-variants]

    همانند "C" و "system"، بیشتر رشته‌های ABI وابسته به سکو نیز گونهٔ -unwind متناظری دارند؛ این گونه‌ها عبارت‌اند از:

    • "aapcs-unwind"
    • "cdecl-unwind"
    • "fastcall-unwind"
    • "stdcall-unwind"
    • "sysv64-unwind"
    • "thiscall-unwind"
    • "win64-unwind"
    [items.extern.variadic]

    تابع‌های متغیر

    [items.extern.variadic.syntax]

    تابع‌های درون بلوک خارجی را می‌توان با مشخص کردن ... به‌عنوان آخرین پارامتر، متغیر کرد. پارامتر متغیر می‌تواند با یک الگو مشخص شود.

    unsafe extern "C" {
    unsafe fn foo(...);
    unsafe fn bar(x: i32, ...);
    unsafe fn with_name(format: *const u8, args: ...);
    // SAFETY: This function guarantees it will not access
    // variadic arguments.
    safe fn ignores_variadic_arguments(x: i32, ...);
}

    Warning

    هشدار توصیف‌گر safe نباید روی تابعی در بلوک extern به کار رود، مگر آنکه تابع تضمین کند اصلاً به آرگومان‌های متغیر دسترسی نخواهد داشت. پاس دادن شمار پیش‌بینی‌نشده‌ای از آرگومان‌ها یا آرگومان‌هایی با نوع پیش‌بینی‌نشده به یک تابع متغیر ممکن است به رفتار تعریف‌نشده منجر شود.

    [items.extern.variadic.conventions]

    پارامترهای متغیر تنها در بلوک‌های extern با یکی از رشته‌های ABI زیر یا گونهٔ -unwind متناظرشان قابل مشخص شدن هستند:

    • "aapcs"
    • "C"
    • "cdecl"
    • "efiapi"
    • "system"
    • "sysv64"
    • "win64"
    [items.extern.attributes]

    ویژگی‌ها (attributes) روی بلوک‌های extern

    [items.extern.attributes.intro]

    ویژگی‌های زیر رفتار بلوک‌های خارجی را کنترل می‌کنند.

    [items.extern.attributes.link]

    ویژگی link

    [items.extern.attributes.link.intro]

    ویژگی link نام کتابخانهٔ بومی‌ای را مشخص می‌کند که کامپایلر باید برای اقلام درون یک بلوک extern به آن پیوند بخورد.

    [items.extern.attributes.link.syntax]

    این ویژگی برای مشخص کردن ورودی‌ها از نحو MetaListNameValueStr استفاده می‌کند. کلید name نام کتابخانهٔ بومی برای پیوند است. کلید kind مقداری اختیاری است که گونهٔ کتابخانه را با یکی از مقادیر ممکن زیر مشخص می‌کند:

    [items.extern.attributes.link.dylib]
    • dylib ــ یک کتابخانهٔ پویا را نشان می‌دهد. اگر kind مشخص نشده باشد، این مقدار پیش‌فرض است.
    [items.extern.attributes.link.static]
    • static ــ یک کتابخانهٔ ایستا را نشان می‌دهد.
    [items.extern.attributes.link.framework]
    • framework ــ یک چارچوب macOS را نشان می‌دهد. این مقدار فقط برای هدف‌های macOS معتبر است.
    [items.extern.attributes.link.raw-dylib]
    • raw-dylib ــ کتابخانهٔ پویایی را نشان می‌دهد که کامپایلر برای پیوند با آن یک کتابخانهٔ واردسازی تولید می‌کند (برای جزئیات، مقایسهٔ dylib و raw-dylib در ادامه را ببینید). این مقدار فقط برای هدف‌های Windows معتبر است.
    [items.extern.attributes.link.name-requirement]

    اگر kind مشخص شود، کلید name نیز باید وجود داشته باشد.

    [items.extern.attributes.link.modifiers]

    آرگومان اختیاری modifiers راهی برای تعیین اصلاح‌گرهای پیوند کتابخانه است.

    [items.extern.attributes.link.modifiers-syntax]

    اصلاح‌گرها به‌صورت رشته‌ای جداشده با ویرگول مشخص می‌شوند و پیش از هر اصلاح‌گر، به‌ترتیب برای فعال یا غیرفعال بودن آن، نشانهٔ + یا - می‌آید.

    [items.extern.attributes.link.modifiers-multiple]

    در حال حاضر تعیین چند آرگومان modifiers در یک ویژگی link یا چند اصلاح‌گر یکسان در همان آرگومان modifiers پشتیبانی نمی‌شود. نمونه: #[link(name = "mylib", kind = "static", modifiers = "+whole-archive")].

    [items.extern.attributes.link.wasm_import_module]

    هنگام وارد کردن نمادها از محیط میزبان، می‌توان با کلید wasm_import_module نام ماژول WebAssembly را برای اقلام درون یک بلوک extern مشخص کرد. اگر wasm_import_module مشخص نشود، نام پیش‌فرض ماژول env است.

    #[link(name = "crypto")]
unsafe extern {
    // …
}

#[link(name = "CoreFoundation", kind = "framework")]
unsafe extern {
    // …
}

#[link(wasm_import_module = "foo")]
unsafe extern {
    // …
}
    [items.extern.attributes.link.empty-block]

    افزودن ویژگی link به یک بلوک extern خالی معتبر است. به‌جای افزودن ویژگی به تک‌تک بلوک‌های خارجی، می‌توانید با این روش نیازهای پیوند بلوک‌های خارجی در جاهای دیگر کد خود، از جمله کریت‌های بالادستی، را برآورده کنید.

    [items.extern.attributes.link.modifiers-bundle]

    اصلاح‌گرهای پیوند: bundle

    [items.extern.attributes.link.modifiers-bundle.allowed-kinds]

    این اصلاح‌گر فقط با گونهٔ پیوند static سازگار است. استفاده از هر گونهٔ دیگری به خطای کامپایلر منجر می‌شود.

    [items.extern.attributes.link.modifiers-bundle.behavior]

    هنگام ساخت یک rlib یا staticlib، مقدار +bundle یعنی کتابخانهٔ ایستای بومی در بایگانی rlib یا staticlib بسته‌بندی شود و سپس هنگام پیوند فایل دودویی نهایی از آنجا بازیابی گردد.

    [items.extern.attributes.link.modifiers-bundle.behavior-negative]

    هنگام ساخت rlib، مقدار -bundle یعنی کتابخانهٔ ایستای بومی «با نام» به‌عنوان وابستگی آن rlib ثبت شود و فایل‌های شیء آن فقط هنگام پیوند فایل دودویی نهایی افزوده شوند؛ جست‌وجوی فایل با آن نام نیز هنگام پیوند نهایی انجام می‌شود. هنگام ساخت staticlib، مقدار -bundle یعنی کتابخانهٔ ایستای بومی اصلاً در بایگانی گنجانده نشود و سامانهٔ ساخت سطح بالاتری لازم باشد آن را بعداً هنگام پیوند فایل دودویی نهایی اضافه کند.

    [items.extern.attributes.link.modifiers-bundle.no-effect]

    این اصلاح‌گر هنگام ساخت هدف‌های دیگر مانند فایل‌های اجرایی یا کتابخانه‌های پویا اثری ندارد.

    [items.extern.attributes.link.modifiers-bundle.default]

    مقدار پیش‌فرض این اصلاح‌گر +bundle است.

    جزئیات پیاده‌سازی بیشتر دربارهٔ این اصلاح‌گر در مستندات bundle برای rustc آمده است.

    [items.extern.attributes.link.modifiers-whole-archive]

    اصلاح‌گرهای پیوند: whole-archive

    [items.extern.attributes.link.modifiers-whole-archive.allowed-kinds]

    این اصلاح‌گر فقط با گونهٔ پیوند static سازگار است. استفاده از هر گونهٔ دیگری به خطای کامپایلر منجر می‌شود.

    [items.extern.attributes.link.modifiers-whole-archive.behavior]

    مقدار +whole-archive یعنی کتابخانهٔ ایستا به‌صورت یک بایگانی کامل و بدون کنار گذاشتن هیچ فایل شیئی پیوند بخورد.

    [items.extern.attributes.link.modifiers-whole-archive.default]

    مقدار پیش‌فرض این اصلاح‌گر -whole-archive است.

    جزئیات پیاده‌سازی بیشتر دربارهٔ این اصلاح‌گر در مستندات whole-archive برای rustc آمده است.

    [items.extern.attributes.link.modifiers-verbatim]

    اصلاح‌گرهای پیوند: verbatim

    [items.extern.attributes.link.modifiers-verbatim.allowed-kinds]

    این اصلاح‌گر با همهٔ گونه‌های پیوند سازگار است.

    [items.extern.attributes.link.modifiers-verbatim.behavior]

    مقدار +verbatim یعنی خود rustc هیچ پیشوند یا پسوند کتابخانهٔ مشخص‌شده برای هدف (مانند lib یا .a) را به نام کتابخانه اضافه نکند و تا جای ممکن همین درخواست را از پیونددهنده نیز داشته باشد.

    [items.extern.attributes.link.modifiers-verbatim.behavior-negative]

    مقدار -verbatim یعنی rustc پیش از فرستادن نام کتابخانه به پیونددهنده، پیشوند و پسوند ویژهٔ هدف را به آن بیفزاید یا از افزودن ضمنی آن‌ها به‌وسیلهٔ پیونددهنده جلوگیری نکند.

    [items.extern.attributes.link.modifiers-verbatim.default]

    مقدار پیش‌فرض این اصلاح‌گر -verbatim است.

    جزئیات پیاده‌سازی بیشتر دربارهٔ این اصلاح‌گر در مستندات verbatim برای rustc آمده است.

    [items.extern.attributes.link.kind-raw-dylib]

    مقایسهٔ dylib با raw-dylib

    [items.extern.attributes.link.kind-raw-dylib.intro]

    در Windows، پیوند با یک کتابخانهٔ پویا نیازمند ارائهٔ کتابخانهٔ واردسازی به پیونددهنده است. این کتابخانه‌ای ایستای ویژه است که همهٔ نمادهای صادرشده از کتابخانهٔ پویا را به شکلی اعلان می‌کند که پیونددهنده بداند باید آن‌ها را هنگام اجرا به‌صورت پویا بارگیری کند.

    [items.extern.attributes.link.kind-raw-dylib.import]

    تعیین kind = "dylib" به کامپایلر Rust فرمان می‌دهد بر پایهٔ کلید name به یک کتابخانهٔ واردسازی پیوند بخورد. سپس پیونددهنده با منطق عادی تفکیک کتابخانهٔ خود آن کتابخانهٔ واردسازی را پیدا می‌کند. در مقابل، تعیین kind = "raw-dylib" به کامپایلر فرمان می‌دهد هنگام کامپایل یک کتابخانهٔ واردسازی تولید و آن را در اختیار پیونددهنده قرار دهد.

    [items.extern.attributes.link.kind-raw-dylib.platform-specific]

    raw-dylib فقط روی Windows پشتیبانی می‌شود. استفاده از آن برای هدف گرفتن سکوهای دیگر به خطای کامپایلر منجر می‌شود.

    [items.extern.attributes.link.import_name_type]

    کلید import_name_type

    [items.extern.attributes.link.import_name_type.intro]

    در Windows روی x86، نام تابع‌ها برای نشان دادن قرارداد فراخوانی خود «تزئین» می‌شوند؛ یعنی پیشوند یا پسوند مشخصی به آن‌ها افزوده می‌شود. برای نمونه، تابعی با قرارداد فراخوانی stdcall و نام fn1 که هیچ آرگومانی ندارد، به‌شکل _fn1@0 تزئین می‌شود. با این حال، قالب PE نام‌های بدون پیشوند یا تزئین‌نشده را نیز مجاز می‌داند. افزون بر این، زنجیره‌ابزارهای MSVC و GNU برای قراردادهای فراخوانی یکسان از تزئین‌های متفاوتی استفاده می‌کنند؛ بنابراین در حالت پیش‌فرض، برخی تابع‌های Win32 را نمی‌توان با گونهٔ پیوند raw-dylib از راه زنجیره‌ابزار GNU فراخواند.

    [items.extern.attributes.link.import_name_type.values]

    برای پشتیبانی از این تفاوت‌ها، هنگام استفاده از گونهٔ پیوند raw-dylib می‌توانید کلید import_name_type را نیز با یکی از مقادیر زیر مشخص کنید تا شیوهٔ نام‌گذاری تابع‌ها در کتابخانهٔ واردسازی تولیدشده تغییر کند:

    • decorated: نام تابع با قالب زنجیره‌ابزار MSVC به‌طور کامل تزئین می‌شود.
    • noprefix: نام تابع با قالب زنجیره‌ابزار MSVC تزئین می‌شود، اما ?، @ یا در صورت وجود _ ابتدایی کنار گذاشته می‌شود.
    • undecorated: نام تابع تزئین نمی‌شود.
    [items.extern.attributes.link.import_name_type.default]

    اگر کلید import_name_type مشخص نشده باشد، نام تابع با قالب زنجیره‌ابزار هدف به‌طور کامل تزئین می‌شود.

    [items.extern.attributes.link.import_name_type.variables]

    متغیرها هرگز تزئین نمی‌شوند؛ بنابراین کلید import_name_type بر شیوهٔ نام‌گذاری آن‌ها در کتابخانهٔ واردسازی تولیدشده اثری ندارد.

    [items.extern.attributes.link.import_name_type.platform-specific]

    کلید import_name_type فقط روی Windows x86 پشتیبانی می‌شود. استفاده از آن برای هدف گرفتن سکوهای دیگر به خطای کامپایلر منجر می‌شود.

    [items.extern.attributes.link_name]

    ویژگی link_name

    [items.extern.attributes.link_name.intro]

    ویژگی link_name را می‌توان روی اعلان‌های درون یک بلوک extern اعمال کرد تا نماد واردشونده برای تابع یا قلم ایستای مورد نظر مشخص شود.

    مثال

    unsafe extern "C" {
    #[link_name = "actual_symbol_name"]
    safe fn name_in_rust();
}
    [items.extern.attributes.link_name.syntax]

    ویژگی link_name از نحو MetaNameValueStr استفاده می‌کند.

    [items.extern.attributes.link_name.invalid-names]

    نام نماد نباید رشتهٔ خالی باشد یا بایت U+0000 (NUL) داشته باشد.

    [items.extern.attributes.link_name.allowed-positions]

    ویژگی link_name فقط می‌تواند روی یک تابع یا قلم ایستا در بلوک extern اعمال شود.

    Note

    نکته rustc استفاده در جایگاه‌های دیگر را نادیده می‌گیرد، اما برای آن لینت صادر می‌کند. این رفتار ممکن است در آینده به خطا تبدیل شود.

    [items.extern.attributes.link_name.duplicates]

    تنها نخستین استفاده از link_name روی یک قلم اثر دارد.

    Note

    نکته rustc برای هر استفاده پس از نخستین مورد، هشداری دربارهٔ سازگاری آینده صادر می‌کند. این رفتار ممکن است در آینده به خطا تبدیل شود.

    [items.extern.attributes.link_name.link_ordinal]

    ویژگی link_name را نمی‌توان همراه ویژگی link_ordinal به کار برد.

    [items.extern.attributes.link_ordinal]

    ویژگی link_ordinal

    [items.extern.attributes.link_ordinal.intro]

    ویژگی link_ordinal را می‌توان روی اعلان‌های درون بلوک extern اعمال کرد تا شمارهٔ ترتیبی عددی مورد استفاده هنگام تولید کتابخانهٔ واردسازی برای پیوند مشخص شود. شمارهٔ ترتیبی برای هر نماد صادرشده از یک کتابخانهٔ پویا در Windows عددی یکتا است و هنگام بارگیری کتابخانه می‌توان به‌جای جست‌وجوی نماد با نام، از آن برای یافتن نماد استفاده کرد.

    Warning

    هشدار link_ordinal فقط باید زمانی استفاده شود که شمارهٔ ترتیبی نماد پایدار باشد. اگر هنگام ساخت فایل دودویی دربرگیرنده، شمارهٔ ترتیبی نماد صریحاً تعیین نشده باشد، مقداری به‌طور خودکار به آن اختصاص می‌یابد و ممکن است میان ساخت‌های مختلف فایل دودویی تغییر کند.

    #[cfg(all(windows, target_arch = "x86"))]
#[link(name = "exporter", kind = "raw-dylib")]
unsafe extern "stdcall" {
    #[link_ordinal(15)]
    safe fn imported_function_stdcall(i: i32);
}
    [items.extern.attributes.link_ordinal.allowed-kinds]

    این ویژگی فقط با گونهٔ پیوند raw-dylib استفاده می‌شود. استفاده از هر گونهٔ دیگری به خطای کامپایلر منجر می‌شود.

    [items.extern.attributes.link_ordinal.exclusive]

    استفاده از این ویژگی همراه ویژگی link_name به خطای کامپایلر منجر می‌شود.
