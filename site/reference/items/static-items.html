    [items.static.intro]

    یک آیتم ایستا شبیه یک ثابت است، با این تفاوت که یک تخصیص حافظه در برنامه را نمایش می‌دهد که با عبارت مقداردهندهٔ اولیه مقداردهی می‌شود. همهٔ ارجاع‌ها و اشاره‌گرهای خام به آن آیتم ایستا، به همان تخصیص اشاره می‌کنند.

    [items.static.lifetime]

    آیتم‌های ایستا طول‌عمر static دارند که از همهٔ طول‌عمرهای دیگر در برنامهٔ Rust بیشتر است. آیتم‌های ایستا در پایان برنامه drop را فراخوانی نمی‌کنند.

    [items.static.storage-disjointness]

    اگر static دست‌کم یک بایت اندازه داشته باشد، تخصیص آن از همهٔ تخصیص‌های static مشابه دیگر و نیز تخصیص‌های heap و متغیرهای تخصیص‌یافته روی stack جداست. بااین‌حال، فضای ذخیره‌سازی آیتم‌های static تغییرناپذیر می‌تواند با تخصیص‌هایی هم‌پوشانی داشته باشد که خودشان نشانی یکتا ندارند؛ مانند مقادیر ارتقایافته و آیتم‌های const.

    [items.static.namespace]

    اعلان static یک مقدار ایستا را در فضای نام مقدار ماژول یا بلوکی که در آن قرار دارد تعریف می‌کند.

    [items.static.init]

    مقداردهندهٔ اولیهٔ static یک عبارت ثابت است که هنگام کامپایل ارزیابی می‌شود. مقداردهنده‌های اولیهٔ static می‌توانند به staticهای دیگر ارجاع دهند و از آن‌ها بخوانند. هنگام خواندن از staticهای تغییرپذیر، مقدار اولیهٔ آن static خوانده می‌شود.

    [items.static.read-only]

    آیتم‌های static بدون mut که نوعشان تغییرپذیری درونی ندارد، ممکن است در حافظهٔ فقط‌خواندنی قرار گیرند.

    [items.static.safety]

    همهٔ دسترسی‌ها به یک static ایمن هستند، اما staticها چند محدودیت دارند:

    [items.static.sync]
    • برای ممکن‌شدن دسترسی ایمن میان نخ‌ها، نوع باید کران صفت Sync داشته باشد.
    [items.static.init-omission]

    عبارت مقداردهندهٔ اولیه باید در یک بلوک خارجی حذف شود و برای آیتم‌های static آزاد ارائه شود.

    [items.static.safety-qualifiers]

    مشخص‌کننده‌های safe و unsafe از نظر معنایی تنها هنگام استفاده در یک بلوک خارجی مجازند.

    [items.static.generics]

    Staticها و عمومی‌ها

    آیتم static تعریف‌شده در یک حوزهٔ عمومی (برای مثال، در یک پیاده‌سازی blanket یا پیش‌فرض) دقیقاً به تعریف یک آیتم static منجر می‌شود؛ گویی تعریف static از حوزهٔ جاری بیرون کشیده و در ماژول قرار داده شده است. برای هر تک‌ریخت‌سازی، آیتم جداگانه‌ای ساخته نخواهد شد.

    این کد:

    use std::sync::atomic::{AtomicUsize, Ordering};

trait Tr {
    fn default_impl() {
        static COUNTER: AtomicUsize = AtomicUsize::new(0);
        println!("default_impl: counter was {}", COUNTER.fetch_add(1, Ordering::Relaxed));
    }

    fn blanket_impl();
}

struct Ty1 {}
struct Ty2 {}

impl<T> Tr for T {
    fn blanket_impl() {
        static COUNTER: AtomicUsize = AtomicUsize::new(0);
        println!("blanket_impl: counter was {}", COUNTER.fetch_add(1, Ordering::Relaxed));
    }
}

fn main() {
    <Ty1 as Tr>::default_impl();
    <Ty2 as Tr>::default_impl();
    <Ty1 as Tr>::blanket_impl();
    <Ty2 as Tr>::blanket_impl();
}

    کد زیر:

    default_impl: counter was 0
default_impl: counter was 1
blanket_impl: counter was 0
blanket_impl: counter was 1
    [items.static.mut]

    Staticهای تغییرپذیر

    [items.static.mut.intro]

    اگر یک آیتم static با کلیدواژهٔ mut اعلان شود، برنامه اجازه دارد آن را تغییر دهد. یکی از هدف‌های Rust دشوارکردن وقوع خطاهای هم‌زمانی است و این نوع داده بدیهی است که می‌تواند منبع بزرگی از شرایط رقابتی یا خطاهای دیگر باشد.

    [items.static.mut.safety]

    به همین دلیل، هم خواندن و هم نوشتن یک متغیر static تغییرپذیر به بلوک unsafe نیاز دارد. باید دقت شود که تغییر static تغییرپذیر نسبت به دیگر نخ‌های در حال اجرای همان فرایند ایمن باشد.

    [items.static.mut.extern]

    بااین‌حال staticهای تغییرپذیر همچنان بسیار سودمندند. می‌توان آن‌ها را با کتابخانه‌های C به‌کار برد یا در یک بلوک extern از کتابخانه‌های C متصل کرد.

    fn atomic_add(_: *mut u32, _: u32) -> u32 { 2 }

static mut LEVELS: u32 = 0;

// This violates the idea of no shared state, and this doesn't internally
// protect against races, so this function is `unsafe`
unsafe fn bump_levels_unsafe() -> u32 {
    unsafe {
        let ret = LEVELS;
        LEVELS += 1;
        return ret;
    }
}

// As an alternative to `bump_levels_unsafe`, this function is safe, assuming
// that we have an atomic_add function which returns the old value. This
// function is safe only if no other code accesses the static in a non-atomic
// fashion. If such accesses are possible (such as in `bump_levels_unsafe`),
// then this would need to be `unsafe` to indicate to the caller that they
// must still guard against concurrent access.
fn bump_levels_safe() -> u32 {
    unsafe {
        return atomic_add(&raw mut LEVELS, 1);
    }
}
    [items.static.mut.sync]

    staticهای تغییرپذیر همان محدودیت‌های staticهای عادی را دارند، جز اینکه نوع مجبور نیست صفت Sync را پیاده‌سازی کند.

    [items.static.alternate]

    استفاده از static یا const

    تشخیص اینکه باید از آیتم ثابت استفاده کنید یا آیتم ایستا ممکن است گیج‌کننده باشد. به‌طور کلی، ثابت‌ها بر staticها ترجیح دارند، مگر اینکه یکی از موارد زیر برقرار باشد:

    • حجم بزرگی از داده ذخیره شود؛
    • ویژگی تک‌نشانی staticها لازم باشد؛
    • تغییرپذیری درونی لازم باشد.
