    [items.union.intro]

    اعلان union از همان نحو اعلان struct استفاده می‌کند، با این تفاوت که union جای struct را می‌گیرد.

    [items.union.namespace]

    اعلان union نام داده‌شده را در فضای نام نوع ماژول یا بلوک محل خود تعریف می‌کند.

    #[repr(C)]
union MyUnion {
    f1: u32,
    f2: f32,
}
    [items.union.common-storage]

    ویژگی اصلی unionها این است که همهٔ فیلدهایشان فضای ذخیره‌سازی مشترکی دارند. در نتیجه، نوشتن در یک فیلد می‌تواند فیلدهای دیگر را بازنویسی کند و اندازهٔ union را اندازهٔ بزرگ‌ترین فیلد آن تعیین می‌کند.

    [items.union.field-restrictions]

    نوع فیلدهای union به زیرمجموعهٔ زیر محدود است:

    [items.union.field-copy]
    • نوع‌های Copy
    [items.union.field-references]
    • ارجاع‌ها (&T و &mut T برای هر T)
    [items.union.field-manually-drop]
    • ManuallyDrop<T> (برای هر T)
    [items.union.field-tuple]
    • تاپل‌ها و آرایه‌هایی که فقط نوع‌های مجاز فیلد union را در خود دارند
    [items.union.drop]

    این محدودیت به‌ویژه تضمین می‌کند که فیلدهای union هرگز نیازی به drop شدن ندارند. مانند structها و enumها، می‌توان برای یک union نیز impl Drop نوشت تا به‌صورت دستی تعریف شود هنگام drop شدن آن چه رخ می‌دهد.

    [items.union.fieldless]

    کامپایلر union بدون فیلد را نمی‌پذیرد، اما ماکروها می‌توانند آن را بپذیرند.

    [items.union.init]

    مقداردهی اولیهٔ union

    [items.union.init.intro]

    مقداری از نوع union را می‌توان با همان نحو نوع‌های struct ساخت، جز اینکه باید دقیقاً یک فیلد مشخص شود:

    union MyUnion { f1: u32, f2: f32 }

let u = MyUnion { f1: 1 };
    [items.union.init.result]

    عبارت بالا مقداری از نوع MyUnion می‌سازد و فضای ذخیره‌سازی را با فیلد f1 مقداردهی می‌کند. با همان نحو فیلدهای struct می‌توان به union دسترسی یافت:

    union MyUnion { f1: u32, f2: f32 }

let u = MyUnion { f1: 1 };
let f = unsafe { u.f1 };
    [items.union.fields]

    خواندن و نوشتن فیلدهای union

    [items.union.fields.intro]

    unionها مفهومی به‌نام «فیلد فعال» ندارند. هر دسترسی به union صرفاً فضای ذخیره‌سازی را به‌عنوان نوع فیلد استفاده‌شده برای دسترسی تفسیر می‌کند.

    [items.union.fields.read]

    خواندن فیلد union، بیت‌های union را با نوع آن فیلد می‌خواند.

    [items.union.fields.offset]

    ممکن است فیلدها offset ناصفر داشته باشند، مگر هنگام استفاده از نمایش C. در این حالت بیت‌ها از offset فیلد خوانده می‌شوند.

    [items.union.fields.validity]

    برنامه‌نویس مسئول است که از معتبر بودن داده برای نوع فیلد مطمئن شود. رعایت‌نکردن این شرط به رفتار تعریف‌نشده منجر می‌شود. برای مثال، خواندن مقدار 3 از فیلدی با نوع بولی رفتار تعریف‌نشده است. در عمل، نوشتن در union دارای نمایش C و سپس خواندن از آن شبیه یک transmute از نوع مورد استفاده برای نوشتن به نوع مورد استفاده برای خواندن است.

    [items.union.fields.read-safety]

    در نتیجه، همهٔ خواندن‌های فیلد union باید در بلوک unsafe قرار گیرند:

    union MyUnion { f1: u32, f2: f32 }
let u = MyUnion { f1: 1 };

unsafe {
    let f = u.f1;
}

    کدی که از union استفاده می‌کند معمولاً پوشش‌های ایمنی پیرامون دسترسی ناامن به فیلدهای union فراهم می‌کند.

    [items.union.fields.write-safety]

    در مقابل، نوشتن در فیلد union ایمن است، زیرا فقط داده‌ای دلخواه را بازنویسی می‌کند و نمی‌تواند رفتار تعریف‌نشده ایجاد کند. توجه کنید که نوع فیلد union هرگز glue مربوط به drop ندارد؛ بنابراین نوشتن در فیلد هرگز چیزی را به‌طور ضمنی drop نمی‌کند.

    [items.union.pattern]

    تطبیق الگو روی unionها

    [items.union.pattern.intro]

    راه دیگر دسترسی به فیلدهای union، استفاده از تطبیق الگوست.

    [items.union.pattern.one-field]

    تطبیق الگو روی فیلدهای union از همان نحو الگوهای struct استفاده می‌کند، اما الگو باید دقیقاً یک فیلد را مشخص کند.

    [items.union.pattern.safety]

    از آنجا که تطبیق الگو مانند خواندن union از طریق یک فیلد مشخص است، باید در بلوک unsafe قرار گیرد.

    union MyUnion { f1: u32, f2: f32 }

fn f(u: MyUnion) {
    unsafe {
        match u {
            MyUnion { f1: 10 } => { println!("ten"); }
            MyUnion { f2 } => { println!("{}", f2); }
        }
    }
}

    Warning

    هشدار ترتیب آزمودن زیرالگوهای یک الگو مشخص نشده است. ممکن است فیلد union نام‌برده در الگو حتی زمانی خوانده شود که کل الگو مطابقت ندارد. خواندن فیلد union، مگر زمانی که مقداری معتبر برای نوعش داشته باشد، رفتار تعریف‌نشده است؛ items.union.fields.validity را ببینید. نمی‌توان برای جلوگیری از خواندن به بخش دیگری از الگو تکیه کرد.

    به‌ویژه هنگام پیاده‌سازی union برچسب‌دار به سبک C، از تطبیق هم‌زمان برچسب و فیلد متناظر union در یک الگو خودداری کنید؛ ممکن است فیلد union حتی در صورت مطابقت‌نداشتن برچسب خوانده شود.

    برای خواندن فیلد union تنها در صورت برقراری یک شرط، شرط را بیازمایید و فیلد را در گام‌هایی جداگانه با ترتیب ارزیابی مشخص بخوانید. برای union برچسب‌دار C، ابتدا روی برچسب تطبیق دهید و فیلد union را در بازوی تطبیق‌یافته بخوانید:

    #[repr(u32)]
enum Tag { I, F }

#[repr(C)]
union U {
    i: i32,
    f: f32,
}

#[repr(C)]
struct Value {
    tag: Tag,
    u: U,
}

fn is_zero(v: Value) -> bool {
    match v.tag {
        Tag::I => unsafe { v.u.i == 0 },
        Tag::F => unsafe { v.u.f == 0.0 },
    }
}
    [items.union.ref]

    ارجاع به فیلدهای union

    [items.union.ref.intro]

    چون فیلدهای union فضای ذخیره‌سازی مشترک دارند، دسترسی نوشتن به یک فیلد می‌تواند دسترسی نوشتن به همهٔ فیلدهای دیگر را فراهم کند.

    [items.union.ref.borrow]

    قواعد بررسی قرض باید این واقعیت را در نظر بگیرند. در نتیجه، اگر یک فیلد union قرض گرفته شود، همهٔ فیلدهای دیگر نیز برای همان طول‌عمر قرض گرفته می‌شوند.

    union MyUnion { f1: u32, f2: f32 }
// ERROR: cannot borrow `u` (via `u.f2`) as mutable more than once at a time
fn test() {
    let mut u = MyUnion { f1: 1 };
    unsafe {
        let b1 = &mut u.f1;
//                    ---- first mutable borrow occurs here (via `u.f1`)
        let b2 = &mut u.f2;
//                    ^^^^ second mutable borrow occurs here (via `u.f2`)
        *b1 = 5;
    }
//  - first borrow ends here
    assert_eq!(unsafe { u.f1 }, 5);
}
    [items.union.ref.use]

    همان‌طور که دیدید، unionها در بسیاری جنبه‌ها—به‌جز چیدمان، ایمنی و مالکیت—دقیقاً مانند structها رفتار می‌کنند؛ عمدتاً چون شکل نحوی خود را از structها به ارث برده‌اند. این شباهت دربارهٔ بسیاری جنبه‌های ذکرنشدهٔ زبان Rust، مانند حریم خصوصی، تفکیک نام، استنتاج نوع، عمومی‌ها، پیاده‌سازی صفت‌ها، پیاده‌سازی‌های ذاتی، انسجام و بررسی الگو نیز برقرار است.
