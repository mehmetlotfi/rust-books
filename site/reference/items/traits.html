    [items.traits.intro]

    یک صفت رابطی انتزاعی را توصیف می‌کند که نوع‌ها می‌توانند آن را پیاده‌سازی کنند. این رابط از اقلام وابسته تشکیل می‌شود که سه گونه دارند:

    • functions
    • نوع‌ها
    • constants
    [items.traits.namespace]

    اعلان صفت، یک صفت را در فضای نام نوع ماژول یا بلوکی که در آن قرار دارد تعریف می‌کند.

    [items.traits.associated-item-namespaces]

    اقلام وابسته، در فضای نام مربوط به خود به‌عنوان اعضای صفت تعریف می‌شوند. نوع‌های وابسته در فضای نام نوع تعریف می‌شوند. ثابت‌ها و تابع‌های وابسته در فضای نام مقدار تعریف می‌شوند.

    [items.traits.self-param]

    همهٔ صفت‌ها یک پارامتر نوع ضمنی به نام Self تعریف می‌کنند که به «نوعی که این رابط را پیاده‌سازی می‌کند» اشاره دارد. صفت‌ها می‌توانند پارامترهای نوع دیگری هم داشته باشند. این پارامترهای نوع، از جمله Self، می‌توانند به شیوهٔ معمول به‌وسیلهٔ صفت‌های دیگر و موارد مشابه مقید شوند.

    [items.traits.impls]

    صفت‌ها از راه پیاده‌سازی‌های جداگانه برای نوع‌های مشخص پیاده‌سازی می‌شوند.

    [items.traits.associated-item-decls]

    تابع‌های صفت می‌توانند با جایگزین کردن بدنهٔ تابع با یک نقطه‌ویرگول، بدنه را حذف کنند. این کار نشان می‌دهد که پیاده‌سازی باید تابع را تعریف کند. اگر تابع صفت بدنه‌ای تعریف کند، آن تعریف برای هر پیاده‌سازی‌ای که آن را بازنویسی نکند نقش پیش‌فرض را دارد. به همین ترتیب، ثابت‌های وابسته می‌توانند علامت مساوی و عبارت را حذف کنند تا نشان دهند پیاده‌سازی‌ها باید مقدار ثابت را تعریف کنند. نوع‌های وابسته هرگز نباید نوع را تعریف کنند؛ نوع فقط در یک پیاده‌سازی قابل مشخص شدن است.

    // Examples of associated trait items with and without definitions.
trait Example {
    const CONST_NO_DEFAULT: i32;
    const CONST_WITH_DEFAULT: i32 = 99;
    type TypeNoDefault;
    fn method_without_default(&self);
    fn method_with_default(&self) {}
}
    [items.traits.const-fn]

    تابع‌های صفت اجازه ندارند const باشند.

    [items.traits.bounds]

    کران‌های صفت

    اقلام عمومی می‌توانند از صفت‌ها به‌عنوان کران پارامترهای نوع خود استفاده کنند.

    [items.traits.generic]

    صفت‌های عمومی

    برای عمومی کردن یک صفت می‌توان پارامترهای نوع را برای آن مشخص کرد. این پارامترها پس از نام صفت و با همان نحو به‌کاررفته در تابع‌های عمومی می‌آیند.

    trait Seq<T> {
    fn len(&self) -> u32;
    fn elt_at(&self, n: u32) -> T;
    fn iter<F>(&self, f: F) where F: Fn(T);
}

    [items.traits.dyn-compatible]

    سازگاری با dyn (Dyn compatibility)

    [items.traits.dyn-compatible.intro]

    یک trait سازگار با dyn می‌تواند trait پایهٔ یک trait object باشد. یک trait هنگامی dyn compatible (سازگار با dyn) است که ویژگی‌های زیر را داشته باشد:

    [items.traits.dyn-compatible.supertraits]
    • همهٔ supertraitها نیز باید dyn compatible باشند.
    [items.traits.dyn-compatible.sized]
    • Sized نباید یک ابرصفت باشد. به بیان دیگر، صفت نباید Self: Sized را الزامی کند.
    [items.traits.dyn-compatible.associated-consts]
    • نباید هیچ ثابت وابسته‌ای داشته باشد.
    [items.traits.dyn-compatible.associated-types]
    • نباید هیچ نوع وابستهٔ دارای پارامتر عمومی داشته باشد.
    [items.traits.dyn-compatible.associated-functions]
    • همهٔ تابع‌های وابسته باید یا از یک شیء صفت قابل اعزام باشند یا صراحتاً اعزام‌ناپذیر باشند:
      • تابع‌های قابل اعزام باید:
        • هیچ پارامتر نوعی نداشته باشند (پارامترهای طول‌عمر مجازند).
        • متدی باشند که جز در نوع گیرنده از Self استفاده نکند.
        • گیرنده‌ای با یکی از نوع‌های زیر داشته باشند:
          • &Self (i.e. &self)
          • &mut Self (i.e &mut self)
          • Box<Self>
          • Rc<Self>
          • Arc<Self>
          • [Pin<P>] که در آن P یکی از نوع‌های بالا است
        • نوع بازگشتی کدر نداشته باشند؛ یعنی:
          • یک async fn نباشند (که نوع پنهان Future دارد).
          • در جایگاه بازگشتی نوع impl Trait نداشته باشند (fn example(&self) -> impl Trait).
        • کران where Self: Sized نداشته باشند (نوع گیرندهٔ Self، یعنی self، این کران را ایجاب می‌کند).
        • پارامتر متغیرِ سازگار با C (_: ...) نداشته باشند.
      • تابع‌هایی که صراحتاً اعزام‌ناپذیرند باید:
        • کران where Self: Sized داشته باشند (نوع گیرندهٔ Self، یعنی self، این کران را ایجاب می‌کند).
    [items.traits.dyn-compatible.async-traits]
    • صفت‌های AsyncFn، AsyncFnMut و AsyncFnOnce با dyn سازگار نیستند.

    Note

    نکته این مفهوم پیش‌تر با نام ایمنی شیء شناخته می‌شد.

    use std::rc::Rc;
use std::sync::Arc;
use std::pin::Pin;
// Examples of dyn compatible methods.
trait TraitMethods {
    fn by_ref(self: &Self) {}
    fn by_ref_mut(self: &mut Self) {}
    fn by_box(self: Box<Self>) {}
    fn by_rc(self: Rc<Self>) {}
    fn by_arc(self: Arc<Self>) {}
    fn by_pin(self: Pin<&Self>) {}
    fn with_lifetime<'a>(self: &'a Self) {}
    fn nested_pin(self: Pin<Arc<Self>>) {}
}
struct S;
impl TraitMethods for S {}
let t: Box<dyn TraitMethods> = Box::new(S);
    // This trait is dyn compatible, but these methods cannot be dispatched on a trait object.
trait NonDispatchable {
    // Non-methods cannot be dispatched.
    fn foo() where Self: Sized {}
    // Self type isn't known until runtime.
    fn returns(&self) -> Self where Self: Sized;
    // `other` may be a different concrete type of the receiver.
    fn param(&self, other: Self) where Self: Sized {}
    // Generics are not compatible with vtables.
    fn typed<T>(&self, x: T) where Self: Sized {}
}

struct S;
impl NonDispatchable for S {
    fn returns(&self) -> Self where Self: Sized { S }
}
let obj: Box<dyn NonDispatchable> = Box::new(S);
obj.returns(); // ERROR: cannot call with Self return
obj.param(S);  // ERROR: cannot call with Self parameter
obj.typed(1);  // ERROR: cannot call with generic type
    use std::rc::Rc;
// Examples of dyn-incompatible traits.
trait DynIncompatible {
    const CONST: i32 = 1;  // ERROR: cannot have associated const

    fn foo() {}  // ERROR: associated function without Sized
    fn returns(&self) -> Self; // ERROR: Self in return type
    fn typed<T>(&self, x: T) {} // ERROR: has generic type parameters
    fn nested(self: Rc<Box<Self>>) {} // ERROR: nested receiver cannot be dispatched on
}

struct S;
impl DynIncompatible for S {
    fn returns(&self) -> Self { S }
}
let obj: Box<dyn DynIncompatible> = Box::new(S); // ERROR
    // `Self: Sized` traits are dyn-incompatible.
trait TraitWithSize where Self: Sized {}

struct S;
impl TraitWithSize for S {}
let obj: Box<dyn TraitWithSize> = Box::new(S); // ERROR
    // Dyn-incompatible if `Self` is a type argument.
trait Super<A> {}
trait WithSelf: Super<Self> where Self: Sized {}

struct S;
impl<A> Super<A> for S {}
impl WithSelf for S {}
let obj: Box<dyn WithSelf> = Box::new(S); // ERROR: cannot use `Self` type parameter
    [items.traits.supertraits]

    ابرصفت‌ها

    [items.traits.supertraits.intro]

    ابرصفت‌ها صفت‌هایی هستند که برای پیاده‌سازی یک صفت مشخص روی یک نوع، باید برای آن نوع پیاده‌سازی شده باشند. افزون بر این، هرجا یک نوع عمومی یا شیء صفت با صفتی مقید شود، به اقلام وابستهٔ ابرصفت‌های آن نیز دسترسی دارد.

    [items.traits.supertraits.decl]

    ابرصفت‌ها به‌وسیلهٔ کران‌های صفت روی نوع Self یک صفت، و به‌صورت تعدی‌پذیر ابرصفت‌های صفت‌های اعلان‌شده در آن کران‌ها، اعلان می‌شوند. اینکه یک صفت ابرصفت خودش باشد خطاست.

    [items.traits.supertraits.subtrait]

    صفتی که ابرصفت دارد، زیرصفت ابرصفت خود نامیده می‌شود.

    مثال زیر Shape را به‌عنوان ابرصفت Circle اعلان می‌کند.

    trait Shape { fn area(&self) -> f64; }
trait Circle: Shape { fn radius(&self) -> f64; }

    مثال زیر همان مثال است، با این تفاوت که از بندهای where استفاده می‌کند.

    trait Shape { fn area(&self) -> f64; }
trait Circle where Self: Shape { fn radius(&self) -> f64; }

    مثال بعد با استفاده از تابع area متعلق به Shape یک پیاده‌سازی پیش‌فرض برای radius فراهم می‌کند.

    trait Shape { fn area(&self) -> f64; }
trait Circle where Self: Shape {
    fn radius(&self) -> f64 {
        // A = pi * r^2
        // so algebraically,
        // r = sqrt(A / pi)
        (self.area() / std::f64::consts::PI).sqrt()
    }
}

    مثال بعد یک متد ابرصفت را روی یک پارامتر عمومی فراخوانی می‌کند.

    trait Shape { fn area(&self) -> f64; }
trait Circle: Shape { fn radius(&self) -> f64; }
fn print_area_and_radius<C: Circle>(c: C) {
    // Here we call the area method from the supertrait `Shape` of `Circle`.
    println!("Area: {}", c.area());
    println!("Radius: {}", c.radius());
}

    به همین شکل، این هم مثالی از فراخوانی متدهای ابرصفت روی اشیای صفت است.

    trait Shape { fn area(&self) -> f64; }
trait Circle: Shape { fn radius(&self) -> f64; }
struct UnitCircle;
impl Shape for UnitCircle { fn area(&self) -> f64 { std::f64::consts::PI } }
impl Circle for UnitCircle { fn radius(&self) -> f64 { 1.0 } }
let circle = UnitCircle;
let circle = Box::new(circle) as Box<dyn Circle>;
let nonsense = circle.radius() * circle.area();
    [items.traits.safety]

    صفت‌های ناامن

    [items.traits.safety.intro]

    صفت‌هایی که با کلیدواژهٔ unsafe آغاز می‌شوند نشان می‌دهند که پیاده‌سازی آن صفت ممکن است ناامن باشد. استفاده از یک صفت ناامن که به‌درستی پیاده‌سازی شده، امن است. پیاده‌سازی صفت نیز باید با کلیدواژهٔ unsafe آغاز شود.

    Sync و Send نمونه‌هایی از صفت‌های ناامن هستند.

    [items.traits.params]

    الگوهای پارامتر

    [items.traits.params.patterns-no-body]

    پارامترها در تابع‌های وابستهٔ بدون بدنه فقط الگوهای IDENTIFIER یا الگوی _ (یعنی نویسهٔ عام) را می‌پذیرند، و نیز شکلی را که SelfParam مجاز می‌کند. در حال حاضر mut IDENTIFIER مجاز است، اما منسوخ شده و در آینده به خطای سخت (hard error) تبدیل خواهد شد.

    trait T {
    fn f1(&self);
    fn f2(x: Self, _: i32);
}
    trait T {
    fn f2(&x: &i32); // ERROR: patterns aren't allowed in functions without bodies
}
    [items.traits.params.patterns-with-body]

    پارامترهای تابع‌های وابستهٔ دارای بدنه فقط الگوهای انکارناپذیر را می‌پذیرند.

    trait T {
    fn f1((a, b): (i32, i32)) {} // OK: is irrefutable
}
    trait T {
    fn f1(123: i32) {} // ERROR: pattern is refutable
    fn f2(Some(x): Option<i32>) {} // ERROR: pattern is refutable
}
    [items.traits.params.pattern-required.edition2018]

    تفاوت‌های ویرایش 2018 پیش از ویرایش ۲۰۱۸، الگوی پارامتر یک تابع وابسته اختیاری بود:

    // 2015 Edition
trait T {
    fn f(i32); // OK: parameter identifiers are not required
}

    از ویرایش ۲۰۱۸ به بعد، الگوها دیگر اختیاری نیستند.

    [items.traits.params.restriction-patterns.edition2018]

    تفاوت‌های ویرایش 2018 پیش از ویرایش ۲۰۱۸، پارامترهای تابع‌های وابستهٔ دارای بدنه به گونه‌های زیر از الگو محدود بودند:

    • IDENTIFIER
    • mut IDENTIFIER
    • _
    • & IDENTIFIER
    • && IDENTIFIER
    // 2015 Edition
trait T {
    fn f1((a, b): (i32, i32)) {} // ERROR: pattern not allowed
}

    از ویرایش ۲۰۱۸ به بعد، همهٔ الگوهای انکارناپذیر مطابق توضیح items.traits.params.patterns-with-body مجازند.

    [items.traits.associated-visibility]

    نمایانی اقلام

    [items.traits.associated-visibility.intro]

    اقلام صفت از نظر نحوی یک حاشیه‌نویسی Visibility را می‌پذیرند، اما هنگام اعتبارسنجی صفت رد می‌شوند. این ویژگی اجازه می‌دهد اقلام با نحوی یکپارچه در بافت‌های مختلفی که به کار می‌روند تجزیه شوند. برای نمونه، مشخص‌کنندهٔ قطعهٔ ماکروی vis خالی را می‌توان برای اقلام صفت به کار برد، در حالی که همان قاعدهٔ ماکرو ممکن است در موقعیت‌های دیگری نیز استفاده شود که نمایانی در آن‌ها مجاز است.

    macro_rules! create_method {
    ($vis:vis $name:ident) => {
        $vis fn $name(&self) {}
    };
}

trait T1 {
    // Empty `vis` is allowed.
    create_method! { method_of_t1 }
}

struct S;

impl S {
    // Visibility is allowed here.
    create_method! { pub method_of_s }
}

impl T1 for S {}

fn main() {
    let s = S;
    s.method_of_t1();
    s.method_of_s();
}
