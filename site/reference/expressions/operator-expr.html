    [expr.operator.intro]

    زبان Rust عملگرها را برای نوع‌های داخلی تعریف می‌کند.

    [expr.operator.trait]

    بسیاری از عملگرهای زیر را می‌توان با استفاده از صفت‌های موجود در std::ops یا std::cmp سربارگذاری کرد.

    [expr.operator.int-overflow]

    سرریز

    [expr.operator.int-overflow.intro]

    عملگرهای صحیح در برنامه‌ای که در حالت اشکال‌زدایی کامپایل شده است، هنگام سرریز پنیک می‌کنند. برای کنترل مستقیم‌تر این رفتار می‌توان از پرچم‌های کامپایلر -C debug-assertions و -C overflow-checks استفاده کرد. موارد زیر سرریز محسوب می‌شوند:

    [expr.operator.int-overflow.binary-arith]
    • هنگامی که +، * یا - دوتایی مقداری بزرگ‌تر از بیشینه یا کوچک‌تر از کمینهٔ قابل ذخیره‌سازی تولید کنند.
    [expr.operator.int-overflow.unary-neg]
    • اعمال - یکانی به منفی‌ترین مقدار هر نوع صحیح علامت‌دار، مگر آنکه عملوند یک عبارت لیترال باشد؛ این استثنا شامل لیترالی که به‌تنهایی در یک یا چند عبارت گروه‌بندی‌شده قرار گرفته باشد نیز می‌شود.
    [expr.operator.int-overflow.div]
    • استفاده از / یا % هنگامی که آرگومان سمت چپ کوچک‌ترین مقدار یک نوع صحیح علامت‌دار و آرگومان سمت راست -1 باشد. به دلایل سازگاری با رفتار قدیمی، این بررسی‌ها حتی با غیرفعال بودن -C overflow-checks هم انجام می‌شوند.
    [expr.operator.int-overflow.shift]
    • استفاده از << یا >> هنگامی که آرگومان سمت راست منفی، یا بزرگ‌تر از یا برابر با تعداد بیت‌های نوع آرگومان سمت چپ باشد.

    Note

    نکته استثنای عبارت‌های لیترال پس از - یکانی به این معناست که شکل‌هایی مانند -128_i8 یا let j: i8 = -(128) هرگز موجب پنیک نمی‌شوند و مقدار مورد انتظار، یعنی ‎−۱۲۸، را دارند.

    در این موارد، خود عبارت لیترال از پیش منفی‌ترین مقدار نوعش را دارد؛ برای نمونه، مقدار 128_i8 برابر با ‎−۱۲۸ است. دلیل این است که طبق توضیح عبارت‌های لیترال صحیح، بیت‌های اضافی لیترال صحیح برای جا گرفتن در نوع آن حذف می‌شوند.

    به‌دلیل قواعد سرریز در نمایش مکمل دو، منفی کردن این مقادیرِ حداقل، مقدارشان را تغییر نمی‌دهد.

    در rustc، بررسی لینت overflowing_literals نیز این عبارت‌های دارای منفی‌ترین مقدار را نادیده می‌گیرد.

    [expr.operator.borrow]

    عملگرهای قرض‌گیری

    [expr.operator.borrow.syntax]

    Syntax
    BorrowExpression →
          ( & | && ) Expression
        | ( & | && ) mut Expression
        | ( & | && ) raw const Expression
        | ( & | && ) raw mut Expression

    [expr.operator.borrow.intro]

    عملگرهای & برای قرض‌گیری اشتراکی و &mut برای قرض‌گیری تغییرپذیر، عملگرهای یکانی پیشوندی هستند.

    [expr.operator.borrow.result]

    هنگامی که این عملگرها بر یک عبارت مکان اعمال شوند، ارجاعی (اشاره‌گری) به محلِ مورد اشارهٔ آن مقدار تولید می‌کنند.

    [expr.operator.borrow.lifetime]

    همچنین محل حافظه تا پایان عمر ارجاع در وضعیت قرض‌گرفته‌شده قرار می‌گیرد. در قرض‌گیری اشتراکی (&)، آن محل قابل تغییر نیست، اما می‌توان آن را خواند یا دوباره به‌صورت اشتراکی قرض گرفت. در قرض‌گیری تغییرپذیر (&mut)، تا پایان قرض‌گیری هیچ‌گونه دسترسی دیگری به آن محل مجاز نیست.

    [expr.operator.borrow.mut]

    &mut عملوند خود را در بافتِ عبارت مکانِ تغییرپذیر ارزیابی می‌کند.

    [expr.operator.borrow.temporary]

    اگر عملگر & یا &mut بر یک عبارت مقدار اعمال شود، یک مقدار موقت ساخته می‌شود.

    این عملگرها قابل سربارگذاری نیستند.

    {
    // a temporary with value 7 is created that lasts for this scope.
    let shared_reference = &7;
}
let mut array = [-2, 3, 9];
{
    // Mutably borrows `array` for this scope.
    // `array` may only be used through `mutable_reference`.
    let mutable_reference = &mut array;
}
    [expr.borrow.and-and-syntax]

    هرچند && یک توکن واحد است (عملگر «و» تنبل)، در بافت عبارت‌های قرض‌گیری مانند دو قرض‌گیری عمل می‌کند:

    // same meanings:
let a = &&  10;
let a = & & 10;

// same meanings:
let a = &&&&  mut 10;
let a = && && mut 10;
let a = & & & & mut 10;
    [expr.borrow.raw]

    عملگرهای قرض‌گیری خام

    [expr.borrow.raw.intro]

    &raw const و &raw mut، عملگرهای قرض‌گیری خام هستند.

    [expr.borrow.raw.place]

    عبارتِ عملوند این عملگرها در بافت عبارت مکان ارزیابی می‌شود.

    [expr.borrow.raw.result]

    سپس &raw const expr یک اشاره‌گر خام ثابت از نوع *const T به محل داده‌شده می‌سازد و &raw mut expr یک اشاره‌گر خام تغییرپذیر از نوع *mut T ایجاد می‌کند.

    [expr.borrow.raw.invalid-ref]

    هرگاه ممکن باشد عبارت مکان به محلی با هم‌ترازی نامناسب یا فاقد مقدار معتبر برای نوعش ارزیابی شود، یا ساختن ارجاع فرض‌های نادرستی دربارهٔ هم‌نامی ایجاد کند، باید به‌جای عملگر قرض‌گیری از عملگر قرض‌گیری خام استفاده کرد. در این وضعیت‌ها، عملگر قرض‌گیری با ساختن ارجاع نامعتبر موجب رفتار تعریف‌نشده می‌شود، اما ساختن اشاره‌گر خام همچنان مجاز است.

    نمونهٔ زیر ساختن اشاره‌گر خام به محلی با هم‌ترازی نامناسب را از طریق یک ساختار packed نشان می‌دهد:

    #[repr(packed)]
struct Packed {
    f1: u8,
    f2: u16,
}

let packed = Packed { f1: 1, f2: 2 };
// `&packed.f2` would create an unaligned reference, and thus be undefined behavior!
let raw_f2 = &raw const packed.f2;
assert_eq!(unsafe { raw_f2.read_unaligned() }, 2);

    نمونهٔ زیر ساختن اشاره‌گر خام به محلی را نشان می‌دهد که حاوی مقدار معتبری نیست:

    use std::mem::MaybeUninit;

struct Demo {
    field: bool,
}

let mut uninit = MaybeUninit::<Demo>::uninit();
// `&uninit.as_mut().field` would create a reference to an uninitialized `bool`,
// and thus be undefined behavior!
let f1_ptr = unsafe { &raw mut (*uninit.as_mut_ptr()).field };
unsafe { f1_ptr.write(true); }
let init = unsafe { uninit.assume_init() };
    [expr.deref]

    عملگر ارجاع‌زدایی

    [expr.deref.syntax]

    Syntax
    DereferenceExpression → * Expression

    [expr.deref.intro]

    عملگر * (ارجاع‌زدایی) نیز یک عملگر یکانی پیشوندی است.

    [expr.deref.result]

    هنگامی که بر یک اشاره‌گر یا Box اعمال شود، محلِ مورد اشاره را مشخص می‌کند.

    [expr.deref.mut]

    اگر عبارت از نوع &mut T، *mut T یا Box<T> باشد و یک متغیر محلی، فیلدی (احتمالاً تودرتو) از متغیر محلی، یا یک عبارت مکان تغییرپذیر باشد، می‌توان در محل حافظهٔ حاصل مقداردهی کرد.

    [expr.deref.box]

    هنگام اعمال این عملگر بر Box، می‌توان مقدار را از محل حاصل منتقل کرد.

    [expr.deref.safety]

    ارجاع‌زدایی از اشاره‌گر خام به unsafe نیاز دارد.

    [expr.deref.traits]

    برای نوع‌های غیرِاشاره‌گر، *x در بافت عبارت مکانِ تغییرناپذیر معادل *std::ops::Deref::deref(&x) و در بافت عبارت مکانِ تغییرپذیر معادل *std::ops::DerefMut::deref_mut(&mut x) است. تنها استثنا این است که اگر *x مشمول تمدید طول عمر مقدار موقت شود، دامنهٔ موقت عبارت ارجاع‌زدایی‌شدهٔ x نیز تمدید می‌شود.

    struct NoCopy;
let a = &7;
assert_eq!(*a, 7);
let b = &mut 9;
*b = 11;
assert_eq!(*b, 11);
let c = Box::new(NoCopy);
let d: NoCopy = *c;
    // The temporary holding the result of `String::new()` is extended
// to live to the end of the block, so `x` may be used in subsequent
// statements.
let x = &*String::new();
x;
    // The temporary holding the result of `String::new()` is dropped at
// the end of the statement, so it's an error to use `y` after.
let y = &*std::ops::Deref::deref(&String::new()); // ERROR
y;
    [expr.try]

    عبارت انتشار نتیجهٔ تلاش

    [expr.try.syntax]

    Syntax
    TryPropagationExpression → Expression ?

    [expr.try.intro]

    عبارت انتشار نتیجهٔ تلاش، با استفاده از مقدار عبارت درونی و صفت Try تصمیم می‌گیرد که آیا مقداری تولید کند و آن مقدار چه باشد، یا مقداری به فراخواننده بازگرداند و مقدار بازگشتی چه باشد.

    مثال

    use std::num::ParseIntError;
fn try_to_parse() -> Result<i32, ParseIntError> {
    let x: i32 = "123".parse()?; // `x` is `123`.
    let y: i32 = "24a".parse()?; // Returns an `Err()` immediately.
    Ok(x + y)                    // Doesn't run.
}

let res = try_to_parse();
println!("{res:?}");
assert!(res.is_err())
    fn try_option_some() -> Option<u8> {
    let val = Some(1)?;
    Some(val)
}
assert_eq!(try_option_some(), Some(1));

fn try_option_none() -> Option<u8> {
    let val = None?;
    Some(val)
}
assert_eq!(try_option_none(), None);
    use std::ops::ControlFlow;

pub struct TreeNode<T> {
    value: T,
    left: Option<Box<TreeNode<T>>>,
    right: Option<Box<TreeNode<T>>>,
}

impl<T> TreeNode<T> {
    pub fn traverse_inorder<B>(&self, f: &mut impl FnMut(&T) -> ControlFlow<B>) -> ControlFlow<B> {
        if let Some(left) = &self.left {
            left.traverse_inorder(f)?;
        }
        f(&self.value)?;
        if let Some(right) = &self.right {
            right.traverse_inorder(f)?;
        }
        ControlFlow::Continue(())
    }
}

fn main() {
    let n = TreeNode {
        value: 1,
        left: Some(Box::new(TreeNode{value: 2, left: None, right: None})),
        right: None,
    };
    let v = n.traverse_inorder(&mut |t| {
        if *t == 2 {
            ControlFlow::Break("found")
        } else {
            ControlFlow::Continue(())
        }
    });
    assert_eq!(v, ControlFlow::Break("found"));
}

    Note

    نکته صفت Try در حال حاضر ناپایدار است و بنابراین نمی‌توان آن را برای نوع‌های تعریف‌شده توسط کاربر پیاده‌سازی کرد.

    عبارت انتشار نتیجهٔ تلاش در حال حاضر تقریباً معادل کد زیر است:

    #![ feature(try_trait_v2) ]
fn example() -> Result<(), ()> {
let expr = Ok(());
match core::ops::Try::branch(expr) {
    core::ops::ControlFlow::Continue(val) => val,
    core::ops::ControlFlow::Break(residual) =>
        return core::ops::FromResidual::from_residual(residual),
}
Ok(())
}

    Note

    نکته عملگر انتشار نتیجهٔ تلاش را گاهی عملگر علامت سؤال، عملگر ? یا عملگر تلاش می‌نامند.

    [expr.try.restricted-types]

    عملگر انتشار نتیجهٔ تلاش را می‌توان بر عبارت‌هایی با نوع‌های زیر اعمال کرد:

    • Result<T, E>
      • Result::Ok(val) به val ارزیابی می‌شود.
      • Result::Err(e) مقدار Result::Err(From::from(e)) را از تابع بازمی‌گرداند.
    • Option<T>
      • Option::Some(val) به val ارزیابی می‌شود.
      • Option::None مقدار Option::None را از تابع بازمی‌گرداند.
    • ControlFlow<B, C>
      • ControlFlow::Continue(c) به c ارزیابی می‌شود.
      • ControlFlow::Break(b) مقدار ControlFlow::Break(b) را از تابع بازمی‌گرداند.
    • Poll<Result<T, E>>
      • Poll::Ready(Ok(val)) به Poll::Ready(val) ارزیابی می‌شود.
      • Poll::Ready(Err(e)) مقدار Poll::Ready(Err(From::from(e))) را از تابع بازمی‌گرداند.
      • Poll::Pending به Poll::Pending ارزیابی می‌شود.
    • Poll<Option<Result<T, E>>>
      • Poll::Ready(Some(Ok(val))) به Poll::Ready(Some(val)) ارزیابی می‌شود.
      • Poll::Ready(Some(Err(e))) مقدار Poll::Ready(Some(Err(From::from(e)))) را از تابع بازمی‌گرداند.
      • Poll::Ready(None) به Poll::Ready(None) ارزیابی می‌شود.
      • Poll::Pending به Poll::Pending ارزیابی می‌شود.

    عملگرهای نقیض‌سازی

    [expr.negate.syntax]

    Syntax

    [expr.negate.intro]

    این‌ها دو عملگر یکانی باقی‌مانده هستند.

    [expr.negate.results]

    جدول زیر رفتار این عملگرها را برای نوع‌های ابتدایی و صفت‌های لازم برای سربارگذاری آن‌ها برای نوع‌های دیگر خلاصه می‌کند. به یاد داشته باشید که اعداد صحیح علامت‌دار همواره با نمایش مکمل دو ذخیره می‌شوند. عملوندهای همهٔ این عملگرها در بافت عبارت مقدار ارزیابی می‌شوند؛ بنابراین منتقل یا کپی می‌شوند.

    نمادعدد صحیحboolممیز شناورصفت سربارگذاری
    -منفی‌سازی*منفی‌سازیstd::ops::Neg
    !نقیض بیتینقیض منطقیstd::ops::Not

    * فقط برای نوع‌های صحیح علامت‌دار.

    چند نمونه از کاربرد این عملگرها:

    let x = 6;
assert_eq!(-x, -6);
assert_eq!(!x, -7);
assert_eq!(true, !false);

    [expr.arith-logic.behavior]

    نمادعدد صحیحboolممیز شناورصفت سربارگذاریصفت سربارگذاری انتساب مرکب

    -تفریقتفریقstd::ops::Substd::ops::SubAssign
    *ضربضربstd::ops::Mulstd::ops::MulAssign

    ** Rust باقی‌مانده را بر پایهٔ تقسیم با حذف بخش کسری تعریف می‌کند. در remainder = dividend % divisor، علامت باقی‌مانده با علامت مقسوم یکسان است.

    *** برای نوع‌های صحیح علامت‌دار، شیفت به راست حسابی و برای نوع‌های صحیح بدون علامت، شیفت به راست منطقی انجام می‌شود.

    [expr.cmp.intro]

    عملگرهای مقایسه نیز هم برای نوع‌های ابتدایی و هم برای بسیاری از نوع‌های کتابخانهٔ استاندارد تعریف شده‌اند.

    [expr.cmp.paren-chaining]

    هنگام زنجیره کردن عملگرهای مقایسه باید از پرانتز استفاده کرد. برای مثال، عبارت a == b == c نامعتبر است و می‌توان آن را به‌صورت (a == b) == c نوشت.

    [expr.cmp.trait]

    برخلاف عملگرهای حسابی و منطقی، صفت‌های سربارگذاری این عملگرها کاربرد عمومی‌تری دارند و نشان می‌دهند که یک نوع چگونه قابل مقایسه است. تابع‌هایی که این صفت‌ها را به‌عنوان کران به کار می‌برند، احتمالاً فرض می‌کنند که آن‌ها مقایسه‌های واقعی را تعریف می‌کنند. بسیاری از تابع‌ها و ماکروهای کتابخانهٔ استاندارد نیز می‌توانند از این فرض استفاده کنند، هرچند نباید ایمنی را بر آن استوار کنند.

    [expr.cmp.place]

    برخلاف عملگرهای حسابی و منطقی بالا، این عملگرها به‌طور ضمنی عملوندهای خود را به‌صورت اشتراکی قرض می‌گیرند و آن‌ها را در بافت عبارت مکان ارزیابی می‌کنند:

    let a = 1;
let b = 1;
a == b;
// is equivalent to
::std::cmp::PartialEq::eq(&a, &b);

    در نتیجه، لازم نیست مقدار عملوندها از محلشان منتقل شود.

    [expr.cmp.behavior]
    نمادمعنامتد سربارگذاری

    [expr.bool-logic.intro]

    عملگرهای || و && را می‌توان بر عملوندهایی از نوع بولی اعمال کرد. عملگر || نشان‌دهندهٔ «یا»ی منطقی و عملگر && نشان‌دهندهٔ «و»ی منطقی است.

    [expr.bool-logic.conditional-evaluation]

    تفاوت آن‌ها با | و & این است که عملوند سمت راست تنها زمانی ارزیابی می‌شود که عملوند سمت چپ به‌تنهایی نتیجهٔ عبارت را مشخص نکند. یعنی || فقط هنگامی عملوند سمت راست را ارزیابی می‌کند که حاصل ارزیابی عملوند سمت چپ false باشد و && فقط هنگامی که آن حاصل true باشد.

    let x = false || true; // true
let y = false && panic!(); // false, doesn't evaluate `panic!()`

    تبدیل عددی

    [expr.as.numeric.int-same-size]

    • تبدیل بین دو عدد صحیح هم‌اندازه (مثلاً i32 به u32) یک no-op است و بیت‌ها را تغییر نمی‌دهد (Rust برای مقادیر منفی اعداد صحیح با اندازهٔ ثابت از مکمل دو استفاده می‌کند).

    • تبدیل از یک عدد صحیح بزرگ‌تر به عدد صحیح کوچک‌تر (مثلاً u32 به u8) مقدار را کوتاه (truncate) می‌کند.

      assert_eq!(42u16 as u8, 42u8);

assert_eq!(0xabcdi32 as i8, -51i8);
    [expr.as.numeric.int-extension]

    • تبدیل از یک عدد صحیح کوچک‌تر به عدد صحیح بزرگ‌تر (مثلاً u8 به u32) به این صورت انجام می‌شود:

      • اگر مبدأ بدون علامت باشد، بیت‌های جدید را با صفر پر می‌کند.
      • اگر مبدأ علامت‌دار باشد، بیت علامت را گسترش می‌دهد.
      assert_eq!(42i8 as i16, 42i16);

assert_eq!(0b1000_1010u8 as u16, 0b0000_0000_1000_1010u16, "Zero-extend");
assert_eq!(0b0000_1010i8 as i16, 0b0000_0000_0000_1010i16, "Sign-extend 0");
assert_eq!(0b1000_1010u8 as i8 as i16, 0b1111_1111_1000_1010u16 as i16, "Sign-extend 1");
    [expr.as.numeric.float-as-int]

    • تبدیل از عدد ممیز شناور به عدد صحیح، مقدار را به‌سمت صفر گرد می‌کند.

      • مقادیر کوچک‌تر از کمینهٔ عدد صحیح، از جمله NEG_INFINITY، به کمینهٔ نوع صحیح محدود می‌شوند.

assert_eq!(42_000_000f32 as i32, 42_000_000);
assert_eq!(f32::NAN as i32, 0);
assert_eq!(1_000_000_000_000_000f32 as i32, 0x7fffffffi32);

    [expr.as.pointer-as-int]

    تبدیل اشاره‌گر به نشانی

    تبدیل اشاره‌گر خام به عدد صحیح، نشانی ماشینی حافظهٔ مورد اشاره را تولید می‌کند. اگر نوع صحیح از نوع اشاره‌گر کوچک‌تر باشد، ممکن است بیت‌های اضافی نشانی حذف شوند؛ استفاده از usize از این اتفاق جلوگیری می‌کند.

    [expr.as.int-as-pointer]

    تبدیل نشانی به اشاره‌گر

    تبدیل عدد صحیح به اشاره‌گر خام، عدد را به‌عنوان نشانی حافظه تفسیر می‌کند و اشاره‌گری به آن حافظه می‌سازد.

    Warning

    هشدار این تبدیل با مدل حافظهٔ Rust در تعامل است؛ مدلی که هنوز در حال توسعه است. اشاره‌گر حاصل از این تبدیل ممکن است محدودیت‌های اضافی داشته باشد، حتی اگر بیت‌به‌بیت با یک اشاره‌گر معتبر برابر باشد. اگر قواعد هم‌نامی رعایت نشوند، ارجاع‌زدایی از چنین اشاره‌گری ممکن است رفتار تعریف‌نشده باشد.

    نمونه‌ای ساده از محاسبات صحیح و ایمن روی نشانی‌ها:

    let mut values: [i32; 2] = [1, 2];
let p1: *mut i32 = values.as_mut_ptr();
let first_address = p1 as usize;
let second_address = first_address + 4; // 4 == size_of::<i32>()
let p2 = second_address as *mut i32;
unsafe {
    *p2 += 1;
}
assert_eq!(values[1], 3);
    [expr.as.pointer]

    تبدیل اشاره‌گر به اشاره‌گر

    [expr.as.pointer.behavior]

    می‌توان *const T یا *mut T را با رفتار زیر به *const U یا *mut U تبدیل کرد:

    [expr.as.pointer.sized]

    • اگر هر دو نوع T و U اندازه‌دار باشند، اشاره‌گر بدون تغییر بازگردانده می‌شود.

      مثال

      let x: i32 = 42;
let p1: *const i32 = &x;
let p2: *const u8 = p1 as *const u8;
// The pointer address remains the same.
assert_eq!(p1 as usize, p2 as usize);
    [expr.as.pointer.discard-metadata]

    • اگر T بی‌اندازه و U اندازه‌دار باشد، تبدیل تمام فراداده‌ای را که اشاره‌گر پهن T را تکمیل می‌کند کنار می‌گذارد و یک اشاره‌گر باریک U می‌سازد که فقط از بخش دادهٔ اشاره‌گر بی‌اندازه تشکیل شده است.

      مثال

      let slice: &[i32] = &[1, 2, 3];
let ptr: *const [i32] = slice as *const [i32];
// Cast from wide pointer (*const [i32]) to thin pointer (*const i32)
// discarding the length metadata.
let data_ptr: *const i32 = ptr as *const i32;
assert_eq!(unsafe { *data_ptr }, 1);
    [expr.as.pointer.unsized.unchanged]
    • اگر هر دو نوع T و U بی‌اندازه باشند، باز هم اشاره‌گر بدون تغییر بازگردانده می‌شود. به‌ویژه، فراداده دقیقاً حفظ می‌شود. این تبدیل تنها در صورتی مجاز است که فراداده طبق قواعد زیر سازگار باشد:
    [expr.as.pointer.unsized.slice]

    • هنگامی که T و U بی‌اندازه و دارای فرادادهٔ برش باشند، همیشه سازگارند. فرادادهٔ برش تعداد عناصر آن است؛ بنابراین تبدیل *[u16] -> *[u8] مجاز است، اما تعداد بایت‌ها را به نصف کاهش می‌دهد.

      مثال

      let slice: &[u16] = &[1, 2, 3];
let ptr: *const [u16] = slice as *const [u16];
let byte_ptr: *const [u8] = ptr as *const [u8];
assert_eq!(byte_ptr.len(), 3);
    [expr.as.pointer.unsized.trait]
    • هنگامی که T و U بی‌اندازه و دارای فرادادهٔ شیء صفت باشند، فراداده فقط در صورت برقرار بودن همهٔ شرایط زیر سازگار است:

      1. صفت اصلی باید یکسان باشد.

        مثال

        trait Foo {}
trait Bar {}
impl Foo for i32 {}
impl Bar for i32 {}

let x: i32 = 42;
let ptr_foo: *const dyn Foo = &x as *const dyn Foo;
// You can't cast to a different principal trait.
let ptr_bar: *const dyn Bar = ptr_foo as *const dyn Bar; // ERROR

      2. حذف صفت‌های خودکار مجاز است.

        مثال

        trait Foo {}
struct S;
impl Foo for S {}
unsafe impl Send for S {}

let s = S;
let ptr_send: *const (dyn Foo + Send) = &s;
// Removing an auto trait.
let ptr_no_send: *const dyn Foo = ptr_send as *const dyn Foo;

      3. افزودن صفت خودکار فقط هنگامی مجاز است که آن صفت، ابرصفتِ صفت اصلی باشد.

        مثال

        trait Foo: Send {}
struct S;
impl Foo for S {}
unsafe impl Send for S {}

let s = S;
let ptr_no_send: *const dyn Foo = &s;
// Adding an auto trait.
let ptr_send: *const (dyn Foo + Send) = ptr_no_send as *const (dyn Foo + Send);
        trait Foo {}
struct S;
impl Foo for S {}
unsafe impl Send for S {}

let s = S;
let ptr_no_send: *const dyn Foo = &s;
// Same as above, except trait Foo does not have Send as a super trait.
let ptr_send: *const (dyn Foo + Send) = ptr_no_send as *const (dyn Foo + Send); // ERROR

      4. طول عمرهای انتهایی فقط می‌توانند کوتاه‌تر شوند.

        مثال

        trait Foo {}

fn shorten_lifetime<'long: 'short, 'short>(
    ptr: *const (dyn Foo + 'long),
) -> *const (dyn Foo + 'short) {
    // Shortening the lifetime is allowed.
    ptr as *const (dyn Foo + 'short)
}
        trait Foo {}

fn lengthen_lifetime<'long: 'short, 'short>(
    ptr: *const (dyn Foo + 'short),
) -> *const (dyn Foo + 'long) {
    // It is not allowed to cast to a longer lifetime.
    ptr as *const (dyn Foo + 'long) // ERROR
}

      5. پارامترهای جنریک، از جمله طول عمرها، و نوع‌های وابسته باید دقیقاً مطابقت داشته باشند.

        مثال

        trait Generic<T> {}
impl Generic<i32> for () {}
impl Generic<u32> for () {}

let x = ();
let ptr_i32: *const dyn Generic<i32> = &x;
// You can't cast to a different generic parameter.
let ptr_u32: *const dyn Generic<u32> = ptr_i32 as *const dyn Generic<u32>; // ERROR
        trait HasType {
    type Output;
}

trait Generic<'x, T> {}

fn cast_via_associated<'a, 'b, A, B>(
    ptr: *const dyn Generic<'a, A::Output>,
) -> *const dyn Generic<'b, B::Output>
where
    'a: 'b,
    'b: 'a,
    A: HasType,
    B: HasType<Output = A::Output>, // Forces equality
{
    ptr as *const dyn Generic<'b, B::Output>
}
    [expr.as.pointer.unsized.compound]

    • اگر T یا U نوع ساختار یا تاپلی باشد که آخرین فیلدش بی‌اندازه است، فراداده و قواعد سازگاری آن همان فراداده و قواعد آخرین فیلدش خواهد بود.

      مثال

      struct Wrapper(u32, [u8]);

let slice: &[u8] = &[1, 2, 3];
let ptr: *const [u8] = slice;

// The metadata (length 3) is preserved when casting to a struct
// where the last field is the unsized type `[u8]`.
let wrapper_ptr: *const Wrapper = ptr as *const Wrapper;

// And preserved when casting back.
let ptr_back: *const [u8] = wrapper_ptr as *const [u8];
assert_eq!(ptr_back.len(), 3);
    [expr.assign]

    عبارت‌های انتساب

    [expr.assign.syntax]

    Syntax
    AssignmentExpression → Expression = Expression

    [expr.assign.intro]

    یک عبارت انتساب مقداری را به محل مشخصی منتقل می‌کند.

    [expr.assign.assignee]

    عبارت انتساب از یک عبارت مقصد انتساب تغییرپذیر، موسوم به عملوند مقصد انتساب، سپس علامت مساوی (=) و یک عبارت مقدار، موسوم به عملوند مقدار انتسابی، تشکیل می‌شود.

    [expr.assign.behavior-basic]

    در ساده‌ترین حالت، عبارت مقصد انتساب یک عبارت مکان است؛ ابتدا همین حالت را بررسی می‌کنیم.

    [expr.assign.behavior-destructuring]

    حالت عمومی‌ترِ انتساب تجزیه‌ای در ادامه بررسی می‌شود، اما این حالت همواره به انتساب‌های متوالی به عبارت‌های مکان تجزیه می‌شود؛ ازاین‌رو می‌توان انتساب به مکان را حالت بنیادی‌تر دانست.

    [expr.assign.basic]

    انتساب‌های ساده

    [expr.assign.evaluation-order]

    ارزیابی عبارت انتساب با ارزیابی عملوندهایش آغاز می‌شود. ابتدا عملوند مقدار انتسابی و سپس عبارت مقصد انتساب ارزیابی می‌شود.

    [expr.assign.destructuring-order]

    در انتساب تجزیه‌ای، زیرعبارت‌های عبارت مقصد انتساب از چپ به راست ارزیابی می‌شوند.

    Note

    نکته تفاوت این عبارت با عبارت‌های دیگر آن است که عملوند راست پیش از عملوند چپ ارزیابی می‌شود.

    [expr.assign.drop-target]

    سپس ابتدا مقدار موجود در محل مقصد تخریب می‌شود؛ مگر آنکه محل، متغیر محلیِ مقداردهی‌نشده یا فیلد مقداردهی‌نشده‌ای از یک متغیر محلی باشد.

    [expr.assign.behavior]

    پس از آن، مقدار انتسابی در محل مقصد کپی یا به آن منتقل می‌شود.

    [expr.assign.result]

    عبارت انتساب همیشه مقدار واحد را تولید می‌کند.

    مثال:

    let mut x = 0;
let y = 0;
x = y;
    [expr.assign.destructure]

    انتساب‌های تجزیه‌ای

    [expr.assign.destructure.intro]

    انتساب تجزیه‌ای، همتای تطبیق الگوی تجزیه‌ای در اعلان متغیرهاست و امکان انتساب به مقادیر مرکب مانند تاپل‌ها یا ساختارها را فراهم می‌کند. برای نمونه، می‌توان مقدار دو متغیر تغییرپذیر را جابه‌جا کرد:

    let (mut a, mut b) = (0, 1);
// Swap `a` and `b` using destructuring assignment.
(b, a) = (a, b);
    [expr.assign.destructure.assignee]

    برخلاف اعلان‌های تجزیه‌ای با let، به‌دلیل ابهام‌های نحوی نمی‌توان الگو را در سمت چپ انتساب قرار داد. در عوض، گروهی از عبارت‌ها که با الگوها متناظرند، عبارت مقصد انتساب نامیده می‌شوند و حضورشان در سمت چپ انتساب مجاز است. این عبارت‌ها سپس به شکل بنیادیِ تطبیق الگو و انتساب‌های متوالی بازنویسی می‌شوند.

    [expr.assign.destructure.irrefutable]

    الگوهای حاصل از این بازنویسی باید ردناپذیر باشند. به‌ویژه، در انتساب تجزیه‌ای فقط الگوهای برشی مجازند که طولشان در زمان کامپایل مشخص باشد، به‌علاوهٔ برش سادهٔ [..].

    روش بازنویسی ساده است و با مثال بهتر روشن می‌شود.

    struct Struct { x: u32, y: u32 }
let (mut a, mut b) = (0, 0);
(a, b) = (3, 4);

[a, b] = [3, 4];

Struct { x: a, y: b } = Struct { x: 3, y: 4};

// desugars to:

{
    let (_a, _b) = (3, 4);
    a = _a;
    b = _b;
}

{
    let [_a, _b] = [3, 4];
    a = _a;
    b = _b;
}

{
    let Struct { x: _a, y: _b } = Struct { x: 3, y: 4};
    a = _a;
    b = _b;
}
    [expr.assign.destructure.repeat-ident]

    استفادهٔ چندباره از یک شناسه در یک عبارت مقصد انتساب ممنوع نیست.

    [expr.assign.destructure.discard-value]

    می‌توان از عبارت‌های زیرخط و عبارت‌های بازه‌ی خالی برای نادیده گرفتن برخی مقادیر، بدون ایجاد اتصال برای آن‌ها، استفاده کرد.

    [expr.assign.destructure.default-binding]

    توجه داشته باشید که حالت‌های پیش‌فرض اتصال بر عبارت بازنویسی‌شده اعمال نمی‌شوند.

    [expr.assign.destructure.tmp-scopes]

    Note

    نکته این بازنویسی، دامنهٔ موقت عملوند مقدار انتسابی (سمت راست) را در انتساب تجزیه‌ای محدود می‌کند.

    در انتساب ساده، مقدار موقت در پایان دامنهٔ موقتِ دربرگیرنده تخریب می‌شود. در مثال زیر، این دامنه همان دستور است؛ بنابراین انتساب و استفاده از مقدار مجاز است.

    fn temp() {}
fn f<T>(x: T) -> T { x }
let x;
(x = f(&temp()), x); // OK

    در مقابل، در انتساب تجزیه‌ای، مقدار موقت در پایان دستور let در شکل بازنویسی‌شده تخریب می‌شود. چون این اتفاق پیش از تلاش برای انتساب به x رخ می‌دهد، مثال زیر با خطا مواجه می‌شود.

    fn temp() {}
fn f<T>(x: T) -> T { x }
let x;
[x] = [f(&temp())]; // ERROR

    شکل بازنویسی‌شدهٔ آن:

    fn temp() {}
fn f<T>(x: T) -> T { x }
let x;
{
    let [_x] = [f(&temp())];
    //                     ^
    //      The temporary is dropped here.
    x = _x; // ERROR
}
    [expr.assign.destructure.tmp-ext]

    Note

    نکته به‌دلیل این بازنویسی، عملوند مقدار انتسابی (سمت راست) در انتساب تجزیه‌ای، یک عبارت تمدیدکننده درون بلوکی است که تازه ایجاد می‌شود.

    در مثال زیر، چون دامنهٔ موقت تا پایان این بلوک تازه تمدید می‌شود، انتساب مجاز است.

    fn temp() {}
let x;
[x] = [&temp()]; // OK

    شکل بازنویسی‌شدهٔ آن:

    fn temp() {}
let x;
{ let [_x] = [&temp()]; x = _x; } // OK

    بااین‌حال، اگر بخواهیم از x استفاده کنیم، حتی در همان دستور، خطا می‌گیریم؛ زیرا مقدار موقت در پایان این بلوک تازه تخریب می‌شود.

    fn temp() {}
let x;
([x] = [&temp()], x); // ERROR

    شکل بازنویسی‌شدهٔ آن:

    fn temp() {}
let x;
(
    {
        let [_x] = [&temp()];
        x = _x;
    }, // <-- The temporary is dropped here.
    x, // ERROR
);

    عبارت‌های انتساب مرکب

    [expr.compound-assign.syntax]

    Syntax
    CompoundAssignmentExpression →
          Expression += Expression
        | Expression -= Expression
        | Expression *= Expression
        | Expression /= Expression
        | Expression %= Expression
        | Expression &= Expression
        | Expression |= Expression
        | Expression ^= Expression
        | Expression <<= Expression
        | Expression >>= Expression

    [expr.compound-assign.intro]

    عبارت‌های انتساب مرکب عملگرهای حسابی و منطقی دوتایی را با عبارت‌های انتساب ترکیب می‌کنند.

    برای مثال:

    let mut x = 5;
x += 1;
assert!(x == 6);

    نحو انتساب مرکب شامل یک عبارت مکان تغییرپذیر به‌عنوان عملوند مقصد، سپس یکی از عملگرها همراه با = در قالب یک توکن واحد (بدون فاصله)، و در پایان یک عبارت مقدار به‌عنوان عملوند تغییردهنده است.

    [expr.compound-assign.place]

    برخلاف دیگر عملوندهای مکان، عملوند مقصد انتساب الزاماً باید یک عبارت مکان باشد.

    [expr.compound-assign.no-value]

    تلاش برای استفاده از عبارت مقدار، به‌جای ارتقای آن به یک مقدار موقت، خطای کامپایل ایجاد می‌کند.

    [expr.compound-assign.operand-order]

    شیوهٔ ارزیابی عبارت انتساب مرکب به نوع عملوندهای آن بستگی دارد.

    [expr.compound-assign.primitives]

    اگر پیش از تک‌ریخت‌سازی مشخص باشد که نوع هر دو عملوند ابتدایی است، ابتدا سمت راست و سپس سمت چپ ارزیابی می‌شود؛ آنگاه محل حاصل از ارزیابی سمت چپ با اعمال عملگر بر مقادیر دو طرف تغییر می‌کند.

    use core::{num::Wrapping, ops::AddAssign};

trait Equate {}
impl<T> Equate for (T, T) {}

fn f1(x: (u8,)) {
    let mut order = vec![];
    // The RHS is evaluated first as both operands are of primitive
    // type.
    { order.push(2); x }.0 += { order.push(1); x }.0;
    assert!(order.is_sorted());
}

fn f2(x: (Wrapping<u8>,)) {
    let mut order = vec![];
    // The LHS is evaluated first as `Wrapping<_>` is not a primitive
    // type.
    { order.push(1); x }.0 += { order.push(2); (0u8,) }.0;
    assert!(order.is_sorted());
}

fn f3<T: AddAssign<u8> + Copy>(x: (T,)) where (T, u8): Equate {
    let mut order = vec![];
    // The LHS is evaluated first as one of the operands is a generic
    // parameter, even though that generic parameter can be unified
    // with a primitive type due to the where clause bound.
    { order.push(1); x }.0 += { order.push(2); (0u8,) }.0;
    assert!(order.is_sorted());
}

fn main() {
    f1((0u8,));
    f2((Wrapping(0u8),));
    // We supply a primitive type as the generic argument, but this
    // does not affect the evaluation order in `f3` when
    // monomorphized.
    f3::<u8>((0u8,));
}

    Note

    نکته این رفتار معمول نیست؛ در جاهای دیگر، قاعدهٔ معمول ارزیابی از چپ به راست است.

    برای نمونه‌های بیشتر، آزمون ترتیب ارزیابی را ببینید.

    [expr.compound-assign.trait]

    در غیر این صورت، این عبارت شکل کوتاه‌شدهٔ استفاده از صفت متناظر با عملگر است (نگاه کنید به expr.arith-logic.behavior)؛ متد آن با سمت چپ به‌عنوان گیرنده و سمت راست به‌عنوان آرگومان بعدی فراخوانی می‌شود.

    برای مثال، دو دستور زیر معادل‌اند:

    use std::ops::AddAssign;
fn f<T: AddAssign + Copy>(mut x: T, y: T) {
    x += y; // Statement 1.
    x.add_assign(y); // Statement 2.
}

    Note

    نکته نکتهٔ غیرمنتظره این است که بازنویسی بیشترِ آن به یک فراخوانی متد با نام کاملاً مشخص‌شده، معادل نیست؛ زیرا وقتی ارجاع تغییرپذیر به عملوند نخست از طریق ارجاع‌گیری خودکار ساخته می‌شود، بررسی‌کنندهٔ قرض‌گیری رفتار ویژه‌ای دارد.

    use std::ops::AddAssign;
fn f<T: AddAssign + Copy>(mut x: T) {
    // Here we used `x` as both the LHS and the RHS. Because the
    // mutable borrow of the LHS needed to call the trait method
    // is taken implicitly by autoref, this is OK.
    x += x; //~ OK
    x.add_assign(x); //~ OK
}
    use std::ops::AddAssign;
fn f<T: AddAssign + Copy>(mut x: T) {
    // We can't desugar the above to the below, as once we take the
    // mutable borrow of `x` to pass the first argument, we can't
    // pass `x` by value in the second argument because the mutable
    // reference is still live.
    <T as AddAssign>::add_assign(&mut x, x);
    //~^ ERROR cannot use `x` because it was mutably borrowed
}
    use std::ops::AddAssign;
fn f<T: AddAssign + Copy>(mut x: T) {
    // As above.
    (&mut x).add_assign(x);
    //~^ ERROR cannot use `x` because it was mutably borrowed
}
    [expr.compound-assign.result]

    همانند عبارت‌های انتساب معمولی، عبارت‌های انتساب مرکب نیز همیشه مقدار واحد را تولید می‌کنند.

    Warning

    هشدار از نوشتن کدی که به ترتیب ارزیابی عملوندهای انتساب مرکب وابسته است خودداری کنید؛ این ترتیب می‌تواند نامعمول و غافلگیرکننده باشد.

    1. فقط وقتی m₁ برابر mut یا m₂ برابر const باشد. تبدیل ارجاع/اشاره‌گر mut به اشاره‌گر const مجاز است. ↩ ↩2

    2. فقط closureهایی که هیچ متغیر محلی را capture نمی‌کنند (بر آن‌ها بسته نمی‌شوند) قابل تبدیل به اشاره‌گر تابع هستند. ↩
