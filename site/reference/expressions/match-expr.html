    [expr.match]

    عبارت‌های match

    [expr.match.syntax]

    Syntax
    MatchExpression →
        match Scrutinee {
            InnerAttribute*
            MatchArms?
        }

    Scrutinee → Expressionexcept StructExpression

    MatchArms →
        ( MatchArm => ( ExpressionWithoutBlock , | ExpressionWithBlock ,? ) )*
        MatchArm => Expression ,?

    MatchArm → OuterAttribute* Pattern MatchArmGuard?

    MatchArmGuard → if MatchConditions

    MatchConditions →
         MatchGuardChain
       | Expression

    MatchGuardChain → MatchGuardCondition ( && MatchGuardCondition )*

    MatchGuardCondition →
         Expressionexcept ExcludedMatchConditions
       | OuterAttribute* let Pattern = MatchGuardScrutinee

    MatchGuardScrutinee → Expressionexcept ExcludedMatchConditions

    ExcludedMatchConditions →
          LazyBooleanExpression
        | RangeExpr
        | RangeFromExpr
        | RangeInclusiveExpr
        | AssignmentExpression
        | CompoundAssignmentExpression

    [expr.match.intro]

    یک عبارت match بر اساس الگو شاخه‌بندی می‌کند. شکل دقیق تطبیق به الگو بستگی دارد.

    [expr.match.scrutinee]

    عبارت match یک عبارت بررسی‌شونده دارد؛ مقداری که با الگوها مقایسه می‌شود.

    [expr.match.scrutinee-constraint]

    عبارت بررسی‌شونده و الگوها باید نوع یکسان داشته باشند.

    [expr.match.scrutinee-behavior]

    رفتار match بسته به اینکه عبارت بررسی‌شونده عبارت مکان باشد یا مقدار متفاوت است.

    [expr.match.scrutinee-value]

    اگر بررسی‌شونده عبارت مقدار باشد، ابتدا در مکانی موقت ارزیابی می‌شود و مقدار حاصل به‌ترتیب با الگوهای بازوها مقایسه می‌شود تا تطبیقی پیدا شود. نخستین بازوی دارای الگوی منطبق به‌عنوان مقصد شاخهٔ match انتخاب می‌شود، متغیرهای متصل‌شده توسط الگو به متغیرهای محلی بلوک بازو نسبت داده می‌شوند و کنترل وارد بلوک می‌شود.

    [expr.match.scrutinee-place]

    وقتی بررسی‌شونده عبارت مکان باشد، match مکان موقتی تخصیص نمی‌دهد؛ هرچند اتصال با مقدار ممکن است از محل حافظه کپی یا جابه‌جا کند. در صورت امکان بهتر است تطبیق روی عبارت مکان انجام شود، زیرا طول‌عمر این تطبیق‌ها طول‌عمر عبارت مکان را به ارث می‌برد و به درون match محدود نمی‌شود.

    نمونه‌ای از عبارت match:

    let x = 1;

match x {
    1 => println!("one"),
    2 => println!("two"),
    3 => println!("three"),
    4 => println!("four"),
    5 => println!("five"),
    _ => println!("something else"),
}
    [expr.match.pattern-vars]

    حوزهٔ متغیرهای متصل‌شده در الگو، نگهبان match و عبارت بازو است.

    [expr.match.pattern-var-binding]

    حالت اتصال—جابه‌جایی، کپی یا ارجاع—به الگو بستگی دارد.

    [expr.match.or-pattern]

    چند الگوی match را می‌توان با عملگر | پیوند داد. هر الگو به‌ترتیب چپ به راست آزموده می‌شود تا تطبیق موفق پیدا شود.

    let x = 9;
let message = match x {
    0 | 1  => "not many",
    2 ..= 9 => "a few",
    _      => "lots"
};

assert_eq!(message, "a few");

// Demonstration of pattern match order.
struct S(i32, i32);

match S(1, 2) {
    S(z @ 1, _) | S(_, z @ 2) => assert_eq!(z, 1),
    _ => panic!(),
}

    Note

    نکته عبارت 2..=9 یک الگوی بازه است، نه عبارت بازه. بنابراین فقط نوع بازه‌هایی که الگوی بازه پشتیبانی می‌کند در بازوهای match قابل استفاده‌اند.

    [expr.match.or-patterns-restriction]

    هر اتصال در هر الگوی جداشده با | باید در همهٔ الگوهای بازو ظاهر شود.

    [expr.match.binding-restriction]

    هر اتصال هم‌نام باید نوع و حالت اتصال یکسان داشته باشد.

    [expr.match.type]

    نوع کل عبارت match کمترین کران بالای بازوهای جداگانهٔ match است.

    [expr.match.empty]

    اگر بازوی match وجود نداشته باشد، عبارت match واگرا و نوع آن ! است.

    مثال

    enum Empty {}

fn diverging_match_no_arms(e: Empty) -> ! {
    match e {}
}
    [expr.match.diverging]

    اگر عبارت بررسی‌شونده یا همهٔ بازوهای match واگرا باشند، کل عبارت match نیز واگراست.

    [expr.match.guard]

    نگهبان‌های Match

    [expr.match.guard.intro]

    بازوهای match می‌توانند نگهبان match بپذیرند تا معیار تطبیق یک حالت دقیق‌تر شود.

    [expr.match.guard.condition]

    نگهبان الگو پس از الگو و کلیدواژهٔ if می‌آید و از یک Expression با نوع بولی یا تطبیق شرطی let تشکیل می‌شود.

    [expr.match.guard.behavior]

    وقتی الگو با موفقیت تطبیق کند، نگهبان اجرا می‌شود. اگر همهٔ عملوندهای شرط نگهبان به true ارزیابی شوند و همهٔ الگوهای let با بررسی‌شوندههای خود تطبیق کنند، بازوی match موفق است و بدنهٔ بازو اجرا می‌شود.

    [expr.match.guard.next]

    در غیر این صورت، الگوی بعدی—از جمله دیگر تطبیق‌های | در همان بازو—آزموده می‌شود.

    let maybe_digit = Some(0);
fn process_digit(i: i32) { }
fn process_other(i: i32) { }
let message = match maybe_digit {
    Some(x) if x < 10 => process_digit(x),
    Some(x) => process_other(x),
    None => panic!(),
};

    Note

    نکته چند تطبیق با عملگر | می‌تواند باعث شود نگهبان الگو و اثرهای جانبی آن چند بار اجرا شوند. برای مثال:

    use std::cell::Cell;
let i : Cell<i32> = Cell::new(0);
match 1 {
    1 | _ if { i.set(i.get() + 1); false } => {}
    _ => {}
}
assert_eq!(i.get(), 2);
    [expr.match.guard.bound-variables]

    نگهبان الگو می‌تواند به متغیرهای متصل‌شده در الگوی پیش از خود ارجاع دهد.

    [expr.match.guard.shared-ref]

    پیش از ارزیابی نگهبان، ارجاعی اشتراکی به بخش متناظر بررسی‌شونده با متغیر گرفته می‌شود. هنگام ارزیابی نگهبان، دسترسی به متغیر از همین ارجاع استفاده می‌کند.

    [expr.match.guard.value]

    تنها وقتی نگهبان با موفقیت ارزیابی شود، مقدار از بررسی‌شونده به متغیر جابه‌جا یا کپی می‌شود. این کار اجازه می‌دهد در صورت شکست نگهبان، قرض‌های اشتراکی درون آن بدون جابه‌جایی از بررسی‌شونده استفاده شوند.

    [expr.match.guard.no-mutation]

    افزون بر این، نگه‌داشتن ارجاع اشتراکی هنگام ارزیابی نگهبان مانع تغییر درون نگهبان می‌شود.

    [expr.match.guard.let]

    نگهبان‌ها می‌توانند از الگوهای let برای تطبیق شرطی بررسی‌شونده و اتصال متغیرهای تازه به حوزه هنگام موفقیت الگو استفاده کنند.

    مثال در این مثال شرط نگهبان let Some(first_char) = name.chars().next() ارزیابی می‌شود. اگر الگوی let موفق باشد—یعنی رشته دست‌کم یک نویسه داشته باشد—بدنهٔ بازو اجرا می‌شود. در غیر این صورت تطبیق با بازوی بعدی ادامه می‌یابد.

    الگوی let اتصال تازهٔ first_char را می‌سازد که در بدنهٔ بازو همراه اتصال اصلی name قابل استفاده است.

    enum Command {
    Run(String),
    Stop,
}
let cmd = Command::Run("example".to_string());

match cmd {
    Command::Run(name) if let Some(first_char) = name.chars().next() => {
        // Both `name` and `first_char` are available here
        println!("Running: {name} (starts with '{first_char}')");
    }
    Command::Run(name) => {
        println!("{name} is empty");
    }
    _ => {}
}
    [expr.match.guard.chains]

    زنجیرهٔ نگهبان‌های Match

    [expr.match.guard.chains.intro]

    چند عملوند شرط نگهبان را می‌توان با && جدا کرد.

    مثال

    let foo = Some([123]);
let already_checked = false;
match foo {
    Some(xs) if let [single] = xs && !already_checked => { dbg!(single); }
    _ => {}
}
    [expr.match.guard.chains.order]

    مانند یک LazyBooleanExpression از نوع &&، عملوندها چپ به راست ارزیابی می‌شوند تا یکی false شود یا تطبیق let شکست بخورد؛ سپس عملوندهای بعدی ارزیابی نمی‌شوند.

    [expr.match.guard.chains.bindings]

    اتصال‌های هر الگوی let وارد حوزه می‌شوند تا در عملوند شرط بعدی و بدنهٔ بازوی match در دسترس باشند.

    [expr.match.guard.chains.or]

    اگر یکی از عملوندهای شرط نگهبان الگوی let باشد، به‌دلیل ابهام و تقدم با بررسی‌شوندهٔ let، هیچ‌یک از عملوندها نمی‌تواند عبارت عملگر بولی تنبل نوع || باشد.

    مثال اگر عبارت || لازم باشد، می‌توان از پرانتز استفاده کرد:

    let foo = Some([123]);
match foo {
    Some(xs) if let [x] = xs
        // Parentheses are required here.
        && (x < -100 || x > 20) => {}
    _ => {}
}
    [expr.match.attributes]

    ویژگی‌های روی بازوهای match

    [expr.match.attributes.outer]

    ویژگی‌های بیرونی روی بازوهای match مجازند. تنها ویژگی‌های معنادار روی این بازوها cfg و ویژگی‌های بررسی lint هستند.

    [expr.match.attributes.inner]

    ویژگی‌های درونی بلافاصله پس از آکولاد باز عبارت match و در همان بافت‌هایی مجازند که ویژگی‌های عبارت بلوکی مجازند.
