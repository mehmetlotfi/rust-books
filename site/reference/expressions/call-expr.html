    [expr.call]

    عبارت‌های فراخوانی

    [expr.call.syntax]

    Syntax
    CallExpression → Expression ( CallParams? )

    CallParams → Expression ( , Expression )* ,?

    [expr.call.intro]

    یک عبارت فراخوانی تابعی را فراخوانی می‌کند. نحو آن یک عبارت به‌نام عملوند تابع است که پس از آن فهرستی از عبارت‌های جداشده با ویرگول و درون پرانتز می‌آید؛ این عبارت‌ها عملوندهای آرگومان نام دارند.

    [expr.call.convergence]

    اگر تابع سرانجام بازگردد، اجرای عبارت کامل می‌شود.

    [expr.call.trait]

    برای نوع‌های غیرتابع، عبارت f(...) بر پایهٔ عملوند تابع از متد یکی از صفت‌های زیر استفاده می‌کند:

    • [Fn] یا AsyncFn — ارجاع اشتراکی.
    • [FnMut] یا AsyncFnMut — ارجاع تغییرپذیر.
    • [FnOnce] یا AsyncFnOnce — مقدار.
    [expr.call.autoref-deref]

    در صورت نیاز، قرض‌گیری خودکار انجام می‌شود. عملوند تابع نیز به‌اندازهٔ لازم به‌طور خودکار ارجاع‌زدایی خواهد شد.

    چند نمونه از عبارت‌های فراخوانی:

    fn add(x: i32, y: i32) -> i32 { 0 }
let three: i32 = add(1i32, 2i32);
let name: &'static str = (|| "Rust")();
    [expr.call.desugar]

    رفع ابهام فراخوانی تابع

    [expr.call.desugar.fully-qualified]

    همهٔ فراخوانی‌های تابع، شکل کوتاه‌شده‌ای از یک نحو کاملاً واجد شرایط و صریح‌تر هستند.

    [expr.call.desugar.ambiguity]

    بسته به ابهامی که آیتم‌های موجود در حوزه برای فراخوانی ایجاد می‌کنند، ممکن است لازم باشد فراخوانی تابع به‌صورت کاملاً واجد شرایط نوشته شود.

    Note

    نکته در گذشته اصطلاح‌های «نحو فراخوانی تابع بدون ابهام» (Unambiguous Function Call Syntax)، «نحو فراخوانی تابع همگانی» (Universal Function Call Syntax) یا «UFCS» در مستندات، issueها، RFCها و دیگر نوشته‌های جامعه استفاده شده‌اند. بااین‌حال، این اصطلاح‌ها قدرت توصیفی کافی ندارند و ممکن است موضوع را مبهم‌تر کنند. آن‌ها را تنها برای آسان‌شدن جست‌وجو در اینجا ذکر کرده‌ایم.

    [expr.call.desugar.limits]

    چند وضعیت رایج می‌توانند دربارهٔ گیرنده یا مرجع فراخوانی متد یا تابع وابسته ابهام ایجاد کنند، از جمله:

    • چند صفت موجود در حوزه، متدهایی هم‌نام برای نوع‌هایی یکسان تعریف کنند؛
    • deref خودکار مطلوب نباشد؛ برای نمونه، هنگامی که باید میان متدهای خودِ یک اشاره‌گر هوشمند و متدهای مرجع آن تمایز گذاشت؛
    • متدهایی مانند default() که آرگومانی نمی‌گیرند و متدهایی مانند size_of() که ویژگی‌های یک نوع را برمی‌گردانند.
    [expr.call.desugar.explicit-path]

    برای رفع ابهام، برنامه‌نویس می‌تواند با مسیرها، نوع‌ها یا صفت‌های دقیق‌تر به متد یا تابع موردنظر اشاره کند.

    برای مثال:

    trait Pretty {
    fn print(&self);
}

trait Ugly {
    fn print(&self);
}

struct Foo;
impl Pretty for Foo {
    fn print(&self) {}
}

struct Bar;
impl Pretty for Bar {
    fn print(&self) {}
}
impl Ugly for Bar {
    fn print(&self) {}
}

fn main() {
    let f = Foo;
    let b = Bar;

    // we can do this because we only have one item called `print` for `Foo`s
    f.print();
    // more explicit, and, in the case of `Foo`, not necessary
    Foo::print(&f);
    // if you're not into the whole brevity thing
    <Foo as Pretty>::print(&f);

    // b.print(); // Error: multiple 'print' found
    // Bar::print(&b); // Still an error: multiple `print` found

    // necessary because of in-scope items defining `print`
    <Bar as Pretty>::print(&b);
}

    برای جزئیات و انگیزه‌های بیشتر به RFC 132 مراجعه کنید.
