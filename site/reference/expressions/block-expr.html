    [expr.block.intro]

    عبارت بلوکی یا بلوک، یک عبارت کنترل جریان و حوزهٔ فضای نام بی‌نام برای آیتم‌ها و اعلان متغیرهاست.

    [expr.block.sequential-evaluation]

    بلوک به‌عنوان عبارت کنترل جریان، دستورهای اعلان غیرآیتمی خود و سپس عبارت نهایی اختیاری را به‌ترتیب اجرا می‌کند.

    [expr.block.namespace]

    به‌عنوان حوزهٔ فضای نام بی‌نام، اعلان آیتم‌ها فقط درون خود بلوک در حوزه است و متغیرهای اعلان‌شده با let از دستور بعدی تا پایان بلوک در حوزه‌اند. برای جزئیات فصل حوزه‌ها را ببینید.

    [expr.block.inner-attributes]

    نحو بلوک شامل {، هر تعداد ویژگی درونی، هر تعداد دستور، یک عبارت اختیاری به‌نام عملوند نهایی و در پایان } است.

    [expr.block.statements]

    دستورها معمولاً باید با نقطه‌ویرگول پایان یابند، با دو استثنا:

    1. دستور اعلان آیتم به نقطه‌ویرگول نیاز ندارد.
    2. دستور عبارت معمولاً به نقطه‌ویرگول نیاز دارد، مگر اینکه عبارت بیرونی آن یک عبارت کنترل جریان باشد.
    [expr.block.null-statement]

    نقطه‌ویرگول‌های اضافی میان دستورها مجازند، اما بر معنا اثری ندارند.

    [expr.block.evaluation]

    هنگام ارزیابی بلوک، همهٔ دستورها به‌جز اعلان آیتم‌ها به‌ترتیب اجرا می‌شوند.

    [expr.block.result]

    سپس در صورت وجود، عملوند نهایی اجرا می‌شود.

    [expr.block.value-trailing-expr]

    بلوک دارای عملوند نهایی، نوع و مقدار همان عملوند را دارد.

    let x: u8 = { 0u8 }; // `0u8` is the final operand.
assert_eq!(x, 0);
let x: u8 = { (); 0u8 }; // As above.
assert_eq!(x, 0);
    [expr.block.value-no-trailing-expr]

    اگر بلوک عملوند نهایی نداشته باشد و واگرا نباشد، نوع واحد و مقدار واحد دارد.

    let x: () = {}; // Has no final operand.
assert_eq!(x, ());
let x: () = { 0u8; }; // As above.
assert_eq!(x, ());
    [expr.block.value-diverges-no-trailing-expr]

    اگر بلوک عملوند نهایی نداشته باشد و واگرا باشد، نوع هرگز دارد و مقدار نهایی ندارد، زیرا نوعش بدون ساکن است.

    fn f() -> ! { loop {}; } // Diverges and has no final operand.
//          ^^^^^^^^^^^^
// The body of a function is a block expression.

    Note

    نکته بلوک بدون عملوند نهایی با بلوک دارای عملوند نهایی صریح از نوع واحد متفاوت است. برای نمونه، با اینکه بلوک زیر واگراست، نوع آن واحد است نه هرگز.

    fn f() -> ! { loop {}; () } // ERROR: Mismatched types.
//          ^^^^^^^^^^^^^^^ This block has unit type.

    Note

    نکته اگر عبارت بلوکی به‌عنوان عبارت کنترل جریان، عبارت بیرونی یک دستور عبارت باشد، نوع مورد انتظار () است؛ مگر اینکه بلافاصله نقطه‌ویرگول پس از آن بیاید.

    [expr.block.diverging]

    بلوک زمانی واگرا محسوب می‌شود که همهٔ مسیرهای کنترل جریان قابل دسترسی دارای عبارت واگرا باشند؛ مگر اینکه آن عبارت یک عبارت مکان خوانده‌نشده باشد.

    fn no_control_flow() -> ! {
    // There are no conditional statements, so this entire function body is diverging.
    loop {}
}

fn control_flow_diverging() -> ! {
    // All paths are diverging, so this entire function body is diverging.
    if true {
        loop {}
    } else {
        loop {}
    }
}

fn control_flow_not_diverging() -> () {
    // Some paths are not diverging, so this entire block is not diverging.
    if true {
        ()
    } else {
        loop {}
    }
}

fn diverging_place_read(x: !) -> ! {
    // A read of a place expression produces a diverging block.
    let _x = x;
}
    fn diverging_place_not_read(x: !) -> ! {
    // Assignment to `_` means the place is not read.
    let _ = x;
} // ERROR: Mismatched types.
    [expr.block.value]

    بلوک‌ها همیشه عبارت مقدار هستند و آخرین عملوند را در بافت عبارت مقدار ارزیابی می‌کنند.

    Note

    نکته در صورت نیاز واقعی می‌توان با این ویژگی جابه‌جایی مقدار را اجباری کرد. مثال زیر در فراخوانی consume_self شکست می‌خورد، زیرا ساختار در عبارت بلوکی از s جابه‌جا شده است.

    struct Struct;

impl Struct {
    fn consume_self(self) {}
    fn borrow_self(&self) {}
}

fn move_by_block_expression() {
    let s = Struct;

    // Move the value out of `s` in the block expression.
    (&{ s }).borrow_self();

    // Fails to execute because `s` is moved out of.
    s.consume_self();
}
    [expr.block.async]

    بلوک‌های async

    [expr.block.async.syntax]

    Syntax
    AsyncBlockExpression → async move? BlockExpression

    [expr.block.async.intro]

    بلوک async گونه‌ای از عبارت بلوکی است که به یک future ارزیابی می‌شود.

    [expr.block.async.future-result]

    عبارت نهایی بلوک در صورت وجود، مقدار نتیجهٔ future را تعیین می‌کند.

    [expr.block.async.anonymous-type]

    اجرای بلوک async شبیه اجرای عبارت بستار است: اثر فوری آن تولید و بازگرداندن نوعی بی‌نام است.

    [expr.block.async.future]

    اما درحالی‌که بستارها نوعی پیاده‌سازی‌کنندهٔ یک یا چند صفت std::ops::Fn برمی‌گردانند، نوع بازگشتی بلوک async صفت std::future::Future را پیاده‌سازی می‌کند.

    [expr.block.async.layout-unspecified]

    قالب واقعی دادهٔ این نوع مشخص نشده است.

    Note

    نکته نوع future تولیدشده توسط rustc تقریباً معادل enumای با یک گونه برای هر نقطهٔ await است؛ هر گونه دادهٔ لازم برای ادامه از نقطهٔ متناظر را نگه می‌دارد.

    [expr.block.async.edition2018]

    تفاوت‌های ویرایش 2018 بلوک‌های async از Rust 2018 در دسترس‌اند.

    [expr.block.async.capture]

    حالت‌های تسخیر

    بلوک async متغیرهای محیط را با همان حالت‌های تسخیر بستارها می‌گیرد. در async { .. } حالت هر متغیر از محتوای بلوک استنتاج می‌شود؛ اما async move { .. } همهٔ متغیرهای مورد ارجاع را به future حاصل جابه‌جا می‌کند.

    [expr.block.async.context]

    بافت Async

    چون بلوک async یک future می‌سازد، بافت async تعریف می‌کند که می‌تواند عبارت‌های await داشته باشد. بلوک async و بدنهٔ تابع async این بافت‌ها را می‌سازند؛ معنای تابع async نیز بر اساس بلوک async تعریف می‌شود.

    [expr.block.async.function]

    عملگرهای کنترل جریان

    [expr.block.async.function.intro]

    بلوک async مانند بستار، همچون مرز تابع عمل می‌کند.

    [expr.block.async.function.return-try]

    بنابراین عملگر ? و عبارت‌های return بر خروجی future اثر می‌گذارند، نه تابع یا بافت دربرگیرنده. return <expr> در بلوک async نتیجهٔ <expr> را به‌عنوان خروجی future برمی‌گرداند. همچنین اگر <expr>? خطایی را منتشر کند، آن خطا نتیجهٔ future خواهد بود.

    [expr.block.async.function.control-flow]

    کلیدواژه‌های break و continue نمی‌توانند از بلوک async به بیرون شاخه بزنند؛ پس کد زیر نامعتبر است:

    loop {
    async move {
        break; // error[E0267]: `break` inside of an `async` block
    }
}
    [expr.block.const]

    بلوک‌های const

    [expr.block.const.syntax]

    Syntax
    ConstBlockExpression → const BlockExpression

    [expr.block.const.intro]

    بلوک const گونه‌ای از عبارت بلوکی است که بدنه‌اش به‌جای زمان اجرا، هنگام کامپایل ارزیابی می‌شود.

    [expr.block.const.context]

    بلوک const اجازه می‌دهد بدون تعریف آیتم ثابت جدید، مقداری ثابت تعریف کنید و به همین دلیل گاهی const درون‌خطی نامیده می‌شود. برخلاف آیتم ثابت، از استنتاج نوع نیز پشتیبانی می‌کند و نیازی به تعیین نوع نیست.

    [expr.block.const.generic-params]

    برخلاف آیتم‌های ثابت آزاد، بلوک const می‌تواند به پارامترهای عمومی در حوزه ارجاع دهد. این بلوک‌ها به آیتم‌های ثابت دارای پارامترهای عمومی در حوزه تبدیل می‌شوند؛ شبیه ثابت‌های وابسته، اما بدون صفت یا نوع وابسته. برای مثال:

    fn foo<T>() -> usize {
    const { std::mem::size_of::<T>() + 1 }
}

    معادل است با:

    fn foo<T>() -> usize {
    {
        struct Const<T>(T);
        impl<T> Const<T> {
            const CONST: usize = std::mem::size_of::<T>() + 1;
        }
        Const::<T>::CONST
    }
}
    [expr.block.const.evaluation]

    اگر عبارت بلوک const در زمان اجرا اجرا شود، ارزیابی ثابت تضمین می‌شود، حتی اگر مقدار بازگشتی نادیده گرفته شود:

    fn foo<T>() -> usize {
    // If this code ever gets executed, then the assertion has definitely
    // been evaluated at compile-time.
    const { assert!(std::mem::size_of::<T>() > 0); }
    // Here we can have unsafe code relying on the type being non-zero-sized.
    /* ... */
    42
}
    [expr.block.const.not-executed]

    اگر عبارت بلوک const در زمان اجرا اجرا نشود، ممکن است ارزیابی بشود یا نشود:

    if false {
    // The panic may or may not occur when the program is built.
    const { panic!(); }
}
    [expr.block.unsafe]

    بلوک‌های unsafe

    [expr.block.unsafe.syntax]

    Syntax
    UnsafeBlockExpression → unsafe BlockExpression

    [expr.block.unsafe.intro]

    برای زمان استفاده از unsafe، بلوک‌های unsafe را ببینید.

    می‌توان با کلیدواژهٔ unsafe در ابتدای بلوک، عملیات ناامن را مجاز کرد. نمونه‌ها:

    unsafe {
    let b = [13u8, 17u8];
    let a = &b[0] as *const u8;
    assert_eq!(*a, 13);
    assert_eq!(*a.offset(1), 17);
}

unsafe fn an_unsafe_fn() -> i32 { 10 }
let a = unsafe { an_unsafe_fn() };
    [expr.block.label]

    عبارت‌های بلوکی برچسب‌دار

    عبارت بلوکی برچسب‌دار در بخش حلقه‌ها و دیگر عبارت‌های شکست‌پذیر مستند شده است.

    [expr.block.attributes]

    ویژگی‌های روی عبارت بلوکی

    [expr.block.attributes.inner-attributes]

    ویژگی‌های درونی بلافاصله پس از آکولاد باز عبارت بلوکی در موقعیت‌های زیر مجازند:

    • بدنهٔ تابع‌ها و متدها.
    • بدنهٔ حلقه‌ها (loop، ‏while و for).
    • عبارت بلوکی استفاده‌شده به‌عنوان دستور.
    • عبارت بلوکی به‌عنوان عنصر عبارت آرایه، عبارت تاپل، عبارت فراخوانی و عبارت ساختار سبک تاپل.
    • عبارت بلوکی به‌عنوان عبارت انتهایی یک عبارت بلوکی دیگر.
    [expr.block.attributes.valid]

    ویژگی‌های معنادار روی عبارت بلوکی cfg و ویژگی‌های بررسی lint هستند.

    برای مثال تابع زیر در سکوهای Unix مقدار true و در دیگر سکوها false برمی‌گرداند.

    fn is_unix_platform() -> bool {
    #[cfg(unix)] { true }
    #[cfg(not(unix))] { false }
}
