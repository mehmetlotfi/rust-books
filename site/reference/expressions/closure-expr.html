    [expr.closure.intro]

    یک عبارت بستار که با نام عبارت لامبدا یا به‌اختصار لامبدا نیز شناخته می‌شود، یک نوع بستار تعریف می‌کند و به مقداری از همان نوع ارزیابی می‌شود. نحو عبارت بستار به‌ترتیب شامل یک کلیدواژهٔ اختیاری async، یک کلیدواژهٔ اختیاری move، فهرستی جداشده با ویرگول از الگوها میان دو نویسهٔ لوله (|) به‌نام پارامترهای بستار است که هرکدام می‌توانند یک : و نوع پس از خود داشته باشند؛ سپس یک -> و نوع اختیاری به‌نام نوع بازگشت و در پایان عبارتی به‌نام عملوند بدنهٔ بستار می‌آید.

    [expr.closure.param-type]

    نوع اختیاری پس از هر الگو، حاشیه‌نویسی نوع آن الگوست.

    [expr.closure.explicit-type-body]

    اگر نوع بازگشت وجود داشته باشد، بدنهٔ بستار باید یک بلوک باشد.

    [expr.closure.parameter-restriction]

    عبارت بستار تابعی را نشان می‌دهد که فهرستی از پارامترها را به عبارت پس از آن‌ها نگاشت می‌کند. درست مانند یک اتصال let، پارامترهای بستار الگوهای ردناپذیر هستند؛ حاشیه‌نویسی نوع آن‌ها اختیاری است و اگر نوشته نشود، از بافت استنتاج خواهد شد.

    [expr.closure.unique-type]

    هر عبارت بستار نوعی یکتا و بی‌نام دارد.

    [expr.closure.captures]

    نکتهٔ مهم این است که عبارت‌های بستار محیط خود را تسخیر می‌کنند، درحالی‌که تعریف‌های تابع عادی چنین نمی‌کنند.

    [expr.closure.capture-inference]

    بدون کلیدواژهٔ move، عبارت بستار شیوهٔ تسخیر هر متغیر از محیط خود را استنتاج می‌کند و تسخیر با ارجاع اشتراکی را ترجیح می‌دهد؛ در عمل همهٔ متغیرهای بیرونیِ ذکرشده در بدنهٔ بستار را قرض می‌گیرد.

    [expr.closure.capture-mut-ref]

    در صورت نیاز، کامپایلر استنتاج می‌کند که باید به‌جای آن ارجاع‌های تغییرپذیر گرفته شوند یا مقدارها—بسته به نوعشان—از محیط جابه‌جا یا کپی شوند.

    [expr.closure.capture-move]

    با افزودن کلیدواژهٔ move در ابتدای بستار می‌توان آن را وادار کرد محیطش را با کپی‌کردن یا جابه‌جایی مقدارها تسخیر کند. این روش اغلب برای اطمینان از 'static بودن طول‌عمر بستار به‌کار می‌رود.

    [expr.closure.trait-impl]

    پیاده‌سازی صفت‌ها برای بستار

    صفت‌هایی که نوع بستار پیاده‌سازی می‌کند به شیوهٔ تسخیر متغیرها، نوع متغیرهای تسخیرشده و وجود async بستگی دارد. برای چگونگی و زمان پیاده‌سازی Fn، ‏FnMut و FnOnce توسط بستار، فصل صفت‌های فراخوانی و وادارسازی‌ها را ببینید. اگر نوع هر متغیر تسخیرشده یک صفت را پیاده‌سازی کند، نوع بستار نیز Send و Sync را پیاده‌سازی می‌کند.

    [expr.closure.async]

    بستارهای ناهمگام

    [expr.closure.async.intro]

    بستارهایی که با کلیدواژهٔ async علامت‌گذاری شده‌اند، به‌شیوه‌ای مشابه یک تابع ناهمگام ناهمگام هستند.

    [expr.closure.async.future]

    فراخوانی بستار ناهمگام کاری انجام نمی‌دهد؛ در عوض به مقداری ارزیابی می‌شود که Future را پیاده‌سازی می‌کند و متناظر با محاسبهٔ بدنهٔ بستار است.

    async fn takes_async_callback(f: impl AsyncFn(u64)) {
    f(0).await;
    f(1).await;
}

async fn example() {
    takes_async_callback(async |i| {
        core::future::ready(i).await;
        println!("done with {i}.");
    }).await;
}
    [expr.closure.async.edition2018]

    تفاوت‌های ویرایش 2018 بستارهای ناهمگام تنها از Rust 2018 به بعد در دسترس هستند.

    مثال

    در این مثال، تابعی به‌نام ten_times تعریف می‌کنیم که یک تابع مرتبه‌بالاتر را به‌عنوان آرگومان می‌گیرد. سپس آن را ابتدا با یک عبارت بستار به‌عنوان آرگومان و بعد با عبارت بستاری که مقدارها را از محیطش جابه‌جا می‌کند، فراخوانی می‌کنیم.

    fn ten_times<F>(f: F) where F: Fn(i32) {
    for index in 0..10 {
        f(index);
    }
}

ten_times(|j| println!("hello, {}", j));
// With type annotations
ten_times(|j: i32| -> () { println!("hello, {}", j) });

let word = "konnichiwa".to_owned();
ten_times(move |j| println!("{}, {}", word, j));
