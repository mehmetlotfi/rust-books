    [patterns.intro]

    الگوها برای تطبیق مقدارها با ساختارها و در صورت نیاز مقیدکردن متغیرها به مقدارهای درون آن ساختارها به کار می‌روند. همچنین در اعلان متغیرها و پارامترهای تابع‌ها و بستارها استفاده می‌شوند.

    الگوی نمونهٔ زیر چهار کار انجام می‌دهد:

    • بررسی می‌کند فیلد car در person دارای مقدار باشد.
    • بررسی می‌کند فیلد age میان ۱۳ و ۱۹ باشد و مقدارش را به متغیر person_age مقید می‌کند.
    • ارجاعی به فیلد name را به متغیر person_name مقید می‌کند.
    • دیگر فیلدهای person را نادیده می‌گیرد؛ آن‌ها می‌توانند هر مقداری داشته باشند و به متغیری مقید نمی‌شوند.
    struct Car;
struct Computer;
struct Person {
    name: String,
    car: Option<Car>,
    computer: Option<Computer>,
    age: u8,
}
let person = Person {
    name: String::from("John"),
    car: Some(Car),
    computer: None,
    age: 15,
};
if let
    Person {
        car: Some(_),
        age: person_age @ 13..=19,
        name: ref person_name,
        ..
    } = person
{
    println!("{} has a car and is {} years old.", person_name, person_age);
}

    [patterns.destructure]

    ساختارشکنی

    [patterns.destructure.intro]

    از الگوها می‌توان برای ساختارشکنی ساختارها، برشمردنی‌ها و چندتایی‌ها استفاده کرد. ساختارشکنی مقدار را به اجزایش می‌شکند و نحو آن تقریباً با ساخت همان مقدارها یکسان است.

    [patterns.destructure.wildcard]

    در الگویی که عبارت مورد تطبیق آن نوع struct، enum یا tuple دارد، الگوی نویسهٔ عام یعنی _ جای یک فیلد داده را می‌گیرد؛ در حالی که ادامه یا الگوی باقی‌مانده یعنی .. نمایندهٔ همهٔ فیلدهای باقی‌ماندهٔ یک گونه است.

    [patterns.destructure.named-field-shorthand]

    هنگام ساختارشکنی ساختار داده با فیلدهای نام‌دار و نه شماره‌دار، می‌توان fieldname را به‌عنوان شکل کوتاه fieldname: fieldname نوشت.

    enum Message {
    Quit,
    WriteString(String),
    Move { x: i32, y: i32 },
    ChangeColor(u8, u8, u8),
}
let message = Message::Quit;
match message {
    Message::Quit => println!("Quit"),
    Message::WriteString(write) => println!("{}", &write),
    Message::Move{ x, y: 0 } => println!("move {} horizontally", x),
    Message::Move{ .. } => println!("other move"),
    Message::ChangeColor { 0: red, 1: green, 2: _ } => {
        println!("color change, red: {}, green: {}", red, green);
    }
};
    [patterns.refutable]

    انکارپذیری

    الگویی انکارپذیر است اگر ممکن باشد مقدار مورد تطبیق با آن جور نشود. در مقابل، الگوهای انکارناپذیر همیشه با مقدار مورد تطبیق جور می‌شوند. نمونه‌ها:

    let (x, y) = (1, 2);               // "(x, y)" is an irrefutable pattern

if let (a, 3) = (1, 2) {           // "(a, 3)" is refutable, and will not match
    panic!("Shouldn't reach here");
} else if let (a, 4) = (3, 4) {    // "(a, 4)" is refutable, and will match
    println!("Matched ({}, 4)", a);
}
    [patterns.literal]

    الگوهای لیترال

    [patterns.literal.syntax]

    Syntax
    LiteralPattern → -? LiteralExpression

    [patterns.literal.intro]

    الگوهای لیترال دقیقاً با همان مقداری تطبیق می‌یابند که لیترال می‌سازد. چون عددهای منفی لیترال نیستند، لیترال در الگو می‌تواند پیشوند منفی اختیاری داشته باشد که مانند عملگر منفی‌سازی کار می‌کند.

    Warning

    هشدار لیترال‌های رشتهٔ C و رشتهٔ خام C در الگوهای لیترال پذیرفته می‌شوند، اما &CStr برابری ساختاری (#[derive(Eq, PartialEq)]) را پیاده‌سازی نمی‌کند؛ بنابراین هر match این‌چنینی روی &CStr با خطای نوع رد می‌شود.

    [patterns.literal.refutable]

    الگوهای لیترال همیشه انکارپذیرند.

    نمونه‌ها:

    for i in -2..5 {
    match i {
        -1 => println!("It's minus one"),
        1 => println!("It's a one"),
        2|4 => println!("It's either a two or a four"),
        _ => println!("Matched none of the arms"),
    }
}
    [patterns.ident]

    الگوهای شناسه

    [patterns.ident.syntax]

    Syntax
    IdentifierPattern → ref? mut? IDENTIFIER ( @ PatternNoTopAlt )?

    [patterns.ident.intro]

    الگوهای شناسه مقدار تطبیق‌یافته را به متغیری در فضای نام مقدار مقید می‌کنند.

    [patterns.ident.unique]

    شناسه باید درون الگو یکتا باشد.

    [patterns.ident.scope]

    متغیر هر متغیر هم‌نام در دامنه را زیر سایه می‌برد. دامنه مقیدسازی تازه به بافت استفاده از الگو، مانند مقیدسازی let یا بازوی match، وابسته است.

    [patterns.ident.bare]

    الگویی که تنها از یک شناسه و شاید mut تشکیل شده باشد با هر مقداری تطبیق می‌یابد و آن را به همان شناسه مقید می‌کند. این رایج‌ترین الگو در اعلان متغیر و پارامتر تابع و بستار است.

    let mut variable = 10;
fn sum(x: i32, y: i32) -> i32 {
   x + y
}
    [patterns.ident.scrutinized]

    برای مقیدکردن مقدار تطبیق‌یافته به متغیر، از نحو variable @ subpattern استفاده کنید. نمونهٔ زیر مقدار ۲ را به e مقید می‌کند، نه کل بازه را؛ بازه در اینجا یک زیرالگوی بازه است.

    let x = 2;

match x {
    e @ 1 ..= 5 => println!("got a range element {}", e),
    _ => println!("anything"),
}
    [patterns.ident.move]

    الگوی شناسه به‌طور پیش‌فرض و بسته به پیاده‌سازی Copy در مقدار، متغیر را به یک کپی از مقدار تطبیق‌یافته مقید می‌کند یا مقدار را انتقال می‌دهد.

    [patterns.ident.ref]

    با کلیدواژهٔ ref می‌توان به‌جای آن ارجاع و با ref mut ارجاع تغییرپذیر را مقید کرد. برای نمونه:

    let a = Some(10);
match a {
    None => (),
    Some(value) => (),
}

match a {
    None => (),
    Some(ref value) => (),
}

    در عبارت match نخست، مقدار کپی یا منتقل می‌شود. در match دوم، ارجاعی به همان مکان حافظه به متغیر value مقید می‌شود. این نحو لازم است، زیرا در زیرالگوهای ساختارشکنی نمی‌توان عملگر & را روی فیلدهای مقدار اعمال کرد. کد زیر معتبر نیست:

    struct Person {
   name: String,
   age: u8,
}
let value = Person { name: String::from("John"), age: 23 };
if let Person { name: &person_name, age: 18..=150 } = value { }

    شکل معتبر آن چنین است:

    struct Person {
   name: String,
   age: u8,
}
let value = Person { name: String::from("John"), age: 23 };
if let Person { name: ref person_name, age: 18..=150 } = value { }
    [patterns.ident.ref-ignored]

    بنابراین ref چیزی نیست که با آن تطبیق انجام شود؛ تنها هدفش تبدیل مقیدسازی به ارجاع به‌جای کپی یا انتقال احتمالی مقدار است.

    [patterns.ident.precedent]

    الگوهای مسیر بر الگوهای شناسه تقدم دارند.

    Note

    نکته وقتی الگو شناسه‌ای تک‌بخشی است، دستور زبان میان IdentifierPattern و PathPattern مبهم است. این ابهام تنها پس از تفکیک نام حل می‌شود.

    const EXPECTED_VALUE: u8 = 42;
//    ^^^^^^^^^^^^^^ That this constant is in scope affects how the
//                   patterns below are treated.

fn check_value(x: u8) -> Result<u8, u8> {
    match x {
        EXPECTED_VALUE => Ok(x),
    //  ^^^^^^^^^^^^^^ Parsed as a `PathPattern` that resolves to
    //                 the constant `42`.
        other_value => Err(x),
    //  ^^^^^^^^^^^ Parsed as an `IdentifierPattern`.
    }
}

// If `EXPECTED_VALUE` were treated as an `IdentifierPattern` above,
// that pattern would always match, making the function always return
// `Ok(_) regardless of the input.
assert_eq!(check_value(42), Ok(42));
assert_eq!(check_value(43), Err(43));
    [patterns.ident.constraint]

    اگر ref یا ref mut مشخص شده باشد و شناسه یک ثابت را زیر سایه ببرد، خطاست.

    [patterns.ident.refutable]

    اگر زیرالگوی @ انکارناپذیر باشد یا زیرالگویی مشخص نشده باشد، الگوی شناسه انکارناپذیر است.

    [patterns.ident.binding]

    شیوه‌های مقیدسازی

    [patterns.ident.binding.intro]

    برای استفادهٔ روان‌تر، الگوها با شیوه‌های مقیدسازی متفاوت کار می‌کنند تا مقیدکردن ارجاع به مقدار آسان‌تر شود. وقتی مقدار ارجاعی با الگوی غیرارجاعی تطبیق یابد، به‌طور خودکار مقیدسازی ref یا ref mut در نظر گرفته می‌شود. نمونه:

    let x: &Option<i32> = &Some(3);
if let Some(y) = x {
    // y was converted to `ref y` and its type is &i32
}
    [patterns.ident.binding.non-reference]

    الگوهای غیرارجاعی همهٔ الگوها جز مقیدسازی‌ها، الگوهای نویسهٔ عام یعنی _، الگوهای const از نوع ارجاع و الگوهای ارجاع را در بر می‌گیرند.

    [patterns.ident.binding.default-mode]

    اگر الگوی مقیدسازی صراحتاً ref، ref mut یا mut نداشته باشد، شیوهٔ مقیدسازی پیش‌فرض چگونگی مقیدشدن متغیر را تعیین می‌کند.

    [patterns.ident.binding.move]

    کامپایلر تطبیق الگو را از بیرون آغاز می‌کند و به درون می‌رود.

    [patterns.ident.binding.top-down]

    هر بار ارجاعی با الگوی غیرارجاعی تطبیق یابد، مقدار خودکار ارجاع‌زدایی و شیوهٔ پیش‌فرض به‌روزرسانی می‌شود.

    [patterns.ident.binding.auto-deref]

    هر بار که یک ارجاع با الگویی غیر از الگوی ارجاع تطبیق داده شود، مقدار به‌طور خودکار ارجاع‌زدایی می‌شود و شیوهٔ اتصال پیش‌فرض به‌روزرسانی می‌شود.

    [patterns.ident.binding.ref]

    ارجاع‌ها شیوهٔ پیش‌فرض را روی ref می‌گذارند.

    [patterns.ident.binding.ref-mut]

    ارجاع‌های تغییرپذیر شیوه را روی ref mut تنظیم می‌کنند، مگر آنکه شیوه از پیش ref باشد که در این صورت همان ref باقی می‌ماند.

    [patterns.ident.binding.nested-references]

    اگر مقدار ارجاع‌زدایی‌شده هنوز ارجاع باشد، دوباره ارجاع‌زدایی می‌شود و فرایند تکرار می‌گردد.

    [patterns.ident.binding.mode-limitations-binding]

    الگوی مقیدسازی تنها زمانی می‌تواند صراحتاً شیوهٔ ref یا ref mut یا تغییرپذیری mut را مشخص کند که شیوهٔ پیش‌فرض move باشد. نمونه‌های زیر پذیرفته نمی‌شوند:

    let [mut x] = &[()]; //~ ERROR
let [ref x] = &[()]; //~ ERROR
let [ref mut x] = &mut [()]; //~ ERROR
    [patterns.ident.binding.mode-limitations-binding-edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴، حتی وقتی شیوهٔ پیش‌فرض move نبود، مقیدسازی می‌توانست صراحتاً ref یا ref mut و با mut تغییرپذیری را مشخص کند. در آن ویرایش‌ها، mut بدون توجه به شیوهٔ پیش‌فرض جاری، شیوه را روی move می‌گذاشت.

    [patterns.ident.binding.mode-limitations-reference]

    به همین ترتیب، الگوی ارجاع تنها زمانی می‌تواند ظاهر شود که شیوهٔ اتصال پیش‌فرض «move» باشد. برای مثال، این پذیرفته نمی‌شود:

    let [&x] = &[&()]; //~ ERROR
    [patterns.ident.binding.mode-limitations-reference-edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴، الگوهای ارجاع حتی با شیوهٔ پیش‌فرض غیر move نیز می‌توانستند ظاهر شوند؛ هم با مورد تطبیق جور می‌شدند و هم شیوهٔ پیش‌فرض را به move بازمی‌گرداندند.

    [patterns.ident.binding.mixed]

    مقیدسازی انتقال و ارجاع را می‌توان در یک الگو آمیخت. این کار باعث انتقال جزئی شیء می‌شود و پس از آن کل شیء قابل استفاده نیست. این قاعده تنها برای نوع‌های غیرقابل کپی است.

    در نمونهٔ زیر name از person منتقل می‌شود. استفاده از کل person یا person.name به‌سبب انتقال جزئی خطا خواهد بود.

    نمونه:

    struct Person {
   name: String,
   age: u8,
}
let person = Person{ name: String::from("John"), age: 23 };
// `name` is moved from person and `age` referenced
let Person { name, ref age } = person;
    [patterns.wildcard]

    الگوی نویسهٔ عام

    [patterns.wildcard.syntax]

    Syntax
    WildcardPattern → _

    [patterns.wildcard.intro]

    الگوی نویسهٔ عام یعنی زیرخط، با هر مقداری تطبیق می‌یابد و برای نادیده‌گرفتن مقدارهای بی‌اهمیت به کار می‌رود.

    [patterns.wildcard.struct-matcher]

    درون الگوهای دیگر با یک فیلد داده تطبیق می‌یابد؛ برخلاف .. که همهٔ فیلدهای باقی‌مانده را می‌گیرد.

    [patterns.wildcard.no-binding]

    برخلاف الگوی شناسه، مقدار تطبیق‌یافته را کپی، منتقل یا وام نمی‌گیرد.

    نمونه‌ها:

    let x = 20;
let (a, _) = (10, x);   // the x is always matched by _
assert_eq!(a, 10);

// ignore a function/closure param
let real_part = |a: f64, _: f64| { a };

// ignore a field from a struct
struct RGBA {
   r: f32,
   g: f32,
   b: f32,
   a: f32,
}
let color = RGBA{r: 0.4, g: 0.1, b: 0.9, a: 0.5};
let RGBA{r: red, g: green, b: blue, a: _} = color;
assert_eq!(color.r, red);
assert_eq!(color.g, green);
assert_eq!(color.b, blue);

// accept any Some, with any value
let x = Some(10);
if let Some(_) = x {}
    [patterns.wildcard.refutable]

    الگوی نویسهٔ عام همیشه انکارناپذیر است.

    [patterns.rest]

    الگوی باقی‌مانده

    [patterns.rest.syntax]

    Syntax
    RestPattern → ..

    [patterns.rest.intro]

    الگوی باقی‌مانده یعنی توکن .. الگویی با طول متغیر است که با صفر یا چند عنصری تطبیق می‌یابد که پیش یا پس از آن تطبیق نیافته‌اند.

    [patterns.rest.allowed-patterns]

    تنها در الگوهای چندتایی، ساختار چندتایی و برش قابل استفاده است و در هر الگو فقط یک بار می‌آید. همچنین فقط برای الگوهای برش درون الگوی شناسه مجاز است.

    [patterns.rest.refutable]

    الگوی باقی‌مانده همیشه انکارناپذیر است.

    نمونه‌ها:

    let words = vec!["a", "b", "c"];
let slice = &words[..];
match slice {
    [] => println!("slice is empty"),
    [one] => println!("single element {}", one),
    [head, tail @ ..] => println!("head={} tail={:?}", head, tail),
}

match slice {
    // Ignore everything but the last element, which must be "!".
    [.., "!"] => println!("!!!"),

    // `start` is a slice of everything except the last element, which must be "z".
    [start @ .., "z"] => println!("starts with: {:?}", start),

    // `end` is a slice of everything but the first element, which must be "a".
    ["a", end @ ..] => println!("ends with: {:?}", end),

    // 'whole' is the entire slice and `last` is the final element
    whole @ [.., last] => println!("the last element of {:?} is {}", whole, last),

    rest => println!("{:?}", rest),
}

if let [.., penultimate, _] = slice {
    println!("next to last is {}", penultimate);
}

let tuple = (1, 2, 3, 4, 5);
// The rest pattern may also be used in tuple and tuple
// struct patterns.
match tuple {
    (1, .., y, z) => println!("y={} z={}", y, z),
    (.., 5) => println!("tail must be 5"),
    (..) => println!("matches everything else"),
}
    [patterns.range]

    الگوهای بازه

    [patterns.range.syntax]

    Syntax
    ModernRangePattern →
          RangeExclusivePattern
        | RangeInclusivePattern
        | RangeFromPattern
        | RangeToExclusivePattern
        | RangeToInclusivePattern

    RangeExclusivePattern →
          RangePatternBound .. RangePatternBound

    RangeInclusivePattern →
          RangePatternBound ..= RangePatternBound

    RangeFromPattern →
          RangePatternBound ..

    RangeToExclusivePattern →
          .. RangePatternBound

    RangeToInclusivePattern →
          ..= RangePatternBound

    ObsoleteRangePattern →
        RangePatternBound ... RangePatternBound

    RangePatternBound →
          LiteralPattern
        | PathExpression

    [patterns.range.intro]

    الگوهای بازه با مقدارهای اسکالر در بازهٔ تعریف‌شده به‌وسیلهٔ کران‌ها تطبیق می‌یابند. آن‌ها از یک نشان (.. یا ..=) و کران در یک یا هر دو سوی آن تشکیل می‌شوند.

    کران سمت چپ کران پایین و کران سمت راست کران بالا نام دارد.

    [patterns.range.exclusive]

    الگوی بازهٔ غیرشامل با همهٔ مقدارها از کران پایین تا پیش از کران بالا تطبیق می‌یابد و به‌شکل کران پایین، .. و کران بالا نوشته می‌شود.

    برای نمونه، 'm'..'p' تنها با 'm'، 'n' و 'o' تطبیق می‌یابد و مشخصاً 'p' را شامل نمی‌شود.

    [patterns.range.inclusive]

    الگوی بازهٔ شامل با همهٔ مقدارها از کران پایین تا خود کران بالا تطبیق می‌یابد و با ..= نوشته می‌شود.

    برای نمونه، 'm'..='p' با 'm'، 'n'، 'o' و 'p' تطبیق می‌یابد.

    [patterns.range.from]

    الگوی بازه از با همهٔ مقدارهای بزرگ‌تر یا مساوی کران پایین تطبیق می‌یابد و با کران پایین و سپس .. نوشته می‌شود.

    برای نمونه، 1.. با هر عدد صحیح بزرگ‌تر یا مساوی ۱ مانند ۱، ۹ یا ۹۰۰۱ تطبیق می‌یابد، اما با ۰ یا عددهای منفی تطبیق ندارد.

    [patterns.range.to-exclusive]

    الگوی بازه تا به‌صورت غیرشامل با همهٔ مقدارهای کوچک‌تر از کران بالا تطبیق می‌یابد و با .. و سپس کران بالا نوشته می‌شود.

    برای نمونه، ..10 با هر عدد صحیح کوچک‌تر از ۱۰ مانند ۹، ۱، ۰ و در نوع‌های علامت‌دار همهٔ مقدارهای منفی تطبیق می‌یابد.

    [patterns.range.to-inclusive]

    الگوی بازه تا به‌صورت شامل با همهٔ مقدارهای کوچک‌تر یا مساوی کران بالا تطبیق می‌یابد و با ..= و سپس کران بالا نوشته می‌شود.

    برای نمونه، ..=10 با هر عدد صحیح کوچک‌تر یا مساوی ۱۰، از جمله ۱۰، ۱، ۰ و همهٔ مقدارهای منفی نوع‌های علامت‌دار تطبیق می‌یابد.

    [patterns.range.constraint-nonempty]

    الگوی بازه نباید خالی باشد و باید دست‌کم یک مقدار از مجموعهٔ مقدارهای ممکن نوع را پوشش دهد. به بیان دیگر:

    • در a..=b باید a ≤ b باشد؛ 10..=0 خطاست ولی 10..=10 مجاز است.
    • در a..b باید a < b باشد؛ 10..0 و 10..10 خطا هستند.
    • در ..b، مقدار b نباید کوچک‌ترین مقدار نوع باشد؛ ..-128i8 و ..f64::NEG_INFINITY خطا هستند.
    [patterns.range.bound]

    کران به یکی از شکل‌های زیر نوشته می‌شود:

    • لیترال نویسه، بایت، عدد صحیح یا ممیز شناور.
    • - و سپس لیترال عدد صحیح یا ممیز شناور.
    • نکته

    Note

    از نظر نحوی موارد بیشتری برای RangePatternBound پذیرفته می‌شوند، اما بعداً از نظر معنایی رد خواهند شد.

    [patterns.range.constraint-bound-path]

    اگر کران به‌صورت مسیر نوشته شود، پس از تفکیک ماکرو باید به آیتم ثابتی از نوع char، نوع صحیح یا نوع ممیز شناور تفکیک شود.

    [patterns.range.type]

    الگوی بازه با نوع کران‌های بالا و پایین خود تطبیق می‌یابد و هر دو باید هم‌نوع باشند.

    [patterns.range.path-value]

    اگر کران مسیر باشد، نوع و مقدار ثابتی را دارد که مسیر به آن تفکیک می‌شود.

    [patterns.range.literal-value]

    اگر کران لیترال باشد، نوع و مقدار عبارت لیترال متناظر را دارد.

    [patterns.range.negation]

    اگر کران لیترالی با پیشوند - باشد، نوع عبارت لیترال متناظر و مقدار منفی‌شدهٔ آن را دارد.

    [patterns.range.float-restriction]

    در الگوی بازهٔ ممیز شناور، ثابت نمی‌تواند NaN باشد.

    نمونه‌ها:

    let c = 'f';
let valid_variable = match c {
    'a'..='z' => true,
    'A'..='Z' => true,
    'α'..='ω' => true,
    _ => false,
};

let ph = 10;
println!("{}", match ph {
    0..7 => "acid",
    7 => "neutral",
    8..=14 => "base",
    _ => unreachable!(),
});

let uint: u32 = 5;
match uint {
    0 => "zero!",
    1.. => "positive number!",
};

// using paths to constants:
const TROPOSPHERE_MIN : u8 = 6;
const TROPOSPHERE_MAX : u8 = 20;

const STRATOSPHERE_MIN : u8 = TROPOSPHERE_MAX + 1;
const STRATOSPHERE_MAX : u8 = 50;

const MESOSPHERE_MIN : u8 = STRATOSPHERE_MAX + 1;
const MESOSPHERE_MAX : u8 = 85;

let altitude = 70;

println!("{}", match altitude {
    TROPOSPHERE_MIN..=TROPOSPHERE_MAX => "troposphere",
    STRATOSPHERE_MIN..=STRATOSPHERE_MAX => "stratosphere",
    MESOSPHERE_MIN..=MESOSPHERE_MAX => "mesosphere",
    _ => "outer space, maybe",
});

pub mod binary {
    pub const MEGA : u64 = 1024*1024;
    pub const GIGA : u64 = 1024*1024*1024;
}
let n_items = 20_832_425;
let bytes_per_item = 12;

}

trait MaxValue {
    const MAX: u64;
}
impl MaxValue for u8 {
    const MAX: u64 = (1 << 8) - 1;
}
impl MaxValue for u16 {

}

    const MAX: u64 = (1 << 32) - 1;
}
// using qualified paths:
println!("{}", match 0xfacade {
    0 ..= <u8 as MaxValue>::MAX => "fits in a u8",
    0 ..= <u16 as MaxValue>::MAX => "fits in a u16",
    0 ..= <u32 as MaxValue>::MAX => "fits in a u32",
    _ => "too big",
});
    [patterns.range.refutable]

    الگوهای بازه برای نوع‌های صحیح با پهنای ثابت و char هنگامی انکارناپذیرند که همهٔ مقدارهای ممکن نوع را پوشش دهند. برای نمونه 0u8..=255u8 انکارناپذیر است.

    [patterns.range.refutable-integer]

    بازهٔ مقدارهای نوع صحیح، بازهٔ بسته از کمینه تا بیشینهٔ آن است.

    [patterns.range.refutable-char]

    بازهٔ مقدارهای char دقیقاً بازه‌هایی است که همهٔ مقدارهای اسکالر Unicode را در بر می‌گیرد: '\u{0000}'..='\u{D7FF}' و '\u{E000}'..='\u{10FFFF}'.

    [patterns.range.constraint-slice]

    نمی‌توان از RangeFromPattern به‌عنوان الگوی سطح بالای زیرالگوها در الگوهای برش استفاده کرد. برای نمونه، الگوی [1.., _] معتبر نیست.

    [patterns.range.edition2021]

    تفاوت‌های ویرایش 2021 پیش از ویرایش ۲۰۲۱، الگوی بازه با هر دو کران را می‌شد با ... به‌جای ..= و همان معنا نوشت.

    [patterns.ref]

    الگوهای ارجاع

    [patterns.ref.syntax]

    Syntax
    ReferencePattern → ( & | && ) mut? PatternWithoutModernRange

    [patterns.ref.intro]

    الگوهای ارجاع، اشاره‌گرهای مورد تطبیق را ارجاع‌زدایی و در نتیجه وام می‌گیرند.

    برای نمونه، این دو تطبیق روی x: &i32 معادل‌اند:

    let int_reference = &3;

let a = match *int_reference { 0 => "zero", _ => "some" };
let b = match int_reference { &0 => "zero", _ => "some" };

assert_eq!(a, b);
    [patterns.ref.ref-ref]

    تولید دستوری الگوی ارجاع برای تطبیق ارجاع به ارجاع باید با توکن && تطبیق یابد، زیرا این یک توکن مستقل است نه دو توکن &.

    [patterns.ref.mut]

    افزودن mut ارجاع تغییرپذیر را ارجاع‌زدایی می‌کند. تغییرپذیری باید با تغییرپذیری ارجاع یکسان باشد.

    [patterns.ref.refutable]

    الگوهای ارجاع همیشه انکارناپذیرند.

    [patterns.struct]

    الگوهای ساختار

    [patterns.struct.syntax]

    Syntax
    StructPattern →
        PathInExpression {
            StructPatternElements?
        }

    StructPatternElements →
          StructPatternFields ( , | , StructPatternEtCetera )?
        | StructPatternEtCetera

    [patterns.struct.intro]

    الگوهای ساختار با مقدارهای ساختار، برشمردنی و اجتماع که همهٔ معیارهای زیرالگوها را برآورده کنند تطبیق می‌یابند و برای ساختارشکنی آن‌ها نیز به کار می‌روند.

    [patterns.struct.ignore-rest]

    در الگوی ساختار، فیلدها با نام، اندیس در ساختار چندتایی، یا با .. برای نادیده‌گرفتن ارجاع داده می‌شوند:

    struct Point {
    x: u32,
    y: u32,
}
let s = Point {x: 1, y: 1};

match s {
    Point {x: 10, y: 20} => (),
    Point {y: 10, x: 20} => (),    // order doesn't matter
    Point {x: 10, ..} => (),
    Point {..} => (),
}

struct PointTuple (
    u32,
    u32,
);
let t = PointTuple(1, 2);

match t {
    PointTuple {0: 10, 1: 20} => (),
    PointTuple {1: 10, 0: 20} => (),   // order doesn't matter
    PointTuple {0: 10, ..} => (),
    PointTuple {..} => (),
}

enum Message {
    Quit,
    Move { x: i32, y: i32 },
}
let m = Message::Quit;

match m {
    Message::Quit => (),
    Message::Move {x: 10, y: 20} => (),
    Message::Move {..} => (),
}
    [patterns.struct.constraint-struct]

    اگر .. استفاده نشود، الگوی ساختار باید همهٔ فیلدها را مشخص کند:

    struct Struct {
   a: i32,
   b: char,
   c: bool,
}
let mut struct_value = Struct{a: 10, b: 'X', c: false};

match struct_value {
    Struct{a: 10, b: 'X', c: false} => (),
    Struct{a: 10, b: 'X', ref c} => (),
    Struct{a: 10, b: 'X', ref mut c} => (),
    Struct{a: 10, b: 'X', c: _} => (),
    Struct{a: _, b: _, c: _} => (),
}
    [patterns.struct.constraint-union]

    الگوی ساختار برای تطبیق اجتماع باید دقیقاً یک فیلد را مشخص کند؛ تطبیق الگو روی اجتماع‌ها را ببینید.

    [patterns.struct.binding-shorthand]

    نحو IDENTIFIER با هر مقداری تطبیق می‌یابد و آن را به متغیری هم‌نام با فیلد مقید می‌کند. این شکل کوتاه fieldname: fieldname است. تعیین‌کننده‌های ref و mut نیز با رفتار patterns.ident.ref قابل استفاده‌اند.

    struct Struct {
   a: i32,
   b: char,
   c: bool,
}
let struct_value = Struct{a: 10, b: 'X', c: false};

let Struct { a, b, c } = struct_value;
    [patterns.struct.refutable]

    اگر PathInExpression به سازندهٔ برشمردنی چندگونه‌ای تفکیک شود یا یکی از زیرالگوها انکارپذیر باشد، الگوی ساختار انکارپذیر است.

    [patterns.struct.namespace]

    الگوی ساختار با ساختار، اجتماع یا گونهٔ برشمردنی‌ای تطبیق می‌یابد که سازنده‌اش از PathInExpression در فضای نام نوع تفکیک می‌شود. patterns.tuple-struct.namespace را ببینید.

    [patterns.tuple-struct]

    الگوهای ساختار چندتایی

    [patterns.tuple-struct.syntax]

    Syntax
    TupleStructPattern → PathInExpression ( TupleStructItems? )

    TupleStructItems → Pattern ( , Pattern )* ,?

    [patterns.tuple-struct.intro]

    الگوهای ساختار چندتایی با مقدارهای ساختار چندتایی و برشمردنی که معیارهای زیرالگوها را برآورده کنند تطبیق می‌یابند و برای ساختارشکنی آن‌ها نیز به کار می‌روند.

    [patterns.tuple-struct.refutable]

    اگر PathInExpression به سازندهٔ برشمردنی چندگونه‌ای تفکیک شود یا یکی از زیرالگوها انکارپذیر باشد، الگوی ساختار چندتایی انکارپذیر است.

    [patterns.tuple-struct.namespace]

    الگوی ساختار چندتایی با ساختار چندتایی یا گونهٔ برشمردنی شبیه چندتایی تطبیق می‌یابد که سازنده‌اش از PathInExpression در فضای نام مقدار تفکیک شده است.

    Note

    نکته در مقابل، الگوی ساختار برای ساختار چندتایی یا گونهٔ شبیه چندتایی مانند S { 0: _ } با سازنده‌ای تطبیق می‌یابد که در فضای نام نوع تفکیک شده است.

    enum E1 { V(u16) }
enum E2 { V(u32) }

// Import `E1::V` from the type namespace only.
mod _0 {
    const V: () = (); // For namespace masking.
    pub(super) use super::E1::*;
}
use _0::*;

// Import `E2::V` from the value namespace only.
mod _1 {
    struct V {} // For namespace masking.
    pub(super) use super::E2::*;
}
use _1::*;

fn f() {
    // This struct pattern matches against the tuple-like
    // enum variant whose constructor was found in the type
    // namespace.
    let V { 0: ..=u16::MAX } = (loop {}) else { loop {} };
    // This tuple struct pattern matches against the tuple-like
    // enum variant whose constructor was found in the value
    // namespace.
    let V(..=u32::MAX) = (loop {}) else { loop {} };
}
// Required due to the odd behavior of `super` within functions.
fn main() {}

    تیم Lang تصمیم‌هایی گرفته است، مانند آنچه در PR #138458 آمده، که دربارهٔ مطلوب‌بودن استفاده از فضای نام مقدار (value namespace) به این شکل برای الگوها پرسش‌هایی ایجاد می‌کند، همان‌طور که در PR #140593 توضیح داده شده است. شاید عاقلانه باشد که عمداً در کد خود به این ظرافت تکیه نکنید.

    [patterns.tuple.syntax]

    [patterns.tuple.intro]

    الگوهای چندتایی با مقدارهایی تطبیق می‌یابند که همهٔ معیارهای زیرالگوها را برآورده کنند و برای ساختارشکنی چندتایی نیز به کار می‌روند.

    [patterns.tuple.rest-syntax]

    شکل (..) با یک RestPattern حالت ویژه‌ای است که به ویرگول نیاز ندارد و با چندتایی هر اندازه‌ای تطبیق می‌یابد.

    [patterns.tuple.refutable]

    let pair = (10, "ten");
let (a, b) = pair;

assert_eq!(a, 10);
assert_eq!(b, "ten");

    let int_reference = &3;

    [patterns.slice]

    الگوهای برش

    [patterns.slice.syntax]

    Syntax
    SlicePattern → [ SlicePatternItems? ]

    SlicePatternItems → Pattern ( , Pattern )* ,?

    [patterns.slice.intro]

    الگوهای برش هم با آرایه‌های اندازه‌ثابت و هم با برش‌های اندازه‌پویا تطبیق می‌یابند.

    // Fixed size
let arr = [1, 2, 3];
match arr {
    [1, _, _] => "starts with one",
    [a, b, c] => "starts with something else",
};
    // Dynamic size
let v = vec![1, 2, 3];
match v[..] {
    [a, b] => { /* this arm will not apply because the length doesn't match */ }
    [a, b, c] => { /* this arm will apply */ }
    _ => { /* this wildcard is required, since the length is not known statically */ }
};
    [patterns.slice.refutable-array]

    الگوی برش هنگام تطبیق آرایه، تا زمانی که هر عنصر انکارناپذیر باشد، انکارناپذیر است.

    [patterns.slice.refutable-slice]

    هنگام تطبیق برش، الگو تنها در شکل دارای یک الگوی باقی‌مانده .. یا الگوی شناسه با زیرالگوی .. انکارناپذیر است.

    [patterns.slice.restriction]

    درون برش، الگوی بازه‌ای که هر دو کران را ندارد باید مانند (a..) در پرانتز باشد تا روشن شود با یک عنصر تطبیق می‌یابد. بازهٔ دارای هر دو کران مانند a..=b به پرانتز نیاز ندارد.

    [patterns.path.unqualified]

    • ثابت‌ها
    • ثابت‌های وابسته

    [patterns.const.structural-equality]

    [patterns.const.primitive]

    [patterns.const.builtin-aggregate]
    • چندتایی، آرایه و برش زمانی برابری ساختاری دارند که همهٔ فیلدها یا عنصرهایشان داشته باشند؛ () و [] همیشه دارند.
    [patterns.const.ref]
    • ارجاع زمانی برابری ساختاری دارد که مقدار مقصد آن داشته باشد.
    [patterns.const.aggregate]
    • مقدار struct یا enum زمانی برابری ساختاری دارد که PartialEq آن با #[derive(PartialEq)] مشتق شده و همهٔ فیلدهای گونهٔ فعال برابری ساختاری داشته باشند.
    [patterns.const.pointer]
    • اشاره‌گر خام اگر به‌صورت عدد صحیح ثابت تعریف و سپس تبدیل شده باشد، برابری ساختاری دارد.
    [patterns.const.float]
    • مقدار ممیز شناور اگر NaN نباشد برابری ساختاری دارد.
    [patterns.const.exhaustive]
    • هیچ مورد دیگری برابری ساختاری ندارد.
    [patterns.const.generic]

    مقدار C باید هنگام ساخت الگو، یعنی پیش از تک‌ریخت‌سازی، معلوم باشد. بنابراین ثابت‌های وابسته‌ای که پارامتر عام دارند نمی‌توانند الگو باشند.

    [patterns.const.immutable]

    مقدار C نباید ارجاعی به ثابت‌های ایستای تغییرپذیر، شامل آیتم static mut یا static با تغییرپذیری درونی، یا ثابت ایستای extern داشته باشد.

    [patterns.const.translation]

    پس از احراز همهٔ شرایط، مقدار ثابت به الگو ترجمه می‌شود و دقیقاً مانند نوشتن مستقیم آن الگو رفتار می‌کند؛ از جمله کاملاً در بررسی جامعیت شرکت دارد. برای اشاره‌گر خام، ثابت‌ها تنها راه نوشتن چنین الگویی هستند و فقط _ برای این نوع‌ها جامع شمرده می‌شود.

    [patterns.or]

    الگوهای یا

    الگوهای یا با یکی از دو یا چند زیرالگو، مانند A | B | C، تطبیق می‌یابند و می‌توانند دلخواه تودرتو شوند. از نظر نحوی هرجا Pattern مجاز است این الگوها نیز مجازند، جز مقیدسازی‌های let و پارامترهای تابع و بستار که با PatternNoTopAlt نمایش داده می‌شوند.

    [patterns.constraints]

    معنای ایستا

    [patterns.constraints.pattern]

    1. الگوی p | q در هر عمقی برای الگوهای دلخواه p و q در شرایط زیر بدشکل است:

      • نوع استنتاج‌شده برای p با نوع استنتاج‌شده برای q یکسان‌سازی نشود؛ یا
      • مجموعهٔ مقیدسازی‌های معرفی‌شده در p و q یکسان نباشد؛ یا
      • دو مقیدسازی هم‌نام در p و q از نظر نوع یا شیوهٔ مقیدسازی با هم یکسان‌سازی نشوند.

      یکسان‌سازی نوع‌ها در همهٔ موارد بالا دقیق است و وادارسازی ضمنی نوع اعمال نمی‌شود.

    [patterns.constraints.match-type-check]

    \۲. هنگام بررسی نوع (type checking) عبارت match e_s { a_1 => e_1, ... a_n => e_n }، برای هر بازوی match مانند a_i که شامل الگویی به شکل p_i | q_i است، الگوی p_i | q_i بدشکل (ill formed) تلقی می‌شود اگر در عمق d که این الگو در آن قرار دارد، یعنی قطعهٔ e_s در عمق d، نوع قطعهٔ عبارت با p_i | q_i یکسان‌سازی (unify) نشود.

    [patterns.constraints.exhaustiveness-or-pattern]

    \۳. در بررسی جامعیت (exhaustiveness)، الگوی p | q به‌گونه‌ای در نظر گرفته می‌شود که هم p و هم q را پوشش می‌دهد. برای یک سازندهٔ دلخواه مانند c(x, ..) قانون توزیع‌پذیری برقرار است، به‌طوری که c(p | q, ..rest) همان مجموعهٔ مقدارهایی را پوشش می‌دهد که c(p, ..rest) | c(q, ..rest) پوشش می‌دهد. این قاعده را می‌توان به‌صورت بازگشتی اعمال کرد تا جایی که دیگر هیچ الگوی تودرتویی به شکل p | q باقی نماند، مگر آن‌هایی که در سطح بالا قرار دارند.

    منظور از «سازنده» تنها الگوی ساختار چندتایی نیست، بلکه الگوی هر نوع حاصل‌ضربی است؛ از جمله گونه‌های برشمردنی، ساختارهای چندتایی، ساختارهای دارای فیلد نام‌دار، آرایه‌ها، چندتایی‌ها و برش‌ها.

    [patterns.behavior]

    معنای پویا

    [patterns.behavior.nested-or-patterns]
    1. معنای پویای تطبیق یک عبارت scrutinee به نام e_s با الگوی c(p | q, ..rest) در عمق d، که در آن c یک سازندهٔ دلخواه است، p و q الگوهای دلخواه‌اند و rest به‌صورت اختیاری هر عامل باقی‌ماندهٔ احتمالی در c است، همان معنای c(p, ..rest) | c(q, ..rest) تعریف می‌شود.
    [patterns.precedence]

    تقدم نسبت به دیگر الگوهای بدون جداکننده

    چند گونه الگو از نظر نحوی جداکننده ندارند، از جمله الگوی شناسه، ارجاع و یا. الگوی یا همیشه کمترین تقدم را دارد. این کار هم فضای نحوی برای قابلیت احتمالی تعیین نوع در آینده نگه می‌دارد و هم ابهام را کم می‌کند. برای نمونه x @ A(..) | B(..) خطا می‌دهد چون x در همهٔ الگوها مقید نیست و &A(x) | B(x) میان نوع x در زیرالگوها ناسازگاری ایجاد می‌کند.
