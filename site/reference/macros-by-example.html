    [macro.decl]

    ماکروهای مبتنی بر مثال

    [macro.decl.syntax]

    Syntax
    MacroRulesDefinition →
        macro_rules ! IDENTIFIER MacroRulesDef

    MacroRulesDef →
          ( MacroRules ) ;
        | [ MacroRules ] ;
        | { MacroRules }

    MacroRules →
        MacroRule ( ; MacroRule )* ;?

    MacroRule →
        MacroMatcher => MacroTranscriber

    MacroMatcher →
          ( MacroMatch* )
        | [ MacroMatch* ]
        | { MacroMatch* }

    MacroMatch →
          Tokenexcept $ and delimiters
        | MacroMatcher
        | $ ( IDENTIFIER_OR_KEYWORDexcept crate | RAW_IDENTIFIER ) : MacroFragSpec
        | $ ( MacroMatch+ ) MacroRepSep? MacroRepOp

    MacroFragSpec →
          block | expr | expr_2021 | ident | item | lifetime | literal
        | meta | pat | pat_param | path | stmt | tt | ty | vis

    MacroRepSep → Tokenexcept delimiters and MacroRepOp

    MacroRepOp → * | + | ?

    MacroTranscriber → DelimTokenTree

    [macro.decl.intro]

    macro_rules به کاربران اجازه می‌دهد گسترش‌های نحوی را به‌شکلی اعلانی تعریف کنند. این گسترش‌ها را «ماکروهای مبتنی بر مثال» یا به‌اختصار «ماکروها» می‌نامیم.

    هر ماکروی مبتنی بر مثال یک نام و یک یا چند قاعده دارد. هر قاعده از دو بخش تشکیل می‌شود: یک تطبیق‌دهنده که نحو مورد تطبیق را توصیف می‌کند و یک رونویس که نحوی را توصیف می‌کند که جایگزین فراخوانی موفق خواهد شد. تطبیق‌دهنده و رونویس هر دو باید میان جداکننده‌ها قرار بگیرند. ماکروها می‌توانند به عبارت‌ها، گزاره‌ها، آیتم‌ها (از جمله صفت‌ها، پیاده‌سازی‌ها و آیتم‌های خارجی)، نوع‌ها یا الگوها گسترش یابند.

    [macro.decl.transcription]

    رونویسی

    [macro.decl.transcription.intro]

    وقتی ماکرویی فراخوانی می‌شود، گسترش‌دهندهٔ ماکرو فراخوانی را با نام پیدا می‌کند و قواعد ماکرو را به‌ترتیب می‌آزماید. نخستین تطبیق موفق رونویسی می‌شود؛ اگر این کار به خطا بینجامد، تطبیق‌های بعدی امتحان نمی‌شوند.

    [macro.decl.transcription.lookahead]

    هنگام تطبیق هیچ نگاه‌به‌جلویی انجام نمی‌شود؛ اگر کامپایلر نتواند با بررسی یک‌به‌یک توکن‌ها، شیوهٔ تجزیهٔ فراخوانی ماکرو را بدون ابهام تعیین کند، خطا رخ می‌دهد. در نمونهٔ زیر، کامپایلر پس از شناسه به جلو نگاه نمی‌کند تا ببیند توکن بعدی ) است؛ هرچند این کار اجازه می‌داد فراخوانی بدون ابهام تجزیه شود:

    macro_rules! ambiguity {
    ($($i:ident)* $j:ident) => { };
}

ambiguity!(error); // Error: local ambiguity
    [macro.decl.transcription.syntax]

    در تطبیق‌دهنده و رونویس، توکن $ برای فعال‌کردن رفتارهای ویژهٔ موتور ماکرو به کار می‌رود که در بخش‌های فرا‌متغیرها و تکرارها توضیح داده شده‌اند. توکن‌هایی که بخشی از چنین فراخوانی‌ای نیستند، به‌صورت لفظ‌به‌لفظ تطبیق و رونویسی می‌شوند، با یک استثنا: جداکننده‌های بیرونی تطبیق‌دهنده با هر جفت جداکننده‌ای تطبیق پیدا می‌کنند. بنابراین برای نمونه، تطبیق‌دهندهٔ (()) با {()} تطبیق دارد، اما با {{}} ندارد. نویسهٔ $ را نمی‌توان به‌شکل لفظی تطبیق داد یا رونویسی کرد.

    [macro.decl.transcription.fragment]

    فرستادن قطعهٔ تطبیق‌یافته

    هنگامی که قطعه‌ای تطبیق‌یافته به ماکروی مبتنی بر مثال دیگری فرستاده می‌شود، تطبیق‌دهنده‌های ماکروی دوم یک AST کدر از نوع همان قطعه می‌بینند. ماکروی دوم نمی‌تواند قطعه را در تطبیق‌دهنده با توکن‌های لفظی تطبیق دهد و تنها می‌تواند از مشخص‌کنندهٔ قطعه‌ای هم‌نوع استفاده کند. نوع‌های قطعهٔ ident، lifetime و tt استثنا هستند و می‌توانند با توکن‌های لفظی تطبیق داده شوند. نمونهٔ زیر این محدودیت را نشان می‌دهد:

    macro_rules! foo {
    ($l:expr) => { bar!($l); }
// ERROR:               ^^ no rules expected this token in macro call
}

macro_rules! bar {
    (3) => {}
}

foo!(3);

    نمونهٔ بعد نشان می‌دهد پس از تطبیق قطعهٔ tt چگونه می‌توان توکن‌ها را مستقیماً تطبیق داد:

    // compiles OK
macro_rules! foo {
    ($l:tt) => { bar!($l); }
}

macro_rules! bar {
    (3) => {}
}

foo!(3);
    [macro.decl.meta]

    فرامتغیرها

    [macro.decl.meta.intro]

    در تطبیق‌دهنده، ساختار $ نام : مشخص‌کنندهٔ قطعه با قطعه‌ای از نحو Rust از گونهٔ مشخص‌شده تطبیق می‌یابد و آن را به فرامتغیر $نام مقید می‌کند.

    [macro.decl.meta.specifier]

    مشخص‌کننده‌های معتبر قطعه عبارت‌اند از:

    • block: یک BlockExpressionNoInnerAttributes
    • expr: یک Expression
    • expr_2021: یک Expression به‌جز UnderscoreExpression و ConstBlockExpression (به macro.decl.meta.edition2024 نگاه کنید)
    • ident: یک IDENTIFIER_OR_KEYWORD به‌جز _، RAW_IDENTIFIER یا $crate
    • item: یک Item
    • lifetime: یک LIFETIME_TOKEN
    • literal: با -?LiteralExpression تطبیق می‌یابد
    • meta: یک Attr، یعنی محتوای یک ویژگی
    • pat: یک Pattern (به macro.decl.meta.edition2021 نگاه کنید)
    • pat_param: یک PatternNoTopAlt
    • path: یک TypePath
    • stmt: یک گزاره بدون نقطه‌ویرگول پایانی، به‌جز گزاره‌های آیتمی که به نقطه‌ویرگول نیاز دارند
    • tt: یک TokenTree؛ یعنی یک توکن یا توکن‌هایی میان جداکننده‌های متناظر ()، [] یا {}
    • ty: یک نوع
    • vis: یک تعیین‌کنندهٔ Visibility که ممکن است خالی باشد
    [macro.decl.meta.transcription]

    در رونویس، چون گونهٔ قطعه در تطبیق‌دهنده مشخص شده است، فرامتغیرها تنها با $نام ارجاع داده می‌شوند. فرامتغیرها با عنصر نحوی‌ای که با آن‌ها تطبیق یافته است جایگزین می‌شوند. هر فرامتغیر ممکن است چند بار یا اصلاً رونویسی نشود.

    [macro.decl.meta.dollar-crate]

    از فرامتغیر کلیدواژه‌ای $crate می‌توان برای اشاره به جعبهٔ جاری استفاده کرد.

    [macro.decl.meta.edition2021]

    تفاوت‌های ویرایش 2021 از ویرایش ۲۰۲۱ به بعد، مشخص‌کننده‌های قطعهٔ pat با الگوهای یا در سطح بالا تطبیق پیدا می‌کنند؛ یعنی Pattern را می‌پذیرند.

    پیش از ویرایش ۲۰۲۱، آن‌ها دقیقاً همان قطعه‌های pat_param را تطبیق می‌دادند؛ یعنی PatternNoTopAlt را می‌پذیرفتند.

    ویرایش مرتبط، ویرایشی است که برای تعریف macro_rules! برقرار است.

    [macro.decl.meta.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴، مشخص‌کننده‌های قطعهٔ expr در سطح بالا با UnderscoreExpression یا ConstBlockExpression تطبیق پیدا نمی‌کنند. استفاده از آن‌ها در زیرعبارت‌ها مجاز است.

    مشخص‌کنندهٔ قطعهٔ expr_2021 برای حفظ سازگاری رو به عقب با ویرایش‌های پیش از ۲۰۲۴ وجود دارد.

    [macro.decl.repetition]

    تکرارها

    [macro.decl.repetition.intro]

    در تطبیق‌دهنده و رونویس، تکرار با قراردادن توکن‌های تکرارشونده درون $(…) و سپس یک عملگر تکرار مشخص می‌شود؛ می‌توان یک توکن جداکنندهٔ اختیاری نیز میان آن‌ها قرار داد.

    [macro.decl.repetition.separator]

    توکن جداکننده می‌تواند هر توکنی جز جداکننده‌های نحوی یا عملگرهای تکرار باشد، اما ; و , رایج‌ترین‌اند. برای نمونه، $( $i:ident ),* هر تعداد شناسهٔ جداشده با ویرگول را نمایش می‌دهد. تکرارهای تودرتو مجازند.

    [macro.decl.repetition.operators]

    عملگرهای تکرار عبارت‌اند از:

    • * — هر تعداد تکرار را نشان می‌دهد.
    • + — هر تعداد، ولی دست‌کم یک تکرار را نشان می‌دهد.
    • ? — قطعه‌ای اختیاری با صفر یا یک رخداد را نشان می‌دهد.
    [macro.decl.repetition.optional-restriction]

    چون ? حداکثر یک رخداد را نمایش می‌دهد، نمی‌توان همراه آن از جداکننده استفاده کرد.

    [macro.decl.repetition.fragment]

    قطعهٔ تکرارشده هم با تعداد مشخص‌شده از قطعه‌ها که با توکن جداکننده از هم جدا شده‌اند تطبیق می‌یابد و هم همان‌گونه رونویسی می‌شود. فرامتغیرها با تک‌تک تکرارهای قطعهٔ متناظر خود تطبیق داده می‌شوند. برای نمونه، در $( $i:ident ),* بالا، $i با همهٔ شناسه‌های فهرست تطبیق می‌یابد.

    هنگام رونویسی، محدودیت‌های بیشتری بر تکرارها اعمال می‌شود تا کامپایلر بداند چگونه آن‌ها را درست گسترش دهد:

    1. فرامتغیر باید در رونویس دقیقاً با همان تعداد، گونه و ترتیب تودرتوی تکرارها ظاهر شود که در تطبیق‌دهنده ظاهر شده بود. بنابراین برای تطبیق‌دهندهٔ $( $i:ident ),*، رونویس‌های => { $i }، => { $( $( $i )* )* } و => { $( $i )+ } همگی نامعتبرند؛ اما => { $( $i );* } درست است و فهرست شناسه‌های جداشده با ویرگول را با فهرستی جداشده با نقطه‌ویرگول جایگزین می‌کند.
    2. هر تکرار در رونویس باید دست‌کم یک فرامتغیر داشته باشد تا تعداد دفعات گسترش آن مشخص شود. اگر چند فرامتغیر در یک تکرار باشند، باید به تعداد یکسانی قطعه مقید شده باشند. برای نمونه، ( $( $i:ident ),* ; $( $j:ident ),* ) => (( $( ($i,$j) ),* )) باید تعداد یکسانی قطعهٔ $i و $j را مقید کند. بنابراین فراخوانی با (a, b, c; d, e, f) معتبر است و به ((a,d), (b,e), (c,f)) گسترش می‌یابد، اما (a, b, c; d, e) نامعتبر است چون تعدادها یکسان نیستند. این الزام در همهٔ لایه‌های تکرار تودرتو برقرار است.
    [macro.decl.scope]

    دامنه، صادرکردن و واردکردن

    [macro.decl.scope.intro]

    به دلایل تاریخی، دامنه‌بندی ماکروهای مبتنی بر مثال کاملاً مانند آیتم‌ها کار نمی‌کند. ماکروها دو گونه دامنه دارند: دامنهٔ متنی و دامنهٔ مبتنی بر مسیر. دامنهٔ متنی بر ترتیب ظاهرشدن چیزها در فایل‌های منبع، حتی در چند فایل، استوار است و دامنه‌بندی پیش‌فرض محسوب می‌شود. در ادامه بیشتر توضیح داده می‌شود. دامنهٔ مبتنی بر مسیر دقیقاً مانند دامنه‌بندی آیتم‌ها عمل می‌کند. دامنه‌بندی، صادرکردن و واردکردن ماکروها تا حد زیادی با ویژگی‌ها کنترل می‌شود.

    [macro.decl.scope.unqualified]

    وقتی ماکرویی با شناسهٔ بدون تعیین‌کننده فراخوانی شود، یعنی شناسه بخشی از مسیر چندقسمتی نباشد، ابتدا در دامنهٔ متنی جست‌وجو می‌شود. اگر نتیجه‌ای به دست نیاید، جست‌وجو در دامنهٔ مبتنی بر مسیر انجام می‌شود. اگر نام ماکرو با یک مسیر تعیین شده باشد، تنها در دامنهٔ مبتنی بر مسیر جست‌وجو خواهد شد.

    use lazy_static::lazy_static; // Path-based import.

macro_rules! lazy_static { // Textual definition.
    (lazy) => {};
}

lazy_static!{lazy} // Textual lookup finds our macro first.
self::lazy_static!{} // Path-based lookup ignores our macro, finds imported one.
    [macro.decl.scope.textual]

    دامنهٔ متنی

    [macro.decl.scope.textual.intro]

    دامنهٔ متنی عمدتاً بر ترتیب ظاهرشدن چیزها در فایل‌های منبع استوار است و شبیه دامنهٔ متغیرهای محلی اعلان‌شده با let عمل می‌کند، با این تفاوت که در سطح ماژول نیز کاربرد دارد. وقتی macro_rules! برای تعریف ماکرو به کار رود، ماکرو از پسِ تعریف وارد دامنه می‌شود—با این حال چون نام‌ها از محل فراخوانی جست‌وجو می‌شوند، می‌توان آن را بازگشتی به کار برد—و تا پایان دامنهٔ دربرگیرنده‌اش، معمولاً یک ماژول، در دامنه می‌ماند. این دامنه می‌تواند وارد ماژول‌های فرزند شود و حتی چند فایل را در بر بگیرد:

    //// src/lib.rs
mod has_macro {
    // m!{} // Error: m is not in scope.

    macro_rules! m {
        () => {};
    }
    m!{} // OK: appears after declaration of m.

    mod uses_macro;
}

// m!{} // Error: m is not in scope.

//// src/has_macro/uses_macro.rs

m!{} // OK: appears after declaration of m in src/lib.rs
    [macro.decl.scope.textual.shadow]

    تعریف چندبارهٔ یک ماکرو خطا نیست؛ تازه‌ترین اعلان، اعلان پیشین را زیر سایه می‌برد، مگر آنکه خودش از دامنه خارج شده باشد.

    macro_rules! m {
    (1) => {};
}

m!(1);

mod inner {
    m!(1);

    macro_rules! m {
        (2) => {};
    }
    // m!(1); // Error: no rule matches '1'
    m!(2);

    macro_rules! m {
        (3) => {};
    }
    m!(3);
}

m!(1);
    [macro.decl.scope.textual.function-local]

    ماکروها را می‌توان به‌صورت محلی درون تابع‌ها نیز اعلان و استفاده کرد و رفتارشان مشابه است:

    fn foo() {
    // m!(); // Error: m is not in scope.
    macro_rules! m {
        () => {};
    }
    m!();
}

// m!(); // Error: m is not in scope.
    [macro.decl.scope.textual.shadow-path-based]

    مقیدسازی نام ماکروها در دامنهٔ متنی، مقیدسازی همان نام‌ها در دامنهٔ مبتنی بر مسیر را زیر سایه می‌برد.

    macro_rules! m2 {
    () => {
        println!("m2");
    };
}

// Resolves to path-based candidate from use declaration below.
m!(); // prints "m2\n"

// Introduce second candidate for `m` with textual scope.
//
// This shadows path-based candidate from below for the rest of this
// example.
macro_rules! m {
    () => {
        println!("m");
    };
}

// Introduce `m2` macro as path-based candidate.
//
// This item is in scope for this entire example, not just below the
// use declaration.
use m2 as m;

// Resolves to the textual macro candidate from above the use
// declaration.
m!(); // prints "m\n"

    Note

    برای ناحیه‌هایی که سایه‌اندازی در آن‌ها مجاز نیست، ابهام‌های تفکیک نام را ببینید.

    [macro.decl.scope.path-based]

    دامنهٔ مبتنی بر مسیر

    [macro.decl.scope.path-based.intro]

    به‌طور پیش‌فرض، ماکرو دامنهٔ مبتنی بر مسیر ندارد. ماکروها از دو راه می‌توانند چنین دامنه‌ای به دست آورند:

    • بازصادرکردن اعلان use
    • macro_export
    [macro.decl.scope.path.reexport]

    ماکروها را می‌توان بازصادر کرد تا از ماژولی غیر از ریشهٔ جعبه، دامنهٔ مبتنی بر مسیر داشته باشند.

    mac::m!(); // OK: Path-based lookup finds `m` in the mac module.

mod mac {
    // Introduce macro `m` with textual scope.
    macro_rules! m {
        () => {};
    }

    // Reexport with path-based scope from within `m`'s textual scope.
    pub(crate) use m;
}
    [macro.decl.scope.path-based.visibility]

    ماکروها به‌طور ضمنی دید pub(crate) دارند. #[macro_export] این دید ضمنی را به pub تغییر می‌دهد.

    // Implicit visibility is `pub(crate)`.
macro_rules! private_m {
    () => {};
}

// Implicit visibility is `pub`.
#[macro_export]
macro_rules! pub_m {
    () => {};
}

pub(crate) use private_m as private_macro; // OK.
pub use pub_m as pub_macro; // OK.
    // Implicit visibility is `pub(crate)`.
macro_rules! private_m {
    () => {};
}

// Implicit visibility is `pub`.
#[macro_export]
macro_rules! pub_m {
    () => {};
}

pub(crate) use private_m as private_macro; // OK.
pub use pub_m as pub_macro; // OK.

pub use private_m; // ERROR: `private_m` is only public within
                   // the crate and cannot be re-exported outside.
    [macro.decl.scope.macro_use]

    ویژگی macro_use

    [macro.decl.scope.macro_use.intro]

    ویژگی macro_use دو کاربرد دارد: می‌توان آن را روی ماژول‌ها به کار برد تا دامنهٔ ماکروهای تعریف‌شده درون آن‌ها گسترش یابد، و می‌توان آن را روی extern crate به کار برد تا ماکروهای جعبه‌ای دیگر به پیش‌درآمد macro_use وارد شوند.

    مثال

    #[macro_use]
mod inner {
    macro_rules! m {
        () => {};
    }
}
m!();
    #[macro_use]
extern crate log;
    [macro.decl.scope.macro_use.syntax]

    وقتی ویژگی macro_use روی ماژول‌ها به کار می‌رود، از نحو MetaWord استفاده می‌کند.

    وقتی روی extern crate به کار می‌رود، از نحوهای MetaWord و MetaListIdents استفاده می‌کند. برای اطلاعات بیشتر دربارهٔ شیوهٔ استفاده از این نحوها، macro.decl.scope.macro_use.prelude را ببینید.

    [macro.decl.scope.macro_use.allowed-positions]

    ویژگی macro_use را می‌توان روی ماژول‌ها یا extern crate اعمال کرد.

    Note

    نکته rustc استفاده در موقعیت‌های دیگر را نادیده می‌گیرد، اما دربارهٔ آن هشدار lint می‌دهد. این وضعیت ممکن است در آینده به خطا تبدیل شود.

    [macro.decl.scope.macro_use.extern-crate-self]

    ویژگی macro_use را نمی‌توان روی extern crate self به کار برد.

    [macro.decl.scope.macro_use.duplicates]

    ویژگی macro_use را می‌توان هر تعداد بار روی یک ساختار به کار برد.

    می‌توان چند نمونهٔ macro_use با نحو MetaListIdents مشخص کرد. اجتماع همهٔ ماکروهای مشخص‌شده وارد خواهد شد.

    Note

    نکته روی ماژول‌ها، rustc دربارهٔ هر ویژگی macro_use با MetaWord پس از نخستین مورد هشدار lint می‌دهد.

    روی extern crate، rustc نسبت به هر ویژگی macro_use که اثری ندارد، چون هیچ ماکرویی را وارد نمی‌کند که پیش‌تر توسط ویژگی macro_use دیگری وارد نشده باشد، هشدار lint می‌دهد. اگر دو یا چند ویژگی macro_use از نوع MetaListIdents یک ماکروی یکسان را وارد کنند، به اولی هشدار داده می‌شود. اگر هر ویژگی macro_use از نوع MetaWord وجود داشته باشد، به همهٔ ویژگی‌های macro_use از نوع MetaListIdents هشدار داده می‌شود. اگر دو یا چند ویژگی macro_use از نوع MetaWord وجود داشته باشد، به آن‌هایی که پس از اولی می‌آیند هشدار داده می‌شود.

    [macro.decl.scope.macro_use.mod-decl]

    وقتی macro_use روی ماژولی به کار رود، دامنهٔ ماکروی ماژول از دامنهٔ واژگانی خود ماژول فراتر می‌رود.

    مثال

    #[macro_use]
mod inner {
    macro_rules! m {
        () => {};
    }
}
m!(); // OK
    [macro.decl.scope.macro_use.prelude]

    مشخص‌کردن macro_use روی اعلان extern crate در ریشهٔ جعبه، ماکروهای صادرشده از آن جعبه را وارد می‌کند.

    ماکروهایی که از این راه وارد می‌شوند، به‌جای دامنهٔ متنی به پیش‌درآمد macro_use وارد می‌شوند؛ بنابراین هر نام دیگری می‌تواند آن‌ها را زیر سایه ببرد. ماکروهای واردشده با macro_use را می‌توان پیش از گزارهٔ import به کار برد.

    Note

    نکته در حال حاضر rustc هنگام تعارض، آخرین ماکروی واردشده را ترجیح می‌دهد. به این رفتار تکیه نکنید. این رفتار نامعمول است، چون importها در Rust معمولاً به ترتیب وابسته نیستند. رفتار macro_use ممکن است در آینده تغییر کند.

    برای جزئیات، مسئلهٔ شمارهٔ ۱۴۸۰۲۵ Rust را ببینید.

    با نحو MetaWord، همهٔ ماکروهای صادرشده وارد می‌شوند. با نحو MetaListIdents، تنها ماکروهای مشخص‌شده وارد خواهند شد.

    مثال

    #[macro_use(lazy_static)] // Or `#[macro_use]` to import all macros.
extern crate lazy_static;

lazy_static!{}
// self::lazy_static!{} // ERROR: lazy_static is not defined in `self`.
    [macro.decl.scope.macro_use.export]

    ماکروهایی که قرار است با macro_use وارد شوند، باید با macro_export صادر شده باشند.

    [macro.decl.scope.macro_export]

    ویژگی macro_export

    [macro.decl.scope.macro_export.intro]

    ویژگی macro_export ماکرو را از جعبه صادر می‌کند و آن را در ریشهٔ جعبه برای تفکیک مبتنی بر مسیر در دسترس قرار می‌دهد.

    مثال

    self::m!();
//  ^^^^ OK: Path-based lookup finds `m` in the current module.
m!(); // As above.

mod inner {
    super::m!();
    crate::m!();
}

mod mac {
    #[macro_export]
    macro_rules! m {
        () => {};
    }
}
    [macro.decl.scope.macro_export.syntax]

    ویژگی macro_export از نحوهای MetaWord و MetaListIdents استفاده می‌کند. با نحو MetaListIdents، تنها یک مقدار local_inner_macros می‌پذیرد.

    [macro.decl.scope.macro_export.allowed-positions]

    ویژگی macro_export را می‌توان روی تعریف‌های macro_rules اعمال کرد.

    Note

    نکته rustc استفاده در موقعیت‌های دیگر را نادیده می‌گیرد، اما دربارهٔ آن هشدار lint می‌دهد. این وضعیت ممکن است در آینده به خطا تبدیل شود.

    [macro.decl.scope.macro_export.duplicates]

    تنها نخستین استفاده از macro_export روی یک ماکرو اثر دارد.

    Note

    نکته rustc دربارهٔ هر استفاده پس از نخستین مورد هشدار lint می‌دهد.

    [macro.decl.scope.macro_export.path-based]

    به‌طور پیش‌فرض، ماکروها تنها دامنهٔ متنی دارند و با مسیر قابل تفکیک نیستند. با استفاده از ویژگی macro_export، ماکرو در ریشهٔ جعبه در دسترس قرار می‌گیرد و می‌توان با مسیرش به آن ارجاع داد.

    مثال بدون macro_export، ماکروها تنها دامنهٔ متنی دارند و در نتیجه تفکیک مبتنی بر مسیر شکست می‌خورد.

    macro_rules! m {
    () => {};
}
self::m!(); // ERROR
crate::m!(); // ERROR
fn main() {}

    با macro_export، تفکیک مبتنی بر مسیر کار می‌کند.

    #[macro_export]
macro_rules! m {
    () => {};
}
self::m!(); // OK
crate::m!(); // OK
fn main() {}
    [macro.decl.scope.macro_export.export]

    ویژگی macro_export باعث می‌شود ماکرو از ریشهٔ جعبه صادر شود تا در جعبه‌های دیگر بتوان با مسیر به آن ارجاع داد.

    مثال فرض کنید در جعبهٔ log کد زیر وجود دارد:

    #[macro_export]
macro_rules! warn {
    ($message:expr) => { eprintln!("WARN: {}", $message) };
}

    از جعبه‌ای دیگر می‌توان با مسیر به ماکرو ارجاع داد:

    fn main() {
    log::warn!("example warning");
}
    [macro.decl.scope.macro_export.macro_use]

    macro_export اجازه می‌دهد با استفاده از macro_use روی extern crate، ماکرو به پیش‌درآمد macro_use وارد شود.

    مثال فرض کنید در جعبهٔ log کد زیر وجود دارد:

    #[macro_export]
macro_rules! warn {
    ($message:expr) => { eprintln!("WARN: {}", $message) };
}

    استفاده از macro_use در جعبهٔ وابسته اجازه می‌دهد ماکرو از پیش‌درآمد استفاده شود:

    #[macro_use]
extern crate log;

pub mod util {
    pub fn do_thing() {
        // Resolved via macro prelude.
        warn!("example warning");
    }
}
    [macro.decl.scope.macro_export.local_inner_macros]

    افزودن local_inner_macros به ویژگی macro_export باعث می‌شود همهٔ فراخوانی‌های تک‌بخشی ماکرو در تعریف آن، پیشوند ضمنی $crate:: بگیرند.

    Note

    نکته این قابلیت در درجهٔ نخست ابزاری برای مهاجرت کدهای نوشته‌شده پیش از افزوده‌شدن $crate به زبان است تا با importهای مبتنی بر مسیر ماکروها در Rust 2018 کار کنند. استفاده از آن در کد جدید توصیه نمی‌شود.

    مثال

    #[macro_export(local_inner_macros)]
macro_rules! helped {
    () => { helper!() } // Automatically converted to $crate::helper!().
}

#[macro_export]
macro_rules! helper {
    () => { () }
}
    [macro.decl.hygiene]

    بهداشت نام‌ها

    [macro.decl.hygiene.intro]

    ماکروهای مبتنی بر مثال بهداشت نامِ ترکیبی در محل دارند. یعنی برچسب‌های حلقه، برچسب‌های بلوک و متغیرهای محلی در محل تعریف ماکرو جست‌وجو می‌شوند، در حالی که نمادهای دیگر در محل فراخوانی ماکرو جست‌وجو می‌شوند. برای نمونه:

    let x = 1;
fn func() {
    unreachable!("this is never called")
}

macro_rules! check {
    () => {
        assert_eq!(x, 1); // Uses `x` from the definition site.
        func();           // Uses `func` from the invocation site.
    };
}

{
    let x = 2;
    fn func() { /* does not panic */ }
    check!();
}

    برچسب‌ها و متغیرهای محلی تعریف‌شده در گسترش ماکرو میان فراخوانی‌ها مشترک نیستند، پس کد زیر کامپایل نمی‌شود:

    macro_rules! m {
    (define) => {
        let x = 1;
    };
    (refer) => {
        dbg!(x);
    };
}

m!(define);
m!(refer);
    [macro.decl.hygiene.crate]

    فرامتغیر $crate یک حالت ویژه است. این فرامتغیر به جعبه‌ای اشاره می‌کند که ماکرو را تعریف کرده و می‌تواند در ابتدای مسیر برای یافتن آیتم‌ها یا ماکروهایی به کار رود که در محل فراخوانی در دامنه نیستند.

    //// Definitions in the `helper_macro` crate.
#[macro_export]
macro_rules! helped {
    // () => { helper!() } // This might lead to an error due to 'helper' not being in scope.
    () => { $crate::helper!() }
}

#[macro_export]
macro_rules! helper {
    () => { () }
}

//// Usage in another crate.
// Note that `helper_macro::helper` is not imported!
use helper_macro::helped;

fn unit() {
    helped!();
}

    توجه کنید چون $crate به جعبهٔ جاری اشاره می‌کند، هنگام ارجاع به آیتم‌های غیرماکرو باید همراه با مسیر کاملاً تعیین‌شدهٔ ماژول به کار رود:

    pub mod inner {
    #[macro_export]
    macro_rules! call_foo {
        () => { $crate::inner::foo() };
    }

    pub fn foo() {}
}
    [macro.decl.hygiene.vis]

    افزون بر این، هرچند $crate هنگام گسترش اجازه می‌دهد ماکرو به آیتم‌های درون جعبهٔ خودش ارجاع دهد، استفاده از آن اثری بر دید ندارد. آیتم یا ماکروی مورد ارجاع همچنان باید از محل فراخوانی قابل مشاهده باشد. در نمونهٔ زیر، هر تلاشی برای فراخوانی call_foo!() از بیرون جعبه شکست می‌خورد، زیرا foo() عمومی نیست.

    #[macro_export]
macro_rules! call_foo {
    () => { $crate::foo() };
}

fn foo() {}

    Note

    نکته پیش از Rust 1.30، $crate و local_inner_macros پشتیبانی نمی‌شدند. این دو هم‌زمان با importهای مبتنی بر مسیر ماکروها افزوده شدند تا کاربران جعبه‌ای که ماکرو صادر می‌کند مجبور نباشند ماکروهای کمکی را دستی وارد کنند. جعبه‌های نوشته‌شده برای نسخه‌های قدیمی‌تر Rust که از ماکروهای کمکی استفاده می‌کنند، برای کارکرد مناسب با importهای مبتنی بر مسیر باید به استفاده از $crate یا local_inner_macros تغییر یابند.

    [macro.decl.follow-set]

    محدودیت‌های ابهام در مجموعهٔ پیرو

    [macro.decl.follow-set.intro]

    تجزیه‌گر مورد استفادهٔ سامانهٔ ماکرو توانمند است، اما برای جلوگیری از ابهام در نسخه‌های کنونی یا آیندهٔ زبان محدودیت‌هایی دارد.

    [macro.decl.follow-set.token-restriction]

    به‌طور خاص، افزون بر قاعدهٔ مربوط به گسترش‌های مبهم، پس از یک غیرپایانه که با فرامتغیر تطبیق یافته است باید توکنی بیاید که استفاده از آن پس از آن گونه تطبیق، ایمن تشخیص داده شده باشد.

    برای نمونه، یک تطبیق‌دهندهٔ ماکرو مانند $i:expr [ , ] از نظر تئوری می‌تواند امروز در Rust پذیرفته شود، زیرا [,] نمی‌تواند بخشی از یک عبارت معتبر باشد و بنابراین تجزیه همیشه بدون ابهام خواهد بود. با این حال، چون [ می‌تواند عبارت‌های پسوندی (trailing) را آغاز کند، [ نویسه‌ای نیست که بتوان با اطمینان آن را به‌عنوان نویسه‌ای که پس از یک عبارت می‌آید کنار گذاشت. اگر [,] در نسخه‌ای بعدی از Rust پذیرفته شود، این تطبیق‌دهنده مبهم می‌شود یا اشتباه تجزیه می‌شود و کدهای در حال کار را می‌شکند. در مقابل، تطبیق‌دهنده‌هایی مانند $i:expr, یا $i:expr; معتبر خواهند بود، زیرا , و ; جداکننده‌های معتبر عبارت‌اند. قواعد دقیق از این قرارند:

    [macro.decl.follow-set.token-expr-stmt]
    • پس از expr و stmt تنها یکی از =>، , یا ; می‌تواند بیاید.
    [macro.decl.follow-set.token-pat_param]
    • پس از pat_param تنها یکی از =>، ,، =، |، if یا in می‌تواند بیاید.
    [macro.decl.follow-set.token-pat]
    • پس از pat تنها یکی از =>، ,، =، if یا in می‌تواند بیاید.
    [macro.decl.follow-set.token-path-ty]
    • پس از path و ty تنها یکی از =>، ,، =، |، ;، :، >، >>، [، {، as، where یا یک متغیر ماکرو با مشخص‌کنندهٔ قطعهٔ block می‌تواند بیاید.
    [macro.decl.follow-set.token-vis]
    • پس از vis تنها یکی از این موارد می‌تواند بیاید: ,، شناسه‌ای غیر از priv غیرخام، هر توکنی که بتواند نوعی را آغاز کند، یا فرامتغیری با مشخص‌کنندهٔ قطعهٔ ident، ty یا path.
    [macro.decl.follow-set.token-other]
    • دیگر مشخص‌کننده‌های قطعه محدودیتی ندارند.
    [macro.decl.follow-set.edition2021]

    تفاوت‌های ویرایش 2021 پیش از ویرایش ۲۰۲۱، پس از pat می‌توانست | نیز بیاید.

    [macro.decl.follow-set.repetition]

    وقتی تکرارها دخیل باشند، قواعد با درنظرگرفتن جداکننده‌ها بر هر تعداد گسترش ممکن اعمال می‌شوند. یعنی:

    • اگر تکرار جداکننده دارد، آن جداکننده باید بتواند پس از محتوای تکرار بیاید.
    • اگر تکرار بتواند چند بار تکرار شود (* یا +)، محتوا باید بتواند پس از خودش بیاید.
    • محتوای تکرار باید بتواند پس از هرچه پیش از آن است بیاید، و هرچه پس از تکرار است باید بتواند پس از محتوای آن بیاید.
    • اگر تکرار بتواند صفر بار تطبیق یابد (* یا ?)، هرچه پس از آن است باید بتواند پس از هرچه پیش از آن است بیاید.

    برای جزئیات بیشتر، مشخصات رسمی را ببینید.
