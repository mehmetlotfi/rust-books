    [attributes.debugger]

    ویژگی‌های اشکال‌زدا

    [attributes.debugger.intro]

    ویژگی‌های زیر تجربهٔ اشکال‌زدایی با اشکال‌زداهای شخص ثالث مانند GDB یا WinDbg را بهبود می‌دهند.

    [attributes.debugger.debugger_visualizer]

    ویژگی debugger_visualizer

    [attributes.debugger.debugger_visualizer.intro]

    از ویژگی debugger_visualizer می‌توان برای جاسازی فایل نمایشگر اشکال‌زدا در اطلاعات اشکال‌زدایی استفاده کرد. این کار نمایش مقادیر در اشکال‌زدا را بهتر می‌کند.

    مثال

    #![debugger_visualizer(natvis_file = "Example.natvis")]
#![debugger_visualizer(gdb_script_file = "example.py")]
    [attributes.debugger.debugger_visualizer.syntax]

    ویژگی debugger_visualizer برای مشخص‌کردن ورودی‌ها از نحو MetaListNameValueStr استفاده می‌کند. یکی از کلیدهای زیر باید مشخص شود:

    • natvis_file
    • gdb_script_file
    [attributes.debugger.debugger_visualizer.allowed-positions]

    ویژگی debugger_visualizer را تنها می‌توان روی یک ماژول یا ریشهٔ crate اعمال کرد.

    [attributes.debugger.debugger_visualizer.duplicates]

    ویژگی debugger_visualizer را می‌توان هر تعداد بار روی یک فرم به‌کار برد. همهٔ فایل‌های نمایشگر مشخص‌شده بارگذاری می‌شوند.

    [attributes.debugger.debugger_visualizer.natvis]

    استفاده از debugger_visualizer با Natvis

    [attributes.debugger.debugger_visualizer.natvis.intro]

    Natvis چارچوبی مبتنی بر XML برای اشکال‌زداهای Microsoft (مانند Visual Studio و WinDbg) است که با استفاده از قواعد اعلانی (declarative)، نحوهٔ نمایش نوع‌ها را سفارشی می‌کند. برای اطلاعات دقیق دربارهٔ قالب Natvis، به مستندات Natvis از Microsoft مراجعه کنید.

    [attributes.debugger.debugger_visualizer.natvis.msvc]

    این ویژگی تنها جاسازی فایل‌های Natvis روی هدف‌های -windows-msvc را پشتیبانی می‌کند.

    [attributes.debugger.debugger_visualizer.natvis.path]

    مسیر فایل Natvis با کلید natvis_file مشخص می‌شود و نسبت به فایل منبع است.

    مثال

    #![debugger_visualizer(natvis_file = "Rectangle.natvis")]

struct FancyRect {
    x: f32,
    y: f32,
    dx: f32,
    dy: f32,
}

fn main() {
    let fancy_rect = FancyRect { x: 10.0, y: 10.0, dx: 5.0, dy: 5.0 };
    println!("set breakpoint here");
}

    محتوای Rectangle.natvis:

    <?xml version="1.0" encoding="utf-8"?>
<AutoVisualizer xmlns="http://schemas.microsoft.com/vstudio/debugger/natvis/2010">
    <Type Name="foo::FancyRect">
      <DisplayString>({x},{y}) + ({dx}, {dy})</DisplayString>
      <Expand>
        <Synthetic Name="LowerLeft">
          <DisplayString>({x}, {y})</DisplayString>
        </Synthetic>
        <Synthetic Name="UpperLeft">
          <DisplayString>({x}, {y + dy})</DisplayString>
        </Synthetic>
        <Synthetic Name="UpperRight">
          <DisplayString>({x + dx}, {y + dy})</DisplayString>
        </Synthetic>
        <Synthetic Name="LowerRight">
          <DisplayString>({x + dx}, {y})</DisplayString>
        </Synthetic>
      </Expand>
    </Type>
</AutoVisualizer>

    متغیر fancy_rect در WinDbg به‌شکل زیر نمایش داده می‌شود:

    > Variables:
  > fancy_rect: (10.0, 10.0) + (5.0, 5.0)
    > LowerLeft: (10.0, 10.0)
    > UpperLeft: (10.0, 15.0)
    > UpperRight: (15.0, 15.0)
    > LowerRight: (15.0, 10.0)
    [attributes.debugger.debugger_visualizer.gdb]

    استفاده از debugger_visualizer با GDB

    [attributes.debugger.debugger_visualizer.gdb.pretty]

    GDB از استفاده از یک اسکریپت ساخت‌یافتهٔ Python به نام pretty printer پشتیبانی می‌کند که توضیح می‌دهد یک نوع چگونه باید در نمای اشکال‌زدا نمایش داده شود. برای اطلاعات دقیق دربارهٔ pretty printerها به مستندات pretty printing در GDB مراجعه کنید.

    Note

    نکته pretty printerهای جاسازی‌شده هنگام اشکال‌زدایی فایل دودویی در GDB خودکار بارگذاری نمی‌شوند.

    دو راه برای فعال‌کردن بارگذاری خودکار آن‌ها وجود دارد:

    1. GDB را با آرگومان‌های اضافی اجرا کنید تا دایرکتوری یا فایل دودویی صریحاً به مسیر امن بارگذاری خودکار افزوده شود: gdb -iex "add-auto-load-safe-path safe-path path/to/binary" path/to/binary. برای اطلاعات بیشتر مستندات بارگذاری خودکار GDB را ببینید.
    2. فایلی به‌نام gdbinit در $HOME/.config/gdb بسازید؛ شاید لازم باشد دایرکتوری را نیز ایجاد کنید. خط زیر را به فایل بیفزایید: add-auto-load-safe-path path/to/binary.
    [attributes.debugger.debugger_visualizer.gdb.path]

    این اسکریپت‌ها با کلید gdb_script_file جاسازی می‌شوند که مسیری نسبی نسبت به فایل منبع است.

    مثال

    #![debugger_visualizer(gdb_script_file = "printer.py")]

struct Person {
    name: String,
    age: i32,
}

fn main() {
    let bob = Person { name: String::from("Bob"), age: 10 };
    println!("set breakpoint here");
}

    محتوای printer.py:

    import gdb

class PersonPrinter:
    "Print a Person"

    def __init__(self, val):
        self.val = val
        self.name = val["name"]
        self.age = int(val["age"])

    def to_string(self):
        return "{} is {} years old.".format(self.name, self.age)

def lookup(val):
    lookup_tag = val.type.tag
    if lookup_tag is None:
        return None
    if "foo::Person" == lookup_tag:
        return PersonPrinter(val)

    return None

gdb.current_objfile().pretty_printers.append(lookup)

    وقتی فایل اجرایی اشکال‌زدایی crate به GDB داده شود1، دستور print bob این خروجی را نشان می‌دهد:

    "Bob" is 10 years old.
    [attributes.debugger.collapse_debuginfo]

    ویژگی collapse_debuginfo

    [attributes.debugger.collapse_debuginfo.intro]

    ویژگی collapse_debuginfo کنترل می‌کند هنگام تولید اطلاعات اشکال‌زدایی برای کدی که ماکرو را فراخوانی می‌کند، آیا محل‌های کد در تعریف ماکرو به یک محل مرتبط با نقطهٔ فراخوانی ماکرو فروکاسته شوند یا نه.

    مثال

    #[collapse_debuginfo(yes)]
macro_rules! example {
    () => {
        println!("hello!");
    };
}

    در اشکال‌زدا، فراخوانی ماکروی example ممکن است مانند فراخوانی تابع دیده شود؛ یعنی هنگام گام‌برداشتن تا محل فراخوانی، به‌جای کد گسترش‌یافته خود فراخوانی ماکرو نمایش داده شود.

    [attributes.debugger.collapse_debuginfo.syntax]

    نحو ویژگی collapse_debuginfo چنین است:

    Syntax
    CollapseDebuginfoAttribute → collapse_debuginfo ( CollapseDebuginfoOption )

    CollapseDebuginfoOption →
          yes
        | no
        | external

    [attributes.debugger.collapse_debuginfo.allowed-positions]

    ویژگی collapse_debuginfo را تنها می‌توان روی یک تعریف macro_rules اعمال کرد.

    [attributes.debugger.collapse_debuginfo.duplicates]

    ویژگی collapse_debuginfo را فقط یک بار می‌توان روی یک ماکرو به‌کار برد.

    [attributes.debugger.collapse_debuginfo.options]

    ویژگی collapse_debuginfo گزینه‌های زیر را می‌پذیرد:

    • #[collapse_debuginfo(yes)] — محل‌های کد در اطلاعات اشکال‌زدایی فروکاسته می‌شوند.
    • #[collapse_debuginfo(no)] — محل‌های کد در اطلاعات اشکال‌زدایی فروکاسته نمی‌شوند.
    • #[collapse_debuginfo(external)] — محل‌های کد فقط زمانی فروکاسته می‌شوند که ماکرو از crate دیگری آمده باشد.
    [attributes.debugger.collapse_debuginfo.default]

    برای ماکروهای بدون این ویژگی، رفتار پیش‌فرض external است؛ مگر ماکروهای داخلی که پیش‌فرضشان yes است.

    Note

    نکته rustc گزینهٔ خط فرمان -C collapse-macro-debuginfo را برای لغو رفتار پیش‌فرض و مقادیر همهٔ ویژگی‌های #[collapse_debuginfo] دارد.

    1. این توضیح فرض می‌کند از اسکریپت rust-gdb استفاده می‌کنید که pretty-printerها را برای نوع‌های کتابخانهٔ استاندارد مانند String پیکربندی می‌کند. ↩
