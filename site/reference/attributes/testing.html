    [attributes.testing]

    ویژگی‌های آزمون

    [attributes.testing.intro]

    ویژگی‌های زیر برای مشخص‌کردن تابع‌های اجرای آزمون به‌کار می‌روند. کامپایل crate در حالت «test»، تابع‌های آزمون را همراه یک چارچوب اجرای آزمون می‌سازد. فعال‌کردن حالت آزمون، گزینهٔ کامپایل شرطی test را نیز فعال می‌کند.

    [attributes.testing.test]

    ویژگی test

    [attributes.testing.test.intro]

    ویژگی test تابعی را برای اجرا به‌عنوان آزمون علامت‌گذاری می‌کند.

    مثال

    pub fn add(left: u64, right: u64) -> u64 { left + right }
#[test]
fn it_works() {
    let result = add(2, 2);
    assert_eq!(result, 4);
}
    [attributes.testing.test.syntax]

    ویژگی test از نحو MetaWord استفاده می‌کند.

    [attributes.testing.test.allowed-positions]

    ویژگی test را تنها می‌توان روی تابع‌های آزاد تک‌ریختی اعمال کرد که آرگومان نمی‌گیرند و نوع بازگشتشان صفت Termination را پیاده‌سازی می‌کند.

    Note

    نکته بعضی نوع‌های پیاده‌سازی‌کنندهٔ Termination عبارت‌اند از:

    • ()
    • Result<T, E> where T: Termination, E: Debug
    [attributes.testing.test.duplicates]

    تنها نخستین استفاده از test روی یک تابع اثر دارد.

    Note

    نکته rustc دربارهٔ استفاده‌های پس از مورد نخست lint صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [attributes.testing.test.stdlib]

    ویژگی test از پیش‌درآمد کتابخانهٔ استاندارد به‌شکل std::prelude::v1::test صادر می‌شود.

    [attributes.testing.test.enabled]

    این تابع‌ها تنها در حالت آزمون کامپایل می‌شوند.

    Note

    نکته حالت آزمون با آرگومان --test برای rustc یا اجرای cargo test فعال می‌شود.

    [attributes.testing.test.success]

    چارچوب آزمون متد report مقدار بازگشتی را فراخوانی می‌کند و بر پایهٔ اینکه ExitCode حاصل نشان‌دهندهٔ پایان موفق باشد یا نه، آزمون را موفق یا ناموفق دسته‌بندی می‌کند. به‌طور مشخص:

    • آزمون‌های برگردانندهٔ () تا زمانی که پایان یابند و panic نکنند موفق‌اند.
    • آزمون‌های برگردانندهٔ Result<(), E> در صورت بازگرداندن Ok(()) موفق‌اند.
    • آزمون‌های برگردانندهٔ ExitCode::SUCCESS موفق و آزمون‌های برگردانندهٔ ExitCode::FAILURE ناموفق‌اند.
    • آزمون‌هایی که پایان نمی‌یابند نه موفق‌اند و نه ناموفق.

    مثال

    use std::io;
fn setup_the_thing() -> io::Result<i32> { Ok(1) }
fn do_the_thing(s: &i32) -> io::Result<()> { Ok(()) }
#[test]
fn test_the_thing() -> io::Result<()> {
    let state = setup_the_thing()?; // expected to succeed
    do_the_thing(&state)?;          // expected to succeed
    Ok(())
}
    [attributes.testing.ignore]

    ویژگی ignore

    [attributes.testing.ignore.intro]

    ویژگی ignore را می‌توان همراه ویژگی test به‌کار برد تا چارچوب آزمون آن تابع را به‌عنوان آزمون اجرا نکند.

    مثال

    #[test]
#[ignore]
fn check_thing() {
    // …
}

    Note

    نکته چارچوب آزمون rustc از پرچم --include-ignored برای اجرای اجباری آزمون‌های نادیده‌گرفته‌شده پشتیبانی می‌کند.

    [attributes.testing.ignore.syntax]

    ویژگی ignore از نحوهای MetaWord و MetaNameValueStr استفاده می‌کند.

    [attributes.testing.ignore.reason]

    شکل MetaNameValueStr ویژگی ignore راهی برای ذکر علت نادیده‌گرفتن آزمون فراهم می‌کند.

    مثال

    #[test]
#[ignore = "not yet implemented"]
fn mytest() {
    // …
}
    [attributes.testing.ignore.allowed-positions]

    ویژگی ignore را تنها می‌توان روی تابع‌های دارای ویژگی test اعمال کرد.

    Note

    نکته rustc استفاده در موقعیت‌های دیگر را نادیده می‌گیرد، اما درباره‌اش lint صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [attributes.testing.ignore.duplicates]

    تنها نخستین استفاده از ignore روی یک تابع اثر دارد.

    Note

    نکته rustc دربارهٔ استفاده‌های پس از مورد نخست lint صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [attributes.testing.ignore.behavior]

    آزمون‌های نادیده‌گرفته‌شده همچنان در حالت آزمون کامپایل می‌شوند، اما اجرا نمی‌شوند.

    [attributes.testing.should_panic]

    ویژگی should_panic

    [attributes.testing.should_panic.intro]

    ویژگی should_panic باعث می‌شود آزمون تنها زمانی موفق شود که تابع آزمون دارای این ویژگی panic کند.

    مثال

    #[test]
#[should_panic(expected = "values don't match")]
fn mytest() {
    assert_eq!(1, 2, "values don't match");
}
    [attributes.testing.should_panic.syntax]

    ویژگی should_panic شکل‌های زیر را دارد:

    • MetaWord

      مثال

      #[test]
#[should_panic]
fn mytest() { panic!("error: some message, and more"); }

    • MetaNameValueStr — برای موفقیت آزمون، رشتهٔ داده‌شده باید در پیام panic وجود داشته باشد.

      مثال

      #[test]
#[should_panic = "some message"]
fn mytest() { panic!("error: some message, and more"); }

    • MetaListNameValueStr — همانند نحو MetaNameValueStr، رشتهٔ داده‌شده باید در پیام panic وجود داشته باشد.

      مثال

      #[test]
#[should_panic(expected = "some message")]
fn mytest() { panic!("error: some message, and more"); }
    [attributes.testing.should_panic.allowed-positions]

    ویژگی should_panic را تنها می‌توان روی تابع‌های دارای ویژگی test اعمال کرد.

    Note

    نکته rustc استفاده در موقعیت‌های دیگر را نادیده می‌گیرد، اما درباره‌اش lint صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [attributes.testing.should_panic.duplicates]

    تنها نخستین استفاده از should_panic روی یک تابع اثر دارد.

    Note

    نکته rustc دربارهٔ استفاده‌های پس از مورد نخست هشدار سازگاری آینده صادر می‌کند. ممکن است در آینده به خطا تبدیل شود.

    [attributes.testing.should_panic.expected]

    هنگام استفاده از شکل MetaNameValueStr یا شکل MetaListNameValueStr با کلید expected، برای موفقیت آزمون رشتهٔ داده‌شده باید در جایی از پیام panic ظاهر شود.

    [attributes.testing.should_panic.return]

    نوع بازگشت تابع آزمون باید () باشد.
