    [attributes.codegen]

    ویژگی‌های تولید کد

    [attributes.codegen.intro]

    ویژگی‌های زیر برای کنترل تولید کد به کار می‌روند.

    [attributes.codegen.inline]

    ویژگی inline

    [attributes.codegen.inline.intro]

    ویژگی inline پیشنهاد می‌کند به‌جای تولید فراخوانی تابع، نسخه‌ای از کد تابع علامت‌خورده درون فراخوان قرار گیرد یا نه.

    مثال

    #[inline]
pub fn example1() {}

#[inline(always)]
pub fn example2() {}

#[inline(never)]
pub fn example3() {}

    Note

    نکته rustc هرگاه سودمند بداند تابع‌ها را خودکار درون‌خطی می‌کند. این ویژگی را با احتیاط به کار ببرید، زیرا انتخاب نامناسب می‌تواند برنامه را کند کند.

    [attributes.codegen.inline.syntax]

    نحو ویژگی inline چنین است:

    Syntax
    InlineAttribute →
          inline ( always )
        | inline ( never )
        | inline

    [attributes.codegen.inline.allowed-positions]

    ویژگی inline تنها روی تابع‌های دارای بدنه قابل اعمال است: بستارها، بلوک‌های async، تابع‌های آزاد، تابع‌های وابسته در پیاده‌سازی ذاتی یا پیاده‌سازی صفت، و تابع‌های وابستهٔ دارای تعریف پیش‌فرض در تعریف صفت.

    Note

    نکته rustc استفاده در موقعیت‌های دیگر را نادیده می‌گیرد، اما هشدار lint می‌دهد. این وضعیت ممکن است در آینده خطا شود.

    Note

    نکته هرچند ویژگی روی بستارها و بلوک‌های async قابل اعمال است، سودمندی آن محدود است، زیرا هنوز ویژگی روی عبارت‌ها پشتیبانی نمی‌شود.

    // We allow attributes on statements.
#[inline] || (); // OK
#[inline] async {}; // OK
    // We don't yet allow attributes on expressions.
let f = #[inline] || (); // ERROR
    [attributes.codegen.inline.duplicates]

    تنها نخستین استفاده از inline روی تابع اثر دارد.

    Note

    نکته rustc دربارهٔ هر استفاده پس از نخستین مورد هشدار lint می‌دهد. این وضعیت ممکن است در آینده خطا شود.

    [attributes.codegen.inline.modes]

    ویژگی inline حالت‌های زیر را پشتیبانی می‌کند:

    • #[inline] انجام گسترش درون‌خطی را پیشنهاد می‌کند.
    • #[inline(always)] پیشنهاد می‌کند گسترش درون‌خطی همیشه انجام شود.
    • #[inline(never)] پیشنهاد می‌کند گسترش درون‌خطی هرگز انجام نشود.

    Note

    نکته این ویژگی در هر شکل تنها یک راهنمایی است و کامپایلر می‌تواند آن را نادیده بگیرد.

    [attributes.codegen.inline.trait]

    هنگامی که inline روی تابعی در صفت اعمال شود، تنها بر کد تعریف پیش‌فرض اثر دارد.

    [attributes.codegen.inline.async]

    هنگامی که inline روی تابع async یا بستار async اعمال شود، تنها بر کد تابع poll تولیدشده اثر دارد.

    Note

    نکته برای جزئیات بیشتر، مسئلهٔ شمارهٔ ۱۲۹۳۴۷ Rust را ببینید.

    [attributes.codegen.inline.externally-exported]

    اگر تابع با no_mangle یا export_name به بیرون صادر شود، ویژگی inline نادیده گرفته می‌شود.

    [attributes.codegen.cold]

    ویژگی cold

    [attributes.codegen.cold.intro]

    ویژگی cold پیشنهاد می‌کند احتمال فراخوانی تابع علامت‌خورده کم است؛ این اطلاعات می‌تواند به کامپایلر در تولید کد بهتر کمک کند.

    مثال

    #[cold]
pub fn example() {}
    [attributes.codegen.cold.syntax]

    ویژگی cold از نحو MetaWord استفاده می‌کند.

    [attributes.codegen.cold.allowed-positions]

    ویژگی cold تنها روی تابع‌های دارای بدنه قابل اعمال است: بستارها، بلوک‌های async، تابع‌های آزاد، تابع‌های وابسته در پیاده‌سازی ذاتی یا پیاده‌سازی صفت، و تابع‌های وابستهٔ دارای تعریف پیش‌فرض در تعریف صفت.

    Note

    نکته rustc استفاده در موقعیت‌های دیگر را نادیده می‌گیرد، اما هشدار lint می‌دهد. این وضعیت ممکن است در آینده خطا شود.

    Note

    هرچند می‌توان این ویژگی را روی closure‌ها و بلوک‌های async اعمال کرد، فایدهٔ آن محدود است، زیرا هنوز از ویژگی‌ها روی عبارت‌ها پشتیبانی نمی‌کنیم.

    [attributes.codegen.cold.extern-custom]

    ویژگی cold را نمی‌توان روی تابع extern "custom" اعمال کرد.

    #[cold] // ERROR: Not allowed.
#[unsafe(naked)]
unsafe extern "custom" fn f() {
    core::arch::naked_asm!("ret")
}
    [attributes.codegen.cold.duplicates]

    تنها نخستین استفاده از cold روی تابع اثر دارد.

    Note

    نکته rustc دربارهٔ هر استفاده پس از نخستین مورد هشدار lint می‌دهد. این وضعیت ممکن است در آینده خطا شود.

    [attributes.codegen.cold.trait]

    هنگامی که cold روی تابعی در صفت اعمال شود، تنها بر کد تعریف پیش‌فرض اثر دارد.

    [attributes.codegen.naked]

    ویژگی naked

    [attributes.codegen.naked.intro]

    ویژگی naked از تولید پیش‌درآمد و پس‌درآمد تابع به‌وسیلهٔ کامپایلر جلوگیری می‌کند؛ چنین تابعی تابع برهنه نام دارد.

    مثال

    #[cfg(target_arch = "x86_64")] {
/// Adds 3 to the given number.
// SAFETY: The body respects the "sysv64" calling convention,
// upholds the signature, and does not fall through.
#[unsafe(naked)]
pub extern "sysv64" fn add_n(number: u64) -> u64 {
    core::arch::naked_asm!(
        "add rdi, {}",
        "mov rax, rdi",
        "ret",
        const 3,
    )
}
}

    Note

    نکته کد اسمبلی تابع برهنه اغلب از قرارداد فراخوانی هیچ ABI شناخته‌شده برای کامپایلر پیروی نمی‌کند. چنین تابعی باید به‌صورت تابع extern "custom" اعلان شود.

    [attributes.codegen.naked.syntax]

    ویژگی naked از نحو MetaWord استفاده می‌کند.

    [attributes.codegen.naked.allowed-positions]

    ویژگی naked تنها روی تابع‌های آزاد، تابع‌های وابسته در پیاده‌سازی ذاتی یا پیاده‌سازی صفت، و تابع‌های وابستهٔ دارای تعریف پیش‌فرض در تعریف صفت قابل اعمال است.

    [attributes.codegen.naked.duplicates]

    تنها نخستین استفاده از naked روی تابع اثر دارد.

    Note

    نکته rustc دربارهٔ هر استفاده پس از نخستین مورد هشدار lint می‌دهد.

    [attributes.codegen.naked.unsafe]

    ویژگی naked باید با unsafe علامت بخورد، زیرا بدنه باید قرارداد فراخوانی و امضای تابع را رعایت کند و یا برگردد یا واگرا شود؛ یعنی از انتهای کد اسمبلی عبور نکند.

    [attributes.codegen.naked.body]

    بدنهٔ تابع باید دقیقاً از یک فراخوانی ماکروی naked_asm! تشکیل شود.

    [attributes.codegen.naked.prologue-epilogue]

    کامپایلر برای تابع برهنه هیچ پیش‌درآمد یا پس‌درآمدی تولید نمی‌کند؛ کد اسمبلی در فراخوانی naked_asm! تمام بدنهٔ تابع است.

    [attributes.codegen.naked.call-stack]

    هنگام ورود، کد اسمبلی می‌تواند فرض کند پشتهٔ فراخوانی و وضعیت ثبات‌ها مطابق امضا و قرارداد فراخوانی تابع معتبرند.

    [attributes.codegen.naked.no-duplication]

    کامپایلر جز هنگام تک‌ریخت‌سازی تابع چندریخت نمی‌تواند کد اسمبلی را تکثیر کند.

    Note

    نکته این تضمین برای تابع‌های برهنه‌ای که نماد تعریف می‌کنند مهم است.

    [attributes.codegen.naked.unused-variables]

    lint نوع unused_variables در تابع‌های برهنه سرکوب می‌شود.

    [attributes.codegen.naked.inline]

    ویژگی inline را نمی‌توان روی تابع برهنه اعمال کرد.

    [attributes.codegen.naked.track_caller]

    ویژگی track_caller را نمی‌توان روی تابع برهنه اعمال کرد.

    [attributes.codegen.naked.testing]

    ویژگی‌های آزمون را نمی‌توان روی تابع برهنه اعمال کرد.

    [attributes.codegen.naked.target_feature]

    ویژگی target_feature را نمی‌توان روی تابع برهنه اعمال کرد.

    [attributes.codegen.naked.abi]

    یک تابع naked نمی‌تواند از ABI «Rust» استفاده کند.

    [attributes.codegen.no_builtins]

    ویژگی no_builtins

    [attributes.codegen.no_builtins.intro]

    ویژگی no_builtins بهینه‌سازی برخی الگوهای کد مربوط به فراخوانی تابع‌های کتابخانه‌ای فرض‌شده را غیرفعال می‌کند.

    مثال

    #![no_builtins]
    [attributes.codegen.no_builtins.syntax]

    ویژگی no_builtins از نحو MetaWord استفاده می‌کند.

    [attributes.codegen.no_builtins.allowed-positions]

    ویژگی no_builtins تنها روی ریشهٔ جعبه قابل اعمال است.

    [attributes.codegen.no_builtins.duplicates]

    تنها نخستین استفاده از ویژگی no_builtins اثر دارد.

    Note

    نکته rustc دربارهٔ هر استفاده پس از نخستین مورد هشدار lint می‌دهد.

    [attributes.codegen.target_feature]

    ویژگی target_feature

    [attributes.codegen.target_feature.intro]

    ویژگی target_feature را می‌توان روی تابعی اعمال کرد تا تولید کد آن برای قابلیت‌های معماری معینی از سکو فعال شود. این ویژگی از نحو MetaListNameValueStr با کلید یگانهٔ enable استفاده می‌کند که مقدارش رشته‌ای از نام قابلیت‌های جداشده با ویرگول است.

    #[cfg(target_feature = "avx2")]
#[target_feature(enable = "avx2")]
fn foo_avx2() {}
    [attributes.codegen.target_feature.arch]

    هر معماری مقصد مجموعه‌ای از قابلیت‌های قابل فعال‌سازی دارد. مشخص‌کردن قابلیت معماری‌ای که جعبه برای آن کامپایل نمی‌شود خطاست.

    [attributes.codegen.target_feature.closures]

    بستارهای تعریف‌شده در تابع علامت‌خورده با target_feature، ویژگی را از تابع دربرگیرنده به ارث می‌برند.

    [attributes.codegen.target_feature.target-ub]

    فراخوانی تابعی که با قابلیتی کامپایل شده که سکوی جاریِ اجرای کد پشتیبانی نمی‌کند رفتار تعریف‌نشده است، مگر آنکه سکو صراحتاً ایمن‌بودن آن را مستند کرده باشد.

    [attributes.codegen.target_feature.safety-restrictions]

    مگر آنکه قواعد سکوی زیر چیز دیگری بگویند، محدودیت‌های زیر برقرارند:

    • تابع‌های ایمن #[target_feature] (و closureهایی که این ویژگی را به ارث می‌برند) را تنها می‌توان در فراخواننده‌ای به‌صورت ایمن فراخوانی کرد که همهٔ target_feature‌هایی را که فراخوانده‌شده فعال می‌کند فعال کرده باشد. این محدودیت در بافت unsafe اعمال نمی‌شود.
    • تابع‌های ایمن #[target_feature] (و closureهایی که این ویژگی را به ارث می‌برند) تنها در بافت‌هایی می‌توانند به اشاره‌گر تابع ایمن تبدیل ضمنی (coerce) شوند که همهٔ target_feature‌هایی را که تابعِ تحت تبدیل فعال می‌کند فعال کنند. این محدودیت برای اشاره‌گرهای تابع unsafe اعمال نمی‌شود.

    قابلیت‌های ضمنی فعال‌شده نیز در این قاعده منظور می‌شوند. برای نمونه تابع sse2 می‌تواند تابع‌های علامت‌خورده با sse را فراخوانی کند.

    #[cfg(target_feature = "sse2")] {
#[target_feature(enable = "sse")]
fn foo_sse() {}

fn bar() {
    // Calling `foo_sse` here is unsafe, as we must ensure that SSE is
    // available first, even if `sse` is enabled by default on the target
    // platform or manually enabled as compiler flags.
    unsafe {
        foo_sse();
    }
}

#[target_feature(enable = "sse")]
fn bar_sse() {
    // Calling `foo_sse` here is safe.
    foo_sse();
    || foo_sse();
}

#[target_feature(enable = "sse2")]
fn bar_sse2() {
    // Calling `foo_sse` here is safe because `sse2` implies `sse`.
    foo_sse();
}
}
    [attributes.codegen.target_feature.fn-traits]

    تابع دارای #[target_feature] هرگز خانوادهٔ صفت‌های Fn را پیاده‌سازی نمی‌کند، هرچند بستارهای وارث قابلیت از تابع دربرگیرنده چنین می‌کنند.

    [attributes.codegen.target_feature.allowed-positions]

    ویژگی #[target_feature] در موقعیت‌های زیر مجاز نیست:

    • تابع main
    • یک تابع panic_handler
    • متدهای ایمن صفت
    • تابع‌های پیش‌فرض ایمن در صفت‌ها
    [attributes.codegen.target_feature.inline]

    تابع‌های علامت‌خورده با target_feature در بافتی که قابلیت‌های داده‌شده را پشتیبانی نمی‌کند درون‌خطی نمی‌شوند. ویژگی #[inline(always)] را نمی‌توان همراه target_feature به کار برد.

    [attributes.codegen.target_feature.availability]

    اطلاعات تکمیلی

    [attributes.codegen.target_feature.remark-cfg]

    برای فعال یا غیرفعال‌کردن انتخابی کامپایل کد بر پایهٔ تنظیمات زمان کامپایل، گزینهٔ کامپایل شرطی target_feature را ببینید. این گزینه از ویژگی target_feature تأثیر نمی‌گیرد و تنها بر پایهٔ قابلیت‌های فعال‌شده برای کل جعبه تعیین می‌شود.

    [attributes.codegen.target_feature.remark-rt]

    فعال‌بودن قابلیت را می‌توان در زمان اجرا با ماکروی ویژهٔ سکو از کتابخانهٔ استاندارد، مانند is_x86_feature_detected یا is_aarch64_feature_detected، بررسی کرد.

    Note

    نکته rustc برای هر مقصد و CPU مجموعه‌ای پیش‌فرض از قابلیت‌های فعال دارد. CPU را می‌توان با پرچم -C target-cpu انتخاب کرد. قابلیت‌های جداگانه را می‌توان برای کل جعبه با پرچم -C target-feature فعال یا غیرفعال کرد.

    [attributes.codegen.track_caller]

    ویژگی track_caller

    [attributes.codegen.track_caller.allowed-positions]

    ویژگی track_caller را می‌توان روی هر تابع دارای ABI نوع "Rust" به‌جز نقطهٔ ورود fn main اعمال کرد.

    [attributes.codegen.track_caller.traits]

    وقتی ویژگی روی تابع‌ها و متدهای اعلان صفت اعمال شود، بر همهٔ پیاده‌سازی‌ها اثر دارد. اگر صفت پیاده‌سازی پیش‌فرض علامت‌خورده‌ای فراهم کند، ویژگی بر پیاده‌سازی‌های بازنویس نیز اعمال می‌شود.

    [attributes.codegen.track_caller.extern]

    وقتی ویژگی روی تابعی در بلوک extern اعمال شود، باید روی همهٔ پیاده‌سازی‌های پیوندخورده نیز اعمال شود؛ در غیر این صورت رفتار تعریف‌نشده رخ می‌دهد. همچنین اگر روی تابعی اعمال شود که در دسترس بلوک extern قرار می‌گیرد، اعلان متناظر در بلوک extern نیز باید این ویژگی را داشته باشد.

    [attributes.codegen.track_caller.behavior]

    رفتار

    اعمال این ویژگی روی تابع f به کدِ درون f امکان می‌دهد نشانه‌ای از Location مربوط به «بالاترین» فراخوانیِ ردیابی‌شده‌ای به دست آورد که به فراخوانی f انجامیده است. در لحظهٔ مشاهده، پیاده‌سازی طوری رفتار می‌کند که گویی از قاب (frame) تابع f در پشته بالا می‌رود تا نزدیک‌ترین قاب تابعِ بدون ویژگی outer را بیابد، و Location فراخوانی ردیابی‌شده در outer را برمی‌گرداند.

    #[track_caller]
fn f() {
    println!("{}", std::panic::Location::caller());
}

    Note

    نکته core برای مشاهدهٔ مکان فراخوان، core::panic::Location::caller را فراهم می‌کند که ذاتی core::intrinsics::caller_location پیاده‌سازی‌شده در rustc را می‌پوشاند.

    Note

    نکته چون Location حاصل تنها راهنمایی است، پیاده‌سازی می‌تواند پیمایش پشته را زود متوقف کند. برای نکته‌های مهم محدودیت‌ها را ببینید.

    نمونه‌ها

    وقتی calls_f مستقیماً f را فراخوانی کند، کد درون f محل فراخوانی خود در calls_f را مشاهده می‌کند:

    #[track_caller]
fn f() {
    println!("{}", std::panic::Location::caller());
}
fn calls_f() {
    f(); // <-- f() prints this location
}

    وقتی تابع علامت‌خوردهٔ دیگری مانند g، تابع f را فراخوانی کند و خود g به‌دست calls_g فراخوانی شود، کد درون هر دو تابع f و g محل فراخوانی g در calls_g را مشاهده می‌کند:

    #[track_caller]
fn f() {
    println!("{}", std::panic::Location::caller());
}
#[track_caller]
fn g() {
    println!("{}", std::panic::Location::caller());
    f();
}

fn calls_g() {
    g(); // <-- g() prints this location twice, once itself and once from f()
}

    وقتی تابع علامت‌خوردهٔ h، تابع g را فراخوانی کند و خود h به‌دست calls_h فراخوانی شود، همهٔ کدهای f، g و h محل فراخوانی h در calls_h را مشاهده می‌کنند:

    #[track_caller]
fn f() {
    println!("{}", std::panic::Location::caller());
}
#[track_caller]
fn g() {
    println!("{}", std::panic::Location::caller());
    f();
}
#[track_caller]
fn h() {
    println!("{}", std::panic::Location::caller());
    g();
}

fn calls_h() {
    h(); // <-- prints this location three times, once itself, once from g(), once from f()
}

    و به همین ترتیب.

    [attributes.codegen.track_caller.limits]

    محدودیت‌ها

    [attributes.codegen.track_caller.hint]

    این اطلاعات تنها راهنمایی است و پیاده‌سازی‌ها ملزم به حفظ آن نیستند.

    [attributes.codegen.track_caller.decay]

    به‌طور خاص، وادارسازی تابع #[track_caller] به اشاره‌گر تابع، یک shim می‌سازد که از دید مشاهده‌گر در محل تعریف تابع علامت‌خورده فراخوانی شده است؛ در نتیجه اطلاعات واقعی فراخوان در گذر از فراخوانی‌های مجازی از دست می‌رود. نمونهٔ رایج این وادارسازی، ساخت شیء صفتی با متدهای علامت‌خورده است.

    Note

    نکته shim یادشده برای اشاره‌گرهای تابع لازم است، زیرا rustc در تولید کد، track_caller را با افزودن پارامتری ضمنی به ABI تابع پیاده‌سازی می‌کند. این کار برای فراخوانی غیرمستقیم نادرست بود، چون پارامتر بخشی از نوع تابع نیست و یک نوع اشاره‌گر تابع ممکن است به تابع دارای ویژگی اشاره کند یا نکند. ساخت shim پارامتر ضمنی را از فراخوان‌های اشاره‌گر پنهان و درستی را حفظ می‌کند.

    [attributes.codegen.instruction_set]

    ویژگی instruction_set

    [attributes.codegen.instruction_set.intro]

    ویژگی instruction_set مجموعه‌دستوری را مشخص می‌کند که تابع هنگام تولید کد به کار می‌برد. این قابلیت ترکیب بیش از یک مجموعه‌دستور در یک برنامه را ممکن می‌کند.

    مثال

    #[instruction_set(arm::a32)]
fn arm_code() {}

#[instruction_set(arm::t32)]
fn thumb_code() {}
    [attributes.codegen.instruction_set.syntax]

    ویژگی instruction_set از نحو MetaListPaths برای مشخص‌کردن یک مسیر شامل نام خانوادهٔ معماری و نام مجموعه‌دستور استفاده می‌کند.

    [attributes.codegen.instruction_set.allowed-positions]

    ویژگی instruction_set تنها روی تابع‌های دارای بدنه قابل اعمال است: بستارها، بلوک‌های async، تابع‌های آزاد، تابع‌های وابسته در پیاده‌سازی ذاتی یا پیاده‌سازی صفت، و تابع‌های وابستهٔ دارای تعریف پیش‌فرض در تعریف صفت.

    Note

    نکته rustc استفاده در جایگاه‌های دیگر را نادیده می‌گیرد، اما دربارهٔ آن هشدار لینت می‌دهد. این وضعیت ممکن است در آینده به خطا تبدیل شود.

    Note

    نکته هرچند ویژگی روی بستارها و بلوک‌های async قابل اعمال است، سودمندی آن محدود است، زیرا هنوز ویژگی روی عبارت‌ها پشتیبانی نمی‌شود.

    [attributes.codegen.instruction_set.duplicates]

    ویژگی instruction_set تنها یک بار روی تابع قابل استفاده است.

    [attributes.codegen.instruction_set.target-limits]

    ویژگی instruction_set تنها با مقصدی قابل استفاده است که مقدار داده‌شده را پشتیبانی کند.

    [attributes.codegen.instruction_set.inline-asm]

    هنگام استفاده از instruction_set، هر اسمبلی درون‌خطی تابع باید به‌جای مجموعه‌دستور پیش‌فرض مقصد از مجموعه‌دستور مشخص‌شده استفاده کند.

    [attributes.codegen.instruction_set.arm]

    instruction_set روی ARM

    هنگام هدف‌گیری معماری‌های ARMv4T و ARMv5te، مقدارهای پشتیبانی‌شدهٔ instruction_set عبارت‌اند از:

    • arm::a32 — تابع را به‌صورت کد A32 نوع «ARM» تولید می‌کند.
    • arm::t32 — تابع را به‌صورت کد T32 نوع «Thumb» تولید می‌کند.

    اگر آدرس تابع به‌صورت اشاره‌گر تابع گرفته شود، بیت کم‌ارزش آدرس به مجموعه‌دستور انتخابی وابسته است:

    • برای arm::a32 یعنی «ARM»، برابر ۰ است.
    • برای arm::t32 یعنی «Thumb»، برابر ۱ است.
