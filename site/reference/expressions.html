    [expr.intro]

    یک عبارت می‌تواند دو نقش داشته باشد: همیشه یک مقدار تولید می‌کند و ممکن است اثرهایی نیز داشته باشد که با نام «اثرات جانبی» شناخته می‌شوند.

    [expr.evaluation]

    یک عبارت به مقداری ارزیابی می‌شود و هنگام ارزیابی اثرهایش را ایجاد می‌کند.

    [expr.operands]

    بسیاری از عبارت‌ها زیرعبارت‌هایی دارند که عملوندهای عبارت نامیده می‌شوند.

    [expr.behavior]

    معنای هر گونهٔ عبارت چند موضوع را تعیین می‌کند:

    • آیا هنگام ارزیابی عبارت، عملوندها ارزیابی شوند یا نه
    • ترتیب ارزیابی عملوندها
    • شیوهٔ ترکیب مقادیر عملوندها برای به دست آوردن مقدار عبارت
    [expr.structure]

    به این ترتیب، ساختار عبارت‌ها ساختار اجرا را تعیین می‌کند. بلوک‌ها نیز گونه‌ای از عبارت هستند؛ پس بلوک‌ها، دستورها، عبارت‌ها و دوباره بلوک‌ها می‌توانند به‌صورت بازگشتی و تا هر ژرفایی درون یکدیگر قرار گیرند.

    Note

    نکته برای آنکه بتوانیم دربارهٔ عملوندهای عبارت‌ها گفت‌وگو کنیم به آن‌ها نام می‌دهیم، اما این نام‌ها پایدار نیستند و ممکن است تغییر کنند.

    [expr.operand-order.operands-before-primary]

    عملوندهای این عبارت‌ها پیش از اعمال اثرهای عبارت ارزیابی می‌شوند. عبارت‌هایی با چند عملوند، به همان ترتیب نوشته‌شدن در کد منبع از چپ به راست ارزیابی می‌شوند.

    Note

    نکته اینکه کدام زیرعبارت‌ها عملوند یک عبارت هستند بر پایهٔ تقدم عبارت‌ها در بخش پیش تعیین می‌شود.

    برای نمونه، دو فراخوانی متد next همیشه به همین ترتیب فراخوانی می‌شوند:

    // Using vec instead of array to avoid references
// since there is no stable owned array iterator
// at the time this example was written.
let mut one_two = vec![1, 2].into_iter();
assert_eq!(
    (1, 2),
    (one_two.next().unwrap(), one_two.next().unwrap())
);

    Note

    نکته از آنجا که این قاعده بازگشتی اعمال می‌شود، این عبارت‌ها از درونی‌ترین به بیرونی‌ترین نیز ارزیابی می‌شوند و تا زمانی که زیرعبارت درونی باقی مانده است، عبارت‌های هم‌سطح نادیده گرفته می‌شوند.

    [expr.place-value]

    عبارت‌های مکان و عبارت‌های مقدار

    [expr.place-value.intro]

    عبارت‌ها به دو دستهٔ اصلی تقسیم می‌شوند: عبارت‌های مکان و عبارت‌های مقدار؛ دستهٔ کوچک سومی نیز با نام عبارت‌های گیرندهٔ انتساب وجود دارد. درون هر عبارت، عملوندها نیز می‌توانند در بافت مکان یا بافت مقدار قرار گیرند. ارزیابی یک عبارت هم به دستهٔ خود آن و هم به بافتی که در آن قرار دارد وابسته است.

    [expr.place-value.place-memory-location]

    عبارت مکان عبارتی است که یک محل حافظه را بازنمایی می‌کند.

    [expr.place-value.place-expr-kinds]

    این عبارت‌ها عبارت‌اند از مسیرهایی که به متغیرهای محلی ارجاع می‌دهند، متغیرهای ایستا، ارجاع‌زدایی‌ها (*expr)، عبارت‌های اندیس‌گذاری آرایه (expr[expr])، ارجاع‌های میدان (expr.f) و عبارت‌های مکانِ پرانتزدار.

    [expr.place-value.value-expr-kinds]

    همهٔ عبارت‌های دیگر عبارت مقدار هستند.

    [expr.place-value.value-result]

    عبارت مقدار عبارتی است که یک مقدار واقعی را بازنمایی می‌کند.

    [expr.place-value.place-context]

    بافت‌های زیر، بافت عبارت مکان هستند:

    • عملوند چپ یک عبارت انتساب مرکب.
    • عملوند یک عبارت میدان.
    • عملوند یک عبارت فیلد.
    • عملوند اندیس‌شوندهٔ یک عبارت اندیس‌گذاری آرایه.
    • عملوند تاپل در یک عبارت اندیس‌گذاری تاپل.
    • عملوند هر قرض‌گیری ضمنی.
    • مقداردهندهٔ اولیهٔ یک دستور let.
    • عبارت بررسی‌شونده در یک عبارت if let، match یا while let.
    • پایهٔ یک عبارت struct با به‌روزرسانی تابعی.

    Note

    نکته از نظر تاریخی، عبارت‌های مکان lvalue و عبارت‌های مقدار rvalue نامیده می‌شدند.

    [expr.place-value.assignee]

    عبارت گیرندهٔ انتساب عبارتی است که در عملوند چپ یک عبارت انتساب ظاهر می‌شود. عبارت‌های گیرندهٔ انتساب دقیقاً این مواردند:

    • عبارت‌های مکان (place expressions).
    • عبارت‌های مکان.
    • زیرخط‌ها.
    • تاپل‌های متشکل از عبارت‌های گیرندهٔ انتساب.
    • tuple structها از عبارت‌های دریافت‌کنندهٔ انتساب (assignee expressions).
    • ساختارهای واحد
    • unit structها
    [expr.place-value.parenthesis]

    استفادهٔ دلخواه از پرانتز درون عبارت‌های گیرندهٔ انتساب مجاز است.

    [expr.move]

    نوع‌های منتقل‌شده و همتاسازی‌شده

    [expr.move.intro]

    هنگامی که یک عبارت مکان در بافت عبارت مقدار ارزیابی شود یا در یک الگو با مقدار مقید شود، نشان‌دهندهٔ مقداری است که در آن محل حافظه نگهداری می‌شود.

    [expr.move.copy]

    اگر نوع آن مقدار Copy را پیاده‌سازی کند، مقدار همتاسازی می‌شود.

    [expr.move.requires-sized]

    در وضعیت‌های دیگر، اگر نوع Sized باشد، ممکن است بتوان مقدار را منتقل کرد.

    [expr.move.movable-place]

    تنها از عبارت‌های مکان زیر می‌توان مقدار را بیرون منتقل کرد:

    • متغیرهای که در حال حاضر قرض گرفته نشده‌اند.
    • مقادیر موقت.
    • میدان‌های یک عبارت مکان که بتوان از آن مقدار را بیرون منتقل کرد و Drop را پیاده‌سازی نکنند.
    • نتیجهٔ ارجاع‌زدایی عبارتی از نوع Box<T> که بتوان از آن نیز مقدار را بیرون منتقل کرد.
    [expr.move.deinitialization]

    پس از بیرون بردن مقدار از عبارت مکانی که به یک متغیر محلی ارزیابی می‌شود، آن محل از حالت مقداردهی خارج شده و تا زمان مقداردهی دوباره قابل خواندن نیست.

    [expr.move.place-invalid]

    در همهٔ موارد دیگر، تلاش برای استفاده از یک عبارت مکان در بافت عبارت مقدار خطاست.

    [expr.mut]

    تغییرپذیری

    [expr.mut.intro]

    برای اینکه بتوان به یک عبارت مکان مقدار نسبت داد، آن را به‌شکل تغییرپذیر قرض گرفت، به‌طور ضمنی و تغییرپذیر قرض گرفت یا به الگویی شامل ref mut مقید کرد، باید تغییرپذیر باشد. این موارد را عبارت‌های مکان تغییرپذیر می‌نامیم. در مقابل، دیگر عبارت‌های مکان عبارت‌های مکان تغییرناپذیر نامیده می‌شوند.

    [expr.mut.valid-places]

    عبارت‌های زیر می‌توانند در بافت عبارت مکان تغییرپذیر قرار گیرند:

    • متغیرهای تغییرپذیری که در حال حاضر قرض گرفته نشده‌اند.
    • [اقلام static تغییرپذیر].
    • مقادیر موقت.
    • میدان‌ها: این مورد زیرعبارت را در بافت عبارت مکان تغییرپذیر ارزیابی می‌کند.
    • ارجاع‌زدایی‌های یک اشاره‌گر *mut T.
    • ارجاع‌زدایی متغیر یا میدان یک متغیر با نوع &mut T. توجه: این مورد استثنایی بر الزام قاعدهٔ بعد است.
    • ارجاع‌زدایی نوعی که DerefMut را پیاده‌سازی می‌کند؛ در این حالت مقداری که ارجاع‌زدایی می‌شود باید در بافت عبارت مکان تغییرپذیر ارزیابی شود.
    • اندیس‌گذاری آرایه روی نوعی که IndexMut را پیاده‌سازی می‌کند؛ در این حالت مقدار اندیس‌شونده، اما نه خود اندیس، در بافت عبارت مکان تغییرپذیر ارزیابی می‌شود.
    [expr.temporary]

    مقادیر موقت

    هنگام استفاده از یک عبارت مقدار در بیشتر بافت‌های عبارت مکان، محل حافظهٔ موقت و بی‌نامی ساخته و با آن مقدار مقداردهی می‌شود. سپس عبارت به‌جای مقدار، به آن محل ارزیابی می‌شود؛ مگر اینکه به یک static ارتقا داده شود. دامنهٔ حذف مقدار موقت معمولاً انتهای دستور دربرگیرنده است.

    [expr.super-macros]

    ابرماکروها

    [expr.super-macros.intro]

    برخی ماکروهای داخلی می‌توانند مقادیر موقتی بسازند که دامنه‌هایشان قابل گسترش باشد. این مقادیر ابرموقت و این ماکروها ابرماکرو نامیده می‌شوند. فراخوانی‌های این ماکروها عبارت فراخوانی ابرماکرو هستند و آرگومان‌هایشان می‌توانند ابرعملوند باشند.

    Note

    وقتی یک عبارت فراخوانی ماکروی super یک عبارت گسترش‌دهنده باشد، عملوندهای super آن عبارت‌های گسترش‌دهنده هستند و دامنه‌های super temporaryها گسترش داده می‌شوند. destructors.scope.lifetime-extension.exprs را ببینید.

    [expr.super-macros.format_args]

    format_args!

    [expr.super-macros.format_args.super-operands]

    به‌جز آرگومان رشتهٔ قالب، همهٔ آرگومان‌های پاس‌داده‌شده به format_args! ابرعملوند هستند.

    fn temp() -> String { String::from("") }
// Due to the call being an extending expression and the argument
// being a super operand, the inner block is an extending expression,
// so the scope of the temporary created in its trailing expression
// is extended.
let _ = format_args!("{}", { &temp() }); // OK
    [expr.super-macros.format_args.super-temporaries]

    ابرعملوندهای format_args! به‌طور ضمنی قرض گرفته می‌شوند و بنابراین بافت عبارت مکان هستند. هنگامی که یک عبارت مقدار به‌عنوان آرگومان پاس داده شود، یک ابرموقت می‌سازد.

    fn temp() -> String { String::from("") }
let x = format_args!("{}", temp());
x; // <-- The temporary is extended, allowing use here.

    گسترش فراخوانی format_args! گاهی ابرموقت‌های داخلی دیگری می‌سازد.

    let x = {
    // This call creates an internal temporary.
    let x = format_args!("{:?}", 0);
    x // <-- The temporary is extended, allowing its use here.
}; // <-- The temporary is dropped here.
x; // ERROR
    // This call doesn't create an internal temporary.
let x = { let x = format_args!("{}", 0); x };
x; // OK

    Note

    نکته جزئیات اینکه format_args! چه زمانی مقدار موقت داخلی می‌سازد یا نمی‌سازد، در حال حاضر مشخص نشده است.

    [expr.super-macros.pin]

    pin!

    [expr.super-macros.pin.super-operands]

    آرگومان pin! یک ابرعملوند است.

    use core::pin::pin;
fn temp() {}
// As above for `format_args!`.
let _ = pin!({ &temp() }); // OK
    [expr.super-macros.pin.super-temporaries]

    آرگومان pin! یک بافت عبارت مقدار است و یک ابرموقت می‌سازد.

    use core::pin::pin;
fn temp() {}
// The argument is evaluated into a super temporary.
let x = pin!(temp());
// The temporary is extended, allowing its use here.
x; // OK
    [expr.implicit-borrow]

    قرض‌گیری‌های ضمنی

    [expr.implicit-borrow-intro]

    برخی عبارت‌ها با قرض گرفتن ضمنی یک عبارت، آن را به‌صورت عبارت مکان در نظر می‌گیرند. برای نمونه، می‌توان دو برش بدون اندازه را مستقیماً از نظر برابری مقایسه کرد، زیرا عملگر == عملوندهای خود را به‌طور ضمنی قرض می‌گیرد:

    let c = [1, 2, 3];
let d = vec![1, 2, 3];
let a: &[i32];
let b: &[i32];
a = &c;
b = &d;
// ...
*a == *b;
// Equivalent form:
::std::cmp::PartialEq::eq(&*a, &*b);
    [expr.implicit-borrow.application]

    قرض‌گیری ضمنی ممکن است در عبارت‌های زیر انجام شود:

    • عملوند چپ عبارت‌های فراخوانی متد.
    • عملوند چپ عبارت‌های میدان.
    • عملوند چپ در عبارت‌های فراخوانی.
    • عملوند چپ عبارت‌های فراخوانی.
    • عملوند عملگر ارجاع‌زدایی (*).
    • عملوندهای مقایسه.
    • عملوندهای مقایسه.
    • آرگومان‌های format_args! به‌جز رشتهٔ قالب.
    [expr.overload]

    بارگذاری بیش از حد صفت‌ها

    بسیاری از عملگرها و عبارت‌های بعدی را می‌توان با استفاده از صفت‌های std::ops یا std::cmp برای نوع‌های دیگر نیز بارگذاری بیش از حد کرد. همین صفت‌ها با همان نام‌ها در core::ops و core::cmp نیز وجود دارند.
