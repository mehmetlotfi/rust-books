مرجع زبان RustThe Rust Reference

    [input]

    قالب ورودی (Input format)

    [input.syntax]

    Lexer
    CHAR → [U+0000-U+D7FF U+E000-U+10FFFF] // a Unicode scalar value

    ASCII → [U+0000-U+007F]

    NUL → U+0000

    EOF → !CHAR // End of file or input

    [input.intro]

    این فصل توضیح می‌دهد که یک فایل منبع چگونه به‌صورت دنباله‌ای از توکن‌ها تفسیر می‌شود.

    برای آشنایی با شیوهٔ سازمان‌دهی برنامه‌ها در فایل‌ها، به بخش کریت‌ها و فایل‌های منبع مراجعه کنید.

    [input.encoding]

    کدگذاری منبع

    [input.encoding.utf8]

    هر فایل منبع به‌صورت دنباله‌ای از نویسه‌های یونیکد با کدگذاری UTF-8 تفسیر می‌شود.

    [input.encoding.invalid]

    اگر فایل UTF-8 معتبر نباشد، خطا رخ می‌دهد.

    [input.byte-order-mark]

    حذف نشان ترتیب بایت

    اگر نخستین نویسهٔ دنباله U+FEFF (BYTE ORDER MARK) باشد، حذف می‌شود.

    [input.crlf]

    عادی‌سازی CRLF

    هر جفت نویسهٔ U+000D (CR) که بلافاصله U+000A (LF) پس از آن آمده باشد، با یک U+000A (LF) جایگزین می‌شود. این کار تنها یک بار انجام می‌شود و تکرار نمی‌شود؛ بنابراین ممکن است پس از عادی‌سازی نیز در ورودی یک U+000D (CR) درست پیش از U+000A (LF) وجود داشته باشد (برای نمونه، اگر ورودی خام شامل «CR CR LF LF» بوده باشد).

    سایر رخدادهای نویسهٔ U+000D (CR) در جای خود باقی می‌مانند (و به‌عنوان فضای خالی در نظر گرفته می‌شوند).

    [input.shebang]

    حذف شِبَنگ

    [input.shebang.removal]

    اگر شِبَنگی وجود داشته باشد، از دنبالهٔ ورودی حذف می‌شود (و در نتیجه نادیده گرفته می‌شود).

    [input.tokenization]

    توکن‌سازی

    دنبالهٔ حاصل از نویسه‌ها، مطابق توضیحات ادامهٔ این فصل، به توکن تبدیل می‌شود.

    Note

    نکته ماکروی include! در کتابخانهٔ استاندارد، تبدیل‌های زیر را روی فایلی که می‌خواند اعمال می‌کند:

    • حذف نشان ترتیب بایت.
    • عادی‌سازی CRLF.
    • حذف شِبَنگ، هنگامی که ماکرو در بافت یک آیتم فراخوانی شود (در برابر بافت عبارت یا دستور).

    ماکروهای include_str! و include_bytes! این تبدیل‌ها را اعمال نمی‌کنند.
