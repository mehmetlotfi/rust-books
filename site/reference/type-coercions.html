    [coerce]

    وادارسازی نوع

    [coerce.intro]

    وادارسازی نوع عملیاتی ضمنی است که نوع یک مقدار را تغییر می‌دهد. این عملیات خودکار و فقط در محل‌های مشخص رخ می‌دهد و نوع‌هایی که واقعاً وادار می‌شوند به‌شدت محدودند.

    [coerce.as]

    هر تبدیلی که با وادارسازی مجاز باشد، با عملگر تبدیل نوع as نیز می‌تواند صریحاً انجام شود.

    وادارسازی‌ها ابتدا در RFC 401 تعریف و در RFC 1558 گسترش یافتند.

    [coerce.site]

    محل‌های وادارسازی

    [coerce.site.intro]

    وادارسازی فقط در محل‌های مشخصی از برنامه رخ می‌دهد؛ معمولاً جاهایی که نوع مطلوب صریح است یا بدون استنتاج نوع، با انتشار از نوع‌های صریح مشتق می‌شود. محل‌های ممکن عبارت‌اند از:

    [coerce.site.let]

    • دستورهای let دارای نوع صریح.

      برای مثال، در کد زیر &mut 42 به نوع &i8 وادار می‌شود:

      let _: &i8 = &mut 42;
    [coerce.site.value]
    • اعلان آیتم‌های static و const، مشابه دستورهای let.
    [coerce.site.argument]

    • آرگومان‌های فراخوانی تابع.

      مقدار مورد وادارسازی پارامتر واقعی است و به نوع پارامتر صوری وادار می‌شود.

      برای مثال، در کد زیر &mut 42 به نوع &i8 وادار می‌شود:

      fn bar(_: &i8) { }

fn main() {
    bar(&mut 42);
}

      در فراخوانی متد، نوع گیرنده—پارامتر self—به‌شکل دیگری وادار می‌شود. برای جزئیات عبارت‌های فراخوانی متد را ببینید.

    [coerce.site.constructor]

    • نمونه‌سازی فیلدهای struct، ‏union یا گونهٔ enum.

      برای مثال، &mut 42 در نمونهٔ زیر به نوع &i8 وادار (coerce) می‌شود:

      struct Foo<'a> { x: &'a i8 }

fn main() {
    Foo { x: &mut 42 };
}
    [coerce.site.return]

    • نتایج تابع؛ عبارت آخر بلوک اگر با نقطه‌ویرگول پایان نیافته باشد، یا هر عبارت در دستور return.

      برای مثال، x در کد زیر به &dyn Display وادار می‌شود:

      use std::fmt::Display;
fn foo(x: &u32) -> &dyn Display {
    x
}
    [coerce.site.assignment]

    • عملوند مقدار نسبت‌داده‌شده در عبارت انتساب.

      برای مثال، y در کد زیر به &i8 وادار می‌شود:

      let mut x = &0i8;
let y = &mut 42i8;
x = y;
    [coerce.site.subexpr]

    اگر عبارت یکی از این محل‌ها انتشاردهندهٔ وادارسازی باشد، زیرعبارت‌های مرتبط آن نیز محل وادارسازی هستند. انتشار از این محل‌های تازه به‌صورت بازگشتی ادامه می‌یابد. عبارت‌های انتشاردهنده و زیرعبارت‌های مرتبطشان عبارت‌اند از:

    [coerce.site.array]
    • لفظ‌های آرایه با نوع [U; n]. هر زیرعبارت آرایه محل وادارسازی به U است.
    [coerce.site.repeat]
    • لفظ‌های آرایه با نحو تکرار و نوع [U; n]. زیرعبارت تکرارشده محل وادارسازی به U است.
    [coerce.site.tuple]
    • تاپل، هنگامی که محل وادارسازی به نوع (U_0, U_1, ..., U_n) باشد. هر زیرعبارت به نوع متناظر وادار می‌شود؛ برای نمونه زیرعبارت صفرم به U_0.
    [coerce.site.parenthesis]
    • زیرعبارت پرانتزی (e): اگر عبارت نوع U داشته باشد، زیرعبارت محل وادارسازی به U است.
    [coerce.site.block]
    • بلوک‌ها: اگر بلوک نوع U داشته باشد، آخرین عبارت آن—اگر با نقطه‌ویرگول پایان نیافته باشد—محل وادارسازی به U است. بلوک‌های بخشی از دستورهای کنترل جریان مانند if/else نیز در صورت داشتن نوع معلوم شامل این قاعده‌اند.
    [coerce.types]

    نوع‌های وادارسازی

    [coerce.types.intro]

    وادارسازی میان نوع‌های زیر مجاز است:

    [coerce.types.reflexive]
    • T به U اگر T زیرنوع U باشد؛ حالت بازتابی.
    [coerce.types.transitive]

    • T_1 به T_3 هنگامی که T_1 به T_2 و T_2 به T_3 وادار شود؛ حالت تعدی.

      این حالت هنوز به‌طور کامل پشتیبانی نمی‌شود.

    [coerce.types.mut-reborrow]
    • &mut T به &T
    [coerce.types.mut-pointer]
    • *mut T به *const T
    [coerce.types.ref-to-pointer]
    • &T به *const T
    [coerce.types.mut-to-pointer]
    • &mut T به *mut T
    [coerce.types.deref]

    • &T یا &mut T به &U اگر T، ‏Deref<Target = U> را پیاده‌سازی کند. برای مثال:

      use std::ops::Deref;

struct CharContainer {
    value: char,
}

impl Deref for CharContainer {
    type Target = char;

    fn deref<'a>(&'a self) -> &'a char {
        &self.value
    }
}

fn foo(arg: &char) {}

fn main() {
    let x = &mut CharContainer { value: 'y' };
    foo(x); //&mut CharContainer is coerced to &char.
}
    [coerce.types.deref-mut]
    • &mut T به &mut U اگر T، ‏DerefMut<Target = U> را پیاده‌سازی کند.
    [coerce.types.unsize]

    • ‏TyCtor(T) به TyCtor(U)، که TyCtor(T) یکی از موارد زیر باشد:

      • &T
      • &mut T
      • *const T
      • *mut T
      • Box<T>

      و U با وادارسازی بدون اندازه از T به‌دست آید.

    [coerce.types.fn]
    • نوع آیتم‌های تابع به اشاره‌گرهای fn.
    [coerce.types.closure]
    • بستارهای بدون تسخیر به اشاره‌گرهای fn.
    [coerce.types.never]
    • ! به هر T.
    [coerce.unsize]

    وادارسازی‌های بدون اندازه

    [coerce.unsize.intro]

    وادارسازی‌های زیر unsized coercions نامیده می‌شوند، زیرا به تبدیل نوع‌ها به نوع‌های بدون اندازه (unsized) مربوط‌اند و در چند حالت که وادارسازی‌های دیگر، همان‌طور که در بالا توضیح داده شد، مجاز نیستند، مجازند. این وادارسازی‌ها همچنان می‌توانند در هر جای دیگری که وادارسازی رخ می‌دهد نیز اتفاق بیفتند.

    [coerce.unsize.trait]

    دو صفت Unsize و CoerceUnsized به این فرایند کمک و آن را برای استفادهٔ کتابخانه آشکار می‌کنند. وادارسازی‌های زیر داخلی‌اند و اگر یکی از آن‌ها T را به U وادار کند، پیاده‌سازی Unsize<U> برای T ارائه می‌شود:

    [coerce.unsize.slice]
    • [T; n] به [T].
    [coerce.unsize.trait-object]
    • T به dyn U، هنگامی که T، ‏U + Sized را پیاده‌سازی کند و U سازگار با dyn باشد.
    [coerce.unsize.trait-upcast]
    • dyn T به dyn U، هنگامی که U یکی از فراصفت‌های T باشد.
      • حذف صفت‌های خودکار مجاز است؛ برای نمونه dyn T + Auto به dyn U.
      • اگر صفت اصلی یک صفت خودکار را فراصفت داشته باشد، افزودن آن مجاز است؛ با trait T: U + Send {}، وادارسازی dyn T به dyn T + Send یا dyn U + Send مجاز است.
    [coerce.unsized.composite]
    • Foo<..., T, ...> به Foo<..., U, ...>، هنگامی که:
      • Foo یک struct باشد؛
      • T، ‏Unsize<U> را پیاده‌سازی کند؛
      • آخرین فیلد Foo نوعی دربرگیرندهٔ T داشته باشد؛
      • اگر نوع فیلد Bar<T> است، ‏Bar<T>، ‏Unsize<Bar<U>> را پیاده‌سازی کند؛
      • T بخشی از نوع هیچ فیلد دیگری نیست.
    [coerce.unsized.pointer]

    افزون بر این، نوع Foo<T> می‌تواند هنگامی که T، ‏Unsize<U> یا CoerceUnsized<Foo<U>> را پیاده‌سازی می‌کند، CoerceUnsized<Foo<U>> را پیاده‌سازی کند. این کار اجازه می‌دهد وادارسازی بدون اندازه به Foo<U> فراهم شود.

    Note

    نکته تعریف و پیاده‌سازی وادارسازی‌های بدون اندازه پایدار شده، اما خود صفت‌ها هنوز پایدار نیستند و مستقیماً در Rust پایدار قابل استفاده نیستند.

    [coerce.least-upper-bound]

    وادارسازی کمترین کران بالا

    [coerce.least-upper-bound.intro]

    در بعضی بافت‌ها کامپایلر باید چند نوع را با هم وادار کند تا عمومی‌ترین نوع را بیابد. این کار وادارسازی «کمترین کران بالا» یا LUB نام دارد و فقط در وضعیت‌های زیر استفاده می‌شود:

    • یافتن نوع مشترک مجموعه‌ای از شاخه‌های if؛
    • یافتن نوع مشترک مجموعه‌ای از بازوهای match؛
    • یافتن نوع مشترک عناصر آرایه؛
    • یافتن نوع مشترک یک عبارت بلوکی برچسب‌دار میان عملوندهای break و عملوند نهایی بلوک؛
    • یافتن نوع مشترک یک عبارت loop دارای break میان عملوندهای break؛
    • برای یافتن نوع بازگشتیِ یک بستار با چند دستور return.
    • برای بررسی نوع بازگشتیِ یک تابع با چند دستور return.
    [coerce.least-upper-bound.target]

    در هر حالت مجموعهٔ نوع‌های T0..Tn باید به‌طور متقابل به نوع هدف T_t وادار شوند که در آغاز ناشناخته است.

    [coerce.least-upper-bound.computation]

    محاسبهٔ LUB تکراری است. نوع هدف T_t ابتدا T0 است. برای هر نوع تازهٔ Ti بررسی می‌شود:

    [coerce.least-upper-bound.computation-identity]
    • اگر Ti به نوع هدف جاری T_t وادار شود، تغییری انجام نمی‌شود.
    [coerce.least-upper-bound.computation-replace]
    • وگرنه بررسی می‌شود آیا T_t به Ti وادار می‌شود؛ اگر چنین باشد، T_t به Ti تغییر می‌کند. این بررسی به ضمنی‌بودن وادارسازی همهٔ عبارت‌های منبع بررسی‌شده تا آن لحظه نیز وابسته است.
    [coerce.least-upper-bound.computation-unify]
    • در غیر این صورت تلاش می‌شود ابرنوع مشترکی برای T_t و Ti محاسبه شود تا نوع هدف جدید باشد.

    نمونه‌ها

    let (a, b, c) = (0, 1, 2);
// For if branches
let bar = if true {
    a
} else if false {
    b
} else {
    c
};

// For match arms
let baw = match 42 {
    0 => a,
    1 => b,
    _ => c,
};

// For array elements
let bax = [a, b, c];

// For closure with multiple return statements
let clo = || {
    if true {
        a
    } else if false {
        b
    } else {
        c
    }
};
let baz = clo();

// For type checking of function with multiple return statements
fn foo() -> i32 {
    let (a, b, c) = (0, 1, 2);
    match 42 {
        0 => a,
        1 => b,
        _ => c,
    }
}

    در این نمونه‌ها، نوع‌های ba* با وادارسازی LUB پیدا می‌شوند. و کامپایلر در پردازش تابع foo بررسی می‌کند که آیا نتیجهٔ وادارسازی LUB برای a، b و c برابر i32 است یا نه.
