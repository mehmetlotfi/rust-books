    واژه‌نامه

    [glossary.ast]

    درخت نحو انتزاعی

    «درخت نحو انتزاعی» یا «AST» بازنمایی میانیِ ساختار برنامه هنگام کامپایل شدن آن به‌وسیلهٔ کامپایلر است.

    هم‌ترازی

    هم‌ترازی یک مقدار مشخص می‌کند ترجیحاً مقدار از چه نشانی‌هایی آغاز شود. هم‌ترازی همیشه توانی از دو است. ارجاع‌ها به یک مقدار باید هم‌تراز باشند. بیشتر.

    [glossary.abi]

    رابط دودویی برنامه (ABI)

    یک رابط دودویی برنامه (ABI) مشخص می‌کند کد کامپایل‌شده چگونه با کد کامپایل‌شدهٔ دیگر تعامل داشته باشد. در بلوک‌های extern و extern fn، رشته‌های ABI بر این موارد اثر می‌گذارند:

    • قرارداد فراخوانی: آرگومان‌های تابع چگونه پاس داده می‌شوند، مقادیر چگونه بازگردانده می‌شوند (برای نمونه در ثبات‌ها یا روی پشته) و مسئول پاک‌سازی پشته کیست.
    • بازپیچی: آیا بازپیچی پشته مجاز است یا نه. برای نمونه، ABI با نام "C-unwind" بازپیچی از مرز FFI را مجاز می‌داند، اما ABI با نام "C" چنین اجازه‌ای نمی‌دهد.

    آریتی (Arity)

    تعداد آرگومان به شمار آرگومان‌هایی اشاره دارد که یک تابع یا عملگر می‌گیرد. برای نمونه، f(2, 3) و g(4, 6) هر کدام دو آرگومان دارند، در حالی که h(8, 2, 6) سه آرگومان دارد. عملگر ! یک آرگومان دارد.

    آرایه

    آرایه، که گاهی آرایهٔ اندازه‌ثابت یا آرایهٔ درون‌خطی نیز نامیده می‌شود، مقداری است که مجموعه‌ای از عنصرها را توصیف می‌کند؛ هر عنصر با اندیسی انتخاب می‌شود که برنامه می‌تواند هنگام اجرا محاسبه کند. آرایه ناحیه‌ای پیوسته از حافظه را اشغال می‌کند.

    قلم وابسته

    قلم وابسته قلمی است که به قلم دیگری وابسته است. اقلام وابسته در پیاده‌سازی‌ها تعریف و در صفت‌ها اعلان می‌شوند. تنها تابع‌ها، ثابت‌ها و نام‌های مستعار نوع می‌توانند وابسته باشند. آن را با قلم آزاد مقایسه کنید.

    پیاده‌سازی فراگیر

    هر پیاده‌سازی‌ای که در آن یک نوع به‌صورت پوشانده‌نشده ظاهر شود. impl<T> Foo for T، impl<T> Bar<T> for T، impl<T> Bar<Vec<T>> for T و impl<T> Bar<T> for Vec<T> پیاده‌سازی فراگیر به شمار می‌آیند. با این حال، impl<T> Bar<Vec<T>> for Vec<T> فراگیر نیست، زیرا همهٔ نمونه‌های T در این impl به‌وسیلهٔ Vec پوشانده شده‌اند.

    کران

    کران‌ها محدودیت‌هایی روی یک نوع یا صفت هستند. برای نمونه، اگر روی آرگومان یک تابع کرانی قرار داده شود، نوع‌هایی که به آن تابع پاس داده می‌شوند باید آن محدودیت را رعایت کنند.

    ترکیب‌گر

    ترکیب‌گرها تابع‌های مرتبه‌بالاتری هستند که تنها تابع‌ها و ترکیب‌گرهای از پیش تعریف‌شده را به کار می‌گیرند تا از آرگومان‌های خود نتیجه‌ای بسازند. از آن‌ها می‌توان برای مدیریت پیمانه‌ای جریان کنترل استفاده کرد.

    کریت

    کریت واحد کامپایل و پیوند است. گونه‌های مختلفی از کریت، مانند کتابخانه یا فایل اجرایی، وجود دارد. کریت‌ها می‌توانند به کریت‌های کتابخانه‌ای دیگر که کریت خارجی نامیده می‌شوند پیوند بخورند و ارجاع دهند. هر کریت یک درخت مستقل از ماژول‌ها دارد که از ماژول ریشهٔ بی‌نام، موسوم به ریشهٔ کریت، آغاز می‌شود. اقلام را می‌توان با عمومی کردنشان در ریشهٔ کریت، از جمله از راه مسیرهای ماژول‌های عمومی، برای کریت‌های دیگر نمایان کرد. بیشتر.

    اعزام

    اعزام سازوکاری برای تعیین نسخهٔ مشخصی از کد است که هنگام درگیر بودن چندریختی واقعاً اجرا می‌شود. دو شکل اصلی آن اعزام ایستا و اعزام پویا هستند. Rust با استفاده از اشیای صفت از اعزام پویا پشتیبانی می‌کند.

    نوع با اندازهٔ پویا

    traitهایی که می‌توان در نوع‌های trait object (dyn Trait) به کار برد. فقط traitهایی که از قواعد مشخصی پیروی کنند dyn compatible هستند.

    این traitها پیش‌تر با نام traitهای object safe شناخته می‌شدند.

    نوع با اندازهٔ پویا (Dynamically sized type)

    نوع با اندازهٔ پویا (DST) نوعی است که اندازه یا هم‌ترازی آن به‌صورت ایستا شناخته‌شده نیست.

    موجودیت

    یک موجودیت سازه‌ای در زبان است که می‌توان در برنامهٔ منبع به شکلی، معمولاً از راه یک مسیر، به آن ارجاع داد. موجودیت‌ها شامل نوع‌ها، آیتم‌ها، پارامترهای عمومی، اتصال‌های متغیر، برچسب‌های حلقه، طول‌عمرها، فیلدها، ویژگی‌ها و lintها هستند.

    عبارت

    عبارت ترکیبی از مقادیر، ثابت‌ها، متغیرها، عملگرها و تابع‌ها است که با یا بدون اثر جانبی به یک مقدار واحد ارزیابی می‌شود.

    برای نمونه، 2 + (3 * 4) عبارتی است که مقدار ۱۴ را برمی‌گرداند.

    قلم آزاد

    یک قلم که عضو یک پیاده‌سازی نیست؛ مانند تابع آزاد یا ثابت آزاد. آن را با قلم وابسته مقایسه کنید.

    صفت‌های بنیادی

    صفت بنیادی صفتی است که افزودن یک impl از آن برای نوعی موجود، تغییری ناسازگار به شمار می‌آید. صفت‌های Fn و Sized بنیادی هستند.

    سازنده‌های نوع بنیادی

    سازندهٔ نوع بنیادی نوعی است که پیاده‌سازی یک پیاده‌سازی فراگیر روی آن تغییری ناسازگار محسوب می‌شود. &، &mut، Box و Pin بنیادی هستند.

    هر زمان نوع T محلی در نظر گرفته شود، &T، &mut T، Box<T> و Pin<T> نیز محلی به شمار می‌آیند. سازنده‌های نوع بنیادی نمی‌توانند نوع‌های دیگر را بپوشانند. هرجا اصطلاح «نوع پوشانده‌شده» به کار رود، T در &T، &mut T، Box<T> و Pin<T> پوشانده‌شده محسوب نمی‌شود.

    دارای ساکن

    نوعی دارای ساکن است اگر سازنده داشته باشد و در نتیجه بتوان از آن نمونه ساخت. چنین نوعی به این معنا «تهی» نیست که می‌توان مقادیری از آن داشت. نقطهٔ مقابل بدون ساکن است.

    پیاده‌سازی ذاتی

    یک پیاده‌سازی که نه روی یک جفت صفت‌ـنوع، بلکه روی یک نوع اسمی اعمال می‌شود. بیشتر.

    متد ذاتی

    متدی که در یک پیاده‌سازی ذاتی تعریف شده باشد، نه در پیاده‌سازی trait.

    مقداردهی‌شده

    یک متغیر زمانی مقداردهی‌شده است که مقداری به آن اختصاص یافته باشد و از آن زمان مقدار از آن منتقل نشده باشد. همهٔ محل‌های دیگر حافظه مقداردهی‌نشده فرض می‌شوند. تنها Rust ناامن می‌تواند محلی در حافظه را بدون مقداردهی ایجاد کند.

    صفت محلی

    یک trait که در کریت جاری تعریف شده است. محلی بودن تعریف صفت به آرگومان‌های نوع اعمال‌شده وابسته نیست. با فرض trait Foo<T, U>، صفت Foo مستقل از نوع‌هایی که جایگزین T و U می‌شوند همیشه محلی است.

    نوع محلی

    یک struct، enum یا union که در کریت جاری تعریف شده باشد. آرگومان‌های نوع اعمال‌شده بر این موضوع اثری ندارند. struct Foo محلی به شمار می‌آید، اما Vec<Foo> نه. LocalType<ForeignType> محلی است. نام‌های مستعار نوع بر محلی بودن اثر نمی‌گذارند.

    ماژول

    ماژول ظرفی برای صفر یا چند قلم است. ماژول‌ها به شکل درختی سازمان یافته‌اند که از ماژول بی‌نام ریشه، موسوم به ریشهٔ کریت یا ماژول ریشه، آغاز می‌شود. برای ارجاع به اقلام ماژول‌های دیگر می‌توان از مسیرها استفاده کرد؛ دسترسی به آن اقلام ممکن است با قواعد نمایانی محدود شود. بیشتر

    [glossary.n-zst]

    نوع بدون اندازه با هم‌ترازی n‏ (n-ZST)

    n-ZST به نوعی اشاره دارد که بدون اندازه است (یک ZST) و هم‌ترازی n دارد. برای نمونه، 1-ZST نوعی بدون اندازه با هم‌ترازی ۱ است.

    نمونه‌های 1-ZST عبارت‌اند از:

    • نوع unit (به layout.tuple.unit مراجعه کنید).
    • نوع never (به type.never.layout مراجعه کنید).
    • ساختارهای repr(C) بدون میدان یا با میدان‌هایی که همگی 1-ZST هستند (بخش‌های layout.repr.c.struct.align و layout.repr.c.struct.size-field-offset را ببینید).
    • ساختارهای repr(transparent) بدون میدان یا با میدان‌هایی که همگی 1-ZST هستند (بخش layout.repr.transparent.layout-abi را ببینید).
    • آرایه‌های 1-ZST (بخش layout.array را ببینید).
    • PhantomData<T> برای هر نوع T (به lang-types.phantom-data مراجعه کنید).
    use core::marker::PhantomData;
use core::mem::{align_of, size_of};
#[repr(C)]
struct C1 {}
#[repr(C)]
struct C2 {
    f1: (),
    f2: [(); 10],
    f3: C1,
}
#[repr(transparent)]
struct T1 {}
#[repr(transparent)]
struct T2 {
    f1: (),
    f2: [(); 10],
}

fn is_1_zst<T>() -> bool {
    size_of::<T>() == 0 && align_of::<T>() == 1
}

assert!(is_1_zst::<()>());
assert!(is_1_zst::<!>());
assert!(is_1_zst::<C1>());
assert!(is_1_zst::<C2>());
assert!(is_1_zst::<[(); 10]>());
assert!(is_1_zst::<T1>());
assert!(is_1_zst::<T2>());
assert!(is_1_zst::<PhantomData<()>>());
assert!(is_1_zst::<PhantomData<u16>>());

    نام

    یک نام یک شناسه یا برچسب طول‌عمر یا حلقه است که به یک موجودیت ارجاع می‌دهد. مقیدسازی نام هنگامی رخ می‌دهد که اعلان یک موجودیت، شناسه یا برچسبی وابسته به آن موجودیت معرفی کند. مسیرها، شناسه‌ها و برچسب‌ها برای ارجاع به موجودیت به کار می‌روند.

    تفکیک نام

    تفکیک نام فرایندی در زمان کامپایل برای پیوند دادن مسیرها، شناسه‌ها و برچسب‌ها به اعلان‌های موجودیت است.

    فضای نام

    فضای نام گروه‌بندی منطقی نام‌های اعلان‌شده بر پایهٔ گونهٔ موجودیتی است که نام به آن اشاره می‌کند. فضاهای نام اجازه می‌دهند یک نام در یک فضای نام با همان نام در فضای نامی دیگر تداخل نداشته باشد.

    درون یک فضای نام، نام‌ها در قالب سلسله‌مراتبی سازمان یافته‌اند که هر سطح آن مجموعهٔ جداگانه‌ای از موجودیت‌های نام‌دار دارد.

    نوع‌های اسمی

    نوع‌هایی که می‌توان مستقیماً با یک مسیر به آن‌ها ارجاع داد؛ به‌طور مشخص enumها، structها، unionها و نوع‌های trait object.

    مسیر

    یک مسیر دنباله‌ای از یک یا چند قطعهٔ مسیر است که برای ارجاع به یک موجودیت در دامنهٔ جاری یا سطوح دیگر سلسله‌مراتب یک فضای نام به کار می‌رود.

    پیش‌درآمد

    پیش‌درآمد یا پیش‌درآمد Rust مجموعهٔ کوچکی از اقلام ــ عمدتاً صفت‌ها ــ است که به همهٔ ماژول‌های همهٔ کریت‌ها وارد می‌شود. صفت‌های پیش‌درآمد در سراسر برنامه حضور دارند.

    دامنه

    یک دامنه ناحیه‌ای از متن منبع است که در آن می‌توان با نام یک موجودیت به آن ارجاع داد.

    عبارت بررسی‌شونده

    عبارت بررسی‌شونده عبارتی است که در عبارت‌های match و سازه‌های مشابه تطبیق الگو با آن تطبیق داده می‌شود. برای نمونه، در match x { A => 1, B => 2 }، عبارت x عبارت بررسی‌شونده است.

    اندازه

    اندازهٔ یک مقدار دو تعریف دارد.

    تعریف نخست، مقدار حافظه‌ای است که باید برای ذخیرهٔ آن مقدار اختصاص یابد.

    تعریف دوم، فاصلهٔ بایتی میان عنصرهای پیاپی در آرایه‌ای با نوع همان قلم است.

    اندازه مضربی از هم‌ترازی، از جمله صفر، است. اندازه ممکن است بسته به نسخهٔ کامپایلر (با افزوده شدن بهینه‌سازی‌های جدید) و سکوی هدف (مشابه تفاوت usize میان سکوها) تغییر کند.

    بیشتر.

    برش

    برش نمایی با اندازهٔ پویا به یک دنبالهٔ پیوسته است که به‌صورت [T] نوشته می‌شود.

    برش اغلب در شکل‌های قرض‌گرفته‌شدهٔ اشتراکی یا تغییرپذیر دیده می‌شود. نوع برش اشتراکی &[T] و نوع برش تغییرپذیر &mut [T] است که در آن T نوع عنصرها را نشان می‌دهد.

    دستور

    دستور کوچک‌ترین عنصر مستقل یک زبان برنامه‌نویسی است که به رایانه فرمان می‌دهد عملی را انجام دهد.

    لفظ رشته‌ای

    لفظ رشته‌ای رشته‌ای است که مستقیماً در فایل دودویی نهایی ذخیره می‌شود و بنابراین برای طول‌عمر 'static معتبر خواهد بود.

    نوع آن برش رشته‌ای قرض‌گرفته‌شده با طول‌عمر 'static، یعنی &'static str، است.

    برش رشته‌ای

    برش رشته‌ای ابتدایی‌ترین نوع رشته در Rust است و به‌صورت str نوشته می‌شود. این نوع اغلب در شکل‌های قرض‌گرفته‌شدهٔ اشتراکی یا تغییرپذیر دیده می‌شود. نوع برش رشته‌ای اشتراکی &str و نوع تغییرپذیر آن &mut str است.

    برش‌های رشته‌ای همیشه UTF-8 معتبر هستند.

    صفت

    صفت قلمی در زبان است که برای توصیف قابلیت‌هایی به کار می‌رود که یک نوع باید فراهم کند. صفت اجازه می‌دهد یک نوع تعهدهای مشخصی دربارهٔ رفتار خود بدهد.

    تابع‌ها و ساختارهای عمومی می‌توانند با استفاده از صفت‌ها نوع‌هایی را که می‌پذیرند محدود یا مقید کنند.

    توربوفیش

    مسیرهای دارای پارامتر عمومی در عبارت‌ها باید پیش از براکت باز از :: استفاده کنند. ترکیب این نشانه با براکت‌های زاویه‌دار پارامترهای عمومی شبیه یک ماهی ::<> دیده می‌شود؛ از همین رو این نحو در گفتار «توربوفیش» نامیده می‌شود.

    نمونه‌ها:

    let ok_num = Ok::<_, ()>(5);
let vec = [1, 2, 3].iter().map(|n| n * 2).collect::<Vec<_>>();

    پیشوند :: برای رفع ابهام مسیرهای عمومی از چند مقایسه در فهرستی جداشده با ویرگول لازم است. برای نمونه‌ای که نبود این پیشوند ابهام ایجاد می‌کند، سنگر توربوفیش را ببینید.

    نوع پوشانده‌نشده

    نوعی که به‌عنوان آرگومان نوعی دیگر ظاهر نشود. برای نمونه، T پوشانده‌نشده است، اما T در Vec<T> پوشانده شده است. این مفهوم فقط برای آرگومان‌های نوع کاربرد دارد.

    رفتار تعریف‌نشده

    رفتاری در زمان کامپایل یا اجرا که مشخص نشده است. پیامدهای آن می‌تواند، بدون محدود شدن به این موارد، شامل پایان یا خرابی فرایند، محاسبهٔ نامناسب، نادرست یا ناخواسته، یا نتایج وابسته به سکو باشد. بیشتر.

    [glossary.uninhabited]

    بدون ساکن

    نوعی بدون ساکن است اگر سازنده‌ای نداشته باشد و بنابراین هرگز نتوان از آن نمونه ساخت. چنین نوعی به این معنا «تهی» است که هیچ مقداری از آن وجود ندارد. نمونهٔ معیار آن نوع هرگز ! یا یک برشمردنی بدون گونه مانند enum Never { } است. نقطهٔ مقابل دارای ساکن است.

    Note

    نکته نوع‌های بدون ساکن لزوماً بدون اندازه نیستند. برای نمونه، enum Never { } بدون ساکن و بدون اندازه است، اما (u8, Never) بدون ساکن است ولی بدون اندازه نیست.

    [glossary.zst]

    نوع بدون اندازه (ZST)

    یک نوع «با اندازهٔ صفر» (zero sized یا ZST) است هرگاه اندازهٔ آن ۰ باشد. چنین نوع‌هایی حداکثر یک مقدار ممکن دارند. نمونه‌ها عبارت‌اند از:

    • نوع unit (به layout.tuple.unit مراجعه کنید).
    • نوع never (به type.never.layout مراجعه کنید).
    • آیتم‌های تابع (به type.fn-item.intro مراجعه کنید).
    • نوع واحد (بخش layout.tuple.unit را ببینید).
    • سازنده‌های گونه‌های enum شبیه tuple (به type.fn-item.intro مراجعه کنید).
    • ساختارهای repr(Rust) بدون میدان یا با میدان‌هایی که همگی بدون اندازه‌اند (بخش layout.repr.rust.struct-zst را ببینید).
    • ساختارهای repr(C) بدون میدان یا با میدان‌هایی که همگی بدون اندازه‌اند (بخش layout.repr.c.struct.size-field-offset را ببینید).
    • ساختارهای repr(transparent) بدون میدان یا با میدان‌هایی که همگی بدون اندازه‌اند (بخش layout.repr.transparent.layout-abi را ببینید).
    • برشمردنی‌های repr(Rust) بدون گونه که بازنمایی ابتدایی مشخصی ندارند (بخش layout.repr.rust.enum-empty-zst را ببینید).
    • برشمردنی‌های repr(Rust) بدون بازنمایی ابتدایی مشخص، دارای تنها یک گونهٔ میدان‌ساختارمانند، گونهٔ واحدساختارمانند یا گونهٔ تاپل‌ساختارمانند که آن سازهٔ ساختارمانند یا میدانی ندارد یا همهٔ میدان‌هایش بدون اندازه‌اند (بخش layout.repr.rust.enum-struct-like-zst را ببینید).
    • آرایه‌هایی از نوع‌های با اندازهٔ صفر (به layout.array مراجعه کنید).
    • آرایه‌هایی با طول صفر (به layout.array مراجعه کنید).
    • unionهایی از نوع‌های با اندازهٔ صفر (به items.union.common-storage مراجعه کنید).
    • PhantomData<T> برای هر نوع T (به lang-types.phantom-data مراجعه کنید).
    use core::marker::PhantomData;
use core::mem::{size_of, size_of_val};
fn f() {}
struct S(u8);
enum E { V(u8) }
struct UnitLike;
struct NoFields {}
struct OnlyZST {
    f1: (),
    f2: [(); 10],
    f3: [u8; 0],
}
#[repr(C)]
struct C1 {}
#[repr(C)]
struct C2 {
    f1: (),
    f2: [(); 10],
    f3: [u8; 0],
    f4: C1,
}
#[repr(transparent)]
struct T1 {}
#[repr(transparent)]
struct T2 {
    f1: (),
    f2: [(); 10],
    f3: [u8; 0],
}
union U {
    f1: (),
    f2: [(); 10],
    f3: [u8; 0],
}
/// An enum with a single field-struct-like variant with all fields
/// being ZSTs.
enum E2 {
    V1 { f1: (), f2: [(); 10] },
}
/// An enum with a single field-struct-like variant with no fields.
enum E3 {
    V1 {},
}
/// An enum with a single unit-struct-like variant.
enum E4 {
    V1,
}
/// An enum with a single tuple-struct-like variant with all fields
/// being ZSTs.
enum E5 {
    V1 ((), [(); 10]),
}
/// An enum with a single tuple-struct-like variant with no fields.
enum E6 {
    V1 (),
}
/// An enum with no variants.
enum E7 {}

assert_eq!(0, size_of::<()>());
assert_eq!(0, size_of::<!>());
assert_eq!(0, size_of_val(&f));
assert_eq!(0, size_of_val(&S));
assert_eq!(0, size_of_val(&E::V));
assert_eq!(0, size_of::<UnitLike>());
assert_eq!(0, size_of::<NoFields>());
assert_eq!(0, size_of::<OnlyZST>());
assert_eq!(0, size_of::<C1>());
assert_eq!(0, size_of::<C2>());
assert_eq!(0, size_of::<T1>());
assert_eq!(0, size_of::<T2>());
assert_eq!(0, size_of::<[(); 10]>());
assert_eq!(0, size_of::<[u8; 0]>());
assert_eq!(0, size_of::<U>());
assert_eq!(0, size_of::<E2>());
assert_eq!(0, size_of::<E3>());
assert_eq!(0, size_of::<E4>());
assert_eq!(0, size_of::<E5>());
assert_eq!(0, size_of::<E6>());
assert_eq!(0, size_of::<E7>());
// `PhantomData` for a ZST.
assert_eq!(0, size_of::<PhantomData<()>>());
// `PhantomData` for a type that is not a ZST.
assert_eq!(0, size_of::<PhantomData<u16>>());
