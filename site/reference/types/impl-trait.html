    [type.impl-trait]

    Impl trait

    [type.impl-trait.syntax]

    Syntax
    ImplTraitType → impl Bounds?

    ImplTraitTypeOneBound → impl TraitBound?

    [type.impl-trait.intro]

    impl Trait راه‌هایی برای مشخص‌کردن نوع‌های نام‌ندار اما عینی فراهم می‌کند که صفت مشخصی را پیاده‌سازی می‌کنند. این نحو در دو نوع موقعیت ظاهر می‌شود: موقعیت آرگومان، که می‌تواند مانند پارامتر نوع بی‌نام برای تابع‌ها عمل کند؛ و موقعیت بازگشت، که می‌تواند نوع بازگشت انتزاعی باشد.

    trait Trait {}
impl Trait for () {}

// argument position: anonymous type parameter
fn foo(arg: impl Trait) {
}

// return position: abstract return type
fn bar() -> impl Trait {
}
    [type.impl-trait.bounds]

    باید دست‌کم یک کران صفت وجود داشته باشد و بیش از یک کران use<..> یا بیش از یک کران انصرافی (مانند ?Sized) مجاز نیست.

    [type.impl-trait.param]

    پارامترهای نوع بی‌نام

    [type.impl-trait.param.intro]

    Note

    نکته این حالت اغلب «impl Trait در موقعیت آرگومان» نامیده می‌شود. اصطلاح «پارامتر» در اینجا دقیق‌تر است، اما عبارت «impl Trait در موقعیت آرگومان» هنگام توسعهٔ این قابلیت به‌کار رفته و هنوز در بخش‌هایی از پیاده‌سازی باقی مانده است.

    تابع‌ها می‌توانند با impl و سپس مجموعه‌ای از کران‌های صفت، پارامتری با نوع بی‌نام اعلان کنند. فراخواننده باید نوعی فراهم کند که کران‌های اعلان‌شده توسط پارامتر نوع بی‌نام را برآورده کند و تابع تنها می‌تواند متدهای در دسترس از طریق کران‌های صفت همان پارامتر را به‌کار ببرد.

    برای مثال، دو شکل زیر تقریباً معادل‌اند:

    trait Trait {}

// generic type parameter
fn with_generic_type<T: Trait>(arg: T) {
}

// impl Trait in argument position
fn with_impl_trait(arg: impl Trait) {
}
    [type.impl-trait.param.generic]

    یعنی impl Trait در موقعیت آرگومان، شکل کوتاه نحوی یک پارامتر نوع عمومی مانند <T: Trait> است؛ با این تفاوت که نوع بی‌نام است و در فهرست GenericParams ظاهر نمی‌شود.

    Note

    نکته برای پارامترهای تابع، پارامترهای نوع عمومی و impl Trait دقیقاً معادل نیستند. با پارامتر عمومی‌ای مانند <T: Trait>، فراخواننده می‌تواند آرگومان عمومی T را با GenericArgs در محل فراخوانی به‌صراحت مشخص کند؛ برای مثال foo::<usize>(1). تغییر یک پارامتر از یکی از این دو شکل به دیگری می‌تواند تغییری ناسازگار برای فراخوانندگان تابع باشد، زیرا تعداد آرگومان‌های عمومی را تغییر می‌دهد.

    [type.impl-trait.return]

    نوع‌های بازگشت انتزاعی

    [type.impl-trait.return.intro]

    Note

    نکته این حالت اغلب «impl Trait در موقعیت بازگشت» نامیده می‌شود.

    تابع‌ها می‌توانند برای بازگرداندن نوع بازگشت انتزاعی از impl Trait استفاده کنند. این نوع‌ها جانشین نوع عینی دیگری می‌شوند که فراخواننده تنها می‌تواند متدهای اعلان‌شده توسط Trait مشخص‌شده را روی آن به‌کار ببرد.

    [type.impl-trait.return.constraint-body]

    هر مقدار بازگشت ممکن از تابع باید به یک نوع عینی یکسان تفکیک شود.

    impl Trait در موقعیت بازگشت به تابع اجازه می‌دهد نوعی انتزاعی و بدون Box برگرداند. این قابلیت به‌ویژه برای بستارها و تکرارگرها سودمند است. برای مثال، بستارها نوعی یکتا دارند که قابل نوشتن نیست. پیش‌تر تنها راه بازگرداندن بستار از یک تابع، استفاده از شیء صفت بود:

    fn returns_closure() -> Box<dyn Fn(i32) -> i32> {
    Box::new(|x| x + 1)
}

    این روش ممکن بود به‌دلیل تخصیص heap و اعزام پویا هزینهٔ کارایی داشته باشد. مشخص‌کردن کامل نوع بستار ممکن نبود و تنها می‌شد از صفت Fn استفاده کرد؛ پس شیء صفت ضروری بود. اما با impl Trait می‌توان آن را ساده‌تر نوشت:

    fn returns_closure() -> impl Fn(i32) -> i32 {
    |x| x + 1
}

    این شکل معایب شیء صفت Boxشده را نیز ندارد.

    به‌همین ترتیب، نوع عینی تکرارگرها ممکن است بسیار پیچیده شود و نوع همهٔ تکرارگرهای پیشین در یک زنجیره را دربرگیرد. بازگرداندن impl Iterator یعنی تابع به‌جای مشخص‌کردن صریح همهٔ نوع‌های تکرارگر درگیر، تنها صفت Iterator را به‌عنوان کران نوع بازگشت آشکار می‌کند.

    [type.impl-trait.return-in-trait]

    impl Trait در موقعیت بازگشت صفت‌ها و پیاده‌سازی صفت‌ها

    [type.impl-trait.return-in-trait.intro]

    تابع‌های درون صفت‌ها نیز می‌توانند از impl Trait به‌عنوان نحو یک نوع وابستهٔ بی‌نام استفاده کنند.

    [type.impl-trait.return-in-trait.desugaring]

    هر impl Trait در نوع بازگشت یک تابع وابسته در صفت، به یک نوع وابستهٔ بی‌نام تبدیل می‌شود. نوع بازگشتی که در امضای تابع پیاده‌سازی ظاهر می‌شود، مقدار آن نوع وابسته را تعیین می‌کند.

    [type.impl-trait.generic-captures]

    تسخیر

    پشت هر نوع انتزاعی impl Trait در موقعیت بازگشت، نوعی عینی و پنهان وجود دارد. برای اینکه این نوع عینی از یک پارامتر عمومی استفاده کند، نوع انتزاعی باید آن پارامتر عمومی را تسخیر کند.

    [type.impl-trait.generic-capture.auto]

    تسخیر خودکار

    [type.impl-trait.generic-capture.auto.intro]

    نوع‌های انتزاعی impl Trait در موقعیت بازگشت، همهٔ پارامترهای عمومی موجود در حوزه را به‌طور خودکار تسخیر می‌کنند؛ از جمله پارامترهای نوع، const و طول‌عمر عمومی، حتی موارد رتبه‌بالاتر.

    [type.impl-trait.generic-capture.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴، در تابع‌های آزاد و تابع‌ها و متدهای وابستهٔ implهای ذاتی، پارامترهای طول‌عمر عمومی که در کران‌های نوع بازگشت انتزاعی ظاهر نمی‌شدند، به‌طور خودکار تسخیر نمی‌شدند.

    [type.impl-trait.generic-capture.precise]

    تسخیر دقیق

    [type.impl-trait.generic-capture.precise.use]

    مجموعهٔ پارامترهای عمومی تسخیرشده توسط نوع انتزاعی impl Trait در موقعیت بازگشت را می‌توان با یک کران use<..> به‌صراحت کنترل کرد. در صورت وجود این کران، تنها پارامترهای عمومی فهرست‌شده در کران use<..> تسخیر می‌شوند. برای مثال:

    fn capture<'a, 'b, T>(x: &'a (), y: T) -> impl Sized + use<'a, T> {
  //                                      ~~~~~~~~~~~~~~~~~~~~~~~
  //                                     Captures `'a` and `T` only.
  (x, y)
}
    [type.impl-trait.generic-capture.precise.constraint-single]

    در حال حاضر، تنها یک کران use<..> می‌تواند در فهرست کران‌ها وجود داشته باشد؛ همهٔ پارامترهای عمومی نوع و const موجود در حوزه باید در آن گنجانده شوند؛ و همهٔ پارامترهای طول‌عمری که در دیگر کران‌های نوع انتزاعی ظاهر می‌شوند نیز باید در آن قرار گیرند.

    [type.impl-trait.generic-capture.precise.constraint-lifetime]

    درون کران use<..>، همهٔ پارامترهای طول‌عمر باید پیش از پارامترهای عمومی نوع و const بیایند. طول‌عمر حذف‌شده ('_) نیز در صورتی مجاز است که در نوع بازگشت impl Trait امکان ظاهرشدن داشته باشد.

    [type.impl-trait.generic-capture.precise.constraint-param-impl-trait]

    چون همهٔ پارامترهای نوع موجود در حوزه باید با نام درج شوند، کران use<..> را نمی‌توان در امضای آیتم‌هایی به‌کار برد که از impl Trait در موقعیت آرگومان استفاده می‌کنند؛ زیرا این آیتم‌ها پارامترهای نوع بی‌نام در حوزه دارند.

    [type.impl-trait.generic-capture.precise.constraint-in-trait]

    هر کران use<..> موجود در یک تابع وابسته در تعریف صفت باید همهٔ پارامترهای عمومی صفت، از جمله پارامتر نوع عمومی ضمنی Self آن صفت را دربرگیرد.

    تفاوت عمومی‌ها و impl Trait در موقعیت بازگشت

    در موقعیت آرگومان، impl Trait از نظر معنایی بسیار شبیه پارامتر نوع عمومی است. اما در موقعیت بازگشت تفاوت‌های مهمی میان آن دو وجود دارد. با impl Trait برخلاف پارامتر نوع عمومی، تابع نوع بازگشت را انتخاب می‌کند و فراخواننده نمی‌تواند آن را انتخاب کند.

    تابع زیر:

    trait Trait {}
fn foo<T: Trait>() -> T {
    // ...
panic!()
}

    به فراخواننده اجازه می‌دهد نوع بازگشت T را تعیین کند و تابع همان نوع را برمی‌گرداند.

    تابع زیر:

    trait Trait {}
impl Trait for () {}
fn foo() -> impl Trait {
    // ...
}

    به فراخواننده اجازهٔ تعیین نوع بازگشت را نمی‌دهد. در عوض، تابع نوع بازگشت را انتخاب می‌کند و تنها تعهد می‌دهد که آن نوع Trait را پیاده‌سازی خواهد کرد.

    [type.impl-trait.constraint]

    محدودیت‌ها

    impl Trait تنها می‌تواند به‌عنوان پارامتر یا نوع بازگشت یک تابع غیر-extern ظاهر شود. نمی‌تواند نوع یک اتصال let یا فیلد باشد یا درون نام مستعار نوع ظاهر شود.
