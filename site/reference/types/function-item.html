    [type.fn-item]

    نوع‌های آیتم تابع

    [type.fn-item.intro]

    وقتی به یک آیتم تابع یا سازندهٔ یک struct تاپل‌مانند یا واریانت enum اشاره شود، مقداری با اندازهٔ صفر از نوع آیتم تابع آن تولید می‌شود.

    [type.fn-item.unique]

    این نوع، خود تابع—نام، آرگومان‌های نوع و آرگومان‌های lifetime زودمقید آن، اما نه lifetimeهای دیرمقید که فقط هنگام فراخوانی تعیین می‌شوند—را صریحاً مشخص می‌کند. بنابراین مقدار به نگهداری اشاره‌گر واقعی تابع نیاز ندارد و فراخوانی تابع نیز بدون indirection انجام می‌شود.

    [type.fn-item.name]

    نحوی برای اشارهٔ مستقیم به نوع آیتم تابع وجود ندارد، اما کامپایلر در پیام خطا آن را شبیه fn(u32) -> i32 {fn_name} نمایش می‌دهد.

    چون نوع آیتم تابع، تابع را صریحاً مشخص می‌کند، نوع آیتم تابع‌های متفاوت—یا یک آیتم یکسان با genericهای متفاوت—متمایز است و ترکیب آن‌ها خطای نوع ایجاد می‌کند:

    fn foo<T>() { }
let x = &mut foo::<i32>;
*x = foo::<u32>; //~ ERROR mismatched types
    [type.fn-item.coercion]

    بااین‌حال، آیتم تابع می‌تواند به اشاره‌گر تابع دارای همان امضا وادار شود. این تبدیل نه‌فقط هنگامی رخ می‌دهد که مستقیماً اشاره‌گر تابع انتظار می‌رود، بلکه زمانی نیز رخ می‌دهد که نوع‌های متفاوت آیتم تابع با امضای یکسان در بازوهای مختلف یک if یا match قرار گیرند:

    let want_i32 = false;
fn foo<T>() { }

// `foo_ptr_1` has function pointer type `fn()` here
let foo_ptr_1: fn() = foo::<i32>;

// ... and so does `foo_ptr_2` - this type-checks.
let foo_ptr_2 = if want_i32 {
    foo::<i32>
} else {
    foo::<u32>
};
    [type.fn-item.traits]

    همهٔ آیتم‌های تابع Copy، ‏Clone، ‏Send و Sync را پیاده‌سازی می‌کنند.

    Traitهای Fn، ‏FnMut و FnOnce نیز پیاده‌سازی می‌شوند، مگر آنکه تابع یکی از موارد زیر را داشته باشد:

    • مشخص‌کنندهٔ unsafe
    • یک ویژگی target_feature
    • یک ABI غیر از "Rust"
