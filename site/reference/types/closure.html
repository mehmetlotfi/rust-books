    [type.closure]

    نوع‌های بستار

    [type.closure.intro]

    یک عبارت بستار مقداری بستار با نوعی یکتا و ناشناس تولید می‌کند که نمی‌توان آن را نوشت. نوع بستار تقریباً معادل ساختاری است که مقدارهای ثبت‌شده را در خود نگه می‌دارد. برای نمونه، بستار زیر:

    #[derive(Debug)]
struct Point { x: i32, y: i32 }
struct Rectangle { left_top: Point, right_bottom: Point }

fn f<F : FnOnce() -> String> (g: F) {
    println!("{}", g());
}

let mut rect = Rectangle {
    left_top: Point { x: 1, y: 1 },
    right_bottom: Point { x: 0, y: 0 }
};

let c = || {
    rect.left_top.x += 1;
    rect.right_bottom.x += 1;
    format!("{:?}", rect.left_top)
};
f(c); // Prints "Point { x: 2, y: 1 }".

    تقریباً نوع بستار زیر را تولید می‌کند:

    // Note: This is not exactly how it is translated, this is only for
// illustration.

struct Closure<'a> {
    left_top : &'a mut Point,
    right_bottom_x : &'a mut i32,
}

impl<'a> FnOnce<()> for Closure<'a> {
    type Output = String;
    extern "rust-call" fn call_once(self, args: ()) -> String {
        self.left_top.x += 1;
        *self.right_bottom_x += 1;
        format!("{:?}", self.left_top)
    }
}

    در نتیجه، فراخوانی f چنان کار می‌کند که گویی چنین نوشته شده است:

    f(Closure{ left_top: &mut rect.left_top, right_bottom_x: &mut rect.right_bottom.x });
    [type.closure.capture]

    شیوه‌های ثبت

    [type.closure.capture.intro]

    شیوهٔ ثبت تعیین می‌کند یک عبارت مکان از محیط چگونه وام گرفته یا به درون بستار منتقل شود. شیوه‌های ثبت عبارت‌اند از:

    1. وام‌گیری تغییرناپذیر (ImmBorrow) — عبارت مکان به‌صورت یک ارجاع مشترک ثبت می‌شود.
    2. وام‌گیری تغییرناپذیر یکتا (UniqueImmBorrow) — شبیه وام‌گیری تغییرناپذیر است، اما باید مطابق توضیح پایین یکتا باشد.
    3. وام‌گیری تغییرپذیر (MutBorrow) — عبارت مکان به‌صورت ارجاع تغییرپذیر ثبت می‌شود.
    4. انتقال (ByValue) — عبارت مکان با انتقال مقدار به درون بستار ثبت می‌شود.
    [type.closure.capture.precedence]

    عبارت‌های مکان محیط با نخستین شیوه‌ای ثبت می‌شوند که با چگونگی استفاده از مقدار ثبت‌شده در بدنهٔ بستار سازگار باشد. کد پیرامون بستار، مانند طول عمر متغیرها یا فیلدهای درگیر یا طول عمر خود بستار، بر این شیوه اثری ندارد.

    [type.closure.capture.copy]

    مقدارهای Copy

    مقدارهایی که Copy را پیاده‌سازی می‌کنند و درون بستار منتقل می‌شوند، با شیوهٔ ImmBorrow ثبت می‌شوند.

    let x = [0; 1024];
let c = || {
    let y = x; // x captured by ImmBorrow
};
    [type.closure.async.input]

    ثبت ورودی Async

    بستارهای Async همیشه همهٔ آرگومان‌های ورودی را ثبت می‌کنند، چه در بدنه استفاده شوند چه نشوند.

    دقت تسخیر (Capture precision)

    [type.closure.capture.precision.capture-path]

    مسیر ثبت دنباله‌ای است که با متغیری از محیط آغاز می‌شود و صفر یا چند تصویر مکان از آن متغیر در پی دارد.

    [type.closure.capture.precision.place-projection]

    یک تصویر مکان (place projection) عبارتی است از نوع دسترسی به فیلد، اندیس چندتایی، ارجاع‌زدایی (و ارجاع‌زدایی‌های خودکار)، اندیس آرایه یا slice یا تجزیهٔ الگو که روی یک متغیر اعمال شده باشد.

    Note

    نکته در rustc، ساختارشکنی الگو به دنباله‌ای از ارجاع‌زدایی‌ها و دسترسی به فیلد یا عنصر نحوگشایی می‌شود.

    [type.closure.capture.precision.intro]

    بستار مسیر ثبت را وام می‌گیرد یا منتقل می‌کند؛ این مسیر ممکن است مطابق قواعد زیر کوتاه شود.

    برای نمونه:

    struct SomeStruct {
    f1: (i32, i32),
}
let s = SomeStruct { f1: (1, 2) };

let c = || {
    let x = s.f1.1; // s.f1.1 captured by ImmBorrow
};
c();

    در اینجا مسیر ثبت با متغیر محلی s آغاز می‌شود، دسترسی فیلد .f1 و سپس اندیس چندتایی .1 را در پی دارد. این بستار یک وام‌گیری تغییرناپذیر از s.f1.1 ثبت می‌کند.

    [type.closure.capture.precision.shared-prefix]

    پیشوند مشترک

    اگر هم یک مسیر ثبت و هم یکی از نیاکان آن مسیر در بستار ثبت شوند، مسیر نیای آن دو با بالاترین شیوهٔ ثبت میانشان ثبت می‌شود: CaptureMode = max(AncestorCaptureMode, DescendantCaptureMode)، مطابق ترتیب ضعیف سخت‌گیرانهٔ زیر:

    ImmBorrow < UniqueImmBorrow < MutBorrow < ByValue

    ممکن است لازم باشد این قاعده بازگشتی اعمال شود.

    // In this example, there are three different capture paths with a shared ancestor:
fn move_value<T>(_: T){}
let s = String::from("S");
let t = (s, String::from("T"));
let mut u = (t, String::from("U"));

let c = || {
    println!("{:?}", u); // u captured by ImmBorrow
    u.1.truncate(0); // u.1 captured by MutBorrow
    move_value(u.0.0); // u.0.0 captured by ByValue
};
c();

    در مجموع، این بستار u را با ByValue ثبت می‌کند.

    [type.closure.capture.precision.dereference-shared]

    کوتاه‌سازی در راست‌ترین ارجاع مشترک

    اگر ارجاع‌زدایی روی یک ارجاع مشترک اعمال شده باشد، مسیر ثبت در راست‌ترین ارجاع‌زدایی کوتاه می‌شود.

    این کوتاه‌سازی مجاز است زیرا فیلدهایی که از راه ارجاع مشترک خوانده می‌شوند، همیشه از راه ارجاع مشترک یا یک کپی خوانده خواهند شد. وقتی دقت بیشتر از دید بررسی وام سودی ندارد، این کار اندازهٔ ثبت را کاهش می‌دهد.

    دلیل انتخاب راست‌ترین ارجاع‌زدایی، جلوگیری از طول عمر کوتاه‌تر از نیاز است. نمونهٔ زیر را در نظر بگیرید:

    struct Int(i32);
struct B<'a>(&'a i32);

struct MyStruct<'a> {
   a: &'static Int,
   b: B<'a>,
}

fn foo<'a, 'b>(m: &'a MyStruct<'b>) -> impl FnMut() + 'static {
    let c = || drop(&m.a.0);
    c
}

    اگر m ثبت می‌شد، بستار دیگر بیشتر از 'static عمر نمی‌کرد، چون m به 'a محدود است. در عوض، (*(*m).a) با ImmBorrow ثبت می‌شود.

    [type.closure.capture.precision.wildcard]

    مقیدسازی الگوی نویسهٔ عام

    [type.closure.capture.precision.wildcard.reads]

    بستارها تنها داده‌ای را ثبت می‌کنند که باید خوانده شود. مقیدکردن مقدار با الگوی نویسهٔ عام مقدار را نمی‌خواند، پس مکان ثبت نمی‌شود.

    struct S; // A non-`Copy` type.
let x = S;
let c = || {
    let _ = x;  // Does not capture `x`.
};
let c = || match x {
    _ => (), // Does not capture `x`.
};
x; // OK: `x` can be moved here.
c();
    [type.closure.capture.precision.wildcard.destructuring]

    ساختارشکنی چندتایی‌ها، ساختارها و برشمردنی‌های تک‌گونه‌ای به‌خودی‌خود باعث خواندن یا ثبت مکان نمی‌شود.

    Note

    نکته برشمردنی‌های علامت‌خورده با #[non_exhaustive] همیشه چندگونه‌ای در نظر گرفته می‌شوند. بخش type.closure.capture.precision.discriminants.non_exhaustive را ببینید.

    struct S; // A non-`Copy` type.

// Destructuring tuples does not cause a read or capture.
let x = (S,);
let c = || {
    let (..) = x; // Does not capture `x`.
};
x; // OK: `x` can be moved here.
c();

// Destructuring unit structs does not cause a read or capture.
let x = S;
let c = || {
    let S = x; // Does not capture `x`.
};
x; // OK: `x` can be moved here.
c();

// Destructuring structs does not cause a read or capture.
struct W<T>(T);
let x = W(S);
let c = || {
    let W(..) = x; // Does not capture `x`.
};
x; // OK: `x` can be moved here.
c();

// Destructuring single-variant enums does not cause a read
// or capture.
enum E<T> { V(T) }
let x = E::V(S);
let c = || {
    let E::V(..) = x; // Does not capture `x`.
};
x; // OK: `x` can be moved here.
c();
    [type.closure.capture.precision.wildcard.fields]

    فیلدهایی که با RestPattern یعنی .. یا StructPatternEtCetera که آن هم .. است تطبیق می‌یابند، خوانده و ثبت نمی‌شوند.

    struct S; // A non-`Copy` type.
let x = (S, S);
let c = || {
    let (x0, ..) = x;  // Captures `x.0` by `ByValue`.
};
// Only the first tuple field was captured by the closure.
x.1; // OK: `x.1` can be moved here.
c();
    [type.closure.capture.precision.wildcard.array-slice]

    ثبت جزئی آرایه‌ها و برش‌ها پشتیبانی نمی‌شود؛ حتی هنگام استفاده از تطبیق الگوی نویسهٔ عام، اندیس‌گذاری یا زیربرش، همیشه کل برش یا آرایه ثبت می‌شود.

    struct S; // A non-`Copy` type.
let mut x = [S, S];
let c = || {
    let [x0, _] = x; // Captures all of `x` by `ByValue`.
};
let _ = &mut x[1]; // ERROR: Borrow of moved value.
    [type.closure.capture.precision.wildcard.initialized]

    مقدارهایی که با نویسهٔ عام تطبیق داده می‌شوند همچنان باید مقداردهی اولیه شده باشند.

    let x: u8;
let c = || {
    let _ = x; // ERROR: Binding `x` isn't initialized.
};
    [type.closure.capture.precision.discriminants]

    ثبت برای خواندن ممیز

    [type.closure.capture.precision.discriminants.reads]

    اگر تطبیق الگو ممیزی را بخواند، مکانی که ممیز را در خود دارد با ImmBorrow ثبت می‌شود.

    [type.closure.capture.precision.discriminants.multiple-variant]

    تطبیق با گونه‌ای از برشمردنی چندگونه‌ای، ممیز را می‌خواند و مکان را با ImmBorrow ثبت می‌کند.

    struct S; // A non-`Copy` type.
let mut x = (Some(S), S);
let c = || match x {
    (None, _) => (),
//   ^^^^
// This pattern requires reading the discriminant, which
// causes `x.0` to be captured by `ImmBorrow`.
    _ => (),
};
let _ = &mut x.0; // ERROR: Cannot borrow `x.0` as mutable.
//           ^^^
// The closure is still live, so `x.0` is still immutably
// borrowed here.
c();
    struct S; // A non-`Copy` type.
let x = (Some(S), S);
let c = || match x { // Captures `x.0` by `ImmBorrow`.
    (None, _) => (),
    _ => (),
};
// Though `x.0` is captured due to the discriminant read,
// `x.1` is not captured.
x.1; // OK: `x.1` can be moved here.
c();
    [type.closure.capture.precision.discriminants.single-variant]

    تطبیق با تنها گونهٔ یک برشمردنی تک‌گونه‌ای ممیز را نمی‌خواند و مکان را ثبت نمی‌کند.

    enum E<T> { V(T) } // A single-variant enum.
let x = E::V(());
let c = || {
    let E::V(_) = x; // Does not capture `x`.
};
x; // OK: `x` can be moved here.
c();
    [type.closure.capture.precision.discriminants.non_exhaustive]

    اگر #[non_exhaustive] روی برشمردنی اعمال شده باشد، برای تصمیم‌گیری دربارهٔ رخ‌دادن خواندن، آن برشمردنی چندگونه‌ای در نظر گرفته می‌شود؛ حتی اگر واقعاً تنها یک گونه داشته باشد.

    [type.closure.capture.precision.discriminants.uninhabited-variants]

    حتی اگر همهٔ گونه‌ها جز گونهٔ مورد تطبیق غیرقابل‌سکونت باشند و الگو را انکارناپذیر کنند، اگر در شرایط عادی ممیز خوانده می‌شد، همچنان خوانده می‌شود.

    let mut x = Ok::<_, !>(42);
let c = || {
    let Ok(_) = x; // Captures `x` by `ImmBorrow`.
};
let _ = &mut x; // ERROR: Cannot borrow `x` as mutable.
c();
    [type.closure.capture.precision.range-patterns]

    ثبت و الگوهای بازه

    [type.closure.capture.precision.range-patterns.reads]

    تطبیق با الگوی بازه مکان مورد تطبیق را می‌خواند و با ImmBorrow ثبت می‌کند، حتی اگر بازه همهٔ مقدارهای ممکن نوع را در بر بگیرد.

    let mut x = 0u8;
let c = || {
    let 0..=u8::MAX = x; // Captures `x` by `ImmBorrow`.
};
let _ = &mut x; // ERROR: Cannot borrow `x` as mutable.
c();
    [type.closure.capture.precision.slice-patterns]

    ثبت و الگوهای برش

    [type.closure.capture.precision.slice-patterns.slices]

    تطبیق یک برش با الگوی برش غیر از الگویی که تنها یک الگوی باقی‌مانده دارد، یعنی [..]، به‌صورت خواندن طول از برش در نظر گرفته می‌شود و برش را با ImmBorrow ثبت می‌کند.

    let x: &mut [u8] = &mut [];
let c = || match x { // Captures `*x` by `ImmBorrow`.
    &mut [] => (),
//       ^^
// This matches a slice of exactly zero elements. To know whether the
// scrutinee matches, the length must be read, causing the slice to
// be captured.
    _ => (),
};
let _ = &mut *x; // ERROR: Cannot borrow `*x` as mutable.
c();
    let x: &mut [u8] = &mut [];
let c = || match x { // Does not capture `*x`.
    [..] => (),
//   ^^ Rest pattern.
};
let _ = &mut *x; // OK
c();

    Note

    نکته شاید شگفت‌آور باشد که با وجود قرارداشتن طول در اشاره‌گر پهن برش، مکان مقصد اشاره‌گر یعنی خود برش، خوانده‌شده و ثبت‌شده در نظر گرفته می‌شود.

    fn f<'l: 's, 's>(x: &'s mut &'l [u8]) -> impl Fn() + 'l {
    // The closure outlives `'l` because it captures `**x`. If
    // instead it captured `*x`, it would not live long enough
    // to satisfy the `impl Fn() + 'l` bound.
    || match *x { // Captures `**x` by `ImmBorrow`.
        &[] => (),
        _ => (),
    }
}

    به این ترتیب، رفتار با ارجاع‌زدایی تا خود برش در عبارت مورد تطبیق سازگار است.

    fn f<'l: 's, 's>(x: &'s mut &'l [u8]) -> impl Fn() + 'l {
    || match **x { // Captures `**x` by `ImmBorrow`.
        [] => (),
        _ => (),
    }
}

    برای جزئیات، PR شمارهٔ ۱۳۸۹۶۱ Rust را ببینید.

    [type.closure.capture.precision.slice-patterns.arrays]

    چون طول آرایه با نوع آن ثابت می‌شود، تطبیق آرایه با الگوی برش به‌خودی‌خود مکان را ثبت نمی‌کند.

    let x: [u8; 1] = [0];
let c = || match x { // Does not capture `x`.
    [_] => (), // Length is fixed.
};
x; // OK: `x` can be moved here.
c();
    [type.closure.capture.precision.move-dereference]

    ثبت ارجاع‌ها در بافت انتقال

    چون انتقال فیلدها از درون ارجاع مجاز نیست، بستارهای move تنها پیشوندی از مسیر ثبت را می‌گیرند که تا پیش از نخستین ارجاع‌زدایی یک ارجاع ادامه دارد؛ خود ارجاع به درون بستار منتقل می‌شود.

    struct T(String, String);

let mut t = T(String::from("foo"), String::from("bar"));
let t_mut_ref = &mut t;
let mut c = move || {
    t_mut_ref.0.push_str("123"); // captures `t_mut_ref` ByValue
};
c();
    [type.closure.capture.precision.raw-pointer-dereference]

    ارجاع‌زدایی اشاره‌گر خام

    چون ارجاع‌زدایی اشاره‌گر خام unsafe است، بستارها تنها پیشوندی از مسیر ثبت را می‌گیرند که تا پیش از نخستین ارجاع‌زدایی اشاره‌گر خام ادامه دارد.

    struct T(String, String);

let t = T(String::from("foo"), String::from("bar"));
let t_ptr = &t as *const T;

let c = || unsafe {
    println!("{}", (*t_ptr).0); // captures `t_ptr` by ImmBorrow
};
c();
    [type.closure.capture.precision.union]

    فیلدهای اجتماع

    چون دسترسی به فیلد اجتماع unsafe است، بستارها تنها پیشوندی از مسیر ثبت را می‌گیرند که تا خود اجتماع ادامه دارد.

    union U {
    a: (i32, i32),
    b: bool,
}
let u = U { a: (123, 456) };

let c = || {
    let x = unsafe { u.a.0 }; // captures `u` ByValue
};
c();

// This also includes writing to fields.
let mut u = U { a: (123, 456) };

let mut c = || {
    u.b = true; // captures `u` with MutBorrow
};
c();
    [type.closure.capture.precision.unaligned]

    ارجاع به درون structهای ناهم‌تراز

    چون ساخت ارجاع به فیلدهای ناهم‌تراز یک ساختار رفتار تعریف‌نشده است، بستارها تنها پیشوندی از مسیر ثبت را می‌گیرند که تا پیش از نخستین دسترسی به فیلد ساختاری با نمایش packed ادامه دارد. این قاعده همهٔ فیلدها، حتی فیلدهای هم‌تراز، را در بر می‌گیرد تا اگر هر فیلدی از ساختار در آینده تغییر کرد، مشکلات سازگاری ایجاد نشود.

    #[repr(packed)]
struct T(i32, i32);

let t = T(2, 5);
let c = || {
    let a = t.0; // captures `t` with ImmBorrow
};
// Copies out of `t` are ok.
let (a, b) = (t.0, t.1);
c();

    به همین شکل، گرفتن آدرس فیلد ناهم‌تراز نیز کل ساختار را ثبت می‌کند:

    #[repr(packed)]
struct T(String, String);

let mut t = T(String::new(), String::new());
let c = || {
    let a = std::ptr::addr_of!(t.1); // captures `t` with ImmBorrow
};
let a = t.0; // ERROR: cannot move out of `t.0` because it is borrowed
c();

    اما اگر ساختار packed نباشد، کد بالا کار می‌کند، زیرا فیلد به‌دقت ثبت می‌شود:

    struct T(String, String);

let mut t = T(String::new(), String::new());
let c = || {
    let a = std::ptr::addr_of!(t.1); // captures `t.1` with ImmBorrow
};
// The move here is allowed.
let a = t.0;
c();
    [type.closure.capture.precision.box-deref]

    Box در برابر دیگر پیاده‌سازی‌های Deref

    پیاده‌سازی صفت Deref برای Box متفاوت با دیگر پیاده‌سازی‌های Deref رفتار می‌کند، زیرا موجودیتی ویژه در نظر گرفته می‌شود.

    برای نمونه، مثال‌های شامل Rc و Box را ببینید. عبارت *rc به فراخوانی متد صفت deref تعریف‌شده روی Rc نحوگشایی می‌شود؛ اما چون با *box متفاوت رفتار می‌شود، ثبت دقیق محتوای Box امکان‌پذیر است.

    [type.closure.capture.precision.box-non-move.not-moved]

    Box با بستار غیر move

    در یک بستار غیر move، اگر محتوای Box به بدنهٔ بستار منتقل نشود، محتوای Box دقیقاً تسخیر می‌شود.

    struct S(String);

let b = Box::new(S(String::new()));
let c_box = || {
    let x = &(*b).0; // captures `(*b).0` by ImmBorrow
};
c_box();

// Contrast `Box` with another type that implements Deref:
let r = std::rc::Rc::new(S(String::new()));
let c_rc = || {
    let x = &(*r).0; // captures `r` by ImmBorrow
};
c_rc();
    [type.closure.capture.precision.box-non-move.moved]

    اما اگر محتوای Box به درون بستار منتقل شود، کل box ثبت می‌شود. این کار برای کمینه‌کردن مقدار داده‌ای است که باید به درون بستار منتقل شود.

    // This is the same as the example above except the closure
// moves the value instead of taking a reference to it.

struct S(String);

let b = Box::new(S(String::new()));
let c_box = || {
    let x = (*b).0; // captures `b` with ByValue
};
c_box();
    [type.closure.capture.precision.box-move.read]

    Box با بستار move

    همانند انتقال محتوای Box در بستار غیر move، خواندن محتوای Box در بستار move کل Box را ثبت می‌کند.

    struct S(i32);

let b = Box::new(S(10));
let c_box = move || {
    let x = (*b).0; // captures `b` with ByValue
};
    [type.closure.unique-immutable]

    وام‌گیری‌های تغییرناپذیر یکتا در ثبت‌ها

    ثبت می‌تواند با گونهٔ ویژه‌ای از وام به نام وام‌گیری تغییرناپذیر یکتا انجام شود که در هیچ جای دیگر زبان قابل استفاده نیست و نمی‌توان آن را صراحتاً نوشت. این حالت هنگام تغییر مقصد یک ارجاع تغییرپذیر رخ می‌دهد، مانند نمونهٔ زیر:

    let mut b = false;
let x = &mut b;
let mut c = || {
    // An ImmBorrow and a MutBorrow of `x`.
    let a = &x;
    *x = true; // `x` captured by UniqueImmBorrow
};
// The following line is an error:
// let y = &x;
c();
// However, the following is OK.
let z = &x;

    در این حالت، وام‌گرفتن تغییرپذیر x ممکن نیست، زیرا x با mut اعلان نشده است. هم‌زمان، وام‌گیری تغییرناپذیر x انتساب را غیرمجاز می‌کند، چون ارجاع & &mut ممکن است یکتا نباشد و بنابراین نمی‌توان با اطمینان از آن برای تغییر مقدار استفاده کرد. پس وام‌گیری تغییرناپذیر یکتا به کار می‌رود: x را تغییرناپذیر وام می‌گیرد، اما مانند وام‌گیری تغییرپذیر باید یکتا باشد.

    در نمونهٔ بالا، خارج‌کردن اعلان y از حالت توضیح خطا تولید می‌کند، زیرا یکتایی وام بستار از x را نقض می‌کند. اعلان z معتبر است، زیرا طول عمر بستار در پایان بلوک تمام شده و وام آزاد شده است.

    [type.closure.call]

    صفت‌های فراخوانی و وادارسازی‌ها

    [type.closure.call.intro]

    همهٔ نوع‌های بستار FnOnce را پیاده‌سازی می‌کنند؛ یعنی می‌توان آن‌ها را یک بار با مصرف مالکیت بستار فراخواند. افزون بر این، برخی بستارها صفت‌های فراخوانی خاص‌تری را پیاده‌سازی می‌کنند:

    [type.closure.call.fn-mut]
    • بستاری که هیچ متغیر ثبت‌شده‌ای را به بیرون منتقل نمی‌کند، FnMut را پیاده‌سازی می‌کند و با ارجاع تغییرپذیر قابل فراخوانی است.
    [type.closure.call.fn]
    • بستاری که هیچ متغیر ثبت‌شده‌ای را تغییر نمی‌دهد یا به بیرون منتقل نمی‌کند، Fn را پیاده‌سازی می‌کند و با ارجاع مشترک قابل فراخوانی است.

    Note

    نکته بستارهای move با وجود ثبت متغیرها به‌صورت انتقال، ممکن است همچنان Fn یا FnMut را پیاده‌سازی کنند. صفت‌های پیاده‌سازی‌شده برای نوع بستار بر اساس کاری تعیین می‌شوند که بستار با مقدارهای ثبت‌شده انجام می‌دهد، نه شیوهٔ ثبت آن‌ها.

    [type.closure.non-capturing]

    بستارهای بدون ثبت چیزی از محیط خود ثبت نمی‌کنند. بستارهای غیر async و بدون ثبت را می‌توان به اشاره‌گر تابعی با امضای متناظر، مانند fn()، وادار کرد.

    let add = |x, y| x + y;

let mut x = add(5,7);

type Binop = fn(i32, i32) -> i32;
let bo: Binop = add;
x = bo(5,7);
    [type.closure.async.traits]

    صفت‌های بستار Async

    [type.closure.async.traits.fn-family]

    بستارهای Async محدودیت دیگری نیز دارند که آیا FnMut یا Fn را پیاده‌سازی می‌کنند یا نه.

    [Future] برگشتی از بستار async ویژگی‌های ثبت مشابه بستار دارد. این Future عبارت‌های مکان را بر پایهٔ چگونگی استفاده در بستار async ثبت می‌کند. اگر یکی از ویژگی‌های زیر برقرار باشد، گفته می‌شود بستار async به Future خود وام می‌دهد:

    • Future یک ثبت تغییرپذیر داشته باشد.
    • بستار async مقداری را به‌صورت انتقال ثبت کند، مگر هنگامی که مقدار با تصویر ارجاع‌زدایی در دسترس قرار گرفته باشد.

    اگر بستار async به Future خود وام دهد، FnMut و Fn پیاده‌سازی نمی‌شوند. FnOnce همیشه پیاده‌سازی می‌شود.

    نمونه: بند نخست دربارهٔ ثبت تغییرپذیر را می‌توان با نمونهٔ زیر نشان داد:

    fn takes_callback<Fut: Future>(c: impl FnMut() -> Fut) {}

fn f() {
    let mut x = 1i32;
    let c = async || {
        x = 2;  // x captured with MutBorrow
    };
    takes_callback(c);  // ERROR: async closure does not implement `FnMut`
}

    بند دوم دربارهٔ ثبت مقدار عادی را می‌توان با نمونهٔ زیر نشان داد:

    fn takes_callback<Fut: Future>(c: impl Fn() -> Fut) {}

fn f() {
    let x = &1i32;
    let c = async move || {
        let a = x + 2;  // x captured ByValue
    };
    takes_callback(c);  // ERROR: async closure does not implement `Fn`
}

    استثنای بند دوم با استفاده از ارجاع‌زدایی نشان داده می‌شود که اجازهٔ پیاده‌سازی Fn و FnMut را می‌دهد:

    fn takes_callback<Fut: Future>(c: impl Fn() -> Fut) {}

fn f() {
    let x = &1i32;
    let c = async move || {
        let a = *x + 2;
    };
    takes_callback(c);  // OK: implements `Fn`
}
    [type.closure.async.traits.async-family]

    بستارهای Async به‌شکلی مشابه پیاده‌سازی Fn، FnMut و FnOnce در بستارهای عادی، AsyncFn، AsyncFnMut و AsyncFnOnce را پیاده‌سازی می‌کنند؛ یعنی بر پایهٔ استفاده از متغیرهای ثبت‌شده در بدنه.

    [type.closure.traits]

    صفت‌های دیگر

    [type.closure.traits.intro]

    همهٔ نوع‌های بستار Sized را پیاده‌سازی می‌کنند. افزون بر آن، اگر نوع ثبت‌های ذخیره‌شده اجازه دهد، نوع بستار صفت‌های زیر را پیاده‌سازی می‌کند:

    • Clone
    • Copy
    • Sync
    • Send
    [type.closure.traits.behavior]

    قواعد Send و Sync با ساختارهای عادی یکسان‌اند، در حالی که Clone و Copy چنان رفتار می‌کنند که گویی مشتق شده‌اند. برای Clone ترتیب همتاسازی مقدارهای ثبت‌شده مشخص نشده است.

    چون ثبت‌ها اغلب با ارجاع انجام می‌شوند، قواعد کلی زیر به دست می‌آیند:

    • بستار زمانی Sync است که همهٔ مقدارهای ثبت‌شده Sync باشند.
    • بستار زمانی Send است که همهٔ مقدارهای ثبت‌شده با ارجاع تغییرناپذیر غیر یکتا Sync و همهٔ مقدارهای ثبت‌شده با ارجاع تغییرناپذیر یکتا یا تغییرپذیر، کپی یا انتقال Send باشند.
    • بستار زمانی Clone یا Copy است که هیچ مقداری را با ارجاع تغییرناپذیر یکتا یا تغییرپذیر ثبت نکرده باشد و همهٔ مقدارهایی که با کپی یا انتقال ثبت می‌کند به‌ترتیب Clone یا Copy باشند.
    [type.closure.drop-order]

    ترتیب رهاسازی

    اگر بستاری فیلدی از نوع مرکب مانند ساختار، چندتایی یا برشمردنی را به‌صورت مقدار ثبت کند، طول عمر فیلد به بستار گره می‌خورد. در نتیجه، فیلدهای جدا از هم در یک نوع مرکب ممکن است در زمان‌های متفاوت رها شوند.

    {
    let tuple =
      (String::from("foo"), String::from("bar")); // --+
    { //                                               |
        let c = || { // ----------------------------+  |
            // tuple.0 is captured into the closure |  |
            drop(tuple.0); //                       |  |
        }; //                                       |  |
    } // 'c' and 'tuple.0' dropped here ------------+  |
} // tuple.1 dropped here -----------------------------+
    [type.closure.capture.precision.edition2018.entirety]

    ویرایش ۲۰۱۸ و پیش از آن

    تفاوت نوع‌های بستار

    در ویرایش ۲۰۱۸ و پیش از آن، بستارها همیشه متغیر را به‌طور کامل و بدون مسیر ثبت دقیق آن ثبت می‌کنند. یعنی در نمونهٔ بخش نوع‌های بستار، نوع بستار تولیدشده در عوض چیزی شبیه این است:

    struct Closure<'a> {
    rect : &'a mut Rectangle,
}

impl<'a> FnOnce<()> for Closure<'a> {
    type Output = String;
    extern "rust-call" fn call_once(self, args: ()) -> String {
        self.rect.left_top.x += 1;
        self.rect.right_bottom.x += 1;
        format!("{:?}", self.rect.left_top)
    }
}

    و فراخوانی f این‌گونه کار می‌کند:

    f(Closure { rect: rect });
    [type.closure.capture.precision.edition2018.composite]

    تفاوت در دقت تسخیر

    نوع‌های مرکب مانند ساختارها، چندتایی‌ها و برشمردنی‌ها همیشه به‌طور کامل ثبت می‌شوند، نه بر پایهٔ فیلدهای جداگانه. در نتیجه شاید لازم باشد برای ثبت یک فیلد، آن را در متغیری محلی وام گرفت:

    use std::collections::HashSet;

struct SetVec {
    set: HashSet<u32>,
    vec: Vec<u32>
}

impl SetVec {
    fn populate(&mut self) {
        let vec = &mut self.vec;
        self.set.iter().for_each(|&n| {
            vec.push(n);
        })
    }
}

    اگر بستار مستقیماً از self.vec استفاده می‌کرد، می‌کوشید self را با ارجاع تغییرپذیر ثبت کند. اما چون self.set از پیش برای پیمایش وام گرفته شده است، کد کامپایل نمی‌شد.

    [type.closure.capture.precision.edition2018.move]

    اگر کلیدواژهٔ move استفاده شود، همهٔ ثبت‌ها—یا برای نوع‌های Copy، کپی‌ها—به‌صورت انتقال انجام می‌شوند، حتی اگر وام‌گیری کار کند. move معمولاً برای این به کار می‌رود که بستار بتواند بیشتر از مقدارهای ثبت‌شده عمر کند، مانند زمانی که بستار برگردانده می‌شود یا برای ایجاد ریسمانی تازه به کار می‌رود.

    [type.closure.capture.precision.edition2018.wildcard]

    صرف‌نظر از اینکه بستار داده را بخواند یا نه، مثلاً در الگوهای نویسهٔ عام، اگر متغیری تعریف‌شده بیرون بستار درون آن نام برده شود، متغیر به‌طور کامل ثبت خواهد شد.

    [type.closure.capture.precision.edition2018.drop-order]

    تفاوت ترتیب رهاسازی

    چون نوع‌های مرکب به‌طور کامل ثبت می‌شوند، بستاری که یکی از آن‌ها را به‌صورت مقدار ثبت کند، هم‌زمان با رهاشدن بستار کل متغیر ثبت‌شده را رها خواهد کرد.

    {
    let tuple =
      (String::from("foo"), String::from("bar"));
    {
        let c = || { // --------------------------+
            // tuple is captured into the closure |
            drop(tuple.0); //                     |
        }; //                                     |
    } // 'c' and 'tuple' dropped here ------------+
}
