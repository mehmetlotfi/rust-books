    [type.trait-object.intro]

    یک شیء صفت (trait object) مقداری کدر از نوعی دیگر است که مجموعه‌ای از صفت‌ها (trait) را پیاده‌سازی می‌کند. این مجموعه از یک صفت پایه سازگار با dyn به‌همراه هر تعداد صفت خودکار تشکیل می‌شود.

    [type.trait-object.impls]

    شیءهای صفت، صفت پایه، صفت‌های خودکار آن و هر یک از فراصفت‌های صفت پایه را پیاده‌سازی می‌کنند.

    [type.trait-object.bounds]

    باید دست‌کم یک کران صفت وجود داشته باشد؛ بیش از یک صفت غیرخودکار و بیش از یک طول‌عمر مجاز نیست، و کران‌های انصرافی (مانند ?Sized) و کران‌های use<..> نیز مجاز نیستند.

    برای مثال، با داشتن صفت Trait، همهٔ موارد زیر شیء صفت هستند:

    • dyn Trait
    • dyn Trait + Send
    • dyn Trait + Send + Sync
    • dyn Trait + 'static
    • dyn Trait + Send + 'static
    • dyn Trait +
    • dyn 'static + Trait.
    • dyn (Trait)
    [type.trait-object.syntax-edition2021]

    تفاوت‌های ویرایش 2021 پیش از ویرایش ۲۰۲۱، می‌شد کلیدواژهٔ dyn را حذف کرد. در ویرایش ۲۰۲۱ و پس از آن، وجود کلیدواژهٔ dyn از نظر معنایی الزامی است.

    [type.trait-object.syntax-edition2018]

    تفاوت‌های ویرایش 2018 در ویرایش ۲۰۱۵، برای اینکه dyn به‌جای یک شناسهٔ عادی به‌عنوان کلیدواژه تفسیر شود، باید پس از آن PathIdentSegment، ‏LIFETIME_TOKEN، ‏for، ‏( یا ? بیاید.

    مهم‌تر از همه، dyn، ‏dyn::T و dyn<T> همگی به‌عنوان مسیر نوع در نظر گرفته می‌شوند. بنابراین اگر یک نوع شیء صفت با صفت ::module::Trait می‌خواهید، باید مسیر را داخل پرانتز قرار دهید و آن را به‌شکل dyn (::module::Trait) بنویسید.

    از ویرایش ۲۰۱۸ به بعد، dyn یک کلیدواژهٔ واقعی است و در مسیرها مجاز نیست؛ بنابراین پرانتزها دیگر ضروری نیستند.

    [type.trait-object.alias]

    دو نوع شیء صفت زمانی نام مستعار یکدیگرند که صفت‌های پایهٔ آن‌ها نام مستعار یکدیگر باشند، مجموعهٔ صفت‌های خودکارشان یکسان باشد و کران‌های طول‌عمر یکسانی داشته باشند. برای مثال، dyn Trait + Send + UnwindSafe همان dyn Trait + UnwindSafe + Send است.

    [type.trait-object.unsized]

    از آنجا که نوع عینی مقدار نامشخص و کدر است، شیءهای صفت نوع‌هایی با اندازهٔ پویا هستند. مانند همهٔ DSTها، شیءهای صفت پشت نوعی اشاره‌گر استفاده می‌شوند؛ برای مثال &dyn SomeTrait یا Box<dyn SomeTrait>. هر نمونه از یک اشاره‌گر به شیء صفت شامل این موارد است:

    • اشاره‌گری به نمونه‌ای از نوع T که SomeTrait را پیاده‌سازی می‌کند؛
    • یک جدول متد مجازی که معمولاً به‌اختصار vtable نامیده می‌شود و برای هر متد از SomeTrait و فراصفت‌های آن که T پیاده‌سازی می‌کند، اشاره‌گری به پیاده‌سازی T (یعنی یک اشاره‌گر تابع) در خود دارد.

    هدف شیءهای صفت، فراهم‌کردن «اتصال دیرهنگام» متدهاست. فراخوانی یک متد روی شیء صفت باعث اعزام مجازی در زمان اجرا می‌شود؛ یعنی یک اشاره‌گر تابع از vtable شیء صفت بارگذاری و به‌طور غیرمستقیم فراخوانی می‌شود. پیاده‌سازی واقعی هر ورودی vtable می‌تواند برای هر شیء متفاوت باشد.

    نمونه‌ای از یک شیء صفت:

    trait Printable {
    fn stringify(&self) -> String;
}

impl Printable for i32 {
    fn stringify(&self) -> String { self.to_string() }
}

fn print(a: Box<dyn Printable>) {
    println!("{}", a.stringify());
}

fn main() {
    print(Box::new(10) as Box<dyn Printable>);
}

    در این مثال، صفت Printable هم در امضای نوع print و هم در عبارت تبدیل نوع در main به‌صورت شیء صفت ظاهر می‌شود.

    [type.trait-object.lifetime-bounds]

    کران‌های طول‌عمر شیء صفت

    چون یک شیء صفت می‌تواند حاوی ارجاع باشد، طول‌عمر آن ارجاع‌ها باید به‌عنوان بخشی از شیء صفت بیان شود. این طول‌عمر به‌شکل Trait + 'a نوشته می‌شود. مقادیر پیش‌فرضی وجود دارند که معمولاً اجازه می‌دهند این طول‌عمر با انتخابی معقول استنتاج شود.
