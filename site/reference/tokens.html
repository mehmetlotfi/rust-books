    توکن‌ها تولیدهای ابتدایی در دستور زبان‌اند که با زبان‌های منظم و غیربازگشتی تعریف می‌شوند. ورودی منبع Rust را می‌توان به گونه‌های توکن زیر شکست:

    • کلیدواژه‌ها
    • کلیدواژه‌ها
    • لیترال‌ها
    • طول عمرها
    • نشانه‌گذاری
    • جداکننده‌ها

    در دستور زبان این مستندات، توکن‌های «ساده» به‌شکل تولید جدول رشته نوشته و با قلم monospace نمایش داده می‌شوند.

    پسوندها

    [lex.token.literal.literal.suffix.intro]

    پسوند دنباله‌ای از نویسه‌ها پس از بخش اصلی لیترال و بدون فاصلهٔ سفید میان آن‌هاست که همان شکل شناسهٔ غیرخام یا کلیدواژه را دارد.

    [lex.token.literal.suffix.syntax]

    Lexer
    SUFFIX →
          _ ^ XID_Continue+
        | XID_Start XID_Continue*

    [lex.token.literal.suffix.validity]

    هر گونه لیترال، مانند رشته یا عدد صحیح، با هر پسوندی به‌عنوان توکن معتبر است.

    توکن لیترال با هر پسوندی را می‌توان بدون خطا به ماکرو فرستاد. خود ماکرو تصمیم می‌گیرد توکن را چگونه تفسیر کند و خطا بدهد یا نه. به‌طور خاص، مشخص‌کنندهٔ قطعهٔ literal در ماکروهای مبتنی بر مثال با توکن‌های لیترال دارای پسوند دلخواه تطبیق می‌یابد.

    macro_rules! blackhole { ($tt:tt) => () }
macro_rules! blackhole_lit { ($l:literal) => () }

blackhole!("string"suffix); // OK
blackhole_lit!(1suffix); // OK
    [lex.token.literal.suffix.parse]

    با این حال، پسوندهای توکن‌های لیترال که به‌صورت عبارت یا الگوی لیترال تفسیر می‌شوند محدودند. همهٔ پسوندها روی توکن‌های لیترال غیرعددی رد می‌شوند و توکن‌های عددی تنها با پسوندهای جدول زیر پذیرفته می‌شوند.

    عدد صحیحممیز شناور

    لیترال‌های نویسه و رشته

    [lex.token.literal.char]

    لیترال‌های نویسه

    [lex.token.literal.char.syntax]

    Lexer
    CHAR_LITERAL →
        '
            ( ~[' \ LF CR TAB] | QUOTE_ESCAPE | ASCII_ESCAPE | UNICODE_ESCAPE )
        ' SUFFIX?

    QUOTE_ESCAPE → \' | \"

    ASCII_ESCAPE →
          \x OCT_DIGIT HEX_DIGIT
        | \n | \r | \t | \\ | \0

    UNICODE_ESCAPE →
        \u{ ( HEX_DIGIT _* )1..=6valid hex char value }​3

    [lex.token.literal.char.intro]

    لیترال نویسه یک نویسهٔ Unicode است که میان دو نویسهٔ U+0027 یعنی نقل‌قول تکی قرار دارد؛ خود U+0027 استثناست و باید با نویسهٔ پیشین U+005C یعنی \ گریز داده شود.

    [lex.token.literal.str]

    لیترال‌های رشته

    [lex.token.literal.str.syntax]

    Lexer
    STRING_LITERAL →
        " (
            ~[" \ CR]
          | QUOTE_ESCAPE
          | ASCII_ESCAPE
          | UNICODE_ESCAPE
          | STRING_CONTINUE
        )* " SUFFIX?

    STRING_CONTINUE → \ LF [TAB LF CR SP]*

    [lex.token.literal.str.intro]

    لیترال رشته دنباله‌ای از نویسه‌های Unicode میان دو نویسهٔ U+0022 یعنی نقل‌قول دوتایی است؛ خود U+0022 باید با نویسهٔ پیشین U+005C یعنی \ گریز داده شود.

    [lex.token.literal.str.linefeed]

    شکست خط که با نویسهٔ U+000A یعنی LF نمایش داده می‌شود در لیترال رشته مجاز است. نویسهٔ U+000D یعنی CR نمی‌تواند در آن ظاهر شود. اگر نویسهٔ گریزندادهٔ U+005C یعنی \ بلافاصله پیش از شکست خط بیاید، شکست خط در رشتهٔ نمایش‌داده‌شده با توکن ظاهر نمی‌شود. برای جزئیات گریزهای ادامهٔ رشته را ببینید.

    [lex.token.literal.char-escape]

    گریزهای نویسه

    [lex.token.literal.char-escape.intro]

    گریزهای افزوده‌ای در لیترال نویسه یا رشتهٔ غیرخام در دسترس‌اند. گریز با U+005C یعنی \ آغاز می‌شود و یکی از شکل‌های زیر را ادامه می‌دهد:

    [lex.token.literal.char-escape.ascii]
    • گریز نقطه‌کد ۷ بیتی با U+0078 یعنی x آغاز می‌شود و دقیقاً دو رقم شانزده‌شانزدهی با مقدار حداکثر 0x7F در پی دارد. این گریز نویسهٔ ASCII هم‌ارز مقدار داده‌شده را نشان می‌دهد. مقدارهای بالاتر مجاز نیستند، زیرا معلوم نیست منظور نقطه‌کد Unicode است یا مقدار بایت.
    [lex.token.literal.char-escape.unicode]
    • گریز نقطه‌کد ۲۴ بیتی با U+0075 یعنی u آغاز می‌شود و حداکثر شش رقم شانزده‌شانزدهی میان آکولادهای U+007B یعنی { و U+007D یعنی } دارد. این گریز نقطه‌کد Unicode هم‌ارز مقدار داده‌شده را نشان می‌دهد. مقدار باید مقدار اسکالر معتبر Unicode باشد.
    [lex.token.literal.char-escape.whitespace]
    • گریز فاصلهٔ سفید یکی از نویسه‌های U+006E یعنی n، U+0072 یعنی r یا U+0074 یعنی t است که به‌ترتیب مقدار Unicode نوع U+000A (LF)، U+000D (CR) یا U+0009 (HT) را نشان می‌دهد.
    [lex.token.literal.char-escape.null]
    • گریز تهی نویسهٔ U+0030 یعنی 0 است و مقدار Unicode نوع U+0000 (NUL) را نشان می‌دهد.
    [lex.token.literal.char-escape.slash]
    • گریز ممیز وارونه نویسهٔ U+005C یعنی \ است که برای نمایش خودش باید گریز داده شود.
    [lex.token.literal.str-raw]

    لیترال‌های رشتهٔ خام

    [lex.token.literal.str-raw.syntax]

    Lexer
    RAW_STRING_LITERAL →
          r " ^ RAW_STRING_CONTENT " SUFFIX?
        | r #n:1..=255 ^ " RAW_STRING_CONTENT_HASHED " #n SUFFIX?

    RAW_STRING_CONTENT → ( !" ~CR )*

    RAW_STRING_CONTENT_HASHED → ( !( " #n ) ~CR )*

    [lex.token.literal.str-raw.intro]

    لیترال‌های رشتهٔ خام هیچ گریزی را پردازش نمی‌کنند. آن‌ها با U+0072 یعنی r آغاز می‌شوند و پس از آن کمتر از ۲۵۶ نویسهٔ U+0023 یعنی # و یک U+0022 یعنی نقل‌قول دوتایی می‌آید.

    [lex.token.literal.str-raw.body]

    بدنهٔ رشتهٔ خام می‌تواند هر دنباله‌ای از نویسه‌های Unicode به‌جز U+000D (CR) باشد. این بدنه تنها با نویسهٔ U+0022 (نقل‌قول دوتایی) دیگری پایان می‌یابد که به‌دنبال آن همان تعداد نویسهٔ U+0023 (#) بیاید که پیش از نویسهٔ U+0022 (نقل‌قول دوتایی) آغازین آمده بودند.

    [lex.token.literal.str-raw.content]

    همهٔ نویسه‌های Unicode موجود در بدنهٔ رشتهٔ خام خودشان را نمایش می‌دهند؛ نویسه‌های U+0022 (نقل‌قول دوتایی) (مگر وقتی که پس از آن دست‌کم به همان تعداد نویسهٔ U+0023 (#) بیاید که برای آغاز لیترال رشتهٔ خام به‌کار رفته است) یا U+005C (\) هیچ معنای ویژه‌ای ندارند.

    نمونه‌های لیترال رشته:

    "foo"; r"foo";                     // foo
"\"foo\""; r#""foo""#;             // "foo"

"foo #\"# bar";
r##"foo #"# bar"##;                // foo #"# bar

"\x52"; "R"; r"R";                 // R
"\\x52"; r"\x52";                  // \x52

    لیترال‌های بایت و رشتهٔ بایتی

    [lex.token.byte]

    لیترال‌های بایت

    [lex.token.byte.syntax]

    Lexer
    BYTE_LITERAL →
        b' ^ ( ASCII_FOR_CHAR | BYTE_ESCAPE ) ' SUFFIX?

    ASCII_FOR_CHAR → ![' \ LF CR TAB] ASCII

    BYTE_ESCAPE →
          \x HEX_DIGIT HEX_DIGIT
        | \n | \r | \t | \\ | \0 | \' | \"

    [lex.token.byte.intro]

    لیترال بایت یک نویسهٔ ASCII در بازهٔ U+0000 تا U+007F یا یک گریز است که پیش از آن U+0062 یعنی b و U+0027 یعنی نقل‌قول تکی و پس از آن U+0027 می‌آید. اگر U+0027 در لیترال باشد، باید با U+005C یعنی \ گریز داده شود. این لیترال معادل یک لیترال عددی صحیح ۸ بیتی بدون علامت u8 است.

    [lex.token.str-byte]

    لیترال‌های رشتهٔ بایتی

    [lex.token.str-byte.syntax]

    Lexer
    BYTE_STRING_LITERAL →
        b" ^ ( ASCII_FOR_STRING | BYTE_ESCAPE | STRING_CONTINUE )* " SUFFIX?

    ASCII_FOR_STRING → ![" \ CR] ASCII

    [lex.token.str-byte.intro]

    یک لیترال رشتهٔ بایتی غیرخام دنباله‌ای از نویسه‌های ASCII و گریزها است که پیش از آن نویسه‌های U+0062 (b) و U+0022 (نقل‌قول دوتایی) و پس از آن نویسهٔ U+0022 قرار دارد. اگر نویسهٔ U+0022 درون لیترال وجود داشته باشد، باید با نویسهٔ U+005C (\) پیش از آن گریز داده شود. به‌عنوان جایگزین، یک لیترال رشتهٔ بایتی می‌تواند یک لیترال رشتهٔ بایتی خام باشد که در ادامه تعریف شده است.

    [lex.token.str-byte.linefeed]

    شکست‌های خط، که با نویسهٔ U+000A (LF) نمایش داده می‌شوند، در لیترال‌های رشتهٔ بایتی مجازند. نویسهٔ U+000D (CR) نباید در لیترال رشتهٔ بایتی ظاهر شود. هنگامی که یک نویسهٔ U+005C (\) گریزنداده بلافاصله پیش از یک شکست خط بیاید، آن شکست خط در رشته‌ای که توکن نمایش می‌دهد ظاهر نمی‌شود. برای جزئیات گریزهای ادامهٔ رشته را ببینید.

    [lex.token.str-byte.escape]

    گریزهای افزوده‌ای در لیترال بایت یا رشتهٔ بایتی غیرخام در دسترس‌اند. گریز با U+005C یعنی \ آغاز می‌شود و یکی از شکل‌های زیر را ادامه می‌دهد:

    [lex.token.str-byte.escape-byte]
    • گریز بایت با U+0078 یعنی x و دقیقاً دو رقم شانزده‌شانزدهی پس از آن آغاز می‌شود و بایت هم‌ارز مقدار داده‌شده را نشان می‌دهد.
    [lex.token.str-byte.escape-whitespace]
    • یک گریز فاصلهٔ سفید یکی از نویسه‌های U+006E (n)، U+0072 (r) یا U+0074 (t) است که به‌ترتیب مقدارهای بایت 0x0A (ASCII LF)، 0x0D (ASCII CR) یا 0x09 (ASCII HT) را نشان می‌دهد.
    [lex.token.str-byte.escape-null]
    • گریز تهی نویسهٔ U+0030 (0) است و مقدار بایت 0x00 (ASCII NUL) را نشان می‌دهد.
    [lex.token.str-byte.escape-slash]
    • گریز ممیز وارونه نویسهٔ U+005C (\) است که برای نمایش کدگذاری ASCII آن، یعنی 0x5C، باید گریز داده شود.
    [lex.token.str-byte-raw]

    لیترال‌های رشتهٔ بایتی خام

    [lex.token.str-byte-raw.syntax]

    Lexer
    RAW_BYTE_STRING_LITERAL →
          br " ^ RAW_BYTE_STRING_CONTENT " SUFFIX?
        | br #n:1..=255 ^ " RAW_BYTE_STRING_CONTENT_HASHED " #n SUFFIX?

    RAW_BYTE_STRING_CONTENT → ( !" ASCII_FOR_RAW )*

    RAW_BYTE_STRING_CONTENT_HASHED → ( !( " #n ) ASCII_FOR_RAW )*

    ASCII_FOR_RAW → !CR ASCII

    [lex.token.str-byte-raw.intro]

    لیترال‌های رشتهٔ بایتی خام هیچ گریزی را پردازش نمی‌کنند. این لیترال‌ها با نویسهٔ U+0062 (b)، سپس U+0072 (r)، سپس کمتر از ۲۵۶ نویسهٔ U+0023 (#) و یک نویسهٔ U+0022 (نقل‌قول دوتایی) آغاز می‌شوند.

    [lex.token.str-byte-raw.body]

    بدنهٔ رشتهٔ خام می‌تواند هر دنباله‌ای از نویسه‌های ASCII به‌جز U+000D (CR) باشد. این بدنه تنها با نویسهٔ U+0022 (نقل‌قول دوتایی) دیگری پایان می‌یابد که به‌دنبال آن همان تعداد نویسهٔ U+0023 (#) بیاید که پیش از نویسهٔ U+0022 (نقل‌قول دوتایی) آغازین آمده بودند. یک لیترال رشتهٔ بایتی خام نمی‌تواند هیچ بایت غیر ASCII داشته باشد.

    [lex.token.literal.str-byte-raw.content]

    همهٔ نویسه‌های موجود در بدنهٔ رشتهٔ خام کدگذاری ASCII خودشان را نمایش می‌دهند؛ نویسه‌های U+0022 (نقل‌قول دوتایی) (مگر وقتی که پس از آن دست‌کم به همان تعداد نویسهٔ U+0023 (#) بیاید که برای آغاز لیترال رشتهٔ خام به‌کار رفته است) یا U+005C (\) هیچ معنای ویژه‌ای ندارند.

    نمونه‌های لیترال رشتهٔ بایتی:

    b"foo"; br"foo";                     // foo
b"\"foo\""; br#""foo""#;             // "foo"

b"foo #\"# bar";
br##"foo #"# bar"##;                 // foo #"# bar

b"\x52"; b"R"; br"R";                // R
b"\\x52"; br"\x52";                  // \x52

    لیترال‌های رشتهٔ C و رشتهٔ خام C

    [lex.token.str-c]

    لیترال‌های رشتهٔ C

    [lex.token.str-c.syntax]

    Lexer
    C_STRING_LITERAL →
        c" ^ (
            ~[" \ CR NUL]
          | !( \0 | \x00 ) BYTE_ESCAPE
          | !( \u{ ( 0 _* )1..=6 } ) UNICODE_ESCAPE
          | STRING_CONTINUE
        )* " SUFFIX?

    [lex.token.str-c.intro]

    یک لیترال رشتهٔ C دنباله‌ای از نویسه‌های Unicode و گریزها است که پیش از آن نویسه‌های U+0063 (c) و U+0022 (نقل‌قول دوتایی) و پس از آن نویسهٔ U+0022 قرار دارد. اگر نویسهٔ U+0022 درون لیترال وجود داشته باشد، باید با نویسهٔ U+005C (\) پیش از آن گریز داده شود. به‌عنوان جایگزین، یک لیترال رشتهٔ C می‌تواند یک لیترال رشتهٔ C خام باشد که در ادامه تعریف شده است.

    [lex.token.str-c.null]

    رشته‌های C به‌طور ضمنی با بایت 0x00 پایان می‌یابند؛ بنابراین لیترال c"" معادل ساخت دستی &CStr از لیترال بایتی b"\x00" است. به‌جز پایان‌دهندهٔ ضمنی، بایت 0x00 درون رشتهٔ C مجاز نیست.

    [lex.token.str-c.linefeed]

    شکست‌های خط، که با نویسهٔ U+000A (LF) نمایش داده می‌شوند، در لیترال‌های رشتهٔ C مجازند. نویسهٔ U+000D (CR) نباید در لیترال رشتهٔ C ظاهر شود. هنگامی که یک نویسهٔ U+005C (\) گریزنداده بلافاصله پیش از یک شکست خط بیاید، آن شکست خط در رشته‌ای که توکن نمایش می‌دهد ظاهر نمی‌شود. برای جزئیات گریزهای ادامهٔ رشته را ببینید.

    [lex.token.str-c.escape]

    در لیترال‌های رشتهٔ C غیرخام، برخی گریزهای اضافی نیز در دسترس‌اند. یک گریز با نویسهٔ U+005C (\) آغاز می‌شود و با یکی از شکل‌های زیر ادامه می‌یابد:

    [lex.token.str-c.escape-byte]
    • یک گریز بایت با نویسهٔ U+0078 (x) آغاز می‌شود و دقیقاً دو رقم شانزده‌شانزدهی (hex) پس از آن می‌آید. این گریز بایتی را نشان می‌دهد که برابر مقدار شانزده‌شانزدهی داده‌شده است.
    [lex.token.str-c.escape-unicode]
    • یک گریز نقطه‌کد ۲۴ بیتی با نویسهٔ U+0075 (u) آغاز می‌شود و حداکثر شش رقم شانزده‌شانزدهی پس از آن می‌آید که میان آکولادهای U+007B ({) و U+007D (}) قرار گرفته‌اند. این گریز نقطه‌کد Unicode برابر با مقدار شانزده‌شانزدهی داده‌شده را نشان می‌دهد که با UTF-8 کدگذاری شده است.
    [lex.token.str-c.escape-whitespace]
    • یک گریز فاصلهٔ سفید یکی از نویسه‌های U+006E (n)، U+0072 (r) یا U+0074 (t) است که به‌ترتیب مقدارهای بایت 0x0A (ASCII LF)، 0x0D (ASCII CR) یا 0x09 (ASCII HT) را نشان می‌دهد.
    [lex.token.str-c.escape-slash]
    • گریز ممیز وارونه نویسهٔ U+005C (\) است که برای نمایش کدگذاری ASCII آن، یعنی 0x5C، باید گریز داده شود.
    [lex.token.str-c.char-unicode]

    رشتهٔ C بایت‌هایی بدون کدگذاری تعریف‌شده را نمایش می‌دهد، اما لیترال رشتهٔ C می‌تواند نویسه‌های Unicode بالاتر از U+007F داشته باشد. چنین نویسه‌هایی با بایت‌های نمایش UTF-8 خود جایگزین می‌شوند.

    لیترال‌های رشتهٔ C زیر معادل‌اند:

    c"æ";        // LATIN SMALL LETTER AE (U+00E6)
c"\u{00E6}";
c"\xC3\xA6";
    [lex.token.str-c.edition2021]

    تفاوت‌های ویرایش 2021 لیترال‌های رشتهٔ C در ویرایش ۲۰۲۱ و پس از آن پذیرفته می‌شوند. در ویرایش‌های پیشین، توکن c"" به‌صورت c "" توکن‌بندی می‌شود.

    [lex.token.str-c-raw]

    لیترال‌های رشتهٔ خام C

    [lex.token.str-c-raw.syntax]

    Lexer
    RAW_C_STRING_LITERAL →
          cr " ^ RAW_C_STRING_CONTENT " SUFFIX?
        | cr #n:1..=255 ^ " RAW_C_STRING_CONTENT_HASHED " #n SUFFIX?

    RAW_C_STRING_CONTENT → ( !" ~[CR NUL] )*

    RAW_C_STRING_CONTENT_HASHED → ( !( " #n ) ~[CR NUL] )*

    [lex.token.str-c-raw.intro]

    لیترال‌های رشتهٔ C خام هیچ گریزی را پردازش نمی‌کنند. این لیترال‌ها با نویسهٔ U+0063 (c)، سپس U+0072 (r)، سپس کمتر از ۲۵۶ نویسهٔ U+0023 (#) و یک نویسهٔ U+0022 (نقل‌قول دوتایی) آغاز می‌شوند.

    [lex.token.str-c-raw.body]

    بدنهٔ رشتهٔ C خام می‌تواند هر دنباله‌ای از نویسه‌های Unicode به‌جز U+0000 (NUL) و U+000D (CR) باشد. این بدنه تنها با نویسهٔ U+0022 (نقل‌قول دوتایی) دیگری پایان می‌یابد که به‌دنبال آن همان تعداد نویسهٔ U+0023 (#) بیاید که پیش از نویسهٔ U+0022 (نقل‌قول دوتایی) آغازین آمده بودند.

    [lex.token.str-c-raw.content]

    همهٔ نویسه‌های موجود در بدنهٔ رشتهٔ C خام خودشان را با کدگذاری UTF-8 نمایش می‌دهند. نویسه‌های U+0022 (نقل‌قول دوتایی) (مگر وقتی که پس از آن دست‌کم به همان تعداد نویسهٔ U+0023 (#) بیاید که برای آغاز لیترال رشتهٔ C خام به‌کار رفته است) یا U+005C (\) هیچ معنای ویژه‌ای ندارند.

    [lex.token.str-c-raw.edition2021]

    تفاوت‌های ویرایش 2021 لیترال‌های رشتهٔ خام C در ویرایش ۲۰۲۱ و پس از آن پذیرفته می‌شوند. در ویرایش‌های پیشین cr"" به‌صورت cr "" و cr#""# به‌صورت cr #""# توکن‌بندی می‌شود که از نظر دستوری نامعتبر است.

    نمونه‌های رشتهٔ C و رشتهٔ خام C

    c"foo"; cr"foo";                     // foo
c"\"foo\""; cr#""foo""#;             // "foo"

c"foo #\"# bar";
cr##"foo #"# bar"##;                 // foo #"# bar

c"\x52"; c"R"; cr"R";                // R
c"\\x52"; cr"\x52";                  // \x52
    [lex.token.literal.num]

    لیترال‌های عددی

    لیترال عددی یا لیترال عدد صحیح است یا لیترال ممیز شناور. دستور زبان تشخیص این دو گونه با هم ترکیب شده است.

    [lex.token.literal.int]

    لیترال‌های عدد صحیح

    [lex.token.literal.int.syntax]

    Lexer
    INTEGER_LITERAL →
        ( BIN_LITERAL | OCT_LITERAL | HEX_LITERAL | DEC_LITERAL )
        ^ !RESERVED_FLOAT SUFFIX?

    DEC_LITERAL → DEC_DIGIT ( DEC_DIGIT | _ )*

    BIN_LITERAL → 0b ^ _* BIN_DIGIT ( BIN_DIGIT | _ )* ![e E 2-9]

    OCT_LITERAL → 0o ^ _* OCT_DIGIT ( OCT_DIGIT | _ )* ![e E 8-9]

    HEX_LITERAL → 0x ^ _* HEX_DIGIT ( HEX_DIGIT | _ )*

    BIN_DIGIT → [0-1]

    OCT_DIGIT → [0-7]

    DEC_DIGIT → [0-9]

    HEX_DIGIT → [0-9 a-f A-F]

    RESERVED_FLOAT → . !( . | _ | XID_Start )

    [lex.token.literal.int.kind]

    لیترال عدد صحیح یکی از چهار شکل زیر را دارد:

    [lex.token.literal.int.kind-dec]
    • لیترال ده‌دهی با رقم ده‌دهی آغاز می‌شود و با هر ترکیبی از رقم‌های ده‌دهی و زیرخط ادامه می‌یابد.
    [lex.token.literal.int.kind-hex]
    • یک لیترال شانزده‌شانزدهی با دنبالهٔ نویسه‌های U+0030 U+0078 (0x) آغاز می‌شود و با هر ترکیبی (با دست‌کم یک رقم) از رقم‌های شانزده‌شانزدهی و زیرخط ادامه می‌یابد.
    [lex.token.literal.int.kind-oct]
    • یک لیترال هشت‌هشتی با دنبالهٔ نویسه‌های U+0030 U+006F (0o) آغاز می‌شود و با هر ترکیبی (با دست‌کم یک رقم) از رقم‌های هشت‌هشتی و زیرخط ادامه می‌یابد.
    [lex.token.literal.int.kind-bin]
    • یک لیترال دودویی با دنبالهٔ نویسه‌های U+0030 U+0062 (0b) آغاز می‌شود و با هر ترکیبی (با دست‌کم یک رقم) از رقم‌های دودویی و زیرخط ادامه می‌یابد.
    [lex.token.literal.int.suffix]

    مانند هر لیترال دیگری، لیترال عدد صحیح می‌تواند بی‌درنگ و بدون فاصله پسوندی مطابق توضیح بالا داشته باشد. پسوند نمی‌تواند با e یا E آغاز شود، زیرا به‌عنوان توان لیترال ممیز شناور تفسیر خواهد شد. برای اثر این پسوندها عبارت‌های لیترال عدد صحیح را ببینید.

    نمونه‌های لیترال عدد صحیح پذیرفته‌شده به‌عنوان عبارت لیترال:

    #![allow(overflowing_literals)]
123;
123i32;
123u32;
123_u32;

0xff;
0xff_u8;
0x01_f32; // integer 7986, not floating-point 1.0
0x01_e3;  // integer 483, not floating-point 1000.0

0o70;
0o70_i16;

0b1111_1111_1001_0000;
0b1111_1111_1001_0000i64;
0b________1;

0usize;

// These are too big for their type, but are accepted as literal expressions.
128_i8;
256_u8;

// This is an integer literal, accepted as a floating-point literal expression.
5f32;

    توجه کنید برای نمونه -1i8 به‌صورت دو توکن تحلیل می‌شود: - و سپس 1i8.

    نمونه‌های لیترال عدد صحیح که به‌عنوان عبارت لیترال پذیرفته نمی‌شوند:

    #[cfg(false)] {
0invalidSuffix;
123AFB43;
0b010a;
0xAB_CD_EF_GH;
0b1111_f32;
}
    [lex.token.literal.int.invalid]
    لیترال‌های عدد صحیح نامعتبر
    [lex.token.literal.int.invalid.intro]

    برخی شکل‌های لیترال عدد صحیح نامعتبرند. برای جلوگیری از ابهام، توکن‌ساز آن‌ها را رد می‌کند و به چند توکن جدا نمی‌شکند.

    0b0102;  // This is not `0b010` followed by `2`.
0o1279;  // This is not `0o127` followed by `9`.
0x80.0;  // This is not `0x80` followed by `.` and `0`.
0b101e;  // This is not a suffixed literal or `0b101` followed by `e`.
0b;      // This is not an integer literal or `0` followed by `b`.
0b_;     // This is not an integer literal or `0` followed by `b_`.
2em;     // This is not a suffixed literal or `2` followed by `em`.
2.0em;   // This is not a suffixed literal or `2.0` followed by `em`.
    [lex.token.literal.int.out-of-range]

    اگر پس از لیترال دودویی یا هشت‌هشتی بدون پسوند، بی‌فاصله رقم ده‌دهی خارج از بازهٔ مبنا بیاید، خطاست.

    [lex.token.literal.int.period]

    اگر پس از لیترال دودویی، هشت‌هشتی یا شانزده‌شانزدهی بدون پسوند، بی‌فاصله نویسهٔ نقطه بیاید، خطاست؛ با همان محدودیت‌های مربوط به چیزی که می‌تواند پس از نقطهٔ لیترال ممیز شناور بیاید.

    [lex.token.literal.int.exp]

    اگر پس از لیترال دودویی یا هشت‌هشتی بدون پسوند، بی‌فاصله e یا E بیاید، خطاست.

    [lex.token.literal.int.empty-with-radix]

    اگر پس از پیشوند مبنا و زیرخط‌های آغازین اختیاری، دست‌کم یک رقم معتبر آن مبنا نیاید، خطاست.

    [lex.token.literal.int.tuple-field]

    اندیس چندتایی

    [lex.token.literal.int.tuple-field.syntax]

    Lexer
    TUPLE_INDEX → DEC_LITERAL | BIN_LITERAL | OCT_LITERAL | HEX_LITERAL

    [lex.token.literal.int.tuple-field.intro]

    اندیس چندتایی (tuple index) برای ارجاع به فیلدهای چندتایی‌ها، ساختارهای چندتایی و گونه‌های enum چندتایی به‌کار می‌رود.

    [lex.token.literal.int.tuple-field.eq]

    اندیس‌های چندتایی مستقیماً با توکن لیترال مقایسه می‌شوند. اندیس‌های چندتایی از 0 آغاز می‌شوند و هر اندیس بعدی مقدار را به‌صورت یک مقدار ده‌دهی به اندازهٔ 1 افزایش می‌دهد. بنابراین تنها مقدارهای ده‌دهی تطبیق می‌یابند و مقدار نباید هیچ نویسهٔ پیشوند 0 اضافی داشته باشد.

    اندیس چندتایی نمی‌تواند پسوندی مانند usize داشته باشد.

    let example = ("dog", "cat", "horse");
let dog = example.0;
let cat = example.1;
// The following examples are invalid.
let cat = example.01;  // ERROR no field named `01`
let horse = example.0b10;  // ERROR no field named `0b10`
let unicorn = example.0usize; // ERROR suffixes on a tuple index are invalid
let underscore = example.0_0; // ERROR no field `0_0` on type `(&str, &str, &str)`
    [lex.token.literal.float]

    لیترال‌های ممیز شناور

    [lex.token.literal.float.syntax]

    Lexer
    FLOAT_LITERAL →
          DEC_LITERAL ( . DEC_LITERAL )? FLOAT_EXPONENT SUFFIX?
        | DEC_LITERAL . DEC_LITERAL SUFFIX?
        | DEC_LITERAL . !( . | _ | XID_Start )

    FLOAT_EXPONENT →
        ( e | E ) ^ ( + | - )? _* DEC_DIGIT ( DEC_DIGIT | _ )*

    [lex.token.literal.float.form]

    لیترال ممیز شناور یکی از دو شکل زیر را دارد:

    • یک لیترال ده‌دهی که پس از آن نویسهٔ نقطهٔ U+002E (.) می‌آید. پس از آن می‌تواند به‌صورت اختیاری لیترال ده‌دهی دیگری با یک توان اختیاری بیاید.
    • یک لیترال ده‌دهی و پس از آن یک توان.
    [lex.token.literal.float.suffix]

    مانند لیترال‌های صحیح، یک لیترال ممیز شناور می‌تواند پسوند داشته باشد، مشروط بر آنکه بخش پیش از پسوند به U+002E (.) ختم نشود. اگر لیترال شامل توان نباشد، پسوند نباید با e یا E آغاز شود. برای اثر این پسوندها عبارت‌های لیترال ممیز شناور را ببینید.

    نمونه‌هایی از لیترال‌های ممیز شناور که به‌عنوان عبارت لیترال پذیرفته می‌شوند:

    123.0f64;
0.1f64;
0.1f32;
12E+99_f64;
let x: f64 = 2.;

    نمونهٔ آخر متفاوت است، زیرا نحو پسوند را نمی‌توان با لیترال ممیز شناوری که به نقطه پایان می‌یابد به کار برد. 2.f64 تلاش می‌کند متدی به نام f64 را روی 2 فراخوانی کند.

    برای نمونه -1.0 نیز به دو توکن - و 1.0 تحلیل می‌شود.

    نمونه‌هایی از لیترال‌های ممیز شناور که به‌عنوان عبارت لیترال پذیرفته نمی‌شوند:

    #[cfg(false)] {
2.0f80;
2e5f80;
2e5e6;
2.0e5e6;
1.3e10u64;
}
    [lex.token.literal.float.invalid-exponent]

    داشتن توان بدون رقم در لیترال ممیز شناور خطاست.

    2e;   // This is not a floating-point literal or `2` followed by `e`.
2.0e; // This is not a floating-point literal or `2.0` followed by `e`.

    طول عمرها و برچسب‌های حلقه

    [lex.token.life.syntax]

    Lexer
    LIFETIME_TOKEN →
          RAW_LIFETIME
        | ' IDENTIFIER_OR_KEYWORD !'

    LIFETIME_OR_LABEL →
          RAW_LIFETIME
        | ' NON_KEYWORD_IDENTIFIER !'

    RAW_LIFETIME →
        'r# ^ IDENTIFIER_OR_KEYWORD !'

    RESERVED_RAW_LIFETIME → 'r# ( _ | crate | self | Self | super ) !( ' | XID_Continue )

    [lex.token.life.intro]

    پارامترهای طول عمر و برچسب‌های حلقه از توکن‌های LIFETIME_OR_LABEL استفاده می‌کنند. واژه‌کاو هر LIFETIME_TOKEN را می‌پذیرد و برای نمونه می‌توان آن را در ماکروها به کار برد.

    [lex.token.life.raw.intro]

    یک طول عمر خام (raw lifetime) مانند یک طول عمر معمولی است، اما شناسهٔ آن با پیشوند r# همراه است. (توجه کنید که پیشوند r# بخشی از خود طول عمر محسوب نمی‌شود.)

    [lex.token.life.raw.allowed]

    برخلاف طول عمر عادی، طول عمر خام می‌تواند هر کلیدواژهٔ سخت‌گیرانه یا رزروشده‌ای جز موارد فهرست‌شده برای RAW_LIFETIME باشد.

    [lex.token.life.raw.reserved]

    استفاده از توکن RESERVED_RAW_LIFETIME خطاست.

    [lex.token.life.raw.edition2021]

    تفاوت‌های ویرایش 2021 طول عمرهای خام در ویرایش ۲۰۲۱ و پس از آن پذیرفته می‌شوند. در ویرایش‌های پیشین، توکن 'r#lt به‌صورت 'r # lt توکن‌بندی می‌شود.

    [lex.token.reserved]

    توکن‌های رزروشده

    [lex.token.reserved.intro]

    چند شکل توکن برای استفادهٔ آینده یا جلوگیری از سردرگمی رزرو شده‌اند. تطبیق ورودی منبع با یکی از این شکل‌ها خطاست.

    [lex.token.reserved.syntax]

    Lexer
    RESERVED_TOKEN →
          RESERVED_GUARDED_STRING_LITERAL
        | RESERVED_POUNDS
        | RESERVED_RAW_IDENTIFIER
        | RESERVED_RAW_LIFETIME
        | RESERVED_TOKEN_DOUBLE_QUOTE
        | RESERVED_TOKEN_LIFETIME
        | RESERVED_TOKEN_POUND
        | RESERVED_TOKEN_SINGLE_QUOTE

    [lex.token.reserved-prefix]

    پیشوندهای رزروشده

    [lex.token.reserved-prefix.syntax]

    Lexer
    RESERVED_TOKEN_DOUBLE_QUOTE →
        IDENTIFIER_OR_KEYWORDexcept b or c or r or br or cr "

    RESERVED_TOKEN_SINGLE_QUOTE →
        IDENTIFIER_OR_KEYWORDexcept b '

    RESERVED_TOKEN_POUND →
        IDENTIFIER_OR_KEYWORDexcept r or br or cr #

    RESERVED_TOKEN_LIFETIME →
        ' IDENTIFIER_OR_KEYWORDexcept r #

    [lex.token.reserved-prefix.intro]

    برخی شکل‌های واژگانی با نام پیشوندهای رزروشده برای استفادهٔ آینده رزرو شده‌اند.

    [lex.token.reserved-prefix.id]

    ورودی منبعی که در حالت عادی به‌عنوان شناسهٔ غیرخام یا کلیدواژه تفسیر می‌شد و بی‌فاصله نویسهٔ #، ' یا " پس از آن می‌آید، پیشوند رزروشده شناخته می‌شود.

    [lex.token.reserved-prefix.raw-token]

    شناسه‌های خام، لیترال‌های رشتهٔ خام و رشتهٔ بایتی خام می‌توانند # داشته باشند، اما دارای پیشوند رزروشده تفسیر نمی‌شوند.

    [lex.token.reserved-prefix.strings]

    به همین شکل، پیشوندهای r، b، br، c و cr در لیترال‌های رشتهٔ خام، بایت، رشتهٔ بایتی، رشتهٔ بایتی خام، رشتهٔ C و رشتهٔ خام C پیشوند رزروشده تفسیر نمی‌شوند.

    [lex.token.reserved-prefix.life]

    ورودی‌ای که در حالت عادی طول عمر غیرخام یا کلیدواژه تفسیر می‌شد و بی‌فاصله # پس از آن می‌آید، پیشوند طول عمر رزروشده شناخته می‌شود.

    [lex.token.reserved-prefix.edition2021]

    تفاوت‌های ویرایش 2021 از ویرایش ۲۰۲۱، واژه‌کاو پیشوندهای رزروشده را خطا گزارش می‌کند و به‌ویژه نمی‌توان آن‌ها را به ماکرو فرستاد.

    پیش از ویرایش ۲۰۲۱، واژه‌کاو پیشوندهای رزروشده را می‌پذیرد و به چند توکن تفسیر می‌کند؛ برای نمونه یک توکن شناسه یا کلیدواژه و سپس توکن #.

    نمونه‌های پذیرفته‌شده در همهٔ ویرایش‌ها:

    macro_rules! lexes {($($_:tt)*) => {}}
lexes!{a #foo}
lexes!{continue 'foo}
lexes!{match "..." {}}
lexes!{r#let#foo}         // three tokens: r#let # foo
lexes!{'prefix #lt}

    نمونه‌های پذیرفته‌شده پیش از ویرایش ۲۰۲۱ و ردشده در ویرایش‌های بعدی:

    macro_rules! lexes {($($_:tt)*) => {}}
lexes!{a#foo}
lexes!{continue'foo}
lexes!{match"..." {}}
lexes!{'prefix#lt}
    [lex.token.reserved-guards]

    نگهبان‌های رزروشده

    [lex.token.reserved-guards.syntax]

    Lexer
    RESERVED_GUARDED_STRING_LITERAL → #+ STRING_LITERAL

    RESERVED_POUNDS → #2..

    [lex.token.reserved-guards.intro]

    نگهبان‌های رزروشده نحوی برای استفادهٔ آینده‌اند و استفاده از آن‌ها خطای کامپایل تولید می‌کند.

    [lex.token.reserved-guards.string-literal]

    لیترال رشتهٔ نگهبانی‌شدهٔ رزروشده توکنی شامل یک یا چند U+0023 یعنی # است که بلافاصله یک STRING_LITERAL پس از آن می‌آید.

    [lex.token.reserved-guards.pounds]

    علامت‌های پوند رزروشده توکنی شامل دو یا چند U+0023 یعنی # است.

    [lex.token.reserved-guards.edition2024]

    تفاوت‌های ویرایش 2024 پیش از ویرایش ۲۰۲۴، واژه‌کاو نگهبان‌های رزروشده را می‌پذیرد و به چند توکن تفسیر می‌کند. برای نمونه #"foo"# سه توکن و ## دو توکن تفسیر می‌شود.

    1. تعداد #ها در دو سوی یک لیترال باید برابر باشد. ↩

    2. همهٔ لیترال‌های عددی _ را به‌عنوان جداکنندهٔ دیداری می‌پذیرند: 1_234.0E+18f64 ↩

    3. نگاه کنید به lex.token.literal.char-escape.unicode. ↩
