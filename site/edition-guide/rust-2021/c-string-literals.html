    لیترال‌های رشتهٔ C

    خلاصه

    • لیترال‌هایی به شکل c"foo" یا cr"foo" یک رشته از نوع &core::ffi::CStr را نمایش می‌دهند.

    جزئیات

    از Rust 1.77 به بعد، رشته‌های C را می‌توان با سینتکس لیترال رشتهٔ C و با پیشوند c یا cr نوشت.

    پیش‌تر، تولید درست یک لیترال رشته که بتواند با APIهای C که با بایت NUL پایان می‌یابند هم‌کنش داشته باشد، چالش‌برانگیز بود. crate با نام cstr راه‌حل محبوبی بود، اما نیاز به کامپایل یک proc-macro داشت که هزینهٔ زیادی داشت. اکنون رشته‌های C را می‌توان مستقیماً با نمادگذاری سینتکس لیترال نوشت، که مقداری از نوع &core::ffi::CStr تولید می‌کند که به‌طور خودکار با بایت NUL پایان می‌یابد.

    use core::ffi::CStr;

assert_eq!(c"hello", CStr::from_bytes_with_nul(b"hello\0").unwrap());
assert_eq!(
    c"byte escapes \xff work",
    CStr::from_bytes_with_nul(b"byte escapes \xff work\0").unwrap()
);
assert_eq!(
    c"unicode escapes \u{00E6} work",
    CStr::from_bytes_with_nul(b"unicode escapes \xc3\xa6 work\0").unwrap()
);
assert_eq!(
    c"unicode characters αβγ encoded as UTF-8",
    CStr::from_bytes_with_nul(
        b"unicode characters \xce\xb1\xce\xb2\xce\xb3 encoded as UTF-8\0"
    )
    .unwrap()
);
assert_eq!(
    c"strings can continue \
        on multiple lines",
    CStr::from_bytes_with_nul(b"strings can continue on multiple lines\0").unwrap()
);

    رشته‌های C بایت NUL داخلی را مجاز نمی‌دانند (مثلاً با escape از نوع \0).

    مشابه رشته‌های معمولی، رشته‌های C نیز سینتکس «خام» (raw) را با پیشوند cr پشتیبانی می‌کنند. این رشته‌های C خام escapeهای بک‌اسلش را پردازش نمی‌کنند، که نوشتن رشته‌هایی را که شامل بک‌اسلش هستند آسان‌تر می‌کند. می‌توان با احاطه کردن نقل‌قول‌ها با نویسهٔ #، گیومهٔ دوتایی را در رشته گنجاند. می‌توان از چند نویسهٔ # برای پرهیز از ابهام با دنباله‌های داخلی "# استفاده کرد.

    assert_eq!(cr"foo", c"foo");
// Number signs can be used to embed interior double quotes.
assert_eq!(cr#""foo""#, c"\"foo\"");
// This requires two #.
assert_eq!(cr##""foo"#"##, c"\"foo\"#");
// Escapes are not processed.
assert_eq!(cr"C:\foo", c"C:\\foo");

    برای جزئیات بیشتر، مرجع Rust را ببینید.

    مهاجرت

    مهاجرت فقط برای ماکروهایی لازم است که ممکن است دنباله‌ای از توکن‌ها را فرض کرده باشند که شبیه c"…" یا cr"…" است؛ پیش از ویرایش 2021 این‌ها به دو توکن جداگانه تقسیم می‌شدند، اما در 2021 به‌صورت یک توکن واحد ظاهر می‌شوند.

    به‌عنوان بخشی از رزرو سینتکس برای ویرایش 2021، هر ورودی ماکرو که ممکن است با این مشکل روبه‌رو شود باید از طریق lint مهاجرت rust_2021_prefixes_incompatible_syntax هشدار صادر کند. برای جزئیات بیشتر به آن فصل مراجعه کنید.
