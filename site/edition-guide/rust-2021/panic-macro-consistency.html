    یکپارچگی ماکروی panic

    خلاصه

    • panic!(..) اکنون همیشه از format_args!(..) استفاده می‌کند، درست مانند println!().
    • panic!("{") دیگر پذیرفته نمی‌شود، مگر اینکه { به‌صورت {{ escape شود.
    • panic!(x) دیگر پذیرفته نمی‌شود اگر x یک لیترال رشته نباشد.
      • برای panic با یک بار داده (payload) غیررشته‌ای از std::panic::panic_any(x) استفاده کنید.
      • یا برای استفاده از پیاده‌سازی Display مربوط به x از panic!("{}", x) استفاده کنید.
    • همین موضوع دربارهٔ assert!(expr, ..) نیز صدق می‌کند.

    جزئیات

    ماکروی panic!() یکی از شناخته‌شده‌ترین ماکروهای Rust است. با این حال، چند ناهمخوانی ظریف دارد که به‌دلیل سازگاری با نسخه‌های قبلی نمی‌توانیم به‌سادگی آن‌ها را تغییر دهیم.

    // Rust 2018
panic!("{}", 1); // Ok, panics with the message "1"
panic!("{}"); // Ok, panics with the message "{}"

    ماکروی panic!() فقط زمانی از قالب‌بندی رشته استفاده می‌کند که با بیش از یک آرگومان فراخوانی شود. وقتی با یک آرگومان فراخوانی شود، حتی به آن آرگومان نگاه هم نمی‌کند.

    // Rust 2018
let a = "{";
println!(a); // Error: First argument must be a format string literal
panic!(a); // Ok: The panic macro doesn't care

    حتی غیررشته‌هایی مانند panic!(123) را نیز می‌پذیرد، که کاربرد نادری دارد و به‌ندرت مفید است، زیرا پیامی به‌طرز شگفت‌آوری بی‌فایده تولید می‌کند: panicked at 'Box<Any>'.

    این موضوع به‌ویژه زمانی که آرگومان‌های قالب ضمنی پایدار شوند مشکل‌ساز خواهد بود. آن قابلیت println!("hello {name}") را به یک میان‌بر برای println!("hello {}", name) تبدیل می‌کند. اما panic!("hello {name}") آن‌طور که انتظار می‌رود کار نخواهد کرد، چون panic!() یک آرگومان تنها را به‌عنوان رشتهٔ قالب پردازش نمی‌کند.

    برای پرهیز از این وضعیت گیج‌کننده، Rust 2021 یک ماکروی panic!() یکپارچه‌تر ارائه می‌دهد. ماکروی جدید panic!() دیگر عبارت‌های دلخواه را به‌عنوان تنها آرگومان نمی‌پذیرد. این ماکرو، درست مانند println!()، همیشه آرگومان اول را به‌عنوان رشتهٔ قالب پردازش می‌کند. از آنجا که panic!() دیگر بارهای داده دلخواه را نمی‌پذیرد، panic_any() تنها راه panic کردن با چیزی غیر از یک رشتهٔ قالب‌بندی‌شده خواهد بود.

    // Rust 2021
panic!("{}", 1); // Ok, panics with the message "1"
panic!("{}"); // Error, missing argument
panic!(a); // Error, must be a string literal

    علاوه بر این، core::panic!() و std::panic!() در Rust 2021 یکسان خواهند بود. در حال حاضر، میان این دو تفاوت‌های تاریخی وجود دارد که ممکن است هنگام روشن یا خاموش کردن #![no_std] محسوس باشند.

    مهاجرت

    یک lint با نام non_fmt_panics هر زمان که فراخوانی‌ای از panic وجود داشته باشد که از رفتاری منسوخ استفاده می‌کند و در Rust 2021 خطا خواهد داد فعال می‌شود. lint با نام non_fmt_panics از نسخهٔ 1.50 به بعد در همهٔ ویرایش‌ها به‌طور پیش‌فرض یک هشدار بوده است (و در نسخه‌های بعدی بهبودهای متعددی یافته است). اگر کد شما از قبل بدون هشدار است، پس باید از قبل برای Rust 2021 آماده باشد!

    می‌توانید کد خود را به‌طور خودکار طوری مهاجرت دهید که با ویرایش Rust 2021 سازگار شود، یا مطمئن شوید که از قبل سازگار است، با اجرای:

    cargo fix --edition

    اگر مهاجرت دستی را انتخاب کنید یا به آن نیاز داشته باشید، باید همهٔ فراخوانی‌های panic را طوری به‌روز کنید که یا از همان قالب‌بندی println استفاده کنند یا برای panic با داده‌های غیررشته‌ای از std::panic::panic_any استفاده کنند.

    برای مثال، در مورد panic!(MyStruct)، باید به استفاده از std::panic::panic_any تبدیل کنید (توجه کنید که این یک تابع است نه یک ماکرو): std::panic::panic_any(MyStruct).

    در مورد پیام‌های panic که شامل آکولاد هستند اما تعداد آرگومان‌ها نادرست است (مثلاً panic!("Some curlies: {}"))، می‌توانید با لیترال رشته panic کنید، یا با استفاده از همان سینتکس println! (یعنی panic!("{}", "Some curlies: {}")) یا با escape کردن آکولادها (یعنی panic!("Some curlies: {{}}")).
