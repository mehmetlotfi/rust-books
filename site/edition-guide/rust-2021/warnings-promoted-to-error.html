راهنمای ویرایش‌های RustThe Edition Guide

    هشدارهایی که به خطا ارتقا یافتند

    خلاصه

    • کدی که lintهای bare_trait_objects و ellipsis_inclusive_range_patterns را فعال می‌کرد، در Rust 2021 خطا خواهد داد.

    جزئیات

    دو lint موجود در Rust 2021 به خطاهای سخت تبدیل می‌شوند، اما این lintها در ویرایش‌های قدیمی‌تر همچنان هشدار باقی خواهند ماند.

    bare_trait_objects:

    استفاده از کلیدواژهٔ dyn برای مشخص کردن شیءهای صفت در Rust 2021 اجباری خواهد بود.

    برای مثال، کد زیر که کلیدواژهٔ dyn را در &MyTrait ندارد، در Rust 2021 به‌جای یک lint ساده، خطا تولید خواهد کرد:

    pub trait MyTrait {}

pub fn my_function(_trait_object: &MyTrait) { // should be `&dyn MyTrait`
  unimplemented!()
}

    ellipsis_inclusive_range_patterns:

    سینتکس منسوخ ... برای الگوهای بازهٔ شامل (یعنی بازه‌هایی که مقدار انتهایی در آن‌ها گنجانده می‌شود) در Rust 2021 دیگر پذیرفته نمی‌شود. این سینتکس جای خود را به ..= داده است که با عبارت‌ها سازگار است.

    برای مثال، کد زیر که از ... در یک الگو استفاده می‌کند، در Rust 2021 به‌جای یک lint ساده، خطا تولید خواهد کرد:

    pub fn less_or_eq_to_100(n: u8) -> bool {
  matches!(n, 0...100) // should be `0..=100`
}

    مهاجرت‌ها

    اگر کد Rust 2015 یا 2018 شما هیچ هشداری برای bare_trait_objects یا ellipsis_inclusive_range_patterns تولید نمی‌کند و این lintها را با #![allow()] یا سازوکار دیگری مجاز نکرده‌اید، نیازی به مهاجرت نیست.

    برای مهاجرت خودکار هر crate که از ... در الگوها استفاده می‌کند یا dyn را با شیءهای صفت به کار نمی‌برد، می‌توانید cargo fix --edition را اجرا کنید.
