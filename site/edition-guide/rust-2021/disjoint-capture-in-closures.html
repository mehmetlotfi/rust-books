    ضبط مجزا در closureها

    خلاصه

    • || a.x + 1 اکنون فقط a.x را ضبط می‌کند، نه کل a را.
    • این موضوع می‌تواند باعث شود چیزها در زمان‌های متفاوتی drop شوند یا بر اینکه closureها صفت‌هایی مانند Send یا Clone را پیاده‌سازی کنند یا نه تأثیر بگذارد.
      • اگر تغییرات احتمالی شناسایی شوند، cargo fix دستورهایی مانند let _ = &a را درج می‌کند تا closure را مجبور به ضبط کل متغیر کند.

    جزئیات

    Closureها هر چیزی را که از درون بدنه‌شان به آن ارجاع دهید به‌طور خودکار ضبط می‌کنند. برای مثال، || a + 1 به‌طور خودکار یک ارجاع به a را از زمینهٔ پیرامون ضبط می‌کند.

    در Rust 2018 و پیش از آن، closureها کل متغیرها را ضبط می‌کنند، حتی اگر closure فقط از یک فیلد استفاده کند. برای مثال، || a.x + 1 یک ارجاع به a را ضبط می‌کند و نه فقط a.x را. ضبط کامل a مانع تغییر یا انتقال فیلدهای دیگر a می‌شود، به‌طوری که کدی مانند این کامپایل نمی‌شود:

    let a = SomeStruct::new();
drop(a.x); // Move out of one field of the struct
println!("{}", a.y); // Ok: Still use another field of the struct
let c = || println!("{}", a.y); // Error: Tries to capture all of `a`
c();

    از Rust 2021 به بعد، ضبط در closureها دقیق‌تر است. معمولاً فقط فیلدهایی را که استفاده می‌کنند ضبط می‌کنند (در برخی موارد ممکن است بیشتر از آنچه استفاده می‌کنند ضبط کنند؛ برای جزئیات کامل به مرجع Rust مراجعه کنید). بنابراین مثال بالا در Rust 2021 بدون مشکل کامپایل می‌شود.

    ضبط مجزا به‌عنوان بخشی از RFC 2229 پیشنهاد شد و این RFC جزئیات انگیزهٔ آن را در بر دارد.

    مهاجرت

    به‌عنوان بخشی از ویرایش 2021، یک lint مهاجرت با نام rust_2021_incompatible_closure_captures اضافه شده است تا به مهاجرت خودکار کدهای Rust 2018 به Rust 2021 کمک کند.

    برای مهاجرت کد خود به سازگاری با ویرایش Rust 2021، این دستور را اجرا کنید:

    cargo fix --edition

    در ادامه بررسی می‌کنیم که چگونه می‌توان کد را به‌صورت دستی طوری مهاجرت داد که با ضبط closureها در Rust 2021 سازگار باشد، برای زمانی که مهاجرت خودکار موفق نشود یا بخواهید نحوهٔ کار مهاجرت را بهتر بفهمید.

    تغییر متغیرهایی که یک closure ضبط می‌کند ممکن است در دو حالت باعث تغییر رفتار برنامه‌ها یا توقف کامپایل شدن آن‌ها شود:

    • تغییر در ترتیب drop، یا زمان اجرای نابودگرها (جزئیات);
    • تغییر در اینکه closure کدام صفت‌ها را پیاده‌سازی می‌کند (جزئیات).

    هرگاه هر یک از سناریوهای زیر شناسایی شود، cargo fix یک «let ساختگی» (dummy let) را درون closure شما درج می‌کند تا آن را مجبور کند کل متغیر را ضبط کند:

    let x = (vec![22], vec![23]);
let c = move || {
    // "Dummy let" that forces `x` to be captured in its entirety
    let _ = &x;

    // Otherwise, only `x.0` would be captured here
    println!("{:?}", x.0);
};

    این یک تحلیل محافظه‌کارانه است: در بسیاری از موارد می‌توان این letهای ساختگی را با خیال راحت حذف کرد و برنامهٔ شما درست کار خواهد کرد.

    الگوهای عام (Wild Card)

    closureها اکنون فقط داده‌ای را ضبط می‌کنند که باید خوانده شود، یعنی closureهای زیر x را ضبط نخواهند کرد:

    let x = 10;
let c = || {
    let _ = x; // no-op
};

let c = || match x {
    _ => println!("Hello World!")
};

    دستور let _ = x در اینجا بی‌اثر (no-op) است، زیرا الگوی _ سمت راست را کاملاً نادیده می‌گیرد و x ارجاعی به یک مکان در حافظه (در اینجا یک متغیر) است.

    این تغییر به‌تنهایی (ضبط مقادیر کمتر) هیچ پیشنهادی را فعال نمی‌کند، اما ممکن است همراه با تغییر «ترتیب drop» در ادامه چنین کاری کند.

    نکتهٔ ظریف: عبارت‌های مشابه دیگری نیز وجود دارند، مانند «letهای ساختگی» let _ = &x که ما درج می‌کنیم و بی‌اثر نیستند. دلیل این است که سمت راست (&x) ارجاعی به یک مکان در حافظه نیست، بلکه عبارتی است که ابتدا باید ارزیابی شود (و سپس نتیجه‌اش دور ریخته می‌شود).

    ترتیب drop

    وقتی یک closure مالکیت یک مقدار را از متغیر t به دست می‌گیرد، آن مقدار هنگام drop شدن closure، drop می‌شود و نه هنگامی که متغیر t از دامنه خارج می‌شود:

    fn move_value<T>(_: T){}
{
    let t = (vec![0], vec![0]);

    {
        let c = || move_value(t); // t is moved here
    } // c is dropped, which drops the tuple `t` as well
} // t goes out of scope here

    کد بالا در Rust 2018 و Rust 2021 به یک شکل اجرا می‌شود. با این حال، در مواردی که closure فقط مالکیت بخشی از یک متغیر را می‌گیرد، ممکن است تفاوت‌هایی وجود داشته باشد:

    fn move_value<T>(_: T){}
{
    let t = (vec![0], vec![0]);

    {
        let c = || {
            // In Rust 2018, captures all of `t`.
            // In Rust 2021, captures only `t.0`
            move_value(t.0);
        };

        // In Rust 2018, `c` (and `t`) are both dropped when we
        // exit this block.
        //
        // In Rust 2021, `c` and `t.0` are both dropped when we
        // exit this block.
    }

// In Rust 2018, the value from `t` has been moved and is
// not dropped.
//
// In Rust 2021, the value from `t.0` has been moved, but `t.1`
// remains, so it will be dropped here.
}

    در بیشتر موارد، drop شدن مقادیر در زمان‌های متفاوت فقط بر زمان آزاد شدن حافظه تأثیر می‌گذارد و اهمیتی ندارد. با این حال، برخی پیاده‌سازی‌های Drop (یا همان نابودگرها) اثر جانبی دارند و تغییر ترتیب drop در آن موارد می‌تواند معنای برنامهٔ شما را عوض کند. در چنین مواردی، کامپایلر پیشنهاد می‌کند یک let ساختگی درج شود تا کل متغیر ضبط شود.

    پیاده‌سازی صفت‌ها

    closureها بر اساس مقادیری که ضبط می‌کنند، صفت‌های زیر را به‌طور خودکار پیاده‌سازی می‌کنند:

    • Clone: اگر همهٔ مقادیر ضبط‌شده Clone باشند.
    • traitهای خودکار (auto trait) مانند Send، Sync و UnwindSafe: اگر همهٔ مقادیر ضبط‌شده trait مورد نظر را پیاده‌سازی کرده باشند.

    در Rust 2021، چون مقادیر متفاوتی ضبط می‌شوند، این موضوع می‌تواند بر اینکه یک closure کدام صفت‌ها را پیاده‌سازی کند تأثیر بگذارد. lintهای مهاجرت هر closure را آزمایش می‌کنند تا ببینند آیا پیش‌تر یک صفت مشخص را پیاده‌سازی می‌کرده و اکنون هم آن را پیاده‌سازی می‌کند یا نه؛ اگر متوجه شوند صفتی که قبلاً پیاده‌سازی می‌شد دیگر پیاده‌سازی نمی‌شود، «letهای ساختگی» درج می‌شوند.

    برای نمونه، یک روش رایج برای امکان جابه‌جایی اشاره‌گرهای خام بین نخ‌ها این است که آن‌ها را در یک ساختار بپیچیم و سپس صفت خودکار Send/Sync را برای آن پوشش پیاده‌سازی کنیم. آن closure که به thread::spawn داده می‌شود از فیلدهای مشخصی درون پوشش استفاده می‌کند، اما صرف‌نظر از آن کل پوشش ضبط می‌شود. از آنجا که پوشش Send/Sync است، کد ایمن در نظر گرفته می‌شود و در نتیجه با موفقیت کامپایل می‌شود.

    با ضبط مجزا، فقط فیلد مشخصی که در closure ذکر شده ضبط می‌شود، که در اصل Send/Sync نبوده و هدف پوشش را از بین می‌برد.

    use std::thread;

struct Ptr(*mut i32);
unsafe impl Send for Ptr {}


let mut x = 5;
let px = Ptr(&mut x as *mut i32);

let c = thread::spawn(move || {
    unsafe {
        *(px.0) += 10;
    }
}); // Closure captured px.0 which is not Send
