    IntoIterator برای آرایه‌ها

    خلاصه

    • آرایه‌ها IntoIterator را در همهٔ ویرایش‌ها پیاده‌سازی می‌کنند.
    • فراخوانی‌های IntoIterator::into_iter در Rust 2015 و Rust 2018 هنگام استفاده از سینتکس فراخوانی متد (یعنی array.into_iter()) پنهان هستند. بنابراین array.into_iter() همچنان مانند قبل به (&array).into_iter() تبدیل (resolve) می‌شود.
    • در Rust 2021، معنای array.into_iter() تغییر می‌کند و به فراخوانی IntoIterator::into_iter تبدیل می‌شود.

    جزئیات

    تا پیش از Rust 1.53، فقط ارجاع‌ها به آرایه‌ها IntoIterator را پیاده‌سازی می‌کردند. این یعنی می‌توانستید روی &[1, 2, 3] و &mut [1, 2, 3] پیمایش کنید، اما نه مستقیماً روی [1, 2, 3].

    for &e in &[1, 2, 3] {} // Ok :)

for e in [1, 2, 3] {} // Error :(

    این مسئله‌ای دیرینه بوده است، اما راه‌حل آن به سادگی که به نظر می‌رسد نیست. فقط افزودن پیاده‌سازی صفت کد موجود را خراب می‌کرد. array.into_iter() همین حالا کامپایل می‌شود، چون به‌طور ضمنی (&array).into_iter() را به‌دلیل نحوهٔ کار سینتکس فراخوانی متد فراخوانی می‌کند. افزودن پیاده‌سازی صفت این معنا را تغییر می‌داد.

    معمولاً این نوع شکست (افزودن یک پیاده‌سازی صفت) «جزئی» و قابل‌قبول دسته‌بندی می‌شود. اما در این مورد کدهای بسیار زیادی با آن خراب می‌شدند.

    بارها پیشنهاد شده است که «IntoIterator فقط در Rust 2021 برای آرایه‌ها پیاده‌سازی شود». اما این به‌سادگی ممکن نیست. نمی‌توان پیاده‌سازی یک صفت را در یک ویرایش داشت و در ویرایش دیگر نداشت، چون ویرایش‌ها می‌توانند با هم ترکیب شوند.

    در عوض، پیاده‌سازی صفت در همهٔ ویرایش‌ها اضافه شد (از Rust 1.53.0 به بعد) اما با یک ترفند کوچک برای جلوگیری از خرابی تا زمان Rust 2021. در کد Rust 2015 و 2018، کامپایلر همچنان array.into_iter() را مانند قبل به (&array).into_iter() تبدیل می‌کند، گویی پیاده‌سازی صفت وجود ندارد. این فقط برای سینتکس فراخوانی متد .into_iter() اعمال می‌شود. بر هیچ سینتکس دیگری مانند for e in [1, 2, 3]، iter.zip([1, 2, 3]) یا IntoIterator::into_iter([1, 2, 3]) اثری ندارد. این موارد در همهٔ ویرایش‌ها شروع به کار خواهند کرد.

    هرچند جای تأسف است که برای جلوگیری از خرابی به یک ترفند کوچک نیاز بود، این راه‌حل تفاوت بین ویرایش‌ها را به حداقل مطلق می‌رساند.

    مهاجرت

    یک lint با نام array_into_iter هر زمان که فراخوانی into_iter() وجود داشته باشد که در Rust 2021 معنایش تغییر می‌کند، فعال می‌شود. lint array_into_iter از زمان انتشار 1.41 در همهٔ ویرایش‌ها به‌طور پیش‌فرض یک هشدار بوده است (با چند بهبود در 1.55). اگر کد شما از قبل بدون هشدار است، پس باید از همین حالا برای Rust 2021 آماده باشد!

    می‌توانید با اجرای دستور زیر، کد خود را به‌طور خودکار با ویرایش Rust 2021 سازگار کنید یا مطمئن شوید که از قبل سازگار است:

    cargo fix --edition

    چون تفاوت بین ویرایش‌ها کم است، مهاجرت به Rust 2021 نسبتاً ساده است.

    برای فراخوانی‌های متد into_iter روی آرایه‌ها، عناصری که پیاده‌سازی می‌شوند از ارجاع به مقادیر مالک (owned) تغییر می‌کنند.

    برای مثال:

    fn main() {
  let array = [1u8, 2, 3];
  for x in array.into_iter() {
    // x is a `&u8` in Rust 2015 and Rust 2018
    // x is a `u8` in Rust 2021
  }
}

    ساده‌ترین راه برای مهاجرت در Rust 2021 این است که با فراخوانی iter() دقیقاً همان رفتار ویرایش‌های قبلی حفظ شود، چون iter() نیز آرایه‌های دارای مالکیت را با ارجاع پیمایش می‌کند:

    fn main() {
  let array = [1u8, 2, 3];
  for x in array.iter() { // <- This line changed
    // x is a `&u8` in all editions
  }
}

    مهاجرت اختیاری

    اگر در یک ویرایش قبلی از سینتکس متد با نام کامل (یعنی IntoIterator::into_iter(array)) استفاده می‌کنید، می‌توانید آن را به سینتکس فراخوانی متد (یعنی array.into_iter()) ارتقا دهید.
