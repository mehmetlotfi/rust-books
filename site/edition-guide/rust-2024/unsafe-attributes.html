راهنمای ویرایش‌های RustThe Edition Guide

    attributeهای unsafe

    خلاصه

    • attributeهای زیر اکنون باید با unsafe علامت‌گذاری شوند:
      • export_name
      • link_section
      • no_mangle

    جزئیات

    Rust 1.82 در همهٔ ویرایش‌ها این امکان را اضافه کرد که برخی attributeها با unsafe علامت‌گذاری شوند تا نشان دهند الزامات سلامت (soundness) دارند که باید رعایت شوند.1 نحو یک attribute از نوع unsafe به این شکل است:

    // SAFETY: there is no other global function of this name
#[unsafe(no_mangle)]
pub fn example() {}

    علامت‌گذاری attribute با unsafe نشان می‌دهد که الزامات ایمنی‌ای وجود دارند که باید رعایت شوند و کامپایلر نمی‌تواند خودش آن‌ها را بررسی کند.

    از ویرایش 2024 به بعد، علامت‌گذاری این attributeها با unsafe الزامی است. بخش بعدی الزامات ایمنی این attributeها را شرح می‌دهد.

    الزامات ایمنی

    attributeهای no_mangle، export_name و link_section بر نام نمادها (symbol) و رفتار پیونددهی (linking) آیتم‌ها اثر می‌گذارند. باید دقت شود که این attributeها درست به کار روند.

    از آنجا که مجموعهٔ نمادها در تمام کتابخانه‌های پیوندشده یک فضای نام سراسری است، اگر میان کتابخانه‌ها تداخل نام نماد رخ دهد ممکن است مشکلاتی پیش بیاید. معمولاً این موضوع برای تابع‌هایی که به‌طور عادی تعریف شده‌اند مسئله‌ای نیست، زیرا تغییر نام نماد (symbol mangling) کمک می‌کند نام نماد یکتا باشد. با این حال، attributeهایی مانند export_name می‌توانند این فرض یکتایی را برهم بزنند.

    برای مثال، در ویرایش‌های قبلی کد زیر در بیشتر پلتفرم‌های شبه‌یونیکس با وجود اینکه فقط شامل کد ایمن است از کار می‌افتد:

    #![allow(invalid_runtime_symbol_definitions)]
fn main() {
    println!("Hello, world!");
}

#[export_name = "malloc"]
fn foo() -> usize { 1 }

    در ویرایش 2024، علامت‌گذاری این attributeها به‌عنوان unsafe الزامی است تا بر این نکته تأکید شود که باید اطمینان حاصل کرد نماد درست تعریف شده است:

    // SAFETY: There should only be a single definition of the loop symbol.
#[unsafe(export_name="loop")]
fn arduino_loop() {
    // ...
}

    مهاجرت

    lint با نام unsafe_attr_outside_unsafe می‌تواند این attributeها را به قالب unsafe(...) به‌روزرسانی کند. این lint بخشی از گروه lint با نام rust-2024-compatibility است که در مهاجرت خودکار ویرایش گنجانده شده است. برای اینکه کد خود را با ویرایش Rust 2024 سازگار کنید، این دستور را اجرا کنید:

    cargo fix --edition

    فقط توجه داشته باشید که این مهاجرت خودکار نمی‌تواند بررسی کند که این attributeها درست به کار رفته‌اند. همچنان مسئولیت بازبینی دستی نحوهٔ استفاده از آن‌ها بر عهدهٔ خود شماست.

    به‌جای آن، می‌توانید lint را به‌صورت دستی فعال کنید تا جاهایی را که این attributeها باید به‌روزرسانی شوند پیدا کنید.

    // Add this to the root of your crate to do a manual migration.
#![warn(unsafe_attr_outside_unsafe)]
