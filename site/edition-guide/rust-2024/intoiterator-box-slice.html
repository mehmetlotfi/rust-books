    افزودن IntoIterator برای Box<[T]>

    خلاصه

    • sliceهای جعبه‌ای (boxed) در همهٔ ویرایش‌ها IntoIterator را پیاده‌سازی می‌کنند.
    • فراخوانی‌های IntoIterator::into_iter در ویرایش‌های پیش از ۲۰۲۴، هنگام استفاده از نحو فراخوانی متد (یعنی boxed_slice.into_iter())، پنهان هستند. بنابراین boxed_slice.into_iter() همچنان مانند گذشته به (&(*boxed_slice)).into_iter() تفسیر می‌شود.
    • در Rust 2024 معنای boxed_slice.into_iter() تغییر می‌کند و IntoIterator::into_iter را فراخوانی می‌کند.

    جزئیات

    تا Rust 1.80، IntoIterator برای sliceهای جعبه‌ای پیاده‌سازی نشده بود. در نسخه‌های قبلی، اگر .into_iter() را روی یک slice جعبه‌ای فراخوانی می‌کردید، فراخوانی متد به‌طور خودکار از Box<[T]> به &[T] ارجاع‌زدایی می‌کرد و iteratorی برمی‌گرداند که ارجاع‌هایی از نوع &T تولید می‌کرد. برای مثال، کد زیر در نسخه‌های قبلی کار می‌کرد:

    // Example of behavior in previous editions.
let my_boxed_slice: Box<[u32]> = vec![1, 2, 3].into_boxed_slice();
// Note: .into_iter() was required in versions older than 1.80
for x in my_boxed_slice.into_iter() {
    // x is of type &u32 in editions prior to 2024
}

    در Rust 1.80، پیاده‌سازی‌های IntoIterator برای sliceهای جعبه‌ای اضافه شد. این کار امکان پیمایش عناصر slice را به‌صورت مقداری (by-value) به‌جای ارجاعی (by-reference) فراهم می‌کند:

    // NEW as of 1.80, all editions
let my_boxed_slice: Box<[u32]> = vec![1, 2, 3].into_boxed_slice();
for x in my_boxed_slice { // notice no need for calling .into_iter()
    // x is of type u32
}

    این مثال در همهٔ ویرایش‌ها مجاز است، چون پیش‌تر این کار خطا بود؛ زیرا حلقه‌های for برخلاف فراخوانی متد .into_iter() به‌طور خودکار ارجاع‌زدایی نمی‌کنند.

    با این حال، این کار معمولاً یک تغییر ناسازگار (breaking change) بود، چون کد موجودی که به‌صورت دستی .into_iter() را روی یک slice جعبه‌ای فراخوانی می‌کرد، از داشتن یک iterator روی ارجاع‌ها به یک iterator روی مقادیر تغییر می‌کرد. برای حل این مشکل، فراخوانی‌های متد .into_iter() روی sliceهای جعبه‌ای رفتاری وابسته به ویرایش دارند. در ویرایش‌های پیش از 2024، همچنان iteratorی روی ارجاع‌ها برمی‌گرداند و از ویرایش 2024 به بعد iteratorی روی مقادیر برمی‌گرداند.

    // Example of changed behavior in Edition 2024
let my_boxed_slice: Box<[u32]> = vec![1, 2, 3].into_boxed_slice();
// Example of old code that still manually calls .into_iter()
for x in my_boxed_slice.into_iter() {
    // x is now type u32 in Edition 2024
}

    مهاجرت

    lint با نام boxed_slice_into_iter هر فراخوانی .into_iter() روی sliceهای جعبه‌ای را به‌طور خودکار به .iter() تغییر می‌دهد تا رفتار قبلی، یعنی تولید ارجاع‌ها، حفظ شود. این lint بخشی از گروه lint با نام rust-2024-compatibility است که هنگام اجرای cargo fix --edition به‌طور خودکار اعمال می‌شود. برای مهاجرت کد خود به سازگاری با ویرایش Rust 2024، این دستور را اجرا کنید:

    cargo fix --edition

    برای مثال، این کد را تغییر می‌دهد:

    fn main() {
    let my_boxed_slice: Box<[u32]> = vec![1, 2, 3].into_boxed_slice();
    for x in my_boxed_slice.into_iter() {
        // x is of type &u32
    }
}

    به این شکل تبدیل می‌شود:

    fn main() {
    let my_boxed_slice: Box<[u32]> = vec![1, 2, 3].into_boxed_slice();
    for x in my_boxed_slice.iter() {
        // x is of type &u32
    }
}

    lint با نام boxed_slice_into_iter در همهٔ ویرایش‌ها به‌صورت پیش‌فرض روی warn تنظیم شده است، بنابراین اگر آن را به‌صورت دستی خاموش نکرده باشید، باید پیش از مهاجرت آن را دیده باشید.
