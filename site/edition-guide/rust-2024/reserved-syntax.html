راهنمای ویرایش‌های RustThe Edition Guide

    نحو رزروشده

    خلاصه

    • رشته‌های محافظت‌شدهٔ بدون پیشوند به شکل #"foo"# برای استفادهٔ آینده رزرو شده‌اند.
    • دو یا چند نویسهٔ # برای استفادهٔ آینده رزرو شده‌اند.

    جزئیات

    RFC 3593 در ویرایش 2024 نحوی را برای لیترال‌های رشتهٔ محافظت‌شده‌ای که پیشوند ندارند رزرو کرد تا جا برای تغییرات احتمالی آینده زبان باز بماند. ویرایش 2021 نحو رشته‌های محافظت‌شده با پیشوند، مانند ident##"foo"## را رزرو کرده بود. ویرایش 2024 این را گسترش می‌دهد تا رشته‌های بدون پیشوند ident را نیز رزرو کند.

    دو نحو رزروشده وجود دارد:

    • یک یا چند نویسهٔ # که بلافاصله بعد از آن‌ها یک لیترال رشته بیاید.
    • دو یا چند نویسهٔ # پشت سر هم (بدون فاصلهٔ خالی بین آن‌ها).

    این رزرو به‌دلیل تعامل با توکن‌سازی (tokenization) و ماکروها در مرز یک ویرایش انجام می‌شود. برای مثال، این ماکرو را در نظر بگیرید:

    macro_rules! demo {
    ( $a:tt ) => { println!("one token") };
    ( $a:tt $b:tt $c:tt ) => { println!("three tokens") };
}

demo!("foo");
demo!(r#"foo"#);
demo!(#"foo"#);
demo!(###)

    پیش از ویرایش 2024، این کد خروجی زیر را تولید می‌کند:

    one token
one token
three tokens
three tokens

    از ویرایش 2024 به بعد، خط #"foo"# و خط ### اکنون خطای کامپایل تولید می‌کنند، چون این شکل‌ها اکنون رزرو شده‌اند.

    مهاجرت

    lint با نام rust_2024_guarded_string_incompatible_syntax هر توکنی را که با نحو رزروشده مطابقت داشته باشد شناسایی می‌کند و تغییری پیشنهاد می‌دهد که در جاهای لازم فاصله درج کند تا اطمینان حاصل شود توکن‌ها همچنان جداگانه تجزیه می‌شوند.

    این lint بخشی از گروه lint با نام rust-2024-compatibility است که در مهاجرت خودکار ویرایش گنجانده شده است. برای مهاجرت کد خود به سازگاری با ویرایش Rust 2024، این دستور را اجرا کنید:

    cargo fix --edition

    همچنین می‌توانید lint را به‌صورت دستی فعال کنید تا فراخوانی‌های ماکرویی را که ممکن است لازم باشد توکن‌های آن‌ها به‌روزرسانی شوند پیدا کنید:

    // Add this to the root of your crate to do a manual migration.
#![warn(rust_2024_guarded_string_incompatible_syntax)]
