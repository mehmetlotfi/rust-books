راهنمای ویرایش‌های RustThe Edition Guide

    تغییر include! تودرتو در Rustdoc

    خلاصه

    وقتی یک doctest با include_str! گنجانده می‌شود، اگر خود آن doctest نیز از include!، include_str! یا include_bytes! استفاده کند، مسیر نسبت به فایل Markdown تفسیر می‌شود، نه نسبت به فایل سورس Rust.

    جزئیات

    پیش از ویرایش 2024، افزودن مستندات با #[doc=include_str!("path/file.md")] اطلاعات span را به هیچ doctestی در آن فایل منتقل نمی‌کرد. در نتیجه، اگر فایل Markdown در دایرکتوری‌ای متفاوت از سورس بود، هر مسیر گنجانده‌شده باید نسبت به فایل سورس مشخص می‌شد.

    برای مثال، یک crate کتابخانه‌ای را با این فایل‌ها در نظر بگیرید:

    • Cargo.toml
    • README.md
    • src/
      • lib.rs
    • examples/
      • data.bin

    فرض کنید lib.rs شامل این است:

    #![doc=include_str!("../README.md")]

    و فرض کنید این فایل README.md را دارید:

    ```
let _ = include_bytes!("../examples/data.bin");
//                      ^^^ notice this
```

    پیش از ویرایش 2024، مسیر در README.md باید نسبت به فایل lib.rs می‌بود. در 2024 و بعد از آن، اکنون نسبت به خود README.md است، بنابراین README.md را این‌گونه به‌روزرسانی می‌کنیم:

    ```
let _ = include_bytes!("examples/data.bin");
```

    مهاجرت

    مهاجرت خودکاری برای تبدیل مسیرها در doctestهای تحت‌تأثیر وجود ندارد. اگر یکی از doctestهای شما تحت‌تأثیر باشد، پس از مهاجرت به ویرایش جدید و هنگام ساخت آزمون‌هایتان خطایی مانند این خواهید دید:

    error: couldn't read `../examples/data.bin`: No such file or directory (os error 2)
 --> src/../README.md:2:24
  |
2 | let _ = include_bytes!("../examples/data.bin");
  |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = note: this error originates in the macro `include_bytes` (in Nightly builds, run with -Z macro-backtrace for more info)
help: there is a file with the same name in a different directory
  |
2 | let _ = include_bytes!("examples/data.bin");
  |                        ~~~~~~~~~~~~~~~~~~~

    برای مهاجرت doctestهای خود به Rust 2024، هر مسیر تحت‌تأثیر را طوری به‌روزرسانی کنید که نسبت به فایل حاوی doctestها باشد.
