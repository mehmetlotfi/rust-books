    هشدار unsafe_op_in_unsafe_fn

    خلاصه

    • lint با نام unsafe_op_in_unsafe_fn اکنون به‌طور پیش‌فرض هشدار می‌دهد. این هشدار فراخوانی عملیات unsafe در تابع‌های unsafe را بدون بلوک unsafe صریح شناسایی می‌کند.

    جزئیات

    lint با نام unsafe_op_in_unsafe_fn زمانی فعال می‌شود که در یک تابع unsafe عملیات unsafe بدون بلوک صریح unsafe {} وجود داشته باشد.

    #![warn(unsafe_op_in_unsafe_fn)]
unsafe fn get_unchecked<T>(x: &[T], i: usize) -> &T {
  x.get_unchecked(i) // WARNING: requires unsafe block
}

    راه‌حل این است که هر عملیات unsafe را درون یک بلوک unsafe قرار دهید:

    #![deny(unsafe_op_in_unsafe_fn)]
unsafe fn get_unchecked<T>(x: &[T], i: usize) -> &T {
  unsafe { x.get_unchecked(i) }
}

    هدف این تغییر کمک به محافظت در برابر استفادهٔ ناخواسته از عملیات unsafe در یک تابع unsafe است. کلیدواژهٔ unsafe در تابع دو نقش را ایفا می‌کرد. یکی اعلام اینکه فراخوانی تابع به unsafe نیاز دارد و فراخواننده مسئول رعایت الزامات ایمنی بیشتر است. نقش دیگر اجازه دادن به استفاده از عملیات unsafe درون تابع بود. تشخیص داده شد که این نقش دوم بدون بلوک‌های unsafe صریح بیش از حد پرخطر است.

    اطلاعات بیشتر و انگیزه‌ها را می‌توانید در RFC #2585 بیابید.

    مهاجرت

    lint با نام unsafe_op_in_unsafe_fn بخشی از گروه lint با نام rust-2024-compatibility است. برای اینکه کد خود را با ویرایش Rust 2024 سازگار کنید، این دستور را اجرا کنید:

    cargo fix --edition

    به‌جای آن، می‌توانید lint را به‌صورت دستی فعال کنید تا جاهایی را که باید بلوک‌های unsafe اضافه شوند پیدا کنید، یا آن را روی allow بگذارید تا lint کاملاً خاموش شود.

    // Add this to the root of your crate to do a manual migration.
#![warn(unsafe_op_in_unsafe_fn)]
