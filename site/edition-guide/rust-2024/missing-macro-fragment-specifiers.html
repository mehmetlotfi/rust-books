    مشخص‌کننده‌های قطعهٔ ماکروی جاافتاده

    نکته: این مورد در ابتدا فقط برای ویرایش 2024 به خطای سخت تبدیل شد. در Rust 1.89 که پس از Rust 2024 منتشر شد، lint در همهٔ ویرایش‌ها به خطای سخت تبدیل شد.

    خلاصه

    • lint با نام missing_fragment_specifier اکنون یک خطای سخت است.

    جزئیات

    lint با نام missing_fragment_specifier وضعیتی را شناسایی می‌کرد که در آن یک الگوی استفاده‌نشده در تعریف ماکروی macro_rules! یک متغیر متا (مثلاً $e) داشت که بعد از آن مشخص‌کنندهٔ قطعه‌ای (مثلاً :expr) نیامده بود. این مورد در ویرایش 2024 به خطای سخت تبدیل شد.

    macro_rules! foo {
   () => {};
   ($name) => { }; // ERROR: missing fragment specifier
}

fn main() {
   foo!();
}

    فراخوانی ماکرو با آرگومان‌هایی که با قاعده‌ای دارای مشخص‌کنندهٔ جاافتاده تطبیق پیدا می‌کردند (مثلاً foo!($name)) در همهٔ ویرایش‌ها خطای سخت بود. اما صرفِ تعریف یک ماکرو با مشخص‌کننده‌های قطعهٔ جاافتاده خطای سخت نبود، هرچند در Rust 1.17 یک lint برای آن اضافه کردیم.

    مهاجرت

    برای مهاجرت کد خود به ویرایش 2024، قاعدهٔ تطبیق‌دهندهٔ استفاده‌نشده را از ماکرو حذف کنید.

    برای این تغییر مهاجرت خودکاری وجود ندارد. انتظار داریم این سبک از ماکرو بسیار نادر باشد. این lint از Rust 1.17 یک lint ناسازگاری آینده بود، از Rust 1.20 یک lint با سطح پیش‌فرض deny شد، از Rust 1.82 دربارهٔ وابستگی‌هایی که از این الگو استفاده می‌کردند هشدار می‌داد و در Rust 1.89 به خطای سخت تبدیل شد.
