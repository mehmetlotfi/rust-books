    دامنهٔ مقدار موقت عبارت انتهایی

    خلاصه

    • مقادیر موقتی که در ارزیابی عبارت انتهایی (tail expression) بدنهٔ یک تابع یا closure، یا یک بلوک تولید می‌شوند، اکنون ممکن است پیش از متغیرهای محلی drop شوند و گاهی به دامنهٔ موقت بزرگ‌تر بعدی گسترش نمی‌یابند.

    جزئیات

    ویرایش 2024 ترتیب drop شدن مقادیر موقت را در عبارت‌های انتهایی تغییر می‌دهد. اغلب غافلگیرکننده است که پیش از ویرایش 2024، مقادیر موقت در عبارت‌های انتهایی می‌توانند از خود بلوک بیشتر عمر کنند و دیرتر از متغیرهای محلی drop شوند، مانند مثال زیر:

    // Before 2024
use std::cell::RefCell;
fn f() -> usize {
    let c = RefCell::new("..");
    c.borrow().len() // error[E0597]: `c` does not live long enough
}

    این کد در ویرایش 2021 خطای زیر را تولید می‌کند:

    error[E0597]: `c` does not live long enough
 --> src/lib.rs:4:5
  |

  |         - binding `c` declared here
4 |     c.borrow().len() // error[E0597]: `c` does not live long enough
  |     ^---------
  |     |
  |     borrowed value does not live long enough
  |     a temporary with access to the borrow is created here ...
5 | }
  | -
  | |
  | `c` dropped here while still borrowed
  | ... and the borrow might be used here, when that temporary is dropped and runs the destructor for type `Ref<'_, &str>`

  |

    در 2021 متغیر محلی c پیش از مقدار موقتی که با c.borrow() ساخته شده drop می‌شود. ویرایش 2024 این را تغییر می‌دهد تا ابتدا مقدار موقت c.borrow() و سپس متغیر محلی c drop شود، و کد همان‌طور که انتظار می‌رود کامپایل شود.

    دامنهٔ مقدار موقت ممکن است محدودتر شود

    وقتی برای ارزیابی یک عبارت مقداری موقت ساخته می‌شود، آن مقدار بر اساس قواعد دامنهٔ مقدار موقت drop می‌شود. این قواعد تعیین می‌کنند که مقدار موقت تا چه مدت زنده نگه داشته شود. پیش از 2024، مقادیر موقت حاصل از عبارت‌های انتهایی یک بلوک به بیرون از بلوک، تا مرز دامنهٔ موقت بعدی، گسترش می‌یافتند. در بسیاری از موارد این مرز، پایان یک دستور یا بدنهٔ تابع بود. در 2024، مقادیر موقت عبارت انتهایی اکنون ممکن است بلافاصله در پایان بلوک (پیش از هر متغیر محلی در بلوک) drop شوند.

    این محدودتر شدن دامنهٔ مقدار موقت ممکن است باعث شود برخی برنامه‌ها در 2024 کامپایل نشوند. برای مثال:

    // This example works in 2021, but fails to compile in 2024.
fn main() {
    let x = { &String::from("1234") }.len();
}

    در این مثال، در 2021 مقدار موقت String به بیرون از بلوک، فراتر از فراخوانی len()، گسترش می‌یابد و در پایان دستور drop می‌شود. در 2024 بلافاصله در پایان بلوک drop می‌شود، که خطای کامپایل دربارهٔ drop شدن مقدار موقت در حالی که هنوز قرض گرفته شده است را به دنبال دارد.

    راه‌حل برای این‌گونه موقعیت‌ها این است که عبارت بلوک را به یک متغیر محلی منتقل کنید تا مقدار موقت به اندازهٔ کافی زنده بماند:

    fn main() {
    let s = { &String::from("1234") };
    let x = s.len();
}

    این مثال خاص از گسترش طول عمر مقدار موقت بهره می‌برد. گسترش طول عمر مقدار موقت مجموعه‌ای از قواعد مشخص است که به مقادیر موقت اجازه می‌دهد بیش از حالت معمول عمر کنند. چون مقدار موقت String پشت یک ارجاع قرار دارد، همان مقدار موقت String به‌اندازه‌ای گسترش می‌یابد که دستور بعدی بتواند len() را روی آن فراخوانی کند.

    برای تغییری مشابه که روی دامنهٔ مقادیر موقت عبارت‌های if let اعمال شده است، فصل دامنهٔ مقدار موقت در if let را ببینید.

    مهاجرت

    متأسفانه هیچ بازنویسی‌ای وجود ندارد که معناشناسی را حفظ کند و در عین حال طول عمر مقادیر موقت در عبارت‌های انتهایی را کوتاه کند1. lint با نام tail_expr_drop_order تشخیص می‌دهد که آیا در یک عبارت انتهایی مقدار موقتی با destructor سفارشی و غیرپیش‌پاافتادهٔ Drop تولید شده است یا نه. هشدارهای این lint هنگام اجرای cargo fix --edition ظاهر می‌شوند، اما در غیر این صورت هیچ تغییری را به‌طور خودکار اعمال نمی‌کنند. توصیه می‌شود هشدارها را به‌صورت دستی بررسی کنید و تعیین کنید که آیا باید تنظیماتی انجام دهید یا نه.

    اگر می‌خواهید بدون انجام مهاجرت ویرایش، این هشدارها را به‌صورت دستی بررسی کنید، می‌توانید lint را به این شکل فعال کنید:

    // Add this to the root of your crate to do a manual migration.
#![warn(tail_expr_drop_order)]
