    تغییرات prelude

    خلاصه

    • traitهای Future و IntoFuture اکنون بخشی از prelude هستند.
    • این ممکن است فراخوانی متدهای صفت را مبهم کند و باعث شود برخی کدها کامپایل نشوند.

    جزئیات

    prelude کتابخانهٔ استاندارد ماژولی است که شامل همه‌چیزهایی می‌شود که به‌طور خودکار در هر ماژول وارد (import) می‌شوند. این ماژول شامل آیتم‌های پراستفاده‌ای مانند Option، Vec، drop و Clone است.

    کامپایلر Rust آیتم‌هایی را که به‌صورت دستی وارد شده‌اند بر آیتم‌های prelude اولویت می‌دهد، تا مطمئن شود افزودن‌ها به prelude هیچ کد موجودی را نمی‌شکند. برای مثال، اگر crate یا ماژولی به نام example داشته باشید که شامل pub struct Option; است، آنگاه use example::*; باعث می‌شود Option بدون ابهام به همان نسخهٔ example اشاره کند؛ نه نسخهٔ کتابخانهٔ استاندارد.

    با این حال، افزودن یک صفت به prelude می‌تواند کد موجود را به شکلی ظریف بشکند. برای مثال، فراخوانی x.poll() که از صفت MyPoller می‌آید ممکن است در صورتی که Future از std نیز وارد شده باشد کامپایل نشود، چون فراخوانی poll اکنون مبهم است و می‌تواند از هر دو صفت باشد.

    به‌عنوان راه‌حل، Rust 2024 از یک prelude جدید استفاده خواهد کرد. این prelude با نسخهٔ فعلی یکسان است، به‌جز تغییرات زیر:

    • افزوده‌شده:
      • std::future::Future
      • std::future::IntoFuture

    مهاجرت

    متدهای متعارض صفت

    وقتی دو صفت که در دامنه هستند نام متد یکسانی دارند، مشخص نیست کدام متد صفت باید استفاده شود. برای مثال:

    trait MyPoller {
    // This name is the same as the `poll` method on the `Future` trait from `std`.
    fn poll(&self) {
        println!("polling");
    }
}

impl<T> MyPoller for T {}

fn main() {
    // Pin<&mut async {}> implements both `std::future::Future` and `MyPoller`.
    // If both traits are in scope (as would be the case in Rust 2024),
    // then it becomes ambiguous which `poll` method to call
    core::pin::pin!(async {}).poll();
}

    می‌توانیم با استفاده از نحو کاملاً مشخص (fully qualified) این مشکل را طوری برطرف کنیم که در همهٔ ویرایش‌ها کار کند:

    fn main() {
    // Now it is clear which trait method we're referring to
    <_ as MyPoller>::poll(&core::pin::pin!(async {}));
}

    lint با نام rust_2024_prelude_collisions هر فراخوانی متد مبهم را به‌طور خودکار طوری تغییر می‌دهد که از نحو کاملاً مشخص (fully qualified) استفاده کند. این lint بخشی از گروه lint با نام rust-2024-compatibility است که هنگام اجرای cargo fix --edition به‌طور خودکار اعمال می‌شود. برای مهاجرت کد خود به سازگاری با ویرایش Rust 2024، این دستور را اجرا کنید:

    cargo fix --edition

    همچنین می‌توانید lint را به‌صورت دستی فعال کنید تا جاهایی را که باید این مشخص‌سازی‌ها اضافه شوند پیدا کنید:

    // Add this to the root of your crate to do a manual migration.
#![warn(rust_2024_prelude_collisions)]
