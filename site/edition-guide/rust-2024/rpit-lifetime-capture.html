    قواعد capture طول عمر در RPIT

    این فصل تغییرات مربوط به قواعد Capture طول عمر 2024 را که در RFC 3498 معرفی شد شرح می‌دهد، از جمله اینکه چگونه از capture دقیق (precise capturing) نوع مات (opaque) که در RFC 3617 معرفی شد برای مهاجرت کد خود استفاده کنید.

    خلاصه

    • در Rust 2024، وقتی قید use<..> وجود نداشته باشد، همهٔ پارامترهای جنریک در دامنه، از جمله پارامترهای طول عمر، به‌طور ضمنی capture می‌شوند.
    • استفاده از ترفند Captures (قیدهای Captures<..>) و ترفند outlives (مثلاً قیدهای '_) را می‌توان با قیدهای use<..> جایگزین کرد (در همهٔ ویرایش‌ها) یا به‌طور کامل حذف کرد (در Rust 2024).

    جزئیات

    Capture کردن

    Capture کردن یک پارامتر جنریک در یک نوع مات RPIT (یعنی impl Trait در جایگاه بازگشتی) اجازه می‌دهد آن پارامتر در نوع پنهان متناظر استفاده شود. در Rust 1.82 قیدهای use<..> را اضافه کردیم که اجازه می‌دهند به‌صراحت مشخص شود کدام پارامترهای جنریک capture شوند. این قیدها برای مهاجرت کد شما به Rust 2024 مفید خواهند بود و در این فصل نیز برای توضیح نحوهٔ کار قواعد capture ضمنی مختص هر ویرایش مفید خواهند بود. این قیدهای use<..> به این شکل هستند:

    fn capture<'a, T>(x: &'a (), y: T) -> impl Sized + use<'a, T> {
    //                                ~~~~~~~~~~~~~~~~~~~~~~~
    //                             This is the RPIT opaque type.
    //
    //                                It captures `'a` and `T`.
    (x, y)
  //~~~~~~
  // The hidden type is: `(&'a (), T)`.
  //
  // This type can use `'a` and `T` because they were captured.
}

    پارامترهای جنریکی که capture می‌شوند بر نحوهٔ استفاده از نوع مات اثر می‌گذارند. برای مثال، این یک خطا است، چون طول عمر capture شده است با اینکه نوع پنهان از آن طول عمر استفاده نمی‌کند:

    fn capture<'a>(_: &'a ()) -> impl Sized + use<'a> {}

fn test<'a>(x: &'a ()) -> impl Sized + 'static {
    capture(x)
    //~^ ERROR lifetime may not live long enough
}

    در مقابل، این درست است:

    fn capture<'a>(_: &'a ()) -> impl Sized + use<> {}

fn test<'a>(x: &'a ()) -> impl Sized + 'static {
    capture(x) //~ OK
}

    قواعد مختص ویرایش وقتی قید use<..> وجود ندارد

    اگر قید use<..> وجود نداشته باشد، کامپایلر از قواعد مختص ویرایش استفاده می‌کند تا تصمیم بگیرد کدام پارامترهای جنریک در دامنه را به‌طور ضمنی capture کند.

    در همهٔ ویرایش‌ها، وقتی قید use<..> وجود نداشته باشد، همهٔ پارامترهای جنریک نوع و ثابت (const) در دامنه به‌طور ضمنی capture می‌شوند. برای مثال:

    fn f_implicit<T, const C: usize>() -> impl Sized {}
//                                    ~~~~~~~~~~
//                         No `use<..>` bound is present here.
//
// In all editions, the above is equivalent to:
fn f_explicit<T, const C: usize>() -> impl Sized + use<T, C> {}

    در Rust 2021 و ویرایش‌های قبلی‌تر، وقتی قید use<..> وجود نداشته باشد، پارامترهای جنریک طول عمر فقط زمانی capture می‌شوند که از نظر نحوی درون یک قید در نوع‌های مات RPIT در امضای توابع ساده و توابع وابسته و متدها درون implهای ذاتی (inherent) ظاهر شوند. با این حال، از Rust 2024 به بعد، این پارامترهای جنریک طول عمر در دامنه بدون قید و شرط capture می‌شوند. برای مثال:

    fn f_implicit(_: &()) -> impl Sized {}
// In Rust 2021 and earlier, the above is equivalent to:
fn f_2021(_: &()) -> impl Sized + use<> {}
// In Rust 2024 and later, it's equivalent to:
fn f_2024(_: &()) -> impl Sized + use<'_> {}

    این کار رفتار را با نوع‌های مات RPIT در امضای توابع وابسته و متدها درون implهای صفت، استفاده از RPIT درون تعریف‌های صفت (RPITIT) و نوع‌های مات Future که توسط async fn ساخته می‌شوند هماهنگ می‌کند؛ همهٔ این‌ها وقتی قید use<..> وجود نداشته باشد، در همهٔ ویرایش‌ها همهٔ پارامترهای جنریک طول عمر در دامنه را به‌طور ضمنی capture می‌کنند.

    پارامترهای جنریک بیرونی

    هنگام تصمیم‌گیری دربارهٔ آنچه به‌طور ضمنی capture می‌شود، پارامترهای جنریک از یک impl بیرونی نیز در دامنه محسوب می‌شوند. برای مثال:

    struct S<T, const C: usize>((T, [(); C]));
impl<T, const C: usize> S<T, C> {
//   ~~~~~~~~~~~~~~~~~
// These generic parameters are in scope.
    fn f_implicit<U>() -> impl Sized {}
    //            ~       ~~~~~~~~~~
    //            ^ This generic is in scope too.
    //                    ^
    //                    |
    //     No `use<..>` bound is present here.
    //
    // In all editions, it's equivalent to:
    fn f_explicit<U>() -> impl Sized + use<T, U, C> {}
}

    طول عمرها از بایندرهای رتبه‌بالاتر

    به همین ترتیب، پارامترهای جنریک طول عمر که توسط بایندر رتبه‌بالاتر for<..> وارد دامنه می‌شوند، در دامنه محسوب می‌شوند. برای مثال:

    trait Tr<'a> { type Ty; }
impl Tr<'_> for () { type Ty = (); }

fn f_implicit() -> impl for<'a> Tr<'a, Ty = impl Copy> {}
// In Rust 2021 and earlier, the above is equivalent to:
fn f_2021() -> impl for<'a> Tr<'a, Ty = impl Copy + use<>> {}
// In Rust 2024 and later, it's equivalent to:
//fn f_2024() -> impl for<'a> Tr<'a, Ty = impl Copy + use<'a>> {}
//                                        ~~~~~~~~~~~~~~~~~~~~
// However, note that the capturing of higher-ranked lifetimes in
// nested opaque types is not yet supported.

    impl Trait در جایگاه آرگومان (APIT)

    پارامترهای جنریک ناشناس (یعنی بدون نام) که با استفاده از APIT (یعنی impl Trait در جایگاه آرگومان) ساخته می‌شوند در دامنه محسوب می‌شوند. برای مثال:

    fn f_implicit(_: impl Sized) -> impl Sized {}
//               ~~~~~~~~~~
//           This is called APIT.
//
// The above is *roughly* equivalent to:
fn f_explicit<_0: Sized>(_: _0) -> impl Sized + use<_0> {}

    توجه داشته باشید که حالت اول دقیقاً با حالت دوم هم‌ارز نیست، چون با نام‌گذاری پارامتر جنریک، اکنون می‌توان از نحو turbofish برای فراهم کردن یک آرگومان برای آن استفاده کرد. هیچ راهی برای گنجاندن صریح یک پارامتر جنریک ناشناس در یک قید use<..> وجود ندارد، مگر اینکه آن را به یک پارامتر جنریک نام‌دار تبدیل کنید.

    مهاجرت

    مهاجرت با پرهیز از capture بیش‌ازحد

    lint با نام impl_trait_overcaptures نوع‌های مات RPIT را که در Rust 2024 طول عمرهای اضافی را capture می‌کنند علامت‌گذاری می‌کند. این lint بخشی از گروه lint با نام rust-2024-compatibility است که هنگام اجرای cargo fix --edition به‌طور خودکار اعمال می‌شود. در بیشتر موارد، این lint می‌تواند در جاهای لازم به‌طور خودکار قیدهای use<..> را درج کند تا در Rust 2024 هیچ طول عمر اضافی capture نشود.

    برای مهاجرت کد خود به سازگاری با Rust 2024، این دستور را اجرا کنید:

    cargo fix --edition

    برای مثال، این کد را تغییر می‌دهد:

    fn f<'a>(x: &'a ()) -> impl Sized { *x }

    …into:

    fn f<'a>(x: &'a ()) -> impl Sized + use<> { *x }

    بدون این قید use<>، در Rust 2024 نوع مات پارامتر طول عمر 'a را capture می‌کرد. با افزودن این قید، lint مهاجرت معناشناسی موجود را حفظ می‌کند.

    مهاجرت موارد مربوط به APIT

    در برخی موارد، lint نمی‌تواند تغییر را به‌طور خودکار اعمال کند، چون باید به یک پارامتر جنریک نامی داده شود تا بتواند درون یک قید use<..> ظاهر شود. در این موارد، lint به شما هشدار می‌دهد که ممکن است لازم باشد تغییری به‌صورت دستی اعمال شود. برای مثال، با فرض این کد:

    fn f<'a>(x: &'a (), y: impl Sized) -> impl Sized { (*x, y) }
//   ^^                ~~~~~~~~~~
//               This is a use of APIT.
//
//~^ WARN `impl Sized` will capture more lifetimes than possibly intended in edition 2024
//~| NOTE specifically, this lifetime is in scope but not mentioned in the type's bounds

fn test<'a>(x: &'a (), y: ()) -> impl Sized + 'static {
    f(x, y)
}

    کد به‌دلیل استفاده از APIT و این واقعیت که پارامتر نوع جنریک باید در قید use<..> نام‌گذاری شود، نمی‌تواند به‌طور خودکار تبدیل شود. برای تبدیل این کد به Rust 2024 بدون capture کردن طول عمر، باید آن پارامتر نوع را نام‌گذاری کنید. برای مثال:

    #![deny(impl_trait_overcaptures)]
fn f<'a, T: Sized>(x: &'a (), y: T) -> impl Sized + use<T> { (*x, y) }
//       ~~~~~~~~
// The type parameter has been named here.

fn test<'a>(x: &'a (), y: ()) -> impl Sized + use<> {
    f(x, y)
}

    توجه داشته باشید که این کار API تابع را اندکی تغییر می‌دهد، چون اکنون می‌توان با نحو turbofish یک آرگومان نوع را به‌صراحت برای این پارامتر فراهم کرد. اگر این مطلوب نیست، می‌توانید به‌جای آن بررسی کنید که آیا می‌توانید به‌سادگی همچنان قید use<..> را حذف کنید و اجازه دهید طول عمر capture شود. اگر ممکن است در آینده بخواهید از آن طول عمر در نوع پنهان استفاده کنید و بخواهید برای آن جا باز بگذارید، این کار می‌تواند به‌ویژه مطلوب باشد.

    مهاجرت از ترفند Captures

    پیش از معرفی قیدهای capture دقیق use<..> در Rust 1.82، capture صحیح یک طول عمر در یک نوع مات RPIT اغلب نیازمند استفاده از ترفند Captures بود. برای مثال:

    #[doc(hidden)]
pub trait Captures<T: ?Sized> {}
impl<T: ?Sized, U: ?Sized> Captures<T> for U {}

fn f<'a, T>(x: &'a (), y: T) -> impl Sized + Captures<(&'a (), T)> {
//                                           ~~~~~~~~~~~~~~~~~~~~~
//                            This is called the `Captures` trick.
    (x, y)
}

fn test<'t, 'x>(t: &'t (), x: &'x ()) {
    f(t, x);
}

    با نحو قید use<..>، دیگر نیازی به ترفند Captures نیست و در همهٔ ویرایش‌ها می‌توان آن را با کد زیر جایگزین کرد:

    fn f<'a, T>(x: &'a (), y: T) -> impl Sized + use<'a, T> {
    (x, y)
}

fn test<'t, 'x>(t: &'t (), x: &'x ()) {
    f(t, x);
}

    در Rust 2024، اغلب می‌توان قید use<..> را به‌طور کامل حذف کرد و کد بالا را می‌توان به‌سادگی این‌گونه نوشت:

    fn f<'a, T>(x: &'a (), y: T) -> impl Sized {
    (x, y)
}

fn test<'t, 'x>(t: &'t (), x: &'x ()) {
    f(t, x);
}

    برای این کار مهاجرت خودکاری وجود ندارد و ترفند Captures همچنان در Rust 2024 کار می‌کند، اما ممکن است بخواهید مهاجرت دستی کد را از این ترفند قدیمی در نظر بگیرید.

    مهاجرت از ترفند outlives

    پیش از معرفی قیدهای capture دقیق use<..> در Rust 1.82، وقتی لازم بود یک طول عمر در نوع پنهان یک نوع مات استفاده شود، رایج بود که از «ترفند outlives» استفاده شود. برای مثال:

    fn f<'a, T: 'a>(x: &'a (), y: T) -> impl Sized + 'a {
    //    ~~~~                                 ~~~~
    //    ^                     This is the outlives trick.
    //    |
    // This bound is needed only for the trick.
    (x, y)
//  ~~~~~~
// The hidden type is `(&'a (), T)`.
}

    این ترفند از ترفند Captures کمتر پیچیده و پرزرق‌وبرق بود، اما درستی کمتری هم داشت. همان‌طور که در مثال بالا می‌بینیم، با اینکه هر مؤلفهٔ طول عمر درون T مستقل از طول عمر 'a است، برای اینکه ترفند کار کند ناچاریم قید T: 'a را اضافه کنیم. این کار محدودیت‌های بی‌مورد و شگفت‌آوری برای فراخواننده‌ها ایجاد می‌کرد.

    با استفاده از capture دقیق، می‌توانید کد بالا را در همهٔ ویرایش‌ها به‌جای آن این‌گونه بنویسید:

    fn f<T>(x: &(), y: T) -> impl Sized + use<'_, T> {
    (x, y)
}

fn test<'t, 'x>(t: &'t (), x: &'x ()) {
   f(t, x);
}

    در Rust 2024، اغلب می‌توان قید use<..> را به‌طور کامل حذف کرد و کد بالا را می‌توان به‌سادگی این‌گونه نوشت:

    fn f<T>(x: &(), y: T) -> impl Sized {
    (x, y)
}

fn test<'t, 'x>(t: &'t (), x: &'x ()) {
   f(t, x);
}

    برای این کار مهاجرت خودکاری وجود ندارد و ترفند outlives همچنان در Rust 2024 کار می‌کند، اما ممکن است بخواهید مهاجرت دستی کد را از این ترفند قدیمی در نظر بگیرید.
