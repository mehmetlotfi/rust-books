    احراز هویت Git

    به‌طور پیش‌فرض، Cargo هنگام استفاده از وابستگی‌ها و رجیستری‌های git، احراز هویت را به git واگذار می‌کند. این پیوست اطلاعاتی دربارهٔ راه‌اندازی احراز هویت git به روشی دارد که با Cargo کار کند، زمانی که net.git-fetch-with-cli غیرفعال است،

    Note

    Cargo برای وابستگی‌های git عمومی به احراز هویت نیاز ندارد؛ بنابراین اگر در چنین موردی با خطای احراز هویت روبه‌رو شدید، مطمئن شوید که URL درست است.

    احراز هویت HTTPS

    احراز هویت HTTPS به سازوکار credential.helper نیاز دارد. چندین credential helper وجود دارد و شما آن را که می‌خواهید استفاده کنید در فایل پیکربندی سراسری git خود مشخص می‌کنید.

    # ~/.gitconfig

[credential]
helper = store

    Cargo گذرواژه نمی‌پرسد، بنابراین برای بیشتر helper‌ها لازم است پیش از اجرای Cargo نام کاربری/گذرواژهٔ اولیه را به helper بدهید. یک راه برای این کار اجرای git clone روی مخزن git خصوصی و وارد کردن نام کاربری/گذرواژه است.

    Tip

    کاربران macOS می‌توانند از helper با نام osxkeychain استفاده کنند.
    کاربران Windows می‌توانند از helper با نام GCM استفاده کنند.

    Note

    کاربران Windows باید مطمئن شوند که پوستهٔ sh در PATH آن‌ها در دسترس است. این پوسته معمولاً با نصب Git for Windows در دسترس قرار می‌گیرد.

    احراز هویت SSH

    احراز هویت SSH برای به‌دست‌آوردن کلید SSH به اجرای ssh-agent نیاز دارد. مطمئن شوید متغیرهای محیطی مناسب تنظیم شده‌اند (SSH_AUTH_SOCK در بیشتر سیستم‌های شبه‌یونیکس) و کلیدهای درست (با ssh-add) اضافه شده‌اند.

    Windows می‌تواند از Pageant (بخشی از PuTTY) یا ssh-agent استفاده کند. برای استفاده از ssh-agent، Cargo باید از OpenSSH‌ای استفاده کند که به‌عنوان بخشی از Windows توزیع می‌شود، زیرا Cargo از سوکت‌های دامنهٔ یونیکس شبیه‌سازی‌شده‌ای که MinGW یا Cygwin استفاده می‌کنند پشتیبانی نمی‌کند. اطلاعات بیشتر دربارهٔ نصب در Windows را می‌توانید در مستندات نصب Microsoft بیابید و صفحهٔ مدیریت کلید دستورالعمل‌هایی دربارهٔ نحوهٔ راه‌اندازی ssh-agent و افزودن کلیدها دارد.

    Note

    Cargo از نشانی‌های SSH کوتاه‌شدهٔ git مانند git@example.com:user/repo.git پشتیبانی نمی‌کند. از یک نشانی SSH کامل مانند ssh://git@example.com/user/repo.git استفاده کنید.

    Note

    فایل‌های پیکربندی SSH (مانند ~/.ssh/config در OpenSSH) توسط کتابخانهٔ SSH داخلی Cargo استفاده نمی‌شوند. نیازهای پیشرفته‌تر باید از net.git-fetch-with-cli استفاده کنند.

    Known host‌های SSH

    هنگام اتصال به یک میزبان SSH، Cargo باید هویت میزبان را با استفاده از «known hosts» که فهرستی از کلیدهای میزبان است راستی‌آزمایی کند. Cargo می‌تواند این known host‌ها را در فایل‌های known_hosts به سبک OpenSSH که در مکان‌های استاندارد خود قرار دارند جست‌وجو کند (.ssh/known_hosts در دایرکتوری خانگی شما، یا /etc/ssh/ssh_known_hosts در پلتفرم‌های شبه‌یونیکس یا %PROGRAMDATA%\ssh\ssh_known_hosts در Windows). اطلاعات بیشتر دربارهٔ این فایل‌ها را می‌توانید در صفحهٔ man مربوط به sshd بیابید. همچنین می‌توان کلیدها را در یک فایل پیکربندی Cargo با net.ssh.known-hosts تنظیم کرد.

    اگر پیش از پیکربندی known host‌ها به یک میزبان SSH متصل شوید، Cargo پیام خطایی نمایش می‌دهد که نحوهٔ افزودن کلید میزبان را توضیح می‌دهد. این پیام شامل یک «fingerprint» نیز هست که هش کوچک‌تری از کلید میزبان است و راستی‌آزمایی بصری آن باید آسان‌تر باشد. مدیر سرور می‌تواند fingerprint را با اجرای ssh-keygen روی کلید عمومی به‌دست آورد (برای مثال، ssh-keygen -l -f /etc/ssh/ssh_host_ecdsa_key.pub). سایت‌های شناخته‌شده ممکن است fingerprint‌های خود را در وب منتشر کنند؛ برای مثال GitHub آن‌ها را در https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints منتشر کرده است.

    Cargo همراه با کلیدهای میزبان github.com به‌صورت داخلی عرضه می‌شود. اگر این کلیدها روزی تغییر کنند، می‌توانید کلیدهای جدید را به فایل پیکربندی یا فایل known_hosts اضافه کنید.

    Warning

    Cargo از نشانگرهای @cert-authority یا @revoked در فایل‌های known_hosts پشتیبانی نمی‌کند. برای استفاده از این قابلیت، از net.git-fetch-with-cli استفاده کنید. این نکته وقتی هم که کلاینت SSH مربوط به Cargo آن‌طور که انتظار دارید رفتار نمی‌کند مفید است.
