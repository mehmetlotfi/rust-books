    واژه‌نامه

    Artifact

    یک artifact فایل یا مجموعه‌ای از فایل‌هاست که در نتیجهٔ فرایند کامپایل ایجاد می‌شود. این شامل کتابخانه‌های قابل لینک، فایل‌های باینری اجرایی و مستندات تولیدشده است.

    Cargo

    Cargo مدیر بستهٔ Rust و موضوع اصلی این کتاب است.

    Cargo.lock

    به lock file مراجعه کنید.

    Cargo.toml

    به manifest مراجعه کنید.

    Crate

    یک crate در Rust یا یک کتابخانه است یا یک برنامهٔ اجرایی؛ این دو به ترتیب library crate و binary crate نامیده می‌شوند.

    هر هدفی که برای یک بستهٔ Cargo تعریف شود یک crate است.

    به‌طور غیردقیق، واژهٔ crate می‌تواند به کد منبع هدف یا به artifact کامپایل‌شده‌ای که آن هدف تولید می‌کند اشاره داشته باشد. همچنین می‌تواند به یک بستهٔ فشرده‌شده اشاره کند که از یک رجیستری دریافت می‌شود.

    کد منبع یک crate مشخص ممکن است به ماژول‌ها تقسیم شود.

    Edition

    یک edition در Rust نقطهٔ عطفی در توسعهٔ زبان Rust است. edition یک بسته در manifest فایل Cargo.toml مشخص می‌شود و هر هدف می‌تواند مشخص کند از کدام edition استفاده می‌کند. برای اطلاعات بیشتر به راهنمای ویرایش‌ها مراجعه کنید.

    Feature

    معنای feature به بافت بستگی دارد:

    • یک feature پرچمی نام‌دار است که کامپایل شرطی را ممکن می‌کند. یک feature می‌تواند به یک وابستگی اختیاری یا به نامی دلخواه اشاره کند که در manifest فایل Cargo.toml تعریف شده و درون کد منبع قابل بررسی است.

    • Cargo پرچم‌های feature ناپایدار دارد که می‌توان از آن‌ها برای فعال‌کردن رفتار آزمایشی خود Cargo استفاده کرد.

    • کامپایلر Rust و Rustdoc پرچم‌های ویژگی ناپایدار مخصوص به خود را دارند (به کتاب Unstable و کتاب Rustdoc مراجعه کنید).

    • هدف‌های CPU دارای target feature‌ها هستند که قابلیت‌های یک CPU را مشخص می‌کنند.

    Index

    index فهرست قابل جست‌وجوی crate‌ها در یک رجیستری است.

    Lock file

    lock file با نام Cargo.lock فایلی است که نسخهٔ دقیق هر وابستگی را که در یک workspace یا بسته استفاده می‌شود ثبت می‌کند. این فایل به‌طور خودکار توسط Cargo تولید می‌شود. به Cargo.toml در برابر Cargo.lock مراجعه کنید.

    Manifest

    یک manifest توصیف یک بسته یا یک workspace در فایلی به نام Cargo.toml است.

    یک virtual manifest فایل Cargo.toml ای است که فقط یک workspace را توصیف می‌کند و شامل هیچ بسته‌ای نیست.

    عضو (Member)

    یک عضو بسته‌ای است که به یک workspace تعلق دارد.

    ماژول (Module)

    سیستم ماژول Rust برای سازمان‌دهی کد در واحدهای منطقی به نام ماژول‌ها به کار می‌رود که فضای نام مجزایی را درون کد فراهم می‌کنند.

    کد منبع یک crate مشخص ممکن است به یک یا چند ماژول جداگانه تقسیم شود. این کار معمولاً برای سازمان‌دهی کد در حوزه‌هایی با قابلیت‌های مرتبط یا برای کنترل دامنهٔ دید (عمومی/خصوصی) نمادهای موجود در کد منبع (ساختارها، تابع‌ها و غیره) انجام می‌شود.

    فایل Cargo.toml عمدتاً به بسته‌ای که تعریف می‌کند، crate‌های آن و بسته‌های crate‌هایی که به آن‌ها وابسته‌اند می‌پردازد. با این حال، هنگام کار با Rust اصطلاح «ماژول» را بارها خواهید دید، بنابراین باید رابطهٔ آن با یک crate مشخص را درک کنید.

    بسته (Package)

    یک بسته مجموعه‌ای از فایل‌های منبع و یک فایل manifest به نام Cargo.toml است که بسته را توصیف می‌کند. هر بسته یک نام و یک نسخه دارد که برای مشخص‌کردن وابستگی‌ها میان بسته‌ها به کار می‌رود.

    یک بسته شامل چند هدف است که هر کدام یک crate هستند. فایل Cargo.toml نوع crate‌های درون بسته (باینری یا کتابخانه) را همراه با فرادادهٔ هر یک توصیف می‌کند — اینکه هر کدام چگونه ساخته می‌شود، وابستگی‌های مستقیمشان چیست و غیره، همان‌طور که در سراسر این کتاب شرح داده شده است.

    ریشهٔ بسته دایرکتوری‌ای است که manifest فایل Cargo.toml بسته در آن قرار دارد. (با ریشهٔ workspace مقایسه کنید.)

    مشخصات شناسهٔ بسته یا SPEC رشته‌ای است که برای ارجاع یکتا به یک نسخهٔ مشخص از یک بسته از یک منبع مشخص به کار می‌رود.

    پروژه‌های Rust کوچک تا متوسط فقط به یک بسته نیاز دارند، هرچند معمول است که چند crate داشته باشند.

    پروژه‌های بزرگ‌تر ممکن است چند بسته را شامل شوند؛ در این صورت می‌توان از workspace‌های Cargo برای مدیریت وابستگی‌های مشترک و سایر فراداده‌های مرتبط میان بسته‌ها استفاده کرد.

    مدیر بسته (Package manager)

    به‌طور کلی، یک مدیر بسته برنامه‌ای (یا مجموعه‌ای از برنامه‌های مرتبط) در یک اکوسیستم نرم‌افزاری است که فرایند به‌دست‌آوردن، نصب و ارتقای artifact‌ها را خودکار می‌کند. در اکوسیستم یک زبان برنامه‌نویسی، مدیر بسته ابزاری متمرکز بر توسعه‌دهنده است که کارکرد اصلی آن دانلود artifact‌های کتابخانه‌ها و وابستگی‌هایشان از یک مخزن مرکزی است؛ این قابلیت اغلب با توانایی انجام ساخت نرم‌افزار (با فراخوانی کامپایلر مخصوص آن زبان) ترکیب می‌شود.

    Cargo مدیر بستهٔ اکوسیستم Rust است. Cargo وابستگی‌های بستهٔ Rust شما (artifact‌هایی که با نام crate‌ها شناخته می‌شوند) را دانلود می‌کند، بسته‌هایتان را کامپایل می‌کند، بسته‌های قابل توزیع می‌سازد و (به‌صورت اختیاری) آن‌ها را در crates.io، رجیستری بستهٔ جامعهٔ Rust، بارگذاری می‌کند.

    پروژه (Project)

    نام دیگری برای بسته.

    رجیستری (Registry)

    یک رجیستری سرویسی است که مجموعه‌ای از crate‌های قابل دانلود را در خود دارد که می‌توان آن‌ها را به‌عنوان وابستگی برای یک بسته نصب یا استفاده کرد. رجیستری پیش‌فرض در اکوسیستم Rust crates.io است. رجیستری یک index دارد که فهرست همهٔ crate‌ها را در خود دارد و به Cargo می‌گوید crate‌های موردنیاز را چگونه دانلود کند.

    منبع (Source)

    یک منبع ارائه‌دهنده‌ای است که crate‌هایی را در خود دارد که ممکن است به‌عنوان وابستگی در یک بسته گنجانده شوند. چند نوع منبع وجود دارد:

    • منبع رجیستری — به رجیستری مراجعه کنید.
    • منبع رجیستری محلی — مجموعه‌ای از crate‌ها که به‌صورت فایل‌های فشرده روی فایل‌سیستم ذخیره شده‌اند. به منابع رجیستری محلی مراجعه کنید.
    • منبع دایرکتوری — مجموعه‌ای از crate‌ها که به‌صورت فایل‌های فشرده‌نشده روی فایل‌سیستم ذخیره شده‌اند. به منابع دایرکتوری مراجعه کنید.
    • منبع Git — بسته‌هایی که در یک مخزن git قرار دارند (مانند یک وابستگی git یا منبع git).
    • منبع Git — بسته‌هایی که در یک مخزن git قرار دارند (مانند یک وابستگی git یا منبع git).

    برای اطلاعات بیشتر به جایگزینی منبع مراجعه کنید.

    Spec

    به مشخصات شناسهٔ بسته مراجعه کنید.

    هدف (Target)

    معنای اصطلاح هدف به بافت بستگی دارد:

    • هدف Cargo — بسته‌های Cargo از هدف‌هایی تشکیل می‌شوند که با artifact‌هایی که تولید خواهند شد متناظرند. بسته‌ها می‌توانند هدف‌های کتابخانه، باینری، مثال، آزمون و benchmark داشته باشند. فهرست هدف‌ها در manifest فایل Cargo.toml پیکربندی می‌شود و اغلب به‌طور خودکار از چیدمان دایرکتوری فایل‌های منبع استنباط می‌شود.

    • دایرکتوری target — Cargo artifact‌های ساخته‌شده را در دایرکتوری target قرار می‌دهد. به‌طور پیش‌فرض این دایرکتوری‌ای به نام target در ریشهٔ workspace است، یا در ریشهٔ بسته اگر از workspace استفاده نشود. این دایرکتوری را می‌توان با گزینهٔ خط فرمان --target-dir، با متغیر محیطی CARGO_TARGET_DIR یا با گزینهٔ پیکربندی build.target-dir تغییر داد. برای اطلاعات بیشتر به مستندات کش ساخت مراجعه کنید.

    • معماری هدف — سیستم‌عامل و معماری ماشین برای artifact‌های ساخته‌شده معمولاً هدف نامیده می‌شود.

    • target tuple — tuple قالبی مشخص برای تعیین معماری هدف است. tuple‌ها ممکن است target tuple نامیده شوند که معماری artifact تولیدشده است، و host tuple که معماری‌ای است که کامپایلر روی آن اجرا می‌شود. target tuple را می‌توان با گزینهٔ خط فرمان --target یا با گزینهٔ پیکربندی build.target مشخص کرد. قالب کلی tuple <arch><sub>-<vendor>-<sys>-<abi> است که در آن:

      • arch = معماری پایهٔ CPU، برای مثال x86_64، i686، arm، thumb، mips و غیره.
      • sub = زیرمعماری CPU، برای مثال arm دارای v7، v7s، v5te و غیره است.
      • vendor = سازنده، برای مثال unknown، apple، pc، nvidia و غیره.
      • sys = نام سیستم، برای مثال linux، windows، darwin و غیره. none معمولاً برای bare-metal بدون سیستم‌عامل به کار می‌رود.
      • abi = ABI، برای مثال gnu، android، eabi و غیره.

      برخی پارامترها ممکن است حذف شوند. برای دیدن فهرست هدف‌های پشتیبانی‌شده دستور rustc --print target-list را اجرا کنید.

    هدف‌های آزمون (Test Targets)

    هدف‌های آزمون در Cargo باینری‌هایی تولید می‌کنند که به راستی‌آزمایی عملکرد صحیح و درستی کد کمک می‌کنند. دو نوع artifact آزمون وجود دارد:

    • آزمون واحد (Unit test) — یک آزمون واحد باینری اجرایی‌ای است که مستقیماً از یک هدف کتابخانه یا باینری کامپایل می‌شود. این باینری کل محتوای کد کتابخانه یا باینری را در خود دارد و تابع‌های دارای حاشیه‌نویسی #[test] را اجرا می‌کند که برای راستی‌آزمایی واحدهای منفرد کد در نظر گرفته شده‌اند.
    • هدف آزمون یکپارچگی (Integration test target) — یک هدف آزمون یکپارچگی باینری اجرایی‌ای است که از یک هدف آزمون کامپایل می‌شود؛ هدف آزمون crate مجزایی است که کد منبعش در دایرکتوری tests قرار دارد یا با جدول [[test]] در manifest فایل Cargo.toml مشخص شده است. این هدف فقط برای آزمودن API عمومی یک کتابخانه یا اجرای یک باینری برای راستی‌آزمایی عملکرد آن در نظر گرفته شده است.

    Workspace

    یک workspace مجموعه‌ای از یک یا چند بسته است که حل وابستگی مشترک (با یک lock file مشترک Cargo.lock)، دایرکتوری خروجی و تنظیمات گوناگونی مانند profile‌ها را با هم به اشتراک می‌گذارند.

    یک virtual workspace workspace ای است که Cargo.toml ریشهٔ آن manifest ای است که بسته‌ای تعریف نمی‌کند و فقط اعضای workspace را فهرست می‌کند.

    ریشهٔ workspace دایرکتوری‌ای است که فایل Cargo.toml manifest مربوط به workspace در آن قرار دارد. (با ریشهٔ بسته مقایسه کنید.)
