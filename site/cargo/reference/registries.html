    رجیستری‌ها

    Cargo، crateها را از یک «رجیستری» (registry) نصب می‌کند و وابستگی‌ها را از آن دریافت می‌کند. رجیستری پیش‌فرض crates.io است. هر رجیستری شامل یک «ایندکس» (index) است که فهرستی قابل‌جست‌وجو از crateهای موجود را در بر دارد. یک رجیستری همچنین می‌تواند یک API وب فراهم کند تا انتشار crateهای جدید مستقیماً از Cargo پشتیبانی شود.

    Note

    اگر به آینه‌سازی (mirroring) یا vendor کردن یک رجیستری موجود علاقه دارید، جایگزینی منبع را ببینید.

    اگر در حال پیاده‌سازی یک سرور رجیستری هستید، برای جزئیات بیشتر دربارهٔ پروتکل میان Cargo و رجیستری، اجرای یک رجیستری را ببینید.

    اگر از رجیستری‌ای استفاده می‌کنید که احراز هویت لازم دارد، احراز هویت رجیستری را ببینید. اگر در حال پیاده‌سازی یک credential provider هستید، برای جزئیات پروتکل credential provider را ببینید.

    استفاده از یک رجیستری جایگزین

    برای استفاده از رجیستری‌ای غیر از crates.io، نام و URL ایندکس آن رجیستری باید به فایل .cargo/config.toml اضافه شود. جدول registries برای هر رجیستری یک کلید دارد، برای مثال:

    [registries]
my-registry = { index = "https://my-intranet:8080/git/index" }

    کلید index باید URL یک مخزن git حاوی ایندکس رجیستری یا یک URL رجیستری sparse در Cargo با پیشوند sparse+ باشد.

    سپس یک crate می‌تواند با مشخص کردن کلید registry و مقداری برابر نام رجیستری در مدخل آن وابستگی در Cargo.toml، به یک crate از رجیستری دیگر وابسته شود:

    # Sample Cargo.toml
[package]
name = "my-project"
version = "0.1.0"
edition = "2024"

[dependencies]
other-crate = { version = "1.0", registry = "my-registry" }

    مانند اغلب مقادیر پیکربندی، ایندکس را می‌توان به‌جای فایل پیکربندی با یک متغیر محیطی مشخص کرد. برای مثال، تنظیم متغیر محیطی زیر همان نتیجهٔ تعریف در یک فایل پیکربندی را خواهد داشت:

    CARGO_REGISTRIES_MY_REGISTRY_INDEX=https://my-intranet:8080/git/index

    Note

    (https://crates.io/) بسته‌هایی را که به crateهای رجیستری‌های دیگر وابسته‌اند نمی‌پذیرد.

    انتشار در یک رجیستری جایگزین

    اگر رجیستری از دسترسی API وب پشتیبانی کند، بسته‌ها را می‌توان مستقیماً از Cargo در رجیستری منتشر کرد. چند دستور Cargo مانند cargo publish پرچم خط فرمان --registry را می‌گیرند تا مشخص کنند از کدام رجیستری استفاده شود. برای مثال، برای انتشار بستهٔ موجود در پوشهٔ جاری:

    1. cargo login --registry=my-registry

      این کار فقط یک بار لازم است. باید توکن API محرمانه‌ای را که از وب‌سایت رجیستری گرفته‌اید وارد کنید. به‌طور جایگزین، می‌توان توکن را مستقیماً با پرچم خط فرمان --token یا با یک متغیر محیطی که نام رجیستری را در خود دارد، مانند CARGO_REGISTRIES_MY_REGISTRY_TOKEN، به دستور publish داد.

    2. cargo publish --registry=my-registry

    به‌جای اینکه همیشه گزینهٔ خط فرمان --registry را بدهید، می‌توان رجیستری پیش‌فرض را در .cargo/config.toml با کلید registry.default تنظیم کرد. برای مثال:

    [registry]
default = "my-registry"

    تنظیم کلید package.publish در manifest فایل Cargo.toml محدود می‌کند که بسته مجاز است در کدام رجیستری‌ها منتشر شود. این برای جلوگیری از انتشار تصادفی یک بستهٔ کدبسته (closed-source) در crates.io مفید است. مقدار می‌تواند فهرستی از نام رجیستری‌ها باشد، برای مثال:

    [package]
# ...
publish = ["my-registry"]

    مقدار publish همچنین می‌تواند false باشد تا هرگونه انتشار محدود شود، که معادل یک فهرست خالی است.

    اطلاعات احراز هویتی که cargo login ذخیره می‌کند در فایل credentials.toml در پوشهٔ خانگی Cargo (پیش‌فرض $HOME/.cargo) نگهداری می‌شود. این فایل برای هر رجیستری یک جدول جداگانه دارد، برای مثال:

    [registries.my-registry]
token = "854DvwSlUwEHtIo3kWy6x7UCPKHfzCmy"

    پروتکل‌های رجیستری

    Cargo از دو پروتکل رجیستری راه‌دور پشتیبانی می‌کند: git و sparse. اگر URL ایندکس رجیستری با sparse+ شروع شود، Cargo از پروتکل sparse استفاده می‌کند. در غیر این صورت Cargo از پروتکل git استفاده می‌کند.

    پروتکل git فرادادهٔ ایندکس را در یک مخزن git ذخیره می‌کند و Cargo باید کل مخزن را کلون کند.

    پروتکل sparse فایل‌های فراداده را یک‌به‌یک با درخواست‌های ساده HTTP دریافت می‌کند. از آنجا که Cargo فقط فرادادهٔ crateهای مرتبط را دانلود می‌کند، پروتکل sparse می‌تواند زمان و پهنای باند قابل‌توجهی صرفه‌جویی کند.

    رجیستری crates.io از هر دو پروتکل پشتیبانی می‌کند. پروتکل crates.io از طریق کلید پیکربندی registries.crates-io.protocol کنترل می‌شود.
