    Web API

    یک رجیستری می‌تواند در مکانی که در config.json تعریف شده است یک رابط برنامه‌نویسی وب (Web API) ارائه کند تا از هر یک از اقدام‌های فهرست‌شده در زیر پشتیبانی کند.

    Cargo برای درخواست‌هایی که به احراز هویت نیاز دارند، سرآیند Authorization را می‌فرستد. مقدار این سرآیند همان توکن API است. اگر توکن معتبر نباشد، سرور باید با کد پاسخ 403 جواب دهد. انتظار می‌رود کاربران برای دریافت توکن به وب‌سایت رجیستری مراجعه کنند، و Cargo می‌تواند توکن را با دستور cargo login یا با ارسال آن در خط فرمان ذخیره کند.

    پاسخ‌ها برای موفقیت از کد پاسخ 2xx استفاده می‌کنند. خطاها باید از کد پاسخ مناسبی مانند 404 استفاده کنند. پاسخ‌های ناموفق باید یک شیء JSON با ساختار زیر داشته باشند:

    {
    // Array of errors to display to the user.
    "errors": [
        {
            // The error message as a string.
            "detail": "error message text"
        }
    ]
}

    اگر پاسخ این ساختار را داشته باشد، Cargo پیام تفصیلی را به کاربر نمایش می‌دهد، حتی اگر کد پاسخ 200 باشد. اگر کد پاسخ نشان‌دهندهٔ خطا باشد و محتوا این ساختار را نداشته باشد، Cargo پیامی را به کاربر نمایش می‌دهد که برای کمک به اشکال‌زدایی خطای سرور در نظر گرفته شده است. سروری که یک شیء errors برمی‌گرداند به رجیستری اجازه می‌دهد پیام خطایی دقیق‌تر و کاربرمحورتر ارائه کند.

    برای سازگاری با نسخه‌های قبلی، سرورها باید هر پارامتر پرس‌وجو یا فیلد JSON غیرمنتظره را نادیده بگیرند. اگر یک فیلد JSON وجود نداشته باشد، باید فرض شود که null است. نقاط پایانی (endpoint) با مؤلفهٔ v1 در مسیر نسخه‌بندی می‌شوند، و در صورتی که در آینده به راهکارهای جایگزین برای سازگاری با نسخه‌های قبلی نیاز باشد، مدیریت آن‌ها بر عهدهٔ Cargo است.

    Cargo سرآیند User-Agent را برای همهٔ درخواست‌ها روی نسخهٔ Cargo تنظیم می‌کند، مانند cargo/1.32.0 (8610973aa 2019-01-02). کاربر می‌تواند این مقدار را در یک مقدار پیکربندی تغییر دهد. این قابلیت در نسخهٔ 1.29 اضافه شد.

    سایر سرآیندها بسته به نقطهٔ پایانی متفاوت‌اند و در ادامه مستند شده‌اند.

    انتشار (Publish)

    • نقطهٔ پایانی: /api/v1/crates/new
    • متد: PUT
    • احراز هویت: ارسال می‌شود
    • سرآیندها:
      • Content-Type: application/octet-stream
      • Accept: application/json
    • بدنه: ارسال می‌شود (در ادامه ببینید)

    نقطهٔ پایانی انتشار برای انتشار نسخهٔ جدیدی از یک crate استفاده می‌شود. سرور باید crate را اعتبارسنجی کند، آن را برای دانلود در دسترس قرار دهد و به ایندکس اضافه کند.

    لازم نیست ایندکس پیش از ارسال پاسخ موفق به‌روزرسانی شده باشد. پس از یک پاسخ موفق، Cargo برای مدت کوتاهی ایندکس را بررسی می‌کند تا ببیند crate جدید اضافه شده است یا نه. اگر crate پس از مدت کوتاهی در ایندکس ظاهر نشود، Cargo یک هشدار نمایش می‌دهد تا به کاربر اطلاع دهد که crate جدید هنوز در دسترس نیست.

    بدنهٔ دادهٔ ارسالی از طرف Cargo به این صورت است:

    • یک عدد صحیح بدون علامت ۳۲ بیتی به‌صورت little-endian که طول داده‌های JSON را نشان می‌دهد.
    • فراداده‌های بسته به‌صورت یک شیء JSON.
    • یک عدد صحیح بدون علامت ۳۲ بیتی به‌صورت little-endian که طول فایل .crate را نشان می‌دهد.
    • فایل .crate.

    آنچه در ادامه می‌آید نمونه‌ای توضیح‌دار از شیء JSON است. برخی یادداشت‌ها دربارهٔ محدودیت‌هایی که crates.io اعمال می‌کند صرفاً برای نشان دادن پیشنهادهایی دربارهٔ انواع اعتبارسنجی‌هایی که می‌توان انجام داد آمده‌اند و نباید فهرستی کامل از محدودیت‌های crates.io تلقی شوند.

    {
    // The name of the package.
    "name": "foo",
    // The version of the package being published.
    "vers": "0.1.0",
    // Array of direct dependencies of the package.
    "deps": [
        {
            // Name of the dependency.
            // If the dependency is renamed from the original package name,
            // this is the original name. The new package name is stored in
            // the `explicit_name_in_toml` field.
            "name": "rand",
            // The semver requirement for this dependency.
            "version_req": "^0.6",
            // Array of features (as strings) enabled for this dependency.
            "features": ["i128_support"],
            // Boolean of whether or not this is an optional dependency.
            "optional": false,
            // Boolean of whether or not default features are enabled.
            "default_features": true,
            // The target platform for the dependency.
            // null if not a target dependency.
            // Otherwise, a string such as "cfg(windows)".
            "target": null,
            // The dependency kind.
            // "dev", "build", or "normal".
            "kind": "normal",
            // The URL of the index of the registry where this dependency is
            // from as a string. If not specified or null, it is assumed the
            // dependency is in the current registry.
            "registry": null,
            // If the dependency is renamed, this is a string of the new
            // package name. If not specified or null, this dependency is not
            // renamed.
            "explicit_name_in_toml": null,
        }
    ],
    // Set of features defined for the package.
    // Each feature maps to an array of features or dependencies it enables.
    // Cargo does not impose limitations on feature names, but crates.io
    // requires alphanumeric ASCII, `_` or `-` characters.
    "features": {
        "extras": ["rand/simd_support"]
    },
    // List of strings of the authors.
    // May be empty.
    "authors": ["Alice <a@example.com>"],
    // Description field from the manifest.
    // May be null. crates.io requires at least some content.
    "description": null,
    // String of the URL to the website for this package's documentation.
    // May be null.
    "documentation": null,
    // String of the URL to the website for this package's home page.
    // May be null.
    "homepage": null,
    // String of the content of the README file.
    // May be null.
    "readme": null,
    // String of a relative path to a README file in the crate.
    // May be null.
    "readme_file": null,
    // Array of strings of keywords for the package.
    "keywords": [],
    // Array of strings of categories for the package.
    "categories": [],
    // String of the license for the package.
    // May be null. crates.io requires either `license` or `license_file` to be set.
    "license": null,
    // String of a relative path to a license file in the crate.
    // May be null.
    "license_file": null,
    // String of the URL to the website for the source repository of this package.
    // May be null.
    "repository": null,
    // Optional object of "status" badges. Each value is an object of
    // arbitrary string to string mappings.
    // crates.io has special interpretation of the format of the badges.
    "badges": {
        "travis-ci": {
            "branch": "master",
            "repository": "rust-lang/cargo"
        }
    },
    // The `links` string value from the package's manifest, or null if not
    // specified. This field is optional and defaults to null.
    "links": null,
    // The minimal supported Rust version (optional)
    // This must be a valid version requirement without an operator (e.g. no `=`)
    "rust_version": null
}

    یک پاسخ موفق شامل شیء JSON زیر است:

    {
    // Optional object of warnings to display to the user.
    "warnings": {
        // Array of strings of categories that are invalid and ignored.
        "invalid_categories": [],
        // Array of strings of badge names that are invalid and ignored.
        "invalid_badges": [],
        // Array of strings of arbitrary warnings to display to the user.
        "other": []
    }
}

    Yank

    • نقطهٔ پایانی: /api/v1/crates/{crate_name}/{version}/yank
    • متد: DELETE
    • احراز هویت: ارسال می‌شود
    • سرآیندها:
      • Accept: application/json
    • بدنه: ندارد

    نقطهٔ پایانی yank فیلد yank مربوط به نسخهٔ داده‌شدهٔ یک crate را در ایندکس روی true تنظیم می‌کند.

    یک پاسخ موفق شامل شیء JSON زیر است:

    {
    // Indicates the yank succeeded, always true.
    "ok": true,
}

    • احراز هویت: ارسال می‌شود
    • سرآیندها:
      • Accept: application/json
    • بدنه: ندارد

    نقطهٔ پایانی unyank فیلد yank مربوط به نسخهٔ داده‌شدهٔ یک crate را در ایندکس روی false تنظیم می‌کند.

    یک پاسخ موفق شامل شیء JSON زیر است:

}

    مالکان (Owners)

    Cargo مفهوم ذاتی برای کاربران و مالکان ندارد، اما دستور owner را فراهم می‌کند تا به مدیریت اینکه چه کسانی اجازهٔ کنترل یک crate را دارند کمک کند. اینکه کاربران و مالکان دقیقاً چگونه مدیریت شوند به عهدهٔ رجیستری است. برای توضیح اینکه crates.io مالکان را از طریق کاربران و تیم‌های GitHub چگونه مدیریت می‌کند، مستندات انتشار را ببینید.

    مالکان: فهرست (List)

    • نقطهٔ پایانی: /api/v1/crates/{crate_name}/owners
    • متد: GET
    • احراز هویت: ارسال می‌شود
    • سرآیندها:
      • Accept: application/json
    • بدنه: ندارد

    نقطهٔ پایانی owners فهرستی از مالکان crate را برمی‌گرداند.

    یک پاسخ موفق شامل شیء JSON زیر است:

    {
    // Array of owners of the crate.
    "users": [
        {
            // Unique unsigned 32-bit integer of the owner.
            "id": 70,
            // The unique username of the owner.
            "login": "github:rust-lang:core",
            // Name of the owner.
            // This is optional and may be null.
            "name": "Core",
        }
    ]
}

    مالکان: افزودن (Add)

    • نقطهٔ پایانی: /api/v1/crates/{crate_name}/owners
    • متد: PUT
    • احراز هویت: ارسال می‌شود
    • سرآیندها:
      • Content-Type: application/json
      • Accept: application/json
    • بدنه: ارسال می‌شود (در ادامه ببینید)

    یک درخواست PUT درخواستی را برای افزودن مالکی جدید به یک crate به رجیستری می‌فرستد. نحوهٔ رسیدگی به این درخواست به عهدهٔ رجیستری است. برای مثال، crates.io برای کاربر یک دعوت‌نامه می‌فرستد که باید پیش از افزوده شدن آن را بپذیرد.

    درخواست باید شامل شیء JSON زیر باشد:

    {
    // Array of `login` strings of owners to add.
    "users": ["login_name"]
}

    یک پاسخ موفق شامل شیء JSON زیر است:

    {
    // Indicates the add succeeded, always true.
    "ok": true,
    // A string to be displayed to the user.
    "msg": "user ehuss has been invited to be an owner of crate cargo"
}

    مالکان: حذف (Remove)

    • نقطهٔ پایانی: /api/v1/crates/{crate_name}/owners
    • متد: DELETE
    • احراز هویت: ارسال می‌شود
    • سرآیندها:
      • Content-Type: application/json
      • Accept: application/json
    • بدنه: ارسال می‌شود (در ادامه ببینید)

    یک درخواست DELETE مالکی را از یک crate حذف می‌کند. درخواست باید شامل شیء JSON زیر باشد:

    {
    // Array of `login` strings of owners to remove.
    "users": ["login_name"]
}

    یک پاسخ موفق شامل شیء JSON زیر است:

    {
    // Indicates the remove succeeded, always true.
    "ok": true
    // A string to be displayed to the user. Currently ignored by cargo.
    "msg": "owners successfully removed",
}

    جست‌وجو (Search)

    • نقطهٔ پایانی: /api/v1/crates
    • متد: GET
    • احراز هویت: ارسال نمی‌شود
    • سرآیندها:
      • Accept: application/json
    • بدنه: ندارد
    • پارامترهای پرس‌وجو:
      • q: رشتهٔ پرس‌وجوی جست‌وجو.
      • per_page: تعداد نتایج؛ پیش‌فرض 10 و حداکثر 100.

    درخواست جست‌وجو با استفاده از معیارهایی که در سرور تعریف شده‌اند، crateها را جست‌وجو می‌کند.

    یک پاسخ موفق شامل شیء JSON زیر است:

    {
    // Array of results.
    "crates": [
        {
            // Name of the crate.
            "name": "rand",
            // The highest version available.
            "max_version": "0.6.1",
            // Textual description of the crate.
            "description": "Random number generators and other randomness functionality.\n",
        }
    ],
    "meta": {
        // Total number of results available on the server.
        "total": 119
    }
}

    ورود (Login)

    • نقطهٔ پایانی: /me

    نقطهٔ پایانی «login» یک درخواست واقعی API نیست. این نقطه صرفاً برای دستور cargo login وجود دارد تا نشانی URL را نمایش دهد و به کاربر بگوید برای ورود و دریافت توکن API آن را در یک مرورگر وب باز کند.
