    پروتکل ارائه‌دهندهٔ اعتبارنامه

    این سند اطلاعاتی برای ساخت یک ارائه‌دهندهٔ اعتبارنامه (credential provider) برای Cargo ارائه می‌دهد. برای اطلاعات دربارهٔ راه‌اندازی یا استفاده از یک ارائه‌دهندهٔ اعتبارنامه، احراز هویت رجیستری را ببینید.

    هنگام استفاده از یک ارائه‌دهندهٔ اعتبارنامهٔ خارجی، Cargo با ارائه‌دهندهٔ اعتبارنامه از طریق پیام‌های stdin/stdout ارتباط برقرار می‌کند که به‌صورت خطوط تکی JSON ارسال می‌شوند.

    Cargo ارائه‌دهندهٔ اعتبارنامه را همیشه با آرگومان --cargo-plugin اجرا می‌کند. این کار به فایل اجرایی ارائه‌دهندهٔ اعتبارنامه امکان می‌دهد قابلیت‌هایی فراتر از نیاز Cargo داشته باشد. آرگومان‌های اضافی از طریق فیلد args در JSON گنجانده می‌شوند.

    پیام‌های JSON

    در پیام‌های JSON این سند برای خوانایی خط جدید اضافه شده است. پیام‌های واقعی نباید شامل خط جدید باشند.

    پیام سلام اعتبارنامه

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: شناسایی پروتکل‌های پشتیبانی‌شده هنگام راه‌اندازی فرایند
    {
    "v":[1]
}

    درخواست‌هایی که Cargo ارسال می‌کند شامل فیلد v خواهند بود که روی یکی از نسخه‌های فهرست‌شده در اینجا تنظیم شده است. اگر Cargo از هیچ‌یک از نسخه‌های پیشنهادی ارائه‌دهندهٔ اعتبارنامه پشتیبانی نکند، خطا صادر می‌کند و فرایند اعتبارنامه را خاتمه می‌دهد.

    اطلاعات رجیستری

    • ارسال‌کننده: Cargo خودش یک پیام مستقل نیست. در همهٔ پیام‌هایی که Cargo می‌فرستد به‌عنوان فیلد registry گنجانده می‌شود.
    {
    // Index URL of the registry
    "index-url":"https://github.com/rust-lang/crates.io-index",
    // Name of the registry in configuration (optional)
    "name": "crates-io",
    // HTTP headers received from attempting to access an authenticated registry (optional)
    "headers": ["WWW-Authenticate: cargo"]
}

    درخواست ورود (login)

    • ارسال‌کننده: Cargo
    • هدف: گردآوری و ذخیرهٔ اعتبارنامه‌ها
    {
    // Protocol version
    "v":1,
    // Action to perform: login
    "kind":"login",
    // Registry information (see Registry information)
    "registry":{"index-url":"sparse+https://registry-url/index/", "name": "my-registry"},
    // User-specified token from stdin or command line (optional)
    "token": "<the token value>",
    // URL that the user could visit to get a token (optional)
    "login-url": "http://registry-url/login",
    // Additional command-line args (optional)
    "args":[]
}

    اگر فیلد token تنظیم شده باشد، ارائه‌دهندهٔ اعتبارنامه باید از توکن ارائه‌شده استفاده کند. اگر token تنظیم نشده باشد، ارائه‌دهندهٔ اعتبارنامه باید از کاربر یک توکن بخواهد.

    علاوه بر آرگومان‌هایی که ممکن است در پیکربندی به ارائه‌دهندهٔ اعتبارنامه داده شوند، cargo login از ارسال آرگومان‌های خط فرمان اضافی نیز از طریق cargo login -- <additional args> پشتیبانی می‌کند. این آرگومان‌های اضافی پس از هر آرگومانی که از پیکربندی Cargo آمده باشد، در فیلد args گنجانده می‌شوند.

    درخواست خواندن

    • ارسال‌کننده: Cargo
    • هدف: گرفتن اعتبارنامه برای خواندن اطلاعات crate
    {
    // Protocol version
    "v":1,
    // Request kind: get credentials
    "kind":"get",
    // Action to perform: read crate information
    "operation":"read",
    // Registry information (see Registry information)
    "registry":{"index-url":"sparse+https://registry-url/index/", "name": "my-registry"},
    // Additional command-line args (optional)
    "args":[]
}

    درخواست انتشار

    • ارسال‌کننده: Cargo
    • هدف: گرفتن اعتبارنامه برای انتشار یک crate
    {
    // Protocol version
    "v":1,
    // Request kind: get credentials
    "kind":"get",
    // Action to perform: publish crate
    "operation":"publish",
    // Crate name
    "name":"sample",
    // Crate version
    "vers":"0.1.0",
    // Crate checksum
    "cksum":"...",
    // Registry information (see Registry information)
    "registry":{"index-url":"sparse+https://registry-url/index/", "name": "my-registry"},
    // Additional command-line args (optional)
    "args":[]
}

    پاسخ موفقیت‌آمیز get

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: ارائهٔ اعتبارنامه به Cargo
    {"Ok":{
    // Response kind: this was a get request
    "kind":"get",
    // Token to send to the registry
    "token":"...",
    // Cache control. Can be one of the following:
    // * "never": do not cache
    // * "session": cache for the current cargo session
    // * "expires": cache for the current cargo session until expiration
    "cache":"expires",
    // Unix timestamp (only for "cache": "expires")
    "expiration":1693942857,
    // Is the token operation independent?
    "operation_independent":true
}}

    token به‌عنوان مقدار هدر HTTP با نام Authorization به رجیستری ارسال می‌شود.

    operation_independent نشان می‌دهد که آیا توکن را می‌توان بین عملیات مختلف (مانند انتشار یا واکشی) کش کرد. به‌طور کلی این مقدار باید true باشد، مگر اینکه ارائه‌دهنده بخواهد توکن‌هایی تولید کند که به عملیات مشخصی محدود شده‌اند.

    پاسخ موفقیت‌آمیز login

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: نشان‌دادن موفقیت ورود
    {"Ok":{
    // Response kind: this was a login request
    "kind":"login"
}}

    پاسخ موفقیت‌آمیز logout

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: نشان‌دادن موفقیت خروج
    {"Ok":{
    // Response kind: this was a logout request
    "kind":"logout"
}}

    پاسخ شکست (URL پشتیبانی نمی‌شود)

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: ارائهٔ اطلاعات خطا به Cargo
    {"Err":{
    "kind":"url-not-supported"
}}

    زمانی ارسال می‌شود که ارائه‌دهندهٔ اعتبارنامه طوری طراحی شده باشد که فقط URLهای رجیستری مشخصی را مدیریت کند و URL داده‌شده پشتیبانی نشود. Cargo در صورت وجود، ارائه‌دهندهٔ دیگری را امتحان خواهد کرد.

    پاسخ شکست (یافت نشد)

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: ارائهٔ اطلاعات خطا به Cargo
    {"Err":{
    // Error: The credential could not be found in the provider.
    "kind":"not-found"
}}

    زمانی ارسال می‌شود که اعتبارنامه یافت نشود. این در درخواست‌های get که اعتبارنامه در دسترس نیست، یا درخواست‌های logout که چیزی برای پاک‌کردن یافت نمی‌شود، مورد انتظار است.

    پاسخ شکست (عملیات پشتیبانی نمی‌شود)

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: ارائهٔ اطلاعات خطا به Cargo
    {"Err":{
    // Error: The credential could not be found in the provider.
    "kind":"operation-not-supported"
}}

    زمانی ارسال می‌شود که ارائه‌دهندهٔ اعتبارنامه از عملیات درخواست‌شده پشتیبانی نکند. اگر ارائه‌دهنده فقط از get پشتیبانی کند و درخواست login بیاید، ارائه‌دهنده باید با این خطا پاسخ دهد.

    پاسخ شکست (سایر)

    • ارسال‌کننده: ارائه‌دهندهٔ اعتبارنامه
    • هدف: ارائهٔ اطلاعات خطا به Cargo
    {"Err":{
    // Error: something else has failed
    "kind":"other",
    // Error message string to be displayed
    "message": "free form string error message",
    // Detailed cause chain for the error (optional)
    "caused-by": ["cause 1", "cause 2"]
}}

    نمونهٔ ارتباط برای درخواست توکن جهت خواندن:

    1. Cargo فرایند اعتبارنامه را ایجاد می‌کند و stdin و stdout آن را به دست می‌گیرد.
    2. فرایند اعتبارنامه پیام Hello را به Cargo می‌فرستد javascript { "v": [1] } 
      { "v": [1] }
    3. Cargo پیام CredentialRequest را به فرایند اعتبارنامه می‌فرستد (برای خوانایی خط جدید اضافه شده است). javascript { "v": 1, "kind": "get", "operation": "read", "registry":{"index-url":"sparse+https://registry-url/index/"} } 
      {
    "v": 1,
    "kind": "get",
    "operation": "read",
    "registry":{"index-url":"sparse+https://registry-url/index/"}
}
    4. فرایند اعتبارنامه CredentialResponse را به Cargo می‌فرستد (برای خوانایی خط جدید اضافه شده است). javascript { "token": "...", "cache": "session", "operation_independent": true } 
      {
    "token": "...",
    "cache": "session",
    "operation_independent": true
}
    5. Cargo لولهٔ stdin به ارائه‌دهندهٔ اعتبارنامه را می‌بندد و ارائه‌دهنده خارج می‌شود.
    6. Cargo از توکن در باقی نشست (تا زمان خروج Cargo) هنگام تعامل با این رجیستری استفاده می‌کند.
