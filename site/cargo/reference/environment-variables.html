    Environment Variables

    Cargo تعدادی متغیر محیطی را تنظیم می‌کند و می‌خواند که کد شما می‌تواند آن‌ها را تشخیص دهد یا بازنویسی (override) کند. فهرست زیر متغیرهایی است که Cargo با آن‌ها کار دارد، بر اساس زمان تعامل:

    متغیرهای محیطی‌ای که Cargo می‌خواند

    می‌توانید این متغیرهای محیطی را بازنویسی کنید تا رفتار Cargo را روی سیستم خود تغییر دهید:

    • CARGO_LOG — Cargo برای نمایش پیام‌های لاگ اشکال‌زدایی از crate با نام tracing استفاده می‌کند. می‌توان متغیر محیطی CARGO_LOG را برای فعال‌کردن لاگ اشکال‌زدایی تنظیم کرد، با مقداری مثل trace، debug یا warn. معمولاً فقط هنگام اشکال‌زدایی استفاده می‌شود. برای جزئیات بیشتر لاگ اشکال‌زدایی را ببینید.
    • CARGO_HOME — Cargo یک حافظهٔ پنهان (cache) محلی از فهرست registry و از checkoutهای git مربوط به crateها نگه می‌دارد. به‌طور پیش‌فرض این‌ها زیر $HOME/.cargo ذخیره می‌شوند (در ویندوز %USERPROFILE%\.cargo)، اما این متغیر محل این پوشه را بازنویسی می‌کند. وقتی یک crate در cache قرار گرفت، دستور clean آن را پاک نمی‌کند. برای جزئیات بیشتر راهنما را ببینید.
    • CARGO_TARGET_DIR — محل قرار‌دادن همهٔ آرتیفکت‌های تولیدشده، نسبت به پوشهٔ کاری فعلی. برای تنظیم از طریق config، build.target-dir را ببینید.
    • CARGO — اگر تنظیم شود، Cargo هنگام ساخت crateها و اجرای اسکریپت‌های ساخت و زیردستورهای خارجی، به‌جای تنظیم آن روی مسیر تشخیص‌داده‌شدهٔ خودش، همین مقدار را منتقل می‌کند. این مقدار مستقیماً توسط Cargo اجرا نمی‌شود و باید همیشه به دستوری اشاره کند که دقیقاً مثل cargo رفتار می‌کند، چون مصرف‌کنندگان این متغیر همین انتظار را دارند.
    • RUSTC — Cargo به‌جای اجرای rustc، این کامپایلر مشخص‌شده را اجرا می‌کند. برای تنظیم از طریق config، build.rustc را ببینید.
    • RUSTC_WRAPPER — Cargo به‌جای اجرای مستقیم rustc، این wrapper مشخص‌شده را اجرا می‌کند و فراخوانی rustc را به‌عنوان آرگومان‌های خط فرمان به آن می‌دهد، که اولین آرگومان مسیر rustc واقعی است. برای راه‌اندازی ابزار cache ساخت مثل sccache مفید است. برای تنظیم از طریق config، build.rustc-wrapper را ببینید. تنظیم آن روی رشتهٔ خالی config را بازنویسی می‌کند و Cargo را به حالت بدون wrapper برمی‌گرداند.
    • RUSTC_WORKSPACE_WRAPPER — Cargo به‌جای اجرای مستقیم rustc، برای اعضای workspace این wrapper مشخص‌شده را اجرا می‌کند و فراخوانی rustc را به‌عنوان آرگومان‌های خط فرمان به آن می‌دهد، که اولین آرگومان مسیر rustc واقعی است. در پروژهٔ تک‌بسته‌ای بدون workspace، همان بسته workspace به حساب می‌آید. این متغیر بر هش نام فایل اثر می‌گذارد تا آرتیفکت‌های تولیدشده توسط wrapper جداگانه cache شوند. برای تنظیم از طریق config، build.rustc-workspace-wrapper را ببینید. تنظیم آن روی رشتهٔ خالی config را بازنویسی می‌کند و Cargo را برای اعضای workspace به حالت بدون wrapper برمی‌گرداند. اگر هم RUSTC_WRAPPER و هم RUSTC_WORKSPACE_WRAPPER تنظیم شده باشند، تو در تو اجرا می‌شوند: فراخوانی نهایی $RUSTC_WRAPPER $RUSTC_WORKSPACE_WRAPPER $RUSTC است.
    • RUSTDOC — Cargo به‌جای اجرای rustdoc، این نمونهٔ rustdoc مشخص‌شده را اجرا می‌کند. برای تنظیم از طریق config، build.rustdoc را ببینید.
    • RUSTDOCFLAGS — فهرستی از پرچم‌های سفارشی که با فاصله جدا شده‌اند و به همهٔ فراخوانی‌های rustdoc که Cargo انجام می‌دهد داده می‌شوند. برخلاف cargo rustdoc، این برای دادن یک پرچم به همهٔ نمونه‌های rustdoc مفید است. برای راه‌های بیشتر تنظیم پرچم‌ها build.rustdocflags را ببینید. این رشته با فاصله تقسیم می‌شود؛ برای رمزگذاری مطمئن‌تر چند آرگومان، CARGO_ENCODED_RUSTDOCFLAGS را ببینید.
    • CARGO_ENCODED_RUSTDOCFLAGS — فهرستی از پرچم‌های سفارشی که با 0x1f (جداکنندهٔ واحد ASCII) جدا شده‌اند و به همهٔ فراخوانی‌های rustdoc که Cargo انجام می‌دهد داده می‌شوند.
    • RUSTFLAGS — فهرستی از پرچم‌های سفارشی که با فاصله جدا شده‌اند و به همهٔ فراخوانی‌های کامپایلر که Cargo انجام می‌دهد داده می‌شوند. برخلاف cargo rustc، این برای دادن یک پرچم به همهٔ نمونه‌های کامپایلر مفید است. برای راه‌های بیشتر تنظیم پرچم‌ها build.rustflags را ببینید. این رشته با فاصله تقسیم می‌شود؛ برای رمزگذاری مطمئن‌تر چند آرگومان، CARGO_ENCODED_RUSTFLAGS را ببینید.
    • CARGO_ENCODED_RUSTFLAGS — فهرستی از پرچم‌های سفارشی که با 0x1f (جداکنندهٔ واحد ASCII) جدا شده‌اند و به همهٔ فراخوانی‌های کامپایلر که Cargo انجام می‌دهد داده می‌شوند.
    • CARGO_INCREMENTAL — اگر روی 1 تنظیم شود، Cargo کامپایل افزایشی را برای کامپایل فعلی اجباراً فعال می‌کند و اگر روی 0 باشد آن را اجباراً غیرفعال می‌کند. اگر این متغیر وجود نداشته باشد، پیش‌فرض‌های cargo به‌کار می‌روند. مقدار config با نام build.incremental را هم ببینید.
    • CARGO_CACHE_RUSTC_INFO — اگر روی 0 تنظیم شود، Cargo تلاش نمی‌کند اطلاعات نسخهٔ کامپایلر را cache کند.
    • HTTPS_PROXY یا https_proxy یا http_proxy — پروکسی HTTP مورد استفاده؛ برای جزئیات بیشتر http.proxy را ببینید.
    • HTTP_TIMEOUT — مهلت HTTP بر حسب ثانیه؛ برای جزئیات بیشتر http.timeout را ببینید.
    • TERM — اگر روی dumb تنظیم شود، نوار پیشرفت را غیرفعال می‌کند.
    • BROWSER — مرورگر وبی که برای باز‌کردن مستندات با پرچم --open در cargo doc اجرا می‌شود؛ برای جزئیات بیشتر doc.browser را ببینید.
    • RUSTFMT — cargo fmt به‌جای اجرای rustfmt، این نمونهٔ rustfmt مشخص‌شده را اجرا می‌کند.

    Configuration environment variables

    Cargo برای برخی مقادیر پیکربندی، متغیرهای محیطی را می‌خواند. برای جزئیات بیشتر فصل پیکربندی را ببینید. در خلاصه، متغیرهای محیطی پشتیبانی‌شده عبارت‌اند از:

    • CARGO_ALIAS_<name> — Command aliases, see alias.
    • CARGO_BUILD_WARNINGS — سطح مؤثر هشدارهای lint برای بسته‌های محلی، نگاه کنید به build.warnings.
    • CARGO_BUILD_JOBS — تعداد کارهای موازی، نگاه کنید به build.jobs.
    • CARGO_BUILD_RUSTC — فایل اجرایی rustc، نگاه کنید به build.rustc.
    • CARGO_BUILD_RUSTC_WRAPPER — wrapper مربوط به rustc، نگاه کنید به build.rustc-wrapper.
    • CARGO_BUILD_RUSTC_WORKSPACE_WRAPPER — wrapper مربوط به rustc فقط برای اعضای workspace، نگاه کنید به build.rustc-workspace-wrapper.
    • CARGO_BUILD_RUSTDOC — فایل اجرایی rustdoc، نگاه کنید به build.rustdoc.
    • CARGO_BUILD_TARGET — پلتفرم هدف پیش‌فرض، نگاه کنید به build.target.
    • CARGO_BUILD_TARGET_DIR — پوشهٔ خروجی پیش‌فرض، نگاه کنید به build.target-dir.
    • CARGO_BUILD_BUILD_DIR — پوشهٔ ساخت پیش‌فرض، نگاه کنید به build.build-dir.
    • CARGO_BUILD_PROFILE — profile پیش‌فرض، نگاه کنید به build.profile.
    • CARGO_BUILD_RUSTFLAGS — Extra rustc flags, see build.rustflags.
    • CARGO_BUILD_RUSTDOCFLAGS — پرچم‌های اضافی rustdoc، نگاه کنید به build.rustdocflags.
    • CARGO_BUILD_INCREMENTAL — Incremental compilation, see build.incremental.
    • CARGO_BUILD_DEP_INFO_BASEDIR — پوشهٔ مبنای dep-info، نگاه کنید به build.dep-info-basedir.
    • CARGO_CACHE_AUTO_CLEAN_FREQUENCY — تعیین می‌کند پاک‌سازی خودکار cache هر چند وقت یک‌بار اجرا شود، نگاه کنید به cache.auto-clean-frequency.
    • CARGO_CARGO_NEW_VCS — سیستم کنترل نسخهٔ پیش‌فرض در cargo new، نگاه کنید به cargo-new.vcs.
    • CARGO_CREDENTIAL_ALIAS_<name> — نام‌های مستعار ارائه‌دهندهٔ اعتبارنامه، نگاه کنید به credential-alias.
    • CARGO_FUTURE_INCOMPAT_REPORT_FREQUENCY — هر چند وقت یک‌بار اعلان گزارش ناسازگاری آینده (future incompat) تولید شود، نگاه کنید به future-incompat-report.frequency.
    • CARGO_HTTP_DEBUG — اشکال‌زدایی HTTP را فعال می‌کند، نگاه کنید به http.debug.
    • CARGO_HTTP_PROXY — پروکسی HTTP را فعال می‌کند، نگاه کنید به http.proxy.
    • CARGO_HTTP_TIMEOUT — مهلت HTTP، نگاه کنید به http.timeout.
    • CARGO_HTTP_CAINFO — فایل مرجع صدور گواهی (CA) برای TLS، نگاه کنید به http.cainfo.
    • CARGO_HTTP_PROXY_CAINFO — فایل مرجع صدور گواهی (CA) برای TLS پروکسی، نگاه کنید به http.proxy-cainfo.
    • CARGO_HTTP_CHECK_REVOKE — بررسی ابطال گواهی TLS را غیرفعال می‌کند، نگاه کنید به http.check-revoke.
    • CARGO_HTTP_SSL_VERSION — نسخهٔ TLS مورد استفاده، نگاه کنید به http.ssl-version.
    • CARGO_HTTP_LOW_SPEED_LIMIT — حد سرعت پایین HTTP، نگاه کنید به http.low-speed-limit.
    • CARGO_HTTP_MULTIPLEXING — اینکه آیا از multiplexing در HTTP/2 استفاده شود، نگاه کنید به http.multiplexing.
    • CARGO_HTTP_USER_AGENT — سرایند user-agent در HTTP، نگاه کنید به http.user-agent.
    • CARGO_INSTALL_ROOT — پوشهٔ پیش‌فرض cargo install، نگاه کنید به install.root.
    • CARGO_INSTALL_PROFILE — profile پیش‌فرض، نگاه کنید به install.profile.
    • CARGO_NET_RETRY — تعداد دفعات تلاش مجدد پس از خطاهای شبکه، نگاه کنید به net.retry.
    • CARGO_NET_GIT_FETCH_WITH_CLI — استفاده از فایل اجرایی git برای دریافت را فعال می‌کند، نگاه کنید به net.git-fetch-with-cli.
    • CARGO_NET_OFFLINE — Offline mode, see net.offline.
    • CARGO_PROFILE_<name>_BUILD_OVERRIDE_<key> — بازنویسی profile اسکریپت ساخت، نگاه کنید به profile.<name>.build-override.
    • CARGO_PROFILE_<name>_CODEGEN_UNITS — تنظیم واحدهای تولید کد، نگاه کنید به profile.<name>.codegen-units.
    • CARGO_PROFILE_<name>_DEBUG — چه نوع اطلاعات اشکال‌زدایی گنجانده شود، نگاه کنید به profile.<name>.debug.
    • CARGO_PROFILE_<name>_DEBUG_ASSERTIONS — فعال/غیرفعال‌کردن debug assertions، نگاه کنید به profile.<name>.debug-assertions.
    • CARGO_PROFILE_<name>_INCREMENTAL — فعال/غیرفعال‌کردن کامپایل افزایشی، نگاه کنید به profile.<name>.incremental.
    • CARGO_PROFILE_<name>_LTO — Link-time optimization, see profile.<name>.lto.
    • CARGO_PROFILE_<name>_OVERFLOW_CHECKS — فعال/غیرفعال‌کردن بررسی سرریز، نگاه کنید به profile.<name>.overflow-checks.
    • CARGO_PROFILE_<name>_OPT_LEVEL — تنظیم سطح بهینه‌سازی، نگاه کنید به profile.<name>.opt-level.
    • CARGO_PROFILE_<name>_PANIC — راهبرد panic مورد استفاده، نگاه کنید به profile.<name>.panic.
    • CARGO_PROFILE_<name>_RPATH — گزینهٔ پیوند rpath، نگاه کنید به profile.<name>.rpath.
    • CARGO_PROFILE_<name>_SPLIT_DEBUGINFO — رفتار خروجی فایل‌های اشکال‌زدایی را کنترل می‌کند، نگاه کنید به profile.<name>.split-debuginfo.
    • CARGO_PROFILE_<name>_STRIP — حذف نمادها و/یا debuginfo را کنترل می‌کند، نگاه کنید به profile.<name>.strip.
    • CARGO_REGISTRIES_<name>_CREDENTIAL_PROVIDER — ارائه‌دهندهٔ اعتبارنامه برای یک registry، نگاه کنید به registries.<name>.credential-provider.
    • CARGO_REGISTRIES_<name>_INDEX — نشانی فهرست یک registry، نگاه کنید به registries.<name>.index.
    • CARGO_REGISTRIES_<name>_MIN_PUBLISH_AGE — حداقل سن انتشار بسته‌ها از یک registry، نگاه کنید به registries.<name>.min-publish-age.
    • CARGO_REGISTRIES_<name>_TOKEN — توکن احراز هویت یک registry، نگاه کنید به registries.<name>.token.
    • CARGO_REGISTRIES_CRATES_IO_PROTOCOL — پروتکل دسترسی به crates.io، نگاه کنید به registries.crates-io.protocol.
    • CARGO_REGISTRY_CREDENTIAL_PROVIDER — ارائه‌دهندهٔ اعتبارنامه برای crates.io، نگاه کنید به registry.credential-provider.
    • CARGO_REGISTRY_DEFAULT — registry پیش‌فرض برای پرچم --registry، نگاه کنید به registry.default.
    • CARGO_REGISTRY_GLOBAL_CREDENTIAL_PROVIDERS — ارائه‌دهندگان اعتبارنامه برای registryهایی که ارائه‌دهندهٔ مشخصی ندارند. registry.global-credential-providers را ببینید.
    • CARGO_REGISTRY_GLOBAL_MIN_PUBLISH_AGE — حداقل سن انتشار پیش‌فرض بسته‌ها از registryها، نگاه کنید به registry.global-min-publish-age.
    • CARGO_REGISTRY_TOKEN — توکن احراز هویت برای crates.io، نگاه کنید به registry.token.
    • CARGO_RESOLVER_INCOMPATIBLE_PUBLISH_AGE — نحوهٔ برخورد با نسخه‌های تازه‌منتشرشده هنگام حل وابستگی، نگاه کنید به resolver.incompatible-publish-age.
    • CARGO_RESOLVER_INCOMPATIBLE_RUST_VERSIONS — نحوهٔ برخورد با نسخه‌های ناسازگار Rust هنگام حل وابستگی، نگاه کنید به resolver.incompatible-rust-versions.
    • CARGO_RESOLVER_LOCKFILE_PATH — مسیر lockfile، نگاه کنید به resolver.lockfile-path.
    • CARGO_TARGET_<tuple>_LINKER — لینکر مورد استفاده؛ target.<tuple>.linker را ببینید. tuple باید به حروف بزرگ و زیرخط تبدیل شود.
    • CARGO_TARGET_<tuple>_RUNNER — اجراکنندهٔ فایل اجرایی (runner)، نگاه کنید به target.<tuple>.runner.
    • CARGO_TARGET_<tuple>_RUSTFLAGS — پرچم‌های اضافی rustc برای یک هدف، نگاه کنید به target.<tuple>.rustflags.
    • CARGO_TARGET_<tuple>_RUSTDOCFLAGS — پرچم‌های اضافی rustdoc برای یک هدف، نگاه کنید به target.<tuple>.rustdocflags.
    • CARGO_TERM_QUIET — Quiet mode, see term.quiet.
    • CARGO_TERM_VERBOSE — سطح پرگویی پیش‌فرض ترمینال، نگاه کنید به term.verbose.
    • CARGO_TERM_COLOR — حالت رنگ پیش‌فرض، نگاه کنید به term.color.
    • CARGO_TERM_HYPERLINKS — اینکه آیا در ترمینال از ابرپیوند استفاده شود، نگاه کنید به term.hyperlinks.
    • CARGO_TERM_UNICODE — اینکه آیا خروجی ترمینال می‌تواند از نویسه‌های یونیکد غیر ASCII استفاده کند، نگاه کنید به term.unicode.
    • CARGO_TERM_PROGRESS_WHEN — حالت نمایش پیش‌فرض نوار پیشرفت، نگاه کنید به term.progress.when.
    • CARGO_TERM_PROGRESS_WIDTH — پهنای پیش‌فرض نوار پیشرفت، نگاه کنید به term.progress.width.
    • CARGO_TERM_PROGRESS_TERM_INTEGRATION — اینکه آیا پیشرفت به شبیه‌ساز ترمینال گزارش شود، نگاه کنید به term.progress.term-integration.

    متغیرهای محیطی‌ای که Cargo برای crateها تنظیم می‌کند

    Cargo هنگام کامپایل crate شما این متغیرهای محیطی را در اختیار آن قرار می‌دهد. توجه کنید که این موضوع برای اجرای فایل‌های دودویی با cargo run و cargo test هم صادق است. برای گرفتن مقدار هر یک از این متغیرها در یک برنامهٔ Rust، این‌طور عمل کنید:

    let version = env!("CARGO_PKG_VERSION");

    version اکنون مقدار CARGO_PKG_VERSION را در بر خواهد داشت.

    توجه کنید که اگر یکی از این مقادیر در manifest ارائه نشده باشد، متغیر محیطی متناظر روی رشتهٔ خالی "" تنظیم می‌شود.

    • CARGO — مسیر فایل دودویی cargo که ساخت را انجام می‌دهد.
    • CARGO_MANIFEST_DIR — پوشه‌ای که manifest بستهٔ شما در آن است.
    • CARGO_MANIFEST_PATH — مسیر manifest بستهٔ شما.
    • CARGO_PKG_VERSION — نسخهٔ کامل بستهٔ شما.
    • CARGO_PKG_VERSION_MAJOR — نسخهٔ major بستهٔ شما.
    • CARGO_PKG_VERSION_MINOR — نسخهٔ minor بستهٔ شما.
    • CARGO_PKG_VERSION_PATCH — نسخهٔ patch بستهٔ شما.
    • CARGO_PKG_VERSION_PRE — نسخهٔ پیش‌انتشار (pre-release) بستهٔ شما.
    • CARGO_PKG_AUTHORS — فهرست نویسندگان از manifest بستهٔ شما که با دونقطه جدا شده است.
    • CARGO_PKG_NAME — نام بستهٔ شما.
    • CARGO_PKG_DESCRIPTION — توضیحات (description) از manifest بستهٔ شما.
    • CARGO_PKG_HOMEPAGE — صفحهٔ اصلی (homepage) از manifest بستهٔ شما.
    • CARGO_PKG_REPOSITORY — مخزن (repository) از manifest بستهٔ شما.
    • CARGO_PKG_LICENSE — مجوز (license) از manifest بستهٔ شما.
    • CARGO_PKG_LICENSE_FILE — فایل مجوز از manifest بستهٔ شما.
    • CARGO_PKG_RUST_VERSION — نسخهٔ Rust از manifest بستهٔ شما. توجه کنید که این حداقل نسخهٔ Rust پشتیبانی‌شده توسط بسته است، نه نسخهٔ فعلی Rust.
    • CARGO_PKG_README — مسیر فایل README بستهٔ شما.
    • CARGO_CRATE_NAME — نام crate‌ای که در حال کامپایل است. این نام همان نام هدف Cargo است که در آن - به _ تبدیل شده، مثل نام کتابخانه، فایل دودویی، مثال، تست یکپارچگی یا benchmark.
    • CARGO_BIN_NAME — نام فایل دودویی‌ای که در حال کامپایل است. فقط برای فایل‌های دودویی یا مثال‌های دودویی تنظیم می‌شود. این نام شامل هیچ پسوند فایلی مثل .exe نیست.
    • OUT_DIR — اگر بسته اسکریپت ساخت داشته باشد، این متغیر روی پوشه‌ای تنظیم می‌شود که اسکریپت ساخت باید خروجی‌اش را در آن بگذارد. در ادامه اطلاعات بیشتری آمده است. Cargo تضمین نمی‌کند که این پوشه خالی باشد و بین ساخت‌ها پاک نمی‌شود.
    • CARGO_BIN_EXE_<name> — مسیر مطلق فایل اجرایی یک هدف دودویی. فقط هنگام ساخت تست یکپارچگی یا benchmark تنظیم می‌شود. می‌توان آن را همراه با ماکروی env به‌کار برد تا فایل اجرایی را برای اهداف تست پیدا کرد. <name> نام هدف دودویی است، دقیقاً همان‌طور که هست. برای مثال CARGO_BIN_EXE_my-program برای فایل دودویی‌ای به نام my-program. فایل‌های دودویی هنگام ساخت تست به‌طور خودکار ساخته می‌شوند، مگر اینکه فایل دودویی featureهای لازمی داشته باشد که فعال نیستند.
    • CARGO_PRIMARY_PACKAGE — اگر بسته‌ای که در حال ساخت است «اصلی» (primary) باشد، این متغیر محیطی تنظیم می‌شود. بسته‌های اصلی آن‌هایی هستند که کاربر در خط فرمان انتخاب کرده است، یا با پرچم‌های -p یا با پیش‌فرض‌های مبتنی بر پوشهٔ فعلی و اعضای پیش‌فرض workspace. این متغیر هنگام ساخت وابستگی‌ها تنظیم نمی‌شود، مگر اینکه یک وابستگی عضو workspace هم باشد و در خط فرمان انتخاب شده باشد. فقط هنگام کامپایل بسته تنظیم می‌شود (نه هنگام اجرای فایل‌های دودویی یا تست‌ها).
    • CARGO_TARGET_TMPDIR — فقط هنگام ساخت کد تست یکپارچگی یا benchmark تنظیم می‌شود. مسیر پوشه‌ای درون پوشهٔ target است که تست‌های یکپارچگی یا benchmarkها آزادند هر داده‌ای که لازم دارند در آن بگذارند. Cargo ابتدا این پوشه را می‌سازد اما محتوای آن را به هیچ شکل مدیریت نمی‌کند؛ این مسئولیت کد تست است.

    Dynamic library paths

    Cargo هنگام کامپایل و اجرای فایل‌های دودویی با دستورهایی مثل cargo run و cargo test مسیر کتابخانه‌های پویا را هم تنظیم می‌کند. این به پیدا‌کردن کتابخانه‌های اشتراکی‌ای که بخشی از فرایند ساخت‌اند کمک می‌کند. نام متغیر به پلتفرم بستگی دارد:

    • Windows: PATH
    • macOS: DYLD_FALLBACK_LIBRARY_PATH
    • Unix: LD_LIBRARY_PATH
    • AIX: LIBPATH

    مقدار از مقدار موجود هنگام شروع Cargo گسترش می‌یابد. macOS ملاحظهٔ ویژه‌ای دارد: اگر DYLD_FALLBACK_LIBRARY_PATH از قبل تنظیم نشده باشد، پیش‌فرض $HOME/lib:/usr/local/lib:/usr/lib را اضافه می‌کند.

    Cargo مسیرهای زیر را شامل می‌شود:

    • مسیرهای جست‌وجویی که هر اسکریپت ساخت با دستور rustc-link-search اضافه کرده باشد. مسیرهای بیرون از پوشهٔ target حذف می‌شوند. مسئولیت تنظیم درست محیط، در صورت نیاز به کتابخانه‌های اضافی سیستم در مسیر جست‌وجو، بر عهدهٔ کاربری است که Cargo را اجرا می‌کند.
    • پوشهٔ پایهٔ خروجی، مثل target/debug، و پوشهٔ «deps». این بیشتر برای پشتیبانی از proc-macroهاست.
    • مسیر کتابخانهٔ sysroot مربوط به rustc. این معمولاً برای بیشتر کاربران اهمیتی ندارد.

    متغیرهای محیطی‌ای که Cargo برای اسکریپت‌های ساخت تنظیم می‌کند

    Cargo هنگام اجرای اسکریپت‌های ساخت چند متغیر محیطی را تنظیم می‌کند. چون این متغیرها هنگام کامپایل اسکریپت ساخت هنوز تنظیم نشده‌اند، مثال بالا با env! کار نمی‌کند و باید مقدارها را هنگام اجرای اسکریپت ساخت بگیرید:

    use std::env;
let out_dir = env::var("OUT_DIR").unwrap();

    out_dir اکنون مقدار OUT_DIR را در بر خواهد داشت.

    • CARGO — مسیر فایل دودویی cargo که ساخت را انجام می‌دهد.
    • CARGO_MANIFEST_DIR — پوشه‌ای که manifest بستهٔ در حال ساخت (بسته‌ای که اسکریپت ساخت را دارد) در آن است. همچنین توجه کنید که این مقدار پوشهٔ کاری فعلی اسکریپت ساخت هنگام شروع آن است.
    • CARGO_MANIFEST_PATH — مسیر manifest بستهٔ شما.
    • CARGO_MANIFEST_LINKS — مقدار links در manifest.
    • CARGO_MAKEFLAGS — پارامترهای لازم برای پیاده‌سازی jobserver در Cargo را دربر دارد تا زیرفرایندها موازی شوند. فراخوانی‌های rustc یا cargo از درون build.rs می‌توانند CARGO_MAKEFLAGS را بخوانند، اما GNU Make لازم دارد پرچم‌ها یا مستقیماً به‌صورت آرگومان داده شوند یا از طریق متغیر محیطی MAKEFLAGS. فعلاً Cargo متغیر MAKEFLAGS را تنظیم نمی‌کند، اما اسکریپت‌های ساختی که GNU Make را فراخوانی می‌کنند آزادند آن را روی محتوای CARGO_MAKEFLAGS تنظیم کنند.
    • CARGO_FEATURE_<name> — برای هر feature فعال‌شدهٔ بستهٔ در حال ساخت، این متغیر محیطی وجود دارد که در آن <name> نام feature است با حروف بزرگ و با تبدیل - به _.
    • CARGO_CFG_<cfg> — For each configuration option of the package being built, this environment variable will contain the value of the configuration, where <cfg> is the name of the configuration uppercased and having - translated to _. Boolean configurations are present if they are set, and not present otherwise. Configurations with multiple values are joined to a single variable with the values delimited by ,. This includes values built-in to the compiler (which can be seen with rustc --print=cfg) and values set by build scripts and extra flags passed to rustc (such as those defined in RUSTFLAGS). Some examples of what these variables are:
      • CARGO_CFG_FEATURE — هر feature فعال‌شدهٔ بستهٔ در حال ساخت.
      • CARGO_CFG_UNIX — روی پلتفرم‌های شبه‌یونیکسی تنظیم می‌شود.
      • CARGO_CFG_WINDOWS — روی پلتفرم‌های شبه‌ویندوزی تنظیم می‌شود.
      • CARGO_CFG_TARGET_FAMILY=unix,wasm — خانوادهٔ هدف.
      • CARGO_CFG_TARGET_OS=macos — سیستم‌عامل هدف.
      • CARGO_CFG_TARGET_ARCH=x86_64 — معماری هدف CPU.
      • CARGO_CFG_TARGET_VENDOR=apple — سازندهٔ هدف.
      • CARGO_CFG_TARGET_ENV=gnu — ABI محیط هدف.
      • CARGO_CFG_TARGET_ABI=eabihf — ABI هدف.
      • CARGO_CFG_TARGET_POINTER_WIDTH=64 — پهنای اشاره‌گر CPU.
      • CARGO_CFG_TARGET_ENDIAN=little — ترتیب بایت (endianness) هدف CPU.
      • CARGO_CFG_TARGET_FEATURE=mmx,sse — فهرست قابلیت‌های هدف CPU که فعال‌اند.

      Note

      سه‌تایی‌های هدف (target tuple) متفاوت مجموعه‌های متفاوتی از مقادیر cfg دارند، بنابراین متغیرهایی که در یک target tuple هستند ممکن است در دیگری در دسترس نباشند.

      برخی مقادیر cfg مثل test در دسترس نیستند.

      Tip

      برای یک API نوع‌دار جهت خواندن این مقادیر، به‌جای تجزیهٔ دستی متغیرهای محیطی از crate با نام build-rs استفاده کنید. همچنین توجه کنید که متغیرهای CARGO_CFG_* باید به‌جای ماکروی cfg! یا attribute با نام #[cfg] در اسکریپت‌های ساخت به‌کار روند، چون آن‌ها پلتفرم میزبان (host) را بررسی می‌کنند، نه هدف (target).

    • OUT_DIR — پوشه‌ای که همهٔ خروجی‌ها و آرتیفکت‌های میانی باید در آن گذاشته شوند. این پوشه درون پوشهٔ ساخت بستهٔ در حال ساخت است و برای آن بسته منحصربه‌فرد است. Cargo این پوشه را بین ساخت‌ها پاک یا بازنشانی نمی‌کند و محتوای آن ممکن است بین ساخت‌های مجدد باقی بماند. اسکریپت‌های ساخت نباید فرض کنند که OUT_DIR خالی است و مسئول مدیریت یا پاک‌سازی فایل‌هایی هستند که می‌سازند. این متغیر هنگام اجرای اسکریپت ساخت و کامپایل crate تنظیم می‌شود، اما هنگام اجرا (runtime) در دسترس نیست.
    • TARGET — target tuple‌ای که برای آن کامپایل می‌شود. کد native باید برای همین tuple کامپایل شود. برای اطلاعات بیشتر توضیح Target Tuple را ببینید.
    • HOST — host tuple کامپایلر Rust.
    • NUM_JOBS — موازی‌سازی‌ای که به‌عنوان موازی‌سازی سطح بالا مشخص شده است. این می‌تواند برای دادن پارامتر -j به سیستمی مثل make مفید باشد. توجه کنید که در تفسیر این متغیر محیطی باید دقت کرد. به دلایل تاریخی هنوز ارائه می‌شود، اما نسخه‌های جدید Cargo، برای مثال، نیازی به اجرای make -j ندارند و می‌توانند متغیر محیطی MAKEFLAGS را روی محتوای CARGO_MAKEFLAGS تنظیم کنند تا jobserver سازگار با GNU Make در Cargo برای فراخوانی‌های make فرعی فعال شود.
    • DEBUG — اگر هر اطلاعات debug تولید شود true و در غیر این صورت false است.
    • OPT_LEVEL — مقدارهای متغیر opt-level متناظر برای profile‌ای که در حال ساخت است.
    • PROFILE — برای ساخت‌های release برابر release و برای بقیهٔ ساخت‌ها debug است. این بر اساس آن تعیین می‌شود که profile از dev یا release ارث می‌برد. استفاده از این متغیر محیطی توصیه نمی‌شود. استفاده از متغیرهای دیگر مثل OPT_LEVEL تصویر دقیق‌تری از تنظیمات واقعی در حال استفاده می‌دهد.
    • DEP_<links>_<key> — برای اطلاعات بیشتر دربارهٔ این مجموعه از متغیرهای محیطی، مستندات اسکریپت ساخت دربارهٔ links را ببینید.
    • RUSTC، RUSTDOC — کامپایلر و تولیدکنندهٔ مستنداتی که Cargo برای استفاده انتخاب کرده است، تا به اسکریپت ساخت داده شوند و آن هم بتواند از آن‌ها استفاده کند.
    • RUSTC_WRAPPER — wrapper مربوط به rustc (در صورت وجود) که Cargo از آن استفاده می‌کند. build.rustc-wrapper را ببینید.
    • RUSTC_WORKSPACE_WRAPPER — wrapper مربوط به rustc (در صورت وجود) که Cargo برای اعضای workspace از آن استفاده می‌کند. build.rustc-workspace-wrapper را ببینید.
    • RUSTC_LINKER — مسیر فایل دودویی لینکری که Cargo برای هدف فعلی برای استفاده انتخاب کرده است، در صورت مشخص‌بودن. لینکر را می‌توان با ویرایش .cargo/config.toml تغییر داد؛ برای اطلاعات بیشتر مستندات پیکربندی cargo را ببینید.
    • CARGO_ENCODED_RUSTFLAGS — پرچم‌های اضافی که Cargo rustc را با آن‌ها اجرا می‌کند، و با نویسهٔ 0x1f (جداکنندهٔ واحد ASCII) جدا شده‌اند. build.rustflags را ببینید. توجه کنید که از Rust 1.55 به بعد، RUSTFLAGS از محیط حذف می‌شود؛ اسکریپت‌ها باید به‌جای آن از CARGO_ENCODED_RUSTFLAGS استفاده کنند.
    • CARGO_PKG_<var> — متغیرهای اطلاعات بسته، با همان نام‌ها و مقادیری که هنگام ساخت crate ارائه می‌شوند.
    • CARGO_TRIM_PATHS_SCOPE — The value of the trim-paths profile option. If the build script introduces absolute paths to built artifacts (such as by invoking a compiler), the user may request them to be sanitized in different types of artifacts. Common paths requiring sanitization include OUT_DIR, CARGO_MANIFEST_DIR and CARGO_MANIFEST_PATH, plus any other introduced by the build script, such as include directories.

      Note

      برای سازگاری رو‌به‌جلو، اسکریپت‌های ساخت باید فهرستی از دامنه‌ها (scope) را که با ویرگول جدا شده بپذیرند.

    • CARGO_TRIM_PATHS_REMAP — جفت‌های بازنگاشت مسیر <from>=<to> که Cargo به کامپایلر می‌دهد، و با جداکنندهٔ مسیر پلتفرم به هم متصل شده‌اند. وقتی trim-paths برابر "none" باشد خالی است. اسکریپت‌های ساخت می‌توانند این نگاشت‌ها را به کامپایلرهای C/C++ و ابزارهای دیگر منتقل کنند، مثلاً از طریق -ffile-prefix-map در cc، تا مسیرها همسو با بقیهٔ ساخت پاک‌سازی شوند.

    متغیرهای محیطی‌ای که Cargo برای cargo test تنظیم می‌کند

    Cargo هنگام اجرای تست‌ها چند متغیر محیطی را تنظیم می‌کند. می‌توانید مقدارها را هنگام اجرای تست‌ها بگیرید:

    use std::env;
let out_dir = env::var("CARGO_BIN_EXE_foo").unwrap();
    • CARGO_BIN_EXE_<name> — مسیر مطلق فایل اجرایی یک هدف دودویی. فقط هنگام اجرای تست یکپارچگی یا benchmark تنظیم می‌شود. <name> نام هدف دودویی است، دقیقاً همان‌طور که هست. برای مثال CARGO_BIN_EXE_my-program برای فایل دودویی‌ای به نام my-program. فایل‌های دودویی هنگام ساخت تست به‌طور خودکار ساخته می‌شوند، مگر اینکه فایل دودویی featureهای لازمی داشته باشد که فعال نیستند.

    متغیرهای محیطی‌ای که Cargo برای زیردستورهای شخص ثالث تنظیم می‌کند

    Cargo این متغیر محیطی را در اختیار زیردستورهای شخص ثالث (یعنی برنامه‌هایی به نام cargo-foobar که در $PATH قرار دارند) می‌گذارد:

    • CARGO — مسیر فایل دودویی cargo که ساخت را انجام می‌دهد.
    • CARGO_MAKEFLAGS — پارامترهای لازم برای پیاده‌سازی jobserver در Cargo را دربر دارد تا زیرفرایندها موازی شوند. فقط وقتی تنظیم می‌شود که Cargo وجود یک jobserver را تشخیص دهد.

    برای اطلاعات گسترده‌تر دربارهٔ محیط خود می‌توانید cargo metadata را اجرا کنید.
