    احراز هویت رجیستری

    Cargo با استفاده از credential providerها در رجیستری‌ها احراز هویت می‌کند. این credential providerها فایل‌های اجرایی خارجی یا providerهای داخلی هستند که Cargo برای ذخیره و بازیابی اعتبارنامه‌ها (credentials) از آن‌ها استفاده می‌کند.

    استفاده از رجیستری‌های جایگزین دارای احراز هویت مستلزم پیکربندی یک credential provider است تا از ذخیره شدن ناخواستهٔ اعتبارنامه‌های رمزنگاری‌نشده روی دیسک جلوگیری شود. به دلایل تاریخی، رجیستری‌های عمومی (بدون احراز هویت) به پیکربندی credential provider نیازی ندارند و اگر هیچ providerی پیکربندی نشده باشد، از provider با نام cargo:token استفاده می‌شود.

    Cargo همچنین شامل providerهای مخصوص هر پلتفرم است که از سیستم‌عامل برای ذخیرهٔ ایمن توکن‌ها استفاده می‌کنند. provider با نام cargo:token نیز گنجانده شده است که اعتبارنامه‌ها را به‌صورت متن ساده و رمزنگاری‌نشده در فایل credentials ذخیره می‌کند.

    پیکربندی توصیه‌شده

    توصیه می‌شود یک فهرست سراسری از credential providerها در $CARGO_HOME/config.toml پیکربندی شود که به‌طور پیش‌فرض در مسیر زیر است:

    • Windows: %USERPROFILE%\.cargo\config.toml
    • Unix: ~/.cargo/config.toml

    این پیکربندی توصیه‌شده از provider سیستم‌عامل استفاده می‌کند و در صورت نبود آن به cargo:token برمی‌گردد تا در فایل credentials یا متغیرهای محیطی Cargo جست‌وجو کند:

    # ~/.cargo/config.toml
[registry]
global-credential-providers = ["cargo:token", "cargo:libsecret", "cargo:macos-keychain", "cargo:wincred"]

    توجه کنید که ورودی‌های بعدی اولویت بالاتری دارند. برای جزئیات بیشتر، registry.global-credential-providers را ببینید.

    برخی رجیستری‌های خصوصی ممکن است یک credential provider مخصوص خود رجیستری را نیز توصیه کنند. برای دانستن اینکه آیا چنین است، مستندات رجیستری خود را بررسی کنید.

    providerهای داخلی

    Cargo چند credential provider داخلی دارد. providerهای داخلیِ در دسترس ممکن است در نسخه‌های آیندهٔ Cargo تغییر کنند (هرچند در حال حاضر برنامه‌ای برای این کار وجود ندارد).

    cargo:token

    از فایل credentials در Cargo برای ذخیرهٔ توکن‌ها به‌صورت متن ساده و رمزنگاری‌نشده استفاده می‌کند. هنگام بازیابی توکن‌ها، متغیر محیطی CARGO_REGISTRIES_<NAME>_TOKEN را بررسی می‌کند. اگر این credential provider فهرست نشده باشد، متغیرهای محیطی *_TOKEN کار نخواهند کرد.

    cargo:wincred

    از Windows Credential Manager برای ذخیرهٔ توکن‌ها استفاده می‌کند.

    اعتبارنامه‌ها با نام cargo-registry:<index-url> در Credential Manager و در بخش «Windows Credentials» ذخیره می‌شوند.

    cargo:macos-keychain

    از macOS Keychain برای ذخیرهٔ توکن‌ها استفاده می‌کند.

    برای مشاهدهٔ توکن‌های ذخیره‌شده می‌توان از برنامهٔ Keychain Access استفاده کرد.

    cargo:libsecret

    از libsecret برای ذخیرهٔ توکن‌ها استفاده می‌کند.

    برای مشاهدهٔ توکن‌های ذخیره‌شده می‌توان از هر مدیر گذرواژه‌ای که از libsecret پشتیبانی می‌کند استفاده کرد. موارد زیر چند نمونه هستند (فهرست کامل نیست):

    • GNOME Keyring
    • KDE Wallet Manager (از KDE Frameworks 5.97.0 به بعد)
    • KeePassXC (از 2.5.0 به بعد)

    cargo:token-from-stdout <command> <args>

    یک زیرفرایند اجرا می‌کند که توکنی را روی stdout برمی‌گرداند. خطوط جدید حذف خواهند شد.

    • فرایند، stdin و stderr کاربر را به ارث می‌برد.
    • در صورت موفقیت باید با کد 0 خارج شود و در صورت خطا با کد غیرصفر.
    • cargo login و cargo logout پشتیبانی نمی‌شوند و در صورت استفاده، خطا برمی‌گردانند.

    متغیرهای محیطی زیر برای دستور اجراشده فراهم خواهند شد:

    • CARGO — مسیر فایل باینری cargo که دستور را اجرا می‌کند.
    • CARGO_REGISTRY_INDEX_URL — URL ایندکس رجیستری.
    • CARGO_REGISTRY_NAME_OPT — نام اختیاری رجیستری. نباید به‌عنوان کلید جست‌وجو استفاده شود.

    آرگومان‌ها به زیردستور داده خواهند شد.

    افزونه‌های اعتبارنامه

    برای افزونه‌های credential provider که از پروتکل credential provider در Cargo پیروی می‌کنند، مقدار پیکربندی باید رشته‌ای باشد که مسیر فایل اجرایی را دارد (یا نام فایل اجرایی اگر در PATH باشد).

    برای مثال، برای نصب cargo-credential-1password از crates.io این کارها را انجام دهید:

    provider را با cargo install cargo-credential-1password نصب کنید

    در پیکربندی، به registry.global-credential-providers اضافه کنید (یا آن را ایجاد کنید):

    [registry]
global-credential-providers = ["cargo:token", "cargo-credential-1password --account my.1password.com"]

    مقادیر در global-credential-providers بر اساس فاصله به مسیر و آرگومان‌های خط فرمان تقسیم می‌شوند. برای تعریف یک credential provider سراسری که مسیر یا آرگومان‌هایش فاصله دارند، از جدول [credential-alias] استفاده کنید.
