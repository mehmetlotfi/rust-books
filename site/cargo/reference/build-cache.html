    کش ساخت

    Cargo خروجی ساخت را در دایرکتوری‌های «target» و «build» ذخیره می‌کند. به‌طور پیش‌فرض، هر دو دایرکتوری به دایرکتوری‌ای به نام target در ریشهٔ workspace شما اشاره می‌کنند. برای تغییر مکان target-dir می‌توانید متغیر محیطی به نام CARGO_TARGET_DIR، مقدار پیکربندی build.target-dir یا پرچم خط فرمان --target-dir را تنظیم کنید. برای تغییر مکان build-dir می‌توانید متغیر محیطی به نام CARGO_BUILD_BUILD_DIR یا مقدار پیکربندی build.build-dir را تنظیم کنید.

    مصنوعات (artifacts) به دو دسته تقسیم می‌شوند:

    • مصنوعات نهایی ساخت
      • مصنوعات نهایی ساخت خروجی‌هایی هستند که برای کاربران نهایی Cargo در نظر گرفته شده‌اند
      • مثلاً فایل‌های باینری crateهای bin، خروجی cargo doc و گزارش‌های --timings در Cargo
      • در target-dir ذخیره می‌شوند
    • مصنوعات میانی ساخت
      • مصنوعات میانی ساخت داخلی Cargo و کامپایلر Rust هستند
      • کاربران نهایی معمولاً نیازی به تعامل با مصنوعات میانی ساخت ندارند
      • در build-dir مربوط به Cargo ذخیره می‌شوند

    ساختار دایرکتوری‌ها به این بستگی دارد که از پرچم --target برای ساخت روی یک پلتفرم مشخص استفاده می‌کنید یا نه. اگر --target مشخص نشود، Cargo در حالتی اجرا می‌شود که برای معماری میزبان می‌سازد. خروجی در ریشهٔ دایرکتوری target قرار می‌گیرد و هر پروفایل در زیردایرکتوری جداگانه‌ای ذخیره می‌شود:

    دایرکتوریتوضیحات
    target/debug/خروجی پروفایل dev را در بر دارد.
    target/release/خروجی پروفایل release را (با گزینهٔ --release) در بر دارد.
    target/foo/خروجی ساخت پروفایل foo را (با گزینهٔ --profile=foo) در بر دارد.

    به دلایل تاریخی، پروفایل‌های dev و test در دایرکتوری debug و پروفایل‌های release و bench در دایرکتوری release ذخیره می‌شوند. پروفایل‌های تعریف‌شده توسط کاربر در دایرکتوری‌ای هم‌نام با پروفایل ذخیره می‌شوند.

    هنگام ساخت برای هدف دیگری با --target، خروجی در دایرکتوری‌ای به نام target قرار می‌گیرد:

    دایرکتوریمثال
    target/<tuple>/debug/target/thumbv7em-none-eabihf/debug/
    target/<tuple>/release/target/thumbv7em-none-eabihf/release/

    Note

    وقتی از --target استفاده نمی‌شود، نتیجه‌اش این است که Cargo وابستگی‌های شما را با build scriptها و ماکروهای رویه‌ای (proc macro) به اشتراک می‌گذارد. RUSTFLAGS با هر فراخوانی rustc به اشتراک گذاشته می‌شود. با پرچم --target، build scriptها و proc macroها جداگانه (برای معماری میزبان) ساخته می‌شوند و RUSTFLAGS را به اشتراک نمی‌گذارند.

    درون دایرکتوری پروفایل (مانند debug یا release)، مصنوعات در دایرکتوری‌های زیر قرار می‌گیرند:

    دایرکتوریتوضیحات
    target/debug/خروجی بسته‌ای که ساخته می‌شود (فایل‌های اجرایی باینری و هدف‌های کتابخانه) را در بر دارد.
    target/debug/examples/هدف‌های مثال را در بر دارد.

    برخی دستورها خروجی خود را در دایرکتوری‌های اختصاصی در سطح بالای دایرکتوری target قرار می‌دهند:

    دایرکتوریتوضیحات
    target/doc/مستندات rustdoc (cargo doc) را در بر دارد.
    target/package/خروجی cargo package را در بر دارد.

    Cargo همچنین چند دایرکتوری و فایل دیگر را که برای فرایند ساخت لازم‌اند در build-dir ایجاد می‌کند. ساختار build-dir داخلی Cargo محسوب می‌شود و ممکن است تغییر کند. برخی از این دایرکتوری‌ها عبارت‌اند از:

    دایرکتوریتوضیحات
    <build-dir>/debug/incremental/خروجی افزایشی rustc، کشی که برای تسریع ساخت‌های بعدی به کار می‌رود.
    <build-dir>/debug/build/نتایج مراحل ساخت، شامل مصنوعات کامپایل و خروجی build script.

    Note

    ساختار build-dir در Cargo 1.100.0 تغییر کرده است، بنابراین نسخه‌های قبل از آن از ساختار دیگری استفاده می‌کنند. (به #15010 نگاه کنید)

    فایل‌های dep-info

    کنار هر مصنوع کامپایل‌شده فایلی به نام فایل «dep info» با پسوند .d وجود دارد. این فایل نحوی شبیه Makefile دارد و همهٔ وابستگی‌های فایلی لازم برای ساخت دوبارهٔ آن مصنوع را نشان می‌دهد. این فایل‌ها برای استفاده با سامانه‌های ساخت خارجی در نظر گرفته شده‌اند تا بتوانند تشخیص دهند که آیا Cargo باید دوباره اجرا شود یا نه. مسیرهای درون فایل به‌طور پیش‌فرض مطلق هستند. برای استفاده از مسیرهای نسبی، گزینهٔ پیکربندی build.dep-info-basedir را ببینید.

    # Example dep-info file found in target/debug/foo.d
/path/to/myproj/target/debug/foo: /path/to/myproj/src/lib.rs /path/to/myproj/src/main.rs

    کش اشتراکی

    ابزار شخص ثالث sccache را می‌توان برای اشتراک‌گذاری وابستگی‌های ساخته‌شده میان workspaceهای مختلف به کار برد.

    برای راه‌اندازی sccache، آن را با cargo install --locked sccache نصب کنید و پیش از فراخوانی Cargo متغیر محیطی RUSTC_WRAPPER را روی sccache تنظیم کنید. اگر از bash استفاده می‌کنید، افزودن export RUSTC_WRAPPER=sccache به .bashrc منطقی است. به‌طور جایگزین می‌توانید build.rustc-wrapper را در پیکربندی Cargo تنظیم کنید. برای جزئیات بیشتر به مستندات sccache مراجعه کنید.
