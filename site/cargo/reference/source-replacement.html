    جایگزینی منبع

    این سند دربارهٔ تغییر مسیر ارتباط با رجیستری‌ها یا مخازن وابستگی‌های مبتنی بر git به یک منبع داده‌ٔ دیگر است، مانند سروری که آینهٔ رجیستری اصلی است یا یک نسخهٔ محلی دقیق.

    اگر می‌خواهید وابستگی‌های منفرد را وصله (patch) کنید، بخش بازنویسی وابستگی‌ها را در این مستندات ببینید. اگر می‌خواهید نحوهٔ ارسال درخواست‌های شبکه توسط Cargo را کنترل کنید، پیکربندی‌های [http] و [net] را ببینید.

    یک منبع (source) ارائه‌دهنده‌ای است که شامل crateهایی است که می‌توانند به‌عنوان وابستگی یک بسته به کار روند. Cargo از قابلیت جایگزین‌کردن یک منبع با منبع دیگر پشتیبانی می‌کند تا راهبردهایی مانند موارد زیر بیان شوند:

    • Vendoring — می‌توان منابع سفارشی تعریف کرد که نمایانگر crateهای روی فایل‌سیستم محلی هستند. این منابع زیرمجموعه‌ای از منبعی‌اند که جایگزین آن می‌شوند و در صورت لزوم می‌توان آن‌ها را درون بسته‌ها commit کرد.

    • Mirroring — می‌توان منابع را با یک نسخهٔ معادل جایگزین کرد که نقش کش خود crates.io را دارد.

    Cargo دربارهٔ جایگزینی منبع یک فرض اساسی دارد: کد منبع در هر دو منبع دقیقاً یکسان است. توجه کنید که این همچنین به این معناست که منبع جایگزین مجاز نیست crateهایی داشته باشد که در منبع اصلی وجود ندارند.

    در نتیجه، جایگزینی منبع برای موقعیت‌هایی مانند وصله‌کردن یک وابستگی یا رجیستری خصوصی مناسب نیست. Cargo از وصله‌کردن وابستگی‌ها از طریق کلید [patch] پشتیبانی می‌کند و پشتیبانی از رجیستری خصوصی در فصل رجیستری‌ها توضیح داده شده است.

    هنگام استفاده از جایگزینی منبع، اجرای دستورهایی که نیاز دارند مستقیماً با رجیستری تماس بگیرند1 مستلزم ارسال گزینهٔ --registry است. این کار به جلوگیری از هرگونه ابهام دربارهٔ اینکه با کدام رجیستری تماس گرفته شود کمک می‌کند و از توکن احراز هویت رجیستری مشخص‌شده استفاده خواهد کرد.

    پیکربندی

    پیکربندی منابع جایگزین از طریق .cargo/config.toml انجام می‌شود و مجموعهٔ کامل کلیدهای موجود به این شرح است:

    # The `source` table is where all keys related to source-replacement
# are stored.
[source]

# Under the `source` table are a number of other tables whose keys are a
# name for the relevant source. For example this section defines a new
# source, called `my-vendor-source`, which comes from a directory
# located at `vendor` relative to the directory containing this `.cargo/config.toml`
# file
[source.my-vendor-source]
directory = "vendor"

# The crates.io default source for crates is available under the name
# "crates-io", and here we use the `replace-with` key to indicate that it's
# replaced with our source above.
#
# The `replace-with` key can also reference an alternative registry name
# defined in the `[registries]` table.
[source.crates-io]
replace-with = "my-vendor-source"

# Each source has its own table where the key is the name of the source
[source.the-source-name]

# Indicate that `the-source-name` will be replaced with `another-source`,
# defined elsewhere
replace-with = "another-source"

# Several kinds of sources can be specified (described in more detail below):
registry = "https://example.com/path/to/index"
local-registry = "path/to/registry"
directory = "path/to/vendor"

# Git sources can optionally specify a branch/tag/rev as well
git = "https://example.com/path/to/repo"
# branch = "master"
# tag = "v1.0.1"
# rev = "313f44e8"

    منابع رجیستری

    «منبع رجیستری» منبعی است که مانند خود crates.io کار می‌کند. این منبع یک ایندکس است که با مشخصات https://doc.rust-lang.org/cargo/reference/registry-index.html سازگار است و یک فایل پیکربندی دارد که نشان می‌دهد crateها از کجا دانلود شوند.

    منابع رجیستری می‌توانند از پروتکل git یا پروتکل sparse HTTP استفاده کنند:

    # Git protocol
registry = "ssh://git@example.com/path/to/index.git"

# Sparse HTTP protocol
registry = "sparse+https://example.com/path/to/index"

# HTTPS git protocol
registry = "https://example.com/path/to/index"

    منابع رجیستری محلی

    «منبع رجیستری محلی» قرار است زیرمجموعه‌ای از یک منبع رجیستری دیگر باشد که روی فایل‌سیستم محلی در دسترس است (همان vendoring). رجیستری‌های محلی از پیش دانلود می‌شوند، معمولاً با Cargo.lock همگام‌سازی می‌شوند و از مجموعه‌ای از فایل‌های *.crate و یک ایندکس مانند رجیستری عادی تشکیل شده‌اند.

    روش اصلی مدیریت و ایجاد منابع رجیستری محلی، زیردستور cargo-local-registry است که در crates.io موجود است و با cargo install --locked cargo-local-registry نصب می‌شود.

    رجیستری‌های محلی در یک دایرکتوری قرار دارند و شامل تعدادی فایل *.crate دانلودشده از crates.io و نیز یک دایرکتوری index با همان قالب پروژهٔ crates.io-index هستند (که فقط با ورودی‌های crateهای موجود پر شده است).

    منابع دایرکتوری

    «منبع دایرکتوری» شبیه منبع رجیستری محلی است، از این جهت که شامل تعدادی crate در دسترس روی فایل‌سیستم محلی است و برای vendor کردن وابستگی‌ها مناسب است. منابع دایرکتوری عمدتاً توسط زیردستور cargo vendor مدیریت می‌شوند.

    اما منابع دایرکتوری با رجیستری‌های محلی تفاوت دارند، چون شامل نسخهٔ بازشدهٔ فایل‌های *.crate هستند و همین در برخی موقعیت‌ها آن را برای commit کردن همه‌چیز در سیستم کنترل نسخه مناسب‌تر می‌کند. منبع دایرکتوری فقط یک دایرکتوری است که شامل تعدادی دایرکتوری دیگر است و آن‌ها کد منبع crateها (نسخهٔ بازشدهٔ فایل‌های *.crate) را دارند. در حال حاضر هیچ محدودیتی روی نام هر دایرکتوری اعمال نمی‌شود.

    هر crate در یک منبع دایرکتوری همچنین یک فایل فراداده (metadata) به نام .cargo-checksum.json دارد تا در برابر تغییرات تصادفی محافظت کند. این یک سازوکار امنیتی نیست و در برابر تغییرات مخرب محافظت نمی‌کند.

    منابع git

    منابع git نمایانگر مخازنی هستند که وابستگی‌های مبتنی بر git از آن‌ها استفاده می‌کنند. از آن‌ها برای مشخص‌کردن اینکه کدام وابستگی‌های مبتنی بر git باید با منابع جایگزین عوض شوند استفاده می‌شود.

    منابع git به رجیستری‌های git ربطی ندارند و نمی‌توان از آن‌ها برای جایگزینی منابع رجیستری استفاده کرد.
