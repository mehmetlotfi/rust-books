    cargo(1)

    نام

    cargo — مدیر بستهٔ Rust

    خلاصه

    cargo [options] command [args]
    cargo [options] --version
    cargo [options] --list
    cargo [options] --help
    cargo [options] --explain code

    توضیحات

    این برنامه یک مدیر بسته و ابزار ساخت برای زبان Rust است و در https://rust-lang.org در دسترس است.

    فرمان‌ها

    فرمان‌های ساخت

    cargo-bench(1)\ benchmarkهای یک بسته را اجرا می‌کند.

    cargo-build(1)\ یک بسته را کامپایل می‌کند.

    cargo-check(1)\ یک بستهٔ محلی و همهٔ وابستگی‌های آن را از نظر خطا بررسی می‌کند.

    cargo-clean(1)\ artifactهایی را که Cargo در گذشته تولید کرده است حذف می‌کند.

    cargo-doc(1)\ مستندات یک بسته را می‌سازد.

    cargo-fetch(1)\ وابستگی‌های یک بسته را از شبکه دریافت می‌کند.

    cargo-fix(1)\ هشدارهای lint گزارش‌شده توسط rustc را به‌طور خودکار رفع می‌کند.

    cargo-run(1)\ یک باینری یا نمونهٔ (example) بستهٔ محلی را اجرا می‌کند.

    cargo-rustc(1)\ یک بسته را کامپایل می‌کند و گزینه‌های اضافی را به کامپایلر می‌دهد.

    cargo-rustdoc(1)\ مستندات یک بسته را با پرچم‌های سفارشی مشخص‌شده می‌سازد.

    cargo-test(1)\ آزمون‌های واحد و یکپارچگی یک بسته را اجرا می‌کند.

    فرمان‌های manifest

    cargo-add(1)\ وابستگی‌ها را به فایل manifest به نام Cargo.toml اضافه می‌کند.

    cargo-generate-lockfile(1)\ فایل Cargo.lock را برای یک پروژه تولید می‌کند.

    cargo-info(1)\ اطلاعات یک بسته را در registry نمایش می‌دهد. registry پیش‌فرض crates.io است.

    cargo-locate-project(1)\ نمایشی JSON از محل یک فایل Cargo.toml را چاپ می‌کند.

    cargo-metadata(1)\ وابستگی‌های حل‌وفصل‌شدهٔ یک بسته را در قالب قابل‌خواندن برای ماشین خروجی می‌دهد.

    cargo-pkgid(1)\ مشخصهٔ کاملاً معین (fully qualified) یک بسته را چاپ می‌کند.

    cargo-remove(1)\ وابستگی‌ها را از فایل manifest به نام Cargo.toml حذف می‌کند.

    cargo-tree(1)\ نمایشی درختی از گراف وابستگی‌ها را نشان می‌دهد.

    cargo-update(1)\ وابستگی‌ها را مطابق آنچه در فایل lock محلی ثبت شده است به‌روزرسانی می‌کند.

    cargo-vendor(1)\ همهٔ وابستگی‌ها را به‌صورت محلی vendor می‌کند.

    فرمان‌های بسته

    cargo-init(1)\ یک بستهٔ جدید Cargo را در یک دایرکتوری موجود می‌سازد.

    cargo-install(1)\ یک باینری Rust را می‌سازد و نصب می‌کند.

    cargo-new(1)\ یک بستهٔ جدید Cargo می‌سازد.

    cargo-search(1)\ بسته‌ها را در crates.io جست‌وجو می‌کند.

    cargo-uninstall(1)\ یک باینری Rust را حذف می‌کند.

    فرمان‌های انتشار

    cargo-login(1)\ یک توکن API از registry را به‌صورت محلی ذخیره می‌کند.

    cargo-logout(1)\ یک توکن API از registry را که به‌صورت محلی ذخیره شده است حذف می‌کند.

    cargo-owner(1)\ مالکان یک crate را در registry مدیریت می‌کند.

    cargo-package(1)\ بستهٔ محلی را در قالب یک tarball قابل‌توزیع گرد هم می‌آورد.

    cargo-publish(1)\ یک بسته را در registry بارگذاری می‌کند.

    cargo-yank(1)\ یک crate منتشرشده را از index حذف می‌کند.

    فرمان‌های گزارش

    cargo-report(1)\ انواع مختلف گزارش را تولید و نمایش می‌دهد.

    cargo-report-future-incompatibilities(1)\ crateهایی را که سرانجام دیگر کامپایل نخواهند شد گزارش می‌کند.

    فرمان‌های عمومی

    cargo-help(1)\ اطلاعات راهنما دربارهٔ Cargo را نمایش می‌دهد.

    cargo-version(1)\ اطلاعات نسخه را نشان می‌دهد.

    گزینه‌ها

    گزینه‌های ویژه

    -V
    --version

    اطلاعات نسخه را چاپ می‌کند و خارج می‌شود. اگر همراه با --verbose استفاده شود، اطلاعات اضافی چاپ می‌کند.

    --list

    همهٔ زیرفرمان‌های نصب‌شدهٔ Cargo را فهرست می‌کند. اگر همراه با --verbose استفاده شود، اطلاعات اضافی چاپ می‌کند.

    --explain code

    فرمان rustc --explain CODE را اجرا می‌کند که توضیح مفصلی دربارهٔ یک پیام خطا (برای مثال، E0004) چاپ می‌کند.

    گزینه‌های نمایش

    -v
    --verbose

    از خروجی مفصل استفاده می‌کند. برای خروجی «بسیار مفصل» که شامل خروجی اضافی مانند هشدارهای وابستگی‌ها و خروجی build script است، می‌توان آن را دو بار مشخص کرد. همچنین می‌توان آن را با مقدار پیکربندی term.verbose مشخص کرد.

    -q
    --quiet

    پیام‌های log مربوط به cargo را چاپ نمی‌کند. همچنین می‌توان آن را با مقدار پیکربندی term.quiet مشخص کرد.

    --color when

    تعیین می‌کند خروجی رنگی چه زمانی استفاده شود. مقادیر معتبر:

    • auto (پیش‌فرض): به‌طور خودکار تشخیص می‌دهد که آیا ترمینال از رنگ پشتیبانی می‌کند.
    • always: همیشه رنگ‌ها را نمایش می‌دهد.
    • never: هرگز رنگ‌ها را نمایش نمی‌دهد.

    همچنین می‌توان آن را با مقدار پیکربندی term.color مشخص کرد.

    گزینه‌های manifest

    --locked

    تأیید می‌کند که دقیقاً همان وابستگی‌ها و نسخه‌هایی استفاده شوند که هنگام تولید اولیهٔ فایل Cargo.lock موجود به کار رفته بودند. Cargo در هر یک از دو حالت زیر با خطا خارج می‌شود:

    • فایل lock وجود نداشته باشد.
    • Cargo به‌دلیل حل‌وفصل متفاوت وابستگی‌ها بخواهد فایل lock را تغییر دهد.

    می‌توان از آن در محیط‌هایی استفاده کرد که ساخت‌های قطعی (deterministic) موردنیاز است، مانند pipelineهای CI.

    --offline

    Cargo را از دسترسی به شبکه به هر دلیلی بازمی‌دارد. بدون این پرچم، اگر Cargo نیاز به دسترسی به شبکه داشته باشد و شبکه در دسترس نباشد، با خطا متوقف می‌شود. با این پرچم، Cargo در صورت امکان بدون شبکه ادامه می‌دهد.

    توجه داشته باشید که این ممکن است به حل‌وفصل وابستگی‌هایی متفاوت از حالت آنلاین منجر شود. Cargo خود را به crateهایی محدود می‌کند که به‌صورت محلی دانلود شده‌اند، حتی اگر طبق نسخهٔ محلی index نسخهٔ جدیدتری وجود داشته باشد. برای دانلود وابستگی‌ها پیش از رفتن به حالت آفلاین، فرمان cargo-fetch(1) را ببینید.

    همچنین می‌توان آن را با مقدار پیکربندی net.offline مشخص کرد.

    --frozen

    معادل مشخص کردن همزمان --locked و --offline است.

    گزینه‌های رایج

    +toolchain

    اگر Cargo با rustup نصب شده باشد و اولین آرگومان cargo با + شروع شود، به‌عنوان نام یک toolchain در rustup تفسیر می‌شود (مانند +stable یا +nightly). برای اطلاعات بیشتر دربارهٔ نحوهٔ کار override کردن toolchain، به مستندات rustup مراجعه کنید.

    --config KEY=VALUE یا PATH

    یک مقدار پیکربندی Cargo را بازنویسی می‌کند. آرگومان باید به نحو TOML و به شکل KEY=VALUE باشد، یا مسیر یک فایل پیکربندی اضافی داده شود. این پرچم را می‌توان چندین بار مشخص کرد. برای اطلاعات بیشتر بخش بازنویسی از خط فرمان را ببینید.

    -C PATH

    پیش از اجرای هر عملیات مشخص‌شده، دایرکتوری کاری فعلی را تغییر می‌دهد. این بر مواردی مانند محل پیش‌فرض جست‌وجوی manifest پروژه (Cargo.toml) توسط cargo و نیز دایرکتوری‌هایی که برای یافتن .cargo/config.toml جست‌وجو می‌شوند اثر می‌گذارد. این گزینه باید پیش از نام فرمان بیاید، برای مثال cargo -C path/to/my-project build.

    این گزینه فقط در کانال nightly در دسترس است و برای فعال شدن به پرچم -Z unstable-options نیاز دارد (به #10098 مراجعه کنید).

    -h
    --help

    اطلاعات راهنما را چاپ می‌کند.

    -Z flag

    پرچم‌های ناپایدار (فقط nightly) برای Cargo. برای جزئیات cargo -Z help را اجرا کنید.

    فایل‌ها

    ~/.cargo/\ محل پیش‌فرض دایرکتوری «home» مربوط به Cargo که فایل‌های گوناگونی را در آن ذخیره می‌کند. این محل را می‌توان با متغیر محیطی CARGO_HOME تغییر داد.

    $CARGO_HOME/bin/\ باینری‌هایی که با cargo-install(1) نصب می‌شوند در اینجا قرار می‌گیرند. اگر از rustup استفاده شود، فایل‌های اجرایی که همراه Rust توزیع می‌شوند نیز در اینجا هستند.

    $CARGO_HOME/config.toml\ فایل پیکربندی سراسری. برای اطلاعات بیشتر دربارهٔ فایل‌های پیکربندی، مرجع را ببینید.

    .cargo/config.toml\ Cargo به‌طور خودکار فایلی به نام .cargo/config.toml را در دایرکتوری فعلی و همهٔ دایرکتوری‌های والد جست‌وجو می‌کند. این فایل‌های پیکربندی با فایل پیکربندی سراسری ادغام می‌شوند.

    $CARGO_HOME/credentials.toml\ اطلاعات احراز هویت خصوصی برای ورود به یک registry.

    $CARGO_HOME/registry/\ این دایرکتوری شامل دانلودهای ذخیره‌شدهٔ (cache) index مربوط به registry و هر وابستگی دانلودشده است.

    $CARGO_HOME/git/\ این دایرکتوری شامل دانلودهای ذخیره‌شدهٔ (cache) وابستگی‌های git است.

    توجه کنید که ساختار داخلی دایرکتوری $CARGO_HOME هنوز stable نیست و ممکن است تغییر کند.

    مثال‌ها

    1. یک بستهٔ محلی و همهٔ وابستگی‌های آن را بسازید:

      cargo build

    2. یک بسته را با بهینه‌سازی‌ها بسازید:

      cargo build --release

    3. آزمون‌ها را برای یک هدف cross-compile‌شده اجرا کنید:

      cargo test --target i686-unknown-linux-gnu

    4. بسته‌ای جدید بسازید که یک فایل اجرایی تولید می‌کند:

      cargo new foobar

    5. در دایرکتوری فعلی یک بسته بسازید:

      mkdir foo && cd foo
cargo init .

    6. دربارهٔ گزینه‌ها و نحوهٔ استفادهٔ یک فرمان بیاموزید:

      cargo help clean
