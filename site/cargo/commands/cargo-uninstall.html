    cargo-uninstall(1)

    نام

    cargo-uninstall — حذف یک فایل باینری Rust

    خلاصه

    cargo uninstall [options] [spec…]

    توضیحات

    این دستور بسته‌ای را که با cargo-install(1) نصب شده است حذف می‌کند. آرگومان spec مشخصات شناسهٔ بسته‌ای است که باید حذف شود (به cargo-pkgid(1) مراجعه کنید).

    به‌طور پیش‌فرض همهٔ فایل‌های باینری یک crate حذف می‌شوند، اما می‌توان با پرچم‌های --bin و --example فقط فایل‌های باینری مشخصی را حذف کرد.

    ریشهٔ نصب به ترتیب اولویت از موارد زیر تعیین می‌شود:

    • گزینهٔ --root
    • متغیر محیطی CARGO_INSTALL_ROOT
    • مقدار پیکربندی install.root در Cargo
    • متغیر محیطی CARGO_HOME
    • $HOME/.cargo

    گزینه‌ها

    گزینه‌های حذف

    -p
    --package spec…

    بسته‌ای که باید حذف شود.

    --bin name…

    فقط فایل باینری name را حذف می‌کند.

    --root dir

    دایرکتوری‌ای که بسته‌ها باید از آن حذف شوند.

    گزینه‌های نمایش

    -v
    --verbose

    از خروجی مفصل استفاده می‌کند. می‌توان آن را دو بار مشخص کرد تا خروجی «بسیار مفصل» شامل خروجی‌های اضافی مانند هشدارهای وابستگی‌ها و خروجی build scriptها تولید شود. همچنین می‌توان آن را با مقدار پیکربندی term.verbose مشخص کرد.

    -q
    --quiet

    پیام‌های گزارش cargo را چاپ نمی‌کند. همچنین می‌توان آن را با مقدار پیکربندی term.quiet مشخص کرد.

    --color when

    تعیین می‌کند خروجی رنگی چه زمانی استفاده شود. مقادیر معتبر:

    • auto (پیش‌فرض): به‌طور خودکار تشخیص می‌دهد که ترمینال از رنگ پشتیبانی می‌کند یا نه.
    • always: همیشه رنگ‌ها را نمایش می‌دهد.
    • never: هرگز رنگ‌ها را نمایش نمی‌دهد.

    همچنین می‌توان آن را با مقدار پیکربندی term.color مشخص کرد.

    گزینه‌های رایج

    +toolchain

    اگر Cargo با rustup نصب شده باشد و اولین آرگومان cargo با + شروع شود، به‌عنوان نام یک toolchain در rustup تفسیر می‌شود (مانند +stable یا +nightly). برای اطلاعات بیشتر دربارهٔ نحوهٔ کار بازنویسی toolchain، به مستندات rustup مراجعه کنید.

    --config KEY=VALUE یا PATH

    یک مقدار پیکربندی Cargo را بازنویسی می‌کند. آرگومان باید با نحو TOML به شکل KEY=VALUE باشد، یا به‌صورت مسیر یک فایل پیکربندی اضافی داده شود. این پرچم را می‌توان چندین بار مشخص کرد. برای اطلاعات بیشتر، بخش بازنویسی‌های خط فرمان را ببینید.

    -C PATH

    پیش از اجرای هر عملیات مشخص‌شده، دایرکتوری کاری فعلی را تغییر می‌دهد. این موضوع بر مواردی مانند محل جست‌وجوی پیش‌فرض cargo برای manifest پروژه (Cargo.toml) و نیز دایرکتوری‌هایی که برای یافتن .cargo/config.toml جست‌وجو می‌شوند اثر می‌گذارد. این گزینه باید پیش از نام دستور بیاید، برای مثال cargo -C path/to/my-project build.

    این گزینه فقط روی کانال nightly در دسترس است و برای فعال شدن به پرچم -Z unstable-options نیاز دارد (#10098 را ببینید).

    -h
    --help

    اطلاعات راهنما را چاپ می‌کند.

    -Z flag

    پرچم‌های ناپایدار (فقط nightly) برای Cargo. برای جزئیات cargo -Z help را اجرا کنید.
