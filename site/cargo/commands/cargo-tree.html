    cargo-tree(1)

    نام

    cargo-tree — نمایش درختی گراف وابستگی‌ها

    خلاصه

    cargo tree [options]

    توضیحات

    این دستور درختی از وابستگی‌ها را در ترمینال نمایش می‌دهد. نمونه‌ای از یک پروژهٔ ساده که به بستهٔ «rand» وابسته است:

    myproject v0.1.0 (/myproject)
└── rand v0.7.3
    ├── getrandom v0.1.14
    │   ├── cfg-if v0.1.10
    │   └── libc v0.2.68
    ├── libc v0.2.68 (*)
    ├── rand_chacha v0.2.2
    │   ├── ppv-lite86 v0.2.6
    │   └── rand_core v0.5.1
    │       └── getrandom v0.1.14 (*)
    └── rand_core v0.5.1 (*)
[build-dependencies]
└── cc v1.0.50

    بسته‌هایی که با (*) علامت خورده‌اند «حذف تکرار» شده‌اند. وابستگی‌های این بسته پیش‌تر در جای دیگری از گراف نمایش داده شده‌اند و بنابراین دوباره تکرار نمی‌شوند. برای تکرار موارد تکراری از گزینهٔ --no-dedupe استفاده کنید.

    از پرچم -e می‌توان برای انتخاب انواع وابستگی‌هایی که باید نمایش داده شوند استفاده کرد. نوع «features» خروجی را طوری تغییر می‌دهد که featureهای فعال‌شده توسط هر وابستگی را نشان دهد. برای نمونه، cargo tree -e features:

    myproject v0.1.0 (/myproject)
└── log feature "serde"
    └── log v0.4.8
        ├── serde v1.0.106
        └── cfg-if feature "default"
            └── cfg-if v0.1.10

    در این درخت، myproject به log با feature به نام serde وابسته است. log نیز به نوبهٔ خود به cfg-if با featureهای «default» وابسته است. هنگام استفاده از -e features ممکن است به‌کار بردن پرچم -i برای نمایش اینکه featureها چگونه به یک بسته می‌رسند مفید باشد. برای جزئیات بیشتر، مثال‌های زیر را ببینید.

    یکپارچه‌سازی feature

    این دستور گرافی را نشان می‌دهد که بسیار به گراف featureهای یکپارچه‌شده‌ای که Cargo می‌سازد نزدیک‌تر است تا به آنچه شما در Cargo.toml فهرست می‌کنید. برای مثال، اگر یک وابستگی را هم در [dependencies] و هم در [dev-dependencies] اما با featureهای متفاوت مشخص کنید، این دستور ممکن است همهٔ featureها را ادغام کند و روی یکی از وابستگی‌ها علامت (*) بگذارد تا تکراری بودن را نشان دهد.

    در نتیجه، برای نمایی تقریباً معادل با کاری که cargo build انجام می‌دهد، cargo tree -e normal,build بسیار نزدیک است؛ و برای نمایی تقریباً معادل با کاری که cargo test انجام می‌دهد، cargo tree بسیار نزدیک است. با این حال، این دستور معادل بودن دقیق با آنچه Cargo قرار است بسازد را تضمین نمی‌کند، زیرا کامپایل پیچیده است و به عوامل بسیار متفاوتی بستگی دارد.

    برای آشنایی بیشتر با یکپارچه‌سازی feature، این بخش اختصاصی را ببینید.

    گزینه‌ها

    گزینه‌های درخت

    -i spec
    --invert spec

    وابستگی‌های معکوس بستهٔ داده‌شده را نشان می‌دهد. این پرچم درخت را وارونه می‌کند و بسته‌هایی را که به بستهٔ داده‌شده وابسته‌اند نمایش می‌دهد.

    توجه کنید که در یک workspace، به‌طور پیش‌فرض فقط وابستگی‌های معکوس بسته درون درخت عضو workspace در دایرکتوری فعلی نمایش داده می‌شود. می‌توان با پرچم --workspace آن را گسترش داد تا وابستگی‌های معکوس بسته در کل workspace نمایش داده شود. پرچم -p را می‌توان برای نمایش وابستگی‌های معکوس بسته فقط در زیردرخت بستهٔ داده‌شده به -p به کار برد.

    --prune spec

    بستهٔ داده‌شده را از نمایش درخت وابستگی‌ها هرس می‌کند.

    --depth depth

    بیشینهٔ عمق نمایش درخت وابستگی‌ها. برای مثال، عمق ۱ وابستگی‌های مستقیم را نشان می‌دهد.

    اگر مقدار داده‌شده workspace باشد، به‌جای آن فقط وابستگی‌هایی را نشان می‌دهد که عضو workspace فعلی هستند.

    --no-dedupe

    وابستگی‌های تکراری را حذف نمی‌کند. معمولاً وقتی بسته‌ای پیش‌تر وابستگی‌هایش را نمایش داده باشد، در دفعات بعدی دوباره وابستگی‌هایش نمایش داده نمی‌شود و علامت (*) می‌گیرد تا نشان دهد پیش‌تر نمایش داده شده است. این پرچم باعث می‌شود آن موارد تکراری دوباره نمایش داده شوند.

    -d
    --duplicates

    فقط وابستگی‌هایی را نشان می‌دهد که در چند نسخه وجود دارند (مستلزم --invert است). وقتی همراه با پرچم -p به کار رود، فقط موارد تکراری درون زیردرخت بستهٔ داده‌شده را نشان می‌دهد.

    پرهیز از ساخت چندبارهٔ یک بسته می‌تواند برای زمان ساخت و اندازهٔ فایل‌های اجرایی سودمند باشد. این پرچم می‌تواند به شناسایی بسته‌های مسئله‌ساز کمک کند. سپس می‌توانید بررسی کنید که آیا بسته‌ای که به نسخهٔ قدیمی‌تر مورد تکراری وابسته است می‌تواند به نسخهٔ جدیدتر به‌روزرسانی شود تا فقط یک نمونه ساخته شود.

    -e kinds
    --edges kinds

    انواع وابستگی‌هایی که باید نمایش داده شوند. فهرستی از مقادیر جداشده با ویرگول می‌گیرد:

    • all — همهٔ انواع یال را نشان می‌دهد.
    • normal — وابستگی‌های معمولی را نشان می‌دهد.
    • build — وابستگی‌های ساخت را نشان می‌دهد.
    • dev — وابستگی‌های توسعه را نشان می‌دهد.
    • features — featureهای فعال‌شده توسط هر وابستگی را نشان می‌دهد. اگر این تنها نوع داده‌شده باشد، به‌طور خودکار انواع دیگر وابستگی را هم شامل می‌شود.
    • no-normal — وابستگی‌های معمولی را شامل نمی‌شود.
    • no-build — وابستگی‌های ساخت را شامل نمی‌شود.
    • no-dev — وابستگی‌های توسعه را شامل نمی‌شود.
    • no-proc-macro — وابستگی‌های ماکروی رویه‌ای را شامل نمی‌شود.

    انواع وابستگی normal، build، dev و all را نمی‌توان با انواع no-normal، no-build یا no-dev ترکیب کرد.

    مقدار پیش‌فرض normal,build,dev است.

    --target tuple

    وابستگی‌هایی را که با tuple هدف داده‌شده مطابقت دارند فیلتر می‌کند. مقدار پیش‌فرض، پلتفرم میزبان است. برای شامل کردن همهٔ هدف‌ها از مقدار all استفاده کنید.

    گزینه‌های قالب‌بندی درخت

    --charset charset

    مجموعه نویسه‌ای را که برای درخت به کار می‌رود انتخاب می‌کند. مقادیر معتبر «utf8» یا «ascii» هستند. اگر مشخص نشود، cargo خودش یک مقدار را برمی‌گزیند.

    -f format
    --format format

    رشتهٔ قالب هر بسته را تعیین می‌کند. مقدار پیش‌فرض «{p}» است.

    این یک رشتهٔ دلخواه است که برای نمایش هر بسته به کار می‌رود. رشته‌های زیر با مقدار متناظرشان جایگزین می‌شوند:

    • {p}، {package} — نام بسته.
    • {l}، {license} — مجوز بسته.
    • {r}، {repository} — نشانی URL مخزن بسته.
    • {f}، {features} — فهرست featureهای فعال بسته، جداشده با ویرگول.
    • {lib} — نامِ کتابخانهٔ بسته، همان‌گونه که در دستور use به کار می‌رود.
    --prefix prefix

    نحوهٔ نمایش هر خط را تعیین می‌کند. مقدار prefix می‌تواند یکی از موارد زیر باشد:

    • indent (پیش‌فرض) — هر خط را به‌صورت درختی و با تورفتگی نشان می‌دهد.
    • depth — به‌صورت فهرست نشان می‌دهد و عمق عددی را پیش از هر مورد چاپ می‌کند.
    • none — به‌صورت فهرست مسطح نشان می‌دهد.

    انتخاب بسته

    به‌طور پیش‌فرض، وقتی هیچ گزینهٔ انتخاب بسته‌ای داده نشده باشد، بسته‌های انتخاب‌شده به فایل manifest انتخاب‌شده بستگی دارند (اگر --manifest-path داده نشده باشد، بر اساس دایرکتوری کاری فعلی). اگر manifest ریشهٔ یک workspace باشد، اعضای پیش‌فرض workspace انتخاب می‌شوند؛ در غیر این صورت فقط بسته‌ای که manifest تعریف می‌کند انتخاب خواهد شد.

    اعضای پیش‌فرض یک workspace را می‌توان با کلید workspace.default-members در manifest ریشه به‌صراحت تعیین کرد. اگر این کلید تنظیم نشده باشد، یک workspace مجازی همهٔ اعضای workspace را شامل می‌شود (معادل دادن --workspace) و یک workspace غیرمجازی فقط خود crate ریشه را شامل می‌شود.

    -p spec…
    --package spec…

    فقط بسته‌های مشخص‌شده را نمایش می‌دهد. برای قالب SPEC، cargo-pkgid(1) را ببینید. این پرچم را می‌توان چندین بار مشخص کرد و از الگوهای glob رایج یونیکس مانند *، ? و [] پشتیبانی می‌کند. با این حال، برای اینکه shell شما پیش از رسیدن الگوها به Cargo به‌طور ناخواسته آن‌ها را باز نکند، باید دور هر الگو از نقل‌قول تکی یا دوتایی استفاده کنید.

    --workspace

    همهٔ اعضای workspace را نمایش می‌دهد.

    --exclude SPEC…

    بسته‌های مشخص‌شده را کنار می‌گذارد. باید همراه با پرچم --workspace استفاده شود. این پرچم را می‌توان چندین بار مشخص کرد و از الگوهای glob رایج یونیکس مانند *، ? و [] پشتیبانی می‌کند. با این حال، برای اینکه shell شما پیش از رسیدن الگوها به Cargo به‌طور ناخواسته آن‌ها را باز نکند، باید دور هر الگو از نقل‌قول تکی یا دوتایی استفاده کنید.

    گزینه‌های manifest

    --manifest-path path

    مسیر فایل Cargo.toml. به‌طور پیش‌فرض، Cargo فایل Cargo.toml را در دایرکتوری فعلی یا هر دایرکتوری والد جست‌وجو می‌کند.

    --locked

    تأیید می‌کند که دقیقاً همان وابستگی‌ها و نسخه‌هایی به کار رفته‌اند که هنگام تولید اولیهٔ فایل Cargo.lock موجود استفاده شده بودند. Cargo در یکی از دو حالت زیر با خطا خارج می‌شود:

    • فایل قفل وجود نداشته باشد.
    • Cargo به‌دلیل تفاوت در حل وابستگی‌ها بخواهد فایل قفل را تغییر دهد.

    می‌توان آن را در محیط‌هایی که ساخت‌های قطعی (deterministic) مطلوب است، مانند خط لوله‌های CI، به کار برد.

    --offline

    مانع می‌شود Cargo به هر دلیلی به شبکه دسترسی پیدا کند. بدون این پرچم، اگر Cargo نیاز به دسترسی به شبکه داشته باشد و شبکه در دسترس نباشد، با خطا متوقف می‌شود. با این پرچم، Cargo در صورت امکان بدون شبکه ادامه می‌دهد.

    توجه داشته باشید که این ممکن است به حل وابستگی‌هایی متفاوت از حالت آنلاین منجر شود. Cargo خود را به crateهایی محدود می‌کند که به‌صورت محلی دانلود شده‌اند، حتی اگر بر پایهٔ نسخهٔ محلی index نسخهٔ جدیدتری وجود داشته باشد. برای دانلود وابستگی‌ها پیش از آفلاین شدن، دستور cargo-fetch(1) را ببینید.

    همچنین می‌توان آن را با مقدار پیکربندی net.offline مشخص کرد.

    --frozen

    معادل مشخص کردن هر دو پرچم --locked و --offline است.

    انتخاب feature

    پرچم‌های feature به شما اجازه می‌دهند کنترل کنید کدام featureها فعال شوند. وقتی هیچ گزینهٔ featureای داده نشده باشد، feature به نام default برای هر بستهٔ انتخاب‌شده فعال می‌شود.

    برای جزئیات بیشتر، مستندات featureها را ببینید.

    -F features
    --features features

    فهرست featureهای قابل فعال‌سازی، جداشده با فاصله یا ویرگول. featureهای اعضای workspace را می‌توان با نحو package-name/feature-name فعال کرد. این پرچم را می‌توان چندین بار مشخص کرد که همهٔ featureهای مشخص‌شده را فعال می‌کند.

    --all-features

    همهٔ featureهای موجود همهٔ بسته‌های انتخاب‌شده را فعال می‌کند.

    --no-default-features

    feature به نام default بسته‌های انتخاب‌شده را فعال نمی‌کند.

    گزینه‌های نمایش

    -v
    --verbose

    از خروجی مفصل استفاده می‌کند. می‌توان آن را دو بار مشخص کرد تا خروجی «بسیار مفصل» شامل خروجی‌های اضافی مانند هشدارهای وابستگی‌ها و خروجی build scriptها تولید شود. همچنین می‌توان آن را با مقدار پیکربندی term.verbose مشخص کرد.

    -q
    --quiet

    پیام‌های گزارش cargo را چاپ نمی‌کند. همچنین می‌توان آن را با مقدار پیکربندی term.quiet مشخص کرد.

    --color when

    تعیین می‌کند خروجی رنگی چه زمانی استفاده شود. مقادیر معتبر:

    • auto (پیش‌فرض): به‌طور خودکار تشخیص می‌دهد که ترمینال از رنگ پشتیبانی می‌کند یا نه.
    • always: همیشه رنگ‌ها را نمایش می‌دهد.
    • never: هرگز رنگ‌ها را نمایش نمی‌دهد.

    همچنین می‌توان آن را با مقدار پیکربندی term.color مشخص کرد.

    گزینه‌های رایج

    +toolchain

    اگر Cargo با rustup نصب شده باشد و اولین آرگومان cargo با + شروع شود، به‌عنوان نام یک toolchain در rustup تفسیر می‌شود (مانند +stable یا +nightly). برای اطلاعات بیشتر دربارهٔ نحوهٔ کار بازنویسی toolchain، به مستندات rustup مراجعه کنید.

    --config KEY=VALUE یا PATH

    یک مقدار پیکربندی Cargo را بازنویسی می‌کند. آرگومان باید با نحو TOML به شکل KEY=VALUE باشد، یا به‌صورت مسیر یک فایل پیکربندی اضافی داده شود. این پرچم را می‌توان چندین بار مشخص کرد. برای اطلاعات بیشتر، بخش بازنویسی‌های خط فرمان را ببینید.

    -C PATH

    پیش از اجرای هر عملیات مشخص‌شده، دایرکتوری کاری فعلی را تغییر می‌دهد. این موضوع بر مواردی مانند محل جست‌وجوی پیش‌فرض cargo برای manifest پروژه (Cargo.toml) و نیز دایرکتوری‌هایی که برای یافتن .cargo/config.toml جست‌وجو می‌شوند اثر می‌گذارد. این گزینه باید پیش از نام دستور بیاید، برای مثال cargo -C path/to/my-project build.

    این گزینه فقط روی کانال nightly در دسترس است و برای فعال شدن به پرچم -Z unstable-options نیاز دارد (#10098 را ببینید).

    -h
    --help

    اطلاعات راهنما را چاپ می‌کند.

    -Z flag

    پرچم‌های ناپایدار (فقط nightly) برای Cargo. برای جزئیات cargo -Z help را اجرا کنید.

    متغیرهای محیطی

    برای جزئیات متغیرهای محیطی که Cargo می‌خواند، مرجع را ببینید.

    وضعیت خروج

    • 0: Cargo موفق بود.
    • 101: Cargo نتوانست کار را کامل کند.

    مثال‌ها

    1. نمایش درخت بستهٔ موجود در دایرکتوری فعلی:

      cargo tree

    2. نمایش همهٔ بسته‌هایی که به بستهٔ syn وابسته‌اند:

      cargo tree -i syn

    3. نمایش featureهای فعال‌شده روی هر بسته:

      cargo tree --format "{p} {f}"

    4. نمایش همهٔ بسته‌هایی که چندین بار ساخته می‌شوند. این اتفاق می‌تواند زمانی بیفتد که چند نسخهٔ ناسازگار از نظر semver در درخت ظاهر شوند (مانند 1.0.0 و 2.0.0).

      cargo tree -d

    5. توضیح اینکه چرا featureها برای بستهٔ syn فعال شده‌اند:

      cargo tree -e features -i syn

      پرچم -e features برای نمایش featureها به کار می‌رود. پرچم -i برای وارونه کردن گراف به کار می‌رود تا بسته‌هایی را که به syn وابسته‌اند نمایش دهد. نمونه‌ای از آنچه این دستور نمایش می‌دهد:

      syn v1.0.17
├── syn feature "clone-impls"
│   └── syn feature "default"
│       └── rustversion v1.0.2
│           └── rustversion feature "default"
│               └── myproject v0.1.0 (/myproject)
│                   └── myproject feature "default" (command-line)
├── syn feature "default" (*)
├── syn feature "derive"
│   └── syn feature "default" (*)
├── syn feature "full"
│   └── rustversion v1.0.2 (*)
├── syn feature "parsing"
│   └── syn feature "default" (*)
├── syn feature "printing"
│   └── syn feature "default" (*)
├── syn feature "proc-macro"
│   └── syn feature "default" (*)
└── syn feature "quote"
    ├── syn feature "printing" (*)
    └── syn feature "proc-macro" (*)

      برای خواندن این گراف، می‌توانید زنجیرهٔ هر feature را از ریشه دنبال کنید تا ببینید چرا شامل شده است. برای مثال، feature به نام «full» توسط crate به نام rustversion اضافه شده است که از myproject (با featureهای پیش‌فرض) می‌آید، و myproject بسته‌ای است که در خط فرمان انتخاب شده است. همهٔ featureهای دیگر syn توسط feature «default» اضافه شده‌اند («quote» توسط «printing» و «proc-macro» اضافه شده است که هر دو featureهای پیش‌فرض هستند).

      اگر در تطبیق ارجاعی موارد (*)ی حذف‌تکرارشده مشکل دارید، با پرچم --no-dedupe امتحان کنید تا خروجی کامل را بگیرید.
