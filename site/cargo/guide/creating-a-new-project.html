    ساخت یک بستهٔ جدید

    برای شروع یک بستهٔ جدید با Cargo، از cargo new استفاده کنید:

    $ cargo new hello_world --bin

    ما --bin را می‌دهیم چون در حال ساخت یک برنامهٔ باینری هستیم: اگر قصد ساخت یک کتابخانه را داشتیم، --lib را می‌دادیم. این دستور به‌طور پیش‌فرض یک مخزن git جدید نیز راه‌اندازی می‌کند. اگر نمی‌خواهید چنین کاری انجام شود، --vcs none را بدهید.

    بیایید ببینیم Cargo برای ما چه چیزی تولید کرده است:

    $ cd hello_world
$ tree .
.
├── Cargo.toml
└── src
    └── main.rs

1 directory, 2 files

    بیایید نگاه دقیق‌تری به Cargo.toml بیندازیم:

    [package]
name = "hello_world"
version = "0.1.0"
edition = "2024"

[dependencies]

    این فایل یک manifest نام دارد و شامل همهٔ فرادادهٔ مورد نیاز Cargo برای کامپایل بستهٔ شماست. این فایل با قالب TOML (تلفظ: /tɑməl/) نوشته شده است.

    این هم محتوای src/main.rs:

    fn main() {
    println!("Hello, world!");
}

    Cargo یک برنامهٔ «hello world» برای شما تولید کرد که با نام binary crate نیز شناخته می‌شود. بیایید آن را کامپایل کنیم:

    $ cargo build
   Compiling hello_world v0.1.0 (file:///path/to/package/hello_world)

    و سپس اجرایش کنیم:

    $ ./target/debug/hello_world
Hello, world!

    همچنین می‌توانید از cargo run استفاده کنید تا کامپایل و اجرا را در یک مرحله انجام دهید (اگر از آخرین کامپایل تاکنون تغییری نداده باشید، خط Compiling را نخواهید دید):

    $ cargo run
   Compiling hello_world v0.1.0 (file:///path/to/package/hello_world)
     Running `target/debug/hello_world`
Hello, world!

    اکنون متوجه یک فایل جدید به نام Cargo.lock می‌شوید. این فایل اطلاعاتی دربارهٔ وابستگی‌های شما دارد. چون هنوز وابستگی‌ای وجود ندارد، چندان جالب نیست.

    وقتی برای انتشار آماده شدید، می‌توانید از cargo build --release استفاده کنید تا فایل‌هایتان با بهینه‌سازی‌های فعال کامپایل شوند:

    $ cargo build --release
   Compiling hello_world v0.1.0 (file:///path/to/package/hello_world)

    cargo build --release فایل باینری حاصل را به‌جای target/debug در target/release قرار می‌دهد.

    کامپایل در حالت debug برای توسعه پیش‌فرض است. زمان کامپایل کوتاه‌تر است، چون کامپایلر بهینه‌سازی انجام نمی‌دهد، اما کد کندتر اجرا می‌شود. حالت release کامپایل طولانی‌تری دارد، اما کد سریع‌تر اجرا می‌شود.
