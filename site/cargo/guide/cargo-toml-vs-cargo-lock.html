    Cargo.toml در برابر Cargo.lock

    Cargo.toml و Cargo.lock دو هدف متفاوت را دنبال می‌کنند. پیش از صحبت دربارهٔ آن‌ها، این خلاصه را ببینید:

    • Cargo.toml وابستگی‌های شما را به‌صورت کلی توصیف می‌کند و خودتان آن را می‌نویسید.
    • Cargo.lock اطلاعات دقیق دربارهٔ وابستگی‌های شما را در خود دارد. این فایل توسط Cargo نگهداری می‌شود و نباید دستی ویرایش شود.

    اگر مطمئن نیستید، Cargo.lock را در سیستم کنترل نسخه (مثلاً Git) ثبت کنید. برای درک بهتر اینکه چرا و جایگزین‌ها چه می‌توانند باشند، به «چرا Cargo.lock در کنترل نسخه باشد؟» در پرسش‌های متداول مراجعه کنید. توصیه می‌کنیم این کار را با تأیید آخرین وابستگی‌ها همراه کنید.

    بیایید کمی عمیق‌تر شویم.

    Cargo.toml یک فایل manifest است که در آن می‌توانید مجموعه‌ای از فراداده‌های مختلف دربارهٔ بستهٔ خود را مشخص کنید. برای مثال، می‌توانید بگویید که به بستهٔ دیگری وابسته‌اید:

    [package]
name = "hello_world"
version = "0.1.0"

[dependencies]
regex = { git = "https://github.com/rust-lang/regex.git" }

    این بسته یک وابستگی واحد دارد، به کتابخانهٔ regex. در این حالت اعلام می‌کند که به یک مخزن Git مشخص که در GitHub قرار دارد تکیه کند. چون اطلاعات دیگری مشخص نکرده‌اید، Cargo فرض می‌کند که می‌خواهید برای ساخت بسته‌مان از آخرین commit در شاخهٔ پیش‌فرض استفاده کنید.

    خوب به نظر می‌رسد؟ خب، یک مشکل وجود دارد: اگر امروز این بسته را بسازید و سپس یک نسخه از آن را برای من بفرستید و من فردا آن را بسازم، ممکن است اتفاق بدی بیفتد. ممکن است در این فاصله commitهای بیشتری به regex اضافه شده باشد و ساخت من شامل commitهای جدید باشد در حالی که ساخت شما نباشد. در نتیجه، ساخت‌های متفاوتی خواهیم داشت. این بد است، چون ما ساخت‌های تکرارپذیر می‌خواهیم.

    می‌توانید با تعریف یک مقدار rev مشخص در Cargo.toml این مشکل را حل کنید، تا Cargo دقیقاً بداند هنگام ساخت بسته از کدام revision استفاده کند:

    [dependencies]
regex = { git = "https://github.com/rust-lang/regex.git", rev = "9f9f693" }

    اکنون ساخت‌های ما یکسان خواهند بود. اما یک عیب بزرگ وجود دارد: حالا باید هر بار که می‌خواهید کتابخانهٔ ما را به‌روز کنید، دستی به SHA-1ها فکر کنید. این کار هم خسته‌کننده است و هم مستعد خطا.

    اینجاست که Cargo.lock وارد می‌شود. به‌خاطر وجود آن، لازم نیست revisionهای دقیق را دستی دنبال کنید: Cargo این کار را برای شما انجام می‌دهد. وقتی manifestی مانند این دارید:

    [package]
name = "hello_world"
version = "0.1.0"

[dependencies]
regex = { git = "https://github.com/rust-lang/regex.git" }

    Cargo آخرین commit را برمی‌دارد و هنگام اولین ساخت، آن اطلاعات را در Cargo.lock شما می‌نویسد. آن فایل چیزی شبیه به این خواهد بود:

    [[package]]
name = "hello_world"
version = "0.1.0"
dependencies = [
 "regex 1.5.0 (git+https://github.com/rust-lang/regex.git#9f9f693768c584971a4d53bc3c586c33ed3a6831)",
]

[[package]]
name = "regex"
version = "1.5.0"
source = "git+https://github.com/rust-lang/regex.git#9f9f693768c584971a4d53bc3c586c33ed3a6831"

    می‌بینید که اطلاعات بسیار بیشتری در اینجا وجود دارد، از جمله revision دقیقی که برای ساخت استفاده کرده‌اید. اکنون وقتی بستهٔ خود را به شخص دیگری بدهید، او دقیقاً از همان SHA استفاده خواهد کرد، حتی اگر شما آن را در Cargo.toml مشخص نکرده باشید.

    وقتی آمادهٔ پذیرش نسخهٔ جدیدی از کتابخانه شدید، Cargo می‌تواند وابستگی‌ها را دوباره محاسبه کند و همه‌چیز را برایتان به‌روز کند:

    $ cargo update         # updates all dependencies
$ cargo update regex   # updates just “regex”

    این دستور یک Cargo.lock جدید با اطلاعات نسخهٔ جدید می‌نویسد. توجه کنید که آرگومان cargo update در واقع یک مشخصهٔ شناسهٔ بسته است و regex فقط یک مشخصهٔ کوتاه است.
