    کمی Rust در کنار C شما

    استفاده از کد Rust در یک پروژهٔ C یا C++ عمدتاً از دو بخش تشکیل می‌شود.

    • ساختن یک API دوستدار C در Rust
    • جاسازی پروژهٔ Rust خود در یک سامانهٔ ساخت خارجی

    جز cargo و meson، بیشتر سامانه‌های ساخت پشتیبانی بومی از Rust ندارند. بنابراین به احتمال زیاد بهترین کار این است که برای کامپایل crate خود و همهٔ وابستگی‌هایش فقط از cargo استفاده کنید.

    راه‌اندازی یک پروژه

    یک پروژهٔ cargo جدید را مثل همیشه بسازید.

    پرچم‌هایی وجود دارند که به cargo می‌گویند به‌جای هدف معمول Rust، یک کتابخانهٔ سیستمی تولید کند. این پرچم‌ها همچنین به شما اجازه می‌دهند اگر بخواهید نام خروجی کتابخانه با بقیهٔ crate شما فرق داشته باشد، نام دیگری برایش تعیین کنید.

    [lib]
name = "your_crate"
crate-type = ["cdylib"]      # Creates dynamic lib
# crate-type = ["staticlib"] # Creates static lib

    ساختن یک API از نوع C

    چون C++ ABI پایداری ندارد که کامپایلر Rust آن را هدف بگیرد، برای هر قابلیت همکاری میان زبان‌های مختلف از C استفاده می‌کنیم. هنگام استفاده از Rust در کد C و C++ هم از این قاعده مستثنا نیستیم.

    #[no_mangle]

    کامپایلر Rust نام نمادها (symbol) را به شیوه‌ای متفاوت از آنچه پیوندگرهای کد بومی انتظار دارند آشفته (mangle) می‌کند. به همین دلیل، به هر تابعی که Rust برای استفاده بیرون از Rust صادر می‌کند باید گفته شود که کامپایلر نامش را آشفته نکند.

    extern "C"

    به‌طور پیش‌فرض، هر تابعی که در Rust می‌نویسید از ABI مخصوص Rust استفاده می‌کند (که آن هم پایدار نشده است). در عوض، هنگام ساختن APIهای FFI رو به بیرون باید به کامپایلر بگوییم از ABI سیستم استفاده کند.

    بسته به پلتفرم شما، ممکن است بخواهید نسخهٔ خاصی از ABI را هدف بگیرید که اینجا مستند شده‌اند.

    با کنار هم گذاشتن این بخش‌ها، تابعی به دست می‌آورید که تقریباً به این شکل است.

    #[no_mangle]
pub extern "C" fn rust_function() {

}

    درست مانند وقتی که از کد C در پروژهٔ Rust خود استفاده می‌کنید، اکنون نیز باید داده را از و به شکلی تبدیل کنید که بقیهٔ برنامه آن را بفهمد.

    پیوند‌دهی و بافتار گسترده‌تر پروژه.

    پس، این نیمی از مسئله بود که حل شد. حالا چگونه از آن استفاده می‌کنید؟

    این به‌شدت به پروژه و/یا سامانهٔ ساخت شما بستگی دارد

    cargo بسته به پلتفرم و تنظیمات شما، یک فایل my_lib.so/my_lib.dll یا my_lib.a می‌سازد. این کتابخانه را سامانهٔ ساخت شما می‌تواند به‌سادگی پیوند بزند.

    با این حال، فراخوانی یک تابع Rust از C به یک فایل سرآیند (header) برای اعلام امضای توابع نیاز دارد.

    هر تابع در API مبتنی بر ffi در Rust شما باید یک تابع متناظر در سرآیند داشته باشد.

    #[no_mangle]
pub extern "C" fn rust_function() {}

    سپس تبدیل می‌شود به

    void rust_function();

    etc.

    ابزاری برای خودکارسازی این فرایند وجود دارد که cbindgen نام دارد؛ این ابزار کد Rust شما را تحلیل می‌کند و سپس از روی آن سرآیندهایی برای پروژه‌های C و C++ شما تولید می‌کند.

    در این مرحله، استفاده از توابع Rust در C به سادگی گنجاندن سرآیند و فراخوانی آن‌هاست!

    #include "my-rust-project.h"
rust_function();
