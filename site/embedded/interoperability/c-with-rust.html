    کمی C در کنار Rust شما

    استفاده از C یا C++ درون یک پروژهٔ Rust از دو بخش اصلی تشکیل می‌شود:

    • پوشاندن API ارائه‌شدهٔ C برای استفاده با Rust
    • ساخت کد C یا C++ شما تا با کد Rust یکپارچه شود

    چون C++ ABI پایداری ندارد که کامپایلر Rust آن را هدف بگیرد، توصیه می‌شود هنگام ترکیب Rust با C یا C++ از ABI نوع C استفاده شود.

    تعریف رابط

    پیش از مصرف کد C یا C++ از Rust، لازم است (در Rust) تعریف کنیم که چه نوع‌های داده و امضاهای توابعی در کد پیوند‌شده وجود دارند. در C یا C++، فایلی سرآیند (.h یا .hpp) را include می‌کنید که این داده را تعریف می‌کند. در Rust لازم است یا این تعریف‌ها را دستی به Rust ترجمه کنید، یا از ابزاری برای تولید این تعریف‌ها استفاده کنید.

    ابتدا ترجمهٔ دستی این تعریف‌ها از C/C++ به Rust را بررسی می‌کنیم.

    پوشاندن توابع و نوع‌های داده در C

    معمولاً کتابخانه‌هایی که با C یا C++ نوشته شده‌اند یک فایل سرآیند فراهم می‌کنند که همهٔ نوع‌ها و توابع به‌کاررفته در رابط‌های عمومی را تعریف می‌کند. یک فایل نمونه ممکن است چنین باشد:

    /* File: cool.h */
typedef struct CoolStruct {
    int x;
    int y;
} CoolStruct;

void cool_function(int i, char c, CoolStruct* cs);

    وقتی به Rust ترجمه شود، این رابط به این شکل خواهد بود:

    /* File: cool_bindings.rs */
#[repr(C)]
pub struct CoolStruct {
    pub x: cty::c_int,
    pub y: cty::c_int,
}

extern "C" {
    pub fn cool_function(
        i: cty::c_int,
        c: cty::c_char,
        cs: *mut CoolStruct
    );
}

    بیایید این تعریف را تکه‌تکه بررسی کنیم تا هر بخش را توضیح دهیم.

    #[repr(C)]
pub struct CoolStruct { ... }

    به‌طور پیش‌فرض، Rust ترتیب، فاصله‌گذاری (padding) یا اندازهٔ داده‌های موجود در یک struct را تضمین نمی‌کند. برای تضمین سازگاری با کد C، attribute به نام #[repr(C)] را اضافه می‌کنیم که به کامپایلر Rust دستور می‌دهد برای سازمان‌دهی داده‌ها درون یک ساختار همیشه از همان قواعدی استفاده کند که C به کار می‌برد.

    pub x: cty::c_int,
pub y: cty::c_int,

    به‌خاطر انعطافی که C یا C++ در تعریف int یا char دارند، توصیه می‌شود از نوع‌های داده‌ای اولیه‌ای استفاده کنید که در cty تعریف شده‌اند و نوع‌های C را به نوع‌های Rust نگاشت می‌کنند.

    extern "C" { pub fn cool_function( ... ); }

    این دستور امضای تابعی را تعریف می‌کند که از ABI زبان C استفاده می‌کند و cool_function نام دارد. با تعریف امضا بدون تعریف بدنهٔ تابع، تعریف این تابع باید در جای دیگری فراهم شود، یا از یک کتابخانهٔ ایستا در کتابخانه یا باینری نهایی پیوند داده شود.

        i: cty::c_int,
    c: cty::c_char,
    cs: *mut CoolStruct

    مشابه نوع داده‌ای که بالا آمد، نوع‌های داده‌ای آرگومان‌های تابع را با تعریف‌های سازگار با C تعریف می‌کنیم. برای وضوح، نام آرگومان‌ها را نیز همان‌طور نگه می‌داریم.

    یک نوع جدید در اینجا داریم: *mut CoolStruct. چون C مفهوم ارجاع‌های Rust را ندارد، که چیزی شبیه این می‌شد: &mut CoolStruct، در عوض یک اشاره‌گر خام داریم. از آن‌جا که dereference کردن این اشاره‌گر unsafe است و اشاره‌گر ممکن است در واقع یک اشاره‌گر null باشد، هنگام تعامل با کد C یا C++ باید مراقب بود که تضمین‌های معمول Rust حفظ شوند.

    تولید خودکار رابط

    به‌جای تولید دستی این رابط‌ها، که ممکن است خسته‌کننده و مستعد خطا باشد، ابزاری به نام bindgen وجود دارد که این تبدیل‌ها را به‌طور خودکار انجام می‌دهد. برای راهنمای استفاده از bindgen به راهنمای کاربر bindgen مراجعه کنید، با این حال فرایند معمول شامل مراحل زیر است:

    1. همهٔ سرآیندهای C یا C++ را که رابط‌ها یا نوع‌های داده‌ای را تعریف می‌کنند و می‌خواهید با Rust استفاده کنید گرد آورید.
    2. یک فایل bindings.h بنویسید که هر یک از فایل‌هایی را که در گام اول گرد آوردید با #include "..." درج کند.
    3. این فایل bindings.h را همراه با هر پرچم کامپایلی که برای کامپایل کدتان به کار رفته به bindgen بدهید. نکته: از Builder.ctypes_prefix("cty") / --ctypes-prefix=cty و Builder.use_core() / --use-core استفاده کنید تا کد تولیدشده با #![no_std] سازگار شود.
    4. bindgen کد Rust تولیدشده را در خروجی پنجرهٔ ترمینال تولید می‌کند. این خروجی را می‌توان به یک فایل در پروژهٔ شما، مانند bindings.rs، هدایت کرد. می‌توانید از این فایل در پروژهٔ Rust خود برای تعامل با کد C/C++ که به‌صورت کتابخانهٔ خارجی کامپایل و پیوند شده است استفاده کنید. نکته: اگر نوع‌ها در bindingهای تولیدشده با cty پیشوند خورده‌اند، فراموش نکنید که از crate به نام cty استفاده کنید.

    ساخت کد C/C++ شما

    چون کامپایلر Rust مستقیماً نمی‌داند چگونه کد C یا C++ (یا کد هر زبان دیگری که رابط C ارائه می‌دهد) را کامپایل کند، لازم است کد غیر Rust خود را از پیش کامپایل کنید.

    در پروژه‌های توکار، این بیشتر به معنای کامپایل کد C/C++ به یک آرشیو ایستا (مانند cool-library.a) است که سپس می‌توان آن را در گام نهایی پیوند با کد Rust شما ترکیب کرد.

    اگر کتابخانه‌ای که می‌خواهید استفاده کنید از قبل به‌صورت آرشیو ایستا توزیع شده است، لازم نیست کدتان را دوباره بسازید. فقط فایل سرآیند رابط ارائه‌شده را همان‌طور که در بالا توضیح داده شد تبدیل کنید و آرشیو ایستا را هنگام کامپایل/پیوند بگنجانید.

    اگر کد شما به‌صورت یک پروژهٔ سورس وجود دارد، لازم است کد C/C++ خود را به یک کتابخانهٔ ایستا کامپایل کنید، یا با راه‌اندازی سامانهٔ ساخت موجودتان (مانند make، CMake و غیره)، یا با انتقال گام‌های کامپایل لازم به ابزاری به نام crate به نام cc. برای هر دوی این گام‌ها لازم است از یک اسکریپت build.rs استفاده کنید.

    اسکریپت‌های ساخت build.rs در Rust

    اسکریپت build.rs فایلی است که با نحو Rust نوشته می‌شود و روی ماشین کامپایل شما اجرا می‌شود، بعد از آن‌که وابستگی‌های پروژهٔ شما ساخته شدند، اما پیش از ساخته شدن پروژهٔ شما.

    مرجع کامل را می‌توانید اینجا بیابید. اسکریپت‌های build.rs برای تولید کد (مثلاً از طریق bindgen)، فراخوانی سامانه‌های ساخت خارجی مانند Make، یا کامپایل مستقیم C/C++ با استفاده از crate به نام cc مفیدند.

    راه‌اندازی سامانه‌های ساخت خارجی

    برای پروژه‌هایی که پروژه‌ها یا سامانه‌های ساخت خارجی پیچیده‌ای دارند، ممکن است ساده‌ترین کار این باشد که با std::process::Command از سامانه‌های ساخت دیگرتان «بیرون‌پرانی» (shell out) کنید: با پیمودن مسیرهای نسبی، فراخوانی یک دستور ثابت (مانند make library) و سپس کپی کردن کتابخانهٔ ایستای حاصل به مکان مناسب در پوشهٔ ساخت target.

    اگرچه crate شما ممکن است یک پلتفرم توکار no_std را هدف بگیرد، build.rs شما فقط روی ماشین‌هایی اجرا می‌شود که crate شما را کامپایل می‌کنند. این یعنی می‌توانید از هر crate Rust که روی میزبان کامپایل شما اجرا می‌شود استفاده کنید.

    ساخت کد C/C++ با crate به نام cc

    برای پروژه‌هایی با وابستگی‌ها یا پیچیدگی محدود، یا پروژه‌هایی که تغییر سامانهٔ ساخت برای تولید یک کتابخانهٔ ایستا (به‌جای باینری یا فایل اجرایی نهایی) در آن‌ها دشوار است، ممکن است استفاده از crate با نام cc آسان‌تر باشد که رابطی Rust‌پسند (idiomatic) برای کامپایلر ارائه‌شده توسط میزبان فراهم می‌کند.

    در ساده‌ترین حالت، یعنی کامپایل یک فایل C به‌عنوان وابستگی یک کتابخانهٔ ایستا، نمونه‌ای از اسکریپت build.rs با استفاده از crate با نام cc چنین خواهد بود:

    fn main() {
    cc::Build::new()
        .file("src/foo.c")
        .compile("foo");
}

    build.rs در ریشهٔ بسته قرار می‌گیرد. سپس cargo build آن را پیش از ساخت بسته کامپایل و اجرا می‌کند. یک آرشیو ایستا به نام libfoo.a تولید می‌شود و در پوشهٔ target قرار می‌گیرد.
