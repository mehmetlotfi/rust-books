    Panic

    panic بخش اصلی زبان Rust است. عملیات داخلی مانند اندیس‌گذاری در زمان اجرا برای ایمنی حافظه بررسی می‌شوند. وقتی اندیس‌گذاری خارج از محدوده انجام شود، به panic می‌انجامد.

    در کتابخانهٔ استاندارد، panic رفتار تعریف‌شده‌ای دارد: پشتهٔ نخی را که panic کرده است باز می‌کند (unwind)، مگر این‌که کاربر انتخاب کرده باشد برنامه هنگام panic متوقف (abort) شود.

    اما در برنامه‌های بدون کتابخانهٔ استاندارد، رفتار panic تعریف‌نشده رها شده است. با تعریف یک تابع #[panic_handler] می‌توان رفتاری را برگزید. این تابع باید دقیقاً یک بار در گراف وابستگی برنامه ظاهر شود و باید امضای زیر را داشته باشد: fn(&PanicInfo) -> !، که در آن PanicInfo ساختاری (struct) است شامل اطلاعاتی دربارهٔ محل وقوع panic.

    با توجه به این‌که سیستم‌های توکار از سیستم‌های رو به کاربر تا سیستم‌های حیاتی از نظر ایمنی (که نباید از کار بیفتند) را شامل می‌شوند، رفتار panicی وجود ندارد که برای همه مناسب باشد، اما رفتارهای رایج بسیاری هست. این رفتارهای رایج در crateهایی بسته‌بندی شده‌اند که تابع #[panic_handler] را تعریف می‌کنند. چند نمونه:

    • panic-abort. panic باعث می‌شود دستور abort اجرا شود.
    • panic-halt. panic باعث می‌شود برنامه، یا نخ جاری، با ورود به یک حلقهٔ بی‌نهایت متوقف شود.
    • panic-itm. پیام panic با ITM، یک دستگاه جانبی مختص ARM Cortex-M، ثبت می‌شود.
    • panic-semihosting. پیام panic با تکنیک semihosting روی میزبان ثبت می‌شود.

    با جست‌وجوی کلیدواژهٔ panic-handler در crates.io ممکن است crateهای بیشتری هم پیدا کنید.

    یک برنامه تنها با پیوند دادن به crate متناظر می‌تواند یکی از این رفتارها را برگزیند. این‌که رفتار panic در سورس برنامه به‌صورت یک خط کد بیان می‌شود، نه‌تنها به‌عنوان مستندات مفید است، بلکه می‌توان از آن برای تغییر رفتار panic بر اساس پروفایل کامپایل هم استفاده کرد. برای مثال:

    #![no_main]
#![no_std]

// dev profile: easier to debug panics; can put a breakpoint on `rust_begin_unwind`
#[cfg(debug_assertions)]
use panic_halt as _;

// release profile: minimize the binary size of the application
#[cfg(not(debug_assertions))]
use panic_abort as _;

// ..

    در این مثال، وقتی با پروفایل dev ساخته شود (cargo build)، crate به crate با نام panic-halt لینک می‌شود، اما وقتی با پروفایل release ساخته شود (cargo build --release)، به crate با نام panic-abort لینک می‌شود.

    شکل use panic_abort as _; از دستور use برای این به کار می‌رود که مطمئن شویم panic handler مربوط به panic_abort در فایل اجرایی نهایی ما گنجانده می‌شود، و در عین حال به کامپایلر روشن کنیم که صراحتاً از هیچ چیزی در این crate استفاده نخواهیم کرد. بدون تغییر نام با as _، کامپایلر هشدار می‌دهد که یک import استفاده‌نشده داریم. گاهی ممکن است به‌جای آن extern crate panic_abort را ببینید، که سبکی قدیمی‌تر است و پیش از ویرایش ۲۰۱۸ Rust استفاده می‌شد و اکنون باید فقط برای crateهای «sysroot» (آن‌هایی که همراه خود Rust توزیع می‌شوند) مانند proc_macro، alloc، std و test به کار رود.

    یک مثال

    این هم مثالی که سعی می‌کند به عنصری فراتر از طول یک آرایه دسترسی بدهد. این عملیات به panic می‌انجامد.

    #![no_main]
#![no_std]

use panic_semihosting as _;

use cortex_m_rt::entry;

#[entry]
fn main() -> ! {
    let xs = [0, 1, 2];
    let i = xs.len();
    let _y = xs[i]; // out of bounds access

    loop {}
}

    این مثال رفتار panic-semihosting را برگزیده است که پیام panic را با semihosting روی کنسول میزبان چاپ می‌کند.

    $ cargo run
     Running `qemu-system-arm -cpu cortex-m3 -machine lm3s6965evb (..)
panicked at 'index out of bounds: the len is 3 but the index is 4', src/main.rs:12:13

    می‌توانید رفتار را به panic-halt تغییر دهید و تأیید کنید که در آن حالت هیچ پیامی چاپ نمی‌شود.
