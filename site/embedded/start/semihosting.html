    نیمه‌میزبانی (Semihosting)

    Semihosting سازوکاری است که به دستگاه‌های توکار اجازه می‌دهد روی میزبان ورودی/خروجی انجام دهند و عمدتاً برای ثبت پیام‌ها در کنسول میزبان به کار می‌رود. Semihosting به یک نشست اشکال‌زدایی نیاز دارد و تقریباً هیچ چیز دیگر (بدون سیم اضافی!)، پس استفاده از آن فوق‌العاده راحت است. اشکالش این است که فوق‌العاده کند است: بسته به اشکال‌زدای سخت‌افزاری (مثلاً ST-Link) که به کار می‌برید، هر عملیات نوشتن می‌تواند چند میلی‌ثانیه طول بکشد.

    crate با نام cortex-m-semihosting یک API برای انجام عملیات semihosting روی دستگاه‌های Cortex-M فراهم می‌کند. برنامهٔ زیر نسخهٔ semihosting برنامهٔ «Hello, world!» است:

    #![no_main]
#![no_std]

use panic_halt as _;

use cortex_m_rt::entry;
use cortex_m_semihosting::hprintln;

#[entry]
fn main() -> ! {
    hprintln!("Hello, world!").unwrap();

    loop {}
}

    اگر این برنامه را روی سخت‌افزار اجرا کنید، پیام “Hello, world!” را در گزارش‌های OpenOCD می‌بینید.

    $ openocd
(..)
Hello, world!
(..)

    ابتدا باید semihosting را در OpenOCD از طریق GDB فعال کنید:

    (gdb) monitor arm semihosting enable
semihosting is enabled

    QEMU عملیات semihosting را می‌فهمد، بنابراین برنامهٔ بالا بدون نیاز به شروع یک نشست اشکال‌زدایی با qemu-system-arm هم کار می‌کند. توجه کنید که برای فعال کردن پشتیبانی از semihosting باید پرچم -semihosting-config را به QEMU بدهید؛ این پرچم‌ها از قبل در فایل .cargo/config.toml قالب گنجانده شده‌اند.

    $ # this program will block the terminal
$ cargo run
     Running `qemu-system-arm (..)
Hello, world!

    یک عملیات semihosting به نام exit هم هست که می‌توان با آن فرایند QEMU را خاتمه داد. مهم: روی سخت‌افزار از debug::exit استفاده نکنید؛ این تابع می‌تواند نشست OpenOCD شما را خراب کند و تا زمانی که آن را دوباره راه‌اندازی نکنید نمی‌توانید برنامهٔ دیگری را اشکال‌زدایی کنید.

    #![no_main]
#![no_std]

use panic_halt as _;

use cortex_m_rt::entry;
use cortex_m_semihosting::debug;

#[entry]
fn main() -> ! {
    let roses = "blue";

    if roses == "red" {
        debug::exit(debug::EXIT_SUCCESS);
    } else {
        debug::exit(debug::EXIT_FAILURE);
    }

    loop {}
}
    $ cargo run
     Running `qemu-system-arm (..)

$ echo $?
1

    یک نکتهٔ آخر: می‌توانید رفتار panic را روی exit(EXIT_FAILURE) تنظیم کنید. این به شما اجازه می‌دهد آزمون‌های run-pass از نوع no_std بنویسید که بتوانید روی QEMU اجرا کنید.

    برای راحتی، crate با نام panic-semihosting یک feature به نام “exit” دارد که وقتی فعال شود، پس از ثبت پیام panic در stderr میزبان، exit(EXIT_FAILURE) را فراخوانی می‌کند.

    #![no_main]
#![no_std]

use panic_semihosting as _; // features = ["exit"]

use cortex_m_rt::entry;
use cortex_m_semihosting::debug;

#[entry]
fn main() -> ! {
    let roses = "blue";

    assert_eq!(roses, "red");

    loop {}
}
    $ cargo run
     Running `qemu-system-arm (..)
panicked at 'assertion failed: `(left == right)`
  left: `"blue"`,
 right: `"red"`', examples/hello.rs:15:5

$ echo $?
1

    توجه: برای فعال کردن این feature روی panic-semihosting، بخش وابستگی‌های Cargo.toml خود را، همان‌جا که panic-semihosting مشخص شده است، این‌گونه ویرایش کنید:

    panic-semihosting = { version = "VERSION", features = ["exit"] }

    که در آن VERSION نسخهٔ موردنظر است. برای اطلاعات بیشتر دربارهٔ featureهای وابستگی‌ها، بخش specifying dependencies کتاب Cargo را ببینید.
