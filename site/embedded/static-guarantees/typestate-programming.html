    برنامه‌نویسی Typestate

    مفهوم typestate‌ها به رمزگذاری اطلاعات دربارهٔ وضعیت فعلی یک شیء در نوع آن شیء اشاره دارد. هرچند ممکن است این موضوع کمی پیچیده و رمزآلود به نظر برسد، اگر در Rust از الگوی Builder استفاده کرده باشید، پیش‌تر برنامه‌نویسی Typestate را شروع کرده‌اید!

    pub mod foo_module {
    #[derive(Debug)]
    pub struct Foo {
        inner: u32,
    }

    pub struct FooBuilder {
        a: u32,
        b: u32,
    }

    impl FooBuilder {
        pub fn new(starter: u32) -> Self {
            Self {
                a: starter,
                b: starter,
            }
        }

        pub fn double_a(self) -> Self {
            Self {
                a: self.a * 2,
                b: self.b,
            }
        }

        pub fn into_foo(self) -> Foo {
            Foo {
                inner: self.a + self.b,
            }
        }
    }
}

fn main() {
    let x = foo_module::FooBuilder::new(10)
        .double_a()
        .into_foo();

    println!("{:#?}", x);
}

    در این مثال، هیچ راه مستقیمی برای ساختن یک شیء Foo وجود ندارد. باید یک FooBuilder بسازیم و پیش از آنکه بتوانیم شیء Foo موردنظرمان را به دست آوریم، آن را به‌درستی مقداردهی اولیه کنیم.

    این مثال کوچک دو حالت را رمزگذاری می‌کند:

    • FooBuilder که حالت «پیکربندی‌نشده» یا «پیکربندی در حال انجام» را نشان می‌دهد
    • Foo که حالت «پیکربندی‌شده» یا «آمادهٔ استفاده» را نشان می‌دهد.

    نوع‌های قوی

    از آنجا که Rust یک سیستم نوع قوی دارد، راه ساده‌ای برای ساختن جادویی یک نمونه از Foo یا تبدیل یک FooBuilder به Foo بدون فراخوانی متد into_foo() وجود ندارد. علاوه بر این، فراخوانی متد into_foo() ساختار FooBuilder اصلی را مصرف می‌کند، یعنی بدون ساختن یک نمونهٔ جدید نمی‌توان آن را دوباره استفاده کرد.

    این کار به ما اجازه می‌دهد حالت‌های سیستم خود را به‌صورت نوع‌ها نمایش دهیم و اقدامات لازم برای انتقال بین حالت‌ها را در متدهایی قرار دهیم که یک نوع را با نوعی دیگر جایگزین می‌کنند. با ساختن یک FooBuilder و تبدیل آن به یک شیء Foo، مراحل یک ماشین حالت ساده را پیموده‌ایم.
